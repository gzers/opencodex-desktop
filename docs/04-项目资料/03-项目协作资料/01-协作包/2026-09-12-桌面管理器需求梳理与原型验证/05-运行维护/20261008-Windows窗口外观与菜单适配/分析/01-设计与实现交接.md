## 范围与行为

| 项目 | 拟议行为 | 原型边界 |
|---|---|---|
| 标题栏 | 单行，左侧图标 / 名称，右侧窗口按钮；空白区拖拽、双击最大化 | 仅双击和尺寸模拟，拖拽命中待原生验证 |
| 按钮 | 最小化、最大化 / 还原、关闭；系统风格悬停 | 网页控件不能证明系统 Snap 语义 |
| 材质 | Win11 原生 Mica；Win10、透明关闭、不可用回退实色；非活动示意实色 | CSS 低对比染色，不是真实桌面合成 |
| 菜单 | Windows 去掉整行原生菜单；macOS 保留 | 旧双栏仅静态结构对照 |
| 关闭 | 保持代理偏好开启 → 留托盘；关闭 → 原有退出路径 | 只改变 mock，不退出浏览器或真实代理 |
| 内容 | 平台外壳独立评审 | 主原型模型内容属 0.2.0 草稿，不纳入本次 0.1.9 范围 |

右侧切换系统、主题、透明可用性、焦点、关闭偏好和 1180×760 / 960×640，并提供现有双栏对照。隐藏窗口后的“重新打开”是评审器按钮，用于模拟任务栏 / 托盘恢复及重新启动，不是新增产品按钮。

菜单功能去向：进程启停归概览 / 托盘；编辑保留标准快捷键与输入框上下文菜单；视图缩放保留应用内入口；诊断归左侧诊断。原生接线和功能无损必须后续验证。

## 固定源码调研与实现交接

初次设计调研依据：feature/0.1.8-windows-package，cffca3afc29b8b251f3f14535f997b5d08560cb2，本轮未修改代码。

- tauri.conf.json 的 Overlay / hiddenTitle 是 macOS 配置，不代表 Windows 已有定制标题栏；当前未配置 Mica。
- src/lib.rs 当前无条件安装应用菜单；后续按平台控制 Windows 菜单，tray_controller.rs 可接受空 native_menu。不要全平台删除。
- macOS Edit 菜单参与 responder chain，应保留 Cmd+C/V/X/A 等行为。Windows 输入框仍需编辑快捷键和上下文菜单验收。
- CloseRequested 已根据保持代理偏好 prevent_close / hide；定制关闭按钮须经过该关闭请求路径，不直接调用 process exit 绕过偏好。
- App.vue 拖拽带和 base.css 的 macOS 标题区需平台分流；按钮不能成为拖拽命中区。应用缩放不得错位系统按钮或覆盖窗口缩放边缘。
- 后续用 Tauri Windows 窗口效果 / DWM 提供真实 Mica，核验系统版本、透明策略、失败回退、布局命中；精确收敛窗口操作权限。
