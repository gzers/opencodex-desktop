# 用户目录与手动渠道恢复配套说明

2026-11-06，用户已确认目标；**本轮仅修改说明，原型页面与生产接线均未完成，目标版本0.2.23**。唯一总原型仍为[原入口](原型/index.html#settings)，不另建可执行原型。范围归[DMD-USER-DIRECTORY](../../../01-需求管理/需求/DMD-OPENCODEX-USER-DIRECTORY.md)，顺序及采用登记归[IMP-32](../../../03-开发实施/IMP-OPENCODEX-DESKTOP-32.md)。

## 路径与界面职责

路径事实唯一见[数据与状态 §1.4](../../../02-项目核心/数据与状态.md#14-用户目录新规则已确认待实现目标版本0223)，界面要求见[UI规范 §55](../../../02-项目核心/UI规范.md#55-新用户目录与手动渠道恢复已确认目标原型与软件待接线)。根下先分desktop/opencodex，旧安装旁data/Application Support不是新版默认。

| 待核对消费者 | 新目标与状态 |
| --- | --- |
| 设置：安装与数据/目录选择 | 展示实际数据根、OpenCodex HOME和程序入口，区分缺失/未安装/损坏/无权限/有效；自定义新版目录须显式选择，不扫描旧来源或注册表。 |
| 安装/更新/卸载 | 仅按新安装合同的路径/来源，程序独立于HOME；不提供旧程序重新绑定、跨版本接管或自动迁移。安装合同冻结前不臆造程序前缀。 |
| 备份树/日志/缓存/导出/同步本机状态 | 使用新版desktop分区的真实路径，不各留一套旧默认；既有备份浏览/恢复和文件传输功能不因此取消。 |
| 模型页“读取现有渠道” | 用户先放JSON到新HOME，再读取当前配置，保持既有入口，不是任意文件导入器；加载/空态/格式错误/引用缺失分别反馈，失败不显示成功空列表。 |
| 清理指引 | 链接人工旧位置及条件，不加自动扫描/删除按钮。独立安装和渠道恢复通过后由用户清理旧资料。 |

## 原型采用边界

维护原型的旧双端示例及迁移预览不是新目录合同。本轮不改index.html/maintenance脚本、不覆盖并行原型草稿，不登记视觉QA通过。实施前在同一总原型核对以上消费者，登记实际采用提交/摘要和必要状态，再对照软件最终组件。普通路径文案/表单优先页面验证，系统路径/权限/进程按条件原生补验。

完整双端树及旧位置手动备份/清理参考见[目录设计第5节](../06-问题记录/20261106-Desktop用户配置目录结构设计.md#5-旧版处理不做自动迁移手动备份与恢复渠道)。启用新版前用户退出旧Desktop及服务；保留旧资料不表示新旧配置同步。
