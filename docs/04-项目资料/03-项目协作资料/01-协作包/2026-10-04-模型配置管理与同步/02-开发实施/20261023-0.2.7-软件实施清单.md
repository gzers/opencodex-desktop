| 项 | 内容 |

### A6 拦下原因走已注册通知

| 项 | 内容 |
| --- | --- |
| 软件现状 | 失败写在 `saveOpen` 弹窗内的 `model-error`；`notifications/registry.rs` L574～585 `SupportedEvent` 只有 `model-policy-save-failed / -succeeded / model-config-changed / model-operation-progress / model-template-external-*`，没有 blocked 事件 |
| 要做 | ① Rust 注册表新增 `model.policy.save.blocked`（warning、toast + center、按固定原因去重）；② 在 `model_config` 发出点产生该事件；③ 前端删弹窗内错误块，改经公共 publisher 投递；④ 原因取门禁第一条（连接未入草稿 → 行未入草稿 → 超预算 → 校验首错 → 无未保存修改 → 条件已变化），不得携带计划 / 渠道名 / URL / Key；⑤ 同原因更新同一条，用户删除后不自动复活 |
| 验收 | 干净草稿确认 → 弹窗关闭 + 通知“未写入 + 草稿保留”；待确认编辑 / 超限 / 校验失败同理；通知详情能回模型页；生产注册表可查到该事件；不新增第二个错误表面 |

### A7 弹窗内启停后第一次确认必须成功（回归）

| 项 | 内容 |
| --- | --- |
| 背景 | 原型侧刚修过同类缺陷：弹窗打开时记下草稿指纹，确认时又比对当前草稿，导致“预览里点一下就判成基准漂移，第一次保存必失败” |
| 要做 | 软件侧确认 `preparePolicy` 的 baseline 只校验**已保存版本 / 库摘要**，不把弹窗内的启停算作漂移；写入时使用确认时刻的草稿快照 |
| 验收 | 打开预览 → 启停渠道与型号 → 直接确认，一次成功且写入的正是刚才的改动；打开后改回原样再确认，按“没有未保存修改”拦下 |

## C. 样式与组件约束（不得自由发挥）

本节是防止实现阶段走偏的硬约束，逐条可由 review 直接判定。

| 约束 | 要求 |
| --- | --- |
| 组件复用 | 按钮 / 弹窗 / 下拉一律 `UiButton`、`UiDialog`、`UiSelectField`；不新写第二套按钮或下拉 |
| 尺寸 | 页级与弹窗动作 md 34px；行内 sm 28px；不因“看起来大”自行改字号或内距 |
| Token | 圆角用 `--radius-2xs/xs/sm/radius/lg`；字号用 `--text-micro/caption/label/control/body`；阴影 `--shadow/--shadow-sm`；色只用语义 Token（`--amber` / `--green` / `--red` 及 soft） |
| 禁止 | 新样式里出现裸 `px` 圆角、裸 `#hex` 投影、`z-index` 魔数、`font-size:10px` 这类硬编码 |
| 状态色 | 颜色只表达启停或风险；Fast 能力必须配文字，不用颜色推断 |
| 文案归属 | 实现过程说明（备份 / 写入 / 重启、操作讲解）不进正文，按 UI 规范 §36 处理；真实错误与业务结果必须保留 |
| 无障碍 | 停用 / 恢复、标签启停需可键盘操作并带 `aria-pressed`；悬浮说明依赖 hover 时必须同时有 `focus-visible` |
| 长按与点击 | 长按只用于“看说明”，与启停是两件事；长按后抬手必须吞掉该次 click。实现约束见 UI 规范 §38.3.1 |
