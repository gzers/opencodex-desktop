## 3. 底层账本及读取方式

`src/usage/log.ts` 的 `PersistedUsageEntry`（约 299–409 行）包含：行 `requestId`、可选 `logicalRequestId`、timestamp、模型 / provider、surface、apiKeyId、status / durationMs、usageStatus / usage、attempts、spend、cacheProvenance 等。持久文件为 `<configDir>/usage.jsonl`（`usageLogPath`，约 527 行）。

其中 `conversationId`、自由文本 `upstreamError`、详细路由等字段不进入本方案默认上传白名单。`accountLogLabel` 是供应商账户标签，不是用户身份；旧记录的 apiKeyId / logicalRequestId 可能缺失。

| 接口 / 来源 | 已有行为 | 可复用性与限制 |
|---|---|---|
| `GET /api/usage` | 汇总 / 过滤；可选组合路由和失败投影 | 用于核对汇总，不能轮询后直接累加快照 |
| `GET /api/usage/timeline` | 有界时间线，可标记截断 | 图表辅助，不能代替事件采集 |
| `GET /api/request-history` | 游标分页、筛选、nextCursor / hasMore、索引 / 源文件状态信息 | 首选采集验证对象；尚未证明字段完整或具备稳定增量 / 变更语义 |
| `GET /api/request-history/:requestId` | 单条详情 | 可用于验证缺失字段，不先假设批量 API 完全同构 |
| 只读 `usage.jsonl` | 持久请求记录 | API 不满足时的版本化后备；处理半行、轮换、截断、旧格式 |
| `/api/logs` 内存环 | 最多 2000 条的近期观察 | 不能当作完整用量历史 |
| `ocx usage --json` | 已连接 client 会调用 Hub，否则查本地汇总 | 不能默认命令输出永远代表本设备 |

源码：`src/server/management/{logs-usage-routes,usage-timeline-routes,request-history-routes}.ts`；`src/cli/observe.ts`（约 166–209 行）。`src/server/usage-ledger-retention.ts` 允许按配置裁剪账本，文件会被替换，不能将旧偏移持续读取视为永不丢失。

## 4. Hub 已解决的部分与仍然缺少的部分

`src/server/hub-usage.ts` 和 `src/server/index/serve-options.ts` 暴露 **`GET /v1/usage`**，仅 Hub 模式可用。服务端从 `x-opencodex-api-key` 认证结果取得 apiKeyId，只返回该接入密钥的用量，调用方不能用任意 userId 查询他人数据。

`src/remote/hub-usage.ts` 的响应为 `schemaVersion: 1`、`source: hub`、`scope: client` 的受限汇总，去掉原始行和账户标签；`src/client/hub-client.ts` 有对应客户端。它提供密钥级远端统计，并未在此响应中提供完整站点账户 / 设备目录。

由这些源码可推导：

- 多台设备用同一个 Hub 接入密钥时，经过该 Hub 的用量可以归到同一密钥，但无法仅凭该密钥区分设备。
- 每设备单独发密钥可形成设备维度，但还需站点账户 → 设备 → 密钥的受控映射、撤销和权限。
- Hub 只观察经过它的流量，不能自动汇总各设备独立本地代理的既有账本。
- 同一流量同时在 Hub 和 client 侧出现时，不能把两个观察结果相加。

因此，用户需求仍需要一个共享的数据与身份服务；是否把推理流量也集中到服务器，是可选的第二个决定。

## 5. 统计口径的兼容风险

1. `summary.ts` 的总 requests 按持久行递增；精确分组用 `entry.requestId`。存在 logicalRequestId 并不意味着已有所有图表都按逻辑请求去重。新服务应明确显示“请求记录”和“逻辑请求（有身份的部分）”。
2. `usageAttributions` 优先取 attempts，否则取行字段；不能把父行与它的 attempts 再加一遍。
3. `totals.ts` 基本口径为输入 + 输出；为兼容旧数据显式 total 可按上游规则保留较大值，不能默默重写历史。
4. 组合请求能触及多个模型 / provider；各模型的请求数相加可能大于全局请求数，`comboOverlap` 已表达此问题。
5. 缺价格、缺计量、采集缺口、时间桶截断是不同状态；任一项都不能变成“真实用量为 0”。

## 6. Desktop 可复用基础

在固定 main 提交中，`apps/desktop/tauri/src/modules/sync/config.rs` 是 WebDAV 配置快照同步，支持地址、用户名和凭据引用；这不是多用户事件数据库。`apps/desktop/tauri/src/infrastructure/keychain.rs` 已封装跨平台系统凭据存储，但用途白名单仅含 WebDAV / 同步加密用途；服务登录凭据需新增独立用途和生命周期，不能直接宣称已有。

Desktop 嵌入官方面板可继续提供本地统计。新功能适合新增独立的账户 / 设备 / 用量模块；不用为远端聚合复制一份上游完整管理面板，也不用把统计请求接进 WebDAV 文件同步流程。
