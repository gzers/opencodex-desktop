# COL-LOCAL-20261014-01 多 Agent 平台扩展管理

## 目的与授权

用户认为既有扩展页考虑的平台过少，横向逐平台开关无法容纳更多平台，要求先调查 OpenCodex 的平台，再考虑新的管理形式，作为版本未定的独立协作包。2026-10-14 用户同意本包位于项目协作资料的 01-协作包 下，与模型配置、Codex 对话配置包同级，随后授权继续分析。

本轮建立材料、核对上游来源并评估既有原型。候选交互、新增适配器、项目作用域与实施顺序尚未确认。

后续用户已确认“资源列表 + 目标管理弹窗 + 客户端页”的管理方向和原型制作，明确不新建活动原型目录。第一轮在唯一总原型注册 extensions 设计范围，覆盖与检查见[原型说明](01-需求分析/05-原型/README.md)。交付平台、版本、项目写入和生产开发仍未确认；前述候选状态保留为本轮分析时的历史。

## 参与人与角色

| 角色 | 责任 |
|---|---|

## 关联、回写与保留

本包负责多平台扩展管理。[模型配置管理与同步](../2026-10-04-模型配置管理与同步/README.md)负责渠道、模型模版和公共同步；[Codex 对话配置管理](../2026-10-11-Codex对话配置管理/README.md)负责命名、搜索和子 Agent 行为；[团队配置发布订阅与模块组合](../2026-10-05-团队配置发布订阅与模块组合/README.md)负责团队发布订阅。公共能力引用相应包，版本分别管理。

2026-10-19 用户提出本包与[渠道特殊能力与代理兼容](../2026-10-16-渠道特殊能力与代理兼容/README.md)大概率同版发布，现将[同版发布关联](../2026-10-16-渠道特殊能力与代理兼容/01-需求分析/03-确认与评审/20261019-与多Agent平台扩展管理同版发布关联.md)作为后续版本统筹输入。两包仍独立承接需求、实现和验收，联合考虑共享配置写入保护、隔离、独立恢复及组合回归；具体版本号、最终范围和同批决定尚未冻结，未启动发布或生产开发。

经确认的稳定结论再回写需求与项目核心的能力地图、领域模型、集成与安全边界、数据与状态和 UI 规范。当前只确认独立包和落点，交互建议不回写成已定规则。

未来原型复用[唯一总原型](../../../01-项目支撑资料/01-产品原型/原型/index.html#extensions)，本包保留增量说明与评审证据。原始输入、来源索引和评审随包保留，替代方案注明关系，关闭时保留权威回写与实施引用。执行时产生的 TASK、回执与机器证据进入 .adg/；本轮不创建虚构执行或验收对象。
