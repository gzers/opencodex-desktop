# 20261016 Krill 真实入口与代理链路验证

性质：用户回复“可以开始验证”后执行的最小真实线路验证。结果属于所测版本、账号和短合成会话，不是产品验收、后台并发验证或质量 / 计费基准。

## 授权、环境与数据边界

- 用户授权延续本专题的真实验证。使用现有 Krill-1 渠道凭据，仅在本机请求进程内读取；未打印或写入凭据，未发送日常对话或仓库内容。
- 运行中 OpenCodex 经 /healthz 确认为 2.84.0，监听 127.0.0.1:10100。本轮没有停止、重启、改包或改写配置。
- 当前 Krill 配置入口为 https://api.krill-code.net/codex/v1，教程入口为 https://api.krill-code.net/backend-api/codex。直接对比只是验证上游，不是产品切换或采用直连方案。
- 使用新测试会话、gpt-6.1-sol 和短合成输入。普通推理输出上限为 128 tokens，推理强度 low，不提供工具。独立压缩仅发送短合成历史。
- 共 12 次目录 / 模型 / 压缩 / history 请求，外加本地健康读取和一次限定测试会话的管理日志读取。未读写既有笔记或历史；请求正常进入服务日志和用量记录。
- 指纹检查中，上轮记录的 13 个原版源码 / 执行文件摘要全部一致。脚本不写日常客户端或代理配置，不修改安装。

计划、脚本、非秘密结果和完整性摘要见[机器证据目录](../../../../../../.adg/evidence/OCX-CHANNEL-CAPABILITIES-20261016-LIVE/)。只保存状态、协议类型、档位回显、计数、用量和错误摘要；未保存原生压缩内容或完整响应。原生状态仅在进程内用于续聊。

## Ultrafast 的证明边界

runner 明确向代理和教程入口分别发送 service_tier = ultrafast，两条路径均完成普通推理，响应均回显 default。结合前序组件检查“特定规则下保留参数”的结果，仍无法确定上游授权、调度、回显契约和实际运行态策略各自的影响。

本轮通过公开管理接口限定新会话读取请求日志，返回 HTTP 401；没有绕过鉴权或读取其他会话日志。因此尚无当前运行态实际出站档位的独立日志证据。目录声明和请求接受可记录，UI 不应标为“Ultrafast 已验证生效”；耗时差异也不作为加速档证明。

## 原生压缩与代理摘要已区分

同一短历史、同一模型经两个 Krill 入口直接调用 /responses/compact，都返回一个不透明 compaction 项；经原版代理则返回普通消息组成的文本摘要。该差异与前序隔离检查一致，已有真实链路佐证。

续聊使用教程入口返回的完整窗口，未解码或修改原生状态。窗口还包含保留用户消息，答出标记不能证明该标记仅从不透明状态恢复，不能据此评价“更不失忆”。本轮未测多轮损失、推理保留或模型质量。

渠道管理必须区分客户端选择的远程协议和代理实际执行的处理。开关及出口参数不能把此摘要路径直接标成原生压缩；也不因为上游原生接口可用，就假定代理路径已经直通。

## history/notes 与费用仍待验证

本轮只对新会话执行 history list，未读取日常会话、写入笔记或重置状态。上游返回“线程无已存上下文”，说明端点到达不等于有效存储与查询已成功。

当前运行代理返回 404；前序临时配置开启 context 后，处理函数曾返回“需要规范官方 ChatGPT provider”的 400。它们属于不同环境，不能合并为同一错误。目录的上下文标记也应在原生客户端认证条件下重新确认。

普通推理终态返回 input / output / total token 数，输出均为 9 tokens，输入计数明显大于合成文本长度。未查账单、余额或倍率，不按脚本文本长度推断最终计费，也不为独立 compact 请求补写费用数据。“后台与普通计费完全相同”仍未验证。

1. 已验证两个 Krill 入口的原生 compact 形状、教程入口窗口的短续聊兼容，以及当前代理摘要路径的实际差异。
2. Ultrafast 部分验证：目录声明和请求接受成立，实际档位授予待核实。
