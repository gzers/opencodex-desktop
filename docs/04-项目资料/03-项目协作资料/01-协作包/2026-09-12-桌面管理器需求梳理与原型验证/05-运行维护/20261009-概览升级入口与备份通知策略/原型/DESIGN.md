## 已确认：取消标准按钮高光

依据本次用户要求，常规、强调、危险、ghost 与图标按钮统一取消渐变高光及顶部 inset 亮线，保留各自语义填充、边框和一层轻外投影。强调按钮保留强调色与文字对比；ghost 沿现有底色令牌。悬停、禁用和键盘焦点提示保留，低画质沿原实底回退。不同材质不再作为按钮单独配置项。

此前概览 .ovb-actions > .btn 存在顶部内高光，强调按钮却没有；共享控件背景还有色纱渐变。本轮从来源样式取消它们。卡片 / 浮层玻璃及特殊悬浮启动器层级不随标准按钮规则重写；稳定规则回写 [UI 规范 §26.3](../../../../../../../02-项目核心/UI规范.md)。这是目标规则与原型修改，不构成生产已实现声明。

## 已确认：背景光覆盖正文边距

源码定位：overview-dual.js 将背景 iframe 挂在状态卡内；overview-dual.css 原先 left:0 / width:100%，只覆盖内容列。嵌入页 stage 为 100vw / 100vh，CSS 光层和 WebGL 画布均在 iframe 内裁剪，无法覆盖 main 的左右 padding，形成图中沿正文列边缘的直线留缝。这是原型源码的原因定位，尚非生产设备原因核验。

overview-dual.css 用同一 --overview-gutter 同时定义正文边距和背景扩展：标准 22px、紧凑 18px；背景左移一个边距并扩宽两个边距。顶部追加按 main 内边界与状态卡实际距离定位，包含 scrollTop、边框及窗口缩放换算；留出至少 64px 的外部缓冲，CSS 顶部 6% 渐隐与 20px 柔化按扩展后的高度计算。光层增加高度以保持底边，presentation.padding 同步补偿 Logo 上边距；嵌入页放宽旧 120px 上限，仍限制在 iframe 可用高度内。main 原有滚动 / 圆角裁剪、正文间距、Logo 位置保持；光效容器高度变化会改变纵向渐隐分布，效果须实屏评审。就绪 / 环境准备、高 / 中档的 CSS 与 WebGL 共用该容器；低档继续关闭光层。窗口标题栏 28px 横带及 main 顶部圆角描边属于外壳分层，此处覆盖 main 内部顶部边距，不扩大窗口外壳或侧栏的光层。

源码及几何核对见 [原型 QA](原型QA.md)。浏览器实屏仍需验证无横向滚动条、边距区无直线断光；后续生产适配另由代码分支实施。

### 生产实施要求（本轮用户要求回写）

此项同时约束 0.1.10 后续开发。背景层覆盖内容面板内顶部和左右边距，边界依据面板实际布局；正文 padding 保留给文字和卡片，不能同时作为背景光的裁剪边界。窗口标题栏、侧栏与面板圆角的已有分层保持。

- 优先让背景层与正文布局分开，以内容面板为覆盖范围；若继续共用 Logo / 背景容器，向上扩展必须同步补偿 Logo 和容器高度，避免 Logo 上移或底部光层缩短。原型的 iframe 补偿是本轮验证方案，生产可采用对应平台适合的结构。
- 顶部不能只照搬四组固定负偏移。标题换行、窗口宽高 / 缩放 / DPR、标准与紧凑布局、就绪与环境准备切换后都要重新满足覆盖边界；滚动计算应使用一致的内容坐标，避免因 scrollTop 重复补偿而漂移。
- CSS 与 WebGL 的渐隐 / 柔化方式不同，应保留自然渐隐并分别核验顶边效果；高 / 中档覆盖同一面板范围，低档继续关闭光效。不得以取消正文间距、移动 Logo、加浓底色或删除圆角描边替代修复。
- Windows / macOS 实屏确认顶部与左右无 padding 硬断层、Logo 位置不变、文字可读、滚动无横向溢出及其他路由无回归后，才可登记完成。原型 Node VM / 算式结果不能替代生产 UI 验收；代码在实现分支提交，文档分支记录提交号与真实证据。

## 候选流程：概览升级

概览分别显示管理器、OpenCodex 面板版本与检查状态；只保留“检查更新”，手动检查完成进入结果步骤，两条状态行分别点击查看详情 / 重试。升级前备份移入确认步骤的默认勾选选项。设置版本升级复用同一状态和动作，不维护另一套模拟结果。

- 状态：未检查 → 检查中 → 已最新 / 有更新 / 失败；确认后准备 → 下载 → 校验 → 应用；面板核验完成，管理器待重启 → 回读完成，或失败。
- 示例管理器 0.1.9 → 0.1.10、面板 2.50.0 → 2.51.0，仅为 fixture；不是已发布候选或更新源事实。
- 更新设置保留 stable / 24h、beta / 6h、手动检查入口；面板官方包保持 24h。切通道取消旧检查、使旧确认失效并重新检查，手动模式不自动查。页面定时只模拟查询，无真实联网 / 安装。
- 检查不改变版本。确认展示对象、当前 / 候选版本、来源、备份边界、影响。确认中默认勾选偏好备份，可取消勾选；勾选后失败阻断并停留确认。沿受控更新或签名自更新语义演示，生产强制保护边界另核定。
- 查询中和应用中禁用重复操作；准备 / 下载 / 校验可取消模拟事务，写入阶段禁用取消。取消撤销本页模拟事务，迟到结果不得回写。真实安装的可取消阶段与回滚边界需代码实施核定，不能直接套用演示计时器。
- 已最新不提前展示候选；失败保留当前版本，可重试。确认时核对版本和状态，过期确认拒绝执行。
- 管理器更新的真实重启、官方运行时运行状态约束、错误详情及生产备份失败阻断仍在实施门禁内。

### 2026-10-10 详情与进度设计深化

依用户最新批注，检查结果与两类详情改为较宽上下布局，版本摘要和内容层次分开。说明区独立滚动、键盘可聚焦，标题与底部操作固定；两类详情保留各自来源与更新范围。右侧增加说明有内容 / 缺失 / 失败 / 加载中四态演示，失败可独立重试。

概览 / 设置复用相同详情、阶段、进度和事务。确认后进度窗口展示准备、下载（fixture 18 / 46 / 78 / 100%）、校验、应用；关闭窗口不取消，也不在完成时抢弹窗。管理器安装就绪显示待重启，旧运行版本保持；“重启并完成更新”只模拟重启后版本回读。面板核验完成才改版本。中 / 低档静态反馈不跟随系统减少动态设置。

更新内容与链接必须来自对应版本的可信记录，详细来源策略、字段、降级与进度生产要求见 [更新详情来源与进度反馈](../分析/03-更新详情来源与进度反馈.md)。当前所有正文和进度均为 fixture；官方网页出口仅为发布列表 / npm 包页面参考，尚未取得候选版本的精确网页与真实正文。以上原型不能代替生产联网、进度事件、签名、安装、重启和设备验收。

## 候选流程：数据与备份

原型按 main@de6862d4 阅读事实明确升级备份对象为**管理器偏好**，另有清单和完整性摘要。不能称作完整 OpenCodex 配置 / 会话 / 登录态 / Skills / MCP 内容或安装包备份。数据页说明对象、手动 / 升级前 / 恢复前触发、保存位置、清理策略和列表；导入 / 同步各自覆盖范围需按实际事务继续核对。

保存位置用“当前数据根 / backups / 管理器偏好（路径示例）”，不捏造设备绝对目录。真实实现解析当前数据根并打开可定位路径；原型只展示位置和安装配置出口。

本轮待评审方案：

1. 数量 10 / 时间 30 天默认；按“最近 N 份 **或** D 天内”保留，不是最多 N 份。数量 1–100、天数 1–365，须为整数。
2. 固定项不参与最近 N 份计数，始终额外保留；解除固定后按策略参与下次轮换。
3. 默认手动确认清理；可选择新备份成功后自动轮换。应用策略不会立即删除，失败创建不触发清理。
4. 清理先列出对象，确认时重算策略与固定保护。空清理禁用；列表有有效与无效校验示例，无效项禁止恢复。
5. 恢复先校验、确认覆盖范围，创建并固定当前偏好保护备份后才演示恢复。取消不改内存；不存在 / 校验失败项拒绝恢复。

以上固定保留、自动轮换与恢复交互是设计候选，未授权生产策略变更。保护当前偏好的备份是否自动解除固定、空间不足及删除失败恢复继续列入实施讨论。

## 候选流程：通知注册与投递

注册表放在右侧评审工具的弹窗，不新增用户自定义通知设置。注册项包含事件 ID、模块、多个触发源 triggers[]、触发条件、分类 / 程度、性质、检查周期、提醒周期、去重键、冷却、恢复、投递、保留期限和脱敏。

当前配置登记 69 个候选事件与 12 种来源，覆盖产品流程结果、状态及公共反馈；见 [统一事件注册与多触发源规划](../分析/02-统一事件注册与多触发源规划.md)。每项注明 prototype / planned。页面启动延迟 15s、概览切入、每分钟到期评估、可见性恢复与 online 信号进入同一 dispatcher；右侧可模拟多来源、备份失败与前进 24h。缓存、失败 5min / 30min / 2h 退避及互斥合并由模型处理。诊断 / WebDAV 周期只注册，未调度。生产调用点全量映射、持久缓存、通用重复提醒与系统投递尚未实现。

注册不等于每次弹窗：可用更新只入通知中心，手动无更新可给 toast，日常备份成功进入 toast / 日志，清理成功只入日志；失败按级别投递。通知中心事件接入既有铃铛 / 通知历史；日志与系统渠道只在投递记录中模拟。重复失败在冷却期合并，解除状态后新失败开启新记录；恢复与已读仍为独立字段。消息只使用固定摘要和示例对象，不携带路径、凭据或原始异常。生产已读 / 已解决 / 软删除语义沿原有规则，不另建状态体系。
