## 项目核心

保存脱离需求历史、缓存和看板后仍足以理解并重建当前项目的长期事实。
<!-- project-governance:managed-end -->

## 本目录内容

| 文档 | 内容 |
|---|---|
| `产品定义.md` | 定位、目标、产品边界、归属与许可、名称约定 |
| `能力地图.md` | 能力域与能力项，及其验收标准对应关系 |
| `系统架构.md` | 分层与技术栈、模块划分、运行时与 IPC、生命周期 |
| `数据与状态.md` | 数据根布局、三维状态模型、持久化与备份 |
| `集成与安全边界.md` | 外部客户端落点、单一真相源与投影、写入边界、信任模型与凭据处理 |

## 阅读顺序

1. `产品定义.md` —— 产品是什么、为谁解决什么问题、明确不做什么。
2. `能力地图.md` —— 能力范围与验收口径。
3. `系统架构.md` —— 由哪些部分组成、怎么跑起来、模块怎么分。
4. `数据与状态.md` —— 数据放在哪、状态如何建模。
5. `集成与安全边界.md` —— 与外部系统交互的边界与安全约束。

## 与其他文档的关系

- 本目录只保存**当前事实**：删除需求历史、协作过程与生成物后，仍可据此理解并重建本项目。
- 需求与验收标准的权威在 `01-需求管理`（`DMD-OPENCODEX-DESKTOP-MANAGER`）；本目录**不复述需求变更过程**，只写已成立的事实。
- 实施契约（`IMP-*`）、运行记录（`RUN-*`）与评审讨论不在本目录。
- 每个事实只写一次；本目录已写的内容，其他文档以引用代替重复。

## 当前状态

产品处于**需求阶段完成、尚未实现**的状态。本目录记录的是**已确认的设计事实**；实现开始后，本目录更新为实际架构事实，历史设计不再保留在本目录。
