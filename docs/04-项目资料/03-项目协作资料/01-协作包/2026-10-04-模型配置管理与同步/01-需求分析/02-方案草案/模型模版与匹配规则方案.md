# 模型模版与匹配规则方案（0.2.0 候选）

日期：2026-10-05（Asia/Shanghai）。依据最新用户输入修订；演示在[产品主原型](../../../../../01-项目支撑资料/01-产品原型/原型/index.html)，验证边界见[原型 QA](../05-原型/原型QA.md)。本文负责模版身份、匹配和操作结构；[主方案](模型配置管理方案.md)负责渠道策略与保存，[Agent 方案](Agent制模与版本恢复方案.md)负责执行、任务和恢复，[协议方案](模型协议与端点方案.md)负责连接与编译。生产 schema、读取器、Agent / CLI 和真实保存尚未实现。

## 1. 模版就是用户创建的模型族

“族”是对一组模型共用规则的称呼，模版本身就是这组规则。新建直接填写名称、说明、匹配规则和配置，不先从 GPT / Claude 等固定族下拉中选择。可建立“企业编码模型”“某渠道轻量模型”或单一型号专用模版，稳定 templateId 不受软件预设族枚举限制。

软件可提供 GPT、Claude、Gemini、Qwen、DeepSeek、Grok 等起始模版，并逐步扩充有来源的预置库；预置与自建使用同一结构，允许编辑为新版本和复制，不把“覆盖市面全部模型”作为已具备能力。示例值不证明渠道实际能力，未知字段继承。发现目录的厂商 / 用途标签只供浏览，不再作为决定匹配的第二套族身份。

模版身份由稳定 ID 和可变显示名称组成；规则、说明、匹配范围及来源随 revision 固定。改名不改策略引用；修改匹配或配置保存新候选，不改旧版。主版本只是以后默认选择的指针，新建可没有主版本。字段缺省表示继承，不要求填满。

## 2. 每个版本的匹配规则

候选表达如下，生产字段在 WP-01 冻结；与[双文件示例](model-family-templates.example.json)一致，不是已经可读取的正式 schema。

~~~json
{
  "include": [{"type": "prefix", "value": "company-"}],
  "exclude": [{"type": "glob", "value": "*-embedding"}],
  "caseSensitive": false,
  "channelMode": "all",
  "channels": [],
  "priority": 0
}
~~~

| 项目 | 定义与操作 |
|---|---|
| 包含规则 | 至少一条；精确 ID、前缀、通配符三种类型；多条为“任一命中” |
| 排除规则 | 可选，与包含使用相同类型；排除优先 |
| 通配符 | `*` 匹配任意长度，`?` 匹配一个字符；其他字符按字面处理，不作为正则 |
| 大小写 | 默认不敏感，可显式开启；匹配不改写上游精确 ID |
| 渠道范围 | 全部 / 白名单 / 黑名单；清单使用稳定 channelId，不保存连接地址；空值与未来渠道语义见下表 |
| 优先级 | 整数，较大优先；同最高优先级多个已采用模版命中时报告冲突，不按列表顺序挑选 |

“预览匹配”显示发现目录中的命中、排除、未选 / 停用和范围原因，也列零命中与重叠提醒。未选及停用模型用于检查规则，不自动加入白名单或启用。零命中规则可保存用于未来模型，提醒当前无应用目标。

| channelMode | 当前清单与空值 | 以后新增渠道 |
|---|---|---|
| all：全部渠道 | 忽略暂存清单 | 自动属于范围 |
| whitelist：仅所选渠道 | 只允许清单内；空清单不匹配任何渠道 | 默认不属于范围，需显式加入 |
| blacklist：排除所选渠道 | 排除清单内；空清单允许所有渠道 | 默认属于范围，除非加入排除清单 |

切模式保留清单，回切不丢勾选；全部模式清单不参与解析。旧候选缺 channelMode 时，非空 channels 按白名单迁入，空按全部迁入；迁入预览说明解释。删除渠道后的失效 ID 保留提示，不能因清单失效回退到全部。此处决定模版适用范围，与模型发布的 selectedModels 白名单独立，始终保留 discovery。

解析先看单模型精确 templateRef；人工指定可越过自动匹配，但显示“人工指定”，仍需通过协议 / 能力校验。否则将全局与渠道引用按 templateId 合并：渠道替换全局同 ID 的 revision，其他 ID 保留；只对已采用集合按版本规则和优先级决胜。未采用的新模版、候选或仅设主版本都不参与运行解析。精确引用只读一个 immutable revision，不叠加同 ID 的不同版本。

同优先级冲突需调整规则 / 优先级、移除引用或明确单模型引用；受影响保存阻止并保留草稿。缺 revision、无效配置和绑定错误同样显示原因。渠道内“族覆盖”按 templateId 关联最终选中的模版；旧字符串族规则迁入须明确对应关系，不按同名自动关联。

### 2.1 可选的版本或后缀配置

顶层配置是族通用规则，用户可在“版本或后缀”中任意新增、编辑、删除后缀项。默认没有条目，只显示空态及“新增版本或后缀”，不要求预建所有型号。每项有稳定 id、名称、字面后缀和逐字段继承 / 自定义规则；不建独立主版本，随当前模版 revision 保存。候选示意：

~~~json
{
  "variants": [
    {
      "id": "mini",
      "name": "轻量型号",
      "suffix": "gpt-5.4-mini",
      "rules": {"reasoning": {"default": {"mode": "custom", "value": "low"}}}
    }
  ]
}
~~~

后缀按完整上游原始 ID 的 endsWith 匹配，不看别名 / 显示名称，也不把后缀当 glob 或正则；大小写沿用当前版本的 caseSensitive。自动匹配先满足顶层渠道范围与包含 / 排除，再取当前 revision 内最长的命中后缀，只叠加这一项。单模型显式 templateRef 继续作为可见的人工指定例外越过顶层自动匹配，再在指定版本内选择后缀；协议和能力仍须校验。子项不扩大自动匹配的顶层范围。

同一版本内 id 唯一，后缀长度 1～256 字符；按大小写策略等价的重复后缀拒绝。非空但零命中可保存供未来型号使用。缺 variants 或空数组仅用通用配置；删除最后一项恢复纯通用配置。子项继承表示跳过本层，不跳回官方值。候选保存同时验证通用规则与每项合成规则，不能让未命中的子项藏入无效默认 / 档位组合；采用时再验具体协议和目标能力。具体数据结构仍由 WP-01 冻结，mock 的 rules.default 等扁平字段与示例的结构化字段不宣称是同一生产 schema。

## 3. 协议选项与配置字段

本机 OpenCodex 2.69.0 的 registry 核对见[调研依据](本地调研依据.md)。通用连接原型候选为 Responses / Chat Completions / Anthropic Messages / Google AI Studio / Ollama，标识分别为 `openai-responses`、`openai-chat`、`anthropic`、`google`、`ollama-native`。其他已注册适配器显示准确标识和“专用连接待接入”；不能因为 registry 中存在就用同一 API Key 表单伪装支持。

输出协议不参与匹配，可覆盖渠道默认。协议优先级为渠道默认 → 模版通用配置 → 命中的版本或后缀配置 → 渠道内模版族覆盖 → 单模型人工覆盖。端点单独负责连接与认证；通用或版本或后缀选协议都不自动创建连接。能力优先级为官方声明 → 模版通用配置 → 命中的版本或后缀配置 → 渠道默认 → 族覆盖 → 单模型覆盖。最终来源标明版本或后缀及 revision，不能让子项压过渠道或单模型例外。

| 配置 | 模版内设置与校验 |
|---|---|
| 名称 / 说明 | 自由名称、用途说明；稳定 ID 可复制，revision 显示另存身份 |
| 匹配规则 | 包含 / 排除、大小写、渠道范围、优先级；单独预览，不改白名单 |
| 输出协议 | 继承 / 自定义；合法 adapter，采用后核对目标端点、路由与参数表达 |
| 上下文窗口 | 继承 / 自定义正整数 tokens；声明不扩大真实窗口，不混同最大输出 |
| 输入模态 | 继承 / 自定义 text、image、audio 非空多选；未知不填，声明不赋予实际能力 |
| 可选推理档位 | 继承 / 自定义列表；none、minimal、low、medium、high、xhigh、max 是合法标签，不证明每个模型支持全套 |
| 默认推理档位 | 独立自定义，同时继承列表；具体目标必须属于最终列表，未知列表时入库为待目标校验规则 |
| Fast 能力 | 继承 / 支持（需依据）/ 不支持 / 未知；与已有全局 / 渠道 Fast 控制分开，不另建总开关 |
| 高级推理 | 显式隐藏档位、强制档、不传推理参数、声明模式；映射由 adapter 核对，原型没有通用映射编辑器 |
| 来源 / 未知项 | 资料、时间、人工或推断说明；不把模型名和发现清单当支持证据 |

默认与自定义列表不兼容就地报错；隐藏列表、none 档位和不传参数不同。强制档与不传参数冲突不能保存。库阶段可保留待核对项，采用到渠道必须按最终协议验证；官方 modelAdapters 只允许两个 OpenAI 值，其他协议需受管 provider 展开，不能写非法值。实际 Fast 派生行跟随父模型，白名单和两级顺序仍由策略文件维护。

## 4. 页面与后续操作

~~~text
模型模版列表：搜索、多选                    新建模版  外部 Agent 配置
  ├─ 新建 / 编辑为新候选
  │    内部导航：基本信息 / 匹配范围 / 族通用配置 / 版本或后缀 / 来源与版本
  │    左侧首位 Agent 自动填充 ↔ 非模态对话 ↔ 手动修改
  │    预览匹配 → 查看字段差异 → 保存候选版本
  ├─ 版本详情：只读摘要、匹配预览、比较、来源、版本操作
  │    设主版本（不升级渠道） / 归档 / 有依赖删除保护
  │    采用此版本 → 直接勾选目标渠道 → 保留例外 → 渠道草稿
  │    前往渠道模型 → 查看草稿 → 保存 → 待 Codex 重启核对
  └─ 外部 Agent 配置：范围 → 要求 → 复制提示词 → 返回批量结果
       整体校验 → 逐项前后比较 → 全批保存候选 → 明确采用
~~~

首屏不放常驻聊天或字段墙。新建建立编辑缓冲，取消不产生空模版；返回列表保留可继续编辑的缓冲。列表行内“编辑”直接打开新候选表单；有未保存缓冲时继续原编辑，不重新取主版本。模版名称与已引用版本入口保留只读预览，预览内也可编辑为新候选。点击编辑只建立缓冲，保存才新增 revision，不改旧版、主指针或渠道引用。编辑中切版本和版本操作先保存或取消，避免默默换基准。比较包含配置、匹配、说明及来源，改名独立展示。删除保护主指针、已保存 / 草稿策略及恢复 / 传入依赖；未引用候选可删除，归档规则仍供旧引用解析。

“保存模版”仅入候选库；“设主版本”仅改默认指针；“采用此版本”仅生成渠道草稿；渠道“保存”才提交运行配置。采用可直接选多个渠道，不要求先在另一 Tab 建范围；默认保留人工协议、指定端点等例外，清除须明确。精确单模型采用选择器仍待生产 / 后续补绘，当前已有引用解析可演示。

编辑器右侧按“基本信息、匹配范围、族通用配置、版本或后缀、来源与版本”连续展示五区，统一使用页面主内容滚动。内部左侧为可展开 / 收起的锚点导航，点击只滚动到对应分区，手动滚动同步高亮；不隐藏分区、不重建表单，也不改变全局路由。收起为带可读标签的短项，按钮及当前定位仍可辨；展开 / 收起保持可见锚点和编辑缓冲，同一对象重绘也保留可见位置。族通用配置集中协议 / 能力、推理、Fast 和高级字段；版本或后缀为空则不显示额外字段墙，新增 / 编辑弹窗“确定”只改当前缓冲，删除先确认。返回图标、可编辑名称、候选状态及版本操作合并为一行标题；Tab 滚过后标题贴住主内容区顶部，左侧导航和锚点定位随实际标题高度调整。名称直接在标题编辑，基本信息只保留说明；左侧导航下独立按钮区依次提供“Agent 自动填充 / 匹配预览 / 与主版本比较 / 更多操作 / 设置”，收起保留图标、tooltip 和可读标签，缺主版本的比较显示不可用原因。页底保留取消 / 保存候选，不为子项增加一套发布动作。只读版本页无内部导航，仍保留详情操作。公共 Select 继续进入最顶层。编辑页移除顶部设置 / 更多及 Agent 条，右下不保留启动器。标题贴顶补偿主内容上内边距，导航与锚点按标题实际高度及边框重新计算，窄窗换行不遮挡分区。

## 5. 编辑器内自动填充与连续纠偏

自动填充是新建 / 编辑内的辅助功能，从左侧导航下第一个“Agent 自动填充”文字按钮打开非模态对话面板，无遮罩；默认悬浮 360 × 480 px 并约束窗口可用高度，浮动模式页面操作与滚动可用；离开模型页隐藏。面板标题下用紧凑一行显示实际执行模型并提供配置入口，右上图标支持放大 / 还原与收起。放大铺满原型应用窗口；还原回悬浮尺寸，仅变更尺寸状态和图标，保留表单 / 聊天 DOM、输入 / 光标与聊天 / 正文位置。收起保留输入 / 消息并记住窗口内尺寸偏好，再开沿用，刷新重置；切模版输入 / 消息隔离，异步重绘继续套用尺寸。收起后焦点尝试返回左侧入口；窄窗 / 导航收起保留图标、tooltip 和可读标签。中部是角色消息 / 待比较结果，独立滚动；底部紧凑资料 / 上下文锁 / 导出与输入框、统一“发送”，可持续纠偏。提示词建议名称说明、渠道黑白名单、通用配置、后缀项及可表达的规则，显示来源 / 未知项与差异；接受只更新当前缓冲，再对话或人工调整。已保存版本先进入新候选编辑。

生成前检查独立执行模型设置，未配置 / 失效给配置入口并保留输入。输入 / 消息按模版隔离；每轮冻结基准、目标对象、执行身份和锁定字段，切到其他模版不让晚回切走当前页面。异步重绘保留输入焦点、光标与滚动；停止使晚回失效。返回做三方比较，期间手动改动保留，冲突列差异。当前 mock 对通用和每个版本或后缀的人工上下文窗口作锁定示例，删除含锁值的子项也受保护；variants 整个数组作为一个合并单元，双方均改时保留人工数组并提示冲突。正式逐字段 / 子项合并、可持久会话和并发多建议服务、检索及 runner 由 WP-06 承接。对话面板低于公共模态，Select 在其上；源码声明不替代真实遮挡 / 焦点验证。

内置流程聚焦当前一个模版；多个新增 / 修改走外部批量入口。执行模型与待分析模型分开，A6api 无额度，演示和默认验证不发送生成或额度探测。

## 6. 外部 Agent 配置与文件

这是与新建并列的独立按钮，可选当前、勾选、全部或仅新建。填写要求后生成可复制提示词，包含各目标规则 / revision、人工编辑缓冲、基准、字段类型 / 合法枚举 / 缺省继承约定、匹配契约、协议目录、纠偏摘要、锁定字段、端点可用性及人工例外、返回格式。外部 Codex 等工具无需此前聊天，使用自己的模型与检索。新建未保存对象先保存候选或选择仅新建任务，原缓冲保留。

| 文件 | 对外角色 |
|---|---|
| `manager-state/model-family-templates.json` | 拟新增；身份、版本规则和主指针；任务只允许新增身份 / 候选 revision，不改主指针 |
| `manager-state/model-policy.json` | 拟新增；渠道、顺序、白名单、精确引用和覆盖；任务只读摘要，采用另走渠道草稿 |
| `manager-state/model-policy-bindings.json` | 拟新增本机绑定；仅提供端点 ID / 协议 / 可用性摘要，无地址、认证、凭据引用 |
| `preferences.json` 的 `modelTemplateAgent` | 拟扩展本机执行偏好；不携带到外部任务，同步 / 全配置导出过滤仍待实现 |

返回可含多个 create / revision。原型“粘贴返回结果”提供批量示例填入，整体校验 taskId、范围、唯一 ID、新 revision、字段 / 规则、锁定值及当前库 / 缓冲基准；任一非法项拒绝全批。逐项比较后再次校验再全批入候选，取消无副作用，不自动主用、采用或写运行态。比较含名称 / 说明、匹配及配置。数字版本和 FNV-1a 摘要仅用于 mock；正式跨机 revision、规范化 digest、重放去重及原子落盘须共用服务冻结。

任务 / 结果契约须包含 channelMode、channels、通用规则及可选 variants，说明最长字面后缀、大小写和继承优先级。版本比较、复制、导出、导入及恢复保留这些字段。外部批次拒绝修改或删除已锁定的子项上下文。单模板导入到当前编辑身份仅形成建议缓冲，不改名称身份或主版本；旧输入缺 variants 保留当前子项，显式空数组表示清除请求，仍受人工锁与三方比较约束。该保守行为是 mock 编辑导入边界，正式全库导入由共同 schema / 版本服务处理。

生产支持外部输出结果文件，通过 CLI / UI 共同服务校验导入，不能裸覆盖旧 revision 或绕过检查改运行配置。外部可提出版本定义和说明，唯一身份由服务分配；CLI 命令、通信和文件 schema 尚未实现。原型展示路径职责和任务 / 结果 JSON，不写实际文件；复制由用户点击触发，剪贴板不可用则选中文本供手动复制。

## 7. 模型原始 ID、别名与显示名称

本机 OpenCodex 2.69.0 支持 provider.modelAliases 和 provider.modelDisplayNames，见[本地源码依据](本地调研依据.md#模型别名与显示名称核对2026-10-04)。modelAliases 的方向是原始上游 ID → 路由别名，路由解析别名后仍请求原 ID；modelDisplayNames 只声明显示文案，不修复协议或能力。内置 defaultAliases 默认为关闭，不能与自定义映射混称自动别名。此结论针对当前 OpenCodex，不能外推为官方 Codex config.toml 的任意映射能力。

~~~json
{
  "providers": {
    "newapi": {
      "modelAliases": {"Vendor-GPT_5.4-Custom": "gpt54"},
      "modelDisplayNames": {"Vendor-GPT_5.4-Custom": "GPT 5.4"}
    }
  }
}
~~~

别名仅字母 / 数字开头，余下允许字母、数字、点、下划线、连字符；大小写不敏感去重，与原生 / 组合身份冲突以及 gpt- / o1- / o3- / o4- / codex- 保留前缀须按当前读取器校验。不要用 gpt-5.4 当别名示例。

Desktop 候选把 naming.alias / displayName 放在渠道单模型策略，逐个映射到实际 provider；模板匹配、后缀、selectedModels、顺序和请求都保持 raw modelId。显示名称用于列表标签，原 ID 随时可看；别名只作路由快捷入口，不悄悄改已发布 catalog 身份。别名表单未补绘，Fast 衍生、目录预算、provider 分组和旧会话兼容须通过 G-10 / AC-M94 真实验证，不承诺改名能节省选择器条数。
