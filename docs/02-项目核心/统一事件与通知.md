## 边界与维护规则

- active表示已登记准入，不证明相关功能全平台、全入口实机已验；planned任务/事件不启动调度或投递，不能借登记启用0.2.0业务。
- 任务、领域事实、UI过程信号、持久通知分别管理。signal及无policy事件只校验，不保存任意payload或自动生成通知；成功不必弹通知，失败须有相应事实与用户反馈。
- 新事件补齐任务/触发源、对象/动作/阶段/通道、事实性质、状态、通知策略和解除列表，同时补真实GUI/CLI/观察/后台发出点及回归，再更新本核心页；未知ID、未注册组合和planned投递拒绝。
- EventIdentity由object、稳定object_id、action、phase、channel、candidate组成；稳定对象与候选使用不含路径的opaque UUID。成功只解除resolves明确列出且完整身份相同、时序合法的旧异常；已读/删除不等于已解决。
- 去重将dedupe与完整作用域绑定；同一未解决候选受持久cooldown约束，不以切页、切通道、重启或另一动作成功清除。无scope旧通知不能提供自动恢复证明。
- 先在副本验证，落盘成功再提交内存；通知保存注册文案/摘要及必要身份，不保存日志、凭据、完整路径或任意远端响应。当前不提供用户自定义通知注册编辑器。

## 调度时间与多入口合并

| 对象/情形 | 当前合同 |
| --- | --- |
| 启动 | UI就绪后45秒评估到期，先读持久状态；启动不等于联网 |
| 管理器stable / beta | 周期86400 / 21600秒，通道独立状态 |
| OpenCodex面板 | 86400秒；管理器切通道不清面板缓存、退避和在途事务 |
| 失败 | 300→1800→7200秒，后回对象正常周期；恢复/路由不绕过截止 |
| 查询启动 | 先持久reserve截止再执行；每对象single-flight、自动串行、手动复用在途 |
| 关闭自动检查 | 不安排新的自动检查，手动保留 |
| 状态位置 | manager-state/update-schedule.json；cache/updates元数据可清，不同时清截止/去重 |
| 挂起与时钟 | 只处理当前到期、不补历史周期；异常未来截止按原预算纠正后先落盘 |

这里只描述冻结合同与代码，不把真实周期、请求/子进程计数、休眠或主线程等未验项写为通过；已证子集和人工接受范围以IMP/REL证据为准。

## 接线与证据责任

0.1.10基线登记87个发出点、8个调度点、9个UI反馈组；0.2.0追加6个发出点，当前合计93个发出点，调度点和UI反馈组不变；路径/清理的owner仍须由所属模块真实消费，登记不是完整接线或行为验收证明。生产调用点和检查引用同SHA注册表及原回归，过程证据归IMP/协作包，完整发布状态归REL/RUN。新增接口/平台/事件要同步核对注册、发出点、投递/解除、脱敏和恢复，不仅增加一行表格。


### 0.2.0接收记录与采用的任务观察身份（2026-10-20）

模型文件接收/统一WebDAV下载开始时可有临时观察ID；校验成功生成durable incomingId后，沿既有注册model-operation-progress信号携previousId（仅UUID、不含路径/配置/秘密）将同一在途transfer观察绑定到接收记录。后续采用/失败重试使用incomingId更新同一张卡。UI只允许在途transfer→review的身份绑定，不接管其他任务，已有终态不被重复接收降级；采用/重试重新进入running后再更新终态。业务接收/持久回执仍归原同步服务，任务卡不作为可移植事实或另一通知宿主。原生现场已验证采用后只一张已完成卡，不遗留旧“待比较采用”。


## 0.2.0模型事件注册增量（2026-10-21）

本版新增一个active任务model_config（允许user/commit），6个事件和2个通知策略。当前合计40任务、87事件、29通知策略、93发出点、8调度点、9UI反馈组、12路径和4清理策略。未修改的0.1.10条目继续使用上方基线，不因该计数宣称延期业务已启用。

所有新增事件归model_config/configuration/local。signal仅经共同入口校验后发给现有UI宿主，不建立持久通知；failure与success经同一publisher按完整身份投递/解除。

| 事件 | action / phase / fact | 策略或解除 | 真实发出点与消费 |
| --- | --- | --- | --- |
| model-config-changed | save / commit / signal | 无策略 | broker.rs::announce在持久候选提交后发出；模型快照刷新保留未保存缓冲，不代表自动采用 |
| model-operation-progress | observe / progress / signal | 无策略 | feedback.rs::progress，生成、资料、外部提交、运行保存、传输和节点检测均交现有TaskProgressHost；接收换incomingId仍为同一观察 |
| model-template-external-failed | save / execution / failure | model_external_failure | feedback.rs::external_terminal，由经过认证/范围校验的外部提交终态驱动，绑定taskId及submissionId |
| model-template-external-succeeded | save / execution / success | 仅解除同身份model-template-external-failed | 同external_terminal；新submission或不同task不能解除旧风险，成功不额外制造通知 |
| model-policy-save-failed | save / execution / failure | model_policy_failure | commands/model_config.rs::observe_policy核对原plan未完成或不确定；prepare/只查看不算写入失败 |
| model-policy-save-succeeded | save / execution / success | 仅解除同身份model-policy-save-failed | 原plan真实committed或compensated才提供成功证据；补偿完成不冒称目标配置已应用 |
| model-policy-save-blocked | save / execution / risk | model_policy_blocked | commands/model_config.rs::model_policy_save_blocked 只接收固定原因枚举；同一原因更新同一条，不同原因各自成条；用户删除后不复活 |

| 新策略 | 用户可见标题 / 动作 | 冷却与去重 |
| --- | --- | --- |
| model_external_failure | 外部模版提交需要处理 / models入口，携原task及submission身份 | 86400秒；model-template:external-failed结合完整作用域 |
| model_policy_failure | 渠道配置保存需要核对 / model_policy“查看保存结果”，绑定原plan | 86400秒；model-policy:save-failed结合完整作用域 |
| model_policy_blocked | 模型配置未保存 / models 入口回到模型配置 | 1秒；model-policy:save-blocked结合完整作用域与固定原因 |

两策略均warning/system/user_action，沿现有持久存储及铃铛/诊断历史；不由页面临时字符串创建通知。投递失败只写安全诊断，不改变业务提交结论。通知和日志不接收prompt、配置、Key、来源URL、私聊或原始远端异常；UI过程载荷仅UUID id、kind、phase和适用previousId，拒绝未知字段。进度进入review表示需要查看相应领域结果，客户端加载状态继续由客户端owner提供。

任务卡收起只改视图。内存显示预算超过24时只移除已完成或已停止项，running/review/failed不能因为数量或收起被驱逐；这不是独立持久任务队列。页面返回/启动恢复继续从领域计划、候选/接收回执重新接管，不把卡片当作便携事实。外部重复提交、旧任务晚回、原plan再核对都按原身份更新，不能接管另一任务或把较新目标标为生效。

### 0.2.7 追加：保存确认被拦下（2026-10-23，原型）

新增一个事件 `model.policy.save.blocked`，与 `model.policy.save` 分开：后者表达保存事务的过程与结果，本条只表达“这次确认没有写入”。**原型与生产均已登记**：生产侧事件 ID 为 `model-policy-save-blocked`（`event-registry.json`，risk / `model_policy_blocked` 策略），由命令 `model_policy_save_blocked` 接收固定原因枚举后投递；2026-10-24 起生效。真实桌面端投递仍待实测。

| 事件 | action / phase / fact | 通道与去重 | 脱敏与边界 |
| --- | --- | --- | --- |
| model.policy.save.blocked | user.action / — / warning（一次性） | toast + center；固定原因去重，同一原因更新同一条 | 只接收固定原因枚举与发生时间；不接收计划、渠道名、URL、Key 或原始异常 |

原因取门禁顺序的第一条：连接编辑未入草稿 → 行编辑未入草稿 → 投影超预算 → 校验未通过（带首条错误）→ 没有未保存修改 → 条件已变化。行为契约见 [UI 规范 §38](UI规范.md#38-模型保存即预览与拦下通知2026-10-23)；当前登记不影响本页“合计”计数所依据的生产注册表，新增生产事件须按本页“接线与证据责任”补齐发出点、消费与回归后再改计数。

本版新增注册对与调用点已有共同注册回归、前端任务并发/收起/身份转换及实际模型保存通知→核对→解除证据。完整运行/平台验收及发布结论仍由IMP/REL记录；本页更新只纠正事实入口，不把静态计数或表格变成设备通过证明。后续原型提示归浮动注释，真实产品反馈按表单/短反馈/任务/通知既定职责登记后复用，禁止另造宿主或绕过publisher。
