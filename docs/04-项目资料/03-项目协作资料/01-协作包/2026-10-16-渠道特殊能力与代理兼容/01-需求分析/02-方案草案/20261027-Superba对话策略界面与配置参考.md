## 2. Superba 实际如何组织界面

### 2.1 提供方连接页

提供方详情使用“连接 / 账户”页签。连接页组织线路、传输检测、认证和密钥、远程压缩状态，以及跳转模型页和设置页的摘要。认证行的手动选择收在其 Advanced 区；远程压缩行使用自己的“更改”展开入口，不能把两者说成同一个高级策略面板。

远程压缩行显示有效支持状态、结果来源和检测信息，并提供“检查”。展开选择后，实际选项为：

- `CompactionChoice::Auto`：自动。
- `CompactionChoice::Native`：原生支持。
- `CompactionChoice::Unsupported`：不支持。

选择变化时，代码克隆 profile，修改 `profile.compaction`，发出 `Action::SaveProfile { profile, key: None }`，随后使界面缓存失效。这里直接证明的是 profile 字段保存意图，不能直接证明它写成某个 Codex 协议值或立即重启。见 S1。新建表单使用 `Default::default()` 初始化该字段；此次未读取枚举定义，不能仅凭此语句断言其具体默认枚举值。

WS 与 zstd 在每条线路上表现为检测徽章，展示支持、不支持、未知、检查时间和结果详情，徽章本身不是启停开关。页面包含自动或手动刷新检测的逻辑；本次研究没有触发这些动作。见 S2。zstd 是传输压缩检测，不能与对话上下文压缩混为一谈。

### 2.2 通用设置页

设置页由分类栏、字段列表和详情编辑器组成，详情显示说明、默认值、当前值、推荐值、版本可用性及编辑控件。数据来自匹配的 Codex 版本 catalog；布尔、枚举、数值、文本等按类型编辑，变化先进入逐字段 pending。

在本次读取的 UI、pending、保存及配置计划中，没有发现将 WS、远程压缩、history/notes、token budget 或 async 组织成互斥组合的逻辑。说明中出现的“自动打开”不能转述为 Superba 编辑器会联动改写其他字段。

Advanced 主要按生命周期扩展显示开发中、废弃、移除和旧键；已配置、正在编辑或有推荐值的条目仍可显示。源码另把 `tui.keymap.*`、`otel.*`、`notice.*` 这类大字段族收在 Advanced 后面，没有把上下文相关字段整体硬编码为一个高级面板。见 S5、S6。

通用列表还排除了 `under_map` 的子项。因此，`model_providers.<name>.*` 出现在 overlay 中，不代表它们全部成为现成的逐 Provider GUI 控件。见 S6 同文件 L455–473。

## 3. 字段、默认值与说明边界

### 3.1 提供方协议与 endpoint

以下协议语义和默认来自 S3 的 overlay 说明，不等于提供方连接页三态到 Codex 配置的完整映射已经核实。

| 完整字段 | 选项、默认或说明 |
| --- | --- |
| `model_providers.<name>.capabilities.remote_compaction` | `v2` / `unsupported`；省略保留供应商默认。说明称 OpenAI、Azure Responses 默认 `v2`，其他自定义供应商默认 `unsupported`。 |
| `model_providers.<name>.capabilities.remote_compaction = "v2"` | 通过 Responses endpoint 发送 `compaction_trigger` 项，由服务端压缩。 |
| `model_providers.<name>.capabilities.remote_compaction = "unsupported"` | 改用本地压缩，由 Codex 自己请求模型生成摘要。 |
| `model_providers.<name>.base_url` | 通用 API 基础地址；说明举例 `<base_url>/responses`、`<base_url>/models`。未配置时回落到 OpenAI 地址，API key 登录示例为 `https://api.openai.com/v1`。 |
| `model_providers.<name>.wire_api` | 说明称默认且目前只支持 `responses`；旧 `chat` 已移除，配置会报错。 |
| `model_providers.<name>.supports_websockets` | 布尔；说明称自定义供应商默认 `false`，内置 OpenAI 默认支持，不能与 `aws` 同用。 |
| `model_providers.<name>.websocket_connect_timeout_ms` | 说明默认 `15000` 毫秒。 |

本次限定源码中没有核实到独立的“压缩 endpoint URL”字段或输入框。这里能够引用的是通用 `base_url` 和 `v2` 使用 Responses endpoint 的说明，不应自行补出 `/compact` 等接口事实，也不应把 `Native` UI 选项直接等同于上表的 `v2` 写入。

### 3.2 上下文、历史与笔记

以下条件和数值来自 S4 的 overlay。它们描述对应 Codex 配置的意图，不代表本项目已具备同样运行能力。

| 完整字段 | 已核对的说明与默认边界 |
| --- | --- |
| `features.context_management.experimental_mode` | 实验性上下文管理。说明要求 ChatGPT Plus/Pro、内置 OpenAI 和支持的模型；生效后自动启用 token budget 及 history/notes。未在本次 overlay 中确认布尔默认。 |
| `features.token_budget.enabled` | 开启模型可见的上下文预算信息；本节其他设置开启后生效，部分默认可由模型目录提供。未确认固定布尔默认。 |
| `features.token_budget.use_history_notes_extension` | 提供压缩前历史窗口浏览、搜索和笔记文件读写。说明要求 OpenAI 供应商及 ChatGPT 后端认证；实验性上下文管理会自动打开。未确认固定布尔默认。 |
| `features.token_budget.guidance_message` | 最长 2000 字节；留空不附加。 |
| `features.token_budget.reminder_threshold_tokens` | 正整数；未设置不提醒，除非模型目录提供默认。 |
| `features.token_budget.reminder_message_template` | 非空，最长 2000 字节；支持 `{n_remaining}`，未设置用内置模板。 |
| `features.token_budget.auto_compact_fallback_prompt` | 最长 2000 字节；说明要求同时设置下面的缓冲 token 数。 |
| `features.token_budget.auto_compact_fallback_buffer_tokens` | 正整数；说明称只在设置 fallback prompt 后生效。 |
| `model_context_window` | 覆盖模型目录窗口值，但受目录声明的最大窗口约束；说明称实际可用通常为窗口的 95%。 |
| `model_auto_compact_token_limit` | 说明默认窗口的 90%；按 `total` 计数时显式值也不会超过该上限。 |
| `model_auto_compact_token_limit_scope` | `total`（说明默认） / `body_after_prefix`；说明称达到完整模型窗口时仍会强制压缩。 |
| `compact_prompt` | 本地压缩提示词，优先于 `experimental_compact_prompt_file`；远程压缩不使用它。 |
| `experimental_compact_prompt_file` | 本地压缩提示词文件；说明称无法读取或内容为空时加载报错，已设 `compact_prompt` 时以后者为准。 |
| `model_post_turn_compact_threshold_percent` | 轮次最终回复结束后的压缩阈值，`0–100`；省略或 `0` 关闭，原自动压缩阈值仍有效。 |

默认值必须分清来源：feature 的默认由匹配版本 catalog 的 `default_on(os)` 提供，普通配置默认由 catalog key 的 `default` 提供；未设置时还可能由模型目录或运行端决定。UI 的布尔显示兜底不能当作运行默认，更不能把未核实值统一写成 `false`。见 S6 同文件 L734–811。

对 `async/后台压缩`，本次限定范围没有核实其确切注册字段、默认值或专用组合 UI。此结论不等于 Superba 或上游不存在该能力；本文件不补造字段。

## 5. 本项目采用的组织与能力边界

### 5.1 最终入口组织

本轮确认采用“设置 → 对话策略”，其下组织：

1. **模型与工具**：原“全局设置”的全部内容迁入此处，避免只迁移部分字段而遗留另一套全局入口。
2. **上下文**：当前原型承载上下文模式、压缩协议和可选阈值；预算提醒、提示词等保留为参考候选，不在本轮冒充已补绘字段。
3. **连接**：承载连接相关策略；协议配置仍按 Provider 单独保存和解释。

对话页仅保留项目与对话树、当前层覆盖。全局默认从“设置 → 对话策略”管理，本层未覆盖的部分按继承链生效。此信息架构是本项目设计，不是 Superba 页面结构的复刻。

### 5.2 上下文模式是本项目的互斥预设

| 模式 | 本项目设计含义 |
| --- | --- |
| 跟随默认 | 保留当前 Codex 与 Provider 默认，不额外固化另一套功能值。 |
| 常规压缩 | 使用常规压缩预设，具体键级映射以本项目后续实现确认。 |
| 后台压缩 | 使用后台压缩预设，后台能力与调度映射尚待确认。 |
| 历史与笔记 | 使用历史与笔记预设，需要实际 history/notes 接入支撑。 |

这四项是本项目选择的互斥预设。不能在需求、界面说明或实现注释中写成“Superba 原生互斥四模式”。Superba 此次可证实的是字段编辑与说明文本，不是这套模式切换器。

预算、提醒、fallback 等字段可以为预设提供细节，但预设需要如何设置或清理底层字段，仍须以当前 OpenCodex 的实际能力确认。本文件不把说明中的自动启用关系转写成已经实现的联动。

### 5.3 协议按 Provider 单独配置

本项目采用以下选择语义：

- **跟随默认**：使用该 Provider 的默认行为。
- **原生远程压缩**：声明使用 Provider 原生远程压缩能力，须对应真实 native 链路。
- **客户端压缩流程**：由客户端组织压缩请求、摘要及上下文替换流程。即使流程调用远程模型，也不能因此标成 Provider native。

该协议维度与上下文模式分开表达，不能把供应商能力声明与用户的上下文预设合成一个选项组。是否支持 WS、是否需要降级以及与压缩流程如何协作，应按 Provider 和当前实现解释，不能凭 Superba 的检测徽章推导通用互斥规则。

当前 OpenCodex 的第三方 summary 属于非 native 流程，不能标注为“原生远程压缩已接通”。history 入口尚未接通，不能把“历史与笔记”预设或原型的存在写成该能力已经可用。

### 5.4 后台执行与轮末触发独立说明

“后台”描述压缩如何调度、执行以及是否影响交互等待；“轮末”描述在一轮最终回复结束后何时触发压缩。两者不是同义词。

`model_post_turn_compact_threshold_percent` 仅可据已读说明表述为轮末阈值，不能据此宣称已实现异步或后台压缩。四种模式中的“后台压缩”是本项目预设；轮末阈值是需要单独解释的参数。其适用预设、字段映射和运行支持待开发确认，不能在原型中暗示两者必然同时开关。

## 6. 可以借鉴与不照搬的部分

可借鉴的 UI 包括：能力状态与来源同列展示、自动判断与手动覆盖分开、配置默认与当前覆盖分开、显示字段版本可用性、修改进入待保存状态，以及将保存和应用结果明确反馈。

本项目不照搬提供方自动探测行为，不把线路徽章当成连接开关，不把所有 overlay 条目当成已存在的 GUI 控件，不把三态 profile 字段直接当作压缩 endpoint 或 Codex 协议写入，也不复制要求官方登录的能力承诺。

本项目的入口迁移可以依据已确认信息架构推进；上下文能力的具体版本、开发时机、后台字段映射、native 链路和 history 接入仍待确定，不绑定旧 `0.2.0`。本参考文档不要求修改旧索引、共享原型或已有方案来伪造实现进度。
