## A. 本轮直接欠账（WP-59～WP-62）

### A1 保存即预览：合并入口

| 项 | 内容 |
| --- | --- |
| 原型 | 列表顶部与渠道详情都只有一个保存；点击后打开“保存 · 选择器预览” |
| 软件现状 | `ChannelsView.vue` L25 `previewOpen` / `previewSource`；L176 Tab 右侧仍有独立 `UiButton`「预览选择器」；`ChannelEditor.vue` L67 actions 同样有「预览选择器」；保存走 `prepareSave()` → `saveOpen` 的 `UiDialog`「确认保存渠道配置」 |
| 要做 | 删两处预览按钮与 `previewOpen` / `previewSource`；保存即打开预览；不得保留“预览”和“确认保存”两张弹窗（确认页里 `removedProviders` / `catalogCount` / `routeChanges` 等必须核对的项并入预览或随写入结果呈现，不能静默丢弃） |
| 验收 | 列表与详情各只剩一个保存入口；无「预览选择器」文案与动作残留；点保存即见完整顺序；确认后直接开始写入 |

### A2 预览固定当前草稿：删除来源切换与数量折叠

| 项 | 内容 |
| --- | --- |
| 软件现状 | `SelectorPreviewDialog.vue` L48「预览来源」`UiSelectField`（draft / saved）；L56「按渠道查看数量」`details`；标签与 aria 仍含该文案 |
| 要做 | 删除来源控件、`emit('update:source')`、`source` prop 与 saved 分支；删除数量折叠区；保留编号顺序、渠道顺序、内部顺序与 Fast 标记 |
| 验收 | 弹窗内无来源控件、无数量折叠；读屏与 title 中无“预览来源”；切换草稿不再是预览的一部分 |

### A3 弹窗内快速启停

| 项 | 内容 |
| --- | --- |
| 软件现状 | `SelectorPreviewDialog.vue` 预览项是只读 `span`，没有任何启停入口 |
| 要做 | 渠道整行成为操作条（眼睛图标 + 右侧“停用 / 恢复”）；停用后整组隐藏并保留恢复；型号标签可单独启停；操作写入 `models.channelDraft`，与列表 / 详情同一份草稿 |
| 验收 | 弹窗内改动进入同一草稿；关闭保留；与列表启停结果一致；不产生第二套状态；原生渠道仍只读 |

### A4 变更内联：删除差异清单

| 项 | 内容 |
| --- | --- |
| 软件现状 | 预览不展示变化；变化在 `savePlan` 的 `runtimeChanges` 等区块里 |
| 要做 | 按 `policyChanges.ts` 计算本次启停：渠道卡琥珀描边 +“改”，悬浮 / 聚焦显示一行；型号标签“新 / 停”；其余字段变化折叠为“另有 N 项字段变化”（最多 8 条）；**保留** `runtimeChanges`、`routeChanges` 这类必须核对的安全信息，改为折叠而不是删除 |
| 验收 | 无“本次变更与写入 / 协议写入计划”整块；启停不再重复列；协议 / 地址 / 别名变更仍可查 |

### A5 确认即关闭

| 项 | 内容 |
| --- | --- |
| 软件现状 | 确认后 `saveOpen` 保持打开，直到执行阶段才收敛 |
| 要做 | 点击确认先 `close`，再冻结草稿并调用保存；不得停留在弹窗内看进度 |
| 验收 | 点击后弹窗立即消失；进度与结果只在任务卡 / 通知中心；再次点击不会重复提交 |

### A6 拦下原因走已注册通知

| 项 | 内容 |
| --- | --- |
| 软件现状 | 失败写在 `saveOpen` 弹窗内的 `model-error`；`notifications/registry.rs` L574～585 `SupportedEvent` 只有 `model-policy-save-failed / -succeeded / model-config-changed / model-operation-progress / model-template-external-*`，没有 blocked 事件 |
| 要做 | ① Rust 注册表新增 `model.policy.save.blocked`（warning、toast + center、按固定原因去重）；② 在 `model_config` 发出点产生该事件；③ 前端删弹窗内错误块，改经公共 publisher 投递；④ 原因取门禁第一条（连接未入草稿 → 行未入草稿 → 超预算 → 校验首错 → 无未保存修改 → 条件已变化），不得携带计划 / 渠道名 / URL / Key；⑤ 同原因更新同一条，用户删除后不自动复活 |
| 验收 | 干净草稿确认 → 弹窗关闭 + 通知“未写入 + 草稿保留”；待确认编辑 / 超限 / 校验失败同理；通知详情能回模型页；生产注册表可查到该事件；不新增第二个错误表面 |

### A7 弹窗内启停后第一次确认必须成功（回归）

| 项 | 内容 |
| --- | --- |
| 背景 | 原型侧刚修过同类缺陷：弹窗打开时记下草稿指纹，确认时又比对当前草稿，导致“预览里点一下就判成基准漂移，第一次保存必失败” |
| 要做 | 软件侧确认 `preparePolicy` 的 baseline 只校验**已保存版本 / 库摘要**，不把弹窗内的启停算作漂移；写入时使用确认时刻的草稿快照 |
| 验收 | 打开预览 → 启停渠道与型号 → 直接确认，一次成功且写入的正是刚才的改动；打开后改回原样再确认，按“没有未保存修改”拦下 |

## C. 样式与组件约束（不得自由发挥）

本节是防止实现阶段走偏的硬约束，逐条可由 review 直接判定。

| 约束 | 要求 |
| --- | --- |
| 组件复用 | 按钮 / 弹窗 / 下拉一律 `UiButton`、`UiDialog`、`UiSelectField`；不新写第二套按钮或下拉 |
| 尺寸 | 页级与弹窗动作 md 34px；行内 sm 28px；不因“看起来大”自行改字号或内距 |
| Token | 圆角用 `--radius-2xs/xs/sm/radius/lg`；字号用 `--text-micro/caption/label/control/body`；阴影 `--shadow/--shadow-sm`；色只用语义 Token（`--amber` / `--green` / `--red` 及 soft） |
| 禁止 | 新样式里出现裸 `px` 圆角、裸 `#hex` 投影、`z-index` 魔数、`font-size:10px` 这类硬编码 |
| 状态色 | 颜色只表达启停或风险；Fast 能力必须配文字，不用颜色推断 |
| 文案归属 | 实现过程说明（备份 / 写入 / 重启、操作讲解）不进正文，按 UI 规范 §36 处理；真实错误与业务结果必须保留 |
| 无障碍 | 停用 / 恢复、标签启停需可键盘操作并带 `aria-pressed`；悬浮说明依赖 hover 时必须同时有 `focus-visible` |
| 长按与点击 | 长按只用于“看说明”，与启停是两件事；长按后抬手必须吞掉该次 click。实现约束见 UI 规范 §38.3.1 |

### 2026-10-24 第六轮（模型行与过滤区实屏：元素挤在一起 / 不垂直居中）

**触发**：用户在软件里看模型列表，报「模型都挤到一起了，元素不能垂直居中对齐」，随后更正为「是表格元素挤到一起了，不是模型」，并要求后续表格都守这条。

复现后确认是两条具体样式缺陷，不是观感问题：

| 缺陷 | 真因 | 实测 |
| --- | --- | --- |
| 行内容贴顶、三列各自为政 | 模型表把 `td` 写成 `vertical-align:top`（唯一一处这样覆盖的表） | 勾选中心 −1.5px、启停 −11.9px、操作 0（相对整行中心） |
| 摘要五段挤一行 | 摘要 `display:block`，无分组行 | `grid-template-columns:none`；原型是两行 `.mp-model-meta-line` |
| 操作组横向溢满 182px | 排序箭头用并排 `UiButton`（共 59px），原型是 22px 竖排迷你对 | 组 `scrollWidth=166`，右侧越界 |
| 过滤区高低不一、「仅启用」被推远 | 全局 `.model-toolbar input{flex:1;min-width:180px}` 命中复选框，13px 勾选被撑到 180px | 勾选框实测 180px → 修正后 13px |
| `Fast未知` 等自造文案 | 实现自拼摘要，原型是 `推理 …` / `快速 …` | 改回前缀式 |

**修法**：严格照原型 `.mp-model-row` —— 单元格改 `middle`、行内 `padding-block:12px`、启停与操作列去掉横向内距；摘要改两行 grid（`gap:4px`，行内 `gap:4px 12px`）；启停列改竖排居中的 `.model-enabled-cell`；箭头改 22×18 竖排迷你按钮；勾选列复选框与抓手并排居中；`.model-toolbar` 的输入选择器限定到搜索框。

### 2026-10-24 第七轮（WP-57 真机缺陷：拖拽框选 + drop 不触发 → 改指针拖拽）

**这一轮的性质变化**：WP-57 原登记为「拖拽误框选文字」，只做了 `user-select` 局部收紧；
本轮在**隔离沙盒的原生窗口**里真拖模型行，发现它其实是两个缺陷，其中第二个是阻断级的。

| 缺陷 | 证据 | 影响 |
| --- | --- | --- |
| 拖拽时整片文字被框选 | 原生窗口截图：表头被框成蓝色，导航与状态文字也被选中 | 观感崩坏，且松手后选区残留 |
| `drop` 从不触发 | 事件埋点：`dragstart` 1 次、`dragenter`/`dragleave` 抖动 13 次、`drop` **0** 次 | 排序**静默失败**，用户只觉得「拖了没反应」 |

关键判断：**不能靠再测一次 Chromium 收口**。Chromium 100% 通过，而 Playwright WebKit 约 1/3 轮次掉 `drop`——
同一动作在同引擎下不稳定，说明这是引擎/时序敏感，真机凑齐「滚动容器 + 行在视口内 + 指针采样」就会掉事件。

**修法**：新增 `pointerDrag.ts`（Pointer Events 实现），模型行与渠道行共用。

| 机制 | 取值 / 行为 | 理由 |
| --- | --- | --- |
| 起点阈值 | 5px | 未过阈值仍按点击处理，不吞点击 |
| 起手排除 | 按钮 / 输入 / 下拉 / 链接 / label / 可编辑区 | 正常交互优先，不抢控件的按下 |
| 落点判定 | `elementFromPoint` 取 `tr[data-item]` | 不依赖引擎投递 `drop` |
| 禁选 | 拖拽期间 `<html>.ocx-pointer-drag` 整体 `user-select:none`，松手移除 | 拖一路不框住一路文字，正文仍可复制 |
| 收尾 | `pointerup` / `pointercancel` / `Esc` | 三条路径都不留半透明行与高亮 |

**验证**：

| 层 | 结果 |
| --- | --- |
| 新增 `tests/pointer-drag.test.ts` | 4 项：阈值、起手排除、Esc 取消、未允许时不接管 |
| 前端全量 | **768 通过 / 10 跳过** |
| `audit:geometry:webkit`（新增，36 项） | 全过；**连续 3 轮稳定**（修复前约 1/3 轮次失败） |
| `audit:geometry`（Chromium，44 项） | 全过 |
| `gate:release` | **17 通过 / 0 失败 / 0 跳过** |
| 后端 | `cargo test --lib` 967 通过 / 3 忽略；`cargo test --tests` 38 个二进制全 ok |
| 原型回归 | 192 通过 / 0 失败 |

**仍缺**：原生 WKWebView 窗口的人工复核（复核中途本机锁屏）。自动化已覆盖同引擎族的同一动作，
但按本项目口径，原生窗口这一项没做完就不算通过；解锁后重跑「拖模型行 + 拖渠道行 + Esc 取消」三步即可收口。
