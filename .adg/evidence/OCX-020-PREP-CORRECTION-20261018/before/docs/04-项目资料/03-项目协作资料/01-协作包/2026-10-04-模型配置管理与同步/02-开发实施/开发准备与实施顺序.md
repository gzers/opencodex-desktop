| 顺序 | 输入与交付 | 可并行工作 | 完成证据/下游条件 |

### 7.2 问题清单（按严重程度排序）

#### P1 阻塞（2项）

1. **Schema中revisionId生成时机不明确**
   - **影响**：冲突检测缺乏唯一标识，无法确定哪版优先
   - **当前状态**：方案草案中提及revisionId但未定义生成规则
   - **解法**：
     - 首次创建时revisionId = null（容忍阶段）
     - 首次修改时生成UUIDv4，存储于manifest.revisionId
     - 传输前必须非null（外部同步/备份前强制补全）
   - **依赖**：无
   - **验收**：ConfigValidator允许首次null，修改时必填；digest测试含补全逻辑

2. **Manifest字段职责边界未定**
   - **影响**：备份/恢复时双文件同步逻辑混乱，可能导致数据不一致
   - **当前状态**：Manifest包含fileType/digest/revisionId/timestamp，但未规定各字段归属
   - **解法**（双文件各含manifest，职责闭包）：
     - model-policy.json: `{ manifest: { fileType: 'policy', digest, revisionId, timestamp, authority }, data: {...} }`
     - model-templates.json: `{ manifest: { fileType: 'templates', digest, revisionId, timestamp, authority }, data: {...} }`
     - 备份/恢复时分别处理，不跨文件查询
   - **依赖**：解法1（revisionId定义）
   - **验收**：双文件序列化/反序列化的集成测试，不同时间修改两文件后仍能正确恢复

#### P2 重要（3项）

3. **WebDAV凭据明文存储风险**
   - **影响**：安全性达不到线上标准，泄露风险高
   - **当前状态**：同步与备份方案中提及WebDAV但未规定凭据加密
   - **解法**：
     - 使用Electron safeStorage加密存储（自动处理系统钥匙链）
     - model-policy.json/model-templates.json的manifest字段中指定excludedFields，标记password/token字段不持久化到本地
     - 首次连接时从用户输入获取，存入内存+safeStorage；断开连接时清空内存
   - **依赖**：解法2（Manifest字段职责）
   - **验收**：Electron dev-tools检查storage不含明文密码；集成测试验证断开连接后内存清空

4. **4类真实存量迁移策略缺失**
   - **影响**：用户0.1.10现有数据无法平滑升级，升级流程失败
   - **当前状态**：没有分清已发布用户数据、既有运行配置、旧导出格式及原型示例
   - **解法**（MigrationHelper实现4类策略）：
     - **策略1**（本地旧配置）：读取0.1.10本地policy/templates → ConfigValidator验证 → 补digest/revisionId → 写入0.2.0位置
     - **策略2**（备份恢复）：使用旧backup清单 → 字段映射到新manifest结构 → 隔离测试验证
     - **策略3**（导出文件）：对旧导出格式做兼容性检查，失败时留原文件不操作
     - **策略4**（原型示例）：标记为内置示例，不作为用户数据处理
   - **依赖**：解法1、解法2（revisionId + Manifest结构）
   - **验收**：4类存量迁移成功率100%；迁移前后数据对比无丢失；旧文件保留，新文件独立存储

5. **通知框架F01-F06各环节的类型安全问题**
   - **影响**：运行时类型错误、隐式any泄漏导致不可预期的行为
   - **当前状态**：统一通知注册盘点中提及框架问题但未给出具体类型定义与守卫
   - **解法**：
     - **F01 NotificationPublisher**：统一NotificationPayload类型（不使用any）
     - **F02 ModelNotificationAdapter**：类型守卫检查payload来源
     - **F03 TaskOwnerPanel**：队列持久化时的序列化/反序列化验证
     - **F04 toast/task分离**：isBroadcast/isTask字段明确类型，不用隐式判断
     - **F05 领域模型对齐**：移除隐式any，明确字段类型
     - **F06 生命周期测试**：3个场景（正常流程/异常中断/恢复）的类型验证
   - **依赖**：无
   - **验收**：tsc严格模式下无implicit any；单元测试覆盖Publisher/Adapter/TaskOwnerPanel的类型守卫

#### P3 一般（2项）

6. **同步与备份的外部传输时机不明**
   - **影响**：不清楚何时触发WebDAV同步、冲突如何检测，可能导致重复或丢失
   - **当前状态**：同步与备份方案提及冻结本地但未定义触发机制
   - **解法**：
     - 冻结本地后触发外部操作（serialization完成 → digest确认 → 推送到WebDAV）

     - 冲突时记录log，按§6.4选择的策略处理
   - **依赖**：解法1、解法4（revisionId + 冲突策略）
   - **验收**：集成测试验证三场景（首次推送/更新推送/冲突检测），日志记录完整

7. **旧版本(0.1.10)兼容性校验方案缺失**
   - **影响**：升级时无法快速判断旧版本是否可升级，影响用户体验
   - **当前状态**：没有定义0.1.10 → 0.2.0的兼容性检查
   - **解法**：
     - MigrationHelper预检查：读取0.1.10的policy/templates → 版本号比对 → 判断是否需迁移
     - 检查失败时记录错误并返回降级建议（e.g., 手动备份 → 重新安装）
     - 成功时执行对应策略（见问题4）
   - **依赖**：解法4（MigrationHelper）
   - **验收**：单元测试覆盖升级前检查的3个场景（兼容/需迁移/失败）
