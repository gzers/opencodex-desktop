## 一条链路、两段传输

通过本地代理时，链路为 `Codex 客户端 → OpenCodex 本地代理 → 已选上游渠道`。第一段是客户端到本地代理的入口，第二段是代理到上游的传输；两段可以不同。直连 provider 则由客户端直接连接其上游，不涉及本地代理入口设置。

| 场景 | 客户端 / 本地入口 | 代理到上游 | 说明边界 |
|---|---|---|---|
| OpenCodex 本地代理，显式优先 WS | 同时声明客户端可尝试 WS、开启本地入口 | 仍由原版版本、渠道和请求条件决定 | 本地 WS 接入成功也不证明上游 WS |
| 经 OpenCodex 2.84.0 访问 Krill 等第三方 | 本地入口可能配置为 WS；实际需观察 | Krill 上游仍为 HTTP/SSE | 不标记 WS 贯通，不用入口偏好覆盖第三方限制 |
| 规范 ChatGPT / `api.openai.com` 条件路径 | 入口配置与实际观察分别展示 | 仅在包内条件满足时存在 WS 可能；未观察不能报成功 | 不新增本轮上游启用开关；现有条件也不等于实际连接结果 |
| Link | 不支持入口 WS | 沿已有链路，未观察则未知 | 显示不支持及原因，不以模拟状态伪造接入 |
| 直连 provider | 只管理 Codex 声明，不改本地入口 | 没有本地代理这一段；实际由客户端及服务决定 | 三方兼容性未知时如实显示，不能套用 OpenCodex 代理的限制证明直连结果 |

HTTP 流式响应的 SSE 与 WebSocket 是不同传输表达。模型、速度档、推理强度、上下文管理及压缩机制各有自己的作用范围，不能用其中一个字段反推另一项已生效。

## 用户级 provider 选项与映射

保存范围是用户级 provider，而非模型、项目或对话。以下布尔值是管理器管理该选项时的目标声明，不是当前运行事实；实际落盘仍沿受控配置入口，内部源码定位不自动成为公开 API。

| 选项 | OpenCodex 本地代理 provider | 直连 provider | 展示语义 |
|---|---|---|---|
| 跟随默认 | 移除管理器对本地 `websockets` 和 Codex `supports_websockets` 的显式覆盖，保留既有入口及原配置来源 | 只移除管理器对 `supports_websockets` 的显式覆盖 | 显示已知来源与版本解析结果；来源或版本不明时显示未知，不固定映射为 `false` |
| 优先 WebSocket | 目标为本地 `websockets = true` 与用户级该 provider 的 `supports_websockets = true` | 仅目标 `supports_websockets = true` | 客户端优先尝试；是否采用、是否允许回退由实际实现与请求决定，不承诺强制端到端 WS |
| 仅 HTTP | 目标为本地 `websockets = false` 与用户级该 provider 的 `supports_websockets = false` | 仅目标 `supports_websockets = false` | 管理这条客户端入口路径使用 HTTP，不改写已有上游传输策略 |

同一 OpenCodex 实例的本地入口开关属于该实例，不能为多个指向同一实例的别名 provider 伪造互不相关的开关。当前沿该实例对应的本地代理 provider 表达；若后续存在多个别名，需说明共享入口与一致性，不能将其拆成项目或对话偏好。本轮不新造多实例默认规则。

“跟随默认 / 不管理”是同一语义，不增加第四个选项。移除覆盖仅撤掉管理器持有的值，不能清空用户手工配置、擅自重建入口或覆盖后续编辑；具体配置归属和既有来源恢复方式属于正式实现待确认项。两个目标声明应在同一次保存中说明一致性与失败结果，不允许 UI 保存一项后把另一项静默当作成功。

全局页下方只读显示本地入口的配置来源、声明 / 解析值、待重启状态和已知限制；若有实际观察，另列实际入口及观察来源。没有第二个“启用本地 WebSocket”开关，也没有上游策略编辑开关。`websocket_connect_timeout_ms` 在本轮仅作来源说明，不扩展为额外设置。

## 收益、成本与兼容性说明

官方 WS 模式允许结合 `previous_response_id` 发送增量，有助于减少重复传输和连接相关开销；缓存失效或丢失时仍需重新提供上下文。历史输入仍按其计费规则计算，不能宣传为免历史 token、必然降费或固定幅度提速。

Superba 的发行说明提示：路由、协议转换、不支持 WS 的目标及压缩会影响回 HTTP 的路径；日志中的预热误记或少算也限制仅凭日志做结论。此来源只是兼容性分析，不能移植成 OpenCodex 2.84.0 已有能力。Krill 的套餐 1 / 2 / 3 只来自用户转述，本包不据此设套餐校验、WS 权益判断或付费请求测试。

WS 的选项不改变既有上下文策略和独立速度档。压缩回 HTTP 不等于项目切换传输偏好，Fast / Ultrafast / 推理强度也不证明 WS；相关组合仍保留原包的验证边界。
