## 2. 对原草案的审计修正

1. 原草案记录的本机样本为 `proxy.running=false`、`startup.status=at-risk`、`protection=none`，不能据一个样本断言所有版本刚装完“必然 at-risk”或所有此类状态均无故障。单字段不足以证明实际故障，也不足以触发恢复建议。
2. 原“三层展示”仍把进程、操作失败、保护和所有权混为并列主状态，改按主线、节点操作和问题的归属组织。`health=degraded` 不能一概命名为启动保护异常。
3. 新增环境事件和一个监听器不能独自保证一致；必须处理新鲜度、订阅竞态、旧响应、来源切换、在途失效和失败恢复。
4. 常态运行轮询为 3 秒，连接为 15 秒；后台为 10/30 秒，失败退避至 60 秒，单次采集可等 5 秒。“全域实时”应改成有明确触发与收敛时延的可验收承诺。
5. 不以“是否曾启动过”判定风险；主动停止也是正常状态。未安装和主动卸载也不自动产生故障通知。
6. 原五个待决策点不再作为阻断清单；用户已确认收敛方向并授权回写。尚待设计的是字段/兼容、具体视觉、每域刷新策略与失败边界，不能误写成已批准的全部技术实现。

## 3. 全功能状态盘点与减法目标

| 功能域 | 当前持有/表达 | 收敛目标 |
|---|---|---|
| 运行/托盘 | 快照 runtime、前端 runtimeState、lifecycleState、场景表、托盘门控 | 一份运行事实；生命周期结果只归操作；统一能力投影 |
| 环境/来源 | 环境报告、runtime source、版本事实分别刷新 | 前置条件按动作判定；来源与版本同代次；就绪摘要一致 |
| 安装/卸载 | 页面步骤及 busy/done、store 标记、后端进度/步骤 | 一条操作与核验结果；页面只留表单/视图状态 |
| 面板 | store 和页面各有 loading/error/ready | 展示模式、运行能力与面板加载流程分离；浏览器模式不是错误 |
| WebDAV | connection 同时表达连通/同步/冲突，独立 busy 布尔 | 配置/连接事实＋测试或同步支线，冲突归具体问题 |
| 扩展 | configError 混合读写失败，页面和 store 双 busy | 对象级操作结果；重新发现核验；读取错误独立 |
| 数据根/迁移 | 多动作共用 error，返回值压成 boolean | 保留失败步骤、部分影响、回滚结果及待重启条件 |
| 更新/备份/恢复 | 页面与 store 双过程；结果多处解释 | 统一操作，备份/核验/重启是证据步骤 |
| 偏好/官方共享开关 | 草稿、保存状态、复读事实交叉 | 草稿与确认值分离；官方复读决定是否生效 |
| 诊断/日志 | 报告保留，但显示标记另存；部分请求已有序号 | 读请求新鲜度与失败统一；复用已有防旧响应方式 |
| 通知/异常 | Toast、任务卡、持久通知、恢复弹窗分别处理 | 同一操作/问题单一结果，一个主要承载渠道；技术详情按需 |

## 5. 设计候选与实施顺序

主线候选为“待接入 → 未运行 ⇄ 运行中”，节点操作见项目核心；未知/过期不得伪装成任一稳定节点。具体字段不在本专题另建一套枚举。

1. 先按 S-01～S-15 确认操作结果和事实归属；优先修复假成功、无法重试与陈旧事实，再删除重复状态。
2. 冻结快照新鲜度/代次、操作结果/问题原因、动作能力与兼容映射；保留 CLI 兼容，明确相互冲突的资源操作。
3. 统一失效与刷新协调，验证替代链路后移除点补；故障与结果按原流程收口，不新建全包式 store。
4. 原型按“摘要＋同块详情”减少常驻区域，再实施概览、托盘及各功能支线。具体高度、断点、颜色与更多菜单布局待原型验证。
5. 验证所有入口及切页后的操作持续性；记录真实证据后才宣告对应整改完成。该顺序不授权发布、破坏性操作或全局同步。

| 场景 | 必须得到的结果 |
|---|---|
| 新安装后未启动、主动停止、主动卸载 | 正常主线与下一步，不由单一 at-risk/未安装枚举制造故障通知 |

| 订阅建立竞态、事件丢失、在途再次变化、恢复前台 | 初始补拉/重试/排队补拉后收敛；时延有测量依据 |
| 命令返回成功但核验未通过、操作超时后迟到成功 | 保留结果待确认并按核验收口，不伪造步骤 |
| 取消安装、卸载部分失败、目录待重启、回滚失败 | 各有真实结论、影响与下一步，不压成通用成功/失败 |
| 测试连接、同步冲突、上传失败正常响应 | 测试成功不叫已同步；冲突不叫全部成功；业务失败不被 IPC 成功吞掉 |
| 更新失败后重试、切页后回到执行支线 | 可重试且无残留 busy；不丢操作事实、不重复提交 |
| 运行中出现/解除保护或所有权问题 | 即使主线不变也更新问题；解除当前待处理项并保留历史 |
| 概览、设置、托盘、原生菜单操作 | 能力与限制原因一致，后端复核；可独立操作不被全局 busy 锁住 |
| 同一失败从当前页面到通知再到诊断 | 同一结果/原因、一个主承载入口，无多重弹出，技术信息脱敏 |
| 宽/窄窗口、键盘、原生面板恢复弹窗 | 默认摘要紧凑，详情可达，无遮挡或无解释禁用；尺寸需实际验证 |

## 8. 设计候选：状态形象动画（2026-09-28，候选、未定稿）

用户批注不满意概览用「颜色显示块」表达状态、占用空间大，希望改为**SVG 形象动画**表达不同状态并实时响应。据此产出候选与分析，位于 `01-需求分析/05-原型/候选/2026-09-28-状态形象动画/`（`index.html` 可运行演示 + `方案分析.md`）。

要点（详见该分析）：

- **定位**：形象是 §2.7 状态投影的另一种表达，**不是新状态机/新真源**；嵌入 `UI规范` §19 摘要块，替代「状态点 + 标签」这一小块，不改信息层级。
- **推荐技术**：内联 SVG + CSS 关键帧，根元素 `data-state` 单一属性驱动；零依赖、可主题化、GPU 合成友好、便于 `prefers-reduced-motion`。Lottie/Rive 仅为复杂形象备选。
- **映射原则**：进行中才循环；失败只做一次性抖动后稳定（不做常驻警示）；颜色不作唯一手段（配符号 + 文本）；**过期事实降饱和 + 虚线环，不冒充实时**。
- **实时**：复用统一状态投影与刷新协调器，只在变化时动、快速连跳去抖；可见性/减少动态时暂停。
