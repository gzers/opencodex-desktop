## 本包配置分层

沿用用户已确认的渠道管理入口、显式配置、重启应用和不修改 OpenCodex 边界。以下为候选映射，不新增运行时自动探索机制，也不把 Superba 的自动探测周期作为本项目要求。

| 层次 | 候选内容 | 处理原则 |
|---|---|---|
| 上下文策略 | 压缩 / 历史与笔记 | history/notes 与后台压缩按 Krill 已提供的二选一说明组合校验 |
| 压缩协议偏好 | 跟随现有 / 客户端本地压缩 / 远程 v2 | 仅在当前 provider 与公开入口确实可控制时开放；否则显示当前处理说明，不造一个无法执行的选择器 |
| 压缩执行偏好 | 普通 / 后台 | 不能把后台等同于原生远程；后台支持条件结合引擎版本和最终协议确认 |
| 请求速度偏好 | Standard / Fast / Ultrafast | 结合模型目录和认证模式说明生效范围；上游授予未知时保留未知 |
| 连接前置事实 | provider 身份、认证模式、模型、实际引擎版本 | 影响上述选项，但不由运行中请求文本猜测；客户端共享配置作用域不变 |
| 实际执行结果 | 代理摘要 / 渠道原生状态、档位回显等 | 来源为实际链路观察，不能从选择值直接推导 |

这里的本地压缩是由客户端组织摘要流程，仍可能请求远程模型；OpenCodex 代理摘要又是单独的实际处理路径。协议偏好与实际处理者应分字段表达，不用“新压缩”或“新上下文”命名正式字段。

### 后台压缩与 history/notes 的候选组合

两个片段是互斥分支，分别合并到同一客户端有效配置，不是完整部署配置。保留现有本地代理入口及允许的认证配置；同名表或标量已有内容时需解析合并，不直接追加重复表。

后台压缩分支：

~~~toml
[features]
context_management = false

[features.async_compaction]
enabled = true
model_async_compact_threshold_percent = 65

[features.token_budget]
enabled = false
~~~

这里显式开启后台预压缩并关闭 token budget。65 为引用版本配置目录记录的默认启动百分比，不是本项目已选定默认值。仅有这段配置仍不能保证当前上游 / OpenCodex 路径满足远程 v2 条件。

历史与笔记分支：

~~~toml
[features]
async_compaction = false
context_management = true

[features.token_budget]
enabled = true
use_history_notes_extension = true
~~~

三项开启有 PAT 推荐键表佐证；关闭后台来自本包按渠道规则进行的互斥封装，不声称 Superba 自己实现了这套单选 UI。其通用设置引擎检查字段和版本，本轮未发现专门的二选一修正逻辑，不能把有说明文字当作其已自动关闭冲突项。

认证仍是必要前提。该项目分别生成 PAT 和 API Key 形状，PAT 为 personal_access_token 与 OPENAI_API_KEY 两字段，API Key 则包含 auth_mode = apikey。其认证决策在 router 模式下选择 API Key，因此 PAT 直连推荐组合不能当作路由模式已贯通 history/notes 的证明。见[认证渲染](https://github.com/krill-lab/superba/blob/9d155f27e392fd4b6a3bedd8486d86b7b960018f/crates/superba-config/src/authjson.rs#L184)、[router 认证条件](https://github.com/krill-lab/superba/blob/9d155f27e392fd4b6a3bedd8486d86b7b960018f/crates/superba-core/src/settings/auth_choice.rs#L84)。本包不复制其直连地址或认证文件到日常代理配置。

### 远程压缩选项受 provider 身份约束

Superba 维持内置 openai provider，其自身没有通过切换该 provider 的 remote_compaction 字段来启用本地压缩，而是管理渠道是否能处理原生协议，并在切换 / 路由时警告和约束。

对确实支持该配置的自定义 provider，协议目录表达的是：

~~~toml
[model_providers.example-custom.capabilities]
remote_compaction = "v2"
~~~

此片段只是字段位置示意，需要已经存在的自定义 provider 定义；不要把 example-custom 改为内置 openai 后据此覆盖，也不将本地渠道名 Krill-1 与 Codex 的 provider 身份等同。切为客户端本地压缩的枚举为 unsupported，省略为沿用默认。

源码依据为[provider 与压缩关系说明](https://github.com/krill-lab/superba/blob/9d155f27e392fd4b6a3bedd8486d86b7b960018f/crates/superba-core/src/compaction.rs#L1)。其声明是项目维护者对所引用版本的判断，本轮未额外反查最新 Codex 源码，不能据此改写已有官方复核或宣布所有版本相同。

### 速度档的写入与生效分开

| 用户选择 | Superba 写入的 service_tier | 对应请求档位意图 |
|---|---|---|
| Standard | default | 标准；其类型映射通常不主动注入快速档位 |
| Fast | fast | priority |
| Ultrafast | ultrafast | ultrafast |

单独速度配置片段，写在 TOML 顶层、首个表头之前：

~~~toml
service_tier = "ultrafast"

[features]
ultrafast_mode = true
~~~

依据：[速度值映射](https://github.com/krill-lab/superba/blob/9d155f27e392fd4b6a3bedd8486d86b7b960018f/crates/superba-core/src/models.rs#L71)、[终端 / 桌面生效判断](https://github.com/krill-lab/superba/blob/9d155f27e392fd4b6a3bedd8486d86b7b960018f/crates/superba-switch/src/models.rs#L220)。其代码把 PAT 桌面交给原生菜单，API Key 桌面在没有其他受支持路径时报告 AppForcesStandard。应把它作为进一步验证线索，不等同于我们前次手工 HTTP 请求回显 default 的原因已被证明。

该项目可生成 -fast / -ultrafast 后缀模型，但仅供明确支持这一约定的站点；[Krill 内置能力](https://github.com/krill-lab/superba/blob/9d155f27e392fd4b6a3bedd8486d86b7b960018f/crates/superba-core/src/catalog.rs#L106)将 tier_model_suffix 设为 false，并说明生产支持未确认。本包不自动添加此类模型，也不以模型重命名绕过当前不确定性。

## 对现有验证材料的补充

Superba 的[原生压缩检查](https://github.com/krill-lab/superba/blob/9d155f27e392fd4b6a3bedd8486d86b7b960018f/crates/superba-net/src/compaction.rs#L46)把 compaction_trigger 放在普通 Responses 请求中，并检查是否返回一个压缩项；相关[测试](https://github.com/krill-lab/superba/blob/9d155f27e392fd4b6a3bedd8486d86b7b960018f/crates/superba-net/tests/compaction_tests.rs#L59)覆盖请求形状。本轮只是阅读测试，未运行。

本包前次真实验证主要调用独立 /responses/compact，因此结果仍按原记录保留，不扩大为新版客户端的远程 v2 或后台路径已通过。后续如需验证应补普通 Responses + compaction_trigger 及状态回传；这是测试方法补充，不是新增生产探测机制。

Superba 路由器通过响应中的压缩项指纹学习归属，和“完全不读取响应”不同。这里只记录为来源能力，当前已确认的出站响应原样透传方向不因此自动改变；更不能把它接在摘要转换之后就当作已补齐原生协议。
