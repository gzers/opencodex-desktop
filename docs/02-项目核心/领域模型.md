# 领域模型

系统的实体与逐字段定义。本文件回答「系统里有哪几样东西、每样有哪些字段」，状态取值见 `数据与状态.md`，跨边界格式见 `契约字段.md`。

**字段名约定**：内部字段名统一用 `snake_case`；界面文案与字段名解耦，不要求逐字一致（见 `术语与命名.md`）。

**冻结标记**：✅ 已定 = 字段或约束已确认；字段级取值以 `docs/03-开发实施/IMP-OPENCODEX-DESKTOP-01.md` 的 FZ 契约为准。

## 状态归属修订（2026-09-28，已确认方向、待实施）

- 状态语义唯一来源为 [数据与状态](数据与状态.md) §2.7、§5.8：运行事实、节点操作、持续问题各有归属；现有字段表是兼容基线，尚未完成新字段迁移。
- `RuntimeFacts` 表达观测依据；操作过程与结果不能另作一份实际运行态。`SyncRun`、`ManagedInstall`、写入事务和更新流程保留各自领域步骤，共用操作结果语义，不新建一个替代所有领域实体的总对象。
- `Notification` 是操作/问题的触达投影，不拥有第二份失败结论；视图展开、搜索、分页不成为领域实体。
- 新鲜度、来源代次、操作关联、问题原因等跨边界字段见 [契约字段](契约字段.md) §5.1，待实施前冻结；不在本轮凭空新增必填字段。

## 1. `EnvironmentGate` 环境前置门禁

| 字段 | 类型 | 取值 / 约束 | 必填 | 冻结 |
|---|---|---|---|---|
| `state` | enum | `checking` `missing_node` `missing_npm` `missing_ocx` | 是 | ✅ |
| `checked_item` | enum | 当前检查项：`node` `npm` `ocx` | 是 | ✅ |
| `missing_item` | enum \| null | 缺失项，`passed` 时为 `null` | 否 | ✅ |
| `homebrew_detected` | bool | 缺 Node.js 时用于选择提示分支 | 否 | ✅ |
| `hint_command` | string \| null | 最短可复制命令；按缺失项与 Homebrew 分支取 IMP 文案 | 否 | ✅ `FZ-13` |
| `checked_at` | timestamp | 最近一次检查时间 | 是 | ✅ |

- 检查顺序**固定短路**：`node` → `npm` → `ocx`。
- 全部通过的事实保留供摘要与详情使用，不常驻大门禁卡；事实保存与视图隐藏分开（`UI规范.md` §19）。
- 提示分支：有 Homebrew 展示 `brew install node`；无 Homebrew 展示 Node.js LTS 官方安装渠道；缺 `ocx` 展示官方 npm 包安装命令（命令文本非最终契约）。

### 7.1 `CredentialRef` 受控凭据引用

| 字段 | 类型 | 取值 / 约束 | 必填 | 冻结 |
|---|---|---|---|---|
| `ref_id` | string | 凭据引用标识；`SyncEndpoint.credential_ref` 指向它 | 是 | ✅ |
| `backend` | enum | macOS 首期固定为 `keychain` | 是 | ✅ |
| `service_name` | string | 固定 `OpenCodex Desktop` | 是 | ✅ `FZ-44` |
| `account_key` | string | `ocx.dav.<ref_id>` 或 `ocx.sync.<ref_id>` | 是 | ✅ `FZ-44` |
| `purpose` | enum | `webdav_credential` `encryption_password` | 是 | ✅ `FZ-44` |
| `created_at` / `updated_at` | timestamp | ISO 8601 UTC | 是 | ✅ `FZ-44` |

生命周期与同步规则：

| 规则 | 要求 |
|---|---|
| 创建 / 更新 | 真实值只经内存或标准输入取得，写入 macOS 系统钥匙串；具体服务名与键名留 IMP |
| 读取 | 仅在后端内部按需取用；界面、日志、错误信息、通知与 `--json` 只显示掩码 |
| 删除端点 | 先提示并让用户确认；默认同步删除引用的凭据，除非用户显式选择保留 |
| 导入 / 导出 / 同步 | 导出文件与同步载荷是**未加密配置 + 完整性校验**，只携带凭据引用；真实值不进入容器、manifest、日志或命令行参数，产品说明不得暗示端到端加密 |
| WebDAV | 真实口令存系统钥匙串；只在 TLS 连接时由后端取用，不进命令行参数 |
| MCP 环境变量 | 只写环境变量引用（如 `bearer_token_env_var`），不写内联值 |
| CLI 口令输入 | `--password-stdin` 仅在读取旧版加密容器时需要；**禁止**通过命令行参数传口令 |

- **详情展示（只读）**：详情回读 `shape` / `command` / `args` 与配置落点（`McpServerProjection` 的客户端配置节点）供用户判断执行边界；`env` 只显示键名，`args` / `headers` 掩码；详情是展示，**不构成写入授权**，展示层**不执行**任何 MCP 命令。

### 13.1 项目级作用域规则

`ClientTarget.scope` 和 `project_root` 一起决定落点，不得只按客户端编号定位：

| 项 | 规则 |
|---|---|
| 用户级作用域 | `scope = user`，`project_root = null`；每个客户端最多一个 |
| 项目级作用域 | `scope = project`，`project_root` 必填；同一客户端可有多个项目级落点 |

| 冲突处理 | 项目级与用户级同用，按当前操作选择的落点分别比较与提示；不静默合并 |
| 展示 | UI 必须同时标出客户端、作用域和项目根，不得把不同项目级落点混成一行 |

> 首期只开放用户级；项目级是字段与投影模型预留，不是本期已授权的实现范围。

### 15.2 自更新终态与失败分支

| 终态 | 触发 | 约束 |
|---|---|---|
| `download_failed` | 下载中断、校验前失败或用户取消下载 | 保留上一版本；不进入安装 |
| `signature_failed` | 签名校验失败 | 立即终止；保留上一版本 |
| `install_failed` | 安装写入或替换失败 | 保留上一版本；按失败原因给恢复建议 |
| `cancelled` | 用户取消下载、安装或重启等待 | 保留已下载内容与当前版本状态 |
| `rollback_failed` | 回滚失败 | 保留上一版本路径与失败原因，进入人工恢复指引；后续不得自动重试 |

- 回滚成功不是稳定停留态，回到上一版本的正常状态展示；回滚失败必须用独立终态留证据。
- 本体升级引导不复用这组自更新终态；本体更新走官方 `ocx update`。

两个对象**不得混用一个按钮**，文案必须让用户分清当前更新的是哪一个对象。

### 15.1 套壳应用更新状态链

```text
检查中 → 有更新 → 下载中 → 校验中 → 校验失败 ──→ 保留上一版本 + 原因
                              ↓
                           安装中 → 等待重启 → 重启接管中 → 成功 / 回滚
```

- 重启**不得停止**由桌面壳托管的 OpenCodex 代理；重启后重新接管并恢复状态展示。
- 检查结果以**非阻塞通知**呈现，不打断当前操作。

### 16.1 与操作任务、技术日志、确认请求的边界

- **六类反馈是职责与展示渠道，不是六种都要持久化为 `Notification` 的实体类型。** 操作任务、通知、技术日志、确认请求分别定义，通过 `operation_id` / 事件标识关联（见 `数据与状态.md` §6）。
- `Notification` 只承载**操作性通知**：用户离开当前页面后仍需要知道、或需要后续处理的事件。
- **操作任务**（长任务进度）与**操作反馈**（短操作 Toast）不写入 `Notification`；任务完成后的低风险成功默认走 Toast，不占持久未读。
- **技术日志**是独立事实记录，不产生未读、不进入通知中心（`FZ-14` / `FZ-15`），最多通过 `operation_id` 与通知互跳。
- **阻断式确认**是高风险决策的 Modal，不是通知；确认后转操作任务或操作反馈。
- 同一业务事件允许同时产生一条日志、一个当前任务或反馈、必要时一条操作性通知，但**不得堆叠多条同类提醒**。
- **类型、严重程度、业务分类与触发来源是四个独立维度**：`level`（严重程度）不并入 Toast 的 `success` / `error`；现有 `info` / `warning` / `danger` 不得未经兼容设计直接替换。
- **三类状态不可压成线性链**：`read`、`resolved`、`deleted` 是不同维度；关闭详情、收起浮层不修改任何业务结果，也不等于已读、已解决或取消任务。
- 必须区分**自动验证已恢复**、**用户确认知悉**、**手工标记处理**三种事实；用户点击「已解决」只记录用户确认，**不得解释为服务实际恢复**。

- 详情弹窗展示：标题、完整正文、`时间 · 级别`；有动作给「前往处理」，否则只有「关闭」；弹窗内可删除。
- 每条通知有**单独删除**按钮；批量动作（全部已读 / 清理通知 / 清理已读）在通知中心头部与「设置 → 日志与通知」。
- 通知中心与「诊断中心 → 通知历史」**共用同一份数据**（同一实体，不是两份副本）；通知中心与通知历史是同一实体的投影，技术日志仍是独立事实记录。
- 正式运行不得由演示种子冒充真实通知。

- **原子性**：先装入 `<前缀>.new-<随机>` 临时区，校验（入口可执行 + 版本可读 + `name` 匹配）通过后**原子替换**；任何失败清理临时区、不改现有前缀与运行来源。
