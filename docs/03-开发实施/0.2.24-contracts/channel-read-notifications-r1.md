# 0.2.24 渠道读取结果的注册通知

revision: 1；2026-11-11。实现 main b6dc941cf6e2e990bae30799c071d732fc77b097；实际进度归 IMP-34。承接用户已采用的“读取匹配结果改为注册通知，移除页面常驻汇总”，不改变读取/匹配/正式保存的既有范围。

## 触发与事实

只有用户明确执行“读取现有渠道”，且现有 guarded read 实际进入后端工作时，按其返回结果发布通知。成功来自真实草稿读回，不是正式配置保存；失败使用固定说明，保留当前输入与此前成功的独立历史。打开页面、普通快照、通知查询不启动读取，也不补造成功。

注册 model-channels-read-succeeded/failed，属于 model_config / configuration / read / execution / local / user。每次实际调用使用服务端 UUID 身份，同一次投递去重；成功与另一次失败不互相解除。成功是明确支持的结果事实，并须携带合法数字统计；无统计、分类总和不符、changed/protocolPending 超总量或跨事件使用统计均拒绝投递。统计仅包括 total、matched、changed、manualPreserved、unmatched、missingDefault、missingDependency、conflict、protocolPending，不包含配置原文、渠道名、模型ID、地址、密钥或自由错误文本。

发布位于 file_work 持有 admission 的工作闭包内，配置操作与通知结果在释放写者前完成。投递失败单独记固定诊断，不将已完成的草稿读取改报成保存失败，不重复执行读取或落盘正式配置。

## 展示

渠道页移除常驻匹配统计，现有草稿修改状态保持。已注册通知成功提示保留8秒，用户可提前收起；铃铛/通知历史保留本次完整数量并可打开详情。“保存配置后才生效”是结果事实。通过已有 models 动作返回模型配置；没有新详情入口或另造本机结果仓库。

通知加载为每store的同一in-flight promise，期间的新广播排队读回后才结算。announce串行观察，不在旧列表刚返回时丢掉新结果，不因普通历史加载/再次广播而重播同一ID。失败的列表查询不制造业务通知。复用现有单Toast展示及通知中心，不更改多通知时只提示新列表首项的既有策略。
