**最终集成结果**

| 流程与定位 | 实际行为 |
| --- | --- |
| 默认导出：data-sx=export、modalConfirm | 重新获取 modelPrototype.state().saved，冻结本次所选渠道的 mock 文件快照。未保存编辑不混入；普通导出 source 为 committed、snapshotSource 为 saved。 |
| 明确导出内存草稿：syncPrototype.open | 仅 action:export、source:draft 使用当前模型渠道 draft，可指定仅存在于草稿的新渠道。没有新增选择控件、弹窗或确认步骤。未确认的行 / 连接输入仍不属于 draft。下一次普通导出恢复 saved 来源。 |
| 导出数据：lastExport.snapshot | modelChannels 包含所选渠道；templates 只取已保存版本或依赖所需精确版本。未选 Key 的引用、原始 Key、口令、模版编辑缓冲及发现 official / 刷新状态不进入快照；lastExport 返回副本。 |
| 文件保护：sxEncrypt、sxPass、sxPassAgain | encryptionRequired 为 false。含凭据时沿用原建议勾选与明文说明，可取消保护后在同一确认中完成。主动选择加密才校验至少 8 位且两次一致；无系统 confirm。WebDAV 既有同步口令校验独立保留。 |
| 载荷：modelPrototype.syncFixture() | 从既有模型 / 渠道种子派生固定 NewApi、私有网关及 GPT v4 内存载荷。NewApi 有实际新增 3、更新 2、明确删除 1 个模型，选中数为 19，包含节点 URL、别名、覆盖及精确版本引用；比较详情改为读取这些实际 fixture。 |
| 桥接：modelPrototype.stageSyncChannels(request) | 仅接受 prototype-sync-fixture/1、file / webdav 来源、两个登记渠道 ID 和 GPT 版本选择。不接受任意传入配置。所有检查先完成，再通过现有 change() 更新模型模块实际持有的 draft。 |
| 文件导入：选择示例 → 读取并比较 → 应用 | 沿用既有流程，正常采用进入当前模型渠道 draft。saved、保存记录和 operation 在这一步不变；既有结果区简短提示“渠道已加入草稿，保存后生效”。直接完成草稿暂存。 |
| WebDAV：同步配置 → 选择采用远端 → 应用 | 与文件导入共用实际暂存入口。保留本机 / 暂不处理不采用渠道；其他 mock 对象仍走既有比较应用。 |
| 身份与凭据：data-sx-import-choice / compare-credential | 私有网关按既有 new / rebind 映射分别进入 legacy-imported / legacy 草稿，默认停用、待补 Key，不复用旧身份凭据。同身份 NewApi 不选来源 Key 时保留本机 Key；选用来源凭据时只在私有 mock 凭据表登记，公开状态保留不透明引用。 |
| 输入保护 | 目标渠道未确认的连接 / Key 输入和模型行编辑会停止采用；未提交的别名输入也受保护。比较期间目标 draft / saved 变化则旧应用过期。已加入草稿的重叠字段保留并提示先处理；无关渠道草稿及输入保留。使用原 sxError，无额外弹窗。 |
| 模版版本接纳 | 所选 GPT v4 独立进入 mock 已保存模版库；只新增一次，不改主版本、人工编辑缓冲或现有渠道 saved。单独接纳模版不采用渠道；渠道使用 v4 需要已存在或本次已选该精确版本。 |
| 保存：mpPolicySave → 保存预览 → modalConfirm | 沿用原保存权威：预览和取消不写入；确认后执行原 mock 备份 / 原子写入，成功才更新 saved 和保存记录。通知仍走原宿主，只有既有“已写入 / 立即重启 Codex / 稍后”。之后普通导出可读到已保存的新值。 |
| 失败与重试 | 同步备份失败 / partial 场景不提前暂存渠道或模版。模型保存失败保留导入草稿与原 saved，可通过原保存确认再次尝试。未知 / 重复身份、缺依赖及忙碌态均在修改前拒绝。 |

实现复用了现有基于稳定 ID 的三方合并，只合并载荷明确涉及的渠道字段、模型增改及明确删除，保留无关本机草稿。没有创建第二套保存状态、文件写入入口或独立结果卡。当前跨模块 mock 导入、采用和保存链路已完成，无待父线接入项。
