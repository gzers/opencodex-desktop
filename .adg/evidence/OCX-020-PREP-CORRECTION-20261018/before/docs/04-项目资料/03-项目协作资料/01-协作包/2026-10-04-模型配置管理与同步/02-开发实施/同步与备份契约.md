# 同步与备份契约

**文档版本**：v1.0  
**创建日期**：2026-10-18  
**适用范围**：OpenCodex Desktop 0.2.0 模型配置管理与同步协作包  
**依赖规范**：生产Schema冻结规范（WP-04）、统一通知注册盘点与开发约束

---

## 1. 同步边界决议表

| 决议对象 | 同步策略 | 冲突处理 | 备份频率 | WP依赖 | 说明 |
|---------|---------|---------|---------|--------|------|
| User.config | 增量同步 | 时间戳优先 | 每次修改触发 | WP-04 | 用户级配置，允许多设备同步 |
| Model.template | 全量同步 | 服务端优先 | 每日定时 | WP-01, WP-04 | 官方模板更新，本地仅缓存 |
| Extension.settings | 增量同步 | 本地优先 | 每次修改触发 | WP-05 | 插件配置，尊重本地定制 |
| Cache层（UI状态） | 不同步 | N/A | 不备份 | - | 临时运行时状态，不持久化 |
| Backup.manifest | 全量备份 | 最新覆盖 | 每日+按需 | WP-04 | 备份元数据，独立存储 |

**冲突解决规则详解**：
- **时间戳优先**：比较修改时间，取最新版本覆盖
- **本地优先**：仅在本地明确放弃时才接受服务端变更
- **服务端优先**：强制拉取官方内容，本地修改降级为"派生版本"

**同步触发条件**：
- 启动时：检查Model.template更新（WP-01本地版本匹配）
- 修改时：User.config/Extension.settings立即触发增量同步
- 定时任务：每日03:00执行全量备份（含manifest生成）

## 2. 备份manifest结构

**版本规范**：遵循§生产Schema冻结规范（WP-04），manifest版本与Schema版本锁定。

**备份粒度**：
- **session**：单次对话会话结束时备份配置快照
- **daily**：每日定时全量备份（保留7日滚动）
- **on-demand**：用户手动导出备份（不参与自动清理）

**manifest TypeScript接口示例**：

interface BackupManifest {
  version: string;              // Schema版本，如"0.2.0"
  timestamp: number;            // Unix时间戳
  type: 'session' | 'daily' | 'on-demand';
  content: {
    userConfig: UserConfigSnapshot;
    extensionSettings: Record<string, unknown>;
    modelTemplateCache: ModelTemplate[];
  };
  checksum: string;             // SHA256校验和
  excludedFields: string[];     // 过滤的敏感字段路径
}

**清理策略**：
- 保留最近7日的daily备份
- 超期备份自动删除（通过cron任务执行）
- session备份仅保留最近3次
- on-demand备份用户手动管理，不自动删除

## 3. WP-04依赖挂钩

**Schema版本绑定规则**：
- 备份manifest.version字段必须与当前Schema版本一致
- Schema升级时（如0.2.0→0.3.0），触发备份格式迁移检查
- 字段映射关系定义在《生产Schema冻结规范》中，本契约不重复定义

**关键字段映射依赖**：
| 备份字段路径 | Schema定义位置 | 版本要求 |
|------------|--------------|---------|
| content.userConfig.modelPreferences | UserConfig.schema.json | >=0.2.0 |
| content.modelTemplateCache[].id | ModelTemplate.schema.json | >=0.2.0 |
| content.extensionSettings | Extension.schema.json | >=0.1.10 |

**向前兼容承诺**：
- 0.2.0备份必须能被0.3.0读取（通过迁移变换器实现）
- Schema字段仅能新增或标记deprecated，不可删除已有字段

## 4. 旧客户保护策略（双文件方案）

**问题背景**：0.2.0前的备份格式缺少manifest版本字段，无法直接识别Schema版本。

**双文件方案**：

1. **旧格式读取**：检测备份文件缺少manifest.version字段时，标记为"legacy格式"

2. **新格式转换逻辑示例**：

function migrateLegacyBackup(legacyData: unknown): BackupManifest {
  return {
    version: '0.1.10',  // 假定为最后一个旧版本
    timestamp: Date.now(),
    type: 'on-demand',
    content: {
      userConfig: normalizeLegacyConfig(legacyData),
      extensionSettings: {},
      modelTemplateCache: []
    },
    checksum: calculateChecksum(legacyData),
    excludedFields: []
  };
}

3. **迁移提示**：首次读取旧格式时，提示用户"检测到旧版本备份，已自动转换为0.2.0格式"

**兼容性窗口**：
- 0.2.0～0.3.0：保留旧格式读取能力
- 0.3.0起：移除旧格式支持，仅接受manifest标准格式

## 5. 凭据过滤规则

**剔除的敏感字段清单**（备份时强制过滤）：
- 密钥类：apiKey, secretKey, privateKey
- 令牌类：accessToken, refreshToken, sessionToken
- 密码类：password, passphrase, credential

**过滤规则实现**：
| 规则类型 | 表达式 | 示例匹配 |
|---------|-------|---------|
| 字段名正则 | /^.*[Kk]ey$/ | apiKey, secretKey |
| 字段名正则 | /^.*[Tt]oken$/ | accessToken |
| 字段路径 | user.credentials.* | 整个credentials对象 |

**过滤后记录**：
- manifest.excludedFields记录被过滤的字段路径
- 恢复备份时，提示用户手动重新输入敏感信息

**技术约束**：
- 过滤逻辑在备份生成阶段执行，不涉及真实凭据消耗
- 不对已加密的凭据二次过滤（由Extension层负责加密）

## 8. Manifest字段定义与凭据加密规范

> **定位**：明确Manifest的完整字段结构、备份加密策略及访问控制，支撑0.2.0首发和后续演进。

### 8.1 Manifest字段定义表

**基础结构**：

| 字段 | 类型 | 必填 | 示例 | 说明 |
|------|------|------|------|------|
| `version` | string | ✓ | `"0.2.0"` | Schema版本，冻结不变 |
| `timestamp` | number | ✓ | `1729248000000` | 备份生成时间戳(ms) |
| `templates` | array | ✓ | `[{...}]` | 模板对象数组，每项包含templateId/revisionId/title/body |
| `checksum` | string | ✓ | `"sha256:abc..."` | 整体内容校验和 |
| `metadata.deviceId` | string | - | `"device-001"` | 设备标识，用于跨设备恢复 |
| `metadata.lastSync` | number | - | `1729248000000` | 上次同步时间戳 |
| `metadata.syncSource` | string | - | `"local"` \| `"webdav"` | 同步源 |

**完整JSON示例**：

```json
{
  "version": "0.2.0",
  "timestamp": 1729248000000,
  "templates": [
    {
      "templateId": "notify.user.login",
      "revisionId": "v1.0.2",
      "title": "登录通知",
      "body": "您的账户于{time}在{location}登录",
      "digest": "sha256:e3b0c44298fc1c149afbf4c8996fb924..."
    }
  ],
  "checksum": "sha256:d7a8fbb307d7809469ca9abdcbed8b00...",
  "metadata": {
    "deviceId": "device-macbook-001",
    "lastSync": 1729248000000,
    "syncSource": "local"
  }
}
```

### 8.2 双文件备份策略

**为何采用双文件**：

1. **当前活跃备份** (`manifest.json`)
   - 实时更新，用于快速恢复
   - 存储位置：`~/.opencodex/backup/manifest.json`
   - 权限：0600 (仅所有者读写)

2. **归档冷备** (`manifest.archive.json.enc`)
   - 定期生成加密备份
   - 存储位置：`~/.opencodex/backup/manifest.archive.json.enc`
   - 权限：0600
   - 加密算法：AES-256-GCM
   - 密钥来源：系统密钥环

**切换策略**：

```typescript
// packages/main/src/services/BackupManager.ts
async rotateBackup(): Promise<void> {
  // 1. 当前manifest.json → 备份为manifest.archive.json
  const current = await fs.readFile('~/.opencodex/backup/manifest.json', 'utf8');
  
  // 2. 加密存储
  const encrypted = await this.encryptWithSystemKeychain(current);
  await fs.writeFile('~/.opencodex/backup/manifest.archive.json.enc', encrypted);
  
  // 3. 设置权限
  await fs.chmod('~/.opencodex/backup/manifest.archive.json.enc', 0o600);
}
```

### 8.3 凭据加密与密钥管理

**涉及凭据**：

| 凭据类型 | 原始存储方式 | 0.2.0处理 | 验证方式 |
|---------|-----------|----------|----------|
| WebDAV密码 | 明文 | 系统密钥环 (macOS Keychain/Windows Credential Manager) | ✓ 运行时读取，不落盘 |
| OAuth2 Token | 明文 | 同上 | ✓ TTL机制，过期刷新 |
| API Key | 明文 | 同上 | ✓ 备份前剔除 |

**备份前过滤逻辑**：

```typescript
// packages/main/src/services/CredentialFilter.ts
export class CredentialFilter {
  private sensitiveFields = ['apiKey', 'token', 'password', 'secret'];

  filterTemplate(template: NotificationTemplate): NotificationTemplate {
    const filtered = { ...template };
    this.sensitiveFields.forEach(field => {
      if (field in filtered) {
        delete filtered[field];
      }
    });
    return filtered;
  }

  filterManifest(manifest: Manifest): Manifest {
    return {
      ...manifest,
      templates: manifest.templates.map(t => this.filterTemplate(t))
    };
  }
}
```

**验收标准**：

- ✓ 备份文件中grep不到apiKey/token字样
- ✓ 系统密钥环存储验证（macOS: `security find-generic-password`）
- ✓ 加密文件无法用文本编辑器打开

### 8.4 旧格式兼容与迁移截止

**兼容策略**：

| 旧格式特征 | 0.2.0行为 | 截止日期 |
|----------|----------|----------|
| 无Manifest包装，纯数组 | 自动转换（见F04-迁移方案） | 2026-12-31 |
| 明文凭据存在 | 迁移时自动移至密钥环，删除明文 | 2026-12-31 |
| 无version字段 | 视为0.1.10，应用迁移规则 | 2026-12-31 |

**迁移流程**：

```typescript
// packages/main/src/startup/MigrationPhase.ts
async function migrateOldBackup(): Promise<void> {
  const oldBackupPath = '~/.opencodex/backup/backup.json';
  
  if (!existsSync(oldBackupPath)) return;
  
  const oldContent = JSON.parse(await fs.readFile(oldBackupPath, 'utf8'));
  
  // 检测格式
  if (!oldContent.version) {
    // 0.1.10格式
    const migrator = new BackupMigrator();
    const newManifest = await migrator.migrateOldFormat(oldContent);
    
    // 过滤凭据
    const filtered = new CredentialFilter().filterManifest(newManifest);
    
    // 提取凭据到密钥环
    await this.extractCredentialsToKeychain(oldContent);
    
    // 保存新格式
    await fs.writeFile('~/.opencodex/backup/manifest.json', JSON.stringify(filtered, null, 2));
    
    // 备份原文件
    await fs.rename(oldBackupPath, oldBackupPath + '.legacy');
    
    this.logger.info('Migration completed: 0.1.10 → 0.2.0');
  }
}
```
