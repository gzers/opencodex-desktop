## 实施选择

代码分支 `feature/0.1.9-windows-appearance`，从 `8a8397a61eee676d6b5166bd67a43930eb5e8d44` 接续。实现提交 `d4d7164`，原生验证与 125% DPR 入口提交 `965c314`，物理坐标和原生菜单消息循环复验补充 `94f3f29`，独立重载迁移补充 `2ec3812`，候选出包工作流补充 `15219bf`。最终源码为 **`15219bf08ceaaef86ae471772d27e04fdbf5ff1d`**。原型仅作为已确认单行结构和行为的设计输入，未把浏览器 mock 当作系统 Mica 或 Snap 证据。

- **单行标题栏**：Windows 保留系统绘制的 caption、图标、名称和最小化／最大化或还原／关闭按钮，仅移除 Windows 的原生应用菜单行。不自绘按钮，也不移除窗口 decorations／缩放边框，User32 继续负责拖拽、双击、系统菜单、Snap 命中与原生可访问性；Windows 不再显示 macOS 的 DOM 拖拽条。系统标题栏高度随实际 DPI 而定，不以网页固定 40px 替代原生尺寸。
- **平台隔离**：`src/lib.rs` 仅 Windows 不安装顶部应用菜单，托盘资源保留；非 Windows 仍安装原来的应用菜单，macOS Edit responder chain、Cmd+C/V/X/A、Overlay 和关闭生命周期代码保留。静态平台分流不构成 macOS 原生回归。
- **功能无损核查**：移除原生菜单后，独立“重载主界面”会失去唯一可见入口，因此在 Windows 托盘复用 `NATIVE_MENU_VIEW_RELOAD`、原 `ReloadMain` 和直接原生重载路径，仍可在 WebView 故障时恢复。进程动作继续概览／托盘，编辑保留快捷键和输入框上下文菜单，缩放与诊断沿现有应用入口。没有添加新的代理动作域。
- **真实材质**：新 `window_appearance` 边界读取系统构建、透明设置、高对比、DWM composition 和窗口激活状态，设置 DWM 系统 backdrop，并回读支持的属性。Win11 22H2+ 使用 `DWMWA_SYSTEMBACKDROP_TYPE=MAINWINDOW`；初始 Win11 使用与 Tauri window-vibrancy 一致的有界兼容入口；Win10 不尝试 Mica。标题栏按产品浅深配色设置 caption color，避免系统强调色形成单独蓝条；客户区 Mica 由 DWM 提供，不靠 CSS blur 仿造。
- **实色回退**：透明关闭／高对比／composition 不可用／非活动／DWM 或背景设置失败时返回实色原因；页面和原生背景对齐，透明 WebView 仅在实际 Mica 生效时启用。监听原生设置、主题与激活消息，无新增连续轮询。
- **偏好与权限**：用户主题仍以后端偏好为事实源，保存／恢复触发主线程更新；系统主题只更新 `system` 的解析值。原生材质策略不读取减少动态，不更改用户 high／mid／low，也不增加动效选项。新增主视图只读诊断命令，不扩大主窗口的关闭／最小化／拖拽权限，官方子视图不能读取该诊断。
- **关闭**：继续走已有 `CloseRequested`；保持运行开启时只隐藏，关闭时沿原退出路径。没有添加直接 process exit 的自绘按钮。
