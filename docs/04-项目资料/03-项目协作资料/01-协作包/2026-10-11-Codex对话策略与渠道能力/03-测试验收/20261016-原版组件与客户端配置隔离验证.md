# 20261016 原版组件与客户端配置隔离验证

性质：专题可行性验证，原版组件隔离观察。不是生产功能验收或 Krill 实际线路通过证明。用户要求先记录官方复核，再寻找验证方法，本轮已按该顺序执行。

## 环境与执行范围

- 本机原版客户端当前返回 `codex-cli 0.163.0-alpha.10.2`。此前讨论中观察过的 `0.162.0-alpha.17.2` 已不是本轮执行文件的版本；本轮没有执行升级，也不把 alpha.10.2 推定为渠道所称 alpha.11 的等价实现。
- 原版代理包内版本为 `@bitkyc08/opencodex 2.84.0`，直接导入其中的解析器、适配器、目录规范化及上下文处理函数进行检查。内部函数仅用于本轮隔离观察，不作为产品集成接口。
- 使用临时 HOME、CODEX_HOME、OPENCODEX_HOME 与 XDG 目录，不继承日常凭据和代理变量；临时目录随检查结束清理。
- 原版组件检查禁用外部 fetch，唯一网络目标为临时回环 HTTP 模拟上游；没有 Krill、官方模型或账号认证请求。客户端只运行版本与功能列表 / 配置解析，不执行 agent turn 或登录。
- 原版源码与安装包未修改；前序记录的 12 份代理源码指纹复核全部一致。没有运行完整 OpenCodex 服务或新增产品出站组件。

脚本、结果、首次失败轮次和来源指纹见[机器证据目录](../../../../../../.adg/evidence/OCX-CHANNEL-CAPABILITIES-20261016-PROTOCOL-VALIDATION/)。原版临时夹具不是产品实现，也不写入 `apps/`。

## 原版出口与上下文入口观察

### 档位参数可到达序列化出口

正常 Responses 请求包含 `service_tier = "ultrafast"` 时，在无覆盖决策下原版适配器保留该字段，回环模拟上游实际收到相同值。显式强制 priority 决策会改变最终字段，drop 决策会删除字段。

这比前序纯策略函数检查多验证了真实适配器的最终请求体和本地 HTTP 发送；尚未执行完整路由策略、真实渠道、模型目录选择或计费验证。

### 远程 v2 触发在第三方出口被转换为摘要

合成输入带 `compaction_trigger` 时，原版解析器识别它为压缩请求；第三方 Responses 适配器发出的请求已没有该触发项，而是包含文本 checkpoint 摘要提示，工具声明也被去掉。

将 `decodesNativeCompactionBlobs` 设为 true 后，触发项仍被转换，且第三方目的地仍未取得原生独立 compact 入口资格。该字段不能当成“启用渠道原生压缩”的总开关。

因此，本轮观察的这条路径可以由 Krill 模型生成摘要，但不能标为 Krill 原生远程压缩。位于该出口之后的出站层，仅按固定配置添加参数，不能补回完整原生请求。此结论适用于测试到的请求形状与包版本，不扩大为所有可能协议路径。

### history/notes 请求在渠道出口前被拒绝

在隔离客户端配置开启上下文管理、使用有效合成准入主体、仅配置 Krill 类第三方目的地时，调用原版 history 处理函数返回 HTTP 400：`History and notes require the native ChatGPT forward provider`，回环上游未收到请求。

另外，原版 routed 模型目录规范化会移除输入中的 `supports_experimental_context = true`。所以单独在渠道出口设置认证头或转发 history/notes，不能证明当前客户端、原版目录和上下文请求已贯通。

### 回程观察的有限范围

本地模拟上游返回的合成 SSE 内容经原生 fetch 读取后保持相同字节。这里只检查了适配器构造请求与回环 HTTP 的原样内容，没有验证产品出站层、完整 OpenCodex 流处理、背压、取消或真实渠道续聊。

## 失败轮次与修正

首轮组件检查在第 7 项断言处停止：脚本将多行摘要原文与 JSON 转义后的字符串直接比较。已改为比较结构化文本字段，保留首轮结果，修正后 20 项通过；原版组件未改。

配置反例首轮有一项被不完整夹具的 provider 名称校验提前拒绝。补齐合成 provider 名称和地址后，本地枚举接受，两个非法配置按预期拒绝，3 项通过。首次失败记录随机器证据保留，不作为上游缺陷。

## 对方案和下一步的影响

已确认的配置驱动、互斥选项、重启应用与不修改原版方向保留；但选项必须区分“客户端请求使用的协议”和“代理实际执行的摘要 / 原生处理”。保存远程 v2 或后台开关，不能直接显示为 Krill 原生能力已生效。

出站增强层首先适合继续验证明确的参数处理。原生压缩与 history/notes 的前置限制已得到组件级证据，应先找到原版公开支持的可达路径，再做完整隔离代理链路；未找到前列为上游依赖，不通过补丁、冒充官方目的地或前置分流自行绕开。

尚未完成：当前引擎实际压缩调度与互斥优先级、普通 / 后台和本地 / 远程的完整组合、Krill 原生压缩、history/notes 成功调用、真实续聊与会话归属、Ultrafast 实际授予及计费。后续真实渠道验证需要明确隔离输入、凭据来源和外部模型调用范围，不能默认使用日常认证。
