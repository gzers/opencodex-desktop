# DMD-OPENCODEX-DESKTOP-MANAGER OpenCodex 桌面管理器

> 2026-09-12 从协作包 `COL-LOCAL-20260912-01` 建立需求草案。参考线程只作为输入线索，不作为权威事实。

## 1. 问题与目标

当前 OpenCodex 主要通过命令行启动，缺少直观的安装路径管理、运行状态观察和配置迁移入口。目标是建设一个桌面管理壳，让用户可以：

- 发现和管理本机已有安装；
- 选择或新建安装目录、数据目录；
- 图形化启动、停止、重启并观察运行状态；
- 打开官方 Web 面板和查看日志；
- 在安全边界内导出/导入配置；
- 通过 WebDAV 同步非敏感配置或显式加密的凭据。

## 2. 范围

| 项 | 内容 |
|---|---|
| 包含 | 桌面壳、安装路径发现与选择、启停控制、状态面板、日志查看、官方面板入口、配置导出/导入、WebDAV 同步。 |
| 优先级 | P0：安装路径 + 启停 + 状态 + 日志 + 面板入口。P1：配置导出/导入。P2：WebDAV 同步与托盘增强。 |
| 不包含 | 重写 OpenCodex 核心代理、绕过官方 API、生产环境部署、自动同步运行中的会话数据、明文迁移凭据。 |

## 3. 候选技术与边界

| 主题 | 候选 | 边界 |
|---|---|---|
| 壳形态 | Tauri v2 + Rust 后端 + Web 前端 | 优先复用官方 CLI/Web 面板，不自建代理。 |
| 安装承载 | npm prefix / runtime root + OPENCODEX_HOME | 区分安装目录与数据目录。 |
| 启停控制 | 子进程或系统服务 | 需要可恢复的健康检测和日志落盘。 |
| 配置迁移 | 官方导出 + 自有封装 | 凭据必须显式加密，不默认同步。 |
| WebDAV | 冷同步 + 快照 | 运行中不写关键文件，冲突需人工确认。 |
