## 3. “完整公共封装”的可验收含义

### 3.1 已有能力与实际缺口

0.2.0已具备styles/tokens.css、base.css、materials.css，components/ui、layout、patterns，DEV Gallery以及43个稳定ID的源映射；不是没有公共层。登记和现有文件不能证明完整适配，registry当前统一pending_full_matrix也不能推断所有单项都坏了或已验。已确认缺口是配方不完整、业务局部覆盖、布局未统一采用、组合与实屏检查不足。

0.2.1复用现有架构，不把“完整”理解为创建大量空壳组件。要求**本版全部在用、自有UI类型都有可定位的规范/配方或组件、真实消费者及适用证据**；未受影响平台项有固定基线与复用理由，新增项先登记。不允许“特殊页面”无依据豁免，也不把仅用一次作为拒绝统一配方的理由。

### 3.2 分层职责与禁止事项

| 层 | 拥有内容 | 业务消费者可做 | 不得做 |
| --- | --- | --- | --- |
| Token/语义材质 | 字体层级、尺寸/间距/圆角、图标及点击区域、语义色、主题/画质/回退 | 通过公开语义规格选择 | 页面重造色板、字号档、玻璃底色或用低画质掩盖高档问题 |
| 基础控件与recipe | 按钮内容槽、输入/选择/复选/分段、标签、表格公共规则、焦点/禁用/加载 | 传props/slots、选择size/variant/density/surface | 用局部CSS覆盖控件的最终字号/内距/高度，或自行拼另一套基础控件 |
| layout | Stack/Inline、Tab+动作+分隔、详情头/锚点/侧栏、宽度与滚动适配 | 选择公开布局和断点，安放区域 | 各页手写一套sticky坐标、全局负margin/translateY修补 |
| patterns | 可点击信息行、设置行、工具栏、身份摘要、主次操作组、空态/字段组 | 注入内容与业务状态 | 每卡、每表复制配方；把业务保存写权塞进公共视图 |
| feature/adapter | 范围、身份、数据、校验、草稿、保存/同步、来源解释与通知事件 | 调用已有服务，组合公共UI | 基础控件直接读业务store/IPC/凭据或投递通知 |

输入框、textarea、checkbox、radio等可以保留原生HTML并共用样式契约；**不机械要求每个标签套Vue组件**，但size/状态/label/错误/焦点等不能任意组合。业务专用的ModelRuleFields保留feature职责，基础视觉和字段排版须同源。必要的业务网格/列宽可配置，不能把所有表格硬套同一比例。

### 3.3 各类公共交付与采用面

下面是实施责任清单，不是第二份组件目录。确切稳定ID沿现有component-catalog/registry；新发现类型先归已有ID，确有新语义才新增。

| 类别 | 要补齐/核实 | 实际采用及验证范围 |
| --- | --- | --- |
| 字体/内容/图标/品牌 | 字号与行高、数值/长ID、图文基线与图标槽、点击区域 | 概览同层行、按钮、侧栏、表格、标题与状态；品牌素材不另画 |
| 主题与材质 | default/hover/focus/disabled/loading，高中玻璃/低档实底及合法无blur回退 | 固定Tab、详情头、控件、卡片、浮层与通知宿主的受影响消费者 |
| 文字/图标按钮 | btn-content布局与gap，纯图标、主次/危险、加载保持布局 | 全部实际导入/配方消费者，不只模型页；概览plain信息行补共用配方 |
| 表单选择与状态 | label/help/error、继承/自定义/未知、单位、Select/Segmented、checkbox/半选、switch、slider | 三处模型规则编辑、设置、同步树、选择器与批量场景；来源来自真实解析 |
| 数据显示 | 选择槽位、表头/行同列、内容最小宽度、长值全文出口、启停/排序 | 渠道表、模版表、型号表和共享树表；行选择不承担启停 |
| 布局与组合 | Tab全宽分隔、无色玻璃、固定避让、导航/操作/保存可达、卡片纵向gap | 所有自有主页面及模型详情；保留连续正文与同一草稿会话 |
| 浮层与反馈 | menu/select/dialog的定位、层级、焦点、busy、取消、空错状态 | 版本/连接/外部任务/Agent/预览、同步确认；通知注册和读/解决语义不改 |
| 复杂公共选择器/节点 | 复用生产组件，不从原型复制DOM；长值/推理/Fast/节点状态 | 实际调用点与业务adapter，执行配置共用，不发真实模型请求 |
| 平台自有外壳/托盘 | 确认是否受公共Token/字体/图标改动影响，明确复用边界 | macOS/Windows在有影响时走原生检查；不把网页平台样例当原生通过 |

开始每批前做实际静态导入图/模板类名/配方扫描，对照登记重点消费者，排查route/feature及全局CSS对公共样式的覆盖。记录准确路径和理由，不能只更新手写43行登记。DEV Gallery直接使用相同生产组件、公共配方及无副作用fixture，不抄一套更好看的展示DOM。

### 3.4 防偏离检查必须补齐

- 当前component-style-rules仅查公共组件内硬编码常量，不足以覆盖业务覆盖及渲染。保留其价值，增加针对公共控件关键属性的消费者覆盖检查、来源/采用完整性检查和实际几何断言。
- 对需要例外的组合，优先扩展公开API/recipe；例外须有准确文件/选择器、属性、理由、影响范围及验收用例，不开放整个目录或笼统白名单。业务内容宽度和布局不是一律禁止CSS。
- 加入一组故意覆盖字号/内距的负例，证明检查会失败；修复后再验证正例。静态检查不能替代可见结果。
- 图文居中/gap、选择列宽、表头对齐、点击区内距、保存可见、固定避让须有真实渲染证据。明确像素容差与逻辑/物理坐标，禁止仅靠源码包含字符串判通过。
- 注册项、实现、gallery、采用、检查结果分别记录；适用项关闭需源SHA和实际证据。已检查项不继续只挂统一pending_full_matrix，未检查项也不能批量改为passed。具体记录结构在实施时沿现有登记/回执扩展，不再另建事实库。

### 4.1 页面还原的具体限制

- UI-001、UI-002、UI-007：选择列窄且独立，渠道/版本/操作分配按内容和可用宽度；同层行内操作密度统一。型号区去同值重复、整理工具栏，但保留公开范围/手动ID等正式能力和完整排序。
- UI-006、UI-013、UI-014：列表动作与详情动作按上下文区分；详情侧栏合理分组，导航可滚而关键保存/状态稳定可达。不能靠重新把动作复制到顶部解决侧栏过长；保存全集/当前渠道/当前模版语义原样保持，未确认输入仍受保护。
- UI-008：版本、来源、编辑基准在详情可见；切换版本遇脏缓冲按既有保护处理。原型“已采用”等mock不能作为真实数据；不自动改默认或采用关系。
- UI-009、UI-010：连接摘要及默认配置回归主次层级，必要的安全连接确认流程继续保留；字段模式/来源按真实规则显示，不因视觉还原清除未知、人工锁、父层或尚未确认值。
- UI-011：列表/设置常驻入口复用现有AgentExecutionField及同一本机执行设置；保存返回原输入，不能创建第二套偏好或触发生成。
- UI-005：外层范围仍消费同一目录、预设、对象树与凭据状态；文件导出按当前范围冻结，WebDAV区分本机未保存/已保存/传输/待采用。导入子集来自包内内容，不能被页面导出预设替代。选范围不自动执行网络/覆盖或取消确认。
- UI-012、UI-015：少量互斥选项按公共Segmented呈现；三卡同层文字一致，是否增大先同环境测量并沿已有字号Token选取，不能擅自放大全软件字号。信息行的hover/focus内距与普通行文字对齐共同核对。

## 5. 验证、证据与测试复用

逐问题用例及环境详见[验收矩阵](../04-项目资料/03-项目协作资料/01-协作包/2026-10-04-模型配置管理与同步/03-测试验收/0.2.1-UI修复验收矩阵.md)。以下是必须分开的四种结论：登记存在、代码实现、页面采用、实际验证。原型截图或gallery好看，只能证明各自所在层。

- 日常批次走类型/单元/组件/来源和消费者守卫及确定性fixture；公共规则改动跑真实受影响消费者，不每改一行都跑发布全套。
- 页面视觉对照至少基准1180×760/100%，另按适用范围覆盖900×600、50/150/200%、亮暗×高中低、长中英文/版本/ID和不同状态；采用覆盖代表组合+风险交叉补测，不要求无意义的全笛卡尔积。不得把原型的缩放模拟当生产缩放证据。
- 公共CSS有跨平台影响：须有Windows真实WebView/壳内受影响页面检查，不只macOS或CI构建；托盘/caption没有改动且未受影响时复用固定原生证据，不重跑无关生命周期长期采样。
- 模型改动验证字段、缓冲、选择/启停、版本上下文及保存范围；同步外置不是纯CSS，必须回归范围/凭据/依赖/冻结/取消/采用。使用隔离目录和本机可控服务，不触碰日常账户、付费生成和用户WebDAV。
- 未改的0.2.0服务/存储/签名/安装等按固定SHA和输入边界复用；涉及其接口或行为则补针对性回归，不能以“上版测过”跳过受影响用例。
- 集成候选稳定后走一次适用完整检查和双平台构建，后续改动只重跑受影响门；拟发布另需对应制品身份/验签/安装回读及发布决策，不用源码测试替代真实制品。当前不执行。

证据最小字段：问题/稳定组件ID、实际消费者、源SHA、基准与候选、窗口/缩放/主题/画质/平台/数据状态、步骤、可见结果、测试结果及适用限制。新截图与旧缺陷证据并存；截图做脱敏，原日志/临时运行输出归.adg或ignored runtime，不混入长期规格。

## 6. 完成与交接门
