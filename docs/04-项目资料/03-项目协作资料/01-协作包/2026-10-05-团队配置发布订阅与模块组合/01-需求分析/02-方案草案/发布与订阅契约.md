# 发布与订阅契约

状态：候选领域与接口契约，不是已经支持的 API 或正式 schema。职责与分期见 [总体方案](总体方案.md)，采用与恢复见 [客户端流程](客户端流程与本地共存.md)。

## 1. 身份与对象

| 对象 | 建议身份 / 关键内容 | 所有者与责任 |
|---|---|---|
| 服务实例 | serviceInstanceId、受验证的服务地址、协议能力 | 服务端；换域名不一定换实例，实例变更必须重新确认信任 |
| 发布命名空间 | namespaceId、ownerType=user/team、ownerId | 个人或团队；显示名可改，身份稳定 |
| 发布源 | sourceId、命名空间、说明、可见范围、维护者、轨道 | 内容维护者；同名源不等于同一个源 |
| 发布版本 | releaseId、versionLabel、formatVersion、manifestDigest、模块清单、兼容要求、说明 | 已发布正文不可变；修改产生新 release |
| 模块快照 | kind、moduleRevision、schemaVersion、内容清单 / 摘要、依赖、范围 | models / skills / mcp 独立版本；模型内部再保留精确 templateRef |
| 订阅关系 | subjectType=user/team、subjectId、sourceId、模块 / 条目范围、固定 / 跟随策略、revision | 服务端存接收意图；不是本机已应用证明 |
| 本地组合方案 | profileId、模块选择、本地保留选项、范围与版本策略 | 用户维护；可选把非敏感选择同步到账户 |
| 本机解析记录 | 精确 release / module / 条目身份、digest、依赖、适配要求 | 每台设备保存；区分“候选解析”与“成功采用” |
| 本机应用记录 | planId、基准、分步结果、备份、读回、待重启 / 授权 | 仅本机；不能由服务端远程改成成功 |

发布对象的完整身份由服务实例 + 发布命名空间 + 发布源 + 对象 ID 构成。模型导入需要单独保存从发布身份到本机 channelId / templateId / endpointId 的映射，不能按名称、模型别名或 URL 猜测同一对象。

复制为本地对象或派生源时创建新身份，保留 originRef 供追溯，并重写所选范围内的引用。originRef 不授予访问 / 再分发权，也不自动关联后续更新。更新已有源时保留其对象身份；删除后同名重建仍是新对象。

本包“发布源”是内容分发对象 ContentSource；服务端用量方案的 Source 是采集来源，两者不能共用一个 source_id 命名空间或绑定含义。订阅 / 切换组合不变更用量空间、设备归属或待传历史；需要切换工作用量空间时仍走原用量来源绑定流程。

## 2. 发布格式与版本分层

| 版本 | 回答的问题 | 规则 |
|---|---|---|
| Desktop / 服务端版本 | 软件是否支持功能 | 与内容发布版本分开 |
| formatVersion / module schemaVersion | 解析格式是否兼容 | 未支持的必选模块阻止采用；不丢字段后继续 |
| 发布版本标签 | 维护者给这套内容起什么版本名 | 可读标签；不靠字符串大小判断新旧 |
| releaseId / moduleRevision / digest | 实际是哪份不可变内容 | 精确解析、缓存和恢复使用 |
| templateId + revision | 模型策略引用哪份模版 | 延续 v0.2.0，不能用“最新模版”动态替代 |
| 轨道及 generation | stable / preview 当前推荐哪份 release | 轨道可前进或显式回指历史；每次变更 generation 单调增加 |

发布清单列出模块及每个内容对象的路径、字节数、媒体类型、SHA-256、依赖与兼容要求。清单使用固定规范化规则计算摘要，摘要字段不参与自身计算；必须提供测试向量。仅知道 digest 可以查内容不代表有权下载该内容。

本机跟随 stable 的一次解析必须冻结成精确版本集合；下载过程中轨道前进不改变此次集合。显式回退轨道保留新的 generation 与理由，客户端显示“推荐回退”，不当作普通向前升级。相同对象 / revision 出现不同内容时拒绝，不最后写入者覆盖。

组合方案示意如下；是数据关系示例，不是客户端可直接读取的 schema，也不是实际发布对象。它省略了生产必需的摘要、权限、依赖和校验字段。

```json
{
  "exampleOnly": true,
  "profileName": "团队研发 + 个人工具",
  "modules": {
    "models": {
      "source": "team-a/model-system",
      "selector": {"track": "stable"},
      "resolvedRelease": "release-models-14",
      "keepLocalItems": true,
      "keepLocalOverrides": true
    },
    "skills": {
      "source": "team-b/coding-skills",
      "selector": {"track": "stable"},
      "includeIds": ["review", "testing"],
      "newItems": "ask",
      "keepLocalItems": true
    },
    "mcp": {
      "source": "team-c/tools",
      "selector": {"releaseId": "release-mcp-20"},
      "includeIds": ["docs-search"],
      "keepLocalItems": true
    }
  }
}
```

完整的运行锁定记录只在应用成功后晋升；候选解析有自己的记录，失败时不得把服务端或本机“当前版本”更新为候选版本。

## 3. 选择范围与依赖闭包

发布者和接收者都能选择范围，但接收者只能在有权读取的发布范围内选择，不能通过订阅过滤器取得未分享条目。

| 范围 | 发布时 | 订阅时 |
|---|---|---|
| 整套 | 选择模块和内容，冻结本次清单 | 一次填写各模块的推荐选择，仍可取消模块 |
| 模型体系 | 全体系 / 所选渠道与模型 / 所选模版 | 选择渠道或只接收模版；所需策略和模版依赖同时解析 |
| Skills / MCP | 勾选条目；Skill 是完整内容包，MCP 是描述及可固定的制品引用 | 固定条目 ID 集合，或显式选择持续接收全部条目 |
| 全局字段 | 全局 Fast、来源排序等单独选取 | 明示全局影响，不被局部范围悄悄带入 |

搜索结果、页面过滤和发布范围分离，预览必须列完整 ID 清单。发布时默认只选已保存内容；若允许发布草稿，必须先形成独立、完整、可校验的发布快照，标明未在本机验证，不上传编辑缓冲或半次应用状态。

依赖解析要求：

1. 模型策略引用的模版、渠道协议声明、模版渠道范围、排序引用要齐备；局部导出把需要的全局规则明确投影为局部引用，并保留原身份映射。
2. 硬依赖必须满足确定的版本 / 能力条件；本次实际采用锁定精确 digest。软建议缺失只提示；不得把所有被推荐的 Skills / MCP 偷偷变成必装。
3. 依赖有独立访问控制：发布者有下载权不等于有再分发权。引用私有源时，接收者必须同时有权访问；不能通过上传依赖副本扩大受众。首期不支持再分发的内容只保留有权解析的引用，缺权阻止采用。
4. 不同模块可独立换源，但硬依赖必须重新求解；无满足组合时保留原运行态，指出冲突，提供一并更换 / 取消本次操作。
5. 版本解析要检测循环、重复对象冲突、缺失制品、兼容版本、体积上限及解包路径。Skill 目录不能省略正文引用的文件后报告完整；外部依赖单列，不假装已打入包。

所选 ID 默认固定，源里新增条目显示“可新增”，不自动启用。显式选择“包含以后新增项”也只扩展候选范围，新增命令、端点、权限与运行影响仍进入预览。

## 4. 本包范围之外的私密内容

默认发布仅允许可分享字段。密码、API key、Cookie、OAuth 会话、订阅访问令牌、系统凭据引用、个人绝对路径、运行时完整配置、模型调用内容和用量账本均不进入包。自由文本、Skill 文件和 MCP 参数也须检查潜在私密内容；扫描只是辅助，不能宣称能识别所有秘密。

模型策略继续只保存逻辑端点与协议。为团队接入便利，可另选“连接建议”作为发布清单的可选附件：明确预览非敏感 origin / 路径、协议与需要填写的参数；拒绝 user-info、带认证的 query / fragment 和秘密头部。接收者确认地址后新建或绑定本机连接，不直接覆盖旧绑定。这是后续扩展提案，不回改 v0.2.0 双文件的职责。

MCP 远端地址 / 本地启动参数天然属于其描述的一部分，同样检查静态敏感值并改为接收端填写的变量。发布侧保存“需要哪个变量 / 哪种认证”，接收侧填值并按服务身份存本机凭据。改域名、可执行命令、包来源或权限时原授权不能静默复用。

订阅服务登录与 MCP 目标认证互相独立，令牌不转用。团队共用上游模型服务也不等于分发同一管理员 API key；可采用每人本机凭据或组织另行提供的、按人授权的代理接入，这不是首期凭据托管能力。

## 5. 团队与访问授权

首期建议支持私有、指定用户、指定团队三种可见范围；站内可发现 / 公开目录作为后续选项。订阅地址标识源，不默认充当永久 bearer secret。邀请链接应短效、单次或可撤销，交换成员 / 读取权限后不能成为长期传播的万能下载地址。

团队、成员状态、所有者 / 管理员 / 成员、membership_epoch_id 和授权版本复用 [团队与数据权限模型](../../../2026-10-05-多用户多设备用量与服务端协作/01-需求分析/02-方案草案/团队与数据权限模型.md)。内容域增加源级维护与读取授权：建议团队所有者管理源权限，管理员可管理团队订阅推荐，具体源的发布权仍显式授予；统计角色不直接转化为所有源的发布权。

| 动作 | 源所有者 | 被授予发布权的成员 | 有读取权的用户 / 团队成员 | 站点管理角色 |
|---|---|---|---|---|
| 修改可见范围 / 授予角色 | 允许 | 无默认权限 | 禁止 | 只按明确站点管理策略执行并审计 |
| 发布新版本、移动发布轨道 | 允许 | 允许指定源 | 禁止 | 不因统计管理权限获得该权利 |
| 读取版本、订阅、下载 | 允许 | 按读权限 | 允许受权范围 | 不默认为所有私有内容读取者 |
| 设置团队订阅推荐 | 需同时有团队管理权限 | 无默认权限 | 需团队订阅管理权限 | 无自动授权 |
| 编辑自己的本地配置 | 本人设备 | 本人设备 | 本人设备 | 无远程改写能力 |
| 上传成员本地配置或执行命令 | 不随上述角色授予 | 不授予 | 由设备使用者显式操作 | 不授予 |

团队管理员只能让团队订阅已授予该团队访问权的源，不能用自己的个人读取权替所有成员分享。成员访问按实时成员关系 + 源授权共同判断；退出团队即停止后续受权获取。数据库 / 存储运维管理员的技术访问不等于产品角色隔离，不能宣称端到端加密或服务运营者无法读取内容。

重新加入同团队建立新成员期，旧发布令牌、旧源维护授权与未提交上传不得自动恢复。面向全体现有成员的团队读权限可按新成员期重新计算；个人订阅是否继续接收需重新校验，旧缓存不能作为仍有权读取的证据。团队暂停 / 解散分别冻结新发布和按策略关闭读取，内容保留责任沿用团队生命周期，不自动转成退出者个人源。

隔离覆盖目录、清单、内容对象、依赖查询、订阅、缓存、短效下载授权与后台任务。内容摘要相同可做内部去重，但不得让已知摘要绕过 ACL、泄露其他租户的内容或存在性。

## 6. 发布与拉取过程

发布流程：本地选范围 → 依赖与私密内容预览 → 上传暂存对象 → 服务端按清单核验齐备与权限 → 提交不可变 release → 可选将某轨道指向它。内容最后提交清单，未完成上传的内容不对订阅者可见。

每次上传 / 提交使用幂等键；重复请求只返回同一结果。轨道更新携带 expectedGeneration，两个发布者并发发布可得到两个 release，但同一轨道的竞争必须显式解决，不能悄悄覆盖对方的推荐。下架状态放在独立元数据，不改已发布正文。

接收流程：解析订阅范围与权限 → 冻结精确版本 → 下载到暂存 → 校验清单、内容与依赖 → 形成候选解析记录 → 与本机组合预览 → 用户采用 → 三类适配器应用与读回。收到更新通知只触发检查，不能直接写运行配置。

首期拉取可用条件请求、手动刷新、带抖动的周期检查与退避；频率为可配置建议，遵循服务器限流。权限检查先于 304 / 下载缓存响应；失败保留上次成功状态。服务端不可用和已撤销权限要分别展示，不把超时误报为取消订阅。

## 7. 接口草案

路径仅表达资源边界；后续 OpenAPI / SDK 从冻结接口派生，不另造事实源。内容源使用 /v1/content-sources，用量采集来源保留服务端包的 /v1/sources，接口与对象身份都区分。

| 建议接口 | 用途 | 必要约束 |
|---|---|---|
| GET /v1/capabilities | 服务实例、格式、认证与模块能力 | 未确认实例前不发送旧站凭据 |
| GET /v1/content-sources | 查询有权发现的发布源 | 按主体过滤；分页；不泄露私有名称 |
| POST /v1/content-sources/{id}/uploads | 建立暂存发布 | 源发布权、配额、体积、幂等；不执行上传内容 |
| POST /v1/content-sources/{id}/releases | 校验并提交完整 release | 对象齐备、依赖可分发、不可变、发布审计 |
| PATCH /v1/content-sources/{id}/tracks/{track} | 推进 / 回退推荐轨道 | expectedGeneration；冲突返回并保留双方 release |
| GET /v1/content-sources/{id}/releases/{release} | 取得版本清单 | 当前读权限；兼容说明；精确身份 |
| POST /v1/subscriptions | 建立个人或团队订阅 | 团队操作权与源读取权同时满足 |
| PATCH /v1/subscriptions/{id} | 改模块范围 / 版本策略 / 暂停 | revision 条件更新，避免多设备设置互相覆盖 |
| POST /v1/subscriptions/{id}/resolve | 返回一次冻结的候选版本集合 | 精确依赖、权限、大小；不能只返回可变 latest |
| GET /v1/content/{digest} | 读取获授权内容 | 以受权 release 校验可达性；不能凭摘要公开下载 |
| DELETE /v1/subscriptions/{id} | 取消后续接收 | 不等于远程删除设备配置；团队 / 个人归属检查 |

团队成员与邀请接口复用共用身份域另行冻结。设备可以可选回报仅含版本 ID 与粗粒度状态的采用摘要用于本人跨设备查看；不上传本地覆盖、路径、秘密、日志或实际配置。团队管理员查看成员采用情况是另一权限 / 产品决策，首期不默认开放。

## 8. 下架、撤销、离线与保留

| 情况 | 服务端 | 客户端 |
|---|---|---|
| 发布新版本 | 原版本保留，新建 release | 提示候选；固定版本者保持固定 |
| 条目从新版本移除 | 清单显式记录范围内的 removedIds / 完整清单语义 | 预览停用 / 移除影响；与“本次未选”区分 |
| 版本下架 / 撤回 | 停止新解析，保留审计与必要恢复元数据 | 已知被撤回的候选不继续新采用；提示已安装影响，不静默远程执行 |
| 取消订阅 / 失去读取权 | 停止后续取内容、撤销访问凭据 | 默认保留已应用快照供退出选择，清理未采用候选按本机策略执行 |
| 网络离线 | 无法提供新状态 | 已验证内容按本机许可和策略继续用；显示最后检查时间，不宣称实时受权 |
| 删除发布源 | 新访问停止，受保留策略约束 | 不把 404 当“清空本地”；显示来源不可达 |

已下载明文无法可靠远程追回；产品不承诺撤销读取权就能擦除离线副本。已签发短效下载 URL 可能在有效期内继续有效，需冻结最长时效；严格即时撤销场景必须经鉴权代理或等效方案，不能把对象存储预签名链接当即时撤销机制。

暂停订阅仅停检查和下载；停用模块进入本机应用流程；取消订阅解除接收关系；删除本地内容为另一次明确操作。恢复旧组合时仍核对已知撤回状态、兼容、依赖、许可和本机绑定，不因“历史版本”跳过检查。

保留策略分别覆盖未完成上传、被下架内容、轨道历史、订阅变更审计、设备候选缓存和本机恢复记录。服务端清理不能删除仍被有效发布引用的依赖；只保留有限个版本时须提前说明固定订阅的可下载保证和例外，不承诺无限历史。
