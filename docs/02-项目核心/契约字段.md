## 1. 导出容器

### 1.3 载荷与拒绝策略

| 项 | 要求 | 冻结 |
|---|---|---|

| 未知字段 | 拒绝，不做"尽力而为"的解析 | ✅ |

## 2. 同步清单（manifest）

面向「本机 ↔ WebDAV 远端」这条边界。远端被视为**不可信**，清单与载荷都不按远端声明直接信任。manifest 单独使用 AEAD 传输包；AAD 绑定格式、版本、兼容版本、设备名与 schema 类型。远端不能替换、裁剪或重排清单。清单里的哈希只用于检测传输损坏与回放，不替代密码学认证。

| 字段 | 类型 | 取值 / 约束 | 冻结 |
|---|---|---|---|
| `format` | string | 固定 `OCXDSYNC` | ✅ `FZ-30` |
| `version` | int | 固定 `1`；不符即拒绝 | ✅ `FZ-30` |
| `compat_version` | int | 固定 `1`；用于识别旧清单回放 | ✅ `FZ-30` |
| `snapshot_id` | string | `snap_<UTC14>_<12 位随机 hex>` | ✅ `FZ-30` |
| `created_at` | timestamp | 生成时间 | ✅ `FZ-30` |
| `device_name` | string | 生成设备名，参与 AAD 与冲突判断 | ✅ `FZ-30` / `FZ-45` |
| `artifacts` | array | 逐件记录 `name`、`size`、`sha256`，参与 manifest 认证 | ✅ `FZ-30` / `FZ-45` |

### 2.1 传输与校验顺序

```text
上传：载荷逐个先传 → manifest 最后传
下载：先取 manifest → 校验格式与协议版本 → 逐件下载并按 manifest 校验（大小 + 哈希）→ 解密 → 应用
```

- **载荷先、manifest 后**：保证「半同步」不会被当成有效快照。
- **manifest 与每个载荷密码学绑定**：逐件哈希必须进入受认证保护的 manifest；载荷哈希与清单不一致、清单本身解密或认证失败，都直接拒绝。
- 逐件校验通过后才应用；校验失败**不应用远端内容**，保持本地不变。
- **本地保存最后接受的快照事实**：`snapshot_id`、接受时间、生成方版本和 manifest 摘要。下载时先比对旧快照事实；缺失、乱序或旧于本地最后接受快照的清单默认进入冲突，**不得直接应用**。
- 远端变更检测：记录上次同步的 manifest 哈希 + ETag，比对识别远端变化。
- 并发：**单端点单次同步**，同步互斥串行化。
- 上限：manifest 与单个对象均有大小上限；解压类载荷另有条目数上限（防压缩炸弹与路径穿越）。
- 载荷不拆分；单载荷 256 MiB、manifest 16 MiB、快照 10,000 条 / 1 GiB；连接 15 秒、单件 10 分钟、总时限 30 分钟，失败按 2/4/8 秒重试 3 次；覆盖备份沿用备份保留策略。

## 3. 备份清单

每次备份登记一条 `BackupRecord`（字段见 `领域模型.md` §6）。清单文件本身的最小字段：

| 字段 | 类型 | 说明 | 冻结 |
|---|---|---|---|
| `backup_id` | string | 备份标识 | ✅ |
| `kind` | enum | `upgrade` `import` `sync_overwrite` `data_root_move` `extension_write` | ✅ |
| `target` | string | 被备份对象 | ✅ |
| `created_at` | timestamp | 生成时间 | ✅ |
| `content_hash` | string | 内容摘要（SHA-256），与 `BackupRecord.content_hash` 同义 | ✅ `FZ-21` |
| `stored_at` | string | 备份落点（相对 `backups` 分区） | ✅ |
| `restorable` | bool | 是否已验证可恢复 | ✅ |

- 备份必须**可定位、可校验、可恢复**；备份失败阻断后续破坏性动作。
- 写入事务还会记录「目标、时间、备份位置、内容摘要」清单，用于冲突检测与恢复（`WR-06`）。

## 4. CLI 契约（`ocxd`）

面向「`ocxd` ↔ 运行中实例」这条边界。官方 CLI 仍叫 `ocx`；`ocxd` 是管理器自己的入口。

### 4.1 总则

| 项 | 要求 | 冻结 |
|---|---|---|
| 默认状态 | 关闭；启用后才注册入口 | ✅ |
| 执行方式 | 经本机 IPC 委托运行中实例，**不产生第二写入者** | ✅ |
| 能力范围 | 仅管理器自有域：发现与只读状态、启停、数据根、备份、加密导出/导入、WebDAV 同步、自更新检查 | ✅ |
| 明确不开放 | provider、路由、模型映射与 OpenCodex 核心运行配置的写入 | ✅ |
| 实例未运行时 | 只读命令降级说明；变更类命令报错，不绕过实例直接写状态 | ✅ |
| 机读输出 | 提供 `--json`，字段、版本与幂等规则见 §4.3 | ✅ `FZ-35` |
| 破坏性操作 | 必须带确认标志，校验、备份与确认语义与 GUI 一致 | ✅ |
| 自发现 | `ocxd --help` 是能力自发现入口 | ✅ |
| PATH 注册落点 | `/usr/local/bin/ocxd` symlink；关闭时只删除指向本应用的 symlink | ✅ `FZ-38` |
| 调用审计 | 记录调用字段（**不含敏感值**），保留 90 天 / 5,000 条 | ✅ `FZ-40` |

## 6. 托管安装记录（管理器 ↔ 磁盘，2026-09-25 新增）

面向「管理器托管 OpenCodex 安装」这条边界。写入目标是数据根的两个分区：`manager state`（来源与历史）与 `runtime`（包体）。

### 6.1 `runtime.json`（`manager state`）

| 字段 | 类型 | 取值 / 约束 | 冻结 |
|---|---|---|---|
| `schema_version` | int | 固定 `1`；未知版本只读降级、不写回 | ✅ `FZ-48` |
| `source` | enum | `explicit` / `managed` / `discovered` / `unresolved` | ✅ `FZ-48` |
| `path` | string \| null | 解析出的 `ocx` 路径；`unresolved` 时为 `null` | ✅ `FZ-48` |
| `resolved_version` | string \| null | **当前来源**的版本；来源路径变化（换到别的路径或变 `unresolved`）时清空 | ✅ `FZ-48` |
| `resolved_at` | timestamp | 最近一次解析时间 | ✅ `FZ-48` |
| `history` | array | 安装 / 卸载历史（见 §6.2），最多保留 50 条 | ✅ `FZ-48` |

- **优先级**：用户显式指定 > 托管安装 > 自动发现候选；应用**不读取 PATH**。
- **只在终态写入**：安装进度（百分比、命令行明细、离线段）不落盘。
- **版本归属**（2026-09-26 明确）：`resolved_version` 描述**当前来源**，不是「历史上读过的任意版本」。
  来源路径发生变化（含切到另一条路径、或变 `unresolved`）时必须清空；安装终态按落地产物版本回填。
- **禁止写入**：代理地址、令牌、任一凭据、安装明细原文；用户 `~/.npmrc` 的令牌不读取、不解码、不展示。
- 生效语义：写盘后由共享解析句柄重新解析；代理进程正在运行时提示「需重启才生效」。

### 6.2 `history` 条目

| 字段 | 类型 | 取值 / 约束 | 冻结 |
|---|---|---|---|
| `action` | enum | `install` / `uninstall` | ✅ `FZ-48` |
| `result` | enum | `succeeded` / `failed` / `rolled_back` | ✅ `FZ-48` |
| `package` | string | 固定 `@bitkyc08/opencodex` | ✅ `FZ-48` |
| `version` | string | 本次安装 / 卸载涉及的版本 | ✅ `FZ-48` |
| `target` | string | 落地前缀（自定义前缀时为用户所选路径） | ✅ `FZ-48` |
| `at` | timestamp | UTC | ✅ `FZ-48` |
| `reason` | string \| null | 失败 / 回滚原因（已脱敏） | ✅ `FZ-48` |

### 6.3 `.runtime-manifest.json`（`runtime` 分区，随前缀）

| 字段 | 类型 | 说明 | 冻结 |
|---|---|---|---|
| `package` | string | 固定 `@bitkyc08/opencodex` | ✅ `FZ-47` |

## 7. 工程重构不改契约（2026-09-27，IMP-04）

IMP-04 的目录与组件重构是**等值迁移**：仅调整前端模块归属与公共组件抽取，**不新增、不删除、不改名、不改取值域**任何跨边界字段（IPC 请求/响应、CLI、导出容器、同步清单、备份清单、通知、状态上报、托管安装记录）。

- 迁移前后同一操作产生的持久化与 IPC 数据形状一致；已冻结字段（`FZ-*`）保持不变。
- 若后续确需变更字段，仍按本文件 §总则「先改 IMP，再回写本文件」执行，禁止静默漂移。

## 8. 统一卸载契约（Revision 11，2026-09-28）

> 来源：`DMD` Revision 11（卸载覆盖**任意已解析来源**并由**应用执行**）。本节修订 `FZ-51`：范围轴由「托管 / 官方」改为「只删包体 / 连运行态一起删」——归属不再等于范围。既有 `uninstall_managed`（托管包体的删除与备份）语义不变。

### 8.1 请求（前端 → 后端）

| 字段 | 类型 | 说明 | 冻结 |
|---|---|---|---|
| `scope` | enum | `body`（仅包体与入口）\| `full`（完整卸载）；其它值一律拒绝（`bad_scope`） | ✅ `FZ-51r` |
| `autoBackup` | bool | 卸载前自动生成备份。**勾选即承诺成功**：备份失败即中止卸载（`T-I13`） | ✅ `FZ-51r` |
| `cleanData` | bool | 完整卸载时是否清空 `OPENCODEX_HOME` 的非自有残留 | ✅ `FZ-51r` |
| `confirmation` | string \| null | 显式确认（界面勾选清单后回传）；**非空**才算已确认，否则拒绝（`uninstall_confirmation_required`） | ✅ `FZ-51r` |

### 8.2 方案（只读，`plan_runtime_uninstall`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `sourceKind` / `sourcePath` | enum / string | 当前已解析的运行来源 |
| `managed` | bool | 包体是否由本产品托管（决定由谁移除） |
| `removable` / `reason` | bool / string | 形态无法确认时 `removable=false` 并给出原因；界面必须据此**禁止确认** |
| `backupId` | string \| null | 已检测到的可复用备份 |
| `removeObjects` | string[] | 将移除的包体 / 入口（托管给路径；npm 全局给「npm uninstall -g @bitkyc08/opencodex」） |
| `runtimeObjects` | string[] | 完整卸载时的运行态对象（service / shim / shell hook / 客户端 config） |
| `dataObjects` | string[] | 官方 `OPENCODEX_HOME` 自有清单（只读官方记录） |
| `residueCandidates` | string[] | 非自有残留候选（显式类别，`T-I12`） |
| `officialCommand` / `externalCommand` | string \| null | 将执行的固定命令（只读展示；包名硬编码） |

### 8.3 结果（后端 → 前端）

| 字段 | 类型 | 说明 |
|---|---|---|
| `scope` | enum | 回显 `body` / `full` |
| `sourceKind` / `sourcePath` | enum / string | **卸载后**重新解析的运行来源 |
| `backupId` / `backupDirectory` | string \| null | 本次或复用的备份 |
| `steps[]` | array | 每步 `{name, status: ok\|skipped\|failed, detail?}`；**失败不静默** |
| `residue[]` | array | 残留核验 `{path, status: cleared\|present\|unknown}`；**`unknown` 不得被当成已清除**（`T-I14`） |
| `officialOutput` | string[] | 官方命令（掩码后）的输出行 |
| `needsRestart` | bool | 卸载后是否需要重启才生效 |
| `message` | string | 可读结论文案 |

### 8.4 稳定错误码（卸载）

`bad_scope`、`uninstall_confirmation_required`、`uninstall_backup_failed`、`uninstall_command_failed`、`uninstall_no_manifest`、`uninstall_package_mismatch`、`uninstall_externally_modified`、`uninstall_target_mismatch`、`uninstall_locked`、`uninstall_filesystem`、`install_in_progress`。

### 8.5 不受修订影响的部分

`runtime.json` / `history` 条目 / `.runtime-manifest.json`（§6.1 ~ §6.3）字段不变；卸载仍写一条 `action="uninstall"` 的历史（`result` 为 `succeeded` / `failed`）。
