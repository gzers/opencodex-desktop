## 用户入口与实际请求

设置 → 通用 → 网络 →「检查连接」一次明确诊断，使用后端读取的当前保存代理偏好，不接受调用方URL。分别请求固定GitHub管理器仓库API与官方npm包latest元数据，两个目的地并行独立产生结果，失败一方不掩盖另一方。每项记录固定目标、状态、HTTP状态、有限Retry-After秒数和本次检查时间；不回传请求/响应原文、代理地址、凭据、模型内容或自由异常。

结果区分连接与来源核验通过、超时、限流、HTTP错误、网络连接失败、来源不符/重定向、响应越限、代理/客户端配置无效。HTTP429或403且明确rate-limit剩余0标限流；重定向不跟随，不能把能连到任意网页当身份通过。GitHub核验full_name/html_url，npm核验包名、合法版本与官方仓库字段；严格JSON拒绝重复字段，读取有体积和总时间上限。TLS校验始终保留。

本次check只作诊断，不启动npm、模型、WebDAV或安装，不修改版本事实或配置，不自动重试。HTTP客户端共用固定超时/UA/无重定向政策，None不继承环境代理，Manual只用明确保存地址及networkNoProxy；System保持既有平台默认发现。保存代理设置的入口保持，不新增另一套GitHub专属代理。此批只把诊断和更新说明HTTP请求接免代理项，不声称已改写全部其它HTTP消费者。

## 更新说明

说明仍是独立的精确target/channel/candidateVersion操作，不参与版本检查或安装。HttpSource将timeout、限流、其它HTTP、身份/版本/仓库校验、超限和网络失败分类传入Details.failure；404只表示该精确发布不存在，不当网络错误，不能猜一个发布链接。失败状态与notesState分开：当前更新器已提供的正文保留其来源；远端独立查询失败不抹除它，不把它显示成旧缓存。

缓存只复用同root/target/channel/version/repository且未过期、时间合法、内容/来源一致的已核验记录。显式刷新失败可回显上述精确缓存，保持原fetchedAt，checkedAt记录本次核对，cached=true并携带本次failure；原缓存字节不被失败覆盖。其它版本、过期/未来/损坏缓存不作为兜底。新缓存schema2；未知/旧开发缓存不迁移或当可信记录。缓存命中不会为了离线显示提前构造代理客户端。

页面显示“上次说明 · 版本 · 获取时间”，本次失败另给分类，并提供「重试说明」「网络设置」。只重试说明，不触发安装、检查更新或真实服务。迟到旧候选结果不替换当前候选，数据根冻结继续阻止新请求；同一root/候选single-flight保持。刷新后正文和页面不带HTML执行，已验证链接仍按已有安全入口打开。
