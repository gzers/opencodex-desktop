# 用户目录分类与新版路径隔离

2026-11-06，Asia/Shanghai。用户已确认方向并授权文档调整；**目标版本0.2.23，未授权本专题开发或执行数据操作**。用户已将本专题纳入0.2.23，与原六项修复同版交付；[IMP-31](../../03-开发实施/IMP-OPENCODEX-DESKTOP-31.md)拥有整版依赖与收口，IMP-32维护本专题明细。不重开已关闭证书，不借历史发布授权开工。

本文拥有范围/验收，路径合同归[数据与状态 §1.4](../../02-项目核心/数据与状态.md#14-用户目录新规则已确认待实现目标版本0223)，双端目录树及旧路径人工参考见[设计](../../04-项目资料/01-项目支撑资料/06-问题记录/20261106-Desktop用户配置目录结构设计.md)，顺序/依赖归[IMP-32](../../03-开发实施/IMP-OPENCODEX-DESKTOP-32.md)。

## 已确认范围

根名按用户指定为.codex-desktop，与产品/仓库标识及原生Codex目录分开。先按desktop/opencodex分类，再分管理器状态与原版HOME。OpenCodex程序默认在Desktop安装根的runtime受管子树，与用户配置分离，只按新版规定位置工作；缺失走正常首次安装/初始化，异常不回退旧根。

用户自行备份旧config.json，放入新HOME后读取现有渠道。验收覆盖当前支持格式的渠道、协议/节点、Key状态、模型选择及有效参数；必要外部引用缺失明确提示，不保证任意历史格式无损恢复。旧管理器设置、同步历史、模板库和其它旧状态不迁移；不因此取消已有文件传输/备份恢复能力。

## 不纳入

自动迁移、旧路径/注册表扫描、旧程序重新绑定、跨版本探测/接管、旧格式转换、跨SID凭据恢复、真实WebDAV同步、真实推理、日常配置替换或旧目录自动删除。旧位置仅供用户手动备份/清理，新版运行不依赖；启用新版前用户退出旧版及服务。

不同Windows用户允许并行打开各自管理器，不用整机单实例锁互相阻挡；同用户（含同SID多会话）仍限制重复实例。各自代理端口仍共享整机监听空间，需有可用且明确归属的端口，不承诺静默自动换端口；占用错误不能伪报为另一用户管理器正在运行。

## 前置与验收边界

具体双端程序前缀/入口、磁盘Schema及IPC待实施前冻结。原型仍有旧示例，不能当作新合同已采用。各AC结果须来自最终实现，旧版证据不直接证明新路径通过；验证按[长期规范](../../03-开发实施/测试与验收规范.md)选取最小适用范围。目前无执行TASK，无AC标通过。

安装结构后继决定：程序默认集成在Desktop内，不再画成独立OpenCodex安装目录；逻辑结构和双端打包/独立更新边界见[数据与状态 §1.5](../../02-项目核心/数据与状态.md#15-desktop集成程序结构0223目标待打包验证)。当前未执行打包或安装，具体物理映射仍由DIR-00闭合。
