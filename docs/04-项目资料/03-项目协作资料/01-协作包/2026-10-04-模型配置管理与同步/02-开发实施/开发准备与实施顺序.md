## 3. 依赖顺序与并行边界

| 顺序 | 输入与交付 | 可并行工作 | 完成证据/下游条件 |

| 2. 本地模版闭环 | 同一校验/匹配/版本服务支撑人工新建与编辑，保存读回、默认及依赖删除；最小原生列表/编辑/预览 | 公共Button/字段/浮层/Tab容器和gallery可独立推进；通知基础沿现有实现查漏 | 本节第4项切片条件通过，真实服务和UI同结果；不要求先接Agent或运行写入 |
| 3. 渠道草稿与只读编译预览 | 复用已采用模版，形成渠道/模型覆盖、顺序、共用认证多URL节点及最终值；接WP-07纯视图与adapter | WP-04可按已冻结schema准备导入导出校验；WP-08注册模型操作的真实事件映射 | fixture可证明确定性；精确目录数量、none/分页/协议/Fast仍须实际版本证据，不能用mock宣告通过 |
| 4. 真实保存与核对 | 在实际接口核验后接差异确认、冻结基准、备份、分阶段写入、读回/补偿、待重启及客户端核对；通知关联同operation | 同步链可准备incoming/依赖校验，不能绕过保存事务 | 对应G-01～04/06/08～10在所用能力范围取得证据；不确定结果不写成成功，未核对不写已生效 |
| 5. 双文件导入导出/WebDAV闭环 | 模版库/策略分别保存，依赖闭包、scope、旧格式/旧客户端保护、incoming与草稿合并；采用进草稿 | 既有页面的公共UI迁移分组完成；WP-06仅在范围决定后按共用服务接入 | G-05/07及适用同步AC，真实落盘/跨机冲突与恢复；不上传半完成事务 |
| 6. 本版集成与交付评审 | 汇总每个切片及所有纳入页面、组件、通知、平台适用验收，处理受影响0.1.10遗留 | WP-05从第一切片持续参与，不等此时才开始测试 | 当前源码绑定生产/实屏/平台证据，缺口明确；正式发布另按用户授权执行 |

并行只限互不改写同一契约/组件及共享注册表的工作；先明确文件责任再分配。schema变化通知其UI/同步/外部消费者，不靠复制实现解耦。技术门约束相应接入和交付，不要求11个门全部通过后才允许写第一段本地功能。

## 4. 首个交付切片：本地模版版本与匹配

这是建议的首个正式开发任务边界，当前只完成准备描述。覆盖WP-01/02/03/05的本地子集；使用隔离测试数据，不修改用户现有库、OpenCodex运行配置或真实渠道。

| 交付内容 | 可检验的完成条件 |
| --- | --- |
| 最小正式契约 | templateId/revisionId稳定且跨机不碰撞；定义规范化、digest、空值/省略/继承、来源/人工锁、错误及旧示例迁入；完整身份与短展示分开；不用mock整数/FNV作生产协议 |
| 人工编辑与版本保存 | 新建、基于保存版编辑后另存新版本；旧正文保持不变；无内容差异不新增版本；摘要从实际前后事实生成，重启/重新读取仍能得到原快照与依据 |
| 匹配与合成 | 原始ID、包含/排除、渠道all/白名单/黑名单、最高优先级冲突及最长字面后缀规则有确定性fixture；仅解析已采用集合，字段合成后仍校验，具体协议/能力采用明确字段定义 |
| 选择、默认与采用分离 | 浏览选择或设默认不改已有渠道精确引用；本切片用可核查的引用fixture证明边界，真实渠道采用与保存留下一切片 |
| 内置来源与删除保护 | 最小可信基线fixture验证不可伪造来源；默认/基线/保存或草稿等依赖不可删；单删/勾选删除同服务、基准过期全批拒绝、取消不改库；全量种子资料另经审核入库 |
| 最小原生UI | 模版列表→编辑→保存→版本管理/匹配预览消费真实本地服务；短下拉最近5加当前/默认去重；全部模版可见；复用公共组件，实际错误有可用出口 |
| 持久化与失败 | 读回、并发旧基准、写中断及失败恢复使用隔离目录验证；旧文件与后来编辑受保护；保留真实失败/不确定状态，不将临时缓冲当成功保存 |
| 组件与证据 | 新增控件登记并接现有gallery；按UI规范核对亮暗/三档、适用窗口/缩放/长文/焦点和Tab/标题关系；测试结论绑定代码身份，实屏缺口单列 |

验收细目沿[现有测试验收入口](../03-测试验收/README.md)维护，不另立第二套AC或把旧总数当全部范围。A6api不发生成请求的既有约束继续有效。真实模型请求、收费/额度消耗和日常配置迁移不属于本轮准备。需要现场验证时先具体列明隔离对象及动作范围，按现有授权执行；不能为了证明接口存在而先创建真实渠道或改运行文件。

下一步产出应是**首个本地切片的具体数据契约、服务边界和验收样例**，随后再进入正式实施；不是时间排期、整包发布承诺或新一轮从零画原型。
