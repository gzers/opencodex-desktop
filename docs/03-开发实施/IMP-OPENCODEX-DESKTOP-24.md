## 实施合同

1. **配置传输**：当前已保存渠道从实际 config.json 读取；所有渠道范围及 WebDAV 与文件使用同源快照。模版版本来自库。接收比较不写渠道文件；明确采用形成当前内存草稿，保留文件基准及未冲突编辑，确认保存才备份原子写回。模版独立采用不替换渠道快照。导入授权需传递至统一文件写入，保留完整语义、原始未编辑字段与本地连接映射，不把来源 Key 自动覆写到本地渠道。
2. **内部 Agent**：执行目录采用文件/布局稳定身份，实际请求沿官方执行路由；已保存数据变化与重新打开时刷新目录，处理晚回和失败重试。当前失效选择不自动切换，未知能力不伪造，不用执行资格否定文件型号合法性。
3. **外部模版任务**：准备、校验、版本提交和回执只依赖模版库及任务记录；旧策略与旧磁盘草稿无关。保留范围、精确版本、人工锁、只检查及防重；结果另存模版版本，套用和渠道写文件仍由已有保存预览完成。
4. **迁移清理**：先列读写消费者与保留用途。必要旧布局按版本迁移，保留稳定 UUID、节点/显示名与采用关系；旧草稿候选可取回，不自动成为当前文件。停用旧回落和无用命令/状态消费者；只清已证实废弃或无引用的暂存。历史备份、恢复、凭据及任务回执保留。新设备、升级、旧损坏数据、中断与重复运行均验收，用户不需要清空配置。
5. **操作边界**：测试写入隔离目录/fixture，真实用户文件只读；不在活跃 Codex 上重启，不默认请求付费模型生成。受控官方执行适配器、真实后端文件及回环 WebDAV/任务提交分别记录，不能互称。发布沿现有 PR/CI、双平台安装器、更新签名、公开/stable 流程。

## 分工与集成

主线负责传输后端/前端合同、最终文件写入、共享命令、文档及发布。内部 Agent 目录/UI、纯模版库事务/任务、旧配置迁移可按互不重叠路径并行；共享 store、命令和原型路径须明确单一写者，贡献者不改共享治理索引与版本。集成时复核跨入口一致性，不能只凭子项测试关闭。
