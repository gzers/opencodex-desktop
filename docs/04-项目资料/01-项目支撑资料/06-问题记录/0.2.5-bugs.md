## WP-32：导出配置无法选择保存路径

**优先级**：P2
**位置**：同步 → 文件同步 → 确认配置导出 → 生成导出文件
**用户原话**：“为什么导出不能选路径？”
**状态**：待修复

### 现状

点“生成导出文件”后，后端直接把包写入数据根下的固定目录：

- 命令 `model_transfer_export`（`commands/model_transfer.rs`）里写死 `root.join("exports")`，文件名固定为 `opencodex-config-<uuid>.ocxdconf`；
- 成功后列表顶部只显示生成后的完整路径，并提供“打开导出目录”按钮；
- 前端没有 `save` 对话框调用，Tauri 能力清单里也只声明了 `dialog:allow-open`，没有 `dialog:allow-save`。

因此用户无法决定文件落在哪里，想通过微信 / 邮件 / U 盘带走时得先去找数据根目录。

### 为什么当初这样设计

`exports/` 属于受管目录（`ManagedPathKey::Exports`），与备份、日志同级，写入受 `safety::check_path` 与原子写入保护，并做了内容读回校验。固定目录让“导出 → 校验 → 留档”这条链路完全在受控范围内，不需要处理用户选到任意目录后的权限与覆盖风险。

### 拟定改法

- 确认导出对话框增加目标位置：默认保持 `exports/`，提供“另存为…”调用系统保存对话框（Tauri `dialog.save`），需要新增 `dialog:allow-save` 能力。
- 后端 `model_transfer_export` 增加可选 `targetPath`：为空时沿用受管目录；有值时校验绝对路径、扩展名与是否覆盖，写入后仍执行读回校验。受管目录之外的写入不再走 `safety::check_path`，需单独定义允许范围（仅用户显式选择的文件）。
- 覆盖已有文件时明确确认，不静默覆盖。
- 界面在成功后同时显示“保存位置”，并保留“在访达 / 资源管理器中显示”入口。
- 原型同步：导出确认弹窗补一行保存位置（默认导出目录 + 另存为），并在注释里说明默认位置与选择边界的差异。

### 待确认

1. 默认仍写 `exports/` 再让用户另存，还是干脆每次都必须选路径？
2. 另存到受管目录之外时，是否仍要求读回校验（会增加一次 IO，但可确认落盘正确）？
3. 是否只在 macOS 提供“在访达中显示”，Windows 对应“在资源管理器中显示”？
