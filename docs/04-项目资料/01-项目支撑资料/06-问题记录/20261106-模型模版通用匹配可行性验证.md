## 1. 当前问题来自哪里

源码基线为桌面0.2.22对应0c57500f8f46ea50655c782c3f04334a39167abb，代码工作树ocx-0219-fixes；matching.rs、schema.rs、store.rs及seed-catalog.json摘要见[来源记录](../../../../.adg/evidence/discussions/model-template-matching-20261106/source-identity.json)。这不证明日常安装二进制与该检出完全同一。

- 引擎已有Exact/Prefix/Glob，glob仅支持*和?，不是正则；并非只能精确匹配。
- 发行种子有17个模型族，包含规则78条，全部是exact。能力已有，但预置数据逐个列完整ID，新增型号和渠道命名变体容易漏掉。
- 版本项仅有字面suffix，composed按ends_with和最长原始后缀选项；不能表达数字版本分隔符等价，填5.5也不等于匹配所有5.5-mini型号。
- 17族通用字段当前全部inherit，具体参数集中在型号例外。扩大族识别后，未知型号不能凭名字套已知型号的上下文/推理/协议等参数。
- 本地没有model-family-templates.json；保存布局的全局/渠道templateRefs和modelRefs均为0。以下是**种子规则潜在命名覆盖**，不是已采用模版的运行命中率，也不证明当前渠道已经用错模版。

## 2. 推荐通用写法

族范围、版本条件和能力配置分层，不要求普通用户写正则，也不逐个枚举完整ID。以下是候选语义，**不是当前可直接导入的Schema**：

~~~text
模版：GPT
渠道范围：明确选择的渠道 / 全部
族包含：前缀 gpt-（现有通配写法也可用 gpt-*）
族排除：显式规则，排除优先

渠道命名前缀：仅在指定渠道声明，例如 GZGG-NewApi 下的 aixj-
只在匹配视图移除此已声明前缀；请求仍使用原始ID

族通用配置：有依据的共用字段，其余继承
覆盖条件（同时满足）：数字版本 = 5.5；名称片段 = mini
名称片段位置：不限 / 版本前 / 版本后（也可保留显式字面前缀或后缀方式）
版本位置：由当前模型族的声明结构识别，例如 gpt- 后的数字段
分隔符等价：点(.) / 连字符(-)，显式启用
规格范围：明确选择，如 mini；不同规格不默认能力相同
规格/构建例外：按需定义；未知型号不套已知型号参数
~~~

通用族识别优先复用现有前缀/通配。Qwen等紧接数字的族名须有数字边界，不能盲目qwen*；Claude的opus/sonnet/haiku等系列、Gemini的embedding/image等用途须保留区别。识别属于Gemini，不等于能套文本聊天配置。

渠道映射必须限定渠道和位置，不能从任意ID中截取gpt/claude/qwen子串。样本GZGG-NewApi的aixj-/btka-/ciii-等仅验证显式映射的写法，尚无供应商身份确认，不自动保存为生产规则，更不证明上游能力等价。

族规则、数字版本条件、名称条件分开；名称片段可以是系列或规格，可能位于版本前或后，不统一称为后缀。保留精确人工例外和不可变revision/采用关系。新规则须明确类型/选项，不静默改变旧字面规则，不自动加入未选模型或采用新模版。

## 3. 符号等价的判断

按**模型族/系列锚点 → 完整数字版本段 → 保留规格和构建 → 配置条件决胜**处理。版本用字符串段序列比较，不当浮点数，不把5.50截成5.5，不删除前导零。

| 输入 | 候选判断 |
| --- | --- |
| gpt-5.5 / gpt-5-5 | 显式启用GPT数字版本规则时，版本段均为[5,5]；原始ID不变。 |
| claude-fable-5.1 / claude-fable-5-1 | 系列fable相同、版本段[5,1]相同；本地确有两个名字，不证明服务/能力相同。 |
| gpt-5.5-mini / gpt-5-5-mini | 版本与规格相同，应用配置仍须满足明确范围。 |
| gpt-5.5-mini / gpt-5-5-pro | 版本相同、规格不同，不作相同配置身份。 |
| 5.5 / 5.50 / 5.5.1 / 55 / 5x5 | 均须区分；5?5还会命中5x5，不能代替分隔符规则。 |
| 5_5、空格、Unicode横线 | 未声明等价，不自动合并；以后支持须显式列出并补反例。 |
| claude-haiku-4-5-20251001 | 明确语法可识别4.5及有效YYYYMMDD构建日期；日期保留，不默认等同无日期别名。 |
| grok-4.20-0309或尾部260915 | 日期/构建/版本有歧义；不能通用截掉或当小版本，未明确槽位时不做等价判断。 |
| qwen3.8-27b-q6 | 3.8可作版本，27b和q6保留为规格/量化名称片段，不混入版本；能力须另有依据。 |

不能把整个ID的.和-统一替换后比较。等价只作用于规则声明的版本位置，其他文字/路径/规格/日期及标点保持原含义。包含/排除若使用数字版本条件，须共用同一识别规则；原字面exact/glob不因新增功能隐式改变。

等价后相同的覆盖条件（例如5.5与5-5各配不同参数）必须判重/报冲突，不按字符串长度或数组顺序任选。跨模版最高优先级冲突仍沿当前已采用集合规则；单模型人工指定不因泛化失效。

## 6. 后续原型与实施

建议原型保留族包含/排除，将“版本或后缀”改为“条件覆盖”（候选名称），允许组合数字版本、名称片段和必要构建条件。名称条件可选完整片段、显式前缀、后缀或完整ID；片段位置可选不限/版本前/版本后。数字版本明确分隔符、位置、规格范围和构建处理。预览显示原始ID、匹配视图、族/系列/版本/规格识别、参数来源和冲突，不能只显示命中。复杂语法由结构化控件生成，不要求用户写正则。

通用族匹配可复用引擎；数字版本类型、Schema、同义冲突、保存/导入导出/Agent编辑及运行解析须一致接线，只改内置规则或原型文案不够。未知能力继承/留未知，已知精确型号参数保留，不无差别套到新型号。

本轮证明了**族通用匹配和局部符号等价可确定性实现，并在当前命名样本与反例上改善覆盖**。供应商语义/能力确认、未来盲测、最终交互采用、Schema冻结和软件集成尚未完成；不标生产功能完成，后续版本归属以最新DMD/IMP为准，用户现已纳入0.2.23。

## 7. 用户纠正：名称片段不限后缀

用户指出Claude常见opus-5-5，而GPT为6-sol，其他命名也可能把系列/规格放在版本前后。因此前轮“数字版本 / 字面后缀”二分不够通用，**最新候选为数字版本条件与名称条件的组合**；旧字面后缀仅保留为一种匹配方式，不再代表所有文字条件。

| 规则组合（条件间为AND） | 本地已保存样本 |
| --- | --- |
| Claude + 名称完整片段opus + 数字版本5.5 | claude-opus-5-5：2条渠道记录；opus在版本前。 |
| GPT + 数字版本6 + 名称完整片段sol | gpt-6-sol：10条渠道记录；sol在版本后。 |
| GPT + 数字版本6.1 + 名称完整片段sol | gpt-6.1-sol：10条渠道记录；sol在版本后。 |

名称条件默认按完整片段判断，sol不命中solar，opus不命中opusplus；可在需要时明确前/后位置，不能强制所有族同一顺序。“不限位置”只是局部条件的作用范围，不是将完整ID分词排序后视为同一模型。具体族的名称布局由声明语法识别，不从任意位置抓数字；未知布局留待确认/显式新增。字面文本原样匹配，不自动改拼写，如oups不会自动等于opus。

点/连字符等价仍仅用于数字版本段；文字分隔和系列/规格保持字面约束。前述候选在不限位置条件下也不推定任意重排语义等价，不把型号名相似当能力相同。原型预览须显示片段的位置、完整性和各条件是否同时满足。

在同一冻结本地样本上追加只读命名验证，16项正反例通过，包含前后位置、完整片段边界、版本差异、系列差异、拼写不自动纠正及不擅自重排；脚本见[追加验证](../../../../.adg/evidence/discussions/model-template-matching-20261106/literal-segments-review.py)，结果见[回执](../../../../.adg/evidence/discussions/model-template-matching-20261106/literal-segments-review.json)。仅扩展离线候选，没有新增网络/配置操作，没有修改原型或生产实现；原轮57项证据保留，不改写原结论。
