# 对话策略页面与 Superba 参考

日期：2026-10-27。状态：用户确认信息架构后完成可交互原型与针对性检查，真实配置、链路和产品版本仍待实施。唯一活动源是[总原型](原型/index.html?design=capabilities#settings?section=dialog-policy&policy=context)，在 docs/governance-main 文档分支维护。

## 菜单与配置归属

| 正式入口 | 内容 | 作用范围与保存 |
| --- | --- | --- |
| 设置 → 对话策略 → 模型与工具 | 原对话“全局设置”的全部命名模型、联网搜索、子 Agent 默认 / 推荐 / 并发 / 指令 | 全局对话策略；同一份全局草稿和保存，不保留另一套全局表单 |
| 设置 → 对话策略 → 上下文 | 处理策略、可选压缩阈值、按 Provider 的压缩方式 | 策略作用于当前 Codex 实例；协议归用户级 Provider，不增加项目 / 对话覆盖 |
| 设置 → 对话策略 → 连接 | 按 Provider 的跟随默认 / 优先 WebSocket / 仅 HTTP、可选连接超时、握手反馈 | 沿已有连接状态模型；保存后待 Codex 完整重启 |
| 对话 → 项目与对话 | 公共树形导航、搜索 / 子 Agent 的本层覆盖、标题操作、执行详情 | 保留项目 → 对话继承和按对象草稿；无重复全局 Tab、无命名 / 传输 / 上下文局部开关 |
| 模型 → 渠道详情 → 服务节点右侧“对话策略” | 跳转同一个全局页面的连接分组 | 快捷入口，不复制配置和常驻说明段落 |
| 设置 → Agent 配置 | 模型模版的制模助手 | 与 Codex 子 Agent 默认分别管理 |
| 同步 → 文件同步 / WebDAV 同步 | 各模块已接入的配置 / 恢复范围 | 不因入口迁移改变默认排除；历史继续仅本地重装用途 |

全局来源显示为“全局对话策略”，可跳转唯一全局编辑页。选择对象不写配置；切换设置分组或往返对话页保留草稿、树展开、过滤和本层选择。全局保存只更新沿用全局的字段，项目 / 对话显式覆盖不被替换。旧 #settings?section=transport 仍兼容进入“连接”，新链接使用 section=dialog-policy 与 policy=models/context/connection。

## 上下文如何表达

| 处理策略 | 主流程解释 | 高级参数 |
| --- | --- | --- |
| 跟随默认 | 保留 Codex 和 Provider 既有行为，不额外写入功能开关 | 可选自动压缩阈值、轮末比例；留空不覆盖 |
| 常规压缩 | 达到阈值后整理上下文 | 自动压缩阈值、轮末比例 |
| 后台压缩 | 接近阈值前准备压缩 | 自动压缩阈值、后台启动比例、轮末比例 |
| 历史与笔记 | 模型按需查阅历史并维护笔记，仍有兜底压缩 | 当前仅可选自动压缩阈值；不新增人工笔记页 |

四种策略是本项目设计的互斥预设，不声称 Superba 已有同款 UI，也不声称官方机制全部互斥。速度档继续由已确认模型 / 推理组件设置；本页不另加 Fast 开关或把 WS 自动写成关闭。

压缩方式单独按 Provider 选择“跟随 Provider 默认 / 客户端压缩流程 / 原生远程压缩”。客户端组织流程可以请求远端模型，不能因此命名为 native。当前 OpenCodex 第三方摘要尚不能等同于原生远程压缩，history/notes 入口也仍待接通；页面按选择给一条简短条件说明。

后台启动比例和轮末比例分别说明，后台比例相对于模型完整上下文窗口，后者不是异步功能开关。2026-10-28 原生正反例确认后台调度还要求 Provider 远程 v2 能力：客户端流程不能仅靠 async 开关启用后台；跟随默认需解释实际协议。高级字段留空跟随客户端，不猜测未知默认；后台比例接受 1–100%，轮末比例接受 0–100%（0 关闭），自动压缩阈值接受正整数。切换模式保留暂不适用的高级输入供切回继续编辑，不将隐藏的无效字段写入当前编译目标或用于阻止保存。

预算提醒、压缩提示词与更多实验参数保留在来源研究中，本次没有一并做成大而全配置器。没有立即压缩、清空远程笔记或真实重启的产品动作。

## 保存、应用与观察

- 模型与工具、上下文、连接分别保存所属草稿；不引入跨模块一次性自动提交。
- 上下文保存后标记待重启，不修改正在执行的会话。右侧“模拟 Codex 完整重启”只把已保存上下文和连接投影到应用态，未保存输入继续保留。
- 实际观察在具体对话“执行采用与连接详情”里展示：采用策略、压缩与整理、历史读取、模型笔记，以及入口 / 上游传输。项目显示进入具体对话查看；其他对话和其他来源无记录时显示未观察。
- 保存、握手、模拟重启均不自动生成实际采用。重启清空旧观察；右侧固定原生 / 笔记示例明确是直连示例，不证明第三方代理已支持。
- 全局模型配置保存反馈改为“已保存 · 采用待观察”，不凭落盘模拟推断执行端已接收。原有标题修改 / 候选预览 / 采用与配置保存仍分别处理。

上下文 / 连接配置编译预览位于折叠区，属于本轮原型的目标说明，不是已经验证的生产写入器。正式接入须按当前 Codex 版本识别字段，并保留用户已有来源及撤销管理器覆盖的语义。同步和备份后续按各模块接入；本次没有把上下文参数塞进对话模型策略导出载荷。

## 2026-10-28 模型入口统一使用公共选择器

全局、项目、对话及本地恢复映射的模型字段现已调用既有公共渠道模型选择器，替代简单模型下拉；搜索路径、Provider、压缩方式等普通枚举继续使用公共 Select。

| 业务入口 | 组件模式 | 回填内容 |
| --- | --- | --- |
| 全局命名模型 | 单选，仅型号 | 渠道与模型；不增加局部命名设置 |
| 全局 / 项目 / 对话的搜索模型、子 Agent 默认模型 | 单选，启用推理与快速模式 | 型号、可选推理档位与 Fast，一次确认 |
| 各层推荐模型列表 | 有序多选，逐项设置 | 每个模型独立的推理 / Fast 与优先级；允许明确清空 |
| 同步 → 文件同步 → 重装恢复的模型映射 | 单选，启用推理与快速模式 | 恢复项目的子 Agent 模型组合；保留已输入工作目录 |

组件内推理与快速模式连续编辑，单选和多选都由主“确定选择”回到当前对象草稿；取消不改草稿。业务页再保存，不因选择或切换对象自动提交。继承与来源由业务页展示，不塞进公共目录；“恢复继承”清除本层该模型的型号 / 推理 / Fast 组合，推荐列表单独恢复。同型号仅改选项时保留型号继承；更换型号使用新模型的实际默认档位，不套用旧型号的推理或 Fast。未修改直接确认不额外建立覆盖。

目录读取模型页已保存样例及有效规则，确认时复核可用性；停用或无额度等项保留原因。未知默认不凭空补值。已有推荐列表字符串在原型中兼容读取，新选择保留完整引用与逐项选项。该载荷仍是 mock 表达，生产 schema、执行采用与兼容迁移按原独立包实施。

66 项相关 Node 检查通过，覆盖公共选择器、调用接线、继承、取消 / 保存、默认重置、多选清空、恢复映射和原有树 / Agent / 注释回归；[测试日志](../../../../.adg/evidence/COL-LOCAL-20261011-01/conversation-model-picker-20261028/tests.tap)。实屏检查覆盖上述入口、推理 / Fast 连续编辑、取消、同模型选项覆盖、恢复继承、亮 / 暗主题及恢复路径保留；[浏览器记录](../../../../.adg/evidence/COL-LOCAL-20261011-01/conversation-model-picker-20261028/browser-checks.json)。截图：[搜索组合](../../../../.adg/evidence/COL-LOCAL-20261011-01/conversation-model-picker-20261028/01-search-picker.png)、[有序多选](../../../../.adg/evidence/COL-LOCAL-20261011-01/conversation-model-picker-20261028/02-roster-multiple.png)、[深色](../../../../.adg/evidence/COL-LOCAL-20261011-01/conversation-model-picker-20261028/03-search-dark.png)、[恢复映射](../../../../.adg/evidence/COL-LOCAL-20261011-01/conversation-model-picker-20261028/04-recovery-mapping.png)。恢复入口在对话专题范围核对；本轮未重新专项验证窄窗、其他平台或真实执行。

## Superba 来源与当前能力

参考固定版本 v0.1.1-alpha.12，commit f78d77a2849aceb8dffc1f27a83869ffceab7e90。实际源码显示 Provider 远程压缩三态和逐字段通用配置编辑，没有发现本页四模式互斥 UI。压缩字段说明、保存 profile、应用 Switch 和运行能力分别记账，完整八条固定链接与字段边界见[Superba 对话策略界面与配置参考](../../03-项目协作资料/01-协作包/2026-10-16-渠道特殊能力与代理兼容/01-需求分析/02-方案草案/20261027-Superba对话策略界面与配置参考.md)。

后台压缩补充核对了[官方 Schema](https://developers.openai.com/codex/config-schema.json)：features.async_compaction 支持含 enabled 与 model_async_compact_threshold_percent 的配置；比例范围 1–100，Schema 默认 65。只有比例不代表功能已启用。features.context_management / token_budget 及 provider 的 remote_compaction 分别是功能与协议维度。本轮保留空值而不把远程文档默认硬编码成所有客户端版本的默认。

[WebSocket 链路依据](../../03-项目协作资料/01-协作包/2026-10-16-渠道特殊能力与代理兼容/01-需求分析/02-方案草案/20261027-WebSocket全局配置与链路边界.md)继续适用：本地入口允许 WS 不等于任意第三方上游已使用 WS；安装包 2.84.0 的只读观察不证明当前运行进程与真实渠道能力。没有安装 Superba、修改运行配置、执行真实握手 / 重启、调用模型或读取真实对话正文。
