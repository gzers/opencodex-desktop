## Agent 平台侧进入连续场景（2026-11-04）

OpenCodex 桌面管理器 / 桌面端，唯一活动入口为[概览](原型/index.html#overview)。本轮按用户要求补绘左侧 Agent 平台，延续[连续场景设计思路](概览连续场景交互方案.md#agent-平台侧连续场景2026-11-04)，不另建可编辑原型。

| --- | --- |
| 平台 → 模型 | 运行后点击 Codex App、OpenCode、Codex CLI、Claude Code 的图标，或悬停卡中的“展开平台模型”。保留原平台节点并移动为路径起点，Desktop 仍在场景内，模型按该平台的归属展开。 |
| 模型 → 请求 | 显示属于该平台和模型的最近请求；每行写实际目标渠道与该条请求速度。平台与模型汇总只显示请求 / Token / 渠道数，不混算不同渠道的平均输出速度。 |
| 请求 → 渠道 | 选中请求后，同场景显出实际目标渠道；涉及实时适配时保留中间节点和可点开的适配详情，光点经过平台 → Desktop → 适配（如有）→ 渠道 → 模型与请求。请求详情明确显示来源平台 → 目标渠道。 |

| 时间 / 停止 | 切时间保留所选平台与模型，清除旧单次请求和目标渠道。未运行不可进入平台明细；停止清理场景、光点和回放，回到整体。 |

样例口径：新增纯数据模块 overview-platform-data.js，以固定、显式的 mock 配额从当前渠道模型明细派生四平台样例，不根据常用程度、入口或真实历史推断来源。已知组合在整数请求与 Token 上与输入模型明细守恒，未知渠道 / 模型组合不进入已知平台；小窗口独立取整时，Token 配额与请求配额可能出现边界差异，不能作为真实日志归属证明。生产需要可靠的平台标识，未区分来源应保持未区分。

接线：原四个平台 DOM 增加 data-client 标识，沿用原 codex / claude 路径分组以保留既有总览；悬停数据按实际平台分开，不继续复用 codex 共用入口卡。原模型、请求、实时适配、Logo 净空与光点逻辑共用同一个连续场景组件；原渠道深入路径保持。分页隐藏内容限制在场景边界内，不靠缩小字号挤进视图。
