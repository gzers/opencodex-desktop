**验证方法**:

## 全局改进建议

### 1. 建立统一全局样式系统
**问题**: 
当前多处存在样式不一致（按钮对齐、卡片间距、字体大小、背景色等），缺少类似原型组件样式的统一规范。

**建议**:
- 在代码层面建立全局样式变量和组件库
- 定义统一的：
  - 按钮样式（大小、内边距、图标对齐）
  - 卡片样式（间距、圆角、阴影）
  - 表格样式（列宽规则、行高）
  - 弹窗样式（`overflow` 处理、浮层层级）
- 所有组件统一引用全局样式，避免各自独立定义

---

### 2. 优化数据流架构
**问题**: 
模型选择器加载慢、误报未保存修改，说明数据流可能存在冗余异步调用和对比逻辑不完善。

**建议**:
- 模型/渠道数据应在 Pinia Store 中统一管理
- 选择器、配置页面等直接从 Store 同步读取
- 优化数据对比逻辑，避免误报 diff

---

### 3. 弹窗浮层层级管理
**问题**: 
推理档位提示被弹窗裁剪（WP-16），说明缺少统一的浮层层级管理。

**建议**:
- 使用 `z-index` 分层管理（弹窗、提示、下拉框等）
- 浮层元素应挂载到 `body` 或专用浮层容器，避免被父元素 `overflow` 裁剪

### WP-24: Tab 滚动固定时背景色处理不当

**优先级**: P2  
**位置**: 所有 Tab 栏（模型、拓展、设置等页面）  
**原型位置**: governance-main/docs/04-项目资料/01-项目支撑资料/01-产品原型/原型/index.html

**问题描述**：
- Tab 栏默认就有不透明背景色，不符合玻璃透明设计
- 原型中 Tab 栏应默认透明玻璃效果，滚动到顶部固定时才淡入不透明背景
- 当前实现缺少滚动状态检测和 CSS 过渡效果

**期望行为**：
- 默认：透明玻璃背景（backdrop-filter）
- 滚动到顶部（sticky 状态）：淡入不透明背景（opacity transition）
- 离开顶部：淡出回透明状态

**根本原因**：
- 原型本身也存在此问题，代码需要主动修正
- 缺少滚动监听和动态 CSS 类切换逻辑

**解决方案**：
```vue
// 使用 Intersection Observer 或滚动监听
<script setup>
import { ref, onMounted } from 'vue'

const isSticky = ref(false)

onMounted(() => {
  const tabBar = document.querySelector('.tab-bar')
  const observer = new IntersectionObserver(
    ([entry]) => {
      isSticky.value = !entry.isIntersecting
    },
    { threshold: 1 }
  )
  observer.observe(tabBar)
})
</script>

<style scoped>
.tab-bar {
  backdrop-filter: blur(10px);
  background: transparent;
  transition: background 0.3s ease;
}

.tab-bar.sticky {
  background: rgba(var(--bg-color), 0.95);
}
</style>
```

### WP-25: 模型选择器每次打开需 3-5 秒加载

**优先级**: P1  
**位置**: 所有模型选择器弹窗（Agent 配置、模型模版等）  
**原型位置**: governance-main/docs/04-项目资料/01-项目支撑资料/01-产品原型/原型/index.html#settings

**问题描述**：
- 打开模型选择器弹窗时，需等待 3-5 秒才显示模型列表
- 当前实现从异步 API 每次重新获取数据
- 用户反馈："为什么每次都要加载很久？"

**期望行为**：
- 瞬时打开（<200ms），直接从 Pinia Store 读取已缓存的渠道模型数据
- 只有在"读取现有渠道"操作时才调用 Tauri 异步 API

**根本原因**：
- 选择器组件直接调用 `invoke('get_channels_with_models')` 等异步命令
- 应该从已经初始化的 Pinia Store（如 `useModelStore`）同步读取

**解决方案**：
1. **数据源切换**：从 Pinia Store 读取，不调用异步 API
2. **Store 结构参考**：
```typescript
// stores/model.ts
export const useModelStore = defineStore('model', {
  state: () => ({
    channels: [] as Channel[],
    models: [] as Model[]
  }),
  getters: {
    // 过滤启用且非隐藏的渠道
    visibleChannels(): Channel[] {
      return this.channels.filter(c => c.enabled && !c.hidden)
    },
    // 过滤非隐藏模型
    visibleModels(): Model[] {
      return this.models.filter(m => !m.hidden)
    }
  }
})
```

3. **选择器组件修改**：
```vue
<script setup>
import { computed } from 'vue'
import { useModelStore } from '@/stores/model'

const modelStore = useModelStore()

// 同步读取，无需 await
const channels = computed(() => modelStore.visibleChannels)
const models = computed(() => modelStore.visibleModels)
</script>
```

**依赖项**：
- WP-22（过滤隐藏渠道模型）必须同时实现
