# 确认与评审

当前状态：**方案草案可评审，未冻结生产契约**。本页列出后续决定和技术验证，不代表本轮仍需等待许可才能交付文档。

## 1. 已明确的用户目标

用户要求调研现有用量，设计多用户隔离、全站统计、单用户跨设备汇总、可配置服务端、自己的登录账户、自定义 / 默认系统设备名，并独立建立协作包，分析后续服务能力；同日明确补充“加入团队的概念”，因此团队纳入核心设计和首期范围。

用户没有确认架构路线、管理员明细权限、身份组件、版本号、预算或保留期。下表为 Agent 建议，不能标记成用户决定。

## 2. 推荐默认值

| 决策项 | 推荐候选 | 影响 / 备选 |
|---|---|---|
| D-01 流量架构 | 本地代理 + 精简用量上传 | 统一 Hub 是可选后续路线，不作为汇总前提 |
| D-02 初期组织模型 | 单站点、个人空间 + 多团队，用户可加入多个团队 | 团队概念已获用户明确要求；具体多团队关系、三角色和历史规则仍为建议 |
| D-03 管理员范围 | 站点管理员看全站；团队管理者看本团队及成员聚合 | 不默认读取他人事件、个人空间或其他团队；明细权限另设 |
| D-04 本地多账户 | 一次一个服务账户；该账户可多团队，来源固定采集用户与空间 | 换账户 / 换空间不用旧队列改归属；独立 profile 能力需验证 |
| D-05 历史范围 | 开启后新增；历史可预览导入 | 无谱系的复制历史默认不导入 |
| D-06 登录 | 成熟身份组件、邀请制起步、浏览器授权 | OIDC / SSO 深度随部署需求确定；不自造认证协议 |
| D-07 设备 | 系统名作为可改显示名，随机稳定身份 | 重装默认新设备，受控恢复另走来源流程 |
| D-08 存储部署 | API + worker 模块化单体、PostgreSQL | 按团队能力选 TypeScript / Fastify 等；不锁定生产版本 |
| D-09 隐私 | 仅指标白名单和必要维度，用户开启 | 不上传对话 / 代码 / 凭据；管理员可见范围在界面明示 |
| D-10 保留策略 | 明细 90 天、汇总 365 天、导出 24 小时 | 候选值；需与补传窗口、去重和备份删除期限共同冻结 |
| D-11 估价 | 服务器版本化价格、USD、未定价单列 | 不承诺与私人价格覆盖或供应商账单一致 |
| D-12 后续价值 | 个人 / 团队预算提醒、成本 / 性能分析、配置 / 模版同步 | 项目维度后续；团队本身已经上调首期 |
| D-13 团队角色 | 所有者、管理员、成员；所有者一名，转移后才能退出 | 管理者可看团队成员聚合，普通成员默认只看本人 |
| D-14 用量归属 | 一条事件仅个人或一个团队，来源登记固定空间 | 不能把个人视图与团队视图相加作为全站总量 |
| D-15 离队历史 | 已入库事件留团队；个人视图不再取得原团队明细 | 重新加入是新成员期，不自动恢复旧权限 |
| D-16 离线补传 | 上传时需仍有团队权限；离队后封存旧团队队列 | 首期不支持离队后补交，未来可有管理员限定授权 |

## 3. 必须验证的技术门

| 编号 | 技术门 | 通过证据 |
|---|---|---|
| G-01 | 官方历史 API 能否稳定增量采集 | 完整字段对照、分页并发写入、晚写、游标失效、保留轮换、可变记录实测；不足时只读 JSONL 适配方案 |
| G-02 | 来源身份及历史谱系 | 重启 / 升级 / 轮换不换身份；受控恢复 / 克隆有可证明分界；无谱系不冒充可精确去重 |
| G-03 | 记录、逻辑请求、attempt 和物理消耗口径 | 普通、重试、修复、combo、失败 / 取消样本；与 2.77.0 原统计核对，解释任何差异 |
| G-04 | 本地来源的用户归属 | 独占 profile、共享 runtime、签出 / 换账号与历史导入测试；不把未知调用者自动归给登录用户 |
| G-05 | 隔离与认证 | API、SQL / RLS、连接池、缓存、导出、任务、设备 / 成员撤销的跨用户和跨团队攻击测试；原生授权与系统凭据生命周期 |
| G-06 | 估价与数据完整度 | 包含缓存 / 推理的规范化、未知价、tier、价格版本、未计量 / 部分采集样本；不把缺失转零 |
| G-07 | 离线与故障恢复 | outbox 崩溃恢复、已提交但 ack 丢失、坏事件、队列满、数据库故障、聚合重算与备份恢复 |
| G-08 | 容量与保留 / 删除 | 代表性负载，事件大小与 attempts 分布、长离线重传、数据删除后重放、旧库恢复后的撤销保护 |
| G-09 | 空间绑定与多团队统计 | 验证独立 profile / 来源；事件只归一个空间，个人 / 团队 / 全站交叉视图不重复；UI 切换不冒充请求归属 |
| G-10 | 团队生命周期与历史权限 | 邀请 / 角色 / 最后所有者、成员期、离队补传 / 重加、任务执行时重新授权、团队删除与个人删号分别验证 |

G-01～G-04 及 G-09 是首个纵向闭环前的主要门；其余在首期对外使用前完成。未通过时缩小兼容矩阵或明确标记缺口，不把页面能出数字视为验证通过。
