# 测试与验收规范

适用项目：OpenCodex Desktop；2026-11-06用户确认，适用于后续版本。本文维护项目长期选测、平台补验与证据复用规则；具体版本的范围、必需检查及结果由对应实施计划/任务/回执记录。历史发行证据和已关闭证书保持原样，本规范不追溯改写既有结论。

## 1. 按改动影响选测

先根据最终diff、受影响消费者、已有缺陷和证据缺口确定验证范围。常规页面和共享业务逻辑优先在本机验证；Windows原生校验有条件触发，不是所有任务或每个版本的默认人工门槛。不因支持Windows就把每项功能、页面及特效重复做双端实屏。

| 变更范围 | 优先验证方式 | 何时增加平台验证 |
| --- | --- | --- |
| 常规表单、布局、下拉、滚动与交互状态 | 软件真实组件的浏览器页面对照原型，覆盖受影响状态与尺寸；按实际CSS/组件影响在本机选用Chromium/WebKit。 | 出现未覆盖的渲染差异，或修改原生WebView/系统集成边界时，定向检查对应平台。 |
| 共享配置、名称/引用迁移、数据状态、文件同步协议 | 单元/真实临时文件集成、可控进程/隔离服务、故障注入；必要时一条本机实际运行链。 | 触及平台路径、权限、锁、凭据后端或进程适配，或存在平台特有反馈时补验。模拟两个同步客户端不要求两种操作系统。 |
| 材质、动画与性能 | 已有有效证据可复用；改变效果/绘制路径时再验证受影响的消费者与预算。 | 改动Windows DWM/Mica/WebView2等路径或相关CSS效果产生未覆盖差异时，补对应Windows专项。未改动不重跑玻璃/性能专项。 |
| 安装、升级/恢复、入口启动、系统路径/权限、进程与文件占用 | 核心逻辑先在本机隔离验证；真实制品/原生边界依据改动和发布检查执行。 | 新改动涉及Windows适配，或既有Windows证据不能覆盖新增恢复/激活路径时，做最小原生验证。页面不能证明系统副作用。 |

## 2. Windows补验的触发条件

至少存在下列一个具体条件才新增Windows原生人工/专项验收：

- 改动直接涉及Windows专属代码、API、构建/安装器、启动入口、路径/权限、凭据后端、进程身份、文件占用或原生材质。
- 实际反馈、测试失败或引擎核对显示Windows特有差异，现有跨平台检查不能解释或覆盖。
- 需要验证的系统行为无法由本机/页面/现有隔离检查证明，且既有Windows证据缺失或已不适用。

触发后在当前实施/测试清单写清“具体变更或缺口 → 需验证的平台行为 → 最小检查 → 可复用证据”，只补这部分，不自动扩大为整版双端全流程。最终diff未触发条件时，记录适用证据和无需新增Windows专项的理由，不创建空的Windows交接/等待项。出现新的失败或范围变化再调整；不得因测试不方便而把已触发的必需检查标成不适用。

## 3. 证据复用

复用前核对来源提交/制品、平台与运行环境、覆盖行为及前提，与当前diff是否相容；检查共享依赖/调用方式是否改变，不仅看平台文件本身有没有改。

- 相关实现和前提未变、旧证据实际覆盖该行为时，引用原证据并说明复用范围，无需重复运行。
- 已有失败、未验证项及用户采用的硬件例外继续保留；它们不转为测试通过，也不自动豁免本次新增行为。
- 功能通过、视觉通过、原生边界通过和发布通过分别说明。静态原型、替换组件的DOM测试或模拟服务不能充当正式软件实屏/真实服务器/原生系统验收。
- 页面验证应使用正式软件源码中的真实组件；外部协议需验证真实请求、文件内容及失败/并发行为。实际端点只读检测不证明写入时的可见性和并发语义。

## 4. 与构建、发布和隔离的关系

本规则约束新增平台补验的选测方式，不撤销实际发布合同、支持平台构建/自动检查、制品签名及完整性等已经要求的检查。发布范围或最终代码引入新平台行为时，重新评估适用性；不以页面验证替代必需的安装/更新制品验证，也不要求无关功能重复原生验收。

测试使用临时目录、合成数据、隔离服务及明确的进程/端口归属；真实同步、重启日常客户端、替换日常安装和远端清空须在相应授权范围。结束后清理本轮服务、端口、临时文件及诊断产物，恢复临时源码，保留复现脚本、成功/失败日志、结果与清理回执。不得清理其它任务、日常数据或把环境缺失写成通过。
