# 产品定义

## 一句话定位

**opencodex-desktop** 是一个面向 OpenCodex 的**独立桌面管理器**：把命令行里的安装发现、进程启停、状态观测、日志诊断、配置迁移、同步与扩展管理，收进一个图形界面。

## 要解决的问题

OpenCodex 的日常使用依赖命令行：启动与停止要敲 `ocx`，状态与日志要另开终端看，配置迁移和跨机同步没有图形入口，Skills 与 MCP 这类扩展配置要手工改多个客户端的配置文件。

opencodex-desktop 把上述操作收敛到一个桌面应用里，同时**不改变 OpenCodex 自身的行为与权威**。

## 目标使用者

| 使用者 | 典型诉求 |
|---|---|
| 日常使用者 | 点一下就启停、一眼看到是否健康、出问题能看到原因 |
| 排障使用者 | 只读日志与运行环境诊断、快速定位启动失败或外部接管 |
| 多机 / 多环境使用者 | 导出配置、经 WebDAV 同步、覆盖前有备份可回退 |
| 多客户端使用者 | 统一管理 Skills 与 MCP，并分发到多个客户端 |
| 脚本与 AI 代理 | 经可选 CLI 控制面以机读方式驱动管理器自有域能力 |

## 产品边界

### 做

- 发现并校验本机已有的 OpenCodex 安装（npm 形态）。
- 托管官方 `ocx start / stop / restart` 子进程，观测状态、端口、进程标识与最近错误。
- 提供日志、运行环境诊断与通知中心，并嵌入官方 Web 面板视图。
- 加密的配置导出/导入，以及经 WebDAV 的加密同步。
- 统一管理 Skills 与 MCP 扩展配置，并分发到多个客户端。
- 区分 OpenCodex 本体升级与应用自身更新两条通道。
- 提供托盘、macOS 原生菜单，以及默认关闭的可选 CLI 控制面。

### 不做

| 不做的事 | 原因 |
|---|---|
| 重写 OpenCodex 核心、绕过官方 API | 复用官方能力，不制造第二套实现 |
| 管理 npm（安装、卸载、依赖解析、全局前缀） | 只发现与校验既有安装形态 |
| 替代官方 `ocx update` 的更新事务 | 更新权威属于官方，本产品只做升级前备份与引导 |
| 安装或管理 launchd | 启停由本产品直接托管子进程完成 |
| 接管 `codex-shim` | 官方能力若需依赖 shim，另行建需求确认 |
| **写入 provider、路由、模型映射等 OpenCodex 核心运行配置** | 该类变更一律走官方 CLI，本产品不提供写入通道 |
| 自动覆盖外部 provider 托管的配置 | 只检测、解释，并在用户确认后引导官方 `restore` |
| 明文迁移或同步凭据 | 凭据必须进加密容器或加密后上传 |

### 唯一例外：扩展配置可写

MCP 配置节点与 Skills 目录同步属于**扩展配置**，本产品可以写入；除此之外的一切 OpenCodex 配置仍不可写。完整边界见 `集成与安全边界.md`。

## 名称约定

| 场景 | 写法 |
|---|---|
| 项目与仓库标识 | `opencodex-desktop`（全小写连字符） |
| 面向用户的展示名 | `OpenCodeX-Desktop` |

两者指同一产品，**并存是既定约定**，不要求统一，不应据此发起批量重命名。

## 产品原则

1. **官方权威优先**：凡官方已有权威通道的（更新、provider、路由），本产品只做引导与展示。
2. **可回退**：任何可能覆盖数据的动作，先备份、可定位、可校验、可恢复。
3. **状态如实**：能力不可用时明确说明，不伪造空成功状态。
4. **敏感值默认掩码**：凭据类数据默认不可见，且不进入日志与错误信息。
5. **不静默覆盖**：检测到外部改动或冲突时，停止并交给用户决定。
