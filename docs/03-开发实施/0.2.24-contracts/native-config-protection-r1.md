# 0.2.24 完整原生配置保护合同

revision: 1；2026-11-11。归属 IMP-34 P24-02，手动备份/恢复代码 main0eea7274c，现有安装事务接线 main11dbbdd9c。范围和进度仍以 IMP-34 为准。

## 原件及入口

「设置 → 数据与备份 → 备份完整配置」在明确确认后调用 model_v2_native_config_backup；IPC 不接收来源路径、Key 或配置 DTO。只备份实际 SharedProcessContext 绑定的当前 HOME/config.json。保存完整原字节，包括未知字段、配置内凭据、密钥池、headers、全局设置及当时端口；草稿、外部账户文件和系统凭据库不在本文件范围。

备份保存在当前 Desktop 数据根按年/月/动作组织的既有备份树。手动记录为 model-config，安装/升级保护为 upgrade，导入/回退前保护为 import；以固定用途标记、目标 HOME 和管理归属筛选，不能把偏好备份误当原生配置。备份清单可包含当前可核验的运行包版本及版本镜像 SHA；没有可验证程序事实则明确未知，不从安装历史或配置内容猜测，不声明这是正在运行的服务版本。

## 保护及回退

| 操作 | 前置与写集 | 保留/失败语义 |
| --- | --- | --- |
| 手动备份 | 共享事务准入、官方 SQLite 配置锁、Desktop 目标锁；读取有界普通单链接文件，保存后复核完整原字节、摘要/大小/权限/HOME | 不要求草稿提交、不改配置；无文件明确失败，不伪造备份；损坏 JSON 仍可保护原字节，但不能假称格式有效 |
| 程序替换前保护 | 当前 install_runtime 与 install_official_update 共用的安装器，在候选包校验后、实际替换前取得保护；保留配置锁直至事务结束 | 缺失配置是明确的无文件事实，不创建空备份；备份失败不替换程序 |
| 激活提交前复核 | 在来源记录提交前再次比较配置存在性/原字节及保护备份记录/内容 | 忽略锁的外部修改触发程序事务失败/回退；不将外部配置补偿覆盖成旧值，保护备份保留 |
| 整文件回退 | 选定有效备份，预览目标和端口，确认时核对真实停止证明/运行包/来源/草稿/设置与事务 | 先保护当前原字节，再按备份原字节恢复；当前文件损坏也可恢复，缺失文件不生成虚假保护备份 ID |

回退允许备份原来未配置 port 或配置为 0，不为其补写一个正数；UI 只显示配置事实，不把它当实际监听端口。Desktop 单独的端口模式记录不在整文件回退内。损坏/缺失目标使用独立、含文件存在性的原字节观察；尚未完成的端口事务或不可核验的模式记录仍阻断。普通「导入配置」继续保留本机有效端口及模式，不采用整文件回退的端口规则。

所有已存在保护文件继续核对当前 HOME、普通文件/链接、原字节、摘要、大小及当前用户私有文件权限。取消不写配置；并发变化、文件未能完整保存、异常路径或未知停止归属均不绕过。现有 Desktop 偏好备份、保护关联及清理合同保持；本次不为原生配置备份增加自动删除策略。
