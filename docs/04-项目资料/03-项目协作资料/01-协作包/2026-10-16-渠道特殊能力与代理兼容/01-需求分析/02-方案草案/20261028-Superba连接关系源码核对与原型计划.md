## 2. 固定来源及实际实现

Superba 来源固定为 krill-lab/superba 的 v0.1.1-alpha.12，commit f78d77a2849aceb8dffc1f27a83869ffceab7e90。通过 GitHub 连接器读取完整目录树及指定文本文件，目录树未截断。界面使用 Rust／egui Painter 绘制，不能直接作为本项目 Vue／HTML 控件导入。

| 已核对内容 | 源码事实 | 本项目采用方式 |
| --- | --- | --- |
| 单工具连接图 [S1] | 本机 → 本地路由 → 供应商·线路 → 模型·速度档；布局高度 148、节点边长 46，均为 egui 布局单位 | 借鉴四列阅读顺序；尺寸按本项目既有令牌和软件缩放重新核对 |
| 直连与代理旁路 [S2] | 代理开启时在主路径；关闭时上移为虚线虚影，主路径直达供应商；贝塞尔曲线绘制旁路虚线 | 依真实配置展示代理、直连或其他网关，不把所有路径画成经过 OpenCodex |
| 延迟与节点反馈 [S1]、[S2] | 渠道前连线上放探测延迟胶囊和探测时间；节点问题标记带悬停说明；探测中为 spinner | 分开命名“连接探测耗时”和“请求耗时”，不把其中一个当作首字延迟或吞吐量 |
| 节点动作 [S2]、[S3] | 节点跳转页面；渠道和模型另有弹层入口，可切线路／供应商或速度档 | 第一阶段节点只读查看、跳现有编辑入口；需要模型选择时复用公共渠道模型选择器 |
| 多工具泳道 [S4]、[S5] | 工具多于一个时自动采用每工具一行、共享路由节点；直连与代理关闭分别处理，放不下的工具折为 +N；不是自由拖拽画布 | 先验证单 Codex 路径，再按已知客户端来源展开泳道，不凭发现了某个平台就画接入线 |
| 线路实际使用 [S6] | 直连取已应用线路；路由模式取最近观察的 last_route；源码明确偏好不等于请求采用 | 配置指向与最近请求分别呈现，重试／回退按具体请求展开 |
| 刷新与动效 [S2]、[S7] | 页面显示时约 20 秒重读请求记录和路由快照；绘制中有悬停与探测 spinner，主路径没有发现流动光点 | 借鉴按需刷新；沿 Desktop 既有刷新机制，不照搬 20 秒或另开常驻高频轮询 |
| 线路小曲线 [S6] | 最近 30 分钟响应时长趋势，按有响应样本绘制 | 它是历史趋势图，不是请求沿连接线流动的实现 |

源码编号和固定行号见第 8 节。上述读取没有执行 Superba、安装软件或运行其 GUI，因此不标记为实屏复刻验收。

## 4. 与 OpenCodex／Desktop 实际架构对应

本地依据为 Desktop 0.2.17 开发工作树，以及安装包 OpenCodex 2.84.0 的只读源码。Desktop 核对时 HEAD 为 b9fcc1b6080135233d6ef44a3e5478fd209aa16d，相关读取文件未修改。安装包版本不证明当前运行进程版本。

~~~mermaid
flowchart LR
  C[Codex App / CLI] -->|模型请求| O[OpenCodex 本地代理]
  O -->|路由与转发| P[Krill / 其他渠道]
  D[Desktop 管理器] -.->|启停、状态、配置| O
~~~

这是经过代理时的结构。直连和其他网关按配置另画；渠道内的模型是选择信息，若单列模型节点，其连线表达使用关系，不增加一个网络转发跳数。

| 当前代码依据 | 已有能力 | 仍需补的展示适配 |
| --- | --- | --- |
| Desktop infrastructure/status_source.rs，54、154、228 行；modules/status/polling.rs | 调用官方 status --json；轻量检查 healthz／readyz；既有前后台刷新与快照推送 | 图与列表消费同一状态快照；区分服务就绪、管理校验结果、读取失败及最后更新时间 |
| Desktop modules/model_config/management.rs，45、130 行 | 绑定本地运行身份后发管理请求；通用管理入口当前只允许已登记的模型配置操作 | 新增独立只读连接摘要／请求记录适配，明确字段；不把现有写操作通道直接当成已有日志读取接口 |
| OpenCodex codex/inject/routing-classify.ts，52 行；codex/routing-adoption.ts，29 行 | 区分原生、OpenCodex 本地、其他本地和远端；可提供待客户端重启的推断 | Desktop 状态 DTO 目前没有完整保留这些路由字段，需要映射；adopted 是启动时间推断，不是流量证据 |
| OpenCodex server/management/request-history-routes.ts、server/request-log.ts | 请求模型、渠道、时间、结果、可用时的对话关联，及路由原因／尝试记录 | 显示最近请求，按请求区分重试／回退；缺少对话关联时停留在实例级，不强行归给当前对话 |
| Desktop modules/model_config/agent.rs，661–686 行 | Desktop 制模助手确实向绑定的 OpenCodex /v1/responses 发请求 | 扩展视图可作为独立请求来源；日常 Codex 对话不画成经 Desktop 转发 |

OpenCodex 已有状态和请求记录可作为第一阶段数据基础，主要工作在 Desktop 的读取、归一化和展示；不替换 OpenCodex 路由器，不给其安装包打补丁。入口 HTTP／WebSocket、上游 HTTP／WebSocket分别在有证据的链路上标注，缺少证据显示未观察。

## 5. 拟做的原型页面与交互

唯一活动源：[总原型](../../../../../01-项目支撑资料/01-产品原型/原型/index.html?design=capabilities#overview)。下列位置均为待制作计划，尚未新增页面或组件。

| 页面／位置 | 拟做内容 | 交互边界 |
| --- | --- | --- |
| 公共组件专题 → 连接关系 | 拟登记 connection-map 专题；单路径、多来源泳道、管理侧支、未知／异常、长名称和窄窗 | 先完成公共组件打样；图和列表共用数据与选中状态，区别于树形导航 |
| 概览 → 连接关系 | 保留现有运行摘要与动作；增加紧凑关系区，默认显示当前实例，支持连接图／列表 | 节点查看详情或进入已有页面；配置指向／最近请求分别标明，不新增侧栏菜单 |
| 模型 → 渠道详情 | 展示选定渠道的局部来源与线路关系 | 沿用现有渠道、服务节点详情；全局连接偏好仍跳对话策略 |
| 对话 → 执行采用与连接详情 | 复用同一组件，显示能关联到当前对话的具体请求路径 | 保留入口／上游分别观察；项目层提示进入具体对话查看；跨来源记录不混用 |
| 设置 → 对话策略 → 连接 | 保留现有 Provider 偏好及保存／待重启表达 | 连接图不是另一套配置器，不新增项目／对话传输开关 |

视觉方向：DOM 节点沿现有玻璃令牌、字号与焦点样式；SVG 只负责箭头、旁路曲线和管理虚线。第一阶段采用固定列／泳道布局，不引入自由画布和拖线编辑。连线层不挡住节点点击；长名称截断可查看完整内容，多来源默认收敛到当前对象，避免全量交叉线。

状态表达建议：配置指向用虚线并写明“配置指向”；最近有记录的请求路径用实线，标记具体时间；异常标在发生问题的节点／链路，悬停给摘要、点击打开详情。管理关系使用独立侧支与“管理”文字，不只靠颜色区分。上游 Superba 的虚线表示旁路／停用，本项目上述配置虚线是自己的语义，必须配图例，不能混称相同原版规则。

探测延迟、请求总耗时和首字延迟分别命名；不凭某个延迟值改变动画速度。没有活跃请求开始／结束事件时，仅展示最近请求，不以持续光点表示正在传输。已有日志只能说明记录的请求，不能将某个渠道长期标成唯一当前连接。

## 6. 后续事项与顺序

1. 公共组件打样：单 Codex 代理路径、直连旁路、管理侧支、多来源泳道及图／列表对照；右侧工具板驱动 mock 场景，注释沿现有顶层标记。
2. 先交效果图：亮／暗整体各一张；补选中路径、读取失败及回退示例截图。保持本软件当前缩放，在 1180×760 与 900×600 软件窗口检查拥挤、折行和浮层可达性。
3. 再接业务原型：概览为主入口，渠道详情与对话执行详情复用，保留已有草稿、保存和导航；模型编辑全部调用既有公共模型选择器，不恢复简单模型下拉。
4. 生产数据适配：定义一个连接摘要模型，分别带配置来源、运行实例、最后成功采样和请求观察时间；补路由字段及按需只读请求读取。沿既有状态刷新与事件推送，不新增独立定时任务体系；记录区显示时才增量读取。
5. 数据条件具备后再评估请求开始／结束驱动的流动效果；隐藏窗口、低特效和减少动态效果时停止。此项是增强，不阻碍第一阶段只读连接图。

待核对的实现问题：实际启用的 OpenCodex 版本所提供的只读日志鉴权与返回字段；Codex App／CLI／制模助手来源是否可可靠区分；对话 ID、物理线路和重试身份能否保留。未取得的字段在图中如实留空或标未观察，不增加禁止用户正常操作的门禁。

验收覆盖：已配置未启动、服务就绪未有请求、最近成功请求、原生／其他网关直连、代理停止、入口与上游不同传输、重试／回退、多来源、过期快照、长名称及最小软件窗口。图与列表解释应一致；配置保存和重启不会自动生成请求观察。
