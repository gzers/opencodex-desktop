# 0.1.3 / 0.1.4 / 0.1.5 OTA 修复有效性审计

审计日期：2026-10-05（Asia/Shanghai）。范围：用户要求核实旧版本能否 OTA，以及既有修复是否有效。本次未修改生产代码、未发布、未替换用户已安装的应用。本文纠正 `REL-OPENCODEX-DESKTOP-05` 中关于代理修复和签名验证范围的表述，不代表发布或真机升级验收通过。

## 结论

**不能判定 0.1.3、0.1.4 完全无法 OTA；可以判定当前稳定通道尚未向它们投递更高版本，且 0.1.5 没有修完全部更新问题。**

| 版本 | 已核实行为 | 修复有效性 / 遗留问题 |
|---|---|---|
| 0.1.3 | 已有真实端点、手动代理注入、下载验签和安装调用 | 检查成功后残留旧错误；安装失败后当前页面无法重试；官方 npm 查询存在 PATH 缺失 |
| 0.1.4 | 桌面 OTA 命令和升级页面与 0.1.3 完全相同 | npm 查询 PATH 修复有效，但不改变桌面 OTA；上述 OTA 缺陷仍在 |
| 0.1.5 | 成功检查统一清空旧错误，两条成功分支均通过故障恢复测试 | 该修复有效；安装重试缺陷仍在，发布流程也未完成新版投递 |

旧错误会使界面显示“失败”，但成功检查仍返回可用版本，安装按钮也不以 `error` 为禁用条件。因此该显示缺陷本身不足以证明首次安装必然失败。

## 审计发现

### P1：稳定通道没有新版，现有公开发布步骤也不推进 Latest

2026-10-05 00:31:54 +08:00 的匿名 HTTP 核查：stable 返回 HTTP 200，`version=0.1.3`；beta 返回 HTTP 404；公开 Release 列表仅含 v0.1.3 及更早版本。旧记录称 v0.1.4/v0.1.5 为草稿，本轮只能独立确认其未公开，未使用凭据重新读取草稿状态。

`main@cb0edcae` 的 `.github/workflows/publish-release.yml:52–74` 明确使用 `--latest=false`，然后恢复之前的 Latest。这能满足“只切公开可见性”的用途，却不能完成稳定通道的新版本投递；步骤名称“取消草稿并标记为最新”与实际行为也不一致。单独触发 `publish/v0.1.5`，不能据此预期稳定通道变为 0.1.5。

处理建议：保留旧版本补公开时不抢占 Latest 的能力；为经确认的新稳定版增加明确的 Latest 晋升步骤，并验证匿名 stable manifest 的版本、平台资产及下载结果。证据：[HTTP 回执](../../.adg/evidence/OTA-AUDIT-20261005/http-receipt.json)。

### P1：安装失败后，当前页面的重试被永久置位的标志拦住

`apps/desktop/ui/src/routes/SettingsRoute.vue:263–278` 中，`installUpdate` 在打开确认框前把 `updateInstalling`、`installRequested` 置为 true。确认后的失败路径没有复位，只有取消路径复位。更新 store 虽在 finally 清理 `appUpdateBusy`，并在失败时返回 false，却无法清理组件中的这两个标志；弹框确认也不会额外调用取消回调。

对三个 tag 的原函数分别执行“确认安装 → store 返回 false → 再次点击”：三个版本都只有一次弹框、一次安装调用，两标志仍为 true，第二次点击直接 return。影响持续到组件重新挂载或应用重启；不是宣称应用从此永久不能更新。

处理建议：在失败/拒绝路径清理组件状态，保留正在安装时防重复提交的行为，并回归“失败后重试、取消后重试”。证据：[重试结果](../../.adg/evidence/OTA-AUDIT-20261005/ui-retry.json)。

### P1：发布命令失败，步骤仍可能返回成功

`.github/workflows/publish-release.yml:38–78` 使用 `set -uo pipefail`，把失败退出码写入 `status`，但末尾没有 `exit "$status"`；最后的 `cat` 成功即得到退出码 0。

在本地抽取原步骤，仅重定向诊断文件、用无网络的 `gh` 替身让发布和恢复 Latest 都返回 17，整个步骤仍返回 0。如果后续诊断公开步骤成功，工作流仍可能全绿。因此不能用它的绿色结果证明公开发布已完成。

处理建议：传播失败退出码，同时用 `if: always()` 保留诊断输出；成功后独立核对目标 Release 与通道状态。证据：[退出码回执](../../.adg/evidence/OTA-AUDIT-20261005/publish-exit-receipt.json)、[模拟日志](../../.adg/evidence/OTA-AUDIT-20261005/publish-failure-stub.log)。

### P2：手动代理“首次补上”的修复说明不成立

0.1.3 已包含 None → `no_proxy()`、System → 保持 builder、Manual → `proxy(...)` 三个分支。0.1.5 对有效手动代理主要是抽取 helper，实际额外变化是非法代理 URL 的回退从保持 builder 改为 `no_proxy()`。三个 tag 的命令测试都能通过手动代理读取真实稳定通道，也都能通过隔离代理下载并验签。

此外，`commands/update.rs:30–36` 所称“系统代理只识别环境变量、不读 macOS 系统设置”与本轮依赖源码不符：实际解析为 updater 2.13.1 → reqwest 0.13.5 → hyper-util system proxy，存在 macOS SystemConfiguration 实现。公开 0.1.3 macOS 桌面二进制也含 updater 2.13.1 标识。这里只纠正绝对化断言，不声称已验收用户机器上的自动代理/PAC 场景。

依赖注意：`Cargo.toml` 的 `"2.11.0"` 是版本范围；`Cargo.lock` 被忽略，未受版本控制。不能仅凭清单字面值认定发布二进制使用 2.11.0，也不能把本轮共同依赖环境的测试当成每个历史制品的完整运行验收。证据：[源码哈希与公钥](../../.adg/evidence/OTA-AUDIT-20261005/source-receipt.json)、[0.1.3 二进制回执](../../.adg/evidence/OTA-AUDIT-20261005/v013-binary-receipt.json)。

## 已完成的有效性验证

- **旧错误清理**：先返回 HTTP 503，再分别返回有更新 / 无更新。0.1.3、0.1.4 保留旧错误；0.1.5 两条成功路径均清空。
- **官方 npm 查询 PATH**：使用真正的 Node 进程和 `#!/usr/bin/env node` 临时 npm 脚本，在无 PATH 环境执行各 tag 的原查询函数。0.1.3 失败，0.1.4 成功返回受控数据。该测试不访问 npm registry，也不等于桌面 OTA 测试。
- **真实插件网络与签名**：读取真实稳定端点；下载公开 0.1.3 macOS 签名包 3,889,685 字节并完成密码学验签。篡改单字节被拒绝；将签名 0.1.3 包冒充 manifest 0.1.6 也被插件拒绝。
- **macOS 替换机制**：在一次性临时 `.app` 中调用真实 `download_and_install`，确认旧标记被移除、新二进制及 0.1.3 Info.plist 写入。未触碰用户已安装应用，未执行重启。
- **重试与工作流失败传播**：上述两个遗留缺陷均已用原函数/原 shell 步骤隔离复现。

Rust 定向审计最终为 **3 passed / 0 failed / 15 filtered out**。证据：[原始测试日志](../../.adg/evidence/OTA-AUDIT-20261005/rust-audit.log)。这三个审计测试包含多项断言，不拿数量代替验收覆盖。

## 方法和边界

源版本：v0.1.3 = `bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028`；v0.1.4 = `5b90fe854f1623239009fea153b2280601b9ee1e`；v0.1.5 = `cb0edcae696c4fdd75461775de2c6201c897a2f5`。实现事实源为这些 tag 的源码；文档不复制实现。

一次性 Rust 测试使用各 tag 的 `commands/update.rs` 与配置快照，在当前 main 的共享模块/依赖环境运行。适配仅包括：MockRuntime、移除重复 command 宏、受控用例端点注入、为私有 builder 增加测试访问桥。线上端点测试关闭注入；隔离 HTTP fixture 才允许明文，真实 HTTPS 测试保留 TLS 验证。偏好/数据根均是临时目录。

受控下载使用真实签名 0.1.3 制品与模拟当前版本 0.1.2；线上同版本下载探针另设比较器以验证下载及验签。二者都不是已安装 0.1.3/0.1.4 → 0.1.5 升级。临时 macOS 安装测试直接使用真实插件 builder 指向一次性应用包，没有调用生产安装命令最后的重启。

临时复现材料保留在 `/tmp/ocx-ota-audit-20261005/`（可能被系统清理）；测试入口已从代码工作树移除。持久证据保存在本报告链接的 `.adg/evidence/OTA-AUDIT-20261005/`。原始命令：
