# 共用认证的服务节点与手动切换

日期：2026-10-14。项目：opencodex-desktop。产品：OpenCodex 桌面管理器。归属：模型配置管理与同步 0.2.0 候选原型。

用户澄清并同意：同一渠道服务有多个 URL 节点，共用 Key 和其他认证信息。此次替代此前独立协议端点设计；旧记录保留当时范围，不视为当前实现契约。

唯一入口：[产品主原型](../../../../../01-项目支撑资料/01-产品原型/原型/index.html#models) → 渠道模型行内“编辑”。同步配套说明仍在该入口的同步菜单。

## 页面与流程

| 入口 / ID | 调整与行为 |
|---|---|
| mpChannelSection-connection | 一份渠道默认协议及认证 / Key，移除重复的可编辑 Base URL；未确认输入仍按既有缓冲与模型确认流程处理 |
| mpChannelSection-nodes | 服务节点替代协议端点，位于模型默认和模型列表之前。名称、URL、当前标记及设为当前 / 编辑 / 删除；原型标签 06 解释边界 |
| 新增渠道 | 第一轮 Base URL 自动成为 primary 默认节点；渠道 connection 只保存认证状态，节点只保存 ID / 名称 / URL |
| 新增 / 编辑节点弹窗 | 只填写名称和 URL；没有协议或 Key 字段。名称 / URL 重复、带凭据 / 查询参数 / 生成接口的地址拒绝，取消不改草稿 |
| 设为当前 | 手动切换渠道级 activeNodeId，全部模型共用，保留清单、选择、顺序、规则与认证；旧连接验证过期，共用账户的无额度状态继续保留 |
| 删除节点 | 至少保留一条，当前节点先切换再删除；确认显示范围并绑定草稿 / 未确认编辑基准，过期确认拒绝 |
| 模型展开与明细 | 移除模型指定端点 / 地址选择，继续独立设置协议及能力；旧节点指定补丁不能绕过新边界 |
| 保存 / 恢复 | 节点操作进入全渠道草稿，差异列节点及旧 / 新 URL；保存前运行配置和 Agent 使用原已保存节点。冻结确认、预算、备份 / 写入 / 核对、待重启和历史恢复继续保留 |
| 列表 / 外部任务 / 同步说明 | 列表展示节点数；Agent 任务仅带节点身份、当前与地址配置状态，不带 URL / Key。同步对象详情使用已保存的当前节点地址并列节点，渠道凭据仍只选择一次 |

同一渠道节点是同一服务的等价访问入口，不按协议分配。协议决定请求格式，当前节点提供地址，渠道提供认证。原型路由分组共用当前节点，分组身份不因切换节点而重派生；真实适配、稳定 provider 身份与旧会话仍待实施核验。第一版只手动切换，没有自动测速、轮询、故障转移或请求重发。

方案回写：[协议与节点方案](../02-方案草案/模型协议与端点方案.md)、[模型页交互细化](../02-方案草案/模型页交互细化.md)、[主方案](../02-方案草案/模型配置管理方案.md)、[示例配置](../02-方案草案/model-policy.example.json)及[实施范围](../../02-开发实施/README.md)。示例删除 protocolEndpoints / 单模型 endpointId，改为节点及渠道当前节点引用。便携候选保留本机 URL 的既有边界，完整同步地址与凭据范围沿同步包规则；没有执行运行数据迁移。
