# Windows 自定义根启动绑定子集

本轮在当前真实Windows账户，以02精确候选验证既有anchor引用外置活动根和HOME后的原生启动。02与8be的五个相关存储源码blob相同，等价范围保存在证据中；实际运行EXE仍记02，不能改标8be。

启动前仅对自有夹具的anchor元数据写入已有自定义根 `custom-root` 和外置 `external-home` 引用。普通实际进程为false/type3，管理员实际进程为true/type2，TokenUser摘要相同；两次原生设置页均显示同一自定义数据根和HOME。原生手动备份实际写入自定义根，原anchor的app.log未更新，进程均正常退出0。

操作后恢复anchor元数据的原始字节，HKCU启动指针保持原值，未替换日常EXE或删除旧配置旁存。49项清单及独立 `verify.py` 通过，原件在 `.adg/evidence/OCX-0110-20261016-WIN-CUSTOM-ROOT/`；首次页面未就绪时按钮未找到的失败记录保留，同一实例就绪后才核对页面。

这是对已有绑定的启动解析验证。没有通过设置界面保存路径，未证明真实OpenCodex子进程继承HOME，也不覆盖目录迁移、宿主安装升级或卸载保留。此前UI保存被真实未核验运行态拒绝的结论仍保留，完整存储检查和TASK-182保持待验。
