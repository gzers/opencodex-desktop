# 20261016 上下文管理补充与模式互斥

状态：用户补充目标与渠道说明已记录，产品方案待评审；没有执行真实配置覆盖、模式切换或联调。后续[边界纠正](20261016-外部管理层边界与方案纠正.md)明确本项目不修改上游，以下适配差距仅作能力观察。

## 新增输入与来源级别

用户补充 Krill 新版上下文管理，转述渠道称 10-12 起重新开放、教程默认开启，使用 history/notes 翻历史和记笔记。用户同时提供 2026-10-16 08:57:32 的 Krill Bot 答复：两种机制二选一，不能同时打开再在对话中选择；后台压缩需要关闭 `context_management` 和 `token_budget`。原文及省略范围见[需求输入](../01-原始输入/需求输入.md)。

互斥、重新开放时间及默认配置目前来自用户转述的渠道材料，未独立访问渠道消息。官方 Schema 支持这些配置及 history/notes 扩展，但本轮未取得足以直接证明互斥规则的官方文档或指定 alpha 运行证据。

## 对前序方案的修订

- 原三项目标保留，增加新版 history/notes 上下文管理，当前共四项目标。
- `context_management`、`token_budget` 不再只作为背景配置列举，新增独立能力链路。
- 根据渠道说明，候选 UI 采用“上下文策略选择 + 速度档选择”；后台压缩与新版上下文管理分别生成一致配置，不设计为三个互不约束的开关。
- 不承诺对话内即时切换。当前依据是客户端配置及完全重启要求，需说明真实作用域并验证旧会话；默认模式尚未选定。
- Ultrafast 作为独立速度维度保留，两种上下文策略都应分别联调，不能提前标为组合已支持。

## 候选配置片段

以下仅用于表达互斥组合，合并时保留原代理地址、认证与其他设置，不是完整配置，也没有写入本机。旧引擎可能不识别新开关，使用前应确认实际版本。

后台压缩模式：

```toml
[features]
async_compaction = true
context_management = false

[features.token_budget]
enabled = false
```

新版 history/notes 模式：

```toml
[features]
async_compaction = false
context_management = true

[features.token_budget]
enabled = true
use_history_notes_extension = true
```

后续实现须按有效配置检查冲突。若导入配置同时打开两套机制，应解释该配置按渠道说明无法产生预期后台压缩效果，再由用户选择策略；不要默默判为两项均已生效。字段合并、覆盖层与配置表写法的兼容需单独验证。

## 只读核实的新发现

本机 OpenCodex 2.84.0 包源码已经包含 history/notes 端点识别和 JSON 转发。`server/context-history.ts` 使用会话归属及凭据主体选择上下文服务；候选来自 `providers/openai-sidecar.ts`，目前严格限定官方 ChatGPT 目的地。`server/responses/response-effects.ts` 的归属登记也受该目的地条件限制。

因此，Krill 模型普通请求能通过代理，不等于对应 history/notes 请求能通过。需要同时验证上下文端点、Krill 认证、会话服务身份和实际转发。按后续用户重申的边界，本项目不修改这些内部实现；仅评估公开配置、独立外层或记录上游依赖。源码位置和指纹见[来源调研](../02-方案草案/官方核实与本机源码调研.md)。

官方 `TokenBudgetConfigToml` 仍定义上下文轮转及自动压缩相关回退参数。因此把渠道的“不再整段压缩”理解为主要工作方式变化；本包不承诺任何异常、手动操作或兜底场景都绝无压缩。
