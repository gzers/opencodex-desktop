# 0.2.24 可继续的版本移除核心

revision: 1；2026-11-11，代码 main5e75b0c866e6fc171b1d5d9ea374513a30cc5480。承接完整镜像目录、版本选择及终端登记合同，进度归 IMP-34。当前为Rust核心，尚未接替卸载窗口的完整端到端命令。

## 准备与调用责任

program_removal::prepare(I,D,H,selections)只接调用方明确提供、已经源准入的CurrentSelection集合；不扫描一份任意镜像清单就赋予自己删除权限。每个版本核对原镜像清单摘要及完整目录；集合必须包含当前版本，I/runtime/versions中存在集合外的目录、文件或重定向均拒绝。冻结普通文件和目录清单、原current、内部入口、D来源记录以及预定未选择版本的来源后像；保留未知来源字段和历史。

Prepared::preview仅返回操作ID、版本列表、程序根、保留的HOME、原总文件数/体积与确认摘要；不写备份或删除。Prepared::execute必须得到同一摘要，并由上层持有应用存储/安装预约、真实进程/服务不在用证明以及已预览的自有终端撤销动作。unused回调必须证明所有命名程序镜像都不在用，不可仅用当前H没有runtime记录代替。Windows跨用户代码共享、进程代次/Job/租约等仍需其原生后端；测试注入回调不能成为生产默认证明。

删除前完整保护H/config.json并复核，随后撤销本用户自有终端入口。终端撤销失败、配置保护失败、原选择/来源/目录变化或停止不确认，不进入程序删除；已生成的保护备份保留，不伪造“什么也未发生”。Mac测试使用真实终端模块，外部替换的命令会保留并阻断移除。

## 删除及中断承接

I/runtime/.removal-pending.json保留原计划及摘要。普通版本读取，包括激活读回路径，都拒绝该pending，避免部分移除的程序被再次采用。它不是安装恢复pending，安装恢复器不能猜测解释它。

顺序为：持久pending → 删除原内部入口/current → 验证并删除命名普通文件 → 只移除已空目录 → 移除清单及空版本根 → 提交未选择来源和卸载历史 → 持久完成记录 → 清pending。每个文件删除前再次核对其原摘要/大小/执行标记和路径，删除不用remove_dir_all。文件逐项流式检查；生命周期/配置/原操作身份在阶段和有界批次复核，不逐文件重新扫描整个版本树。

resume(I,D,H,confirmation,unused,revoke_terminal)是明确继续，不会自动回退已删除文件。恢复时允许原冻结对象已经缺失，但存活对象必须仍是原清单中精确相同的条目；新增文件/目录、被改动文件、陌生入口或外部来源值拒绝，未删原件及pending保持。清单最后删除，若清单缺失而目录仍有内容则拒绝。另一D/H和错误确认摘要不能借原卸载记录执行。

完成记录I/runtime/.runtime-removed.json保留原操作和结果所需后像；D来源记录目录与I事务目录均同步后才完成。正常启动核对该标记，不自动重新供应运行包。RuntimeHandle在没有选择版本时只观察，不再改写来源时间。标记、来源或目录不一致时保持未知，不以“找不到入口”伪报完整卸载；记录存在且pending未清时仍需继续原操作。

## 范围及未完

核心仅移除明确版本代码和内部入口，保留H配置、D备份、其它用户数据和I内无关工具。它本身不执行官方ocx uninstall、不清空HOME、不删除Desktop .app，也没有决定完整卸载选项。来源集合登记器、完整卸载的官方清理/用户数据选项、真实程序不在用证明、命令/窗口及继续入口、卸载后的用户明确内置重装仍需接线。不能把启动抑制标记当成“显式重装已实现”。

此前实际卸载窗口仍为旧入口，尚未因此完成对新版本目录的消费；P24-01和W1/W2仍未关闭或放行。后继集成应将UI预览、终端写集和核心确认绑定，不在执行时从新的任意来源生成删除范围。
