状态：已记录官方复核与产品表达修正；用户要求“先记录然后想办法验证”。本轮先开展原版组件的隔离检查，不将配置定义、模拟上游或纯函数检查当作 Krill 实际线路验收。生产开发未启动。

## 已核实的配置维度

| 维度 | 官方资料实际支持的结论 | 仍不能推出的结论 |
|---|---|---|
| 压缩协议 | `model_providers.<id>.capabilities.remote_compaction` 省略沿用默认，`unsupported` 使用客户端本地压缩，`v2` 通过 Responses 发送压缩触发项 | Codex 配置为 v2 后，OpenCodex 出口一定仍调用 Krill 原生协议 |
| 后台执行 | Schema 有 `features.async_compaction` 开关及启动阈值 | 本地、远程协议和代理摘要均能任意组合后台执行，或压缩永不等待 |
| history/notes | Schema 有上下文管理、token budget 与历史 / 笔记扩展字段；普通参考页仍将相关实验设置标为尚未开放 | 所有账号和渠道普遍稳定可用，或官方已证明和后台压缩通用互斥 |
| 请求速度 | 官方有 Fast / Ultrafast 及 `service_tier`；实际可用性受模型、账号等条件限制 | 开启面板或选择参数就证明渠道实际授予了对应档位 |

来源为本次对话前一轮实际联网打开的[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)、[官方 Schema](https://learn.chatgpt.com/docs/config-schema.json)、[官方速度档](https://learn.chatgpt.com/docs/agent-configuration/speed)、[Ultrafast API](https://developers.openai.com/api/docs/guides/ultrafast-mode)及[压缩说明](https://developers.openai.com/api/docs/guides/compaction)。网页会更新，未保存整页快照；精确 alpha 门槛尚未独立核实。

## 名称与选项修正

“新压缩”在本讨论中是后台压缩，“新上下文”指 history/notes，避免作为正式字段名。“本地”指客户端组织的压缩流程，不表示一定由本机模型计算；OpenCodex 代理摘要是另一个实现路径。

四个维度不是官方提供的四个可自由组合菜单。此前建议的配置 UI 属于产品封装，尚未冻结完整可选组合；远程协议、后台调度及实际处理者须分开记录。保留用户已同意的渠道固定配置、互斥校验、重启应用与出站增强方向，不把后续组合自动记为已获批准或已支持。

“history/notes 与后台压缩二选一”目前按用户转述的 Krill 规则保留，未扩大为官方普遍结论。“远程一定更不失忆”和“后台与普通计费完全一样”也未获本轮官方依据确认；实际质量与渠道账单待专项核实。

## 验证顺序与边界

| 层次 | 方法 | 能回答什么 |
|---|---|---|
| 当前客户端 | 临时 HOME / CODEX_HOME，使用原版引擎检查版本、功能及配置解析 | 本机引擎是否识别配置；不能证明新版或 Krill 可用 |
| 原版请求构造与处理 | 隔离临时配置，仅在检查脚本中导入原版处理函数，合成上下文、档位和压缩输入；产品集成不引用私有入口 | 请求在出口是否保留、是否转成摘要、状态是否被过滤；不修改原版 |
| 本地模拟上游 | 必要时仅在回环地址模拟 Responses / compact / history / notes，使用无真实凭据的可定位输入 | 可验证代理处理和回程形状；模拟成功不证明 Krill 接受 |
| 指定新版客户端 | 若可取得原版预览组件，在隔离目录验证后台与上下文组合 | 明确实际版本条件，不升级日常客户端 |
| Krill 实际线路 | 后续按隔离路径和外部请求授权，使用最小非敏感内容验证 | 原生压缩、history/notes、档位授予、续聊及计费；本轮不默认使用日常认证 |

只核对固定输入与明确模式，不新增运行时探索机制。机器结果、检查脚本和来源摘要进入 `.adg/`；下方结果仅在实际执行后追加。

## 当前执行结果

已完成首轮隔离检查：5 组客户端配置 / 功能列表观察、3 项配置正反例、20 项原版组件及回环模拟检查。当前客户端为 `0.163.0-alpha.10.2`，能读取后台开关；全开组合在解析阶段不被拒绝。
