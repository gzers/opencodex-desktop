# 通知自动收起进度条组件

2026-10-30，Asia/Shanghai。项目：OpenCodeX Desktop，桌面端。首轮按用户要求先制作组件示例，随后经视觉复核确认“按类型半透明着色、左端清晰/右端渐隐、无闪动/明暗/流动”，用户现授权回主原型调整。当前已由总原型的公共Toast与终态任务宿主采用，正式软件未开发或发布；下方试用和历史验证分别保留。

唯一活动入口为[总原型 / 组件与样式 / 通知与任务](原型/index.html#components?section=notifications)，本节“自动收起进度条”区域为#ctNotificationCountdown。界面继续引用原有材质、语义颜色、Toast/任务卡与铃铛，不建立第二个通知宿主。

## 可操作示例

| 入口 / 状态 | 行为 |
| --- | --- |
| 成功通知 / data-ct=notify-countdown-success | 右上既有Toast底部使用3px绿色半透明进度，长度递减表示8秒可见停留时间，固定透明度，不明暗变化或横向流动，归零时收起。 |
| 错误通知 / data-ct=notify-countdown-error | 相同计时，红色半透明进度；不恢复左侧强调条，结果仍由原有标题与正文说明。收起只隐藏展示，铃铛待处理事项保留。 |
| 警告通知 / data-ct=notify-countdown-warning | 琥珀色半透明进度，沿现有warning令牌及注册示例；暂停、收起和铃铛待处理语义一致。 |
| 信息通知 / data-ct=notify-countdown-info | 蓝色半透明进度，沿现有info令牌及注册示例。 |
| 已完成任务 / data-ct=notify-countdown-task | 在原有完成任务卡底部使用同一组件；主原型终态任务共用，不给运行任务套自动消失计时。 |
| 指针悬停 / 键盘焦点 | 暂停计时及线条；所有停留条件结束后从剩余时长继续。页面不可见也暂停，避免回到页面时提示已消失。 |
| 重复播放 / 替换 / 手动收起 | 重复播放更新同一示例并重启展示计时；新通知替换正文即撤销旧倒计时；旧回调不得提前收起新通知。收起和删除语义分开。 |
| 减少动态 | 保留固定半透明渐变并按秒递减，仍使用相同8秒计时；三档材质不改变倒计时语义。 |
| 铃铛 / 历史 | 历史列表不显示倒计时，不自动删除。点击本示例通知可恢复原表面并重新计时。 |

底部线条只表示自动收起剩余时间，任务执行进度仍由任务自身表达。组件不显示每帧倒数文本，不使用持续live播报；保留对现有aria-describedby的关联，提供停留暂停说明。

## 组件与注册边界

- 组件登记ID：feedback.dismiss-countdown，原型资源notification-countdown.js / .css。组件只处理DOM、单调时钟和生命周期，不自行发布业务事件、不访问文件、网络或偏好。
- 示例事件：component.demo.countdown，先在既有maintenance-events目录登记，再由prototypeNotificationPublisher投到原Toast/任务卡/铃铛。variant仅接受success/error/warning/info/task固定枚举；通知语义与读/解决/删除仍属于公共宿主。
- 当前消费者为总原型toast()、showTask()终态宿主及组件示例；文件导入/导出、WebDAV、模型保存等既有消费者共用同一倒计时。组件只负责显示与时间，不新增业务事件、第二宿主或通知条目。
- 组件目录已更新为“主原型采用 / 正式软件未实施”。关联同步通知规划仍沿[0.2.18问题清单S18-03](../06-问题记录/0.2.18-bugs.md)，原型采用不等于真实软件、Windows或持久通知验收。
