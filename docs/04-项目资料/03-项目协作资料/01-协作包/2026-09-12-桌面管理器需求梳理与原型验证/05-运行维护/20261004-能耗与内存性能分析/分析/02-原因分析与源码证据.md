# 02-原因分析与源码证据

## 1. 原因分级

桌面源码固定为 `v0.1.3@bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028`，下文链接均指向该提交。官方源码以安装包 2.69.0、相对路径、SHA-256 固定，见 [source-review.json](../../../../../../../../.adg/evidence/MNT-OPENCODEX-DESKTOP-20261004-04/source-review.json)。E / O 编号对应其中审阅条目。

| 编号 | 问题 | 本轮证据 | 优先级 |
|---|---|---|---|
| PERF-01 | 高档概览两套持续绘制，存在重复计算与写入；应用前后台门控待补齐 | **短时 A/B/A + 源码确认**；可见概览相关 CPU 约 45%，各改动收益待测 | P1 |
| PERF-02 | 隐藏窗口仍判定为前台，驱动循环固定 3 秒唤醒 | **源码确认**；真实后台能耗差值待测 | P1 |
| PERF-03 | 高频监测复用完整官方诊断，连接维度未隔离工作量 | **源码确认**；子进程次数与分项 CPU 待测 | P1 |
| PERF-04 | 托盘 1 秒轮询与重复状态 / 原生托盘写入 | **源码确认**；独立成本未量化 | P2 |
| PERF-05 | 隐藏面板复用 WebView，没有闲置回收策略 | **保留策略已确认**；后台请求与长期增长待验证 | P2 |
| PERF-06 | 状态命令超时路径未显式终止子进程 | **清理风险由源码确认**；本机残留未证实 | P2 |
| PERF-07 | 日志尾读缺字节上限、事件落盘逐次同步 | **触发条件明确**；未证明是当前空闲能耗主因 | P3 |

官方 Bun 的长期 CPU 与内存趋势单列测量，不在缺少剖析结果时认定为运行时泄漏。

## 2. PERF-01：默认高档的持续绘制成本

[effects.ts:18、63–64](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/ui/src/app/appearance/effects.ts#L18) 将默认档设为高，在高档且 DOM 可见时允许连续装饰动画。

[scene.ts:203–289](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/ui/src/features/runtime/motion/scene.ts#L203) 每帧执行三角计算、临时数组、光场颜色、CSS 变换、SVG 几何与渐变属性写入。即使服务状态不变，浮动、旋转与光场仍推进，回调继续逐帧排程。

[meshGlow.ts:191–195](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/ui/src/features/runtime/motion/meshGlow.ts#L191) 另有 WebGL 循环，每帧更新 uniform 并绘制。两条循环没有独立 FPS 上限，实际节奏受浏览器与显示刷新影响。脚本、SVG / 样式更新、WebKit 合成与图形绘制共同构成持续成本。

实测高 → 中 → 高的 CPU 约 46.25 → 0.27 → 44.89，支持装饰渲染归因；尚未拆分 logo、光场和玻璃合成的贡献。

**已有保护应保留：** [RuntimeMotionMark.vue:31–49、81–102](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/ui/src/features/runtime/components/RuntimeMotionMark.vue#L31) 在中档 / 减少动态时关闭 active，光场 `setActive(false)` 会停止续帧；低档不创建光场。光场 DPR 限制为 1.6，销毁时取消帧、断开观察并释放上下文。概览路由也有可见性处理和卸载清理（E05），设置页的实测近乎空闲与之相符。

用户已明确前台效果不能减少。优化重点据此调整为：保留前台高档动画，减少重复计算与相同属性写入，补齐原生应用前后台与窗口可见状态的暂停联动。当前中档不会持续执行这些装饰循环，离开概览也有清理；中档对照用于定位原因，不能直接作为完整效果的交付方案。

## 3. PERF-02 / 03：后台监测没有真正变轻

### 3.1 后台判定与关闭路径不一致

[lib.rs:393–398](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/lib.rs#L393) 通过 `windows().is_empty()` 判断后台。默认关闭行为在 [534–546](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/lib.rs#L534) 调用 `prevent_close()` 与 `hide()`；窗口对象仍存在，因此正常托盘驻留不进入后台策略。

[固化策略 runtime.defaults.json:4](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/config/runtime.defaults.json#L4) 设定运行 / 连接前台 3 / 15 秒、后台 10 / 30 秒。配置存在，但隐藏路径没有正确消费。

[runtime_defaults/mod.rs:88–96、119–131](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/modules/runtime_defaults/mod.rs#L88)（E17）以构建期嵌入 JSON 与类型化访问器读取上述值。因此现有检查周期已经部分配置化；新增轻重检查与退避应沿用这一默认来源，优化重点包括分项采集与调度正确消费配置。

[lib.rs:412–415](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/lib.rs#L412) 的装配循环固定休眠前台 3 秒。[polling.rs:125–158](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/modules/status/polling.rs#L125) 已有按下次到期时间休眠的逻辑，却未接入。失败退避仍可减少实际采集，但固定驱动唤醒不会随之变长。

### 3.2 高频状态刷新执行完整命令

[polling.rs:87–122](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/modules/status/polling.rs#L87) 任一维度到期就调用同一个完整 `collector.refresh_at`；[status/mod.rs:775–823](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/modules/status/mod.rs#L775) 再调用 `source.fetch`。1 秒防抖不会给连续 3 秒刷新提供缓存。

[status_source.rs:46–58、94–116](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/infrastructure/status_source.rs#L46) 每次采集启动 `ocx status --json`，等待输出、解析 JSON，通过同步桥接进入运行时，期间持有采集器锁。

官方 2.69.0 的 `src/cli/status.ts:686–765`（O01）包含运行时解析、客户端连接、远端 hub、健康探测、启动健康、服务管理器、shim、插件和用户主目录诊断。综合诊断的工作量超过简单读取运行状态。连接维度虽设为 15 秒，但运行维度 3 秒触发的完整命令已包含连接相关工作。

3 秒名义周期对应**每小时最多约 1200 次周期性完整采集**；实际间隔还包括命令耗时、调度与退避，另有手工刷新。这是配置推导量级，**本轮没有统计实际次数**。固定 PID 表未捕获临时子进程，不能据其估算这些命令的全部成本。

## 4. PERF-04：托盘桥接与状态发布

[useAppController.ts:170–207](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/ui/src/composables/useAppController.ts#L170) 每 1 秒拉取托盘请求队列，组件卸载才清理计时器；该处没有可见性降频、失败退避或在途保护。名义量级为每小时 3600 次触发，真实调用可能受 WebKit 节流影响，尚未统计。

[lib.rs:342–349](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/lib.rs#L342) 更新托盘并发状态快照；[tray_controller.rs:120–142](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/infrastructure/tray_controller.rs#L120) 重写 tooltip、标题和启用状态。运行状态通知已有去重，这些托盘 / 快照操作尚未按语义变化缓存。

独立成本尚未量化，优先级低于已实测动画。优化必须保留托盘命令可靠性；相关既有事故见 [白屏与托盘左键菜单记录](../../20261004-白屏与托盘左键菜单/README.md)。

## 5. PERF-05：内嵌面板的驻留取舍

[panel.rs:230–256](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/commands/panel.rs#L230) 隐藏子 WebView、下次打开复用，源站变化时才关闭。[PanelRoute.vue:251–257](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/ui/src/routes/PanelRoute.vue#L251) 清理路由计时器、观察器与布局帧，再通知后端隐藏面板。

策略以驻留内存换取再次打开速度，离开后不会立即释放官方页面的 JS 堆、资源与缓存。候选 WebContent footprint 约 109M，后期 `top MEM` 为 163～165M，但归属与增加原因未确认，不能计为已证明的泄漏。

官方 GUI 编译包 `gui/dist/assets/App-DDbgOTh6.js`（O03）已有 DOM 可见性与 `opencodex:host-visibility` 门控。需要验证原生 `hide` 是否正确改变页面可见性 / 宿主信号，再决定补桥接、暂停恢复或闲置 TTL 回收；单凭计时器存在不能断言隐藏后持续请求。

## 6. PERF-06 / 07：次级健壮性风险

状态命令使用 5 秒超时，同时配置 `kill_on_drop(false)`（[status_source.rs:58、98–100](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/infrastructure/status_source.rs#L58)）。超时后未见显式终止与回收，存在慢命令继续存活风险。是否累积需用可控慢命令和子进程树验证，本轮未证明实际残留。

日志已有 [64 KiB 分块尾读与行数截断](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/modules/logs/mod.rs#L87)，但少数超长行 / 无换行文件可使缓冲区扩大、反复统计与前置复制，缺少额外字节上限。管理器自身日志有 [5 MiB 轮转](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/infrastructure/runtime_log.rs#L13)，每个事件仍调用 [sync_all](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/infrastructure/runtime_log.rs#L71)。两项风险分别依赖极端日志与高事件率，本轮没有相应负载证据。

## 7. 对内存与整体优化水平的判断

官方 watchdog（O02）默认 60 秒采样、最多 360 条记录，停止时清理计时器；历史采样有边界。其源码中的 Windows / Bun 内存问题提示不能直接套用本机 macOS。

当前已有减少动态、可见性、卸载清理、DPR 限制、日志尾读与轮转、失败退避等保护。实测与源码仍显示：**持续视效的默认预算偏高，后台策略接线不完整，监测链路没有分清轻量状态与重诊断**。这些缺口足以优先优化；长期服务泄漏和面板隐藏行为由后续证据定案。
