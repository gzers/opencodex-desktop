# 兼容与异常恢复

## 写入与回退

每次应用冻结对象范围、身份映射、依赖和基准。写前重新验证，备份成功后才开始写入；备份失败不写。模型策略复用预算与编译规则，不能因来自导入 / WebDAV 绕过限制。

各域分别记录应用阶段、成功 / 失败 / 未开始和可恢复范围；含凭据的备份同样加密并受保留策略约束。中途取消、崩溃、超时不能伪报整体成功；重新进入先核对磁盘与安全存储，再重试或补偿，不盲目重放。

回退按本次实际影响字段恢复，保留操作后的无关修改。登录态回退特殊处理：服务端已撤销或轮换的旧材料不能仅凭本地备份恢复为有效登录，需重新验证。运行配置已写入、客户端待重启及账户可用性是不同状态。

## 实施冻结前的门

| 门 | 需要的证据 |
|---|---|
| S-G01 对象注册与去重 | Desktop 策略 + 原有渠道同身份唯一；漂移、独立字段、精确依赖有契约 |
| S-G02 容器与兼容 | 新结构版本、旧读取、新旧互拒、大小与路径边界、独立域隔离 |
| S-G03 凭据过滤与加密 | 已知认证字段过滤、未知内容处理、认证加密、派生上限、口令分离、秘密无日志 |
| S-G04 账户免登录 | 按 provider / OS 验证新设备、过期后刷新、原设备持续可用、设备绑定降级 |
| S-G05 部分同步 | 取消不删除、子集上传保留远端、接收受范围限制、去重与并发基准 |
| S-G06 应用与恢复 | 备份失败、部分失败、漂移、超时、崩溃、令牌轮换冲突的结果可核对 |

本专题纳入 v0.2.0 需求与 WP-04 扩展，不代表这些门已通过。如果任一账户类型暂不支持，应逐类标示，不得静默砍掉账户范围或宣传“全部免登录”。实现拆分与发布承诺待契约 / 证据评审。

生产代码在 main / feature 分支实施；本 docs 分支仅持有需求和原型。实际全局同步、恢复或发布按项目规则另行确认，本轮制作与模拟验证不执行这些操作。
