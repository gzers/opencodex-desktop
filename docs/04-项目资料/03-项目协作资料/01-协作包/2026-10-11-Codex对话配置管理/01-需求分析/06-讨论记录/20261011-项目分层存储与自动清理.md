# 项目分层存储与自动清理

日期：2026-10-11（Asia/Shanghai）。状态：方案增量，版本与开发时机未定，尚未实现。

用户指出项目与对话数量增长会使集中配置文件过长，建议按项目建立配置，并随项目删除、对话归档同步清理。原始输入见 [需求输入](../01-原始输入/需求输入.md)。

本次以该建议调整 [独立配置存储与事件订阅适配方案](../02-方案草案/独立配置存储与事件订阅适配方案.md)，替代此前全量作用域单文件布局：

- 全局文件只保存新增全局行为；项目按数据源和稳定项目 ID 分目录，项目覆盖独立保存，对话有专属覆盖才创建文件。
- 状态按项目有界保存，根状态只保留连接和未完成操作；按需加载当前继承链，不建全量人工项目清单。
- 项目确认删除后清理目录；若原生仍保留对话，先将对话自己的覆盖随真实新归属迁移。
- 对话确认归档 / 删除后移除专属覆盖和相关状态；取消归档后继承当前上层，不自动恢复旧覆盖或重跑历史命名。
- 生命周期事件、成功操作或明确读回用于自动清理；断线后校准已配置对象，列表分页缺项不当成删除。
- 保存、清理与任务收尾串行协调，迟到结果不重新生成被清理文件；只清理管理器拥有的资源。
- 分层配置用专用单载荷 bundle 备份，需新增校验及恢复器；正常恢复不重新激活已归档 / 删除对象的旧覆盖。

本轮只修改 docs/governance-main 的本协作包文档。未修改真实配置、运行模型或新增生产代码；生命周期清理、跨项目迁移与分层备份需要后续针对性验证，原有 8 项原生探针不能证明这些产品能力已完成。

## 导出与同步后续补充

用户随后明确“另外考虑导出同步的操作的时候。webdav默认不同步。”据此将 WebDAV 的本包默认范围改为空，覆盖全局、项目、对话三级。手动导出 / 导入及本机备份独立选择；一次性操作不自动开启 WebDAV。后续若支持协作同步，由用户显式选择模块与作用域，关闭后不交换协作条目或传播删除。详细建议见 [导出与 WebDAV 默认范围](../02-方案草案/独立配置存储与事件订阅适配方案.md#81-导出与-webdav-默认范围)；本轮只回写文档，未改真实设置。
