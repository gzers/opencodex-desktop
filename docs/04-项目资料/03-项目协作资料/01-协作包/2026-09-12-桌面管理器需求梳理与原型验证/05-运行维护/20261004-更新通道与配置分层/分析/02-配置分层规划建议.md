# 配置分层规划建议

维护 ID：MNT-OPENCODEX-DESKTOP-20261004-02。登记日：2026-10-04。本文件是规划建议，**尚未实施，也不构成 0.1.2 的范围冻结**。

## 1. 现状问题

| 编号 | 问题 | 说明 |
|---|---|---|
| C-01 | 扁平化单层配置 | `Preferences` 为单层 28 字段（`apps/desktop/tauri/src/modules/preferences/mod.rs`），前端另有 `PreferencesDto`（`types/preferences.rs`）与 UI 类型，**三处手写映射** |
| C-02 | 校验集中 | 合法性在一条长 `allowed()` 白名单里，新增字段要同时改结构、DTO、校验与界面 |
| C-03 | 通道与频率耦合 | `app_update_channel` 单字段同时编码通道与频率（`stable-24h` / `beta-6h` / `manual`），切频率必然切通道 |
| C-04 | 端点硬编码且双源 | `UpdateChannel::endpoint()` 定义 stable/beta 两个 URL，但真实请求由 Tauri 插件读 `tauri.conf.json` 的静态 `endpoints`；`endpoint()` 全仓无人调用，且通道**不改变实际查询端点** |
| C-05 | 偏好与运行默认混淆 | 更新端点、registry、npm 发现路径属“有默认值、可受控覆盖”的运行配置，与用户偏好同放一份文件 |
| C-06 | 缺版本与迁移 | 仅靠 `serde(default)` 兜底，新增字段时旧文件有被误判为损坏的风险 |

## 2. 目标形态

### 2.1 按域分组

`preferences.json` 只放**用户偏好**，按域分组：

```
preferences
├─ appearance    （界面缩放、特效档位、光场渲染）
├─ lifecycle     （启动打开主界面、关窗保持代理、随 Codex 启动）
├─ backup        （保留数量、完整性算法、包含范围）
├─ extensions    （MCP 冲突策略、掩码、客户端开关）
├─ sync          （冲突策略、冷同步、覆盖前备份）
├─ update        （通道、检查频率、自动检查开关）
├─ cli           （控制面开关）
└─ advanced      （清理、日志 / 通知保留）
```

每域自带默认值与校验；域内字段独立演进，互不牵连。

### 2.2 通道与频率解耦

```
update.channel        = stable | beta
update.checkInterval  = manual | 6h | 24h
update.autoCheck      = true | false
```

界面“更新通道与频率”拆成两个控件；`manual` 不再隐含“落在稳定通道”，通道与频率彼此独立。

### 2.3 分离内置默认配置

更新端点、registry、超时这类“运行默认”移到单独模块（可显式覆盖，但有受版本管理的默认值）：

- **端点 / registry 可配置**（默认值内置，可用受控覆盖）；
- **公钥必须保持编译期受信任常量**：更新端点可配置是为了镜像 / 自建分发，但一旦公钥可运行时替换，任何人都能把更新指向自己的签名，等于放弃更新安全。公钥与端点必须分开治理。
- 删除 `UpdateChannel::endpoint()` 死代码，端点收敛为单一事实源；真正驱动 `updater_builder().endpoints(...)` 或 registry 查询，让通道选择产生实际效果。

### 2.4 版本与迁移

- `preferences.json` 增加 `schema_version`；每域提供迁移函数，旧版本文件按域升级，不再以整体 `serde(default)` 兜底。
- 迁移失败显式报错并保留原文件，不静默重置。

### 2.5 单一事实源

- 由 Rust 域类型驱动 DTO（减少手写映射），或以快照测试锁住“域类型 ↔ DTO ↔ UI 类型”三处字段一致，降低漂移。

## 3. 迁移与兼容边界

1. **读写兼容**：旧 `preferences.json`（扁平字段）读取时按映射迁移到分域结构；写出新结构时保留旧字段的等价语义。
2. **不丢用户选择**：`app_update_channel` 的既有取值映射到 `channel` + `checkInterval`（`stable-24h` → stable + 24h；`beta-6h` → beta + 6h；`manual` → 保持通道 + manual）。
3. **共享文件一致性**：`preferences.json` 由管理器写入数据根，无跨分支文件归属问题；但字段改名须同步前后端与导出 / 导入容器契约（`契约字段.md`）。
4. **导出 / 导入**：分域后导出容器与 `OCXDCONF` 结构需同步，旧容器导入仍按原口令 / 原结构读取。

## 4. 与更新通道的耦合点

配置分层的直接收益是修好“通道不生效”这一根因：端点成为受版本管理、可被通道驱动的单一事实源后，`channel` 才真正决定查询目标。二者应一起设计，先冻结“配置形态”，再接通“端点驱动”，避免再次出现“改了通道但端点没变”的空转。相关候选见 [0.1.2-候选范围与待决策](03-0.1.2-候选范围与待决策.md)。
