## 为什么做这一版

0.2.11 装机后用户连续反馈四件事，收敛成三组：

| # | 用户原话 | 归组 |
| --- | --- | --- |
| 1 | 「重启 codex 了但是还是显示待重启……而且当前写入后也不能生效」 | A |
| 2 | 「那暂时统一通知时效……是指这个界面」（配图：10 张节点连接检测卡） | B |
| 3 | 「我发现渠道的测速还是无效」 | C |
| 4 | 「通知需要一个一键清理的按钮」 | C |

## 三组的结论

### A 保存通知化（WP-69）

| 项 | 结论 |
| --- | --- |
| 根因 | `client_state.rs` 只看磁盘上是否有一条 `committed` 且有变化的计划，**与用户是否重启无关**；因此重启一百次也不会消失 |
| 用户口径 | 「我们就是写入文件，然后重启 codex 肯定生效」+「这个是执行完的通知提示就行了」 |
| 裁决 | 用户选 **A（什么都不留）**，原话：「B 还要有个状态确认，之前麻烦就是这里。」 |
| 做法 | 删四态状态机 + 删除客户端核对弹窗；保存成功只给一条「已写入」+ [立即重启 Codex] / [稍后]；点「稍后」彻底结束 |

### B 时效统一（WP-70 / WP-73）

| 项 | 结论 |
| --- | --- |
| 堆积根因 | ① `tasks.ts` 淘汰白名单只有 succeeded / stopped，`failed` 永不入候选 ② 每次检测都是新 UUID，同 kind 无合并维度 ③ 点铃铛调 `expandAll()` 把所有收起全反悔 |
| 实盘 | 10 张「节点连接检测 · 未完成」永久叠在右上角，压住渠道表格 |
| 做法 | 同 kind 合并（显示第 N 次）+ 终止态 8s 自动收起（不删除）+ 同屏最多 3 张 + 删掉点铃铛的 expandAll；Toast 恢复 2200 / 5200 两档；删 `expires_at` 断管道 |

### C 测速闭环（WP-71 / WP-72）

| 项 | 结论 |
| --- | --- |
| 实测 | 同一地址不带 Key → **401**（1.02s）；带 Key → **200**（0.69s）。端点通、链路通，只是没带 Key |
| 根因 | ① `ChannelNodeSelect.vue` 取 Key 的函数恒返回空串 ② `upstream.ts` 读现有渠道时 `credentialRef: null`；实盘 26 渠道仅 1 个有 ref |
| 做法 | 新增 `discovery_config`：未提供 Key 时按 providerId 读 `config.json`，**必须同源（scheme+host+port）且协议一致**才携带；新增 `credential_unconfirmed` 与 `discovery_auth` 区分；通知中心补「清理」 |

## 四项裁决定稿

| # | 项 | 裁决 |
| --- | --- | --- |
| 1 | `expires_at` 去留 | **(a) 删掉**（界面无变化，本来就没生效） |
| 2 | 任务卡 TTL 与条数 | **终止态 8s / 同屏最多 3 张** |
| 3 | 测速同源校验范围 | **scheme+host+port 且协议一致，两者都要** |
| 4 | 「立即重启」默认焦点 | **默认聚焦「立即重启」**（覆盖我原「默认稍后」建议）；但默认聚焦≠跳过二次确认 |

## 边界（不声称通过）

- **真机 `--restart-codex`**：会结束正在进行的对话，需用户在场确认；本地包已出但未实机跑该动作。
- Windows WebView2 实屏、触屏手势。
- 代理网络下的测速（`discovery` 走 `no_proxy()` 独立客户端）。
- 8s / 3 张、2200 / 5200ms 是否合适，需真人使用校准。
- 本地构建是 **adhoc 签名**；正式签名链由 CI 流水线产出。
