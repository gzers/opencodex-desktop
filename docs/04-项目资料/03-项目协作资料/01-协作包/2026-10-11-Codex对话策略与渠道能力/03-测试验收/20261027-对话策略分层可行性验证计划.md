# 对话策略分层可行性验证计划

日期：2026-10-27—28。对应[执行架构](../01-需求分析/02-方案草案/20261027-对话策略执行架构与OpenCodex扩展边界.md)。目的：先判断原型里的能力能接到什么执行入口，再确定生产范围；不以配置落盘、界面状态或手写替身逻辑替代实际采用。版本与生产时机未定。

## 1. 验证装置

先用真实 Codex 可执行文件、原版 OpenCodex 隔离进程和本地 Responses / 搜索 / WebSocket 替身。合成项目、对话、模型名和令牌只用于识别请求，不读取真实对话或付费模型质量。

~~~text
test/codex-collaboration/        复用已存在的原生探针（实现工作树）
test/architecture-probes/       本轮出站契约探针与后续接线探针
系统临时目录/                   每轮 HOME / CODEX_HOME / OPENCODEX_HOME、独立端口
.adg/evidence/<本包>/.../       版本、源码指纹、各检查与合成请求摘要
~~~

测试可以创建临时文件和自己持有的进程，退出只清理自己的资源；不改当前 App 配置、不重启正在执行的会话、不运行影响日常服务的 start / stop / sync。后续原版 OpenCodex 启动测试必须先核对其注入开关和数据根，不能仅设一个临时 OPENCODEX_HOME 就假定完全隔离。平台登录态、凭据、代理和遥测环境不从当前终端透传给替身探针。

最初不做大而全框架，每个探针回答一个架构问题；已有脚本能复跑就复用。只有真实上游语义无法由替身验证的项目，最后才采用少量合成内容做真实线路检查。

## 2. 检查顺序与判据

| 步骤 | 必须回答的问题 | 方法 / 通过证据 | 不通过时的结论 |
| --- | --- | --- | --- |
| V0 版本与契约 | 目标二进制到底支持哪些字段、接口和插件 | 记录实际二进制版本 / 指纹、生成该版本实验协议、检查字段；包版本与运行进程分别标明 | 不支持字段单独列缺失，不按较新文档伪造本机支持 |
| V1 原生执行闭环 | 对象 ID、标题、模型更新和恢复继承是否真的影响发送 | 临时 app-server → 本地 Responses 替身，捕获最终 model / effort；同实例与双实例对照 | 能读记录不能称为能控制活动会话；只声明所测实例范围 |
| V2 实际 owning 引擎连接 | 管理器能否连接实际执行该对话的引擎 | 先只读发现公开端点，核对 loaded 对象与事件归属；隔离同一引擎双客户端再做测试对象更新，并检查原客户端事件和最终发送 | 若当前 App 没有可接入端点，外部活动会话控制仍未接通；自行新建引擎只能覆盖自己的任务 |
| V3 原版 OpenCodex 接线 | 公开管理接口、插件加载和出站路径是否真实可用 | 原版隔离服务 + 伪凭据 / 本地上游；管理 API 保存读回，执行请求捕获；插件在自己的插件目录加载，日志和最终目标核对 | 纯函数 hook 通过不等于实际加载成功；Windows 禁用不能靠修改加载器绕过 |
| V4 项目 / 对话与 child | 局部策略能否到达 plan / spawn 前，且并发不串对象 | 两项目 A/B 分别采用模型 A/B，A 下对话再覆盖 C；交错发送，两个兄弟 child，记录 source / project / thread / parent / purpose / revision 和最终参数；撤销覆盖再发送 | 若没有早期入口或身份丢失，记为接口缺口；不能反复切全局配置模拟通过 |
| V5 上下文与传输 | 是否按真实协议完成压缩、笔记和续聊；入口与上游是否不同 | 分别验证摘要、native compact、history/notes；完成一次压缩或读写后续聊及工具回传；HTTP / WS 两段分别抓取，握手与完整响应分开 | 普通摘要、已被拒绝的请求或只握手不证明 native / notes / WS 全链路；记具体上游限制 |
| V6 最小真实确认 | 通过替身的能力在目标版本与渠道能否完整执行 | 少量合成输入，沿已证明身份与通路，保留最终模型 / 协议、续聊及必要结果；真实搜索和子 Agent 分别确认 | 限定失败能力与渠道，不推翻已通过的独立全局功能，不将替身结果升级为真实效果 |

V2 是局部配置的首要架构问题，V3 全局接线可以独立推进。V4 依赖真实早期执行入口；只测试自己写的 PolicyResolver 虽可证明继承计算，却不能证明外部 App 或 sidecar 会读取它。V5 已知缺口应先作负例确认，不反复发真实请求期待绕过。

## 3. 最小场景，而不是堆测试项

### 全局设置

搜索 sidecar 保存模型 X 后，必须捕获下一次 plan 及实际 sidecar 使用 X；另走 hosted search，确认不能把它当作同一路径。只有读回成功不足以通过。命名专用路由需同时运行标题和其他 helper 对照；若一并被改写，结论是 broad helper 可配置、标题专用未满足。显式重新命名另测候选生成、采用与原生标题读回。

子 Agent 全局默认分别检验默认值、显式 spawn 和角色配置，保留原生最终优先级。以脚本化模型替身产生真实原生 spawn 调用，可验证创建与发送参数；不能在测试里直接伪造 child 记录就称为原生继承通过。并发 / 指令与模型发送是不同检查，模型改对不代表并发限制有效。

### 项目与对话

配置全局 G、项目 A 模型 A、项目 B 模型 B、A 下对话 T 模型 C。并发交错发送，检查 A 未覆盖的对话用 A，B 用 B，T 用 C；清除 T 后用 A，清除 A 后用 G。

运行期间保存新 revision，核对它从哪个真实边界生效：下一 HTTP 请求、下一父 turn、下一 child 或重载后。若只能看到请求，不能标成整轮快照；父 sessionId 不能把两个兄弟 child 合并为同一对象。缺失身份是未匹配，不用提示词里的目录推断项目。

### 原生上下文与连接

常规 / 后台压缩的读取与调度用原生引擎验证；代理摘要和原生远程压缩分别标识。history/notes 必须出现真实工具、到达同一服务身份并完成读写及后续调用，单独 curl 路径可达不够。WS 分客户端 → OpenCodex、OpenCodex → 上游，记录完整交换；现有版本不支持的第三方路径明确记为不支持，不靠地址伪装通过。

取消、关闭适配器、一次保存失败和重连各取一个实际场景，验证原通路和未保存输入不受影响；可行性阶段不提前建立完整性能 / 故障演练矩阵。

## 5. 每个探针交付什么

输出只保留 testId、目标版本 / 指纹、执行进程 / 数据源关联、合成对象、期望与实际参数、结果和对应局限，不记录真实凭据或完整生产正文。结果区分：

- passed：所述边界内确有运行证据；
- failed：可执行接口的行为不符合预期；
- unsupported：明确无接口、字段或被上游拒绝；
- inconclusive：连接 / 观测不足，不能判断。

每轮最终产物是一张“能力 × 执行入口 × 生效时机 × 证据”的表，用来修正原型可用范围和实施次序；不要求全部候选同时通过才开发已证实的原生全局能力。

本轮最新原生 child 探针使用 CLI 0.164.0-alpha.11.1；OpenCodex 使用隔离包 2.84.0。真实上游范围仅完成一条现有代理路线的合成请求与公开 example.com 搜索；没有做渠道 / 模型矩阵或质量评估。当前 App 连接仍判为 unsupported_current_launch。V4 的“项目 / 对话搜索”还缺搜索 plan 构建前的策略入口，不能因为 V4 child 通过就扩大为全局局部策略已完成。

当前最重要的架构结论是：独立 owning 引擎已经证明“两个客户端共同控制同一执行实例”可行，但当前桌面启动方式没有向外暴露该连接；要支持外部活动会话，必须改变启动 / 连接方式并取得用户明确选择，不能截取现有 stdio。OpenCodex 出站插件可以做固定目标适配，却不能补齐项目 / 对话身份。


### 本轮测试程序与复跑

本轮均在文档工作树的 test/architecture-probes 内创建研究探针，没有增加生产应用代码：

- probe_owner_connection.py：当前进程只读端点盘点、临时 Unix WebSocket owning 引擎双客户端验证。
- probe_opencodex_service.py：原版 CLI 临时服务、插件真实加载、管理 API、HTTP/SSE、WS 入口、history 拒绝与真实引擎压缩后续聊。
- probe_native_children.py：脚本化合成模型返回真实命名空间 spawn 调用，原生执行器创建 child；三个父 thread / 两项目、对话覆盖及新全局默认。
- probe_protocol_schema.py：目标二进制协议生成与上下文配置正反例。
- ws_json_client.py：仅探针使用的有界本地 WebSocket JSON 传输；不进入产品。

owner / child 探针复用已有实现工作树 probe_native.py 的 RPC / SSE helper。开始时曾遇到探针自身格式问题：project/create 缺少幂等键、命名空间 function_call 写法错误、旧型号不在当前 child 目录，以及 loopback provider 缺少 allowPrivateNetwork 声明。修正均只在临时夹具；不将这些初轮失败登记成原版缺陷。Unix socket 直接采用公开 HTTP Upgrade 成功，早期 stdio proxy 尝试超时不推断为协议不支持。

V6 已完成受限真实确认：沿现有 2.84.0 OpenCodex 代理，用 FeiMao/gpt-6.1-sol 发送一条合成短文本并得到 PROBE_OK；同一路由要求一次 web_search 后成功打开公开 example.com 并返回标题 / URL。结果见 [real-basic.json](../../../../../../.adg/evidence/COL-LOCAL-20261016-01/feasibility-20261028/real-basic.json)、[real-search.json](../../../../../../.adg/evidence/COL-LOCAL-20261016-01/feasibility-20261028/real-search.json)。真实确认范围只覆盖该模型、该代理路由和合成输入，不扩大为所有渠道 / 模型，也未读取日常凭据。第一阶段已能支撑以下实现范围：原生全局设置、受控 owning 引擎的新任务 / child 配置和可选出站适配；外部活动 App 局部控制、任意搜索模型、标题专用路由和第三方 history/notes 仍需契约补齐。


### 收尾、取消与原生并发补验

继续完成同一计划中的四项独立场景：

| 场景 | 当前结果与证据 |
| --- | --- |
| 无效保存 | sidecar API 拒绝非法 enabled 类型，测试配置 SHA-256 前后完全一致，之后 GET 仍成功。只证明本次校验拒绝路径，不冒充磁盘 I/O 故障恢复。 |
| WebSocket 客户端取消 | 收到 response.created 后关闭客户端；回环上游在界限内观察到连接断开，随后的独立请求 HTTP 200。 |
| 关闭插件 | 仅重启自己持有的测试服务，使用原版 OCX_PLUGINS=0 禁用加载；响应成功，上游路径从 /hooked/ 回到 /direct/，插件标记消失。没有重启日常 OpenCodex 或当前 App。 |
| 子 Agent 并发上限 | 创建时设置 agents.max_threads=1；脚本化两次真实 spawn，第二次返回 agent thread limit reached，实际仅 1 次子任务发送。此限制作用于所测父线程树，不是管理器跨项目总预算。 |

另外，三个受控父 thread 的 developerInstructions 标记出现在 6 个子任务的原生模型请求中，证明本次 parent-config 指令继承；不能据此声称存在独立 child-only 公共指令字段。上述结果分别附于 opencodex-service.json 和 native-children.json，采用新的源指纹，不复用旧脚本结果。

当时后台调度仍未观察（后续已完成下节复测）；一次尝试以裸原生型号绕到普通 key 测试渠道被原版要求 canonical openai provider 的规则拒绝，该结果保留为边界证据，未通过冒充官方目的地绕过。V6 已完成最小真实确认；未扩大到其他渠道 / 模型，也未使用真实对话或读取日常凭据。


### 后台压缩阈值纠正与非阻塞复测

先前 inconclusive 的探针只设置自动压缩阈值，没有设置模型完整上下文窗口，因此没有证明后台阈值被达到。原型提示也错误写成“占自动压缩阈值”。本轮根据固定上游 Schema / 实现纠正为“占模型完整上下文窗口”；旧 JSON 以 before-context-threshold-fix 文件保留，不回写成通过。

复测显式设置：完整窗口 100000、后台比例 65%、自动压缩阈值 90000、合成使用量 70000、async 开启、token budget 关闭、Provider remote_compaction=v2。引擎 tokenUsage 事件显示可用窗口 95000，后台摘要请求到达真实 OpenCodex 的回环上游。替身把摘要响应挂起，前台下一轮在挂起尚未结束前完成；之后才释放后台响应。检查使用 background_finished 事件排除“替身等候超时后误判并发”。

对照将 remote_compaction 设为 unsupported，相同窗口与用量、同样开启 async，仅出现两次前台发送，没有后台摘要。此结果与原生 enabled 条件一致：异步压缩开启、token budget 未启用、远程协议为 v2。产品继续允许保存意图，但必须解释该条件，不能把三个维度彼此完全独立的可选项等同于所有组合均运行。

固定源码：[Schema 中完整窗口比例](https://github.com/openai/codex/blob/e3149ddb11e24edea64999030f218447336667ed/codex-rs/core/config.schema.json)、[async_compaction enabled / maybe_start](https://github.com/openai/codex/blob/e3149ddb11e24edea64999030f218447336667ed/codex-rs/core/src/session/async_compaction.rs#L40)。源码用于说明条件，真实通过依据仍是当前二进制与本地链路；不是把最新主线当成本机运行结果。


### 同一已加载父 thread 的 resume 实测

不能只凭 ThreadSettingsUpdateParams 没有通用 config 就推断所有原生入口都不支持，本轮追加真实运行对照。父 thread 首轮创建 child 使用 gpt-6.1-sol / high；其父 turn 完成后，在同一 owning app-server 对同一 thread 调用 thread/resume，传 config 中 agents.default_subagent_model=gpt-6-astra 与 reasoning=xhigh。接口成功返回同一 threadId，但后续真实创建的两个 child 仍使用 gpt-6.1-sol / high。

该结果将“热更新尚未证明”收窄为所测版本的 **same-owner loaded resume 不应用这些新的 child defaults**。settings/update 无专用字段与这条运行证据结合，不能承诺已加载父会话实时更新；start/config 创建时投影仍已通过。此对照没有卸载、迁移或重建原线程，也不证明断开后重新装载的全部状态。

本轮原型上下文提示修订完成后，相关 DOM / 状态回归 12 项通过，记录为 prototype-context-regression.tap；不与引擎检查合计。当前仍只剩真实渠道选择这一需要外部输入的检查项，未触碰当前 App 的启动方式。
