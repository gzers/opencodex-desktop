## 入口与范围

设置 → 安装配置 → 程序安装与卸载 →「重装内置程序」。适用于已有明确完成卸载记录的当前安装，或者该记录所开始的原重装继续；不是损坏镜像修复，不接管未登记目录，不读旧版配置或自动迁移。使用当前应用编译时固定摘要的本地完整资源，不联网下载其它版本，不自动启用终端命令，不执行服务启动或修改本机配置。用户先停止服务；Mac 实际 require_program_unused 证明保持，未知拒绝；Windows 原生占用证明待其独占后端接入，当前执行命令明确拒绝。

预览不备份或安装，显示固定版本、实际程序根、保留配置路径和是否继续原重装。确认 IPC 只接受 confirmationDigest，拒绝任意路径/版本/文件清单。摘要绑定 I/D/H、当前固定资源 pin/版本及原卸载或重装记录原字节，取得 I 的原生程序写者后再次核对；旧预览不能授权另一个原操作。安装/恢复预约、管理器更新排斥和数据绑定保护沿共同入口。

## 证据与可恢复事务

I/runtime/.reinstall-pending.json 绑定新操作 UUID、I/D/H、原卸载 marker 摘要、原 catalog revision、原 unresolved 来源后像摘要及固定新候选选择/资源摘要。只有明确已完成且有原登记的卸载才可开始；partial removal、另一 H/D、目录/登记/原证据漂移均拒绝。

原 .runtime-removed.json 与 image-admissions 整体通过不覆盖的原子移动，保存在 I/runtime/reinstall-history/<operationId>/removed.json 和 image-admissions/；不删旧证据。新镜像复用首次供应的 pin/归档/完整清单/链接实体化/镜像 builder，全量核验后只发布到不存在的版本目录；存在版本必须与同一原候选完整相符，未知文件和版本不覆盖。新 live 登记只接受同一原镜像；归档旧登记不被自动用来接管新镜像。

激活前保留同一原 activation.json，绑定原 unresolved 来源后像；每次继续都使用原字节，不能在源码漂移后生成新基线。激活复用既有 entry/current/runtime.json 的合法前后像和读回校验，补入一次实际安装历史，保留其它历史字段。I 的重装 journal 先于这些写入存在，普通启动/来源读取不能自动供应、继续、启动或绕道采用其它来源；普通激活恢复窗口不得接管重装内部的选择事务。

完整当前 config.json 备份和官方配置/目标锁贯穿执行，动作前后验证当前配置和备份未变；失败不补偿覆盖外部配置。归档、镜像、登记、激活准备/entry/current/record、完成回执等12个检查点可按同一原操作继续；最后保存 D/manager-state/runtime-reinstalls/<operationId>.json 再移除 pending。最终明确选择读回后才返回完成。
