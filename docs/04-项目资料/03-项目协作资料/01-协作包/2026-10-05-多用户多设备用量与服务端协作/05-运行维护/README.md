# 运行维护

状态：**未开始**，以下为候选运行要求。

| 观察 / 操作 | 目的 |
|---|---|
| 接收速率、拒绝 / 冲突、鉴权失败、限流 | 识别采集兼容或身份异常，避免只看 HTTP 成功率 |
| 队列积压、同步延迟、聚合水位、数据缺口 | 解释图表是否完整，区分设备未上传与后台处理迟缓 |
| 未计量 / 未定价比例、价格版本、来源版本 | 上游变化时及时暂停不兼容适配和修复口径 |
| 数据量、索引、查询延迟和 worker 重试 | 按实测决定分区、聚合与专用队列扩容 |
| 认证密钥轮换、设备 / 成员撤销、角色 / 所有权变更审计 | 维护个人 / 团队边界与最小权限，避免恢复旧成员权限 |
| 个人 / 团队分别授权的保留 / 删除任务、导出过期、去重标记 | 避免数据超期、已删数据复活或重复计数 |
| 备份与恢复演练 | 验证事件、来源身份、去重、删除与撤销记录的完整恢复 |
| 兼容矩阵复核 | OpenCodex 升级后验证字段、计价、历史读取和口径，而非仅检查进程能启动 |

日志不记录上传载荷和凭据；监控标签不使用任意用户输入，以免泄露信息或造成高基数问题。告警通道先用应用内通知，邮件 / Webhook 属于后续由用户配置的发送能力；本轮未向任何外部人员发送通知。

初期恢复目标可提议 RPO 24 小时、RTO 4 小时，但必须经备份演练与部署资源验证后才能承诺。删除 / 撤销日志需要独立于可能恢复的旧数据快照保存；恢复对外开放前先执行这些记录，不能靠恢复旧库重新启用旧密钥。

旧事件明细过期后，保留的汇总粒度会限制再分析和任意时区分桶，界面和导出应标明。备份中的删除何时完成也需明确说明；不能承诺一次前台删除就即时从所有离线备份物理消失。
