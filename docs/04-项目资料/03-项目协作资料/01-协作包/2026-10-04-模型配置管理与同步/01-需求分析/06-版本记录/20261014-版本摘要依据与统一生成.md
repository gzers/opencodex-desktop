# 版本摘要依据与统一生成

日期：2026-10-14。项目：opencodex-desktop。产品：OpenCodex 桌面管理器，模型配置管理与同步 0.2.0 候选原型。

用户确认版本摘要必须有实际依据，要求调整并增加原型标签。此前第三版“新增候选配置”按演示序号预填，人工保存按分区数量、Agent按建议标签、外部按执行类型生成，依据不统一。本轮替换为共用快照差异生成。

唯一入口：[产品主原型](../../../../../01-项目支撑资料/01-产品原型/原型/index.html#models) → 模型模版。

## 页面与保存路径

| 入口 / 位置 | 调整与依据 |
|---|---|
| 列表模版名下面的摘要 | 展示右侧所选保存版的冻结内容差异摘要，最多三项，更多显示另N项；tooltip保留全文，不按默认/采用/候选状态改变 |
| GPT演示版本 | 第一版按可信来源为内置基线；第二版实际改变可选及默认推理等级；第三版相对第二版只调整可选推理等级，不再显示新增候选配置 |
| 人工保存 | 读取基于保存版本的快照，与最终表单比较，生成字段事实；说明/名称/匹配/规则/型号变化按稳定顺序列出 |
| Agent更新保存 | 来源是任务冻结的保存版，比较实际接受后的最终内容，包含一并提交的人工编辑；不直接把建议条数当变更摘要 |
| 外部结果保存 | 全批先验证基准，再按实际保存版比较；只为有变化的修订/新建保存版本，无变化项在预览中说明并跳过，调用方不能自由提供摘要 |
| 首次/复制 | 无来源的用户首版描述首次创建事实；复制描述新身份及相对复制时快照的实际修改，复制来源的未保存状态已有元数据说明 |
| 来源与版本、版本历史 | 展示完整摘要；冻结来源身份与逐字段前后事实。来源普通版之后被允许删除，已保存摘要仍可解释 |
| ann-mp-10 | 举例说明比较依据、字段措辞、首版、复制、无变化与缺失依据、短摘要/全文和采用状态分离 |
| 多版本与清理场景 | 每条历史演示也按实际上下文差异生成摘要，不按序号填“历史调整” |

新增原型纯数据模块 model-template-summary.js，在主模块前加载；它不使用模版来源名、执行类型或采用状态猜测变化。对象键与集合排列规范化，稳定型号ID比较新增/删除/字段/顺序；字段设置/调整/恢复继承和型号规则数量都有前后依据。无变化不新增版本，无法证明的旧摘要明确显示变更依据缺失。

保存时记录版本名称用于解释当时差异，当前显示名仍按现有可变元数据处理；仅打开旧版不因后来改名制造未保存编辑状态。来源临时复制快照保存后移除，只留下复制元数据和摘要事实；不增加运行配置事实源。

权威规则写入[数据与状态 §6.5](../../../../../../02-项目核心/数据与状态.md#65-保存版本的变更摘要依据2026-10-14-用户确认)；接入说明见[交互细化](../02-方案草案/模型页交互细化.md)、[模版规则](../02-方案草案/模型模版与匹配规则方案.md)、[Agent与恢复](../02-方案草案/Agent制模与版本恢复方案.md)、[0.2.0实施范围](../../02-开发实施/README.md)。
