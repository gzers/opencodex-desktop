# 概览背景光场范围与原型对齐（含单层柔化性能修复）

2026-10-02。用户看实际制品后指出：概览背景光没有按之前定义的「扩大范围」做，原型已经是更大的光场，注意不要有波纹效果。承接 [IMP-05](IMP-OPENCODEX-DESKTOP-05.md) 的还原与配对装置。

## 1. 现象与根因

实测（无头 Chromium，1180×760，正文列宽 889）：

| 项 | 原型（hero 光场 iframe） | 软件（改动前） |
| --- | --- | --- |
| 光场容器 | `889×400`，`top:-75px`（＝正文列整宽） | `720×412`，`top:-94px`（**被限宽**） |
| 柔光团 A/B/C | `817.9×540` / `760×660` / `780×480` | `350×200` / `285×235` / `310×160` |
| 能量束 | `1280×840`、径向遮罩 | `500×270`、**无遮罩** |
| 近地光 | `380×12`、`top:250px` | `150×24`、`top:236px` |
| 光效层透明度 | 浅 `0.74` / 深 `0.48` | 浅 `0.6` / 深 `0.48` |

根因两条：

1. 软件用**视口单位 `vw`** 表达横向尺寸并给容器加了 `max-width: 720px`；原型那份光场跑在「与正文列等宽的 iframe」里，`vw` 就等于容器宽。于是软件的光团只做到原型约 40%，且窗口变窄时还可能被裁出硬边。
2. 能量束缺径向遮罩，放大后是硬边圆环（用户说的「波纹」）。

## 2. 修复

- **几何对齐**：`.motion-mark` 改为正文列整宽（`width:100%`、`top:-75px`、`height:400px`）；柔光团／能量束的横向尺寸由 `vw` 改为**容器百分比**（`min(92%,820px)`、`min(86%,760px)`、`min(88%,780px)`、`min(150%,1280px)`），纵向沿用原型像素值；近地光 `380×12`、`top:250px`；光效层透明度浅色 `0.74`、纵向渐隐 `10%/88%`；能量束补径向遮罩 `radial-gradient(ellipse, transparent 24%, #000 45%, transparent 72%)`。
- **性能修复（必要，否则撞 §7 预算）**：柔化 `filter: blur(28px)` 只加在容器 `.motion-ambient` 一层，不再在四个光团／光束上各做一次。四层大模糊合计约 2.4M 像素，高档持续动画下帧间隔 p95 51.3ms（超 `2B(33.4ms)`）；收敛成容器一层（可视区约 0.36M 像素）后 p95 25.7ms。光团本身是低频径向渐变，肉眼无差别。
- **回归守卫**：`qa/audit.browser.mjs` 概览用例新增 4 条断言——光场铺满正文列、柔化在容器（单层模糊）、光场纵向渐隐、能量束带径向遮罩。

## 5. 执行记录（2026-10-02）

### 5.1 取证与排查

- 先用无头 Chromium 读原型 hero 光场（同源 iframe 内）与软件光场的**计算样式**，得到 §1 的对照表——
  原型的光团尺寸是软件的约 2.3 倍，容器少 169px（软件被 `min(100%,720px)` 卡住）。
- 放大后 `audit:browser` 的「性能·档位动画-high」由 p95 23.6ms 掉到 **51.3ms**（超 `2B` 预算，可复现）。
  逐项做了 8 组对照实验（见 `evidence/performance.md`）：只减模糊、只停光束、只停光团、全停、
  全停+减模糊都不够；**柔化收敛到容器一层**回到 p95 25.8ms，且保留了光场尺寸与持续漂移。
- 用户提到的「波纹」定位到能量束缺径向遮罩：放大后是硬边圆环；补上原型同款遮罩后消失。
