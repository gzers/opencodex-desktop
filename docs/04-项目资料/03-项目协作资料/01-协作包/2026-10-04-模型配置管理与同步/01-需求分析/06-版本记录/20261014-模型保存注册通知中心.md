# 模型保存注册通知中心

日期：2026-10-14。项目：opencodex-desktop。产品：OpenCodex 桌面管理器，模型配置管理与同步 0.2.0。

用户指出模型页内出现了独立的“保存成功 · 待重启 Codex”进度卡，要求接入应用已有右上角通知。依据现有通知组件，模型保存使用窗口级 notifHost 的任务卡，并注册到通知中心同一实体；模型页不再自行绘制进度卡。

## 页面、事件与状态

| 位置 / 对象 | 本轮调整 |
|---|---|
| 模型页 #models | 移除 .mp-progress 进度卡及相关按钮；模型页继续展示业务状态框，保存事务状态由通知宿主承载 |
| 应用壳层右上角 notifHost | 模型保存进行中、保存成功待重启、失败、超时、停止和已核对均使用共享任务卡；右上角“收起到铃铛”沿用现有行为 |
| 右上角通知中心 | 新增注册事件 model.policy.save，投递 task + center；同一 operationId 更新一条模型保存通知，不重复堆叠。收起后可从通知中心恢复任务卡 |
| 保存成功 | 任务卡显示“保存成功 · 待重启 Codex”和校验、备份、写入、核对目录、发布成功快照五个步骤；待重启仍是独立状态，客户端未自动确认 |
| 保存失败 / 超时 / 停止 | 任务卡显示真实结果和“核对实际结果”入口；停止或收起不伪装成成功、不删除保存草稿 |
| 通知历史与清理 | 复用现有 read / resolved / deleted 三维度和软删除规则；最新保存替代旧终态时旧任务标记为已替代，不生成第二条持久任务 |

事件注册位于 maintenance-events.js，消费者为 modelSaveNotificationBridge。原型数据仍为内存 mock，不执行真实写入、重启或通知推送。
