## 3. 渠道改名的已确认合同

用户决定：直接改名，保存后重启生效；不需要旧标识兼容、旧别名保留或历史会话迁移。此前“仅改管理器label”及“先做显示名适配”的候选不再作为本项采用方案。界面须明确目标名称与对应运行标识；Krill-1改Krill时两者都更新到Krill，原始模型ID不改。

技术拆分属于既定结果的实现完整性，不是新增产品审批：

- 目标名称/运行标识在原保存预览中可核对，运行标识沿现有合法字符/长度与保留来源校验；无法直接用作标识的名称在原表单就地校验并允许明确目标标识，不静默用随机ID、自动后缀或覆盖同名渠道代替用户目标。完整配置及派生标识的占用须检查。
- 保留channel.id、节点ID、模版/型号采用及UUID凭据引用；更新布局中运行标识映射，重新读取仍是同一渠道。OAuth/forward及官方保留来源不能借改名脱离保护。
- 当前provider键、defaultProvider、modelPickerOrder、disabledModels、Agent执行选择/连接摘要等引用一并更新；原始型号含斜杠和相邻前缀按完整身份处理。provider归属的keychain引用及Key池需事务重绑，认证内容不变，不输出秘密值。
- 同时覆盖当前渠道保存与全页保存；不把其它渠道草稿一起提交。并发漂移、凭据/文件写入失败须回滚，取消不写；未知配置字段保留。协议派生分组按其稳定channel.id/协议身份核对，不误重建或遗留父provider引用。
- 同步/导入仍按稳定channel.id匹配，回归确认改名不变成新对象、不按名称错绑凭据。现有便携格式不携带源providerId、接收端保持本机连接；本项是本机当前配置直接改名，不声称已增加跨设备强制复制运行标识能力。

只读源码依据：ChannelEditor.vue:127；config_file.rs:477、514、897；config_file_mapping.rs:370、669、837、1188；provider_auth.rs:403；agent.rs:21；execution_directory.rs:282；transfer.rs:42、1653；protocol_groups.rs:148、409（路径均在apps/desktop对应目录）。现有只改label不改官方JSON的测试必须与新合同一起修订，不能只解除输入只读或提示重启就关闭本项。

## 4. 保存时间判新：数据合同和方向表

以下是对已确认“按保存时间取新”的技术落实；不能把未知时间补成现在，或把无法比较包装成云端新版。

保存版本至少绑定scopeKey、contentDigest、savedAt及timeKind。timeKind区分真实内容保存、仅历史mtime及未知；接收/复制继承原时间及来源性质。真实新对象或内容变更成功落盘时产生保存事实，失败、无变化保存、读取、打包、加密方式变化不推进时间。首次发现旧内容和外部文件仅有mtime时仍不得冒充可靠保存事件。本机revision只在本机范围内计数，不能跨端按大小排序。

同一所选范围的内容先比较；两个可靠时间按UTC时刻比较。首次、无共同基线、改范围、换连接及单侧/双侧变化都使用同一表，不靠“没有基线”固定下载。

| 内容/版本事实 | 方向与用户可见状态 |
| --- | --- |
| 两侧确实没有选中内容 | 无需更新。读取失败不算空。 |
| 远端确实不存在、本机有已保存内容 | 预览上传，保留来源时间。 |
| 本机确实为空、只有远端有选中内容 | 预览下载新增，保留来源时间；未知时间不代表本机为空。 |
| 所选内容相同 | 无需更新，不因打包字节、指针或时间不同而覆盖。 |
| 内容不同、两端时间可靠、本机较新 | 本机配置→云端，预览上传。 |
| 内容不同、两端时间可靠、云端较新 | 云端配置→本机，预览下载。 |
| 内容不同、同一时刻 | 无法判定，说明原因，不自动选新且确认更新不可执行。 |
| 时间缺失/无效/仅历史mtime、绑定不明或已知时钟异常 | 无法判定，不选云端兜底、不写；不新增强制用户选源弹窗。 |

来源版本只属于对应内容和覆盖范围；合并时范围外对象及其时间保持。预览、准备、确认使用同一合同，冻结连接/范围/本机内容版本/远端指针；任一改变重新比较或阻断，不沿旧预览写入。下载/导入备份、取消与范围外保护沿原已确认规则，整对象删除不扩入本项。

现有缺口：content_versions.rs已有摘要/时间记录，但继承路径同摘要仍可换时间；file_objects.rs:558/616/626仍在打包时取源文件最大mtime；config_remote.rs:605/670没有向方向判断提供可靠时间；sync_state.rs:234/242/246固定回退remote。旧sync_state.rs:684、config_remote.rs:2119测试须改为新决策反例，不能只改说明文案。

必须验证的具体链：本机11月4日/云端10月30日无基线上传及对称下载；双侧/单侧变化、改范围/换连接、旧快照重入；真实保存与迁移/mtime触碰分流；A→云端→B→再导出保时、同内容不改时；不同表示的同一UTC时刻、未知/坏时间真正禁用写入；检查后云端再保存的方向竞态；确认仅所选范围、取消无业务写入、再次同步无变化。使用双隔离根和测试传输，不接日常WebDAV。
