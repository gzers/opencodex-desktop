## 已确定的保存合同

| 入口 / 动作 | 写入范围与结果 |
| --- | --- |
| 详情编辑名称、协议、认证、Key、节点与已确认型号配置 | 进入当前内存编辑；不要求再确认连接，不写配置文件 |
| 型号行“加入草稿” | 只确认该行编辑到内存；保留已有字段校验，不视为文件保存 |
| 详情“保存” | **只写当前渠道**，不弹完整保存预览；成功后返回渠道列表，失败留在详情并保留输入 |
| 详情“返回渠道列表” / 切换渠道 | 不写文件；当前编辑保留 |
| 列表“保存” | 打开现有完整保存预览，确认后写入全部剩余修改；取消预览不撤销已保存的渠道 |
| 列表“还原修改” | 确认后只还原尚未保存的修改到最新文件基线；已完成的单渠道保存保留 |
| 无修改 | 对应范围的保存置灰禁用，旧点击事件也不能打开弹窗、产生通知或创建写入 |
| 保存成功反馈 | 现有全局通知提示“已写入”，提供“立即重启 Codex / 稍后”；沿已有铃铛，无页面底部结果块或持久待重启状态 |

仍坚持当前 config.json 为已保存事实源、内存为未保存编辑；不恢复旧磁盘草稿、保存计划准入或客户端加载核对。文件允许站点的精确原始型号，连接检测或获取模型清单失败不能阻止合法的离线编辑保存。

## WP-85：连接区直接编辑，删除重复的局部操作

源码依据：ui/src/features/models/ChannelEditor.vue 的 connectionOriginal、connectionChanged、resetConnection、discover 和 channel-config-footer。连接字段已直接编辑内存，但界面仍保留“确认连接与模型／还原配置”和“尚未加入草稿”文案。

- [x] 删除连接区“确认连接与模型”“还原配置”，以及该区重复的待确认连接提示和占位。删除无用途的局部还原快照、方法、监听与样式。
- [x] 名称、协议、认证、Key 直接进入当前编辑；修改、切换和返回不需要额外的连接确认。保留只读渠道标识。
- [x] “获取模型列表”只留在模型列表；连接检测与切换只留在服务节点。保留请求取消、错误说明和晚回保护，不因删除按钮而删掉实际获取清单能力。
- [x] 已有 Key 掩码加载、眼睛显隐、空输入保持、明确清空继续有效；只改 Key 可离线保存。检测使用当前明确输入，同时保留来源与服务地址绑定，不因展示旧 Key 而擅自向新地址发送。
- [x] 全局“还原修改”仍在列表。详情侧栏按原型只保留保存，不再提供会还原所有渠道的模糊局部入口，不重复铺设保存状态行。

## WP-86：详情只保存当前渠道，成功返回列表

源码依据：ui/src/features/models/ChannelsView.vue 的详情 @save 与列表共用 prepareSave / confirmSave；确认时发送完整 channelDraft 和全部 credentialEdits。store.ts 的 acceptTransfer 会替换全渠道草稿、清空所有 Key 意图。tauri/src/modules/model_config/config_file.rs 的 save 与 record_layout 接收完整策略。**不能只跳过弹窗而保留这些全局提交与重置行为。**

- [x] 为同一文件保存服务明确区分“当前渠道”和“全部剩余修改”的提交范围；后端按实际文件及期望摘要构建候选，不以完整内存草稿隐式扩大单渠道范围。现有写入器接收完整策略，不能把只含 A 的渠道数组当局部补丁传入而误删其它渠道；沿用完整请求时，以完整已保存策略为底只合入 A，并限定凭据及导入范围。
- [x] 单渠道提交包括其名称、连接、当前节点、节点元数据、启停、选择、渠道规则、已确认型号覆盖、精确采用关系、原始型号顺序和该渠道明确的凭据意图。其他渠道、未修改未知字段及原有秘密保持。
- [x] 详情保存不提交全局渠道顺序、全局采用关系、其他渠道的新增/删除/启停或 Key。新增渠道只加入当前对象，并保留既有渠道的保存顺序；渠道内顺序按当前编辑写入。
- [x] 预算和校验针对“当前已保存文件 + 本次渠道改动”的实际候选：不得借用另一渠道未保存的停用来放行，也不能因另一渠道未提交的超限编辑挡住有效的当前保存。仅当前渠道的待确认型号行限制本次提交。
- [x] 成功后更新真实文件快照与摘要、当前渠道的清洁基准，仅消费该渠道本次已写入的凭据/导入意图。其他渠道的名称、Key、节点、型号缓冲、模版缓冲、全局顺序及未保存新增/删除原样保留，继续基于新文件保存。
- [x] 复核 ChannelEditor 的文件摘要监听：保存 A 引发文件基线更新时，不能清除 B 的 Key 输入；恢复值时同步恢复 replace / clear 意图与 keyExplicit，读取失败分支也不能丢意图。保留 keySequence 过期响应保护；后续输入不被旧响应覆写或误标已保存。
- [x] 布局元数据与实际提交范围一致，不能把未提交渠道/节点/采用关系写成已保存布局，也不能丢掉其它渠道已存布局。record_layout 在文件 changed=false 时也会执行，仍需范围保护。保留写锁、写前备份、原子写入、外部文件冲突保护；备份/保存记录必须对应实际 before / after。
- [x] 成功后回到渠道列表并恢复合理的列表位置；保存中留在详情并防重复提交，失败或取消保留详情与输入。若当前页面已切换，晚回不得强制导航回别的渠道。
- [x] 导入采用后的渠道仍能用详情单独保存，未提交的其他导入候选及凭据引用保留。显式历史恢复沿已有独立流程，不把单渠道成功冒记为整份恢复完成，不新增恢复确认页。

## WP-87：保存禁用与状态按入口范围统一

源码依据：ChannelsView.vue 当前将 models.channelDirty / 全局 pendingRows 作为详情状态，详情与列表保存禁用条件未完整包含对应范围的“无修改”。ChannelEditor.vue 的状态作用域仍标为 all-channels。

- [x] 详情“未修改／未保存修改”只反映当前渠道；列表状态反映全部剩余修改。A 已保存、B 未保存时，重开 A 为未修改、列表仍为未保存修改。
- [x] 列表与详情无修改时保存置灰禁用；只读官方渠道按既有能力禁用。鼠标、键盘和直接触发旧处理器都不能绕过；不得为无修改点击新增“未保存”通知。
- [x] 修改恢复原值、成功保存、全局还原和只读取现有渠道后正确回到禁用；只修改 Key、明确清空 Key、明确采用的导入原字段等真实差异不能漏判。
- [x] 型号行缓冲按渠道保持归属，复核 ChannelEditor 初始化捕获 rowState 的行为；切换渠道不得复用别的渠道缓冲。脏状态、按钮可用性与差异范围共用规范化比较（canonicalPolicy 及明确凭据/导入意图）；不把读取回执、检测结果、行展开、搜索、选中或眼睛显隐算作文件修改。
- [x] 若已打开列表预览后又改回原值，保留最终确认的无变化守卫；仍有未确认型号或校验问题时保留具体原因，不用“无修改”掩盖未处理输入。
- [x] 成功更新基线后，列表再次保存只提交剩余内容；取消列表预览、还原剩余修改或重开详情都不能撤销此前的单渠道保存。

## WP-88：通知材质与原型一致，正确提供预览依赖

**证据边界：**用户看到的全透明通知发生在本机原型预览。已确认原因是预览服务根目录未包含上层 glass-tokens.css / glass-components.css 等资源，背景变量失效。原型已修正服务路径并增加沿原配方的兜底；这不等于已证实软件 0.2.15 也有同一故障，不安排无依据的通知系统重做。

- [x] 以总原型的共享 glass-tokens.css 为依据，对照软件现有通知变量、CSS 入口及打包依赖，补真实缺口；保持现有字号、圆角、按钮顺序、阴影与铃铛位置。
- [x] 正常亮暗主题中，运行中与保存终态卡均有可读底板；保留原玻璃配方，既不全透明，也不擅改为纯白新卡。原型标准档浅色填充 rgba(244,245,249,.52)、深色 rgba(34,36,42,.56)，模糊 saturate(1.5) blur(8px)；低特效档沿原配方降级。
- [x] 保存结果只在已有全局通知宿主反馈；“立即重启／稍后”、聚焦、收起和铃铛行为保留，不新增任务聚合入口、状态卡或页面底部占位。
- [x] 原型预览必须提供父目录共享资源，检查其实际 HTTP 加载成功；不能只看页面能打开。对照软件时使用相同主题、窗口和特效档。
- [x] 保留配对截图和计算样式/真实界面证据；生产缺陷与预览服务问题分开记录，不能用 mock 通知代替软件的实际保存反馈验收。

## 必做验收场景

以下14场景已完成本轮规定范围验收，实际证据与平台边界见 [矩阵](../../../../.adg/evidence/0.2.16/acceptance-matrix.json)。真实文件验证使用隔离配置，不改用户日常配置，不把重启活跃 Codex 当作普通保存验收步骤。

| 场景 | 必须证明的结果 |
| --- | --- |
| 1. 新开列表/详情、读取现有渠道但未编辑 | 保存置灰；旧事件不打开预览、不写文件、不记通知/历史 |
| 2. 名称/Key/型号修改后恢复原值 | 对应范围恢复清洁与禁用；检测和查看不制造脏状态 |
| 3. A 修改后返回，再修改 B 并在详情保存 | B 真正写入并返回列表；A 未写入，名称/节点/Key/型号编辑均保留 |
| 4. 单渠道保存后重开两渠道 | B 清洁并读到实际文件值；A 仍脏，列表仍显示剩余修改 |
| 5. 随后列表保存、取消或还原剩余修改 | 完整预览范围正确；取消/还原只影响未保存内容，不撤销 B |
| 6. 只改 Key、空输入保持、明确清空、离线或清单失败 | 真实文件与重新打开结果正确，凭据不进入公开日志、预览或证据 |
| 7. 另一渠道有待确认型号，或存在超限草稿 | 只约束实际提交范围；保留其缓冲；不能借未保存停用绕过本次预算 |
| 8. 多个待新增/删除渠道、全局排序和全局采用尚未保存 | 当前渠道单独提交，不顺带增加/删除其它对象或写入全局设置；定义好的型号内部顺序保留 |
| 9. 保存期间输入、切换页面、连续点击与旧响应晚回 | 不重复写入，不清后续输入，不错误导航，基线/清洁范围准确 |
| 10. 备份失败、写入失败、取消、外部文件冲突 | 原文件和全部编辑保留；失败留在详情；如实通知，无新核对流程 |
| 11. 导入采用、模版采用、显式历史恢复 | 与单渠道保存范围不混淆；精确版本/未知字段/凭据引用和必要候选保留 |
| 12. 亮暗、低/高特效、窄窗与表格行 | 与原型配对核对，表格控件垂直居中且不拥挤；成功通知不透明失底，无多出两行状态 |
| 13. Windows WebView2 与 macOS 对应引擎的实际保存/重开 | 使用真实文件写入接口验证；源码通过、浏览器 mock、原生包结果分别记录 |
| 14. 正式发布（实施完成后） | 完整相关回归、双平台 CI/制品与安装器、三个更新包签名及公开/stable manifest 验证；版本/清单/长期事实按实际回执回写 |
