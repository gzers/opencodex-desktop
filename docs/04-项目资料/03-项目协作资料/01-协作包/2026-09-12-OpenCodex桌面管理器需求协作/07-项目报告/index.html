What it is

这个项目是什么

一句话：把 OpenCodex 日常要敲的命令、要另开终端看的状态，收进一个 macOS 桌面应用，同时不改变 OpenCodex 自己的行为和权威。

产品身份

独立产品

仓库标识 opencodex-desktop，界面展示名 OpenCodeX-Desktop。与 OpenCodex 官方项目没有隶属、授权或背书关系。

技术选型

Tauri v2 + Rust

桌面壳用 Tauri v2，后端 Rust，前端是渲染在 WebView 里的 Web 界面。第一阶段 macOS 优先，跨平台只做抽象预留，不算首期验收范围。

许可

MIT

本项目代码与素材用 MIT。官方素材（页面快照、界面截图、标识）不随仓库分发，只在本地保留。

为什么反复强调“不改变官方权威”：更新、provider、路由这些 OpenCodex 已经有官方通道的能力，本产品只做引导和展示，不自己再实现一套。唯一能写的是扩展配置，见「范围与能力」。
Problem

它解决什么问题

麻烦的地方不在单条命令，而在于这些事散落在终端、配置文件和多个客户端之间。

现在

  • 启停要敲 ocx start / stop / restart
  • 状态和日志得另开一个终端看
  • 配置导出、跨机同步没有图形入口
  • Skills 和 MCP 要手工改好几份客户端配置
  • 出问题只能自己翻日志、翻环境

装了它之后

  • 一个窗口里点启停，直接看到健康、端口、PID
  • 日志和诊断中心并排看，敏感值自动打码
  • 配置导成加密容器，走 WebDAV 同步，覆盖前先备份
  • Skills / MCP 统一管一次，再分发到六个客户端
  • 出问题给原因和建议动作，不甩一个红点
Bottom line

现在能做什么、不能做什么

现在能做的

  • 打开原型点一遍，看界面结构和状态分支
  • 看架构图、状态模型和 10 张流程图，对齐理解
  • 改需求和契约——这一步改成本最低

现在还做不了的

  • 安装使用：没有可运行的应用
  • 连真实环境：原型用的全是 mock 数据
  • 开工写代码：实施契约（IMP）还没创建
顺序上的一个硬约束：先定稿「项目核心」这五份事实，再创建 IMP 冻结契约，然后才拆实施任务。跳过中间一步直接写代码，后面返工概率很高。
