## 为什么做这一版

0.2.10 装机后，用户在「核对 Codex 客户端加载」里被红字挡住：「已有保存计划待核对，请先核对原计划或撤回其未完成写入」。实测确认：

| 路径 | 结果 |
| --- | --- |
| 点通知 → 重新检查 | 失败：当前运行态与那次期望不一致 |
| 点通知 → 撤回未完成写入 | 失败：`compensation_drift`（保护用户后来的修改） |
| 删 `manager-state` 文件 | 能解，但要用户手工删文件 |

即：**要求用户处理一个界面无法收口的对象**。

## 实施（四态一条线）

| 状态 | 出口 |
| --- | --- |
| ① 未保存修改 | 保存 → 预览 → 确认保存 |
| ② 正在保存 | 无（等待） |
| ③ 已写入 · 待重启 Codex | 我已重启，检查 |
| ④ 未完整写入 | 重新检查 / 撤回本次未完成写入 / 放弃这次 |
| 完成 · 客户端已确认 | 终态 |
| 已放弃这次 | 终态 |

## 代码要点

| 层 | 改动 |
| --- | --- |
| `client_state::check()` | 去掉全库 `reject_incomplete`：无关旧计划不再挡住本次核对 |
| `runtime::abandon()` | 新终态 `abandoned`：prepared 拒绝、已终态幂等、进白名单、过滤 `latest()`、`history()` 可见但不可恢复、继续参与版本保护判定 |
| 命令 | 新增 `model_policy_abandon` |
| 前端 | `partialPlan` 第 ④ 态唯一判定；`driftBlocked` 识别漂移拒绝；三出口 |
| 夹具 | `?partialSave=1` 可复现第 ④ 态 |

## 边界

- 未改真实保存事务；写入 / 备份 / 核对 / 回滚时序与 0.2.10 相同。
- 核对判据仍是「运行目录 vs 那次写入内容」；用户改过配置时会如实报不一致。
- 触屏与 Windows WebView2 实屏未复核。
