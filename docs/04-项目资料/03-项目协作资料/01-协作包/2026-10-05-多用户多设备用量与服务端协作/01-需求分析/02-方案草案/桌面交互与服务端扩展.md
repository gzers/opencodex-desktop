# 桌面交互与服务端扩展（候选）

团队已按用户补充纳入首期，角色和历史策略见 [团队模型](团队与数据权限模型.md)。

## 1. 服务端与账户设置

在 Desktop 设置增加“服务端与账户”分区。首次未配置显示用途说明和“连接服务端”；本地模式仍可继续使用。

| 区域 | 用户可见内容 / 操作 |
|---|---|
| 服务地址 | HTTPS 地址、站点名称、测试连接；发现不兼容、证书或实例变化时给出明确原因 |
| 账户 | 打开系统浏览器登录；显示当前站点和账户，提供退出登录 |
| 团队与空间 | 我的团队、创建 / 接受邀请入口；显示当前角色；用量来源明确归个人或某个团队 |
| 本设备 | 默认系统设备名，可修改；另可复制只读设备编号供排查；设备仍归个人账户 |
| 用量同步 | 用户开启；解释上传字段、可见人员和历史范围 |
| 同步范围 | 默认“从现在开始”；“导入历史”单独预览日期、记录数和归属；不可采集时说明限制 |
| 同步状态 | 最后成功同步时间、待同步数量、数据缺口、失败原因；重试 / 暂停 |
| 数据管理 | 查看个人导出 / 删除任务和服务声明的保留时间 |

首次使用流程：填地址 → 测试并识别站点 → 浏览器登录 → 查看账户和设备名 → 选择个人空间或创建 / 加入团队 → 为该空间选择明确归属的本地来源 → 查看上传范围并开启同步 → 首批成功后进入“我的全部设备”报表。

登录成功不等于已经开启用量上传。导入历史显示将上传的字段和归属账户；不能只给“继续”按钮隐式认领整本共享账本。用户自定义的是显示名，稳定 ID 无需常规编辑。设备名可能含真实姓名，登记前提供修改入口。

## 2. 用量页面

顶层“用量”提供 **本机、我的全部设备、团队** 范围；团队范围再选团队。普通成员看本人在该团队的用量，团队管理者可看全体及成员聚合。未连接服务时展示本机和接入入口。本机继续可使用官方能力，跨设备由新服务提供；来源、时间范围、时区和数据更新时间在页面可见。不要把 `ocx usage` 的 client 模式结果误标成本机来源。

| 内容 | 首期展示 |
|---|---|
| 总览卡片 | 请求记录数、输入 / 输出 Token、估算费用、计量覆盖；逻辑请求有可靠身份时补充显示 |
| 筛选 | 时间、时区、个人 / 团队空间、设备、surface、渠道 / 模型；团队管理者另可筛成员 |
| 趋势 | Token / 费用随时间变化，缺口区间有标记 |
| 分布 | 按设备、模型、渠道的占比与表格；团队视图用团队范围设备别名，成员分布仅管理者可见 |
| 数据质量 | 已同步至何时、多少记录未计量 / 未定价、哪些设备有采集缺口 |
| 费用说明 | “估算 USD”、价格版本、未定价数量；不把订阅用量等同供应商现金账单 |
| 导出 | 本人有权读取的筛选结果，或管理者有权读取的团队聚合；异步进度和下载时再次复核成员身份 |

例：A 笔记本上午离线，B 台式机已经上传，则“全部设备”显示 B 的最新数据和 A 的同步时间；不会把 A 显示成今日真实用量 0。A 补传后按原发生时间更新趋势。

“数据最后同步于 10:20”只表示最后成功活动，不能据此断言设备现在在线。需要实时在线能力时另设计心跳和超时定义。

## 3. 设备管理

“我的设备”显示设备名、平台、Desktop / OpenCodex 版本、来源所属空间、最后同步、同步状态和历史用量入口；这不是对团队公开的私人设备目录。改名即时影响名称，统计身份保持一致。首期支持归档、撤销上传授权；“删除历史”是单独动作，需展示影响范围。

重装会出现新的设备记录，可提示归档旧设备。不要因为两台机器同名就自动合并，也不要因为系统名变化就新增设备。恢复 / 克隆时先确认来源谱系；无法核对的旧历史不进入自动导入。

换账号流程要显示旧账户仍有多少待传数据。选择保留封存或明确丢弃，之后也只允许原账户恢复上传；新账户不能一键接管旧队列。首期已有账本来源不转属，B 需要自己的独立运行配置 / 来源。

## 4. 团队与管理员页面

增加“团队”入口：创建 / 加入团队、成员角色、邀请状态和退出。所有者可任命管理员、转移所有权和解散；管理员可管理普通成员及查看团队 / 成员聚合；普通成员默认只看本人团队用量。权限按当前有效成员期确定。

团队上下文切换默认影响查看范围，不自动改变正在采集的来源归属。若用户要改后续调用的归属，需要切换绑定到目标空间的来源 / profile；首期能力不足时明确显示“当前来源归属团队 A”，不能给出看似生效的空切换。旧队列始终保留原空间。

成员退出后，团队历史留团队，退出者不能继续从服务访问原团队明细；个人空间和其他团队不受影响。尚未上传的团队记录封存待处理，不偷偷算成个人用量。

### 站点管理

建议由服务器提供独立 Web 管理页面：全站总量、趋势、模型 / 标准供应商类别分布、活跃用户 / 设备数量及同步健康。“活跃”按报表时窗内有有效事件定义，不能与当前在线混用。用户目录用于邀请、停用、角色和设备管理。

站点管理统计只提供全站聚合，普通用户看不到全站；团队管理者的成员聚合权限仅在本团队生效。站点管理员不默认获得个人 / 团队事件导出或具体团队钻取；如后续需要，新增清晰权限和审计。全站数字来自客户端报告及已接收范围，不能作为防作弊计费账本。

## 5. 服务端功能扩展及价值

| 优先级 | 功能 | 用户价值 | 前提 / 代价 |
|---|---|---|---|
| P0 | 账户、团队 / 成员 / 角色、设备、个人 / 团队 / 全站统计 | 多设备统一视图，个人与团队数据分别授权 | 本包首期闭环 |
| P0 | 同步健康、个人导出 / 删除、凭据撤销 | 知道数据是否完整，换机和停用可控 | 纳入首期交付 |
| P1 | 个人 / 团队日月预算提醒与周期报告 | 及时发现费用增长，减少手工查表 | 基于估算和已同步数据；提醒可去重、阈值可配置 |
| P1 | 模型 / 渠道比较 | 看成功率、重试、首输出延迟、吞吐、缓存与成本变化 | 需足够样本、统一口径；不从用量数字推断回答质量 |
| P1 | 配置与模型模版版本同步 | 新设备快速获得相同工作环境，可比较 / 恢复版本 | 对齐已有模型方案；版本依赖、冲突、备份、应用前预览 |
| P1 | 可恢复备份与设备迁移 | 换机少配置，恢复时保持来源谱系 | 先同步非敏感偏好 / 模版；凭据另定加密和恢复边界 |
| P2 | 团队内项目与配额报告 | 在已有团队空间内区分项目投入 | 团队是首期核心；项目标签后续加入，不能从路径自动泄露项目信息 |
| P2 | 受控 Skills / MCP / 模版共享 | 统一工具配置，减少重复安装 | 内容来源、版本、权限说明，本地预览 / 确认后应用 |
| P2 | SSO、组织审计、成员生命周期 | 企业账户统一开通 / 停用 | 身份供应商和组织权限独立验证；个人部署可不启用 |
| P2 | 版本兼容检查和设备健康 | 提醒客户端 / 采集协议不兼容、上游版本问题 | 自愿上传最少版本信息；现有更新机制继续核验签名 |
| P2 | 用户主动提交诊断包 | 更容易定位同步或设备问题 | 先本地脱敏和预览，明确一次性授权及过期清理 |
| 单独立项 | Hub 统一路由 / 上游凭据托管 | 集中接入和资源管理 | 影响模型流量与密钥托管，需另立安全 / 可用性契约 |
| 单独立项 | 远程任务执行、提示词 / 会话同步 | 可能支持自动化和跨设备上下文 | 权限与内容风险明显扩大，不随“有服务端”自动启用 |

**最值得优先扩展的是预算提醒、质量与成本分析、配置 / 模版同步。** 它们能直接利用账户与设备基础，又与 Desktop 的日常使用连接紧密。

预算提醒是提示性能力：离线设备未上传、供应商未上报或模型流量绕过 Hub 时，服务器无法可靠地执行“达到预算立即停止”。若要求硬限制，必须由所有流量必经的执行 / 代理层实施，并处理并发预占、失败回滚和各计费方对账；不能在统计服务里只加一个阈值就声称做到。

配置同步适合与现有 WebDAV 并列为另一后端，但用量事件和配置版本分别管理。不得把一份原始运行配置上传给所有用户，也不自动下发供应商 API key。模型模版 / 策略继承正在独立设计，服务端只在结构冻结后承接版本存储。

2026-10-05 团队共享的进一步需求已由 [团队配置发布订阅与模块组合](../../../2026-10-05-团队配置发布订阅与模块组合/README.md) 独立承接，包含模型体系、Skills、MCP、模块选源与本地保留。上文“另一同步后端”继续描述个人多设备同步；团队发布订阅另有内容所有权、源授权与版本采用规则，不能直接套用个人双向同步。它复用本包团队身份，但不要求开启用量上传，也不改变用量空间归属，具体版本未定。

## 6. 文字走查场景

| 场景 | 期望体验 |
|---|---|
| 个人两台设备 | 同一账号登录，各取默认名字；全部设备立即列出两个稳定身份，历史按来源补齐 |
| 团队多用户 | 成员看本人授权用量，团队管理者看本团队 / 成员聚合，站点管理员看全站；个人空间不自动共享 |
| 一人加入两团队 | 各事件只有一个空间；我的视图可合并授权范围，全站按唯一事件统计不重复 |
| 离队时尚未同步 | 暂停该团队队列并说明去向；个人和其他团队同步继续，历史不自动改归属 |
| 服务器离线 | 显示“等待同步”和待传数量；用户照常调用本地模型；恢复后补传不重复 |
| 服务域名指向全新实例 | 显示服务身份变化，重新登录和选择同步范围；不把旧队列静默发过去 |
| 自定义设备名 | 改名后历史连续，设备数不增加；相同名称仍按设备编号区分 |
| 未知价格 / 上游未上报 | 显示未定价 / 未计量，卡片不把它们填成零费用 / 零 Token |
| 登录另一账户 | 清楚展示旧队列归属；为新账户选独立来源，不接管旧历史 |

本轮未修改共享原型；后续补绘只需覆盖连接、登录、团队加入 / 角色 / 退出、设备与空间登记、三层用量和同步异常的关键流程，再按阶段加入管理端和扩展功能。
