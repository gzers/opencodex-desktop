## 1.1 版本规范

- **格式**：`主版本.功能版本.补丁`（`x.y.z`）。
- **含义**：**主版本** = 不向后兼容的大改动；**功能版本** = 向后兼容的新功能；**补丁** = 向后兼容的缺陷修复。
- **阶段口径**：当前处于**内部测试阶段**，版本保持 `0.x.y`（前导 `0` 表示尚未达到稳定公开版）；`y`（功能号）随成批功能递增、`z`（补丁号）随缺陷修复递增。达到稳定、准备正式公开时发布首个 `1.0.0`。
- **载体（三处必须一致）**：`apps/desktop/tauri/tauri.conf.json`、`apps/desktop/tauri/Cargo.toml`、`apps/desktop/ui/package.json`；「关于」页展示该版本，应用自更新的通道与官方 `ocx` 完全独立。
- **当前值**：`0.1.0`（内部测试起点）。
- **来源**：2026-09-27 用户决定（开始为本软件定义版本；内部测试阶段使用 `0.x.y`）。

## 2. 一句话定位

**opencodex-desktop** 是一个面向 OpenCodex 的**独立桌面管理器**：把命令行里的安装发现、进程启停、状态观测、日志诊断、配置迁移、同步与扩展管理，收进一个图形界面。

## 3. 要解决的问题

OpenCodex 的日常使用依赖命令行：启动与停止要敲 `ocx`，状态与日志要另开终端看，配置迁移和跨机同步没有图形入口，Skills 与 MCP 这类扩展配置要手工改多个客户端的配置文件。

opencodex-desktop 把上述操作收敛到一个桌面应用里，同时**不改变 OpenCodex 自身的行为与权威**。

## 4. 目标使用者

| ID | 使用者 | 典型诉求 |
|---|---|---|
| `USER-01` | 日常使用者 | 点一下就启停、一眼看到是否健康、出问题能看到原因 |
| `USER-02` | 排障使用者 | 只读日志与运行环境诊断、快速定位启动失败或外部接管 |
| `USER-03` | 多机 / 多环境使用者 | 导出配置、经 WebDAV 同步、覆盖前有备份可回退 |
| `USER-04` | 多客户端使用者 | 统一管理 Skills 与 MCP，并分发到多个客户端 |
| `USER-05` | 脚本与 AI 代理 | 经可选 CLI 控制面以机读方式驱动管理器自有域能力 |

## 5. 产品边界

### 5.1 做

| ID | 内容 |
|---|---|
| `IN-01` | 发现并校验本机已有的 OpenCodex 安装（npm 形态） |
| `IN-02` | 托管官方 `ocx start / stop / restart` 子进程，观测状态、端口、进程标识与最近错误 |
| `IN-03` | 提供日志、运行环境诊断与通知中心，并嵌入官方 Web 面板视图 |
| `IN-04` | 加密的配置导出/导入，以及经 WebDAV 的加密同步 |
| `IN-05` | 统一管理 Skills 与 MCP 扩展配置，并分发到多个客户端 |
| `IN-06` | 区分 OpenCodex 本体升级与应用自身更新两条通道 |
| `IN-07` | 提供托盘、macOS 原生菜单，以及默认关闭的可选 CLI 控制面 |
| `IN-08` | 把官方包 `@bitkyc08/opencodex` 安装到**自有数据根内的私有前缀** `runtime/opencodex/`（联网安装或离线 `file.tgz` 导入），并卸载**任意已解析来源**的安装（托管包体应用直接移除、外部包体应用代执行官方卸包命令、完整卸载由应用调用官方 `ocx uninstall`）；解析并展示**运行来源**（用户显式指定 > 托管安装 > 自动发现候选） |

### 5.2 不做

| ID | 不做的事 | 原因 |
|---|---|---|
| `OUT-01` | 重写 OpenCodex 核心、绕过官方 API | 复用官方能力，不制造第二套实现 |
| `OUT-02` | 管理**全局** npm 前缀、依赖解析代理、写系统目录 | 托管安装只写自有数据根内的私有前缀（`IN-08`），不碰系统目录与全局前缀 |
| `OUT-03` | 替代官方 `ocx update` 的更新事务；自行删除官方 service / shim / config | 更新与卸载权威属于官方，本产品只做前备份、确认与引导执行 |
| `OUT-04` | 安装或管理 launchd | 启停由本产品直接托管子进程完成 |
| `OUT-05` | 接管 `codex-shim` | 官方能力若需依赖 shim，另行建需求确认 |
| `OUT-06` | 写入 provider、路由、模型映射等 OpenCodex 核心运行配置 | 该类变更一律走官方 CLI，本产品不提供写入通道 |
| `OUT-07` | 自动覆盖外部 provider 托管的配置 | 只检测、解释，并在用户确认后引导官方 `restore` |
| `OUT-08` | 明文迁移或同步凭据 | 凭据必须进加密容器或加密后上传 |

### 5.3 唯一例外：扩展配置可写

`IN-05` 的写入对象是**扩展配置**：MCP 配置节点与 Skills 目录同步。除此之外的一切 OpenCodex 配置仍不可写（`OUT-06`）。

例外范围、允许写入的客户端清单与写入事务规则见 `集成与安全边界.md`；涉及字段见 `领域模型.md` 的 `McpServer`、`ClientTarget` 与 `Skill`。

## 7. 产品原则

| ID | 原则 | 含义 |
|---|---|---|
| `PR-01` | 官方权威优先 | 凡官方已有权威通道的（更新、provider、路由），本产品只做引导与展示 |
| `PR-02` | 可回退 | 任何可能覆盖数据的动作，先备份、可定位、可校验、可恢复 |
| `PR-03` | 状态如实 | 能力不可用时明确说明，不伪造空成功状态 |
| `PR-04` | 敏感值默认掩码 | 凭据类数据默认不可见，且不进入日志与错误信息 |
| `PR-05` | 不静默覆盖 | 检测到外部改动或冲突时，停止并交给用户决定 |
| `PR-06` | 动作按状态渲染 | 不渲染无解释的禁用按钮；原因说明按性质分流（需关注 → 持久通知，稳定事实 → 一次 Toast，瞬时进度 → 不写），**概览状态卡只放事实与动作**（`UI规范.md` §19） |

> 原则的落地位置：`PR-01` 见 `能力地图.md` 各域的禁止项；`PR-02` / `PR-03` 见 `数据与状态.md` 与各流程状态链；`PR-04` / `PR-05` 见 `集成与安全边界.md`。
