# 独立配置存储与事件订阅适配方案

状态：**独立协作包的讨论草案；版本未定，开发时机未定，尚未实现**。日期：2026-10-11（Asia/Shanghai）。

用户要求分析独立配置文件的必要性，结合 0.1.10 规划说明存储、订阅和实施结构；订阅是否需要、如何安排，由方案根据可行性、易用性和操作合理性提出建议。本文承接 [对话配置与实时生效方案](Codex对话配置与实时生效方案.md) 和 [逻辑与可行性审计](../03-确认与评审/20261011-方案逻辑与可行性审计.md)。适配 0.1.10 底座不代表本功能纳入 0.1.10 交付。

## 1. 建议结论

1. 按用户后续建议，将全局、项目、thread 策略分层存储：全局文件保持小型；每个有覆盖的项目使用独立目录及项目文件；对话有专属覆盖时才创建独立文件。搜索与子 Agent 同层设置保存在同一份作用域文件中；命名模型仅全局，不进入项目或对话覆盖。
2. 本机 Codex 数据源连接信息单独保存；执行状态和任务去重单独保存；项目 / 对话列表作为可重建缓存。这样用户配置、设备绑定、历史状态的备份与清理边界清楚。
3. 配置变化事件与实际 Codex 生命周期事件是必要的接入能力；定时检查只是事件不足时的补充。首批采用事件、进入页面及窗口恢复后的到期刷新、手动刷新即可，不强制增加周期任务。
4. 保存策略立即更新界面；实际模型、搜索或 child 配置按执行端真实读取点采用。保存成功、执行端接收、实际观察到采用分别展示。
5. 复用 0.1.10 的活动数据根、写者准入、原子文件写入、事件注册、反馈和备份格式；需要扩展的能力明确列出，不把更新专用定时器当成已经完成的通用任务系统。
6. 项目确认删除、对话确认归档 / 删除后，自动清理对应配置、状态和派生资源。取消归档后恢复继承，不自动还原已清理的对话覆盖；外部变更在连接恢复或按需校准时补处理。
7. 按用户明确要求，WebDAV 默认不包含本包对话配置，覆盖全局、项目和 thread 三级；手动导出、本机备份与 WebDAV 同步范围分别选择。
8. 项目与对话内容也应支持导出，并可与关联配置联合打包。日常配置文件仍不保存正文；可阅读记录与原生可恢复载荷区别呈现，详见 [项目与对话联合导出及恢复方案](项目与对话联合导出及恢复方案.md)。

本次布局修订替代此前“全量作用域统一写入一个主策略文件”的建议，原因是项目与对话数量增长后的文件规模、局部保存和清理需求。该方向已由用户提出；具体文件名及执行契约仍待实现时确定。

Windows 默认使用 `<实际安装目录>\data`，macOS 默认使用 `~/Library/Application Support/com.gzers.opencodex.desktop`；已有活动根 / 自定义根优先。这里的路径是目标规则，不表示用户当前目录已经迁移。原生 `CODEX_HOME` 与管理器 / OpenCodex 数据根各自独立，允许选择外置 Codex 数据源。

| 文件 | 保存内容 | 不保存的内容 | 生命周期 |
|---|---|---|---|
| `codex-collaboration.json` | schema、布局版本、文件身份与 revision、新增全局行为 | 全量项目 / thread 列表与覆盖、模型目录副本、API key、官方全局字段的无来源副本 | 全局用户事实；备份，清缓存不影响 |
| `projects/<project-key>/project.json` | source / project 身份、文件身份与 revision、本项目搜索 / 子 Agent 覆盖 | 全量 thread 覆盖、全局配置副本 | 项目用户事实；恢复全部继承时可删除该文件，项目确认删除时清理目录 |
| `threads/<thread-key>.json` | source / thread 身份、归属信息、文件身份与 revision、本对话搜索 / 子 Agent 覆盖 | 项目 / 全局配置副本、对话正文 | 仅有专属设置时创建；对话归档 / 删除时清理，恢复归档后继承上层 |
| `codex-collaboration-local.json` | 本机数据源 UUID、宿主身份、Codex HOME / 连接描述、用户选定执行适配器及绑定 revision | 口令、运行中临时连接句柄、伪造的执行能力 | 本机事实；迁移后重新核对，普通跨设备同步默认排除 |
| `codex-collaboration-state.json` | 连接世代、未完成的迁移 / 清理操作；需要周期任务时保存 nextDue / 退避 | 全部对话历史、完整策略、命名输入 | 有界协调状态；完成操作后移除，不成为第二个无限增长的汇总文件 |
| 项目 / unassigned 下的 `state.json` | 该容器内适配任务、必要去重与采用摘要 | 全量对话正文、完整配置副本、将历史成功冒充当前连接状态 | 有界操作状态；随对象收尾清理，不能被“清缓存”删除 |
| `cache/.../discovery.json` | 数据源、项目和 thread 的显示字段、分页游标、归档标记、父子关系、抓取时间 | 用户策略、手工覆盖、永久人工绑定 | 可清理、可重建；过期后展示状态并按需刷新 |

项目目录放在管理器活动数据根，不写进项目 Git 仓库。目录名使用由原生 ID 确定的稳定、文件系统安全 key，文件内保留原始 ID 以校验映射；名称和 cwd 只用于显示，改名和移动工作目录无需重命名配置目录。多个数据源分开命名空间，不按同名项目混用。

没有项目覆盖、对话覆盖或任务状态时不创建空目录；只有对话覆盖时，项目目录可以仅含 threads，不强制生成空 project.json。恢复本层全部继承后删除覆盖文件，目录确实为空时移除。归档对话可在发现缓存中展示，但不再保留主动作用域覆盖。

按需读取全局、当前项目、当前对话及本机绑定即可完成解析，无需每次扫描所有配置。初期使用 JSON 文件与有界内存索引足够；发现缓存只保留已加载分页，完成任务详情有界保留并合并落盘，避免每个 token 都写文件。

## 4. 配置事实源与建议结构

### 4.1 独立文件不复制原生全局配置

统一页面不等于所有字段都写入同一个文件：

| 设置 | 事实源与保存方式 |
|---|---|
| OpenCodex 已支持的全局 sidecar、helper 路由、子 Agent 全局字段 | 通过已有管理 API 写 OpenCodex；页面读取并显示来源，不在协作 JSON 镜像一份可独立修改的相同值 |
| 全局命名模型选择 | 复用已有 OpenCodex 全局管理 API；若后续由 Desktop 持有标题专属字段，则显式定义事实源，不镜像第二份可改值 |
| 项目 / thread 搜索、模型或子 Agent 覆盖 | 分别保存到对应 project.json / thread 文件；由请求级 / 原生执行适配器应用，不能靠轮流修改全局设置实现 |
| Codex 原生默认、已有角色、原生权限 | 原生配置持有；显式同步时才写，按原生装载点报告生效 |
| 模型与渠道定义 | 复用现有模型目录及后续模型配置模块，只存身份引用 |

若后续决定把某一类原生全局字段正式改为 Desktop 所有，必须增加明确的导入 / 接管和回写规则；不在本次草案中形成双方都会自动覆盖的双事实源。

一次编辑默认只保存当前作用域，采用单文件原子操作；全局保存不重写所有项目，项目保存不重写所有 thread。同时修改多个作用域或 OpenCodex 原生全局值时，按实际写入步骤分别报告结果并只重试失败步骤，不声称跨文件或跨配置源已有原子事务。

### 4.2 分层策略文件示意

下面分别示意全局、项目和对话文件；字段、模型引用与角色支持情况仍需在实现时冻结。示例身份是占位值，不可直接写入真实运行配置。

    "naming": {

        "channel_id": "channel-demo",
        "model_id": "title-model"
      }
    }
  }
}

对话 `threads/<thread-key>.json`：

示例中的 global.naming 仅示意全局模型引用，不是新增命名触发或提示词，也不要求把既有 OpenCodex 全局字段复制进 Desktop 文件；事实源依第 4.1 节确定。项目与对话示例只有搜索 / 子 Agent 覆盖，命名字段不适用。default_model_ref 仍是待执行器落实的默认意图，不等于推荐 roster。

字段省略代表继承；false 为明确关闭；空数组为明确清空且按字段约束判断能否使用；null 只在字段明确支持时有含义。“恢复继承”删除本层字段并重新解析，不能统一向原生传 null。数组整体替换。建议在序列化契约中显式记录删除操作，避免 merge-patch 的 null 语义混入用户配置。

普通字段按 原生默认 → 全局协作行为 → 项目 → thread → 本轮显式值 解析；强制 cap、权限和模型可用性随后约束，不能被普通覆盖绕过。自动命名、搜索和 subagent 分组各自说明支持范围与读取点。

### 4.3 本机绑定与多来源标识

本机文件建议使用 `schema_version / revision / sources[]`；每项包含 `source_id / host_id / codex_home / adapter_kind / connection_ref`。只有已经选定的数据源和连接描述才是配置；实时连接是否在线、支持哪些方法由适配器探测，不永久写死成用户配置。

项目 / thread 键使用 source_id + 原生 ID；名称与 cwd 只用于显示和候选匹配。执行实例重新启动可以保留数据源身份，但执行实例 ID / 世代必须更新。换 HOME、换宿主或接入不同实例时不沿用旧实例的“已接收 / 已采用”。

新增数据源先保存本机登记，再保存引用它的作用域文件；第二步失败留下一个未使用数据源即可。普通项目 / thread 覆盖只修改对应文件。移除数据源连接不等于删除原生项目，默认保留策略待重新绑定；明确删除原生项目则执行第 7.5 节清理。

### 4.4 修订与有效配置

`revision` 是本文件内的单调修订，不是 Desktop 软件版本。每份作用域文件有独立 config_id；删除后重建使用新身份，避免旧编辑页拿着相同 revision 覆盖新文件。完整有效配置以全局 / 项目 / thread 的文件身份、修订及摘要，加本机绑定修订和 upstream_fingerprint 共同标识；缺失文件明确表示继承，不要求一次项目修改递增全局修订或重写其他文件。没有原生 revision 的字段，可以对已读回的相关字段计算摘要；未知读回不能冒充已确认值。

例如本机策略仍为 r12，用户在 OpenCodex 面板改了全局搜索模型，相关有效配置也会变化；管理器应刷新原生来源视图并重新解析继承，不能只比较 r12 后忽略外部变更。执行记录保存具体来源集合，既能说明“来自项目覆盖”，也能定位实际模型经过 fallback 后的结果。

## 5. 事件订阅与时间检查的必要性

| 机制 | 必要性 | 建议安排 |
|---|---|---|
| 管理器配置提交事件 | 必须 | 保存成功后更新视图、使相关解析失效并通知执行适配器 |
| 实际执行端的 turn / thread / child 事件 | 对象生命周期与真实采用反馈需要 | 由后端连接目标执行器；按它实际提供的方法接入，不能通过启动第二个 app-server 假装接入原实例 |
| 项目删除、thread 归档 / 删除 / 移动 | 自动清理与归属维护需要 | 操作成功或确认事件后处理；缺少事件时校准已配置对象，分页缺项不触发删除 |
| 原生 / OpenCodex 配置变化观察 | 需要一致性，但不必首批建设全量 watcher | 本机受控写入立即刷新；外部改动优先官方事件，否则窗口恢复 / 页面到期读取 |
| 周期刷新项目与对话列表 | 可选补充 | 首批不必启用；缺少对象事件且用户持续停留列表时，才评估低频前台刷新 |
| 周期调用模型生成标题 | 没有必要 | 由 Codex 原有流程触发，本模块不增加命名定时任务 |
| 定时切模型 / 切策略 | 当前需求不需要 | 不增加按时段切换、通用 cron 表达式或日历 UI |
| 团队远端配置订阅 | 独立后续方向 | 接入既有团队发布订阅包；当前先支持本地配置闭环 |

事件订阅应为应用级服务，不随配置页销毁。命名仍由 Codex 触发，本模块不再建立需要管理器常驻的自建命名服务；全局模型路由由相应 OpenCodex 路径读取，按真实运行状态反馈。后台生命周期仍沿现有应用规则，不额外安装守护进程。

定时器能补列表新鲜度，不能补回错过的 turn 事件或证明模型采用。断线后可以重新读取对象，但默认不自动补跑历史命名。需要用户处理的未完成任务显示一次；不每次恢复都重新发起付费请求。

## 6. 默认交互与低打扰安排

### 6.1 页面和作用域

侧栏入口按用户确认命名为“对话”，页面标题为“Codex 对话配置”，顶部切换全局 / 项目 / 对话。项目列表按需分页；选中项目后加载其 thread，归档为可选筛选，不开页就扫描全部历史。每个字段显示当前有效值及来源，例如“继承项目：研发工具”。

本轮实际走查现有页面后，布局候选进一步简化为“全局设置 / 项目与对话”两入口，项目与对话通过对象列表切换；原作用域及继承语义不变。宽窄布局、按对象草稿和恢复包操作以 [对话页交互方案](对话页交互方案.md) 为后续原型候选，不把此前三个平级 Tab 当作已确认约束。

归档对话在配置页显示只读的继承预览及“专属配置已清理”；取消归档后才能重新创建专属覆盖。归档 / 删除操作就地说明会清理关联配置，沿既有操作一次执行，不增加独立清理审批。外部归档被发现后同样处理，不反复弹确认。

模型与枚举选择器始终可操作，继承项显示具体值 / 来源；直接选择即创建本层覆盖，“恢复继承”清除该字段或本层覆盖。数值和指令可直接编辑，推荐模型多选。常用字段直接可见，高级内容按需展开，重绘保持展开状态；未接通字段说明范围，不禁用整页。

用户按“保存”一次提交当前本机策略修改；保存成功用短反馈，不弹二次确认。只有确实涉及跨源部分成功、真实全局配置变更影响或目录迁移等需要用户判断的情况，才展示对应说明。策略日常编辑不增加统一审批流程。

### 6.2 刷新建议

| 时机 | 默认动作 | 用户体验 |
|---|---|---|
| 打开对话页 | 先显示缓存，再读取到期部分 | 保留选择、展开、分页和滚动，不先清空列表 |
| 配置保存成功 | 立即更新来源与目标修订 | 显示“已保存；下一轮采用”或当前真实边界 |
| 收到项目 / thread 变化 | 合并受影响对象或使对应分页失效 | 不重拉全部、不抢焦点 |
| 窗口恢复 / 重连 | 合并一次到期校准 | 不补跑错过周期，不连续弹通知 |
| 手动刷新 | 跳过新鲜度缓存，复用同对象在途读取 | 按钮有进行状态，其他编辑继续可用 |
| 上游暂不可达 | 保留缓存和已有绑定，标记最后更新时间 | 允许离线保存，恢复连接后再判断采用 |

首批建议使用约 60 秒的列表新鲜度作为可调内部默认，而非立即暴露一组时间输入框；这是读取缓存的候选 TTL，不等于每分钟后台执行。只有事件缺失造成用户可感知的列表滞后时，再增加约 60 秒的前台低频刷新，离开相关页 / 后台停止，失败退避；具体间隔在验证后定稿。

0.1.10 的 45 秒延迟用于启动后的更新检查；本地读取与用户保存不应机械等待 45 秒。网络或低优先级目录发现可以延迟，但不阻塞配置页显示。

### 6.3 全局命名模型与反馈

用户已明确只保留全局命名模型。项目和对话不提供命名配置，首次自动命名触发继续交给 Codex；本模块不建立每轮 / 后台自动命名任务。后续用户选择点击“按当前内容重新命名”，属于一次生成候选、预览并采用的操作，使用全局模型；失败保持原标题，不写入局部命名策略或新增保护开关。全局模型路由的匹配范围仍需验证。详情见 [标题更新交互](对话页交互方案.md#41-对话期间更新标题)。

保存成功、正常采用、正常命名不进入通知中心；就地反馈足够。持续无法连接、应用失败、跨源部分保存等需要处理的情况才进入中心，按数据源 / 对象 / 修订去重。同一次失败的重连或轮询不反复弹窗；通知失败不反转已成功保存的结果。

“重启 Codex”只在具体字段确有需要时显示。默认反馈优先使用“下一轮”“下一次搜索计划”“新创建的子 Agent”“需重新连接”，比统一要求重启更准确。

## 7. 保存、订阅与执行闭环

~~~mermaid
flowchart LR
  U[GUI / CLI 编辑] --> S[同一协作服务]
  S --> P[校验当前修订并原子保存策略]
  P --> E[发布配置提交事件]
  E --> V[刷新有效值与来源]
  E --> A[执行适配器接收修订]
  C[实际 Codex 生命周期事件] --> A
  A --> X[在真实执行边界解析并应用]
  X --> O[观察实际请求或原生回读]
  O --> R[记录采用状态并更新界面]
~~~

### 7.1 受控保存

同一宿主进程中的 `CollaborationService` 是本模块统一写入入口，GUI 与后续 CLI 通过它调用。保存步骤：取得活动根写者准入 → 在本模块串行区核对作用域状态、config_id 与 revision → 应用字段修改 / 删除 → 校验可保存结构 → 原子写入对应文件或移除空覆盖 → 提交内存 → 发布作用域变更。保存与归档清理在同一串行区排序，已确认归档的对象不再接受新覆盖。

revision 用于避免两个编辑页覆盖彼此未见的修改。冲突时显示受影响字段并让用户合并，不能静默丢掉另一侧值；无需每次编辑弹确认。可保存结构与执行能力分别校验，离线 / 暂不支持执行不阻止保存已有绑定策略。

旧进程已保存根切换时，新保存及持久回执写入遵守原有停写规则；已接收的工作需要在其持有的准入期间完成或记录结果。执行连接若带来非文件副作用，还要参与根切换前的相关任务所有权判断，不能只管 JSON 文件而让旧任务在切根后继续应用过期设置。

### 7.2 配置事件

建议新增 `collaboration-policy-committed` signal，携带对象身份、修订、变更分组及操作 ID，不传配置正文和提示词。组件先订阅，再读取带修订的完整快照；读取期间收到的新事件触发一次后续校准，从而避免“先读后订阅”漏掉变化。signal 是刷新提示，事实仍在持久配置。

Tauri 事件默认不假定可靠重放。首批重连 / 重开页读取快照即可，不先建设永久事件日志。执行器接收端也先核对当前策略快照；确需远程或 CLI watch 时再增加有界序列 / 快照恢复协议，明确版本和流控。现有单响应 IPC 不直接宣称具有订阅能力。

外部手工编辑协作文件可先支持“重新加载”，随后按需求加入原子替换感知和短去抖 watcher。外部文件摘要有变化时按新内容重新加载并生成有效配置标识，不只相信编辑者是否递增 revision；非法内容保留原件和最后有效内存，提示修复，不以默认空配置覆盖。不得让 watcher 与管理器互相回写形成循环。

### 7.3 执行事件与采用记录

候选内部 signal 包括 `collaboration-source-changed`、`collaboration-effective-changed`、`collaboration-adoption-changed`；真实生命周期由 Codex 适配器翻译为 thread / turn / child 领域事件。事件名与 Job / ObjectKind 等枚举需要同步生产注册，不能只新增 JSON 字符串。

“执行端已接收 r12”只证明接收；“实际采用”要有对应 turn、HTTP 请求、搜索 plan 或 child 创建的证据。记录包含 source、执行实例世代、thread、可用的 turn / plan ID、策略快照标识与实际模型。无具体观察能力时停在“已接收 / 待观察”，不据时间流逝变成成功。

新增局部策略建议在父 turn 开始时冻结，child 继承；仅能观察 HTTP 请求时按请求冻结并标注真实粒度。模型参数有持续性，撤销覆盖时重新解析当前有效值并显式应用；应用按同 thread 排序，避免旧恢复动作覆盖较新选择。

### 7.4 如后续需要周期任务

沿用一个应用级 nextDue 唤醒、同对象 single-flight、恢复只补一次与失败退避。必须先扩展共享调度驱动，让更新与协作分别提供 plan，再选择最早到期；不能为每个组件、项目、thread 建一个 interval。

保留现有 `update-schedule.json` 的更新格式；协作任务的 nextDue / 失败次数放操作状态文件，或在确实统一调度 schema 时显式迁移。现有更新 Schedule 仅允许三个对象、16KiB 且拒绝未知字段，不能直接加 `project-refresh` 当作兼容。

后台持续执行与当前前台更新 timer 的生命周期不同。首批只需要本地事件与前台到期校准；若以后承诺窗口隐藏仍刷新，则先将必要驱动放到存活的后端服务并验证退出行为，再向用户提供该选项。周期读取和团队订阅下载不自动触发模型调用或采用远端配置。

### 7.5 项目与对话生命周期清理

用户提出“按项目建配置，并随项目删除、对话归档同步删除”。这里首先指本机配置随 Codex 对象生命周期联动；不要求先完成 WebDAV 或团队订阅。目录分层适用于搜索和子 Agent；命名模型仅在全局保存。

| 已确认的变化 | 自动处理 | 后续行为 |
|---|---|---|
| 项目改名 / 工作目录移动 | 保持稳定目录 key，仅刷新显示信息 | 原覆盖继续命中 |
| 对话归档 / 删除 | 移除该 thread 覆盖、相关任务和采用摘要，收尾专属派生资源 | 项目及其他 thread 覆盖不受影响 |
| 对话取消归档 | 不自动恢复已删除覆盖 | 继承当前项目 / 全局；用户可重新设置，不触发历史首轮命名 |
| 对话移动项目 / 取消项目归属 | 将已有 thread 文件和必要状态迁移到真实目标项目或 unassigned | thread 身份不变；重新继承新项目配置 |
| 项目确认删除 | 先处理仍存在且已重新归属的 thread，再清理原项目覆盖、状态及空目录 | 如果 Codex 保留对话，保留它们自己的覆盖并迁移；不能把项目删除当成对话删除 |
| 清缓存 / 暂时离线 / 列表筛选缺项 | 仅清缓存或标记待校准 | 不删除用户配置 |

归档清理必须依据目标来源的成功操作、可信生命周期事件或明确状态读回；分页未加载、默认不显示归档、短暂请求失败都不构成删除证据。缺少项目删除事件 / 确认接口时标记待核对，不声称已实现实时删除。重连后针对已有配置的对象校准，不扫描全部历史；离线期间不能承诺外部归档立即清理。

项目已删除但存活对话的新归属尚未确认时，先停用已删除项目的覆盖，保留这些对话自己的文件待迁移；确认迁移完成后再移除旧目录，不提前递归删除其中的对话配置。

清理先使对象的适配任务世代失效并取消管理器可控的待执行工作，再移除配置 / 状态，刷新有效策略。迟到结果不得重新创建目录或写回已清理覆盖；已运行的模型请求及 child 不因文件清理而假装取消。对仍可控制的会话，在真实下一执行边界重新应用继承值，避免已持久化原生参数继续保留被删覆盖。

跨目录迁移和递归清理用操作 ID 记录尚未完成的步骤，复用有界协调状态；成功后清除记录。迁移先原子写入目标再清理旧文件，解析期间以服务确认的当前归属及待完成操作为准，恢复时幂等完成，不让两份文件同时成为有效配置。待完成清理期间禁止新覆盖；可控任务收尾后移除临时记录，无需永久保存每个已归档对话的 tombstone。

恢复未完成操作或处理迟到事件时，核对当前生命周期状态及目标文件身份。对话已经取消归档并创建新 config_id 的覆盖后，旧清理不得删除新文件；先完成旧操作收尾，再允许新覆盖保存。

目录与资源只清理管理器所拥有且已无引用的部分；不删除原生对话、用户已有的 CODEX_HOME/agents 文件或共享角色模板。未创建过覆盖的对象无需生成文件再删除。项目最后一条对话归档只清对话覆盖，不清仍有效的 project.json。历史备份沿既有保留规则处理，不因一次归档连带清空。

取消归档 / 重连不是新的首轮事件。本模块不拥有命名触发，取消归档或首次接入不主动补跑历史命名。自动清理无需独立确认，持续失败才就地提示或合并通知。

## 8. 备份、迁移与配置订阅

| 场景 | 建议范围 | 恢复 / 采用原则 |
|---|---|---|
| 本机对话配置备份 | 全局、选定项目 / thread 策略及可选本机绑定；清单标明真实作用域文件 | 配套核对 source 身份；可单独恢复策略，缺绑定时保留待匹配 |
| 当前升级前偏好备份 | 仍是 preferences 原有范围 | 本模块正式接入时另登记“对话配置”，不能误称既有备份已经覆盖 |
| 活动根迁移 | 用户事实随受控迁移；缓存可重建；运行中连接先收尾 | 原生外置 HOME 不自动搬动；重启后旧采用记录只作历史，重新核对实例 |
| 手动导出 / 导入 | 通用配置导出默认不勾选协作模块；专用导出入口选择全局、项目或 thread，迁移同设备时可选本机绑定 | 导入生成本机新 revision；显示改动范围与未匹配来源，不改变 WebDAV 选择 |
| 项目 / 对话联合包 | 显式选择元数据、历史、关联策略与可读取附件；支持时附原生恢复载荷 | 阅读与原生恢复分别说明；导入形成新 ID 后重新绑定策略，不自动开始任务 |
| WebDAV / 跨设备个人同步 | 全局、项目与 thread 协作策略均默认排除；后续支持时由用户显式选择模块和作用域 | 原生 ID 与 source 不按同名自动绑定；重映射模型引用与对象身份，关闭时跳过协作载荷 |
| 团队发布订阅 | 将来作为可选协作策略模块接入 | 只发布可复用行为或角色模板，不发布本机 HOME、thread ID、任务状态或采用证明 |

备份 manifest v1 一个记录一个 payload。分层文件建议由协作模块打成单份带版本的 collaboration-bundle.json，载荷包含选择范围、相对路径 / 原生身份和对应配置内容；复用现有单 payload 存储，但新增协作载荷校验与恢复器，不能交给偏好恢复器直接加载。收集快照时经过同一服务保持一致；恢复逐文件受控应用并记录未完成步骤，不把多个文件写入声称为一次原子替换。若未来改用多 payload manifest，再显式升级格式。

恢复 / 导入要创建新的本机 revision 并重新解析当前有效值，而非把旧 revision 原样倒退。操作状态不恢复为“当前已采用”，未决命名任务不自动重放；去重历史用于避免重复执行，缺失或不确定时提供人工重试。

正常恢复不自动重建已确认归档 / 删除对象的覆盖；先核对对象状态，未知对象列为待匹配，旧配置可供查看 / 提取但不直接激活。远端同步若以后包含这些作用域，删除也必须作为可传播操作并在确认后有界保留记录，避免另一端旧文件重新导入；这属于同步契约扩展，不把本机“文件不存在”自动当成远端删除命令。

模型目录、引用映射和同步连接复用 [模型配置管理与同步](../../../2026-10-04-模型配置管理与同步/README.md) 的相应契约，但本包仍独立。团队订阅复用 [团队配置发布订阅与模块组合](../../../2026-10-05-团队配置发布订阅与模块组合/README.md)；该包当前模块为 models / skills / mcp，协作策略需要显式新增模块契约，不假定已经在订阅范围内。

远端自动检查或下载可在以后复用集中调度，只生成候选；采用另有真实应用结果。本机覆盖保留，不能远端发布一次就改写运行中的所有对话。当前无需为此新增独立订阅服务器或第二套账号系统。

### 8.1 导出与 WebDAV 默认范围

用户明确要求“webdav默认不同步”。本包的全局命名模型等设置、项目覆盖、对话覆盖均适用，不仅排除 thread。新建同步配置及旧配置升级后缺少协作选择项时，均按未选择处理；已有模型 / 渠道同步不会因为引用同一模型或存在同一数据目录就自动包含对话配置。

后续实现时，在既有同步范围中增加默认未勾选的“Codex 对话配置”，由用户选择需要同步的作用域；对话范围也不自动全选。关闭状态不上传、不应用下载中的协作条目，也不传播协作删除操作。同步载荷按模块与作用域清单收集和应用，不递归打包 manager-state、backups 或 exports 整目录来绕过该选择。普通 WebDAV 策略载荷不包含本机来源绑定、执行状态、发现缓存或任务记录。

手动导出是一次性操作，不开启 WebDAV。通用导出中协作模块默认未勾选；专用“导出对话配置”入口可直接选择全局、指定项目或指定对话。导出所选作用域的覆盖及必要模型引用；继承值不自动展开为固定覆盖，需要携带上层策略时一并选择。导入沿用对象 / 模型映射和生命周期核对，不自动修改本机 WebDAV 范围或启用同步。

本机协作备份按已登记范围执行，仍可备份这些策略，不受 WebDAV 默认关闭影响；本机备份成功不代表已上传。后续用户关闭协作同步，仅停止该模块继续交换，不删除本机配置或远端已有副本。将来显式启用后，归档 / 删除的传播仅限已选择并完成身份映射的作用域，不能扩大到其他项目或对话。

默认不同步是用户已明确的需求；上述入口安排与载荷细节是适配建议，尚未实现，不增加独立确认门禁。

### 8.2 项目与对话内容导出

用户进一步提出项目和对话本身也要支持导出。只导出配置适用于复用设置；任务迁移需要历史、对象关系、关联配置和必要资源一同可选打包。详细结构、身份映射与当前隔离可行性验证见 [联合导出及恢复方案](项目与对话联合导出及恢复方案.md)。

日常协作目录不存正文，配置备份不冒充完整对话备份；历史由 Codex 持有并在显式导出时读取。已有导出包不随原对象归档 / 删除被移除。WebDAV 默认也不包含历史；即使以后选择对话配置同步，也不自动包含对话内容。原生恢复使用新 ID 映射，不能只靠来源 threadId 或 Markdown 保证可继续。

2026-10-13 用户将内容导出用途明确为临时重装恢复，首批以本地恢复包及导入映射为核心；对话历史作为独立同步范围默认未勾选，通用预设、缺字段升级和恢复包导入不自动开启。当前不上传 WebDAV，也不要求先实现远端历史同步。未归档容量与候选入口见 [临时重装用途评估](../03-确认与评审/20261013-对话体积与导出空间评估.md#7-后续澄清未归档容量与临时重装用途)。

### 8.3 公共配置能力的分模块接入

用户指出同步等公共部分会随各版本的配置文件增加而扩展。因此“功能包独立”不足以说明完整版本边界，还要记录公共流程如何接入新增配置。本节为后续适配建议，未形成生产注册表或新增实现；沿既有 [同步专题](../../../2026-10-04-模型配置管理与同步/01-需求分析/02-方案草案/配置同步/README.md) 的统一逻辑清单和各域适配器扩展，不在对话包复制一套公共同步契约。

公共能力负责文件容器、连接与传输、范围选择、清单与依赖、前后比较、应用步骤及汇总结果；功能模块负责配置所有权、可移植字段、对象身份、序列化 / 校验、映射与真实读写。活动数据根、原子保存和备份存储继续复用已有底座，模块另登记真实备份范围与恢复器。

新增持久化内容时，登记以下最小接入信息，文件在同一目录并不自动进入导出或 WebDAV：

| 登记内容 | 用途 | 本包示例 |
|---|---|---|
| 稳定模块 / 对象类型、所有者 | 对应清单、页面分类及读写实现 | 对话配置与对话历史分别登记，显示名可变、类型身份保持稳定 |
| 对象 schema / 迁移支持 | 判断载荷是否能正确解释 | 全局 / 项目 / thread 策略版本、原生历史来源及兼容恢复能力 |
| 操作能力与默认范围 | 区分导出、导入、备份和 WebDAV 各自支持 | 本地策略与重装包按显式选择；对话配置 / 历史默认不同步，历史远端能力未接通时如实表示 |
| 引用 / 依赖与绑定规则 | 收集必需内容并正确关联目标对象 | 模型身份、上层策略和主 / 子关系；依赖不隐含扩大用户同步范围 |
| 校验 / 应用 / 读回 / 恢复入口 | 按模块形成真实应用结果 | 策略应用与原生历史恢复分别报告；本机状态不导入成当前采用证明 |
| 首次交付版本及实际支持状态 | 固定每个软件版本提供的模块能力 | 本包交付版本未定；设计可以展示，不代表 0.2.0 已支持 |

后续其他版本也按相同信息接入新增模型、扩展或业务配置；日志、缓存、运行任务及本机绑定按其边界排除，不能以“新增配置文件”直接推导为同步对象。公共页面只呈现实际受支持的能力，默认选择依据各模块规定，新增模块不因为“全部配置”或已有连接自动开启。

三个版本维度分别记录：Desktop 软件发布版本说明交付哪些模块 / 操作；文件容器或 WebDAV 协议版本定义包与交换结构；各模块 schema 定义其内容格式。它们不要求同号，也不因一次菜单或标签修改自动升级全部格式。现有严格读取器不能接受新字段时，明确升级 / 隔离容器或协议；不能只把新文件塞进旧载荷声称兼容。

兼容处理沿原同步专题的范围和合并原则，明确两种情况：

1. 外层格式无法识别、不能安全解密或遍历时，停止本次导入并说明所需支持；保留原文件和本机数据。不能声称已读到可用的内部模块。
2. 只有在公共容器已验证可读、独立模块边界和依赖可识别的前提下，才允许导入已支持且用户选择的独立模块；未知类型或新 schema 显示“当前版本不支持”。受其依赖的相关项待处理，其他独立项是否可应用按真实计划决定；结果是部分导入，不宣称全部恢复。该能力需要后续明确实现，不默认推翻原 strict 容器的拒绝行为。

WebDAV 上传按已选择、受支持模块更新，保留远端未选择和不认识的对象；本机未勾选、读不到或尚不支持都不是删除命令。旧客户端若只支持全量替换且无法保留新模块，须按已有版本化域隔离或拒绝该次覆盖，不能静默冲掉新内容。修改范围不清除远端，模块显式删除只在已支持的传播契约内处理。重新启用时先比较现状，避免旧端文件恢复已清理对象。

本地重装恢复包与普通配置交换可以共用范围、预览及进度组件，但容器内的原生历史载荷由恢复适配器持有；配置传输器不因能读 ZIP 就声明可以恢复会话。当前首批对话历史以本地恢复为用途，WebDAV 历史交换不成为共同底座必须实现的依赖。

后续验证重点为：当前已支持模块往返、旧包缺新模块不清本机值、未知格式保留原状、可读模块化混合包如实报告部分支持、未选新模块不被预设加入，以及旧端子集上传不抹掉远端新内容。仅新增界面分类和文件路径不构成公共能力接入完成。

## 10. 依赖顺序与最小可用计划

这些是实施顺序建议，不是版本承诺；可逐步交付经过验证的能力，不要求全部扩展同时完成。

| 步骤 | 内容与可评审产物 | 最小验证 |
|---|---|---|
| A 实际执行端接入 | 明确当前 Codex 实例如何连接、支持的事件 / 设置；确认 OpenCodex 局部请求上下文如何取得 | 一个真实 thread 接收设置并在下一轮观察采用；第二 app-server 读取不得冒充控制原实例 |
| B 独立配置与解析 | 全局文件、项目目录、按需 thread 文件、本机来源及有界状态；继承、离线编辑；最小备份 / 恢复 | 当前作用域单独保存；false / 空数组 / 删除覆盖正确；文件重建拒绝旧修订；备份真实可恢复 |
| C 对象发现与页面闭环 | 项目分页、thread 筛选、缓存、来源反馈及归档 / 删除 / 移动清理 | 改名保持绑定；归档移除专属覆盖；取消归档恢复继承；迁移保留正确归属；不因分页缺项清理 |
| D 事件与实时采用 | 配置提交、快照恢复、对应执行边界与采用状态；选择一个已接通字段做完整链路 | 保存 rN → 接收 → 下一轮实际采用；断线恢复、撤销 sticky 参数均正确 |
| E 三项行为逐一接入 | 搜索先限定明确 sidecar 路径；子 Agent 验证父子继承；命名沿用 Codex，仅接入全局模型路由 | 两项目并发不串配置；child 参数可观察；命名路由范围可观察，不产生额外命名任务 |
| F 生命周期完善 | 完善备份恢复入口、数据根迁移与导入导出；需要时才补前台周期刷新 | 清缓存保留用户配置与去重；切根无旧写者；恢复不自动重放付费任务 |
| G 可选分发 | 默认关闭的 WebDAV 协作模块、个人同步与团队协作策略模块 | 默认无协作载荷；显式选择才交换；导出 / 导入不启用同步，导入重新绑定身份 |

A 中执行端接入结果决定实时功能能做到哪一步；B / C 的配置编辑与发现可以独立推进，但页面要显示实际支持边界。产品首次可用应至少包含一个字段的 D 闭环，不能仅有编辑页就标注“实时生效已完成”。

B 的存储接入同步完成活动根路径、写者和最小备份 / 恢复登记；F 用于完善界面及跨环境流程，不把基础数据可恢复性推迟到可选分发。事件反馈和备份登记直接沿既有契约扩展，不另建一套审批系统。

建议先沿用已有 `test/codex-collaboration/probe_native.py` 的隔离方法，再新增实际实例连接、双项目并发、父子继承、配置事件重连与清缓存 / 恢复的针对性验证。当前文档变更不需要重跑已经通过的 8 项原生测试；新增存储与事件链路也尚未被这些历史测试覆盖。
