## WP-32：导出配置无法选择保存路径

**优先级**：P2
**位置**：同步 → 文件同步 → 确认配置导出 → 生成导出文件
**用户原话**：“为什么导出不能选路径？”
**状态**：待修复

### 现状

点“生成导出文件”后，后端直接把包写入数据根下的固定目录：

- 命令 `model_transfer_export`（`commands/model_transfer.rs`）里写死 `root.join("exports")`，文件名固定为 `opencodex-config-<uuid>.ocxdconf`；
- 成功后列表顶部只显示生成后的完整路径，并提供“打开导出目录”按钮；
- 前端没有 `save` 对话框调用，Tauri 能力清单里也只声明了 `dialog:allow-open`，没有 `dialog:allow-save`。

因此用户无法决定文件落在哪里，想通过微信 / 邮件 / U 盘带走时得先去找数据根目录。

### 为什么当初这样设计

`exports/` 属于受管目录（`ManagedPathKey::Exports`），与备份、日志同级，写入受 `safety::check_path` 与原子写入保护，并做了内容读回校验。固定目录让“导出 → 校验 → 留档”这条链路完全在受控范围内，不需要处理用户选到任意目录后的权限与覆盖风险。

### 拟定改法

- 确认导出对话框增加目标位置：默认保持 `exports/`，提供“另存为…”调用系统保存对话框（Tauri `dialog.save`），需要新增 `dialog:allow-save` 能力。
- 后端 `model_transfer_export` 增加可选 `targetPath`：为空时沿用受管目录；有值时校验绝对路径、扩展名与是否覆盖，写入后仍执行读回校验。受管目录之外的写入不再走 `safety::check_path`，需单独定义允许范围（仅用户显式选择的文件）。
- 覆盖已有文件时明确确认，不静默覆盖。
- 界面在成功后同时显示“保存位置”，并保留“在访达 / 资源管理器中显示”入口。
- 原型同步：导出确认弹窗补一行保存位置（默认导出目录 + 另存为），并在注释里说明默认位置与选择边界的差异。

### 待确认

1. 默认仍写 `exports/` 再让用户另存，还是干脆每次都必须选路径？
2. 另存到受管目录之外时，是否仍要求读回校验（会增加一次 IO，但可确认落盘正确）？
3. 是否只在 macOS 提供“在访达中显示”，Windows 对应“在资源管理器中显示”？

### 补充（0.2.4 实机回看）

用户在 0.2.4 上导出后反馈“我没有看到打开导出目录”。核实结论：

- 该按钮只在**导出成功之后**出现，位置在页面顶部“导出配置”按钮下方，与生成的文件完整路径同一行；它是一个小号 ghost 按钮，视觉权重低于主按钮，容易被忽略。
- 若尚未导出或导出失败，这一行整体不渲染，因此界面上没有任何“打开导出目录”的入口。
- 另一种可能：确认对话框还开着时用户以为已经写入，实际要再点一次“生成导出文件”才落盘。

改进方向：

- 把“打开导出目录”提到更显眼的位置，例如确认对话框的成功态与页面顶部同时出现；
- 未导出时也提供入口，让用户随时能看到已有导出文件；
- 生成成功后给出明确成功提示（含文件名与目录），而不是静默更新一行文字。

### 原型已调整

- 导出确认弹窗新增“保存位置”：单选“默认导出目录 / 自定义目录”；选自定义时展开只读路径输入与“选择目录…”按钮；未选择目录仍按默认目录保存，选了自定义却没选目录会明确报错。
- 结果文案改为“保存到 <目录>”，注释里写明默认与自定义的边界。
- 样式补充 .sx-destination 与 .sx-dir-row，与弹窗字段规格一致。

### 待确认（更新）

1. 实现侧默认仍写 exports/ 再允许另存，还是每次都必须选路径？（原型现为“默认 + 可选自定义”）
2. 另存到受管目录之外时是否仍做读回校验？
3. “打开导出目录”是否也应在未导出时常驻？

## WP-33：同步页整体布局与原型偏离

**优先级**：P1
**位置**：同步 → 文件同步
**用户原话**：“当前同步的界面 按钮 右侧控制的布局都有差异，而且有些配置都是在带出才有的中的，有很大差异。按钮位置也不对。你先对比。”
**状态**：仅登记，未实施

### 实测对照（原型 57300 / 实现 5183，均暗色高画质）

| 项 | 原型 | 实现 |
| --- | --- | --- |
| 卡片标题 | 导入与导出 | 文件同步 |
| 标题说明 | 把选定配置带到另一台设备，或用分享预设导出不含凭据的配置。 | 导入导出管理器配置和模型；模型采用后进入本机草稿。 |
| 主按钮位置 | 面板右上角，与标题同一行 | 描述下方左侧一行 |
| 主按钮集合 | 导入配置、导出配置（2 个，导入在前） | 导出配置、导入配置、恢复上次接收、重新读取范围目录（4 个，导出在前） |
| 工具栏 | 范围预设 + 搜索 + 清空选择，同一行 | 导出来源 + 范围预设一行；搜索 + 全选 + 清空塞在对象树内部 |
| 两栏宽度 | 649px / 220px | 695px / 240px |
| 右栏标题 | 其他凭据 | 其他凭据与同步选项 |
| 右栏首项 | 说明文字 | 读取扩展目录按钮（原型无此入口） |
| 凭据分组 | 渠道 API Key、扩展凭据 两个独立区块，各带说明 | 展平成复选框：扩展凭据 / 已检查 Skill / 全局采用 / 口令 / 渠道Key池 |
| 收尾提示 | 所选凭据需加密 | 无，改成口令占位符提示 |
| 左栏列 | 配置对象 / 范围与凭据 | 类别 / 配置对象 / 内容与同步选项 |

### 结论

1. **按钮位置**：原型把主操作放在面板标题行右侧；实现放在描述下方左侧，且多出两个原型没有的次级按钮（恢复上次接收、重新读取范围目录），四个并列按钮压住内容。
2. **右栏结构**：原型是“标题 → 说明 → 渠道 API Key 区块 → 扩展凭据区块 → 加密提示”；实现拆成散装复选框，插入原型没有的“读取扩展目录”，并把“全局采用及渠道组顺序”“文件保护口令”混进同一列，层次被压平。
3. **“只有带出才有”**：实现里“携带所选扩展凭据”“已检查所选 Skill…”依赖 hasAssets 才渲染，渠道 Key 勾选又要求已选渠道，于是多数情况右栏只剩一两项，看起来像配置缺失；原型恒定展示两个凭据区块，未选时以禁用与说明呈现。
4. **工具栏错位**：原型的预设、搜索、清空是一条完整工具栏；实现的搜索与全选被塞进对象树组件，和预设分处两行。

### 拟定改法

- 标题与说明改为原型措辞；导入配置 / 导出配置移到标题行右侧。
- 恢复上次接收、重新读取范围目录降级为次级入口，不与主操作平级。
- 右栏按原型重建：其他凭据 → 说明 → 渠道 API Key → 扩展凭据 → 加密提示；未选中时区块仍在，说明为何不可选。
- 读取扩展目录移到 Skills / MCP 位置或工具栏，不占凭据清单首位。
- 搜索、全选、清空与范围预设合并为一条工具栏。
- 两栏宽度对齐原型（约 649 / 220）。

### 待确认

1. 恢复上次接收 / 重新读取范围目录是否保留？保留的话放工具栏还是更多菜单？
2. 右栏是否严格照原型只留两个凭据区块，把全局采用、口令、WebDAV 密码收进各自区块？

### 决策（2026-10-22）

用户明确：“完全按照原型，不要扩散思维，原型本身就是确认过的。”

因此本轮不做取舍讨论，原型即目标态。实现按下面清单逐项对齐，不新增原型没有的入口，也不保留原型已没有的旧入口：

**卡片头部**

- 标题：导入与导出。
- 说明：把选定配置带到另一台设备，或用分享预设导出不含凭据的配置。
- 主操作在标题行右侧，顺序为「导入配置」「导出配置」。

**工具栏（一行）**

- 范围预设（默认配置范围 / 分享配置 · 不含凭据 / 换设备 · 含可转移凭据 / 自定义范围）。
- 搜索配置对象。
- 清空选择。

**左栏对象列表**

- 列名：配置对象 / 范围与凭据。
- 分组顺序：渠道与模型、模型模版、账户、Skills、MCP、桌面偏好、WebDAV 配置。

**右栏（其他凭据）**

- 标题：其他凭据。
- 说明：账户按平台能力提供可选范围；当前仅账户信息，WebDAV 密码随配置选择；以下凭据可另选。
- 区块一：渠道 API Key，说明“渠道可单独分享，接收方自行填 Key。”
- 区块二：扩展凭据，说明“例如 MCP 的 Authorization / 环境变量。”
- 收尾说明：所选凭据需加密（口径见下方说明）。

**两栏宽度**：约 649 / 220。

### 按原型移除的入口

以下三项在原型中不存在，本轮实现中移除：

- 恢复上次接收
- 重新读取范围目录
- 读取扩展目录（原型右栏首项是说明文字）

若日后确实需要“恢复上次接收”，应由原型先定义位置与状态，再回到实现，不在本轮自行加回。

### 一处已知冲突

原型右栏收尾写“所选凭据需加密”，与 WP-31 已确认的“口令完全可选、允许明文携带凭据”冲突。

处理：布局与分组完全照原型，仅该句文案按 WP-31 决策改为“所选凭据将随文件传输，口令可选”。若需要原型也同步改这句，另行确认后修改原型。

### 验收口径

- 头部只剩两个动作按钮且位于标题行右侧；
- 工具栏三个控件同行；
- 右栏结构为 标题 → 说明 → 两个凭据区块 → 收尾说明，无按钮插在首项；
- 左栏列名与分组顺序一致；
- 页面上不出现“恢复上次接收”“重新读取范围目录”“读取扩展目录”。

## WP-34：WebDAV 同步页与原型偏离

**优先级**：P1
**位置**：同步 → WebDAV 同步
**用户原话**：“webdav也看看对比原型。”
**状态**：仅登记，未实施（沿用 WP-33 决策：完全照原型）

### 实测对照（原型 57301 / 实现 5183，均暗色高画质）

| 项 | 原型 | 实现 |
| --- | --- | --- |
| 卡片标题 | 设备间同步 | 配置同步 · WebDAV |
| 标题说明 | 本机范围同时用于上传与接收；下载的变化先预览，再应用。 | 本设备范围同时约束上传和接收；下载后比较并采用。 |
| 主操作位置 | 标题行右侧 | 描述下方左侧 |
| 主操作集合 | 保存本机范围、同步配置（2 个） | 保存本机范围、预览上传、下载并比较、查看原上传计划、重新读取范围目录（5 个） |
| 连接信息 | 个人 WebDAV + 地址 + 连接设置按钮，位于卡片之上独立一行 | 当前 WebDAV 连接 + 地址 + 连接设置按钮，位于页签与卡片之间 |
| 右栏标题 | 其他凭据 | 其他凭据与同步选项 |
| 右栏结构 | 说明 → 渠道 API Key 区块 → 扩展凭据区块 → 当前不携带凭据 | 后续新增对象（折叠）→ 读取扩展目录按钮 → 全局采用 → 口令 → 渠道Key池 |
| 工具栏 | 范围预设 + 搜索 + 清空，同一行 | 只有范围预设一行；搜索与全选在对象树内部 |
| 两栏宽度 | 649px / 220px | 695px / 240px |

### 与文件同步同源的问题

WP-33 里记录的四类偏差在 WebDAV 页同样存在：

1. 主操作错位且数量翻倍（原型 2 个，实现 5 个）；
2. 右栏被展平并插入原型没有的入口（后续新增对象、读取扩展目录）；
3. 工具栏被拆成两处；
4. 两栏宽度不一致。

### WebDAV 特有差异

- 连接信息块：原型是卡片外的独立一行（个人 WebDAV / 地址 / 连接设置），实现把它放在页签与卡片之间，标题也改成“当前WebDAV连接”。
- 原型右栏收尾是“当前不携带凭据”，实现没有这句统一状态。

### 拟定改法

与 WP-33 同一套处理，不单独发散：

- 卡片标题改“设备间同步”，说明用原型原话。
- 主操作只保留“保存本机范围”“同步配置”，移到标题行右侧；预览上传、下载并比较、查看原上传计划、重新读取范围目录按原型移除。
- 连接信息沿用原型措辞与位置。
- 右栏重建为 说明 → 渠道 API Key → 扩展凭据 → 当前不携带凭据；移除后续新增对象与读取扩展目录。
- 工具栏合并为一行；两栏宽度对齐 649 / 220。

### 风险提示

实现里“预览上传”“查看原上传计划”承担了上传前核对与失败后重查的职责，按原型移除后，这两条路径需要确认是否由“同步配置”内部的确认对话框承接；若承接不了，属于原型缺口，需在原型层面补，而不是实现自行加回。

## WP-35：Agent 配置页缺“已配置模型”的完整态

**优先级**：P2
**位置**：设置 → Agent 配置（原型工具板 + 页面本体）
**用户原话**：“这里是否在工具板再做一个本页看这个tab已经配置好模型的效果，布局要合理好看。因为本页空间还有很多。”
**状态**：已修复（原型侧，0.2.5 待发布）

### 问题

1. 原型工具板只有 settings:general / backup / extensions / cleanup / cli / upgrade / about 的演示卡，Agent 配置页没有任何演示卡，无法在本页看到“已配置模型”的效果。
2. 页面本体在未配置时只有一行摘要 + 一个按钮，右侧大片留白；用户要求利用本页空间。

### 改法

**工具板**

- 新增 `settings:models` 演示卡（页签的 data-settings-section 值为 models，不是 agent）。
- 两个单选：尚未配置 / 已配置模型，调用 `window.modelPrototype.applyAgentDemo(mode)` 切换内存投影。

**页面本体**

- 未配置：保留空态说明“尚未选择执行模型。自动填充与模版检查需要先配置一个可用的执行模型。”，按钮为主色“Agent 配置”。
- 已配置：标题行摘要保留，右侧按钮改为“更换执行模型”；下方铺开三块：
  - 四项事实横排（执行渠道 / 型号 / 推理档位 / 快速模式），自适应列宽；
  - 适用范围说明（自动填充与更新共用、不影响 Codex 命名与子 Agent、只影响之后启动的任务）；
  - 与运行配置的边界（写入 preferences.json 的 modelTemplateAgent 分区，不进入默认同步或普通导出）。

### 验证

- 原型 31 个测试文件 255 项全部通过；`agent-settings-page.test.cjs` 5 项通过（含新增的空态/已配置断言）。
- 浏览器实测：工具板卡片在 Agent 页签可见，切“已配置模型”后四项事实渲染（facts=4），摘要变为 NewApi / gpt-5.4 · 中（模型默认） · 快速已关闭。

### 边界

只改原型，不涉及实现代码；实现侧 Agent 配置页是否同步这套排版，随 0.2.5 其它项一并处理。
