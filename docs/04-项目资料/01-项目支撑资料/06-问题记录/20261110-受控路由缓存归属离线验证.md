# 受控路由缓存归属离线验证

2026-11-10。用户同意在Windows revision4接收后继续本机缓存规则验证。目标Desktop0.2.24，当前产品基线0.2.23；本轮只对已声明合成后像进行离线技术原型，不启动服务、不修改官方2.99或生产代码，不增加缓存保留例外。

## 问题和采用范围

revision4唯一服务链在producer-r4的native-cache-only规则拒绝，原accepted:false保留。这轮缓存原来缺席，ready、pre-stop、official-stop的原字节/文件ID/owner/DACL保持一致，包含fixture/gpt-6.1-sol，且ready catalog就是同一模型条目。实际官方server/index.ts启动序列以startup-cache写者调用缓存失效/重建，retained-sync.ts明确输出2000-01-01T00:00:00Z、0.0.0和models包装。因此“已受控生成、Stop没有改变的缓存”与“Stop已转换成原生行缓存”是两种需要区分的后像，不能只支持后者。

新候选保留旧native-cache分支和另四路径规则，仅增加“原来不存在的受控启动缓存”分支。原来存在的缓存、外部写者/未知来源、不完整证明仍拒绝；不是只删掉斜杠模型限制，也不是让缓存残留算通过。

## 精确新增分支

必须同时满足：

1. 当前绑定的私有事务根、原TokenUser SID/HOME/FILETIME/目录身份、固定官方2.99原包摘要、唯一启动回执、原health/ready及原句柄退出0/受控Job空/全部实际监听退出均有当前宿主观察。阶段文件的受保护原字节摘要和ledger一致，当前原Stop秒表仍未超10秒。不能从普通JSON生成真正进程授权，宿主必须保留原句柄与阶段文件排他读/禁止改写、删除的句柄。
2. 精确codex/models_cache.json在before是absent，ready/pre-stop/official-stop都是安全普通单链接文件；采集器不得跟随reparse或未知路径，长度/sha256/base64回算一致。
3. ready→pre-stop→official-stop的原字节、文件ID、owner和DACL完全保持；owner是本轮SID，DACL只限本SID/SYSTEM。任何晚变/外部追加/替换/权限扩展拒绝。
4. 原字节完全等于官方固定包装的序列化结果，模型数组与受保护ready catalog完全一致，全部路由属于**启动前独立冻结**的合成模型声明，不从after生成允许清单。未知字段/额外或重复模型、未知包装/版本/时间值拒绝。
5. audit原前缀不变，ready/pre-stop/official-stop审计后像无晚追加；有本轮PID、启动时间区间、writer/command=startup-cache、target=cache、intent=cache、configSource=file、outcome=written的匹配写入记录。诊断记录是约束之一，不独立认证来源；原包/宿主上下文和原生排他仍是必要前提。
6. 该分支只给予恢复原缺席状态的候选权限，实际删除必须由原五路径事务在必要官方协调与排他句柄内执行，并最终读回。原有cache不能借此分支被清理；未知内容不因名称正确便获准。

## 实际验证

在sandbox拒绝外网/日常数据读写、仅私有临时目录可写的Bun1.4.4环境，用不可变Windows revision4原始合成后像和实际结果回放。原producer-r4源码从df66f5bba固定Git对象只读提取；新候选/桥接及测试保存在.adg/evidence/0.2.23/post-release-20261110/cache-provenance-followup/，不是另一份产品实现。

首次37项通过；补固定官方原包身份、精确官方包装字节和null停止计时拒绝后，第二次39项通过。包括实际revision4旧规则拒绝/候选仅缓存分支可授权，原native-cache路径继续支持、缺上下文保持旧拒绝；缓存变化/替换ID/owner/DACL/新增宽权限、全部阶段未知字段/模型、审计外部追加或错误写者/时间、原来有cache、错HOME/根/SID/FILETIME、缺原证明、Job未空/监听未退/子进程未退/原退出非0、超时/null时间、阶段ledger缺失/失配、unknown/错误阶段/重复路径/坏摘要/长度/链接及缺独立声明均拒绝。另三例证明config/catalog/备份自身失败不会被缓存通过掩盖。

实际Windows旧轮没有执行五项补偿/当前轮N/K/两锁重获，候选回放通过**不得追认旧轮整体通过**。本机不实际删除原Windows缓存，不改变任何原证据。该结果只说明新增分支可在受保护合成上下文内判断，不能证明日常配置的任意写者归属、恶意同SID隔离或实际Win32竞态。
