## 圆角分路与请求数据流（2026-10-28）

用户继续反馈连线布局不好看，并询问连接产生token用量时是否有数据流动效果。本轮在同一个总原型 #connection-map 调整，非功能菜单 → 全景概览；OpenCodex Desktop产品形象、圆形玻璃节点和居中Tab继续保留。此前“没有流动动画”仅适用于历史观察／配置场景；现在增加明确的请求生命周期模拟，仍未接入真实请求。

| 范围／场景 | 本轮调整 | 核对 |
| --- | --- | --- |
| 静态聚合布局 | 原先汇成同一点的大曲线改成圆角折线，入站使用分开的端口与走线位置。普通出站在上方展开，Desktop适配单走下方；Desktop与适配渠道对齐，细小高度差不产生多余折角 | 默认亮暗及900×600实屏；节点文字不被主干穿过 |
| 请求发送中 | 仅当前客户端 → OpenCodex → 当前普通渠道出现蓝色脉冲；其他关系弱化，尚未得到用量时显示“用量待返回” | 浏览器读取两个流动段方向；不把连接／请求开始当成已计费 |
| 生成中 | 当前路径改为回复返回方向，绿色脉冲从渠道经OpenCodex返回客户端；顶部展示输入／输出token。示例输出逐步递增，约45秒完成该轮演示 | 连续截图读取dashoffset从161.993变为321.511，示例输出从384变为444；录制24帧动图 |
| 请求完成 | 脉冲停止，保留示例最终用量；普通历史／配置／适配目标场景无实时脉冲 | DOM及实屏读取完成后flow数为0 |
| 取消／失败 | 停止流动，已有示例输出作为部分用量，标明“用量待核对” | 场景状态检查；不将请求失败等同于零费用 |
| 适配支路 | 无关实时演示仍保留 OpenCodex → Desktop → Krill 的配置关系，不因观察普通请求而将Krill改画成直达；当前适配仅目标配置，没有实际流量演示 | 新检查覆盖没有proxy → krill直达、没有给待接入适配虚构实际观察 |
| 直连 | 本地服务／Desktop移到上方管理区域；客户端与对应渠道按行对齐，本地节点不挡在直连线上。简略信息仍可从节点弹窗查看 | 直连实屏、路径检查；不把管理产品放进每条请求 |
| 展示偏好与生命周期 | 概览设置／显示增加“请求流动效果”“本次token用量”，取消不生效、应用只改本专题。离开专题或页面隐藏停止计数刷新，CSS暂停；低特效及系统减少动态规则隐藏脉冲 | 草稿隔离检查；900暗色流动及低档display=none实屏；系统减少动态仅检查CSS规则，未改系统偏好 |
