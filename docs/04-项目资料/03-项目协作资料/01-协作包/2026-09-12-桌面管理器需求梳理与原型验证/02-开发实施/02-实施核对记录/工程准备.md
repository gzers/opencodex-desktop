# 工程准备

## 1. 只读盘点（2026-09-14）

| 工具 | 本机版本 | 判断 |
|---|---|---|
| Node.js | 26.8.1 | 可运行前端工具链 |
| npm | 11.19.0 | 可管理前端依赖 |
| Rust | 1.95.0 | 可构建 Rust / Tauri 后端 |
| Cargo | 1.95.0 | 可执行测试与构建 |
| Python | 3.11.15 | 可用于报告构建和脚本 |

本轮未安装依赖、未创建工程、未修改环境变量。Tauri CLI、前端依赖和具体 crate 版本在授权后的 WP-01 中通过锁定文件固定。

## 2. 工程初始化方案

```text
/
  src-tauri/
    src/
      commands/
      modules/
      infrastructure/
      errors/
      types/
      state.rs
      lib.rs
    tauri.conf.json
    Cargo.toml
    tests/
  src-ui/
    index.html
    vite.config.ts
    package.json
    tsconfig.json
    src/
      main.ts
      App.vue
      routes/
      components/
      stores/
      commands/
      styles/
    tests/
  docs/
  .gitignore
```

- 前端框架：Vue 3 + TypeScript + Vite + Pinia；不引入 UI 组件库。
- 若实现者更倾向 Svelte 或 React，必须在 WP-01 授权前提出；本方案默认 Vue，因为它与已有报告构建链和组件习惯一致，并且不改变“原生前端、无 UI 库”的冻结结论。
- 样式只使用原型提取的 CSS Design Token。

## 3. 公共接口边界

| 接口 | 责任 | 禁止 |
|---|---|---|
| `TauriCommand` | 前端到后端命令封装与错误转换 | 直接访问文件、网络、Keychain |
| `ProcessRunner` trait | 启停官方进程与注入环境 | 读真实 Keychain、写真实配置 |
| `Keychain` trait | 凭据存取与删除 | 在测试实现中访问真实钥匙串 |
| `HttpClient` trait | WebDAV / 更新请求 | 连接真实远端 |
| `AppError` | 错误码、摘要、脱敏、日志 ID | 输出 S3 级数据 |
| `DataRootService` | 数据根定位、检查、迁移 | 替代备份引擎 |
| `BackupService` | 备份存储、清单、恢复 | 编排业务写入事务 |
| `WriteEngine` | 锁、临时写、原子替换、回滚 | 直接实现业务模块逻辑 |

## 4. 构建与测试命令设计

```bash
# 前端
npm --prefix src-ui ci
npm --prefix src-ui run typecheck
npm --prefix src-ui run test -- --run
npm --prefix src-ui run build

# Rust
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace

# 桌面
cargo tauri dev
cargo tauri build --target aarch64-apple-darwin
```

CI 最小阶段：lint → typecheck → frontend test → backend test → build。签名和公证只保留任务位，不在无凭据的普通 CI 执行。

## 5. 安全与平台约束

- 测试只使用仓库临时目录和 fixture。
- 不读取 `~/.codex`、`~/.claude`、`~/.gemini`、`~/.grok`、`~/.config/opencode`、`~/.hermes`。
- 不连接真实 WebDAV。
- 不访问真实 Keychain。
- 不写 `/usr/local/bin/ocxd`。
- 首个正式验证目标为 `aarch64-apple-darwin`；Windows ARM64 本轮不生成。
- 平台差异封装在 `infrastructure/`，不进入业务模块。

## 6. 分支边界

- `docs/governance-main`：需求、治理、协作包、报告与项目事实；不承载产品源码、构建产物或 CI 实现。
- `codex/implementation-base`：`TASK-OPENCODEX-DESKTOP-01` 起的工程实现、测试、构建配置与实现回执；从文档分支当前状态派生。
- 文档记录实现状态时只引用实现分支和真实证据，不复制源码。

## 7. 授权前置

满足以下条件才初始化：

1. 用户确认 `IMP-OPENCODEX-DESKTOP-01`。
2. 用户确认首批范围：WP-01、WP-21A、WP-22A、WP-17A、WP-18A。
3. 治理机制创建正式 TASK 并授权执行。
4. 产品代码只提交到实现分支，不在 `docs/governance-main` 提交。
