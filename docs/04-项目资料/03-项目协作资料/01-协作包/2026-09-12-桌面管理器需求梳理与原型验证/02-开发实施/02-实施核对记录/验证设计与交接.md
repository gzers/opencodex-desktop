# 验证设计与交接

## 1. 目标

先设计“如何证明正确”，再授权写测试。所有验证分为：隔离功能、隔离系统集成、目标环境验收、发布验证四层。

## 3. 场景路径模板

每个 AC 场景至少登记四类路径：

| 路径 | 必须证明 |
|---|---|
| 正常 | 输入、动作、状态变化、可观察输出 |
| 失败 | 触发点、错误摘要、资源不变 |
| 取消 | 取消点、无副作用或明确清理 |
| 恢复 | 备份、回滚、人工路径或重试结果 |

## 5. 证据格式

每个 TASK 回执至少记录：

```text
evidence_id
task_id
commit_or_artifact
check_name
result: passed | failed
command_or_method
environment: isolation | target-environment | release
fixture_ids
expected
actual
logs_or_screenshot_ref
checked_at
```

失败回执必须保留完整失败原因和清理结果；不允许只写“重试后通过”。

## 6. Mock 与目标环境边界

| 层次 | 可以证明 | 不可以证明 |
|---|---|---|
| 隔离功能 | 状态映射、路径规则、加密、白名单、枚举 | 真实权限、系统行为 |
| 隔离系统集成 | 并发锁、临时目录、fake runner、局部 mock 网络 | 真实 Keychain、真实远端、真实 GUI |
| 目标环境验收 | macOS arm64 的真实 CLI、Keychain、窗口、权限、受控 WebDAV | 未授权平台的行为 |
| 发布验证 | 签名、公证、安装升级回退、更新通道 | 未完成安全确认的发布决策 |

`R-17` 生产面板不进入发布验证前置；发布前单独确认。

## 7. 性能与资源验证

性能与资源预算的权威定义在 DMD §2.5。验证侧只规定如何取证和判定，不重复设置第二套阈值。

| 层次 | 当前执行方式 | 证据 |
|---|---|---|
| 构建体积 | C-03 构建基线记录 `.dmg`、`.app`、首屏 gzip 体积 | 构建产物路径、字节数、构建哈希 |
| 启动与响应 | 本机 release 包脚本化采样；每项 ≥10 次，记录 p50 / p95 | 采样命令、原始样本、剔除样本与原因 |
| CPU / 内存 | 本机采样空闲、后台、轮询三类场景；统计 Tauri 主进程与 WebView 子进程 | 采样时长、进程组、均值与峰值 |
| 内存稳定性 | 8 小时空闲观察，不混入重型业务操作 | 开始 / 结束内存、增长值、异常事件 |
| 数据根空间 | 使用隔离临时数据根做首次初始化采样 | 初始化路径、文件数、总字节数 |
| 界面流畅度 | 遍历常规滚动、切换、列表操作；记录掉帧比例 | 操作脚本、持续时长、掉帧统计 |

判定规则：

- 全部性能证据以 `aarch64-apple-darwin` release 构建为准。
- CI 先覆盖可确定性较强的包体积和前端体积；启动、CPU、内存、流畅度先做本机采样。
- 性能证据与功能证据分开保存，但不允许只记录“通过”；必须带样本数、统计值、环境和命令。
- 任一预算未达标不得进入阶段验收；同一指标连续两次不达标触发性能回退。
