# 多平台扩展管理形式建议

日期：2026-10-14。状态：候选设计，尚未确认或制作新原型。依据见[平台调研](OpenCodex平台清单与扩展能力调研.md)。

## 1. 推荐组织

保留侧栏“拓展”，页内采用 Skills、MCP、客户端三个 Tab。客户端页管理目标平台及能力，Skills / MCP 管理资源；沿用公共页面 Tab 固定规则。

| 表面 | 主要内容 | 日常动作 |
|---|---|---|
| Skills / MCP 列表 | 名称、必要说明、来源 / 版本、目标摘要、异常与单条动作 | 查找、查看详情、管理目标、更新 / 编辑，多选后批量操作 |
| 目标管理弹窗 | 当前资源、可搜索目标、选择意图与实际状态、变更预览 | 增加 / 移除目标或更新受管投影 |
| 客户端页 | 平台、运行端 / 实例、能力、已发现落点与异常 | 发现、查看资源、进入适配设置、处理异常 |

顶部改为紧凑的资源统计和异常入口。平台筛选采用带搜索的选择器，避免统计区和页内导航随着平台增加铺成长串品牌按钮。

## 2. 资源列表

一个目标摘要列替代逐平台固定列，例如“已选 6 个 · 已同步 5 个”，有失败再显示“失败 1”。可辅以常用两项名称及其余数量，图标不承担唯一识别职责。点击摘要或“管理目标”打开同一弹窗。

“已选择”描述意图，“已同步”描述本管理器的投影，“客户端可用”描述已观察发现关系。未获得客户端实际读取证据时，只声称“配置已写入 / 目录已投影”，不声称运行中的 Agent 已加载。

名称与说明打开资源详情；目标摘要打开目标管理；更新、编辑、删除点名资源。不设置含糊的整行默认动作。最小窗口可将来源和摘要放在名称下方，保持内容与操作可见，具体尺寸后续实测。

## 3. 目标管理弹窗

推荐独立模态弹窗，背后保留资源位置。页内反复展开会让每项资源都携带平台面板，本轮不采用。标题点名资源与类型，搜索、已选总数和底部动作常驻，中间列表独立滚动；尺寸由 900 × 600、1180 × 760 原型检查确定。

目标行显示客户端名称、必要实例 / profile / 项目区分、当前资源类型的能力与适配状态、实际落点和投影状态，再提供选择或不可操作原因。有差异 / 失败时能进入具体原因。

默认先显示本机已发现且该资源类型适配可用的目标，同时保留已选择但暂不可用的项；“显示全部客户端”可查看未安装和待适配。未安装、不支持、待核实分别标注，不合并成“未开启”。搜索不会隐藏全部已选数量。

操作流程：

1. 选择只进入弹窗草稿，取消放弃本次变化；搜索 / 筛选保留草稿。
2. “预览变更”列出新增、更新、移除、无需变化、无法处理和实际落点。
3. 明确提交后沿既有受控写入流程执行，运行中冻结资源与目标范围。
4. 逐目标显示结果；成功项保留，失败可单独重试，部分成功不能显示成整批成功。
5. 更新资源与客户端视图，并提示新会话、重载或重启等实际生效条件。

取消选择的默认动作是移除本管理器拥有的该目标投影，保留源资源。原生独立安装、插件提供、共享目录发现需要另行说明，不随此动作删除。

## 4. 客户端页

纵向列表支持名称搜索和“已发现 / 已配置 / 有异常 / 待适配”筛选。每行独立显示 Skills / MCP 的能力和适配状态；只有模型接入能力的平台可留在调查目录，不能因此提供扩展开关。

详情查看来源、版本、实际落点、资源与生效说明；进入该客户端 Skills / MCP 列表时带入筛选，返回保留位置。源目录、默认同步方式、全局冲突策略仍位于设置页的扩展管理；客户端路径和兼容项从详情进入同一设置数据，不维护两份配置。

“发现 / 添加目标”识别已安装客户端，或指定已支持适配器的落点。任意手填平台 / 路径只能形成待核实对象，不能自动获得写入能力；首次发现也不自动给全部资源新增目标。

## 5. 平台与实际目标

平台是产品目录项，目标是实际配置实例。同平台可以有不同主目录、项目或 profile；不同运行端也可能读取同一文件。

候选目标身份包含平台 ID、运行端 / 实例、作用域和解析后的落点。只用品牌 ID 无法处理 Aside 多 profile、Cline CLI / IDE、Codex / omo 相关落点。实施时检查既有 ClientId、ClientTarget 和分发意图的兼容读取；迁移方案另行评审。

第一轮建议以已有用户级目标为主，关系预留项目 / profile 识别。项目写入、多账户和远端 / 云端分发需独立核实边界，不能因界面有标签而扩大当前写入范围。

## 6. 共享目录与重复发现

Cursor、Kilo 可能直接读取 .agents 或兼容目录，因此需要同时记录源资源、客户端发现关系和本管理器的投影。建议采用“经共享目录可用 / 原生副本 / 插件提供 / 受管链接或复制”等来源状态。

- 共享目录已可发现时，是否建立专用投影在预览中说明，不静默重复复制。
- 取消专用投影后，若共享目录仍可见，继续显示该事实。
- 去重依据资源身份和实际路径；同名不同内容的原生副本保留为差异。
- 多目标解析到同一物理落点时合并实际写入并标注影响；不同意图有冲突时先说明，避免互相撤销。
- 源库为 .agents/skills 时，停止某平台投影不等价于删除共享源。

本轮只是关系设计，尚未实现扫描、身份判断或去重。

## 7. 批量管理

资源多选后，批量目标管理默认“增加目标”或“移除目标”，只修改显式选中的资源与目标，保留其他意图。“替换所有目标”如需要，应成为明确的独立动作。

批量选择显示“选中当前筛选结果的 N 个可用目标”，同时显示全部已选数；不把待核实 / 不可写目标纳入可用选择，也不静默选中隐藏平台。混合关系采用未选 / 部分选 / 全选状态。

预览列出资源数、目标数与实际落点数，它们可能不同。结果按资源与目标保留失败和冲突，重试只针对选择的未完成项。导入客户端配置形成候选合并，不自动把全部读取到的平台设为目标。

## 8. 备选形式

| 形式 | 适用处 | 本轮判断 |
|---|---|---|
| 每平台固定列 | 少量目标直接切换 | 23 列预计约 1602 px，退出默认列表 |
| 自动换行图标 | 临时低密度展示 | 行高随平台变化，难对齐且缺能力 / 异常说明 |
| 每平台一个 Tab | 少量独立页面 | 平台增加后导航也拥挤，改用客户端搜索列表 |
| 资源 × 平台矩阵 | 集中检查覆盖与差异 | 可作为后续高级视图，非窄窗日常入口 |
| 资源摘要 + 目标弹窗 + 客户端页 | 日常管理与多目标配置 | 推荐，两个入口观察同一份分发关系 |

## 9. 后续原型

实际项目为 OpenCodex 桌面管理器，产品端为 Desktop。[唯一总原型](../../../../../01-项目支撑资料/01-产品原型/原型/index.html#extensions)继续作为活动入口，未来增加“多平台扩展 · 版本未定”设计范围，覆盖：

- Skills / MCP 摘要、平台筛选、多选；
- 单条 / 批量弹窗的搜索、草稿、预览、取消、执行与部分失败；
- 客户端页、反向资源视图、设置关联；
- 已发现、未安装、不支持、待核实、冲突、共享目录可用和无结果；
- 六个平台、23 项目录、50 个模拟目标；宽窄窗口、暗色、键盘与焦点回归。

本轮完成分析和既有原型观察。最终平台名单、项目写入、交互及版本待评审；导入导出、备份和 WebDAV 引用已有公共方案，本机目标路径不能自动成为跨机稳定绑定。
