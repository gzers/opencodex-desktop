## 2. 客户端落点与适配器

### 2.1 适配器字段

六个客户端的键名、容器类型、命令形态、环境变量键名与文件格式**逐客户端不同**，必须按客户端分别实现适配器，**不得假定统一 schema**。

| 字段 | 说明 |
|---|---|
| `client_id` | 稳定标识，内部引用与启用矩阵的键 |
| 显示名 | 界面展示用 |
| MCP 配置落点 | 文件路径形态 |
| 格式 | TOML / JSON / JSONC / YAML |
| MCP 键 | 服务器集合在文件里的键名 |
| 容器形状 | 映射 / 数组 |
| 命令形态 | `command` + `args` 两字段，或 `command` 数组 |
| 环境变量键 | `env` / `environment` |
| Skills 目录 | Skills 安装落点 |
| 官方写入者 | 该节点是否也被官方 CLI 写入；是则只能受控共享写入 |

### 2.4 核实发现（长期事实）

| ID | 结论 |
|---|---|
| `INT-F-1` | 六个客户端**全部存在官方写入者**，MCP 节点是**共享节点**。「不制造写者竞争」不能靠独占满足，只能靠**受控共享写入**：文件锁 + 写入前内容摘要比对 + 备份 + 原子替换 + 显式确认。 |
| `INT-F-2` | MCP 配置形状在各客户端之间**不统一**（键名、容器类型、命令形态、环境变量键名、格式都不同），因此「节点级写回」必须**每客户端独立实现**。 |
| `INT-F-3` | 凭据处理有官方先例可对齐：Codex 拒绝 `mcp_servers` 中的内联 `bearer_token`，要求使用 `bearer_token_env_var`。本产品采用同一原则——**只允许写入环境变量引用，不写入内联凭据值**。 |
| `INT-F-4` | 官方项目自身也在建设扩展编辑能力。本产品在 IMP 明确「只做跨客户端统一视图与受控写入，不复制官方编辑器」。 |

## 3. 单一真相源与投影

```text
管理器统一扩展配置（含每个能力项的启用矩阵）
        │  逐客户端投影
        ▼
各客户端 live 配置文件
```

- 管理器维护统一事实；客户端配置是**投影**（`ARC-01`）。
- 每个能力项记录它在哪些客户端启用，启停以投影方式同步到对应文件。
- 导入方向相反：从客户端 live 配置读回并合并进统一结构，**不覆盖**其他客户端的启用状态。
- 逐客户端适配器需要四类能力：导入、全量同步、单条同步、移除。

## 4. 写入边界

| | 范围 |
|---|---|
| **允许写入** | Skills 目录同步；各客户端的 MCP 服务器节点；**数据根内私有前缀 `runtime/opencodex/`（托管安装/卸载）** |
| **禁止写入** | provider、路由、模型映射，以及 OpenCodex 核心运行配置 |

被禁止的内容一律走官方 CLI；本产品不提供写入通道。

**托管安装的边界**：安装/卸载作用在**私有前缀**（默认 `runtime/opencodex/` 与 `runtime/bin/ocx`，等价于一个私有 npm 项目）；安装位置可由用户显式改为其它目录，但**系统保护目录必须拒绝**（显式选择即授权，仍不得写全局 npm 前缀）；**禁止**写系统目录、全局 npm 前缀，也**禁止**触碰 `~/.codex/config.toml`、`OPENCODEX_HOME` 内的官方配置（官方 `ocx uninstall` 的删除面由官方命令承担，本产品只做备份、二次确认与引导执行）。联网安装与离线 `file.tgz` 导入都必须显式确认；卸载前必须有可定位备份与回滚依据（包名 + 版本 + 记录）。

**联网安装的代理是临时参数**（2026-09-25）：网络不通时可填 HTTP / SOCKS5 代理，应用只把它作为**本次安装**的 `--proxy` 参数传给 npm（SOCKS5 用 `socks5h://`）；**不写系统代理、不改全局 npm 配置、不持久化凭据**，关闭弹窗即失效。

**托管安装的已确认控制**（安全评审 `安全评审输入.md` §12.4 / §16.6，2026-09-25，Rev 9）：

- **只允许官方包**：包名硬编码 `@bitkyc08/opencodex`，不接受用户改写；安装后回读 `package.json` 校验 `name` / `version` 与请求值一致，不一致即失败回滚；registry TLS 校验失败**默认拒绝**、不提供「忽略证书」。
- **安装脚本默认禁用**：默认 `--ignore-scripts`；若因此缺 bin，**只在用户显式开启并二次确认（高风险提示）后**才允许带脚本重跑；命令在受控环境（目标前缀为工作目录、受限 `PATH`、不继承凭据环境变量）下执行。
- **离线包解包加固**：只接受 `.tgz` / `.tar.gz`（不自动二次解包）；逐条规范化条目路径，任一条越出目标根即整体拒绝；拒绝符号链接与硬链接条目；设条目数与解压总大小上限；先解到临时目录、校验通过后再原子就位。
- **目标前缀路径校验**：规范化真实路径；拒绝符号链接与非目录；**拒绝系统保护目录**（Unix `/`、`/usr`、`/etc`、`/System`、`/Library` 等；Windows 系统盘根、`Windows`、`Program Files*`、`ProgramData`）；与扩展管理复用同一套路径边界校验。
- **卸载判定**：一级卸载只删**安装记录登记的托管前缀**，删除前校验安装记录与包内 `name` 匹配、目录非符号链接；二级卸载本产品**不删任何文件**，只备份 + 二次确认 + 引导官方 `ocx uninstall`。
- **代理与明细掩码**：代理地址中的 `user:pass@` 掩码后才进界面与日志；代理与令牌**不写安装记录**；安装明细只在弹窗就地展示，落日志统一走掩码层；用户 `~/.npmrc` 令牌本产品不读取、不解码、不展示。**含凭据的代理不改写命令行参数**（argv 可被同机其它进程读取）：改写临时 `--userconfig`（Unix `0600`，安装结束含失败与取消即删），凭据不进 argv（IMP `FZ-50`）。

**非目标文件不可触碰**：只写 MCP 节点所在文件，且只改该节点；不得改写同目录的凭据、认证等非目标文件（例如 Codex 的 `auth.json`）。

## 5. 写入规则

| ID | 规则 | 要求 |
|---|---|---|
| `WR-01` | 目标校验 | 目标必须是**普通文件**；符号链接、FIFO、设备文件或越出预期根目录的路径一律拒绝写入，并给出可读原因 |
| `WR-02` | 前置备份 | 任何写入前生成可恢复备份；备份失败即阻断（`ARC-04`） |
| `WR-03` | 原子替换 | 同目录临时文件写入后原子替换；替换后保留原文件权限（`ARC-03`） |
| `WR-04` | 节点级写回 | 只改目标节点，保留未知字段与注释；解析失败即拒绝，不做"尽力而为"的部分写回（`ARC-02`） |
| `WR-05` | 并发互斥 | 每个 `resolved_config_path` 一把锁，锁文件为 `<target>.lock`；先获取 `app.lock` 再获取目标锁，覆盖校验、备份、写入与复验（`FZ-26`） |
| `WR-06` | 冲突处理 | 检测到外部改写或客户端间不一致时进入待处理，**不静默覆盖** |
| `WR-07` | 可恢复删除 | 卸载 Skills、删除 MCP 等删除类操作进入回收区，可恢复 |
| `WR-08` | 串行化 | 扩展配置写入由**单一状态锁**串行化，避免并发动作互相覆盖 |
| `WR-09` | 未安装不落盘 | 目标客户端未安装时跳过写入与删除，**且不创建任何文件或目录**（`ARC-09`） |
| `WR-10` | 权限收紧 | 涉及凭据的配置文件在 Unix 上固定 `0600`，新文件与替换后的文件都生效 |
| `WR-11` | 路径边界 | 校验写入目标与源存储不重叠、不互为别名，并拒绝符号链接逃逸 |

写入事务的执行顺序、失败点处理与实体字段见 `领域模型.md` 的 `WriteTransaction`。

## 6. 敏感值与凭据

### 6.1 数据分级

| 级别 | 数据 | 示例 | 落点 / 流向 | 约束 |
|---|---|---|---|---|
| S0 公开 | 应用版本、官方项目信息 | `v0.1.0`、npm 包名 | 界面 | 无 |
| S1 内部 | 安装路径、版本、运行状态、端口、进程标识、数据根路径；**托管安装的目标路径、包名与版本、安装记录、registry 地址、不含凭据的代理地址** | `~/.npm-global/...`、端口号、`runtime/opencodex/`、`@bitkyc08/opencodex@0.3.1` | 界面、`manager state`、数据根 `runtime/` | 不上传、不进仓库 |
| S2 敏感 | 日志正文、备份内容、同步索引摘要、冲突记录、Skills 文件内容、MCP 配置结构；**安装命令行明细、离线包内容与包内元数据** | 最近错误、`mcp_servers` 节点、`npm http fetch GET 200 …` | `logs` `backups` `sync state`；安装明细在弹窗就地展示 | 只读脱敏；可定位可校验；写日志前掩码 |
| S3 凭据 | API key、token、Authorization、WebDAV 账号口令、MCP 环境变量值；**代理地址中的 `user:pass@`、npm 令牌** | `env.OPENAI_API_KEY`、`http://user:pass@proxy:7890` | 系统钥匙串 | 默认掩码；禁止进仓库 / 日志 / 命令行参数 / 明文文件；导出与同步载荷只携带引用 |

### 6.2 字段级判定

| 字段 | 级别 | 处理 |
|---|---|---|
| `env` 值 | S3 | 默认掩码；只写环境变量引用，不写内联值 |
| `args` | S3（潜在） | 一律按潜在敏感值处理，默认掩码；仅结构化展示 |
| `headers` | S3（潜在） | 同 `args` |
| `env` 键名 | S1 | 可展示 |
| `command` | S1 | 必须展示，作为执行边界确认的一部分 |
| MCP 服务器名称 | S1 | 可展示 |
| WebDAV 口令 | S3 | 掩码；只经内存；2026-09-20 起同步不再有额外加密口令 |
| 旧容器导出/导入口令 | S3 | 只经内存 / 标准输入；**不得进入命令行参数**；仅读取旧版加密容器时需要 |
| 安装路径、版本、端口、进程标识 | S1 | 可展示，不上传 |
| 日志正文 | S2 | 只读脱敏 |

### 6.3 处理规则

- S3 **不得**进入仓库、Markdown、日志、命令行参数或未加密文件。
- **敏感值范围包含** `env`、`args`、`headers`：三者一律按潜在敏感值处理，默认掩码。
- 掩码必须在**取值之前**完成，不得"先明文取回再在界面掩码"；掩码长度**不泄漏真实值长度**。
- 唯一例外：用户主动进入编辑或校验时，按字段**短暂显示**，离开即恢复掩码。
- 禁止落点：日志、错误信息、命令行参数、导出摘要、通知正文。
- MCP 的 `command` / `args` / `env` 具备执行本地程序的能力：必须展示执行边界并经用户**显式确认**，不得静默执行任意本地程序。
- 绝对路径、shell 元字符、下载执行类模式（如管道执行远程脚本）标记为**高风险**并额外提示。

## 7. 信任模型

| 对象 | 信任假设 | 结论 |
|---|---|---|
| WebDAV 远端 | **不可信** | 2026-09-20 起不再客户端加密：远端保存未加密配置，哈希只用于检测损坏与回放，**不构成对恶意远端的真实性保护**；必须使用 HTTPS 与服务端认证、选择可信远端，产品说明与界面不得暗示端到端加密 |
| WebDAV 连接 | 需要证书校验 | 证书校验失败**默认拒绝**，且**不提供**"忽略证书"选项；错误文案按连接 / 下载 / 上传分支，不显示凭据（`FZ-41`） |
| 外部客户端配置 | 可能被第三方改写 | 写入前比对内容摘要，冲突进入待处理 |
| 官方 CLI | 权威写入者 | 不与其争夺 provider / 路由 / 模型映射的写入权 |
| 应用自身更新包 | 需要签名校验 | 签名校验通过后才安装 |

## 8. 明确不做

- 不重写 OpenCodex 核心，不绕过官方 API。
- 不管理**全局** npm 前缀，不写系统目录，不替代官方 `ocx update` 事务；托管安装仅限自有数据根内的私有前缀。
- 不自行删除官方 service / shim / config（`ocx uninstall` 的执行权威属于官方 CLI）。
- 不接管 `codex-shim`，不安装或管理 launchd。
- 不写入 provider、路由、模型映射等核心运行配置。
- 不自动覆盖外部 provider 托管配置，只检测、解释并引导官方 `restore`。
- 不明文迁移或同步凭据。
