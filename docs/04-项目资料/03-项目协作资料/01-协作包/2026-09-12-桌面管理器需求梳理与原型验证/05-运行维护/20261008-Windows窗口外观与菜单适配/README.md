## 来源与范围修正

用户本轮明确指出本目录“是不是没做，这个也算 0.1.9 的内容才对”。核对发现，本地文档提交 `a4b062198c0bb75c327bd61259d8942f9c685aee` 及本轮 fetch 后的远端 `docs/governance-main@bc6561acac5075bce76babfc367ff18067b17efe` 均不含该目录。本次据用户给定路径补建维护入口，确认版本归属并登记实施遗漏。

这次登记没有取得另一端可能已有的原专题全文、外观原型或配对截图，不能凭目录名推定完整设计。此前 [画质策略交接](../20261006-Windows启动崩溃与图标适配/分析/11-画质用户自主策略与Windows接续排查.md) 将标题栏／Mica／菜单栏作为独立维护范围；**独立专题不代表排除出 0.1.9**。本轮纠正的是版本完整范围及完成口径。

这里的“菜单”必须分别核对：页面 `.select-menu` 是 WebView DOM；应用菜单栏／托盘菜单是原生菜单。页面模糊与选项键盘检查不能作为原生菜单栏颜色、层级、快捷键、焦点及操作功能的验收。

## 接续与完成条件

1. 接续本专题原文与已确认设计；若材料尚在另一端，仅登记缺失，不能将推测的外观方案当作用户决定。
2. 在同一 0.1.9 feature 分支核对原生窗口外观／标题栏／菜单接线，补实际实现与回归；已有 macOS 路径和菜单动作应保持可用。
3. 使用隔离候选采集原生窗口截图、主题切换、菜单动作／快捷键／焦点及双权限、实际 DPI 的证据。WebView DPR 模拟不能代替标题栏和系统菜单的物理 DPI 验收。
4. 只有本专题和已有玻璃／画质专题的必需门禁都完成，才能将 0.1.9 实施标为完成。安装、合并、推送和发布仍遵循用户另行授权边界。

本轮此补充仅登记与修正文档，未为本专题改源码，也未宣称原生外观已修复。日常安装继续保留，代码和文档分支分开，本地提交不推送。
