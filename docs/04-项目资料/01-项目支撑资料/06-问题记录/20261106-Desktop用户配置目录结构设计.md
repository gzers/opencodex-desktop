# Desktop用户配置目录结构设计

2026-11-06，Asia/Shanghai。**最新根名：.codex-desktop；OpenCodex实例HOME在其下，程序保留Desktop原位置。** 用户本轮明确以此重新规划并分端说明，本稿替代Git提交74e8a6aa2中的.opencodex-desktop/data及更早AppData/Application Support建议。只设计/记录，未开发、迁移或加入0.2.23六项范围；不把新目标写成当前实现。

## 1. 拥有者与HOME边界

| 对象 | 拥有者与职责 |
| --- | --- |
| 用户.codex-desktop | 本项目Desktop的设置、绑定、布局、日志、备份和本机同步状态。 |
| 用户.codex-desktop/opencodex-home | 原版OpenCodex实例的OPENCODEX_HOME：配置、账号/认证、运行记录/锁、用量等；不是纯配置，不含程序安装包。 |
| 用户.opencodex/ocx-homes | 原版跨HOME实例登记，仅定位实际HOME，由原版维护，非渠道配置副本。 |
| 原有CODEX_HOME或用户.codex | Codex客户端配置、授权、会话、生成目录；不移入Desktop数据根。 |
| 现有Desktop/OpenCodex程序位置 | 可执行代码、依赖、资源及启动入口；本轮不搬、不新装另一份。 |

系统HOME/USERPROFILE仍为当前OS用户主目录，不能设置成Desktop数据根。OPENCODEX_HOME才指向上述子目录。Desktop渠道界面继续读取/修改原版config.json，manager-state里的布局/采用关系不成为第二份渠道权威。

根名按用户最新拼写.codex-desktop，与原版已使用的.opencodex-desktop、.opencodex以及Codex的.codex分开，不因名称相似自动接管。此前data层是为在原版同名根避让而设，现在不再保留该无必要层级。新根已有未知/损坏/其它拥有者数据时明确停止，不能当空覆盖。

## 2. macOS端位置

| 对象 | 目标位置 |
| --- | --- |
| Desktop程序 | 原实际.app安装位置，例如/Applications/<实际应用名>.app；用户安装在~/Applications时保持实际路径。 |
| OpenCodex程序及入口 | 原已登记前缀/入口，如旧runtime/opencodex、runtime/bin/ocx，保留不移动。 |
| Desktop用户根 | /Users/<用户>/.codex-desktop |
| OPENCODEX_HOME | /Users/<用户>/.codex-desktop/opencodex-home |
| 原版登记 | /Users/<用户>/.opencodex/ocx-homes/<hash>.json |
| Codex客户端 | 原有CODEX_HOME或/Users/<用户>/.codex |

~~~text
<现有Desktop安装位置>/<应用>.app/      程序及资源不搬
<现有明确OpenCodex前缀及入口>          托管程序/依赖/入口不搬

/Users/<用户>/
├── .codex-desktop/                   本管理器用户根（目标）
│   ├── manager-location.json         唯一活动数据根定位（新增设计，默认指向本根）
│   ├── manager-startup.lock          本用户固定入口协调锁（新增设计）
│   ├── manager-state/                Desktop拥有

│   │   ├── preferences.json          主题/缩放/界面偏好
│   │   ├── runtime.json              既有程序前缀/入口、来源与安装历史
│   │   ├── model-channel-layout.json 布局/采用关系，不复制渠道权威
│   │   ├── notifications.json        通知/任务记录
│   │   ├── sync-endpoints.json       WebDAV连接及秘密引用
│   │   ├── transfer-choices.json     本机传输选择/范围
│   │   ├── credentials/             已有秘密文件后端，私有权限
│   │   ├── skills-store/            已有受管Skill源
│   │   ├── config-uploads/          冻结上传计划
│   │   ├── transfer-results/         原操作回执
│   │   ├── app.lock                  活动根独占锁
│   │   └── …                        模版库、内容版本、事务等保持原相对路径
│   ├── opencodex-home/               原版拥有，即OPENCODEX_HOME
│   │   ├── config.json               渠道/模型/路由/实例port权威
│   │   ├── runtime-port.json         原版实际PID/端口/身份材料
│   │   └── …                        原版账号/认证/用量/日志/锁等
│   ├── backups/                     Desktop保护备份与恢复材料
│   ├── logs/                        Desktop日志，不替代原版日志
│   ├── cache/                       可重建缓存/下载
│   ├── sync-state/                  本机同步状态/索引
│   └── exports/                     默认导出；用户另选可外置
├── .opencodex/
│   ├── ocx-homes/<hash>.json         原版登记上述实际HOME，仅定位
│   └── config.json                  若有独立默认CLI配置，保留不合并
├── .codex/                          客户端原有配置/授权/会话，不搬
└── .opencodex-desktop/               若存在：原版Desktop终端入口等，不接管
~~~

敏感目录0700、敏感文件0600，原系统安全存储保持；钥匙串、WebView/Cookie等OS管理文件可继续在平台用户目录，不为了“集中”强行搬入点目录。旧~/Library/Application Support/com.gzers.opencodex.desktop为迁移来源，不直接删除；新用户可读目录名不要求更改Tauri内部应用标识。

不同Profile下的同名目录是不同完整路径；根路径由当前用户OS API解析，不从工作目录/程序目录或另一用户环境推断。NTFS ACL与本用户DPAPI仍是必要保护；点前缀不自动等于隐藏或加密。WebView2、系统安装/更新、OS凭据等保留平台管理的用户路径，不强搬。示例及省略号是职责范围与代表文件，真实其它文件沿原版/既有消费者清单，不为美化结构整体改名。

## 4. 定位、程序与端口合同

- 固定用户根manager-location.json只定位活动数据根，默认本根；manager-state/data-root.json负责结构/内部或外部HOME绑定。新Schema须消除重复active_data_root权威，旧HKCU或旧元数据只作受控迁入来源，不能长存双写两套定位。未知/损坏不当空，不静默创建替代配置。
- 用户自定义活动数据根仍可通过同一定位选择，默认内部HOME位于所选根下。现有明确外置OPENCODEX_HOME不自动复制，用户采用迁移后再变更绑定；不合并用户独立CLI原有.opencodex/config.json。
- 程序与配置根显式解耦：runtime.json中的程序前缀/入口仍是原路径；启动/升级/卸载/恢复不能按新根拼另一份runtime。当前代码尚有按数据根推导runtime路径，需要后续接线与版本化迁移，不能仅改环境变量假称完成。共享程序更新还需原所有权/其它用户活动检查。
- 启动原版传本用户OPENCODEX_HOME，系统HOME/USERPROFILE和CODEX_HOME保持真实绑定；原版负责登记、监听、鉴权和运行事实。Desktop不手写ocx-homes代替身份验证，不新增一层HTTP代理。
- 同机TCP端口仍共享。复用原版config.port/公开启动能力与真实绑定结果，Desktop不另养第二份端口权威，也不能仅凭health200复用其它用户服务；需核对进程归属、令牌与各用户客户端指向。端口/PID/路径/本机凭据不作普通跨设备同步对象。

## 5. 迁移、备份及卸载

1. 识别实际当前锚点、活动根、内/外部HOME、程序前缀和用户数据归属；macOS旧Application Support、Windows旧AppData/安装旁data/合法自定义根保留为来源。不能因为新目录缺失而静默开空根导致渠道“消失”。
2. 用户采用后暂停相关写者、准备对应保护备份，按自有清单复制本用户配置/业务/持久状态，核对摘要/权限/引用；程序包不复制不搬，外部HOME不擅动。同SID秘密保留并校验，不自动跨SID克隆；共享旧根无可信归属时不能复制全份给每个用户。
3. 原PID/端口/锁/瞬时身份不当作可迁移事实。原版账本/恢复材料内含旧路径时按其契约转换/恢复，不整文件字符串替换；真实用量/业务记录保留，原版启动后再生成身份及登记。
4. 校验成功提交唯一定位、重启重绑定并读回；中断/失败保留旧绑定/旧数据并提供恢复。旧目录不自动删，不删除锁来绕过仍在运行的实例。
5. 卸载默认保留用户配置，明确清理只针对本管理器拥有清单/用户范围；不整删.opencodex、.opencodex-desktop、.codex或其它用户数据。程序卸载按真实运行来源独立处理，不把新配置根存在当作程序拥有权证明。
