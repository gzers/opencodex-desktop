02 · 开发实施协作包是干什么的

开发实施包不是把 docs/03-开发实施 复制一份，也不是再写一份技术契约。它是给你看的准备材料：把实施前置条件、工作包、测试口径和打包准备收拢成一份能读的东西。

它应该放什么

  • 实施前核对清单：确认 IMP、验收口径、开工授权
  • 工作包拆分草案：22 个 WP 的依赖、产出物、验收点
  • 实施核对记录：目录、状态、加密、扩展、同步、CLI 与 IMP 的对照
  • 测试基线：AC-01 ~ AC-13 的正常 / 失败 / 取消 / 恢复场景
  • 打包与签名准备：Tauri、macOS 签名、更新通道
  • 可读报告：HTML 单页，方便你不用翻一堆 Markdown

它不应该放什么

  • 不复制 IMP-OPENCODEX-DESKTOP-01 的全部字段，避免出现第二个契约源
  • 不写代码实现结论；没跑过的东西不能标「已通过」
  • 不把确认讨论当成正式事实；确认后要回写 docs/03-开发实施
  • 不放真实凭据、真实路径里的敏感内容

看权威事实

  • docs/02-项目核心：项目是什么、边界在哪
  • docs/03-开发实施/IMP-OPENCODEX-DESKTOP-01.md：技术怎么做、参数是什么
  • DMD-OPENCODEX-DESKTOP-MANAGER：需求与验收权威

看实施包

  • 一眼看清「现在能开工什么、还不能开工什么」
  • 把 WP-01 ~ WP-22 转成可执行的 TASK 草案
  • 把 46 项冻结按工作包对上，确认没有漏项
  • 准备测试 fixture 与打包脚手架

04 · 契约已经锁住了什么

IMP 不只是方向，已经把字段、参数和阈值定死。这里只挑影响开工顺序最大的部分：

契约域 已冻结的关键点
数据根 七个物理目录：manager-state / opencodex-home / backups / logs / exports / cache / sync-state；结构版本 1
备份 每类最近 20 份、保留 30 天；备份清单含 SHA-256、字节数、文件数、可恢复标记
状态 内部与 --json 都用 runtime / connection / operation / gate；轮询 3 秒 / 15 秒，失败指数退避
进程 启动 20 秒、停止 10 秒；pending 判定 3 秒 ×10；取消不发 SIGKILL
加密 Argon2id：256 MiB、迭代 3、并行 2、盐 16 字节；AES-256-GCM：12 字节 nonce
导入 明文 128 MiB、密文 512 MiB、数组 20,000 条；失败不部分写入
扩展 六客户端默认可写；用户可逐个关闭；未安装跳过且不落盘
写入 目标文件锁 3 秒；单一状态锁；SHA-256 比对；备份失败阻断
同步 manifest 独立 AEAD；AAD 绑定格式、版本、设备名；旧快照进冲突
CLI 命令固定为 ocxd；schema_version=1；IPC socket 权限 0600
审计 保留 90 天 / 5,000 条；只记参数键，不记值
核对结果：IMP 覆盖项目核心 46 个 ⏳ 项，编号连续无缺号。`docs/03-开发实施/IMP-OPENCODEX-DESKTOP-01.md` 现在是唯一实施契约入口。

05 · 22 个工作包怎么用

工作包不是为了「看起来工作量很大」，而是为了把需求、验收、依赖和安全控制拆到能建 TASK 的粒度。

先拆横切底座

WP-01 工程底座、WP-03 数据根与备份、WP-17 写入引擎、WP-21 测试基线、WP-22 打包签名。这些不做稳，后面的业务模块会反复返工。

P0 先打通主线

WP-02 发现 → WP-04 启停 → WP-05 状态 → WP-06 日志诊断通知 → WP-07 面板 → WP-08 风险恢复 → WP-09 升级引导 → WP-10 托盘 → WP-11 关于。

P1 处理写入与更新

WP-12 自更新、WP-13 / WP-14 加密导出导入、WP-15 Skills、WP-16 MCP、WP-17 写入引擎、WP-18 CLI / IPC。

P2 最后做同步

WP-19 WebDAV。它依赖加密、备份和写入引擎，不能提前抢跑。

先看懂 P0 / P1 / P2

P0 / P1 / P2 不是「重要 / 不重要」，而是交付顺序和前置依赖。原型里出现的所有功能都要实现，只是先做谁、后做谁不同。

分段 它解决什么 覆盖需求 为什么放这里
P0 · 运行管理主线 让 OpenCodex 在桌面壳里可用：发现安装、管理数据目录、启停进程、看状态日志、打开面板、识别风险、引导升级、托盘菜单和关于页 REQ-01 ~ REQ-12、REQ-16、REQ-19 ~ REQ-21 这是最低可用的日常入口；不先打通它，后面的安全能力和同步都没有稳定宿主
P1 · 写入、迁移与更新 开始碰真实文件和系统边界：加密导出导入、应用自更新、Skills / MCP 管理、受控写入、CLI / IPC REQ-13、REQ-14、REQ-17、REQ-18、REQ-22 ~ REQ-27 这些能力会写文件、碰凭据或开本地端口，需要复用 P0 的底座和备份机制
P2 · 跨机同步 WebDAV 加密同步与冲突处理 REQ-15 它同时依赖加密容器、备份、写入引擎和冲突模型，必须排在前面稳定之后

一句话：P0 是“桌面壳能日常用”；P1 是“敢写文件、能迁移、能自更新”；P2 是“敢跨机器同步”。

06 · 开工前要准备什么

不是所有准备都要等 TASK。以下 5 类材料可以现在做，做的时候不写业务代码、不碰真实数据。

准备项 现在能做什么 产出位置
实施前核对 把 46 项 FZ 分配到工作包，标记「确认 / 有疑问」 02-实施核对记录/
TASK 拆分草案 22 个 WP → TASK 候选，不创建正式 TASK 01-方案资料/
测试基线 AC-01 ~ AC-13 的 fixture 和四路径矩阵 02-实施核对记录/
打包脚手架 Tauri 目录、macOS 签名清单、更新通道占位 01-方案资料/
实施报告 本页 HTML，给评审和日常翻阅用 输出/实施与工作包报告/
这些准备也不等于开工授权。它们只是把「确认后要执行什么」提前想清楚，避免拿到授权后才开始补文档。
