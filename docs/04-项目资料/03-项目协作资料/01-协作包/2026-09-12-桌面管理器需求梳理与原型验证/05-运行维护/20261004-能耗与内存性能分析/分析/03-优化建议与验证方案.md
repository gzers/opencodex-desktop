# 03-优化建议与验证方案

## 1. 建议顺序

用户已确认以下方案边界，**目标版本 0.1.7，已实施并公开发布；实际交付与验证边界见 [04-实施与验证结果](04-0.1.7实施与验证结果.md)**：前台概览保留完整动画与画质；离开概览或应用进入后台时停止装饰绘制；减少后台检查，检查周期集中配置且暂不增加设置界面；闲置面板可回收，官方代理持续运行。

| 顺序 / 编号 | 建议 | 预期解决的问题与实施注意 |
|---|---|---|
| P1 / PERF-01 | 仅在前台可见概览执行装饰绘制；保留完整效果并优化图形计算、缓存与重复写入 | 保留已有路由卸载清理，补齐应用前后台联动。前台不降帧率、画质或动画持续性；图形优化细项见下文。 |
| P1 / PERF-02 | 统一应用激活、窗口隐藏 / 最小化与页面状态，接入下一到期时间驱动 | 切换到其他应用即暂停装饰绘制；后台检查按集中配置的运行 / 连接周期执行，失败时按配置退避。应用级前台状态由原生事件提供，避免仅凭窗口集合或 DOM 可见性判断。 |
| P1 / PERF-03 | 分离轻量存活 / 健康、连接与完整诊断；缓存环境事实，共享在途刷新；周期与退避从 JSON 读取 | 高频链路只取所需动态事实；完整 CLI 放到手工诊断、启停变化或配置的低频重校验。维持官方契约和状态新鲜度，记录原因、耗时、子进程次数；暂不增加设置入口。 |
| P2 / PERF-04 | 原生托盘事件驱动，保留带退避的队列兜底；按语义变化推送状态 | 降低空队列 IPC 与原生 setter 重写；事件遗漏可恢复。在途去重，时间戳 / 新鲜度和状态语义分别处理。 |
| P2 / PERF-05 | 确认可见性门控；加入面板闲置 TTL 与恢复机制 | 暂停隐藏面板的界面刷新，闲置后仅回收 WebView。官方代理服务和已有代理连接持续运行；保存必要页面状态，处理未完成编辑，避免每次临时隐藏都销毁。 |
| P2 / PERF-06 | 超时后终止并回收本次诊断子进程，限制并发与输出大小 | 防止异常命令累积，范围限于本次采集命令；用慢命令夹具验证。 |
| P3 / PERF-07 | 日志尾读增加总字节上限与增量解析；按持久性等级合并同步落盘 | 控制极端日志内存与扫描成本；关键结果可靠落盘，批量策略明确允许延迟。 |

更换桌面框架或官方运行时缺少本轮证据支持。优先改正具体调度与绘制策略，再判断更大范围调整。

### 1.1 什么时候绘制

在用户既有特效偏好与减少动态设置之外，装饰绘制需同时满足：**当前页面为概览、应用在前台、主窗口可见且未最小化**。离开概览、切换到其他应用、隐藏到托盘或最小化，SVG 动画和 WebGL 光场都停止续帧与绘制。

返回前台概览时衔接最新运行状态，正常恢复动画；不补跑后台积压帧，不因计时重置产生突然跳变。这里暂停的是界面装饰，代理转发、连接和必要状态监测持续工作。现有离开概览的清理已在源码中确认，实施要验证它生效，再补足应用前台状态。

### 1.2 图形怎么优化，同时保留效果

依据 [现有绘制链路](02-原因分析与源码证据.md)，先剖析 SVG、WebGL 与合成的成本，再验证以下具体改动。每项保留现有数学结果、颜色、透明度、形变、光场、玻璃效果、运动速度和前台流畅度；收益尚未实测。

| 方向 | 具体措施 | 保留效果的边界 |
|---|---|---|
| 少做重复计算 | 按状态缓存目标配色与不变参数；同帧重复使用的计算只做一次；复用数值缓冲，减少临时数组 | 继续计算真正随时间变化的形变、旋转和光场，不通过数值舍入减小变化 |
| 少写重复属性 | 颜色、几何输入或样式值完全没变时复用结果，跳过相同的 SVG / CSS 写入和 WebGL 参数上传 | 有变化的属性仍正常更新，不删渐变、模糊或细节 |
| 图形参数按变化更新 | 分辨率参数在尺寸变化时更新，配色与主题参数在值变化时更新；动画时间仍正常推进 | 保持现有渲染尺寸、DPR 与图形质量 |
| 减少光场着色器重复计算 | 评估将只依赖本帧时间的光团位置、旋转与缩放计算为 uniform 参数，避免在每个像素重复计算 | 保留相同光团运动、叠加、渐隐与颗粒效果；核对浮点差异和 GPU 剖析结果，未确认收益时不交付该改动 |
| 协调绘制与暂停 | 评估 SVG 与 WebGL 共用帧调度、统一暂停恢复入口，避免重复调度和时间不同步 | 不以降低前台帧率作为收益；合并须通过速度、时序和视觉对照 |

如果某项改动不能保持效果，就调整实现或撤回。不能把中档静态的采样结果当作完整动画优化后的预期成绩；前台收益必须用同样高档效果的优化前后对照验证。

### 1.3 具体技术

方案沿用当前 Vue 页面、SVG 形变图标和 WebGL 光场渲染器，围绕以下技术改动：

1. **原生事件控制绘制**：macOS 原生层监听 NSApplication 激活 / 退出激活通知，结合窗口隐藏与最小化状态，通过 Tauri 的 Rust → 前端事件传递应用前台状态；前端再结合概览路由状态统一启停。应用级激活判断不只依赖单个窗口焦点。
2. **统一动画帧调度**：使用 `requestAnimationFrame`，停止时 `cancelAnimationFrame`，共用暂停恢复时钟，销毁时移除订阅；不以后台计时器继续推进装饰绘制。
3. **缓存与差量更新**：复用数组和几何计算结果，比较属性的新旧值，只提交真正变化的 SVG / CSS 属性与 WebGL uniform。WebGL 本身已存在，新增收益需要来自具体计算与提交优化。
4. **光场着色器等效优化**：现有 [片元着色器](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/ui/src/features/runtime/motion/meshGlow.ts#L25) 含只依赖时间的光团变换；评估每帧预计算后传入 uniform。此项是候选，需视觉对照与图形剖析确认，保持原有渐变、玻璃、颗粒与流畅度。

API 依据：[Apple 应用激活](https://developer.apple.com/documentation/appkit/nsapplication/didbecomeactivenotification)、[退出激活](https://developer.apple.com/documentation/appkit/nsapplication/didresignactivenotification)、[Tauri Rust 到前端事件](https://v2.tauri.app/develop/calling-frontend/)、[取消动画帧](https://developer.mozilla.org/en-US/docs/Web/API/Window/cancelAnimationFrame)、[WebGL uniform](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/uniform)。文档证明 API 能力；本节保留技术选择依据，实际桥接与回归见 04，Windows 原生 GUI 尚未验收。

### 1.4 检查周期集中配置

沿用 `apps/desktop/tauri/config/runtime.defaults.json` 作为默认值来源，复用类型化访问器。当前前台 / 后台运行与连接周期已集中在该文件；[读取模块](https://github.com/gzers/opencodex-desktop/blob/bd2b1b26cc7c2ade5cb243cd7c8f94560ebc9028/apps/desktop/tauri/src/modules/runtime_defaults/mod.rs#L88) 在构建时嵌入 JSON，运行时统一解析。现有 3 / 15 / 10 / 30 秒是当前版本默认值，后续策略读取有效配置，不在调度器内重复写死。

| 配置范围 | 消费方式 |
|---|---|
| 前台 / 后台轻量运行检查周期 | 调度器根据应用前台状态选取相应配置 |
| 前台 / 后台连接检查周期 | 独立判断到期，仅采集连接所需状态 |
| 完整诊断重校验周期 | 与轻量检查分开；手工诊断和启停变化仍可立即触发 |
| 失败退避、最大退避与采集超时 | 按配置延后下次采集，命令超时后明确终止与回收 |
| 托盘队列兜底与面板闲置回收时间 | 默认值同样集中，避免新增散落定时常量 |

配置定义单位、字段类型及有效范围，调度与前端消费同一有效策略；本轮字段必填，缺项、零值、超限和非法关联关系在构建期拒绝，不由各调用方另加默认常量。**暂不增加设置页入口**。本阶段采用已有版本固化默认机制，配置文件变更随构建生效；日后如需本机直接编辑，沿用 [既有配置分层规划](../../20261004-更新通道与配置分层/分析/02-配置分层规划建议.md) 的覆盖层设计。

## 2. CPU 与能耗验证

### 2.1 建立受控矩阵

同一设备、系统、窗口尺寸、缩放、显示刷新率、电源和能耗模式下重复；分别记录代理无业务请求与固定请求负载。每个状态先稳定 1 分钟，再采集至少 10 分钟，重复 3 次。排除采样工具首帧，记录工具本身的影响。

| 场景 | 要验证的原因 |
|---|---|
| 设置 / 通用，代理运行 | 外壳基础与监测成本 |
| 概览完整高档效果，优化前 / 优化后 | PERF-01 在同等效果下的 CPU、图形成本与流畅度 |
| 光场关闭、logo 静止等仅供剖析的隔离版本 | 拆分 SVG、WebGL、合成成本；不作为交付效果 |
| 概览 → 其他页面 → 概览 | 既有路由清理、零装饰续帧与恢复 |
| 切换到其他应用、主窗口隐藏 / 最小化 / 再显示 | 应用前后台门控、后台检查与动画暂停恢复 |
| 官方面板显示 / 隐藏 / 闲置回收 / 再打开，同时持续代理请求 | PERF-05 界面暂停与内存回收；代理与已有连接连续运行 |
| 可控诊断失败、超时、恢复 | 退避、唤醒、子进程回收和托盘新鲜度 |
| 使用不同检查周期配置构建，含缺项 / 非法值 | 验证配置消费、分项调度与校验；不出现另一套硬编码周期 |

同时记录主进程、经核实的全部 WebKit 辅助进程、官方服务和短时 CLI 子进程。采集平均值、P95、峰值、CPU 时间、唤醒次数、命令次数与耗时；GPU 辅助进程 CPU 不能代替 GPU 利用率。

活动监视器能耗页比较同条件的相对“能耗影响”；定量功率另补可归因的功率采样或性能工具，明确覆盖整机还是进程。稳定电源状态下比较，再补电池场景，保留时间和业务条件。

### 2.2 候选验收目标

**下列保留原候选验收目标；并非全部长测或收益目标已达到，实际覆盖与限制以 04 为准。性能降幅由同等效果实测确定。**

| 对象 | 候选目标 |
|---|---|
| 页面 / 前后台门控 | 离开概览或应用不在前台时，装饰 rAF 回调与 WebGL 绘制次数为 0；恢复后衔接最新状态，无跳变与积压补帧 |
| 前台完整效果 | 保持形变、颜色、渐变、光场、玻璃效果、运动速度与流畅度；按统一时间点截图及连续录像对照，无效果减少 |
| 前台图形成本 | 同样高档效果、同条件长窗口下，平均 CPU 时间重复下降；分项报告脚本、SVG / 样式与图形成本，降幅由实测给出 |
| 后台监测 | 隐藏真正使用配置的后台间隔；失败时驱动唤醒随配置退避减少；记录实际执行次数。10 / 30 秒仅为当前默认值 |
| 周期配置 | 所有新增检查与退避周期来自集中 JSON；修改配置后实际执行间隔随之改变，加载校验与默认值来源统一，暂不增加设置入口 |
| 完整诊断 | 稳定运行不再由每个 3 秒轻量刷新重复启动完整 CLI；手工刷新和启停变化仍及时生效 |
| 托盘 | 无操作时避免 1 秒空 IPC；命令可恢复派发，维持状态新鲜度与异常提示 |
| 面板与代理 | 面板隐藏 / 回收 / 重开不触发代理停止或重启；持续请求与已有连接不中断，未保存编辑有明确保护 |
| 能耗 | 固定工作量下相对能耗影响重复下降，提供原始记录；没有功率采样时不报瓦数或续航百分比 |

## 3. 内存验证

先核实面板 WebContent 身份，再同时记录 RSS、physical footprint、峰值和可取得的 JS 堆。同一业务负载，每 30 秒记录，至少覆盖 2 小时；固定暖机和缓存条件，保存时间。

1. **基础驻留**：启动到设置页，面板未打开，代理空闲 / 固定负载，建立稳定基线。
2. **面板生命周期**：首次打开 → 离开 → 等待闲置回收 → 再打开，重复 20 轮，观察是否逐轮积累、形成稳定平台，以及重开耗时；全过程保持代理运行与固定业务负载，验证已有连接和转发不中断。
3. **长期服务**：重复固定请求批次，结束后等待连接收敛和缓存过期，观察 footprint 与堆是否回落；持续增长时取得分配 / 对象证据。
4. **异常采集**：慢命令与超时恢复后检查子进程、文件描述符和未回收输出缓冲。

验收说明缓存保留政策、闲置 TTL 和恢复体验。泄漏结论需要稳定负载下可重复增长及分配证据；当前约 250M 服务 footprint 作为本机参考，暂不规定跨平台统一绝对上限。

官方内存接口需要有效授权，本轮未取得堆数据。后续在具备正常访问条件的测试环境采集，将服务计数器与系统 footprint 对照。

## 4. 交付证据与运行边界

实施在代码归属分支开展，交付引用实际提交、条件明确的前后采样、托盘 / 启停 / 面板恢复回归与已知限制。本记录更新优化状态时引用真实实施和运行证据。

本轮中档采样用于定位装饰渲染成本，正式方案保留前台完整效果。测量结束已恢复原高档偏好。原始规划阶段仅更新分析与方案；后续 0.1.7 已按确认范围实施，面板回收仅涉及界面，代理服务持续运行。
