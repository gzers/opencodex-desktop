## 2. 指标口径

| 指标 | 本文用法与限制 |
|---|---|
| macOS“使用大量能耗” | 定性反馈；截图没有数值或时间窗口。活动监视器“能耗影响”也是相对指标，不能直接换算瓦数。 |
| 进程 `%CPU` | 按单核 CPU 时间尺度理解，100% 约为占满一个核。GPU 辅助进程的 `%CPU` 仍是 CPU 时间，不是 GPU 利用率。 |
| `top MEM` | 同工具、同字段对照，保留原始 M/K 标记及变化符号，不当作 JS 堆或 `ps RSS`。 |
| `ps RSS` | 常驻页计数，原单位 KiB；含共享等页面，不能简单相加作为整个应用的独占内存。 |
| `vmmap physical footprint` | 观察进程需要系统承担的内存负担，区别于 RSS、虚拟地址空间与 JS 堆；本文保留原工具的 M 单位。 |
| 泄漏 | 需要受控负载的长期趋势、对象 / 分配证据与回收验证；单点大 RSS、峰值或缓存驻留不足以定案。 |

外部口径参考：[Apple 活动监视器能耗说明](https://support.apple.com/guide/activity-monitor/view-energy-consumption-actmntr43697/mac)、[Apple 对 physical footprint 与 resident memory 的解释](https://developer.apple.com/videos/play/wwdc2018/416/)。首帧排除依据为本机 `man top`：日志模式第一帧的 CPU 百分比无效。

## 3. CPU 对照方法与结果

每组运行 `top -l 16 -s 2`，限定下表 7 个 PID，并记录 CPU、MEM、线程、idle wakeups 和 CPU time。每组约 32 秒，排除首帧，**每个进程使用 15 个有效 CPU 样本，以下为算术平均**。保留代理运行，实际请求负载未隔离。

| 条件 | 2026-10-04 本地时间 | 桌面主进程 + 关联 WebContent / GPU 的平均 CPU |
|---|---|---:|
| 设置 / 通用，原高档 | 22:31:48–22:32:20 | **0.69%** |
| 概览，高档 + WebGL | 22:40:54–22:41:26 | **46.25%** |
| 概览，中档静态 | 22:48:22–22:48:54 | **0.27%** |
| 概览，恢复高档复核 | 22:54:36–22:55:08 | **44.89%** |

| PID / 角色 | 设置高档 | 概览高档 | 概览中档 | 概览高档复核 |
|---|---:|---:|---:|---:|
| 17819 桌面主进程 | 0.57% | 6.35% | 0.12% | 5.87% |
| 17821 WebKit GPU 辅助进程 | 0.00% | 22.57% | 0.00% | 23.97% |
| 17822 桌面壳 WebContent | 0.11% | 17.33% | 0.15% | 15.06% |
| 17823 WebKit Networking | 0.00% | 0.00% | 0.00% | 0.00% |
| 18502 官方 Node 启动器 | 0.00% | 0.00% | 0.00% | 0.00% |
| 18504 官方 Bun 服务 | 7.21% | 3.18% | 2.41% | 2.49% |
| 19088 另一个 WebContent，面板候选 | 0.00% | 0.03% | 0.07% | 0.00% |

设置页近乎空闲；同一概览页高 → 中 → 高出现约 46 → 0.27 → 45 的 CPU 变化，结合源码两套持续绘制循环，可以将**可见概览高档装饰渲染**列为本轮已证实的显著成本。合计只覆盖 17819/17821/17822，包含合成等间接成本，尚未拆分每个动画的贡献。

官方服务在设置页平均为 7.21%，概览对照时为 2.4%～3.2%；波动不能算作特效优化收益。它还承担代理请求、连接与管理接口工作，需要受控负载和剖析才能归因。

### 进程归属边界

- 官方 Node 是桌面进程的子进程，Bun 是 Node 的子进程，父子关系已核对。
- WebKit XPC 进程由 launchd 托管，PPID 为 1。17821/17822 与桌面同秒启动，且随页面与特效切换呈一致响应，关联度高；未通过系统审计建立完整归属证明。
- 19088 启动较晚，符合内嵌面板候选，但**归属尚未证明**，不并入已归因的动画合计。
- 短时 `ocx status` 子进程未纳入固定 PID 采样，表格不能代表桌面应用全部进程的 CPU 总成本。

逐样本见 [process-samples.csv](../../../../../../../../.adg/evidence/MNT-OPENCODEX-DESKTOP-20261004-04/process-samples.csv)，分布与原始输入摘要见 [measurement-summary.json](../../../../../../../../.adg/evidence/MNT-OPENCODEX-DESKTOP-20261004-04/measurement-summary.json)。

## 4. 内存观测

下表保留不同计数器，**列之间不是同一时刻的等值换算**。RSS 快照为 22:57:08；footprint 初次观察约 22:31:13。

| 进程 | RSS（KiB / 约 MiB） | 初次 physical footprint / 峰值 | 四组 `top MEM` 观测 |
|---|---:|---|---|
| 桌面主进程 17819 | 118064 / 115.3 | 未单独采集 | 约 37～38M |
| GPU 辅助进程 17821 | 76784 / 75.0 | 未单独采集 | 设置 37M；高档 143～220M；中档 40M；复核约 141M |
| 壳 WebContent 17822 | 97952 / 95.7 | 144.2M / 389.5M | 设置约 144M；高档 106～142M；中档 93～94M；复核 103～109M |
| Networking 17823 | 42832 / 41.8 | 未单独采集 | 约 7M |
| Node 18502 | 46800 / 45.7 | 未单独采集 | 约 17M |
| 官方 Bun 18504 | 1303808 / 1273.3（约 1.24 GiB） | **255.0M / 560.2M** | 约 255 → 253～254 → 253 → 252M |
| WebContent 候选 19088 | 247968 / 242.2 | 109.3M / 407.3M | 前两组约 109M；后两组约 163～165M |

22:58:52 再次对同一 Bun 进程采集 `vmmap`，footprint 为 **251.5M**，峰值仍为 560.2M。初次与复核间约 28 分钟，没有观察到该计数器持续上涨；仍不足以排除特定负载下的慢泄漏。

本轮确认官方服务 RSS 较大，但不能说它独占同等物理内存；也不能把服务的 255M 当作桌面壳、图形辅助进程和面板的总和。另一个 WebContent 的 MEM 后期增加，归属、缓存与业务负载尚未排除，保留为待核实项。

短时线程采样中官方主线程多处等待，符号信息不足，未得到可指认的 JS 热点。官方内存接口返回 401，未收集经过认证的 JS 堆或历史曲线。计数器原文节选见 [memory-counter-excerpts.txt](../../../../../../../../.adg/evidence/MNT-OPENCODEX-DESKTOP-20261004-04/memory-counter-excerpts.txt)。

## 5. 证据强度与未覆盖条件

本轮支持“高档装饰渲染显著增加可见概览的 CPU 时间”。具体耗电量、截图提示出现时的页面、后台隐藏的实际能耗和服务 CPU 热点仍未测定。

四组为短窗口，组间有数分钟间隔；未固定显示刷新率、温度、电源状态和业务流量。同机其他应用仍在运行，未建立全机内存压力归因。未执行长时间空闲、面板反复切换、代理关闭对照或 GC / 堆分析。

测量后已恢复原高档特效并返回通用设置页，代理持续运行。后续验收使用 [03 的受控方案](03-优化建议与验证方案.md)，不能以本轮 CPU 差值宣称“节电 99%”或“内存泄漏已排除”。
