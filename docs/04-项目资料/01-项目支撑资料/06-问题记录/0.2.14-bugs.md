### 已确认的源码链路

以上确认的是数据与基准依赖。尚未用用户配置实测错误导出、输入丢失或凭据漏写，不把这些影响写成已经发生的数据事故。

### 记录的调整方向

1. 已保存渠道导出以当前 config.json 为源，布局与模版关系使用当前合法元数据；不能让旧渠道副本的不同成为导出资格。模版版本仍来自模版库。若明确导出未保存候选，应保持其独立含义，不混称已保存配置。
2. 导入所选渠道先合并到当前内存编辑，保留实际文件保存基准；继续使用已有保存预览，确认后才写 config.json。只有模版的导入只更新模版库，不替换渠道或 Key 编辑。
3. 当前有未保存渠道、型号或 Key 输入时，不因空操作 persistDraft 就视为已经保护；应合并不冲突内容，无法合并时保留输入并明确说明。取消与失败不得静默丢弃输入。
4. 明确采用的导入凭据接入同一保存意图；保留本地连接映射时继续保留本地 Key，不能把来源凭据自动覆盖过去。Key 池/引用、账户授权、WebDAV 密码、扩展凭据保持各自真实语义与已有选择范围。延续既定可选文件保护口径，不借本项新增强制加密。
5. 文件导出/导入、WebDAV 配置上传/下载使用同一渠道事实与采用规则，保留既有范围选择、比较及确认界面。

### 后续验收要求

- 文件改地址、协议、选择或顺序后再导出，产物反映当前文件，不因旧策略不同拒绝；覆盖完整渠道、部分型号族与共享范围。
- 导入比较、采用、取消阶段不修改渠道文件；确认保存后读回目标文件，重开管理器仍保留导入值与顺序，未选择对象及未修改字段不变。
- 已有渠道/型号/Key 未保存输入分别覆盖合并、取消、失败与结果晚回，不能被旧快照替换；仅导入模版也不能清除这些输入。
- 勾选/不勾选渠道 Key、保留本地连接/新建导入渠道分别验证，重新打开读取真实保存结果；不回显凭据到日志或证据。
- 同一选取范围通过文件与 WebDAV 的往返结果一致；不能把模拟成功或只打开比较弹窗当作最终文件写入已验。

## WP-83：内部 Agent 的渠道身份与执行模型缓存未跟随文件主线

### 已确认的源码链路

- tauri/src/modules/model_config/execution_directory.rs:120 调用 ModelStore.load，:140～151 用其旧 policy 获取渠道 UUID 和显示名；型号与顺序来自当前官方快照。执行目录因此仍混用旧渠道身份与新数据，也连带依赖旧草稿能被读取。
- ui/src/features/models/AgentExecutionField.vue:28～29 在取得后端目录后优先使用该目录；:36～41 的 directoryLoaded 标记使后续打开直接返回，没有按已保存文件或连接变化失效。仅反应式更新本地文件快照不足以刷新该目录。
- 文件主线的新渠道 UUID、改名、删除重建，以及当前节点/协议变化，需要和上述执行目录身份及缓存一起核对；不只检查画面上的型号文字。

### 记录的调整方向

1. 渠道身份和名称与当前文件及稳定布局元数据一致，移除旧策略/草稿的无关依赖。内部 Agent 仍使用当前官方支持的执行路由，不以未保存草稿假称当前可执行配置。
2. 渠道保存、外部文件变化被读取、导入采用后保存等操作，应使执行目录缓存失效；重新打开选择器可读取最新目录，失败可在既有入口重试。新旧异步结果不能相互覆盖。
3. 保留本机共用执行偏好；选择失效时明确提示本次任务无法执行，不静默切换到其它渠道/模型，也不新增常驻核对状态。未知推理/Fast 能力继续保持未知。
4. 文件允许保存站点的精确原始型号；实际生成时检查执行路由、连接和所选能力属于发请求的要求，不能反过来阻塞渠道文件保存或改写用户型号。

### 后续验收要求

- 首次加载目录后，保存改名、增加/删除渠道、切换节点/协议，再打开 Agent 配置看到新值；UUID、显示名和实际执行目标一致。
- 当前模型被移除或连接变化时，后续任务如实反馈；不继续使用旧绑定，不自动改选，不清除渠道编辑。覆盖目录失败重试及旧请求晚回。
- 真实执行请求使用精确原始 ID 对应的官方路由；保存合法但尚不可执行的型号仍可走普通文件保存，不引入型号拼写/发现清单核对。
- 继续沿既有 Agent 配置和模型选择器原型；不在按钮外另加摘要行或新状态卡。

## WP-84：外部模版任务仍连带依赖旧渠道策略和磁盘草稿

### 已确认的源码链路

- tauri/src/modules/model_config/tasks.rs:184 在准备纯模版任务时调用 ModelStore.load；:405 的任务校验再次读取完整旧快照，:567 的 save_submission 最终通过 store.rs:597 的 load_unlocked 读取旧策略与磁盘草稿。只将一个读取点替换为 library_only 不能证明提交链已解耦。
- 模版任务范围是模版、精确版本、当前编辑缓冲和补充要求；broker.rs:349 的任务说明明确不授权修改默认指针、采用关系、凭据或运行文件。上述渠道依赖并非任务本身所需。
- 0.2.14 的 BatchAgentDialog.vue:50～53 已修正为只合并模版库、保留渠道与 Key 编辑；不能因新增本条而误记该项仍未修。ModelsRoute.vue:85 的变更事件走当前文件读取，现有前端保护方向应保留。

### 记录的调整方向

1. 准备、校验、另存新版本与回执恢复完整使用模版库及必要任务记录，不要求旧渠道策略或旧磁盘草稿有效。内部制模共用的 Tasks 路径也需覆盖。
2. 保留任务范围、精确模版版本、人工锁、只检查场景、提交身份及回执防重；这些是模版任务的已有功能，不随普通渠道保存简化一并删除。
3. 外部结果可以按已授权范围另存模版新版本；用户明确套用到渠道内存编辑，再经已有保存预览确认写文件。外部任务不自动带出渠道 Key，不获得直接写运行文件或默认选择的权限。
4. 返回结果只更新应更新的模版内容，不替换当前渠道文件快照，不清除未保存的渠道/Key/模版缓冲；过期目标保留结果并说明，不静默覆盖后来编辑。

### 后续验收要求

- 有旧策略缺失/损坏、旧磁盘草稿损坏等隔离夹具时，纯模版任务仍可准备、提交、查询回执并读取新版本；只依赖真实必要的模版数据。
- 任务进行中改普通渠道并保存，不使纯模版任务因旧渠道基准失效；回执返回后当前渠道文件及未保存输入保持。
- 同提交身份重试不重复创建版本，修改同一提交内容仍被拒；人工锁、只检查场景、目标版本冲突与明确新增范围保留。
- 套用模版进入渠道编辑，取消预览不写文件，确认保存后重新读取的文件内容与预览一致；不增加新的任务完成确认页或核对状态。

## 三组共同要求：旧配置迁移与遗留逻辑清理

2026-10-27 用户补充询问旧配置和遗留逻辑是否纳入规划。本节将清理列为三组的必做验收项；当前只记录，未执行配置迁移、删除或代码清理。

### 已知现状与处置边界

| 对象 | 当前依据 | 规划处置 |
| --- | --- | --- |
| 旧渠道副本及磁盘草稿 | WP-82～WP-84 的读取和写入链仍使用 model-policy.json / model-config-draft.json | 盘点所有消费者，迁移仍需保留的信息；相关普通入口停止读写旧副本，不再生成旧渠道基准 |
| 兼容布局输入 | tauri/src/modules/model_config/config_file.rs:49 在没有新布局时仍回读旧 policy；:274 的 record_layout 已将部分字段清理后写入新布局 | 迁移稳定 UUID、渠道显示名、节点信息和模版采用等必要元数据；字段级确认后停用旧回落，不能只删旧文件而丢失身份与采用关系 |

| 已退役客户端状态 | tauri/src/commands/retired_files.rs 已列明 model-client-state.json，启动时调用 purge_retired | 复核现有清理继续有效；新增残留只按核实后的固定路径/字段清理，不扩大为整个 manager-state 清空 |

### 实施时必须覆盖

1. **先盘点，再迁移和清理。** 对本轮涉及的旧文件、字段、接口和状态列出实际读者、写者、剩余用途与处置，逐项标明“迁移后删除 / 保留为历史 / 保留为必要兼容 / 已无引用删除”。没有核实的对象不能笼统写成全部清理完成。
2. **清理遗留代码及消费者。** 三组改造完成后，删除已经没有用途的旧读取/暂存/基准比较分支、命令注册、旧通知动作与失效状态；同步修正对应测试、夹具、注释和当前文档，避免旧用例继续要求过时行为。仍服务显式历史恢复的逻辑单独保留，不因名称含 legacy 就误删。
3. **旧设备自动升级可用。** 需要的迁移在升级后按版本执行并可重复运行，保留渠道身份、节点及模版采用等有效信息；config.json 的当前渠道地址、协议、Key、选择和顺序不被旧副本反向覆盖。旧草稿不能静默当作已保存配置；仍有价值的旧候选先保留为可取回候选或隔离归档，迁移成功后停止旧路径回落。用户无需清空配置或重新输入全部 Key。
4. **清理已证实无用的残留。** 迁移完成后移除已无读取用途的固定状态文件、废弃字段和无引用暂存。保留用户真实配置、模版版本、有效凭据、可用历史备份和任务回执；不把清空整个配置目录作为修复方案。迁移失败不破坏当前文件，重试不重复创建渠道、版本或采用关系。
5. **不新增用户核对流程。** 必要迁移与清理属于内部升级处理，结果使用既有通知；不新增常驻“迁移待核对”状态、额外入口或脱离原型的确认卡。真实冲突或失败如实说明，不阻塞无关的普通文件编辑。

### 清理完成的验收要求

- 同时验证全新安装、从旧配置升级、旧副本过期/损坏、旧计划未完成，以及迁移中断后再次启动；不能只在空配置上通过。
- 升级后文件值、稳定渠道身份和模版采用保持；导入导出、Agent 选择与外部模版任务均使用各自正确来源。损坏的无关旧草稿不会重新挡住已解耦入口。
- 重复启动和重复迁移不新增副本、不重复写入、不恢复旧状态；已退役文件不会被残留写者重新生成。
- 删除项取得无用途/无引用证据，保留项列明现行消费者。备份与显式历史恢复仍可用，现有有效 Key 和任务回执不丢失。
- 对旧命令、旧数据读取与旧状态文案做调用点复查，并运行对应实际操作链；只有源码搜索无结果或删掉文件，不足以证明迁移与兼容验收完成。
