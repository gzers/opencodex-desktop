## 2. 身份与版本建议

| 对象 | 建议与约束 |
| --- | --- |
| templateId | 用户模版首次成功保存时由Rust共用服务生成UUIDv4完整身份；复制为新身份，不继承默认/采用/可信内置来源。前端临时缓冲ID不能成为已保存引用 |
| revisionId | 每个实际新增保存快照由同一服务生成独立UUIDv4；首次保存即非空，旧版正文不原地修改。不能用每机max+1、时钟或短标识作为跨机身份 |
| 内置身份 | 由可信随软件种子清单提供固定模版/基线身份，各设备保持一致；不在每次安装随机重建，不相信导入方自称builtin |
| 显示信息 | 完整UTC保存时间和短标识只用于展示，引用必须携带完整templateId/revisionId；可见序号不充当版本身份，也不因删除重用 |
| 来源与基准 | 保存实际基准revisionId、来源快照和逐项变更事实；时间/生成者/默认/采用与内容变更分别记录 |

服务在持久化锁内检查身份占用：同revisionId同标准化内容为重复接收，不新增；同revisionId异内容为冲突，保留双方及原库；同templateId不同revisionId可以共存，不能按“同模板内容不同”拒绝正常版本同步。新生成身份遇已占用时重新生成或明确失败，不覆盖已有对象。随机ID的概率性质、边界测试与实际冲突检查分别说明，有限测试不能证明绝对无碰撞。

## 3. 字段与内容边界

| 类别 | 必须表达 | 依据/边界 |
| --- | --- | --- |
| 身份元数据 | 稳定ID、当前显示名、可信内置来源与保护关系、以后默认指针 | 默认和名称是独立元数据；版本保存另冻结当时名称以解释摘要 |
| 保存快照 | 说明、匹配、通用配置、具体型号/后缀及稳定子项身份、字段依据和人工锁 | 人工、内部生成、外部提交共用字段与保存服务，不建NotificationTemplate的title/body结构 |
| 匹配 | include/exclude的exact/prefix/glob、caseSensitive、priority、channelMode/channels | 原始模型ID匹配，通配符不是任意正则；渠道范围和发布白名单分别表达 |
| 可继承规则 | 协议、contextWindow、inputModalities、推理可选集合与独立默认、Fast及已有高级字段 | 逐字段沿已确认inherit/custom与空值语义；协议/能力须在实际adapter验证，不凭族名或URL猜测 |
| 策略引用 | 全局/渠道/精确模型的完整保存版本引用，选择范围、两级顺序、渠道及单模型覆盖 | 同templateId的渠道引用替换全局版本，其他模板保留；单模型精确引用优先 |
| 连接与节点 | 渠道共用认证和默认协议，多URL节点及渠道级activeNodeId | 不在模版放URL/Key，不恢复模型独立选节点；便携与本机绑定沿同步方案 |

机器schema须明确必填、可选、枚举、未知字段及限制：省略/继承不变成false或零，显式false保留；null只有在具体字段合同允许时才合法，不能充当任意未知值。精确模型ID/渠道ID不截断或重写。

版本可保存当前零命中的规则，但必须能指出零命中；空包含规则的合法性及错误位置随机器schema明确，不以新增文档擅自改业务。渠道all忽略清单，空白名单不命中、空黑名单允许全部，失效渠道引用不能退回all。

## 4. 标准化、digest与摘要

建议采用SHA-256与明确的规范化JSON字节合同。WP-01冻结规范化算法/库及测试向量后才作为正式接口；不能以“预留字段”代替该工作，也不把算法实现全部完成列为开工前置。

1. 先按字段语义规范化。对象键顺序不算变化；匹配集合、渠道清单、模态和推理集合只改排列不产生内容变化。all下不参与解析的渠道清单不制造有效修改。型号子项顺序、渠道顺序及模型顺序等有语义数组必须保留。
2. 建议在上述语义投影上采用JCS（RFC 8785）规范化，UTF-8编码后计算SHA-256，表示为`sha256:`加64位小写十六进制。数值范围、重复键、非有限数及Unicode/转义向量须明确；上游原始ID不做隐式Unicode归一化。
3. 内容digest覆盖冻结的有效内容及当时名称/说明等摘要比较事实；ID、保存时间、默认/采用指针、digest自身不参与该内容摘要。来源与人工锁等证据另随版本冻结，任务提交/计划需比较的完整基准另定义，不能混用内容digest与文件/传输摘要。
4. 成功保存版由服务计算非空digest并读回核验。只有未保存缓冲或尚未识别的历史输入可缺摘要；历史输入须先按已识别格式解析/校验，再由服务计算，不能一律补值冒充历史真实性。已有digest失配拒绝接收或应用。
5. 同内容保存返回无变化，不新增版本；变更摘要共用核心§6.5确定性比较，不能信任Agent自报文字。哈希证明内容一致性，不证明作者、授权或可信内置身份。

## 5. 匹配、依赖与删除

只在已采用集合内解析，按作用域合并后取唯一最高优先级；并列最高报告冲突，受影响保存/编译停止。缺精确版本、字段非法或能力未核实时保留原运行态和待处理原因，不能跳过模板继续报成功，也不能随机挑选。保存模版与采用到渠道的验证范围分开，不能把未采用的新版本自动当成运行集合。

顶层规则通过后，具体型号仅按原始ID字面后缀取最长项；同长歧义按现有规则报错，合成后再次验证。人工精确引用可越过自动匹配，但不能越过字段/协议合法性。

可信初始/当前内置基线永久保护；默认版本先切默认才能删除，保存/草稿/恢复/任务等实际依赖存在时保护。单删与勾选删除共用整批依赖检查和过期基准拒绝；不恢复归档、用户保留或按数量轮换。下拉最近5加当前/默认去重是显示规则，不是库容量。

## 7. 首切片实现采用（2026-10-18）

当前feature/0.2.0-model-config的modules/model_config/schema.rs与store.rs已定义首切片Rust类型及deny_unknown_fields读取边界。实际字段使用Template.id、Revision.id及精确引用templateId/revisionId；UTC createdAt与savedLabel随版本冻结，changes保存逐项before/after事实。前序JSON示例仍只作设计输入，不直接传给该读取器。

内容摘要采用命名合同`model-content-v1`：TemplateContent先按集合/有序语义规范化，再组成`{label,content}`的serde_json::Value；对象键按Map顺序输出UTF-8紧凑JSON，数值字段仅允许schema中的有界整数，最后SHA-256并加sha256:前缀。没有实现通用浮点JCS，不宣称RFC8785完全支持。当前Rust/TS类型共同维护接口，后续外部契约必须由正式类型同源投影，不能复制旧示例充当协议。
