## 已确认的组织方向

1. 完整桌面原型保持一个持续维护入口。后续模型配置页面加入现有桌面壳、导航和交互；每个产品版本不再复制整套 HTML、CSS、JavaScript 和共用素材。
2. 共用主原型仍归项目协作资料，已启用位置为 `docs/04-项目资料/03-项目协作资料/03-共享原型/`。该目录是本项目经确认的 COL 派生资产共用存放区，不是治理 Skill 已有标准槽位，也不是需求或项目核心的第二份事实源。
3. 只提取持续维护的主原型及必要共用资源。原始输入、历史候选、截图、评审说明和验收证据保留在所属协作包原位，不能全部改为只在 Git 历史中保留。
4. 每次迭代继续在对应协作包的 `01-需求分析/05-原型/` 记录增量说明及必要的新证据，在 `01-需求分析/06-版本记录/` 登记固定基线与决策。包根保留 COL 主记录与 README 索引，不平铺原型文件或版本说明。
5. 稳定需求和界面规则按原有职责回写 DMD、UI 规范等权威文档。原型是设计与状态验证的派生产物，其修改不代表生产功能已实现。

## 版本引用与可复现性

每个已定稿版本至少记录以下内容：

| 字段 | 要求 |
|---|---|
| 产品版本与设计轮次 | 分开登记；产品版本可以暂定为 `0.2.0`，原有 `V0.1` 至 `V0.9` 保持设计轮次语义 |
| 状态与确认来源 | 区分进行中、已确认和历史；保留确认日期及评审指向 |
| 来源与版本关系 | 登记所属 COL、来源 COL 和前一基线；未有前一基线时明确说明 |
| 固定原型基线 | 完整 Git commit、该 commit 下的原型路径和入口；资源依赖须可随该版本检出 |
| 增量与证据 | 指向当次改动说明、必要截图和原型 QA 结论 |

共用区索引负责跨版本导航，各协作包负责自身的决策与评审记录，两者以引用关联，不维护两份结论正文。仅指向可变分支或“当前版”不能作为旧版基线；Git commit 也不能代替用户确认和证据。

需要对照旧版时，按登记的 commit 与当时路径临时检出或导出完整依赖，不常驻多套完整原型。Git 基线只能覆盖已纳入版本管理的内容，不能据此承诺本机忽略素材也能复现。

## 整理的前置条件与执行核对

下列条件已作为本次执行检查项；实际结果及依赖边界见 [迁移记录](../06-版本记录/20261004-共享迁移与0.2.0补绘.md)，不把新稿误登记为已定稿：

- 在项目资料与协作资料索引登记共享区的用途、来源关系、维护责任、保留策略和启用状态；当前目录规范仍按实际已有目录执行。
- 盘点正式入口、共用资源和历史候选的依赖，明确提取范围。若历史页面依赖拟移动资源，先确定可复现的固定基线及访问方式；不能为减少重复破坏历史证据。
- 登记可核对的旧基线，更新来源 COL 的输出、处置与保留说明，以及旧原型区和各阶段索引。
- 核对移动涉及的相对引用、导航、忽略规则及 QA 路径；官方来源素材仍按现行规则仅在本机保留。
- 保持文档与原型资料在 `docs/` 分支；如涉及全分支共享文件，按 AGENTS 的一致性规则处理。
- 核对当前入口可打开、必要资源可加载、历史资料仍在原位、固定基线可复现且各版本可双向导航，再记录整理结果。

如果后续要把主原型作为 CDOC 受控交付件，还须满足受控主版本与父版本、原始件摘要、审批状态、存放位置和保留责任等准入要求。此次不将一般过程草稿登记为 CDOC。
