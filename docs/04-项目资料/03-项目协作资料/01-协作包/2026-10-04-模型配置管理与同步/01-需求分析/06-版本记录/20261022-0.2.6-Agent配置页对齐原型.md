# 0.2.6：Agent 配置页按原型落地（已配置 / 未配置两态）

2026-10-22，0.2.5 装机后用户在设置 → Agent 配置页连续指出两处偏差：“agent配置了模型展示没有按照原型来做”“没有配的时候效果也要参考做”。本文登记结论与实施边界，仅记录，未实施。

## 背景

0.2.5 的 WP-35 只改了原型侧：原型补了工具板演示卡与“已配置模型”完整态，并在记录里写明“实现侧 Agent 配置页是否同步这套排版，随 0.2.5 其它项一并处理”。该跟进未发生，于是原型有完整态、代码仍是旧形态，形成本轮的实机偏差。

## 决策

沿用 0.2.5 已确认的原则：“完全按照原型，不要扩散思维，原型本身就是确认过的。”原型 `model-config.js` 的 `renderSettings()` 即目标态，实现侧不改结构、不增删信息块。

## 两态目标态

**未配置**

- 卡片上方面板标题 `h2`「Agent 配置」。
- 卡片标题行：`h3`「模型模版助手 · 本机共用」+ 摘要 `尚未选择执行模型 · 请配置执行模型`（`role="status"`）+ 右侧主色按钮「Agent 配置」。
- 空态说明：「尚未选择执行模型。自动填充与模版检查需要先配置一个可用的执行模型。」

**已配置**

- 摘要：`渠道 / 型号 · 档位（模型默认） · 快速状态`，快速状态按能力分四类（快速已开启 / 快速已关闭 / 不支持快速模式 / 快速能力待核对）。
- 右侧按钮降级为「更换执行模型」。
- 四项事实横排：执行渠道 / 型号 / 推理档位 / 快速模式（能力：可用 / 不可用）。
- 适用范围三条：自动填充与更新共用；不改 Codex 命名、搜索与子 Agent；只影响之后启动的任务。
- 与运行配置的边界：写入 `manager-state/preferences.json` 的 `modelTemplateAgent` 分区，不进入默认同步或普通导出。

## 实现边界

- 改 `apps/desktop/ui/src/features/models/AgentExecutionField.vue`：新增页面态（标题行 + 两态正文），保留 `compact` 紧凑态给助手面板、批量对话框与模型页页签行。
- 改 `apps/desktop/ui/src/routes/SettingsRoute.vue`：`section === 'agent'` 不再用 `UiCard` + `UiCardHeader` 套出第二层标题，`h2`「Agent 配置」放在卡片外。
- 摘要与事实取值按“渠道 label 优先、缺省回退 providerId”“档位中文化、`null` 视为继承并标（模型默认）”；快速模式在摘要与事实两处口径不同，分别取值。
- 样式复用全局 token（`--rail`、`--border`、`--radius-sm`、`--text-caption`），不引入 `mp-` 前缀类名。
- 测试改写 `apps/desktop/ui/tests/model-execution-field.test.ts`，补两态结构断言，文本与原型 `agent-settings-page.test.cjs` 一致。

## 未决

3. 现说明句“保存不触发任务”原型没有，按“完全照原型”应删；是否并入“适用范围”。
