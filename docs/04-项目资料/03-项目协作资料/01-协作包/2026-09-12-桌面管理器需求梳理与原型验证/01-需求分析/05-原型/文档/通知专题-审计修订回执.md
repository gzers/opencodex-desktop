### 7.5 「状态标签太长」的根因（2026-09-19 第三轮）

用户指出条目里的「未解决 / 已解决」标签「太长很奇怪」。实测该标签被渲染成 `display:block`、宽 **294px**（几乎与整张卡片等宽）——原因是给正文用的
`.notification-item span{display:block;margin-top:3px;font-size:11px;…}` **把 `.n-tag` 也一并命中**（`.notification-item span` 优先级 0-1-1 高于 `.n-tag` 的 0-1-0）。

修复：新增更高优先级的
`.notification-item strong .n-tag, .history-item strong .n-tag{display:inline-block;margin:0 0 0 6px;font-size:10px;white-space:nowrap;…}`
（0-2-1），把标签扳回标题行内。

修复后实测：标签 `display:inline-block`、**41 × 18 px**、字号 10px（修复前 `block` / 294px / 11px）；通知中心与「通知历史」两处都已生效。

### 7.6 分类 tab 的底色来源与玻璃加厚（2026-09-19 第四轮）

**① 「tab 不要背景，只要底部亮条」** —— 上一轮加的 tab 样式之所以还是带底色，是因为那条宽泛的按钮规则把它盖掉了：

| 规则 | 优先级 | 文件位置 |
|---|---|---|
| `.notification-cats button.active{…border-bottom-color:var(--accent)}` | 0-2-1 | 靠前 |
| `.notification-panel button:not(.n-main){background:var(--notif-btn-bg);border:1px solid …}` | **同为 0-2-1** | **靠后 → 胜出** |

于是 tab 被刷上了 `rgba(13,13,13,.06)` 底 + `1px rgba(13,13,13,.14)` 四边框。修复：把该广域选择器收窄成点名式（面板里只有 `.notification-clear` 是「文字动作按钮」），并把 tab 明确写成与页面内 tab（`.settings-tabs` / `.diag-tabs`）同一套：`flex:none` 自然宽度、`background:transparent`、`border-radius:0`、底部 2px 指示条、字号 `--text-control`。

实测（亮色）：tab 选中 `background: rgba(0,0,0,0)`、`border-bottom: 2px solid rgb(13,13,13)`、`border-top: 0`、`13px`、高 36；未选中底边为透明。`.n-del` 恢复为 `background:transparent`、`padding:0`、24×24。

**② 「半透明效果深一点，不然文字看不清」** —— 提高通知表面的密度：

| 令牌 | 亮色 | 暗色 |
|---|---|---|
| 面板玻璃填充 `--glass-fill-glass` | `.34` → **`.52`** | `.40` → **`.56`** |
| 条目卡片 `--notif-card-bg` / hover | `.52` / `.70` → **`.72` / `.88`** | `.07` / `.12` → **`.12` / `.18`** |

### 7.8 窗口分隔线对齐软件（2026-09-19 第六轮）

用户对照软件截图指出：**菜单栏那条竖线应该一直延伸到窗口顶部，而不是让顶栏的横线贯穿整个窗口宽度**。

### 7.9 窄菜单（面板路由）下的分隔线（2026-09-19 第七轮）

上一轮的竖线写死在 `left:244px`。但**面板路由的菜单会收成 64px 窄栏**（`body.panel-mode .app{grid-template-columns:64px …}`），这条线于是落到内容里、正好压在下方的按钮上。

用户给的判断是：「窄菜单会导致线条在按钮下面，所以应该是页面本身是圆角边缘，顶栏和菜单看起来是个整体。」按此实现：

| 调整 | 落点 |
|---|---|
| 竖线宽度改为跟随列宽 | 新增 `--side-w:244px`；`.app{grid-template-columns:var(--side-w) …}`；`.window::after{left:var(--side-w)}` |
| 窄菜单不再画竖线 | `body.panel-mode{--side-w:64px}`；`body.panel-mode .window::after{display:none}`；`body.panel-mode .side{box-shadow:none}`（原来那条规则里的 `box-shadow:1px 0 0` 也一并去掉） |
| 内容自己成为圆角页面 | `body.panel-mode .main{border-radius:12px 0 0 12px;background:var(--panel);border-left:1px solid var(--border)}`；`.panel-shell` / `.panel-frame` 底色由 `--bg` 改为 `--panel`，这样圆角处才看得见外壳 |

实测：面板路由 `--side-w:64px`、`::after` 不显示、`.side` 无阴影、`.main` 圆角 12px、`.app` 列宽 `64px 1114px`；其它路由仍是 `--side-w:244px`、`::after` 在 `244px` 处显示、`.side` 有 1px 阴影、`.main` 圆角 0（未受影响）。

> 本轮把「圆角页面」限定在面板路由（也就是用户指出的这一屏）。若要推广到全部路由（即彻底用「圆角内容」替代所有竖线），说一声即可；那会是一次全局外观改动。

### 7.11 内容页面左上角「漏出尖角」（2026-09-19 第九轮）

用户指着内容页左上角问「这里有漏出一个尖角是怎么回事」。

根因：标题栏原来**铺满整个窗口宽度**（`background:var(--glass-rail)` + `backdrop-filter:blur(22px) saturate(1.6)`）。内容页做成圆角后，左上角那块「缺角」露出来的不是纯色外壳，而是**被标题栏玻璃盖住、又叠了模糊的一层**——于是圆角旁出现一块形状不干净的角。

修法：让标题栏**只占菜单那一列**，和软件一致（不再横跨内容列）：

```css
.window{display:grid;grid-template-columns:var(--side-w) minmax(0,1fr);grid-template-rows:28px minmax(0,1fr)}
.titlebar{grid-column:1;grid-row:1}
.app{grid-column:1 / -1;grid-row:2}
```

这样内容列顶部那 28px 是干净的窗口底色，圆角缺角处也就只剩一种颜色。实测：`#settings` 下 `.titlebar` `[left 86, width 244, height 28]`；`#panel` 下 `[left 86, width 64, height 28]`；`.main` 分别在 `left 330` / `left 150`。左上角逐像素核对（亮/暗）为干净的圆弧，缺角区域颜色单一，无杂色角。

证据图：`13-窗口左上角-light.png`。

### 7.12 菜单与顶栏颜色对不齐（2026-09-19 第十轮）

上一轮把标题栏收窄到菜单列之后，用户指出：「这样菜单和顶栏颜色不一致，有没有别的办法」——标题栏与菜单是**两块独立的玻璃**（`.titlebar` 和 `.side` 各自有 `background:var(--glass-rail)` + `backdrop-filter`），而它们背后的环境光不同（标题栏在窗口最顶端，光斑更亮），于是同一套玻璃值渲染出两段颜色，接缝可见。

更好的做法不是去调平两块玻璃，而是**让它们本就是一块**：

| 调整 | 落点 |
|---|---|
| 菜单贯通到窗口顶 | `.app{grid-row:1 / -1}`，`.app` 自带 `grid-template-rows:28px minmax(0,1fr)`；`.side{grid-row:1 / -1}`（原来只占第二行） |
| 内容页只占第二行 | `.main{grid-column:2;grid-row:2}` |
| 标题栏不再是表面 | `.titlebar{background:transparent;backdrop-filter:none;z-index:6}` —— 只剩红绿灯，直接压在菜单那块玻璃上 |
| 内容位置不变 | `.side` 的 `padding-top` 由 18px 补成 **46px**（= 原 28px 标题栏 + 18px），面板路由同理 |

实测：`.side` 现在从窗口顶（top 79）贯通到底（height 758），标题栏 `background:rgba(0,0,0,0)`、`backdrop-filter:none`；`.main` 仍在 top 107（`#settings` left 330 / `#panel` left 150）。菜单与标题栏之间不再有第二种颜色，接缝消失。

证据图：`13-窗口左上角-light.png`、`14-窗口左上角-dark.png`。

### 7.13 底层合成一整块（2026-09-19 第十一轮）

用户给出更本质的做法：「整个软件底层一整块，然后页面内部是上面一层块，这样菜单和顶栏就保持同色了。」

前几轮一直在「把两块玻璃调平」，方向就不对。正确的结构是：**窗口只有一块底面**，菜单和标题栏都是这块底面上的内容（不各自成面），内容页才是浮在底面上的那一层。

| 调整 | 落点 |
|---|---|
| 底面抬到窗口本身 | `.window{background:var(--glass-rail)}`（原来是 `--bg`） |
| 菜单不再自带底色/模糊 | `.side{background:transparent;-webkit-backdrop-filter:none;backdrop-filter:none}`；面板路由同步 |
| 标题栏保持透明 | `.titlebar{background:transparent;backdrop-filter:none}`（上一轮已是） |
| 内容页是上面那一层 | `.main{background:var(--panel)}`（不变，实底一张圆角页） |

实测：

| | `.window` | `.side` | `.titlebar` | `.main` |
|---|---|---|---|---|
| 亮色 | `rgba(249,249,249,.66)` | `rgba(0,0,0,0)` | `rgba(0,0,0,0)` | `rgb(255,255,255)` |
| 暗色 | `rgba(23,23,23,.62)` | `rgba(0,0,0,0)` | `rgba(0,0,0,0)` | `rgb(38,38,38)` |

像素复核（菜单区 x150,y400 vs 标题栏区 x700,y135）：亮色 `(245,245,246)` / `(244,245,245)`、暗色 `(20,20,20)` / `(20,20,20)`——**菜单与顶栏同色**，只剩环境光本身的平滑渐变。

### 7.20 弹窗改为「标题 + 正文 + 操作」三段式（2026-09-19 第十八轮）

用户：「标题应该是固定才对。」「底部操作也是固定。」

**真因**：`.modal` 是 `overflow:auto; padding:20px`——**整个弹窗**是一个滚动容器，所以标题、正文、底部按钮一起被滚走。体检表（6 行 × 4 列 + 事实区 + 汇总）比弹窗高度长，标题与按钮就被顶出可视区。

**改法**：`.modal` 改成 flex 纵向三段，`overflow:hidden`，只有正文滚动。

| 元素 | 改前 | 改后 |
|---|---|---|
| `.modal` | `overflow:auto; padding:20px` | `display:flex;flex-direction:column;overflow:hidden;padding:0;max-height` 不变 |
| `.modal>h3`（标题） | 随内容滚走 | `flex:none;padding:20px 20px 0`（钉住） |
| `#modalBody` | 随弹窗整体滚动 | `flex:1 1 auto;min-height:0;overflow:auto;padding:0 20px 14px`（唯一滚动区） |
| `.modal-actions` | 随内容滚走、无分隔 | `flex:none;padding:14px 20px 20px;border-top:1px solid var(--border)`（钉住 + 发丝分隔线） |
| 覆盖式滚动条选择器 | `.modal::-webkit-scrollbar…` | 改为 `#modalBody::-webkit-scrollbar…`（6 条规则同步迁移，`.is-scrolling` 由既有捕获阶段 scroll 监听自动打在真正的滚动容器上） |

**范围**：这是 `.modal` 这个基类的改动，**所有弹窗**一并生效（原型的弹窗本来就共用同一套结构）。因此额外回归了三种形态：

| 形态 | 弹窗 | 结果 |
|---|---|---|
| 长内容 + 宽弹窗 | 新增 MCP（`modal-wide`，720px） | 标题钉住、底部 `返回` / `添加` 钉住并带分隔线 |
| 中等内容 | Skills 同步体检 | 同上 |
| 短内容 | 卸载 Skill | 高度贴合内容，分隔线正常，无多余滚动 |
