# 五项恢复差额本机验证与Windows补验方案

2026-11-10。用户授权“继续完成到Windows补验”，本轮承接Windows revision2回交的2个变化原文件和3个新增文件。产品基线Desktop0.2.23，目标0.2.24；仅隔离技术原型，不开发apps、不改官方2.99、不操作日常配置或发布。已采用的两锁有限例外保持，不增加缓存/日志/备份例外。

## 本机做了什么

在私有HOME/OPENCODEX_HOME/CODEX_HOME/GROK_HOME调用真实官方API：refreshCodexModelCatalog→injectCodexConfig→injectGrokConfig→restoreNativeCodexAsync→stripGrokConfig→invalidateCodexModelsCache。没有启动服务、模型请求、OAuth刷新或网络；所有外网被sandbox拒绝，日常目录拒读，官方源码/依赖只读。

两组正常主路径均完成：辅助3文件原不存在、辅助文件已有合成用户内容。每组都保留before/during/after原始字节（包括变化后的原件）、模式和摘要；JSON/TOML结构只在原字节之后派生，不能解析失败便丢原件。config和Grok config字节恢复；catalog/缓存/审计/备份的实际变化如上。

首次写入链因沙箱漏列官方原子adoption临时SQLite失败；第二次修正regex转义仍拒绝；第三次配置/catalog恢复成功，但history worker独立协调SQLite被拒绝，导致整体success:false。三次原始失败分别保留，**都不算官方产品根因或通过**。第四次仅补本次私有HOME摘要/状态DB摘要对应的确切新协调路径和adoption临时文件命名空间，保留官方身份/写锁/路径检查，整个链完成。没有开放整个共享运行根或改上游保护。已有辅助文件的第二组输入另开目录验证。

## 候选恢复方案与验证结果

候选采用受保护的“操作前原件＋官方写入后像＋退出后封口＋精确写集”，范围只含这5个对象，继承已验证的Agent事务思路：

1. 首次启动/写入前保存实际原件字节、路径身份/权限及原来不存在；记录源、目标、事务ID和根绑定。不把已跑过服务的事后目录冒作原始基线。
2. 正常服务退出、原句柄/Job/全部监听证明完成后，在当前用户/HOME的官方必要协调锁与原生排他文件边界内封口。后像必须与本次受控写入及官方恢复阶段有可审查关联；**仅观察到新文件或拿到摘要不构成归属证明**。手动外部变化、未识别字段/追加或非本事务写者保持冲突，不强套原件。
3. 审计/失败内容先受保护封存，不以恢复客户端目录为由销毁诊断。全批先验证后像、路径/文件身份、链接/多硬链/可读性、原件完整性及空位；全部满足才补偿。原存在恢复原字节/权限；原不存在只删除本事务新建且当前仍等于已封存后像的对象。未变对象无操作。
4. 逐步记录持久事务意图/进度；失败先尝试在同受控边界回退到封存后像，不误报正常还原；未知/崩溃恢复必须核对实际状态属于原件或后像，不覆盖第三种状态。原始两个锁文件不在删除/重建集合内。
5. 读回配置、路由、catalog/cache及完整客户端树，原10秒Stop计时包括全部官方退出、Agent/五项补偿、锁证明和最终核对，不能给补偿另开预算。

本机13项检查通过：两组真实官方产物恢复原件及模式、用户备份/缓存/原审计保留、外部编辑/符号链接/硬链接/缺失/不可读/计划改动/父路径链接整批拒绝且不提前写、第二步注入失败回退、真实子进程写一步后突然退出及新进程恢复、未知新增用户文件保留并仍报告树不一致、恢复时遇第三种内容拒绝。事务内审计后像仍保存在受保护样例证据中。

采集器7项通过：变化后内容无条件封存、不合法JSON仍保原字节、不可读为unknown且继续其它项、缺席独立记录、链接不跟随、base64/长度/摘要一致、未注册凭据或任意发现路径拒绝。它修正的是旧“after仅等于before时才保存字节”的采集缺陷，不是宣称Windows实际故障根因已经补出。

**验证限制**：以上是POSIX隔离算法/官方函数链。Windows排他句柄、owner/DACL、官方N/K协调锁集成、实际服务停止总预算及崩溃恢复必须在原生test原型验证；本机文件API的预检不被当作跨进程排他。真实日常配置的后像归属尚未实现/证明；此方案不是任意whole-file强覆盖器，也不是生产适配完成。
