# 0.2.6：页面主 Tab 到顶后的玻璃材质

2026-10-22，用户在原型 models 页指出主 Tab 滚到顶部后仍然全透明，随后确认桌面软件同样如此，纳入 0.2.6。本文登记根因、修法与验证。

## 现象

Tab 条贴住页面顶部后依旧全透明，下方渠道列表从 Tab 背后穿过，文字互相叠压。CSS 里本来就有 180ms 的 `background-color` 过渡，但从未被触发。

## 根因

**把负的 sticky top 又加了一次。**

Tab 为吃掉主容器内距，`top` 设成负值（实测 `-20px`）。浏览器会把负偏移**夹在滚动口边缘**，Tab 贴住的位置就是容器上边框内侧。但判定写的是 `吸附线 = 容器顶边 + clientTop + offset`，相当于把吸附线推到容器上方 20px——Tab 永远够不到，`data-stuck` 恒为 `false`。

浏览器实测（本地静态服务，models 页）：

| scrollTop | Tab 上沿 | 是否已贴住 | 旧判定 |
| --- | --- | --- | --- |
| 0 | 130 | 否 | false |
| 95 | 35 | 否 | false |
| 100 | 30 | 是 | false ← 错 |
| 600 | 30 | 是 | false ← 错 |

把 `data-stuck` 强制为 `true` 后玻璃立即出现，证明材质与过渡本身没问题，纯粹是判定没触发。

实现侧还有一层独立错误：`StickyTabs.vue` 用 `offsetTop` 链累加求自然偏移，而 `.main` 是 `position: static`，不是 `offsetParent`，链在中途跳出容器；同一页面两次测量得到 129 与 429，判定完全不可靠。

## 修法

**原型 `sticky-tabs.js`**：吸附线改为 `容器可视顶边 + clientTop`，与浏览器夹住负偏移的位置一致；半像素容差只吸收舍入。

**实现 `components/layout/StickyTabs.vue`**：判定优先用矩形比较 `bar.top <= main.top + clientTop + 0.5`；jsdom 矩形恒为 0 时退回 `offsetTop` 链，保持既有单测语义。真实运行一定走矩形比较。

## 过渡时长（2026-10-23 修正）

用户反馈“淡入太慢，跟不上”。原实现把吸顶材质挂在常规过渡 `--motion-normal`（180ms）上；吸顶是跟随滚动的位置态，180ms 明显滞后。

新增 `--motion-sticky: .09s`，只用于吸顶的背景与下边框；`--motion-normal` 仍保留给内容层。中 / 低画质档下该令牌为 0，直接给终态。原型 `index.html`、`sticky-tabs.css`、`model-config.css` 与实现 `tokens.css`、`StickyTabs.vue` 五处同值。

## 验证

- 原型 `sticky-tabs.test.cjs` 5 项通过（用例改为按 `main.top + clientTop` 计算，并断言“差 1px 仍透明、到线才吸顶、越过保持、回滚取消”）；原型全量 31 文件 258 项通过。
- 实现 `vue-tsc` 通过；前端 152 文件 737 项通过 / 11 项跳过。
