## 2. 已确认与待决策

- **D-1 官方版本卡片语义**：
  - A. 文案改为“重新读取本地版本”，承认只做本地事实——最小改动，语义诚实；
  - B. 新增只读远端查询（`npm view @bitkyc08/opencodex@latest version` + `dist.integrity`），显示“有可用更新”。B 更接近用户预期，但引入了网络查询与版本比对逻辑。
- **D-2 官方更新的承载方式**：查询走桌面管理器自建只读查询，还是读官方代理 `GET /api/update/check`（需管理 token）。
- **D-3 安装是否由桌面管理器代跑**：建议复用 `install_runtime` 由管理器完成，避免官方更新器写托管前缀；是否允许代跑属独立授权点。
- **D-4 配置分层深度（2026-10-04已确认）**：采用“固化默认 + 单文件分域偏好 + 既有机器配置 + 状态 + 凭据”；确认文件结构与通用自动转换规划，先统一内部类型与消费，再升级存储schema。30字段兼容与29项盘点见 [分层建议](02-配置分层规划建议.md) / [固化清单](04-硬编码盘点与固化配置清单.md)。配置实现须同步更新中英文 README（U-10）；具体行为裁决与版本分配仍见下文，未执行迁移。
- **D-5 0.1.2 范围**：是只做“更新通道可用”，还是同时完成配置分层；建议先做默认与有效策略最小闭环；容器/同步兼容的存储升级可独立安排。
- **D-6 与 MNT-01 的关系**：0.1.2 是否合并承接 MNT-01 未纳入 0.1.1 的 F-08 / F-10 / F-11 / F-12 候选（尤其 F-10 测试版自动更新端点，与本记录同域）。

补充待裁决：历史退役字段的保留范围；导入/同步必需备份与无效果开关的处理；自动检查默认启用时机；registry继承或显式默认；新容器/同步版本与旧客户端的兼容范围；U-09最早支持的schema/应用版本与恢复备份窗口。

## 3. 限制与边界

- 本记录不构成版本发布决定；未修改 `CHANGELOG.md`、`tauri.conf.json` 或任何源码。
- 端点可配置、**公钥不可运行时配置**——这是安全边界，不是实现细节。
- “检查更新”（只读）与“安装更新”（写）必须分开；写操作需单独授权与备份。
- 面板内更新器对托管 / 自定义前缀不安全，**不**建议由桌面管理器调用它去改托管前缀。
- 查询远端会产生网络访问与版本比对；需超时、脱敏与失败不改写本地状态的约束。
