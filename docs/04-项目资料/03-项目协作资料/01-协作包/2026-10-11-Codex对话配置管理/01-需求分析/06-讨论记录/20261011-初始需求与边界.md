# Codex 对话配置与实时生效

日期：2026-10-11（Asia/Shanghai）
状态：需求分析增量，待评审与原生能力验证。

## 背景

本轮讨论提出以下独立方向：Codex 对话自动命名、Web Search 模型自定义、子 Agent 自定义，以及全局、项目、thread 三个作用域的配置和继承。此前误建的 packages/opencodex-collaboration 是 Rust 代码包，已从文档分支移除；本轮材料归入新建的独立协作包。

## 本轮写入

新增 [Codex 对话配置与实时生效方案](../02-方案草案/Codex对话配置与实时生效方案.md)，记录：

- 全局 → 项目 → thread → 当前请求的覆盖顺序；
- 项目 / thread 列表读取、稳定 ID 和失效绑定处理；
- 自动命名、Web Search、子 Agent 的独立配置边界；
- 请求前生成运行时 overlay，不反复改写全局 config.toml；
- 当前请求不切换，以及下一次请求、下一次子 Agent、刷新 / 重启和暂不支持等生效阶段；
- 开发前必须验证的原生接口与验收条件。

## 状态与限制

本轮只修改文档，没有修改 apps、OpenCodex 运行配置、用户凭据或原生 config.toml，也没有把需求写成已实现功能。OpenCodex 是否支持某个字段的实时更新，必须以目标版本的 API 探测、读回和最小运行验证为准；若原生没有暴露独立 Web Search 模型或 thread 标题更新能力，应在界面标记暂不支持或采用用户明确选择的跟随策略。
