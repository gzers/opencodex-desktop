# 对话体积与导出空间评估

日期：2026-10-13（Asia/Shanghai）。状态：本机文件元数据统计与设计建议；未读取对话正文，未压缩或导出真实对话，未清理文件；版本与开发时机未定。

用户要求：“但是评估一下对话是不是会很大，占用空间多么？”本文评估 [项目与对话联合导出及恢复方案](../02-方案草案/项目与对话联合导出及恢复方案.md) 的容量影响及原型需要补充的反馈。

## 1. 结论

大部分历史记录只有少量 MiB，但少数长任务的原生文件可以达到 GiB 级，不能用普通聊天记录的体积推断完整项目包。当前本机有明显的大文件长尾，因此导出要支持选择范围、体积预览、流式打包和明确的轻量 / 完整用途。配置文件本身继续保持独立，不会因为支持导出就自动增长为完整历史副本。

导出可作为显式一次性操作，不需要为容量增加强制审批或硬性限制。空间不足时根据实际执行所需容量报告失败或提供缩小范围的选项，不用未经校准的阈值禁止所有大对话导出。

统计边界：

- 文件逻辑大小及 stat 分配块数不等于 APFS 去重 / 克隆后的唯一物理占用；也不等于 ZIP 大小。源文件运行中可能继续增长。
- 未读正文或压缩，最大文件成因和实际压缩率仍未知。本轮不检查内容或做大文件压缩测试。

## 3. 哪些因素会使包变大

以下是通用增长因素，不是对本机超大文件成因的判定：

| 内容 | 对容量的影响 | 设计处理 |
|---|---|---|
| 用户 / 助手文本 | 通常比完整原生事件少；长回复和多轮会增长 | 轻量记录可以聚焦可见消息，注明是否省略其他内容 |
| 工具调用 / 输出 | 大段日志、源码、搜索结果或重复事件可显著增大历史 | 阅读模式可选摘要 / 完整输出；原生恢复模式不擅自删改事件 |
| 子 Agent 与 fork | 多条独立记录可能有继承或重复上下文 | 按实际选中记录统计，包内相同对象只收集一次，不把关系重复遍历成多份 |
| 图片、音视频和附件 | 压缩过的二进制可能占主要容量；文本内编码也会膨胀 | 附件独立选择，显示实际打包 / 仅引用 / 缺失，不对二进制承诺固定压缩比例 |
| 多种历史表示 | Markdown、结构化历史与原生载荷同时保存可能重复内容 | 默认按用途保留一种主要历史表示，其他表示按需生成 |
| 重复整项目导出 | 每个包都有当时副本，长期保留会累积 | 每次明确范围及大小，已有导出文件由用户保留；不随配置保存反复自动导出 |

同一线程的上下文压缩也不据此认定落盘历史已被清除。新的任务、fork 或归档操作是否减少磁盘空间，应看实际存储行为；本包的归档配置清理只清管理器策略和状态，不删除 Codex 历史。

纯文本与 JSON 通常可以压缩，实际比例依赖内容；图片和已压缩附件改善有限。本机没有实测压缩率，方案不以“固定减少 90%”等假设估算成功条件。

## 4. 导出用途与体积控制

保持此前三种导出用途，但进一步限定默认内容：

| 用途 | 主要历史表示与默认行为 | 恢复含义 |
|---|---|---|
| 仅配置 | 仅策略、引用和元数据；不含历史 | 可复用设置，不承担任务上下文恢复 |
| 对话记录 / 轻量留档 | 用户 / 助手可见消息为主，工具记录可选摘要或完整；默认不带附件二进制，提供单一 Markdown 或结构化输出 | 适合阅读 / 交接；省略部分内容时明确标记，不保证原生续聊 |
| 项目 / 对话联合包 / 原生恢复 | 保留所选原生历史和关联配置；子对话、附件按范围选择。默认不再复制一份完整 history.jsonl 和 transcript.md | 保持适配器所需原生载荷完整；若缺依赖资源或子树关系，说明具体恢复范围 |

原生恢复模式不能为了省空间任意删掉工具输出或只取最后几轮，仍显示“完整恢复”。选择近期记录或人工 / 模型摘要可以作为单独留档 / 交接用途，不混同无损原会话恢复；摘要本身也不是必需模型任务，本轮不增加付费自动总结。

需要可阅读副本时可由已导出的主要历史表示生成，包内附带为用户选项；需要全部形式也允许，但预览显示额外体积。附件在一个包内按内容摘要复用一份，选中记录按对象 key 去重；原生记录内部的数据不通过未经验证的跨线程文本去重改写。

项目默认带入当前选择，不开页即全选所有归档和全部子 Agent。预览分列配置、主对话、子对话、附件、额外阅读副本以及合计。原生文件用元数据先估算，额外表示尚未生成时标“待计算”；压缩包只显示估计值 / 实际值的区别，不为了预览先把所有内容读进内存。

## 5. 实现与空间峰值

长历史通过受支持的 turn / item 分页或原生记录流式读取，边读边写压缩输出，不将完整大项目组成一个内存数组或巨型 JSON。分页后端不支持时如实选择可用读取方案及范围，不把全量 includeTurns 当作任何大小都能处理的默认路径。

压缩输出直接写入目标目录的临时包，结束后完成校验并改名；不先复制整个未压缩项目，再生成第二个完整包。取消 / 失败只清理本次临时产物，保留源历史、已完成的其他导出及原配置。大包使用支持 ZIP64 的格式和读写库，覆盖单文件 / 总包超过 4 GiB 的情况。

显示未压缩所选数据量、压缩进度 / 已写入量、目标盘可用空间；压缩率未知时使用保守容量估算并在流式写入时更新。容量限制由实际介质与格式能力决定，不使用统计平均值掩盖大记录。

导出额外空间至少是最终包和必要临时工作区；原生导入还需要暂存 / 展开及目标记录的空间，具体峰值取决于是否同卷移交、是否能避免再次复制。需要按实际流水线计算，不能统一承诺额外空间只有压缩文件大小。

仅作预算示例：若选中约 10 GiB 原生记录，在压缩率未测前，应按可能生成接近原始大小的包安排目标空间。导入若同时保留包、展开件和目标副本，峰值会明显高于单份历史；采用流式输出和受控移交可以减少临时重复，但不能凭方案存在就承诺已完成优化。

本包不新增默认后台全量内容备份、定期整项目压缩或 WebDAV 历史上传。需要长期重复备份时再讨论增量机制，不将远端同步 / 分卷 / 跨包去重作为首轮导出的前置条件。

## 6. 原型与后续验证

原型设计仍可继续，导出弹窗增加用途、对象范围和体积摘要；大项目的分页收集、计算中、压缩进度、取消、空间不足、单文件超 4 GiB、部分内容不可读都用 mock 演示。正常导出一次操作，大小提示不额外增加统一确认门禁。

后续实现需用合成数据验证有界内存、流式取消与临时清理、ZIP64 往返及空间不足反馈；去重不遗漏父子关系，原生恢复不因瘦身丢上下文。压缩率以具体导出结果衡量，不把当前元数据统计记为性能测试或大包恢复验收通过。

本轮仅保存聚合容量回执和文档建议，没有读用户对话正文、压缩 / 复制历史、删除数据或新增生产功能。

扣除大文件仅用于分析容量分布，不表示恢复包应自动忽略它们；是否需要其上下文由用户选择。两份大记录仍在未归档目录，排除归档不会解决主要空间占用。统计只覆盖当前一个 HOME 下的原生 JSONL，不含全部附件、数据库或其他数据源。

对于临时重装，一次性保存所需未归档历史及关联配置合理：大部分文件较小，全选当前范围则需要按约 12.01 GiB 原生量评估包与恢复空间，最终压缩大小仍需实际打包。重装后恢复完成，用户可自行处理临时包；不能自动因原对象归档或首次导入成功就删除用户导出文件。

导出的必要性取决于重装是否清理原 Codex 数据源和管理器配置根：若原目录保留且新版本能够读取，可以重新接入原数据，不必为了重装再复制所有历史；若会清理目录或需要换到新数据根，恢复包才承担保留数据的作用。不假设卸载应用必然删除或保留这些独立目录。

**首批产品范围收敛为本机重装前导出、重装后恢复**。不要求同时做日常全量内容备份、团队交接、跨设备周期历史同步或自动总结服务；前文轻量阅读用途保留为可选设计，不是首批恢复能力的必要条件。原生包优先完整保留所选对话恢复所需数据，不能用摘要替代。

建议专用入口为“导出重装恢复包”，默认候选范围为当前选择的未归档项目 / 对话及关联配置；归档另行勾选。显示大记录与合计，主 / 子对话和附件依赖明确呈现，用户可以按实际需要选择，导出目的地由用户指定为重装后仍可访问的本地目录或外置介质；不默认把唯一恢复包留在计划清除的 Codex 数据根内。未修改系统或自动执行卸载。

同步页面的“对话配置”和“对话历史”保持两个独立范围，对话默认不勾选。新建连接、旧配置缺字段、通用预设重置、恢复包导入均不自动开启对话同步；选择配置不顺带选择对话。本次用户用途明确为本地重装恢复，不上传 WebDAV，也不要求首批实现历史远端交换。以后是否显式启用历史同步另行选择，不改变默认值。

原型第一轮应验证本地恢复包的对象 / 内容范围、体积预览、保存位置、恢复映射和结果，以及同步页对话默认未选；重装包可以主动包含对话，这属于显式本地导出预设，不能沿用该勾选到 WebDAV。
