# 测试验收

状态：**以下 58 项均为生产验收条件，尚未执行**。本轮完成的是文档检查，证据见 [版本记录](../01-需求分析/06-版本记录/README.md)。

使用合成、脱敏样本和隔离测试站点，不上传日常真实账本或供应商凭据。每项结果应记录版本、输入 / 动作、预期 / 实际和可复核证据。

| ID | 场景 | 验收条件 |
|---|---|---|
| AC-U01 | 两用户、各两设备 | 个人总量等于各自仍有权限的设备 / 空间事件集合；全站等于有效唯一集合，不重复、不串账 |
| AC-U02 | 越权读写与伪造 owner | 改 user_id、team_id、成员期、device_id、source_id、筛选或分页参数均不能读写他人数据；无内容泄漏 |
| AC-U03 | 缓存 / SQL / RLS 连接复用 | 切用户、并发请求和后台任务不会继承前一租户上下文或缓存 |
| AC-U04 | 导出任务 / 下载越权 | 他人任务 ID 和下载地址无效；过期文件不可下载；错误不泄露内容 |
| AC-U05 | 管理员权限 | 站点角色允许全站聚合和用户管理，团队角色单独判定；不能凭聚合权限导出他人明细；操作有审计 |
| AC-U06 | 服务发现与身份变化 | 不兼容协议、证书错误、同域新实例被识别；旧凭据与队列不会自动发送 |
| AC-U07 | 原生登录 / 凭据 | 验证 PKCE、state / issuer / redirect，凭据仅在正确系统账户位，日志和 WebView 不暴露长效秘密 |
| AC-U08 | 撤销设备 / 用户停用 | 新请求及时被拒，客户端暂停；旧访问令牌不能无限等到到期才体现撤销 |
| AC-U09 | 改设备名 / 同名设备 | 改名不增设备数、不改历史归属；同名机器仍各自独立 |
| AC-U10 | 换账号有待传数据 | A 队列封存，B 不能获取 / 接管；A 来源不转属，必须用 B 独立来源 |
| AC-U11 | 共享 runtime | 无可信调用者映射时拒绝自动归属；不能把整本共享账本归给当前登录人 |
| AC-U12 | 默认范围 / 历史预览 | 默认只采开启后；导入历史有范围、数量、归属和缺口预览，无隐式全量认领 |
| AC-U13 | 已提交但 ack 丢失 | 重传任意次数只保留一份事件，统计不增加；返回 duplicate |
| AC-U14 | 身份内容冲突 | 同 source / event 改 payload 时显式 conflict，不覆盖旧值或换新 ID 偷加 |
| AC-U15 | 本地进程崩溃 | 采集位置与 outbox 同事务；任一崩溃点恢复均不跳过未持久化记录 |
| AC-U16 | 分页边界与并发晚写 | 游标失效、同时间戳、读取期间追加、晚写均可重扫去重；无法覆盖时显示缺口 |
| AC-U17 | JSONL 半行 / 轮换 / 裁剪 | 只读完整行；来源身份稳定；旧内容不可达有 gap，不能谎报全量完成 |
| AC-U18 | 限流 / 服务器故障 | 遵循退避与 Retry-After，模型调用继续；恢复后补传并显示新水位 |
| AC-U19 | 坏事件 / 超大事件 / 队列满 | 不静默截断；隔离坏数据，其他记录可前进；队列满有提示和后续缺口策略 |
| AC-U20 | 受控恢复 / 克隆 | 历史来源 / 事件 / 原设备保留；克隆后新数据有独立分界，旧历史不重复 |
| AC-U21 | 无谱系旧副本 | 默认不导入；人工认领不冒充已经自动验证精确去重 |
| AC-U22 | 双采集器 / ID 碰撞 | 同来源重扫只计一次；不同合法来源相同 requestId 不被误删 |
| AC-U23 | Hub 与本地重复观察 | 一个权威观察路径；未经可靠关联的两侧记录不直接叠加 |
| AC-U24 | 请求 / 逻辑 / 尝试 | 重试、修复、combo 显示各自语义；缺 logicalRequestId 单列覆盖，不全并成 1 |
| AC-U25 | 父行 / attempts / sends | 总量与分摊不重复相加；行级 spend 与 attempt sends 不再累加；跨行覆盖关系有样本证据 |
| AC-U26 | Token 包含关系 | 输入 1000、读缓存 600、写缓存 100、输出 200、推理 50 得基础总量 1200；旧 source_total 差异保留版本标记 |
| AC-U27 | 未计量 / 未定价 | reported / estimated / unreported / unsupported 区分；没有价格不是费用 0，未同步不是用量 0 |
| AC-U28 | 分组与合并比例 | 多模型请求数不误加为全局数；吞吐 / 缓存用有效分子分母，p95 不平均设备 p95 |
| AC-U29 | 定价版本与 tier | 重算产生可识别的新版本；缓存 / 长上下文 / tier 按已验证规则计价，USD 和其他货币不混加 |
| AC-U30 | 跨午夜与夏令时 | 同 UTC 事件在指定 IANA 时区正确落桶；半开区间无漏计 / 重复，设备时区不同不影响统一报告 |
| AC-U31 | 晚到 / 时钟偏差 | 晚到更新发生日并刷新聚合；异常未来时间标记，不无声改为 received_at |
| AC-U32 | 水位与质量提示 | accepted 与已聚合区分；本地缺口、未计量、过期不可重分桶分别可见；最后同步不当作在线 |
| AC-U33 | 白名单与敏感样本 | 含 prompt / 响应 / 路径 / 会话 / key / 自由错误文本的样本不会出现在上传、队列投影、服务日志和导出 |
| AC-U34 | 标签维度 | 同名渠道不自动跨用户或跨来源合并；用户别名长度校验，无自动上传仓库路径 |
| AC-U35 | 明细过期后重复上传 | 去重窗口 / 截止线与保留策略配套，不能再次增加保留的汇总；超窗导入受控 |
| AC-U36 | 主动删除与旧队列重放 | 事件、聚合、缓存、导出同步清理；墓碑 / 删除水位阻止旧记录复活 |
| AC-U37 | 备份恢复与撤销 / 删除 | 先重放删除与撤销记录，旧凭据不复活；恢复后重复补传不翻倍；实测恢复时间 |
| AC-U38 | 源码兼容矩阵 | 对支持的 OpenCodex 版本逐一复核字段 / 口径；未知版本显示受限状态，不瞎猜格式 |
| AC-U39 | 代表性负载 | 记录事件 / attempts 分布、批量吞吐、查询延迟、队列和存储增长；不把容量假设当成达标 |
| AC-U40 | 分析可信度与扩展边界 | 页面说明为已接收的自报统计 / 估价；预算为提醒；没有借统计连接偷偷启用远程执行或上传配置凭据 |

## 团队与跨空间验收

| ID | 场景 | 验收条件 |
|---|---|---|
| AC-U41 | 一人多团队 / 交叉成员 | 两用户交叉加入团队 A / B，个人、团队和全站各自范围明确；成员资格不复制历史事件 |
| AC-U42 | 交叉视图去重 | 同用户个人 10 + 团队 A 20 + 团队 B 5，在有权限时我的视图 35、全站 35，不把团队视图再次叠加 |
| AC-U43 | 团队管理者越权 | 只看本团队 / 成员聚合，不能看成员私人数据、其他团队、完整设备名录或他人事件明细 |
| AC-U44 | 篡改团队和成员期 | 上传伪造 team_id / binding / membership_epoch 被拒；服务器从当前授权来源推导 scope |
| AC-U45 | 切团队有待传数据 | 原队列保留原团队 / 成员期，不随 UI 当前团队或上传凭据切换重贴标签 |
| AC-U46 | 来源空间与独立 profile | 验证一来源一空间，页面切换不能改变既有记录；多 profile 不支持时明确限制，不能重新登记旧账本转属 |
| AC-U47 | 邀请安全与角色 | 一次性 / 过期 / 重复接受有效控制，接受人必须登录明确确认；管理员不能邀请所有者或越权提权 |
| AC-U48 | 唯一所有者 / 转移 | 最后所有者不能直接退出或被移除；并发转移保持恰好一名所有者，授权和审计一致 |
| AC-U49 | 成员撤销 / 角色降级 | 已签 token、连接池、缓存、导出任务及下载都复核新权限；个人来源和其他团队不受影响 |
| AC-U50 | 离队后的离线补传 | 即便自报发生时间在离队前也拒绝直传；封存原空间队列，不自动算作个人或其他团队 |
| AC-U51 | 重新入队 | 新成员期不激活旧授权 / 旧队列 / 原成员期明细；首期新记录使用新建独立来源，不能导入原期账本 |
| AC-U52 | 历史权限与离队成员 | 团队保留已入库历史并标记已离队；管理者可看团队历史聚合，普通成员离队后不可再读 |
| AC-U53 | 个人删号与团队记录 | 清理个人空间和档案关联，团队记录按明示策略保留去身份化引用；不把团队历史误删或转属新账号 |
| AC-U54 | 解散 / 删除团队 | 撤销邀请和上传授权，清理对应聚合 / 任务 / 下载；无孤儿事件、无个人转存、无重放复活 |
| AC-U55 | 导出期间角色变化 | 创建、执行、读取、下载时重新授权；成员被移除后无法利用旧任务取数 |
| AC-U56 | 团队展示隐私 | 团队视图只显示团队范围设备 / 来源别名及必要成员信息，不泄露私人系统名、其他团队或全体邮箱 |
| AC-U57 | 团队预算 / 项目后续范围 | 团队聚合可供未来预算使用，但首期不声称硬限额或未实现的项目标签 / 模版共享已可用 |
| AC-U58 | 共有机器 / Hub 服务身份边界 | 缺个人映射时不伪造某个成员；团队服务身份未实现时明确拒绝该接入方式 |

团队是首期核心，AC-U41～U56 应纳入首期回归；其余适用条件一并执行。对暂不支持的恢复 / 项目预算 / 服务身份场景，验证明确拒绝及产品说明，不能跳过后宣称全部通过。
