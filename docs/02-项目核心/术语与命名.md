# 术语与命名

写文档、写代码、写界面文案时对齐用。术语的定义以本文件为准；本节之外的编号（`REQ-*` / `AC-*` / `R-*` / `T-*`）由需求侧与安全评审定义，本目录只引用。

## 1. 术语表

| 术语 | 定义 | 不要写成 |
|---|---|---|
| 数据目录 | 用户可见、承载**管理器自有产物**的统一数据根。 | 数据根、统一数据根 |
| `OPENCODEX_HOME` | **OpenCodex 自身**的数据目录，可在数据目录内，也可指定为独立路径。 | 与「数据目录」混用 |
| 管理器自有域 | 发现与只读状态、启停、数据目录、备份、加密导出/导入、WebDAV 同步、自更新检查。CLI 控制面的能力边界。 | 自有能力、本机能力 |
| 外部域 | provider、路由、模型映射等 OpenCodex 核心运行配置。一律走官方 CLI。 | 核心配置、官方配置 |
| 扩展配置 | 本产品**允许写入**的例外范围：Skills 目录同步与各客户端的 MCP 服务器节点。 | 插件配置 |
| 核心运行配置 | provider、路由、模型映射等**禁止写入**的内容。 | 与「扩展配置」混用 |
| 托管子进程 | 由管理器后端启动并持有的官方 `ocx` 进程。 | 子进程、代理进程混用 |
| 官方 CLI | 命令名 `ocx` 的 OpenCodex 官方命令行。 | 简称「CLI」（会与管理器 CLI 混淆） |
| 管理器 CLI | 命令名 `ocxd` 的本产品命令行入口。 | 简称「CLI」 |
| 运行状态 | 代理进程本身的观测状态。 | 与「连接状态」「操作状态」混用 |
| 连接状态 | WebDAV 等外部依赖的连接与同步状态。 | 同步状态 |
| 操作状态 | 单次动作的执行阶段状态。 | 任务状态 |
| 环境前置门禁 | 安装发现前的 `node` → `npm` → `ocx` 短路检查。 | 前置检查、环境检查 |
| 冷同步 | 运行中不直接写关键文件，需用户确认后才执行覆盖。 | 手动同步 |
| 单一真相源 | 管理器维护的统一扩展配置，是权威。 | SSOT 直接写进界面文案 |
| 投影 | 由统一配置逐客户端生成 / 更新的 live 配置文件，不是权威。 | 同步副本 |
| 受控共享写入 | 官方 CLI 与外部编辑器也会写同一节点，因此靠文件锁 + 摘要比对 + 备份 + 原子替换 + 冲突待处理来写。 | 独占写入 |
| 原子替换 | 同目录临时文件写入后原子改名覆盖，替换后保留原权限。 | 直接覆盖 |
| 可恢复删除 | 删除类操作进回收区而非直接抹除，保留恢复窗口。 | 软删除 |
| 风险摘要 | 对 `at_risk` / `external_takeover` 的可读解释与建议动作。 | 报错信息 |
| 通知中心 | 顶栏通知入口与「诊断中心 → 通知历史」**共用同一份数据**的视图。 | 消息中心 |
| 诊断中心 | 日志路由内的只读排障入口：运行环境诊断 + 通知历史。 | 体检中心 |
| 套壳应用 | 本产品（OpenCodeX-Desktop）在「双版本升级」语境下的自称。 | 客户端、外壳 |

> 「数据目录」是**用户可见文案的统一写法**；正式文档里若需强调其数据根性质，可写「数据目录（数据根）」，但界面与用户可见文案只用「数据目录」。

## 3. 命名写法约定

| 对象 | 规则 | 示例 |
|---|---|---|
| 仓库 / 项目标识 | 全小写连字符 | `opencodex-desktop` |
| 界面展示名 | 驼峰式品牌写法 | `OpenCodeX-Desktop` |
| 治理项目 ID | 与仓库标识一致 | `opencodex-desktop` |
| 治理项目编号 | 全大写连字符 | `OPENCODEX-APP` |
| 客户端标识 `client_id` | 全小写单词，不加连字符 | `codex` `claude` `gemini` `grok` `opencode` `hermes` |
| 状态枚举取值 | 全小写 `snake_case`，英文 | `starting_failed` `external_takeover` |
| 实体字段名 | 全小写 `snake_case`，英文 | `opencodex_home` `content_hash` |
| 界面文案与字段 | **解耦** | 字段叫 `data_root`，界面写「数据目录」 |
| 协作包目录 | `<日期>-<主题>` | `2026-09-12-桌面管理器需求梳理与原型验证` |
| 文档目录 | 两位数字前缀 + 中文名 | `01-需求管理` `02-项目核心` |
| 数据根分区 | 文档与代码引用**分区键**（逻辑名），不引用物理目录名 | `sync state` |
| 时间戳 | ISO 8601，带时区 | `2026-09-14T15:32:13+08:00` |
| 内容摘要 | SHA-256，十六进制小写 | — |

### 3.1 两个名称并存

`opencodex-desktop` 与 `OpenCodeX-Desktop` 指同一产品，**并存是既定约定**：前者用于项目与仓库标识，后者用于界面展示。不要求统一写法，**不得据此发起批量重命名**。

## 4. 口径红线

| 红线 | 说明 |
|---|---|
| 界面不得出现阶段编号 | `P0` / `P1` / `P2` 不进入应用界面；界面只用功能名与状态（「规划中 / 可用」）。阶段编号只在文档与原型注译区使用。 |
| 不使用含糊按钮文案 | 不用「修复」「清理」表达不可逆动作；按钮用明确动词：启动、停止、重启、刷新状态、打开面板、查看日志。 |
| 敏感值永远掩码 | 任何界面、日志、错误信息、通知正文都不出现明文凭据；掩码长度不泄漏真实长度。 |
| 不伪造成功 | 能力不可用时明确说明原因，不显示空成功状态。 |
| 两个版本对象不混 | OpenCodex 本体与套壳应用不得共用一个更新按钮；文案必须让用户分清当前更新的是哪一个对象。 |
| 数据目录与 `OPENCODEX_HOME` 不混 | 界面不得把两者写成同一个东西。 |
| 官方权威不越权 | 凡官方已有权威通道的（更新、provider、路由），只做引导与展示，不提供写入通道。 |
