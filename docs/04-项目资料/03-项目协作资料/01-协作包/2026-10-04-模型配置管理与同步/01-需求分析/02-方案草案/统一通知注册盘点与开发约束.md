## 4. 纳入 0.2.0 的开发范围

新增 WP-08 公共通知注册与发布约束，复用已提交的正式通知目录 / publisher / 壳层宿主，不另建正式注册机制。0.2.0 必交付是公共底座防绕行、当前已交付入口的映射核对、模型 / 同步本版入口接入和对应检查；既有 0.1.10 行为迁移只收口接入，不回写为 0.2.0 新业务。

| 工作责任 | 产出 |
|---|---|
| WP-08 公共 owner | 事件目录与业务适配清单、统一发布入口、任务 / 通知分离、共享宿主 / 多任务队列、投递跟踪、未知 / planned 拒绝、旧入口收口和防绕行检查 |
| WP-01 / WP-02 | 模型对象身份、planId / operationId、冻结目标与证据，保存 / 核对 / 待重启 / 补偿 / 外部漂移事件；不能由前端猜真实终态 |
| WP-03 | 模型页面和已确认公共组件只提交业务事件；节点与发现局部状态继续从业务事实投影 |
| WP-04 | 文件导出、导入、WebDAV 测试 / 应用 / 冲突 / 凭据迁移流程的事件与处理入口 |

## 5. 后续原型制作的强制规则

唯一权威规则回写[UI 规范](../../../../../../02-项目核心/UI规范.md#32-统一通知注册与原型制作约束2026-10-14确认020)。开始绘制一个有操作反馈 / 异步流程的页面前先查注册表和调用点；缺少事件则登记候选与消费者，再接公共发布入口。新原型不得直接创建 Toast / 任务通知卡、写 notifications 数组、发自定义通知或新增业务专用通知宿主。

注册表必须能展示事件 ID、所属业务 / owner、触发源、对象 / 操作范围、性质、渠道、去重 / 冷却、真实解决条件、处理动作、保留与脱敏、所属版本、调用点、登记 / mock接入 / 生产接入 / 验证状态。只登记和只接 UI 的状态不互相替代。

合法的确认、字段错误、局部连接状态、进度详情、日志、空态、模型选择器和助手聊天正文仍属于业务流程；它们不在页面自建第二份通知结果。调试工具的场景切换提示只留原型工具域，不成为用户未读通知。
