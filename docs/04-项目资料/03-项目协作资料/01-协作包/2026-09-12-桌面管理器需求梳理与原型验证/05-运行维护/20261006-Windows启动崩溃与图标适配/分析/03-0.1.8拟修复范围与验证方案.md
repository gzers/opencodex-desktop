# 03-0.1.8 拟修复范围与验证方案

## 版本与授权状态

本节保留登记阶段的拟修复范围。用户随后授权开发、测试与提交，已完成的实施及仍未覆盖的门禁见 [04-0.1.8开发测试与交接](04-0.1.8开发测试与交接.md)；以下“尚未”描述原始计划时点，不覆盖后续实际结果。

受影响版本为 **0.1.7 / Windows x64**。用户提出**暂定 0.1.8 发版**，据此登记拟修复版本与交付意向。以下为建议范围和验收方案，**尚未冻结、尚未实施、尚未验收、尚未发布**。

本轮维护登记不改软件版本号、不创建发布标签或 REL 完成记录。后续在实现分支形成具体修复与候选制品，记录实际检查结果；公开发布仍需按项目约定单独确认。

## 建议实施顺序

| 顺序 | 对应问题 | 建议范围 | 完成依据 |
|---|---|---|---|
| 1 | WIN-01 | 统一跨平台家目录解析；移除 Windows 启动对 HOME 单变量的依赖，补明确启动错误 | 无 HOME 的 Windows 环境正常初始化；目录缺失或非法时错误可定位 |
| 2 | WIN-02 | 从统一品牌应用图标源生成多尺寸 ICO，检查最终 EXE 嵌入资源 | 有效图形占比与 PNG 基准一致；快捷方式、任务栏、开始菜单在不同 DPI 下可辨识 |
| 3 | WIN-03 | Windows 最终 EXE 启动冒烟、必要后端回归和图标资源检查 | CI 实际执行 setup，失败可保留日志，进程与测试数据可收口 |
| 4 | WIN-04 | 平台化 Node/npm/ocx 受控发现，兼容本机工具布局与入口后缀 | 发现与明确未发现状态均正确；显式/托管/发现来源优先级不回退 |
| 5 | WIN-05 | Windows 托管入口、受控 PATH、npm 调用及参数转发 | 新装及托管更新、启停、失败回滚在隔离环境实际通过 |
| 待决定 | WIN-06 | Windows IPC 原生实现，或明确不支持并延后 | 记录范围决定；若延后，不显示已启用或已注册成功 |

建议至少先验证 WIN-01～05，再确定 Windows 0.1.8 的支持与发布范围。如果只修启动和图标，需要清楚声明其余运行流程仍未验收，不能沿用“跨平台改造已完成”的笼统结论。

## 验收矩阵

以下均为后续应执行的检查，**不是本轮通过回执**。

| 场景 | 条件与操作 | 预期与需保留证据 |
|---|---|---|
| 默认 Windows 启动 | 子进程移除 HOME，USERPROFILE 有效；使用独立测试数据根启动最终 release EXE | 建议观察至少 30 秒，进程未异常退出、主窗口建立、初始化完成，首屏有实际渲染；保留退出码、日志、窗口与版本身份 |
| 家目录边界 | HOME 为空、与 Windows 用户目录不同；家目录缺失、非法或相对路径 | 按明确平台策略取值；无有效目录时返回可定位错误，不回退工作目录、不覆盖其他用户数据 |
| 应用尚未配置 | 无官方 OpenCodex、无托管运行时 | 管理器主界面正常打开并展示引导；运行时未配置不变成桌面壳启动失败 |
| 用户路径 | 含空格、中文及不同盘符的安装与测试路径 | 发现、调用与日志均能处理；参数传递正确，无隐式 shell 拼接 |
| 图标资源 | 解码 ICO 全部尺寸，并从最终 EXE 重新提取 | 记录画布、有效图形与像素来源；不只检查素材路径存在 |
| 图标外观 | 全新安装和旧版本升级；100%、150%、200% DPI | 桌面快捷方式、开始菜单、任务栏及安装器显示正常；测试前后图标缓存条件明确 |
| 工具发现 | Windows 受控路径、npm 前缀、本机 NVM Desktop 布局；缺 Node/npm/ocx | 找到正确入口或准确提示缺失；不误报缺 Homebrew，不改变既定来源优先级 |
| 托管运行 | 隔离根完成离线/联网安装、版本读取与代理启停 | Windows 启动器和受控环境实际可用；失败保留既有来源，明确是否启用了脚本 |
| 窗口与托盘 | 关闭保持运行、从托盘重开、明确退出 | 主窗口和托管代理行为符合偏好；不把创建句柄等同于托盘交互通过 |
| 更新兼容 | 隔离候选测试升级 0.1.7 → 0.1.8，以及安装失败和重试 | 保留偏好、数据和代理连续性观察；不以更新包生成成功代替实际升级 |
| macOS 回归 | 同一修复提交执行现有必要检查与主流程 | 平台分支不破坏 macOS 家目录、默认发现、托管入口、托盘和更新 |

Windows 启动冒烟应使用现有 `OPENCODEX_SANDBOX` / `OPENCODEX_SANDBOX_ROOT` 机制，将数据根指向验证过的绝对临时路径；本次诊断使用日常根的做法不应成为 CI 模板。CI 与本机执行需只清理自己创建且路径已核对的进程和数据。

## 实施与发布回写

- 按用户确认，从 `main` 新建 `feature/0.1.8-windows-fixes` 开发修复，完成后合入 `main`；文档与证据继续在 `docs/governance-main` 登记，保持仓库分支归属。
- 必要技术选择形成 IMP；检查结果与实际制品身份回写 `.adg` 回执，再更新本专题与 RUN。
- 版本一旦确定，才在实现分支同步清单版本号及 CHANGELOG，并准备可审查的候选制品。
- 双平台构建、Windows 实际运行、图标核对、必要升级回归各自记录结果与未覆盖项；不得把 macOS 通过结果投射为 Windows 通过。
- 正式发布确认后才执行打标签、上传、公开与通道晋升，并在 REL 中记录事实。维护登记、发布意向和真正发布是不同阶段。

当前本机补 HOME 的诊断启动仅证明 WIN-01 的故障定位，没有修复原快捷方式，也没有形成 0.1.8 候选制品。
