# 0.2.24 版本化安装消费者

revision: 1；2026-11-11，代码 main b617717c365ce847a66dea9ee979d3939436e5fb。承接 program-consumers-r2、program-activation-r1 和 native-config-protection-r1；阶段进度归 IMP-34。

## 当前接线

install_runtime 与 install_official_update 遇到 versioned RuntimeHandle 时，共用 RuntimeInstaller::install_versioned。请求中的路径只允许当前经过核验版本的 package_root，Node/npm 必须匹配该 SelectedProgram；候选最终位置由实际官方三段版本号派生为 I/runtime/versions/<version>，不再写 flat runtime/opencodex。真实新装无可用当前镜像时仍先走固定内置供应；此接口不会从 PATH 或旧目录寻找依赖。

独立 .runtime-install-stage-* 内准备官方源及 npm 输出。源归档先有界复制、摘要和版本复核，再以 file:sources/opencodex-<version>.tgz 规范交 npm；保留相对来源，临时下载目录不进入版本镜像。离线模式严格传 --offline，只使用本次显式缓存，缓存不足明确报错。依赖脚本继续默认禁用，原有显式脚本许可仍受现有入口约束；原包文件变化会被拒绝，不能借脚本许可修改官方 OpenCodex。

Node/npm 从当前已核验镜像复制到候选的独立 dependencies；npm文件链接仅允许源树内的相对普通文件，复制为独立文件，路径/数量/深度/总量受界限约束。Bun wrapper 与平台包的名称/版本必须一致，native binary 放入该版本的 dependencies/bun，并与 node_modules/bun/bin/bun.exe 一致。Bun 1.4.4 的450字节正常错误占位文件摘要已用锁定npm归档验证，只替换该已知占位或接受已相同的native内容；未知占位版本不假定兼容。

## 关键准入及失败

1. 应用存储/安装预约与 I 的OS程序锁保持，当前镜像与请求一致才准备候选；真实服务停止事实必须明确，不使用collector旧状态代替它。
2. npm输出的官方包内容与原始tgz展开树比较，入口实际版本必须与包版本一致。复制后再次检查Node/npm摘要及实际入口。
3. 配置完整保护在发布前完成，候选发布后核对完整文件树；配置变化、取消、服务再次出现均拒绝继续。原版本目录、配置与失败证据保留。
4. current、稳定入口、本机来源和成功安装history共用可恢复激活事务。中断保留pending，普通读取继续报未知，不虚报新版本或停止成功。
5. 已存在同版本目录不覆盖。仅在重新构建候选与该目录整树相同的情况下复用，用于原操作在激活前失败后的明确重试；外部文件/目录冲突拒绝。与当前核心程序身份相同的候选为无切换核验，不改配置、不制造备份。

产品当前采用“先停止并核验退出，再切换版本”，防止版本切换后失去旧实例归属。服务查询/停止本身仍有版本化归属改造待完成，因此本批不宣布正常启停整链通过。需要恢复pending、修复被改动的同版本镜像时，后继产品恢复命令/UI必须使用既有Rust恢复合同；本批没有提供静默覆盖或自动回退扫描。
