# Mac 官方配置锁的写入边界

本轮为隔离组件诊断，整版 `accepted:false`。使用候选 `b33369498525854f0c9f7e335f11b3261cc6af41` 的 Desktop 配置守卫和原样官方 2.99.0。输入摘要及进程回执见 [result.json](result.json)，测试条件见 [hypothesis.md](hypothesis.md)。

| 对象 | 按锁协议的竞争者 | 独立同用户写入 | 持锁者与清理 |
| --- | --- | --- | --- |
| Codex | 获取锁失败，退出 1 | 原子替换成功，字节摘要一致、inode 改变、合成扩展属性丢失 | 替换前后锁文件一致。持锁者正常释放，退出 0，探针锁文件消失 |
| Grok | 获取锁失败，退出 1 | 原子替换成功，字节摘要一致、inode 改变、合成扩展属性丢失 | 替换前后锁文件一致。持锁者正常释放，退出 0，探针锁文件消失 |

两个夹具均已清理。首次探针在加锁前因本机 Python 缺少 `os.setxattr` 失败，失败回执单独保留。后继探针调用 macOS 的 `/usr/bin/xattr`，完成两种夹具。[首次脚本](probe-first.py) · [首次结果](result-first.json) · [后继脚本](probe.py)

官方 advisory lock 能协调遵守协议的写入。相同的锁文件和内容摘要无法证明共享配置原件的身份，也无法为覆盖提供排他性。IMP231 历史现场的写入者、完整产品在竞态下的行为和实际稳定锁的释放仍需各自举证。TEAM79 Windows 待命继续有效。
