# 能力地图

> 字段级配套：能力项涉及的状态取值见 `数据与状态.md`，实体字段见 `领域模型.md`，写入边界见 `集成与安全边界.md`。

## 1. 范围原则

- **原型中出现的全部功能都在实现范围内**，不做功能取舍。
- `P0` / `P1` / `P2` 与「可选」只表示**实现与交付顺序及前置依赖**，不表示"可以不做"。
- 顺序依据：**P0** 运行管理主线 → **P1** 需要安全评审的能力（配置迁移、扩展管理、CLI 控制面）→ **P2** WebDAV 同步。安全评审未完成不阻塞立项，但阻塞对应能力的实现。

## 2. 编号方案

| 对象 | 编号 | 说明 |
|---|---|---|
| 能力域 | `DOM-01` ~ `DOM-13` | 十三个能力域，编号稳定，不随排序变化 |
| 能力项 | `CAP-<域号>.<序号>` | 例：`CAP-1.2` 属 `DOM-01`；能力项是能力的可验收最小单位 |
| 实现模块 | `MOD-01` ~ `MOD-13` | 与能力域一一对应，定义见 `系统架构.md` |
| 需求 / 验收 | `REQ-*` / `AC-*` | 权威在 `01-需求管理`，本目录只引用 |

## 4. 能力项明细

每条能力项给出：输入、可观察输出、涉及状态、边界（禁止或例外）。表格里的字段名指向 `领域模型.md` 的实体。

### `DOM-01` 安装发现 · `MOD-01`

| 能力项 | 名称 | 输入 | 可观察输出 | 状态 | 冻结 |
|---|---|---|---|---|---|
| `CAP-1.1` | 环境前置门禁 | 本机 `node` / `npm` / `ocx` 存在性 | 当前缺失项、当前状态、最短可复制命令 | `checking` `missing_node` `missing_npm` `missing_ocx` | ✅ |
| `CAP-1.2` | 安装发现与校验 | 已通过前置门禁 | 安装路径、版本、可执行校验结果 | `not_found` `stopped` | ✅ |
| `CAP-1.3` | 重新检查 | 用户手动触发 | 重新执行门禁与发现 | 同 `CAP-1.1` / `CAP-1.2` | ✅ |

- 检查顺序**固定短路**：`node` → `npm` → `ocx`，前一项未通过即停止后续检查。
- **禁止**：执行 npm 安装、卸载、依赖解析或全局前缀管理；代装 `brew` / `node` / `ocx`；自动监听系统变化。应用只做检测与引导，用户安装后由本人手动触发重新检查。
- 缺 Node.js 时按是否检测到 Homebrew 分支提示：有 Homebrew 展示 `brew install node`，无则展示 Node.js LTS 官方安装渠道。

### `DOM-02` 数据目录 · `MOD-06`

| 能力项 | 名称 | 输入 | 可观察输出 | 状态 | 冻结 |
|---|---|---|---|---|---|
| `CAP-2.1` | 数据根选择与切换 | 用户选定的目录路径 | 数据根就位、分区按结构划分 | `validating` `succeeded` `failed` | ✅ |
| `CAP-2.2` | `OPENCODEX_HOME` 指定 | 目录在数据根内，或独立路径 | 生效的 `OPENCODEX_HOME` 与来源 | `validating` `succeeded` | ✅ |
| `CAP-2.3` | 引用 / 迁移 | 检查结果 + 用户显式选择 | 引用不搬动；迁移后校验通过 | `backing_up` `applying` `rolling_back` | ✅ |

- 采用**引用优先、迁移可选**：默认引用已有位置、不搬动数据；仅在显式选择「迁移」时执行移动。
- 检查阶段即阻断：目标不可写、空间不足、已有数据结构异常。
- 迁移前强制备份；迁移中断或校验失败**自动回滚并保留原数据目录**。
- 分区字段与检查项字段见 `数据与状态.md`。

### `DOM-07` WebDAV 同步 · `MOD-08`

| 能力项 | 名称 | 输入 | 可观察输出 | 状态 | 冻结 |
|---|---|---|---|---|---|
| `CAP-7.1` | 加密同步 | 用户指定的端点与凭据 | 加密上传、同步结果、索引摘要 | `connecting` `syncing` `synced` `failed` | ✅ |
| `CAP-7.2` | 冲突处理 | 本地与远端差异 | 冲突列表、用户选择、被覆盖侧备份 | `conflict` | ✅ |
| `CAP-7.3` | 覆盖前备份 | 即将被覆盖的一侧 | 可恢复备份 | `backing_up` | ✅ |

- 同步**全量内容**，上传前**客户端加密**。
- 采用**冷同步**：运行中不直接写关键文件，需用户确认后才执行覆盖。
- 冲突先入 `conflict`，**不静默覆盖**；远端一律视为**不可信**。
- TLS 证书校验失败**默认拒绝**，且**不提供**"忽略证书"选项。
- 与官方 `ocx connect` remote hub 是**并列能力**：不自建 hub、不替代官方 hub，只同步用户指定的端点。

### `DOM-09` 应用自更新 · `MOD-10`

| 能力项 | 名称 | 输入 | 可观察输出 | 状态 | 冻结 |
|---|---|---|---|---|---|
| `CAP-9.1` | 自身版本检查与更新 | 更新通道（`stable` / `beta`） | 可用更新、下载与签名校验结果 | 状态链见 `数据与状态.md` | ✅ |

### `DOM-10` CLI 控制面 · `MOD-12`

| 能力项 | 名称 | 输入 | 可观察输出 | 状态 | 冻结 |
|---|---|---|---|---|---|
| `CAP-10.1` | 本机 IPC 委托 | `ocxd` 命令 | 命令输出或 `--json` 机读结果 | 见 `契约字段.md` | ✅ `FZ-34` ~ `FZ-36` |
| `CAP-10.2` | 端点访问控制 | 启用 / 关闭开关 | 端点存在或不存在；调用方校验结果 | — | ✅ `FZ-37` ~ `FZ-40` |

- **默认关闭**；启用后注册 `ocxd` 入口，并明确提示开放的能力范围。
- 是**运行中实例的客户端**，经本机 IPC 委托执行，**不产生第二写入者**；实例未运行时只读命令降级说明、变更类命令报错。
- 能力限定在**管理器自有域**：发现与只读状态、启停、数据根、备份、加密导出/导入、WebDAV 同步、自更新检查。
- **不提供**任何直接改写 OpenCodex 自身配置（provider、路由、模型映射）的通道。
- 变更层命令需实例在线与显式确认；破坏性操作需确认标志；提供 `--json` 机读输出。
- 关闭时**不得留下可被调用的监听端点**。

|---|---|---|---|---|---|

| `CAP-11.2` | MCP 管理 | 服务器定义（命令、参数、环境变量、请求头） | 导入、新增、编辑、删除结果 | 同上 | ✅ `FZ-25` ~ `FZ-29` / `FZ-46` |
| `CAP-11.3` | 多客户端分发 | 统一扩展配置 + 启用矩阵 | 逐客户端投影结果 | 同上 | ✅ `FZ-22` / `FZ-25` / `FZ-27` |
| `CAP-11.4` | 冲突检测 | 目标文件当前内容 | 冲突标记与提示，交由用户决定 | `conflict` | ✅ |

- **允许写入**：Skills 目录同步与各客户端的 MCP 服务器节点。
- **禁止写入**：provider、路由、模型映射与 OpenCodex 核心运行配置。
- 写入前**强制备份**，临时区 + **原子替换**，失败回滚；删除类操作**必须可恢复**。
- `env`、`args`、`headers` 一律按**潜在敏感值**处理，默认掩码。
- MCP 的 `command` / `args` / `env` 具备执行本地程序的能力：必须**展示执行边界并经用户显式确认**，不得静默执行任意本地程序。
- 多客户端不一致或外部应用改写后**检测冲突并提示**，不得静默覆盖。
- 实施前**必须完成安全评审**。
