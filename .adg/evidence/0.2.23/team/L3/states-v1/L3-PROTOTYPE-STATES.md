## 1. 本轮已经固定的交互约束

- 预览与 prepare 全只读。打开页面、切来源、重算变化、测试连接不能创建代次 G、上传载荷或修改正式配置。是否需要持久化本地预览材料由总控合同另明；本稿不以 prepare 授予落盘。
- 首次确认上传明确包含初始化；执行阶段才创建 G。确认文案为“初始化并上传”，预览同时说明将初始化当前已核实空目录。
- 多个初始化 G 一律停写。原目录保留，仅提供只读查看和专用恢复内容/导出计划；选择另一个已核实为空的目录重新开始。没有自动清空、自动搬移或初始化决议图。
- 协议按低到高解析：实际导入的逐模型事实 → 已保存模版通用值 → 命中条件覆盖 → 单模型人工值。继承跳过当前层；没有渠道默认、没有隐式 Responses。UI 不从名称、临时清单方式或旧 provider.adapter 猜逐模型协议。导入事实由后端明确标记来源及可用性。
- 临时清单方式默认未选，只服务当前清单读取；认证方式独立。读取现有渠道成功，按保存模版自动更新草稿，不增加采用弹窗；正式保存才生效。
- Windows 程序默认用户 LocalAppData/Programs/OpenCodeX Desktop，runtime 与 exe 同安装根；macOS 拟定用户 ~/Applications/OpenCodeX Desktop/，.app 与 runtime 并列。macOS 物理映射仍待总控最终冻结，不能画为已验证安装。配置根仍为当前用户 ~/.codex-desktop，分类 desktop 与 opencodex/home。
- 产品只展示 API 返回的实际绝对路径、权限和有效性，不硬编码用户名、系统盘或 Mac 用户目录；程序根与配置根分栏呈现。

## 2. 共用页面与退出规则

沿现有页面导航、13px 标准字号、公共 UiDialog/Select/字段和令牌；本轮不改公共组件或全局样式。表单先复用现有宽度/布局能力，长路径、ID、条件和变化清单在内容区滚动；标题/X 与底部动作始终可达。900×650 窄窗按字段逐行排布，不横向截断主要操作。

状态文案写事实与可执行动作，原操作 ID、提交摘要等技术详情默认放在可展开明细，不占主流程。业务保存时间未知显示“未知”；观察时刻单列“本次核对时间”，不能冒作版本时间。凭据仅展示状态，不在截图、来源链和错误详情中输出真实值。

关闭、取消、返回都使当前读取会话失效，晚到结果不能更新已关闭页面或另一草稿。无写入前取消不产生初始化、正式配置、备份或远端文件。已可能写入时按 SYNC-11 保留待核对事实；关闭结果窗口不取消后台事实。未保存的模版/渠道退出沿现有“继续编辑 / 放弃草稿”保护，不把返回上一步当作丢弃。

以下表的主操作仅在对应前提满足时可用；没有可执行权限/能力时保留说明并禁用，不显示一个点击后必败的确认按钮。操作名称是页面设计文案，生产字段/命令名由最终 DTO 定义。

## 3. 模版条件覆盖与命中预览

入口：模型配置 → 模版详情 → 原“版本或后缀”区改为“条件覆盖”。保留通用规则、来源和不可变版本管理。编辑基于明确保存 revision；新保存产生新 revision，不改原历史。

编辑器从上到下为：覆盖项名称；名称结构/版本识别位置；条件列表；规格/剩余文本限制；覆盖字段及锁定；预览。每个覆盖项显示“以下条件全部满足”，默认新增一条空条件，填完前不允许保存。条件类型为“数字版本 / 名称片段 / 字面前缀 / 字面后缀 / 完整模型 ID”；不暗增 OR 或自动把旧字面规则转换成数字规则。名称结构是后端支持的声明布局，可选择/编辑后端允许的前缀、完整数字槽位及剩余文本规则，不提供自由执行表达式。

数字版本以文本输入完整段序列，显示“仅声明版本位置内，点与连字符等价”。前导零、段数、日期/构建和尾部规格按声明语义保留，不解析成浮点数。名称片段位置默认“不限”，可选“版本前 / 版本后”；完整片段边界由合同控制，sol 不命中 solar。选择版本前/后而没有可识别版本结构时，显示字段错误并阻止保存；不猜一个数字位置。旧字面后缀行显示“字面后缀”，保持旧语义。

“剩余文本/规格”明确显示本条覆盖范围：精确剩余文本，或后端声明允许的范围。不默认把 mini/pro/日期构建视为相同身份。参数字段沿已有 ModelRuleFields，默认继承，只有显式自定义字段覆盖下层；当前锁定值、字段来源和来源说明同屏可查。

预览输入为本次选择的渠道及原始模型 ID；不读取真实客户端。上下双栏在窄窗改成上下分区：左侧条件，右侧结果。结果显示原始 ID、仅用于匹配的视图、已识别版本/片段/剩余文本、每条件命中与原因、选中模版/revision/覆盖项、字段级最终值和来源链。算法全部来自同一后端预览或合成固定场景，不写 TS 匹配器。

## 4. 渠道与读取自动匹配的相邻状态

## 5. 目录与程序位置

入口：设置 → 安装与数据。以两块信息展示“用户数据与配置”和“程序安装”，不把 HOME 画进 runtime。

用户区字段：当前用户数据根、Desktop 数据目录、OpenCodex HOME、渠道配置文件；程序区字段：Desktop 安装根、OpenCodex 程序入口、运行包版本、安装记录一致性。每个实际路径提供完整查看与复制；打开目录只对后端返回可访问目标开放。原始完整路径可选中复制，界面截断时仍可展开，不以提示气泡作为唯一完整查看方式。复制失败显示行内原因，实际路径不变。

有效性与运行状态分别显示：路径有效不等于代理已运行；代理停止不等于未安装。缺失/未初始化/损坏/无权限/未来格式各自反馈。接口只给错误而无有效路径时不填示例当真实值。“选择新版目录”只面向新合同允许的显式位置，先只读校验及变化预览；不提供旧目录扫描/自动迁移选项。

## 6. 安装身份失配与恢复

入口：设置 → 程序安装 → 诊断提示“安装内容与记录不一致” → “查看并恢复”。不复用“恢复管理器偏好”或 JSON 读取的成功文案。

对话框上半区是实际安装目标、包版本、程序入口、受管清单/来源记录逐项诊断；下半区选择本次明确安装源：受支持的指定注册源版本或离线包。可用方式和默认选择由后端返回，未验证来源时不默认任意最新版或旧程序。离线包显示文件名、版本、摘要及校验结果，不显示伪造“可信”。

下一步同一框切到确认页：将恢复的目标、明确版本/摘要、受影响服务及停止动作、保护备份结果、保留用户配置的范围。保护备份是执行前置；预览不能提前创建备份。用户确认授予该次恢复执行，执行先保护成功，再停止后端确认归属的服务，再替换/核验；实际顺序和取消安全点最终沿 L0 恢复事务 DTO，UI 不自行编排 shell/进程。

| --- | --- | --- | --- | --- |
| INSTALL-01 | 诊断读取中/失败；不存在可用诊断时无恢复确认 | “重新诊断”只读 | 关闭 | 不删除清单后让错误消失 |
| INSTALL-02 | 包/入口/清单/来源逐项一致或失配；实际目标完整可查 | 失配且可恢复时“选择恢复来源” | 查看详情、返回 | 一致时不宣称需要修复；缺包可走正常安装 |
| INSTALL-03 | 选择受支持注册源版本或离线包，未核验态 | “核对来源”只读，须满足选择条件 | 返回诊断、取消 | 不扫描/绑定旧 runtime，不自动联网安装 |

## 7. 同步：预览、首次上传与原操作

入口沿同步页与既有概览入口的同一消费者，不改概览布局。预览框保留标题/X、内容滚动与固定底栏；“本次来源”在原来源行使用两项下拉：“本机配置 → 云端（上传） / 云端配置 → 本机（下载）”。切换仅发只读比较；旧方向结果立即过期，确认禁用直到新结果可用。

可靠业务保存时间能判新时按较新一方预选；不能判新且有有效可读取云端配置时默认下载；已核实空目录/无云端配置且本机有所选内容时默认上传。读取失败/损坏/列举不完整/多个 G 不是空目录。双方所选都空或强制方向不存在来源时禁用确认。内容一致显示“所选内容一致，无需更新”，不生成写入。

下载默认勾选“更新前备份”；上传不显示无意义的下载备份。首次空目录预览新增说明“此目录尚未初始化。确认后将初始化并上传所选配置。”主按钮“初始化并上传”。已存在唯一有效 G 但暂无提交时不新建 G，主按钮“确认上传”。普通上传主按钮“确认上传”，下载为“确认下载”；确认只作用已展示范围，范围外保持。

## 8. 多代次歧义与提交分叉

两类问题单独呈现。多 G 是目录初始化歧义，普通写入停用，不显示“选择一个作为活动代次”；同 G 多有效头是配置提交分叉，需要显式选择/解决冲突，不能用两项上传/下载下拉掩盖多个云端版本。

### 8.1 多个初始化代次

标题“此目录存在多个初始化记录”。说明“此目录已暂停写入。现有内容保留，可先查看并导出可恢复内容，再选择另一个空目录重新开始。”列表显示每个代次的可核验提交/内容状态、可读范围、业务保存时间或未知；时间和名称不作为默认赢家，无预选“最新代次”。技术 ID 在详情中可复制。

只读恢复内容流程：选择可读内容 → “查看恢复内容” → 后端专用只读计划给出对象范围/依赖、损坏或缺失项、可恢复动作 → “导出恢复文件”。导出目标必须明确，文件写入只发生在用户确认导出后，由专用恢复导出服务执行；不复用普通 apply_download 绕过歧义门禁。导出文件不自动覆盖本机正式配置，也不自动上传。若后续允许将恢复内容下载到本机暂存，需 DTO 显式能力与独立确认；当前不添加普通“应用到本机”动作。

“选择新的同步目录”沿现有连接编辑，只接受另一个明确目录；先核实可访问/列表完整/确实为空，再展示新目录初始化预览。仅修改连接或核实空目录不写远端；在新目录确认“初始化并上传”才开始。待恢复内容被核对并通过受控本机流程形成明确已保存来源后，才能以它构造上传；默认不沿用原本机内容冒充用户选中的恢复材料。目录切换后旧预览全过期，旧操作仍保留原目录绑定。

| 状态 ID | 可见内容/控件 | 主操作与前提 | 次操作/退出 | 结果与重开规则 |
| --- | --- | --- | --- | --- |
| AMBIG-01 | 多 G，普通上传/下载应用停用；每分支可读性列表 | 可读分支“查看恢复内容”，不默认选赢家 | 选择新目录、关闭 | 原目录只读保留，无 DELETE/MKCOL/决议图动作 |
| AMBIG-02 | 专用恢复内容计划只读加载/成功；对象/依赖/缺项明确 | 可完整恢复的选定范围“导出恢复文件” | 返回分支、关闭 | 不把坏分支或缺依赖包装为完整可恢复 |
| AMBIG-03 | 导出确认、目标文件与具体范围；导出失败原因 | 明确目标后“确认导出”；失败按原计划重新核对 | 取消、重新选目标 | 取消零文件写；成功只表示恢复文件已导出 |

### 8.2 同代次多提交头

标题“云端存在并发配置”。列表展示后端给出的所有已观察头、各内容范围/差异与可核验来源；业务保存时间可为未知，不按时间自动选一个。用户选择某个头完整快照或后端明确支持的对象合并方案；合并能力未就绪时只提供合法完整来源选择，不自行拼接字段。

选择后只读预览显示所选内容、每分支将被保留/替换的范围、范围外影响和依赖；主按钮“确认解决并发布”明确产生新操作。原头与载荷保持不删除；父集合包含本次已确认所有头。提交前头集合变动则要求重新比较，提交后观察到迟到分支或并发决议仍显示冲突。

## 9. 代表流程与设计核对点

1. 条件：COND-01 → 02 → 04 → 保存新版本；以 COND-06/08 校验规格外溢与重叠错误，并与旧字面 COND-03 并列。固定合成样例可用 gpt-6.1-sol / gpt-6-1-sol / gpt-6.1-sol-mini / gpt-6.10-sol 与 claude-opus-5.5 / claude-5-5-opus；每个样例按明确结构及精确尾部限制解释，不能仅凭这个列表推断供应商参数。
2. 渠道：READ-01 → 02（未选清单、手动 ID）→ 05 → 正常保存；对 READ-04/07 核对晚回和空结果保护；协议明细确实显示四层来源。
3. 目录：DIR-UI-01 → 02 → 05 → 06，分别展示当前/待生效；损坏/权限/未来格式走 04，不回旧根；JSON 说明走 07 → READ。
4. 安装：INSTALL-02 → 03 → 04 → 05 → 06 → 08 → 09；备份失败、被占用、结果未知分别走 06/07/10，重开走 11，不能只演示成功。
5. 首次上传：SYNC-01 → 04 → 明确确认 → 10 → 11 → 12；关闭预览/测试连接不写，发送后停止不是撤回；目录非空或代次变动走 08 或 AMBIG。
6. 原操作：SYNC-11 → 本机后改动/MCP选择改变 → 只读核对原 O → 13；原上传存储事实与新变化并存；本地结果读取与远端核对调用不同。
7. 初始化歧义：AMBIG-01 → 02 → 03 → 04 → 05 → 明确本机来源 → 新目录 SYNC-04；原目录始终保留，恢复导出不等于已同步。
8. 同代并发：FORK-01 → 02 → 确认新操作 → 12；注入迟到分支走 03，多头不被上传/下载下拉省略。
