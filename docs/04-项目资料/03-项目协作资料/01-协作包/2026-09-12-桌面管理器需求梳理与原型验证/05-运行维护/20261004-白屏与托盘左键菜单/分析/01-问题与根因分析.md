## 1. 结论与证据等级

左键不弹托盘菜单另有明确配置依据，右键可用，和白屏分开处理。完整重启恢复解释了旧进程状态被清除，但不能重建首次触发链。这里“分析完成”指已知相关路径均有证据、判断和验证去向；事故定位、代码修复和运行验收尚未完成。

### F-01：左键菜单配置

依据：apps/desktop/tauri/tauri.conf.json:34 明确 showMenuOnLeftClick=false；未找到 on_tray_icon_event / TrayIconEvent 自定义左键处理。用户右键能弹菜单，符合这个配置行为。若预期顶部图标左键展开菜单，现行为存在交互差异；应显式确认并实现左键语义，不能用“托盘进程卡死”解释全部点击。

### F-02：隐藏后重开与渲染恢复

依据：apps/desktop/tauri/src/lib.rs:463–467 在保留代理的关闭策略下 prevent_close、hide，转 Accessory；:478–488 的 macOS Reopen 和 :373–377 的原生打开入口均 show → set_focus → 恢复 Regular，没有主动 reload 或重建主 WebView。

这是一条正常的保留后台行为，但异常窗口被复用时不会自然得到完整进程重启的重置效果。本次页面脚本能响应，仍看不到内容，符合这类恢复不足。没有采集到最初隐藏动作与第一次图层错误的连续证据；不得把“隐藏复用”直接写成白屏根因，也不建议每次 show 无条件 reload，避免打断正在操作的页面。

**框架恢复能力纠正**：本地 tauri-runtime-wry-2.12.1/src/lib.rs:5048–5074 在未指定自定义 WebContent 终止处理时注册默认回调并尝试 reload。该框架路径有可能因查找/借用失败而不完成重载，且只覆盖终止回调；本次存活且响应的页面未必触发它。不能写“框架完全没有崩溃自动恢复”，也不能把当前依赖检查当安装包版本证明。

### F-03：窗口调用结果与激活顺序

依据：lib.rs:373–377、:463–467、:478–488 中 show、set_focus、hide 结果以 let _ = 忽略；:517–522 对 set_activation_policy 同样忽略。打开时先 show/focus 再设置 Regular，是否在当前 macOS 的 Accessory → Regular 过渡中造成可见/焦点状态不一致需实测。

候选动作：统一各入口的窗口生命周期处理，记录入口、前后可见性、激活策略和错误；对先激活策略后 show/focus 的序列做对照。本次未证明任何调用实际返回错误，也没有证据足够要求直接交换顺序作为最终修复。

### F-04：Mesh 运行中上下文恢复

依据：ui/src/features/runtime/motion/meshGlow.ts:91 创建上下文，:191–195 的 rAF 循环持续绘制，:219–234 管理启停与销毁；未找到 webglcontextlost / webglcontextrestored 监听。ui/src/app/appearance/glowRender.ts:74–78 主要在启动安装时检测能力。

**已有保护须保留**：RuntimeMotionMark.vue:36–49 在 Mesh 创建失败时 setWebglSupported(false) 回退 CSS；appearance/effects.ts:125–134 已监听 visibilitychange，组件 animating 监听控制动画。因此缺口限于“创建成功后运行中丢失/恢复上下文”，不能写成没有任何回退或隐藏暂停。

本次偏好为 high + mesh，故值得做 CSS/低特效对照。尚未取得 contextlost 事件；单个 canvas 不绘制不自动证明整个主窗白屏。处理建议是丢失时停止渲染、显式回退，恢复时重建 GPU 资源并清理监听，不只再次启动旧 rAF。

### F-05：启动异常空档

依据：ui/src/main.ts:21–26 中 store、installEffectsRuntime、installGlowRenderRuntime 在启动 try 之前；try 只包偏好/快照/路由；:40 起到启动末尾才安装全局处理。app/errors.ts:68–81 覆盖 Vue errorHandler 与 unhandledrejection，未覆盖所有 window.error 或模块导入失败。

冷启动发生早期异常有可能无可视恢复提示；但本次设置/概览 DOM 已完整、路由可切换、脚本成功，故不能把启动失败判为主因。后续可尽早安装异常记录、覆盖 bootstrap Promise 与 window.error，另为资源/模块失败设计不依赖完整 Vue 的最小恢复入口。

### F-06：恢复入口可达性

依据：ui/src/App.vue:23–25 提供 reloadUi，:52–59 的故障弹窗提供“重新加载界面”；当前没有独立原生菜单的“重载主界面”入口。既有 DOM 恢复能力不能解决用户看不到 DOM 的情况。

候选动作：提供不依赖 JS 轮询的原生主 WebView 重载入口，明确区别于官方面板刷新和运行时启停；失败时给原生反馈。重载仍可能解决不了 GPU/合成异常，重建主视图应作为有状态保护的后续方案，不能直接当作已验证可行。

### F-07：托盘动作与前端桥接

依据：lib.rs:366 的 Quit 直接 app.exit(0)；其他动作入 SharedTrayRequests；ui/src/composables/useAppController.ts:168–172 每秒 drain 并处理，catch(() => {}) 吞掉失败。原生“菜单能展开”、命令入队、前端处理和最终动作成功是不同观测点。

JS 冻结、轮询停止或 IPC 失败时可能出现菜单项无结果。本次原生打开概览能转换路由，支持至少当时桥接仍工作；故不把它写成右键菜单失灵的根因。后续增加请求编号、处理结果和失败反馈，核心 UI 恢复命令走原生路径。

### F-08：嵌入子 WebView 并发与层级

依据：ui/src/routes/PanelRoute.vue:99–140 用 syncBusy 阻挡非 hide 请求，hide 仍可并发；:188–210 的 loadPanel 经多次 await 后 show，没有 disposed / generation 取消；:250–256 卸载时 fire-and-forget hide，未 await/catch。tauri/src/commands/panel.rs:230 每请求 spawn_blocking，:231–233 hide，:255–295 创建、布局、show，没有统一代次或执行序列。后台 collector 的锁不等同于所有视图操作串行。

离开面板后旧 show 可能晚于 hide 完成，让子视图重新可见；并发 show 创建也需检查去重与错误反馈。若边界/层级异常可覆盖主内容，这是静态竞态候选。本次 page 38 也有图层警告，但没有测其 native visible、bounds 和 route 代次，不能证明覆盖发生，也不能仅凭 DOM 完整排除 native 子视图遮挡。

候选动作：前后端统一路由代次/期望可见状态、丢弃过时请求、串行化原生视图变更、卸载时取消旧任务并记录 hide 失败；回归快速 panel → overview/settings 和同刻布局/隐藏。

### F-09：观测与构建追溯

app.log 主要记录托管运行时启停，本次没有主窗绘制健康、show/hide 结果、主/子 WebView 关联和恢复记录。系统日志能定位 page 8 / 38，但只有时间窗口，没有首次触发的连续链。完整采样临时文件不保证长期保留，只持久保存前 90 行。

候选动作：增加非敏感生命周期事件、原生错误、路由/面板代次、渲染丢失和恢复结果；构建注入源码提交与依赖/制品摘要。DOM/心跳成功不等于画面可见，健康检测必须区别“脚本响应”和“绘制恢复”，不能仅凭心跳通过就关闭事故。

### F-10：更新占位端点

依据：tauri.conf.json:59–60 仍为 updates.example.invalid 的 stable/beta 地址。当前更新错误属于独立配置问题，没有证据表明它导致原生绘制失败；故不与白屏合并归因。是否在 0.1.1 配置真实通道或明确禁用测试版检查，留作范围决策；不因此自行执行签名、发布或自动升级。
