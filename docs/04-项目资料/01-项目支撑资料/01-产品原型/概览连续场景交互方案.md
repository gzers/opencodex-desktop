# 概览连续场景交互方案

2026-11-04，OpenCodex 桌面管理器，桌面端。设计来源为本轮关于“长镜头、一镜到底、同一个场景联动”的讨论；本文件记录设计意图与首轮效果范围。唯一活动入口是[总原型概览](原型/index.html#overview)，当前为探索原型，尚未作为生产交互验收。

## 场景原则

用户沿客户端、Desktop、渠道、模型与请求关系逐层深入，始终保留上一级对象和可识别的路径。转场由明确点击或键盘激活触发，悬停只作快速预览。进入一层只增加这一层需要的信息，返回时按相反方向收拢。

保留现有二维关系图、Logo 反应堆、流光与玻璃材质。用节点位移、连线延伸、背景退让表达深度，主要转场约 300～450ms；读数与按钮在转场结束后保持稳定。低特效或系统减少动态时立即呈现最终布局。

## 首轮体验路径

| 层级 | 明确操作 | 同场景反馈 | 返回 |
| --- | --- | --- | --- |
| 全局 | 点击渠道圆形节点，或从其详情选择展开 | 原渠道节点移到展开位置，Desktop 留在路径起点，其他关系退到背景，模型从渠道旁分支展开 | 概览路径按钮 |
| 渠道 | 选择模型 | 选中模型保留为锚点，其他模型退让，下方展开少量请求记录；用量与速度归该渠道及模型 | 返回渠道 |
| 模型 | 选择单次请求 | 请求保持原身份，呈现首字、输出、完成或失败的阶段，支持一次路径回放 | 返回模型 |
| 请求 | 点击回放或返回 | 回放使用该条样例的阶段时间，播放结束即停；返回沿原路径收回 | 路径导航或 Esc 逐层返回 |

全局统计与顶部时间范围继续保留。场景内明确展示当前渠道 / 模型范围；切换时间窗口后重新获取该范围的样例，单次请求选择复位，避免旧请求混进新窗口。切换页面、环境门禁和关闭场景清理临时状态。

## 数据与动效边界

渠道与模型读取概览同一份内存样例，不另建第二套渠道汇总。请求与阶段为明确的原型样例，归属所选渠道、模型和时间窗口。原型说明通过共享注释展示，产品交互区只保留阅读和操作需要的内容。

模型速度只描述该模型经过该渠道时的输出速度；历史统计和实时状态不能互相代替。请求回放代表单条记录的阶段顺序，缺失阶段显示未知，不根据其他渠道或模型拼造链路。

## 后续方向

同一场景可继续扩展同模型跨渠道比较、异常追踪、模型搜索与更多请求。比较时统一模型与时间范围，并显示样本数；节点过多时按需展开，保持概览一页展示。第一轮先验证完整深入 / 返回路径及视觉连续性，再决定这些分支的交互细节。

## 验证与交付

本轮检查包含渠道进入、模型展开、请求选择、回放、逐级返回、时间切换、窗口适配、键盘、路由清理、低特效与减少动态。实际结果及截图回写[概览专题说明](全景概览第二轮专题说明.md)，生产组件和真实采集仍待后续实施。

## Agent 平台侧连续场景（2026-11-04）

运行后，左侧 Codex App、OpenCode、Codex CLI、Claude Code 分别成为可进入的来源对象。点击平台：保留原平台节点，Desktop 沿路径让位，展开这个平台记录到的模型。模型数量多时每组三项翻组，保留选中与返回位置。

选择模型后，列出属于该平台和模型的请求，行内明确目标渠道与该条请求输出速度。平台与跨渠道模型汇总只显示请求 / Token / 渠道数，不用一个混合 t/s 代表不同渠道。选择请求才在同一场景中显出实际目标渠道，涉及适配时保留中间适配层；光点经过平台 → Desktop → 适配（如有）→ 渠道 → 当前模型 / 请求。

单次请求详情明确标出来源平台 → 目标渠道，并提供“从渠道查看同一请求 / 从平台查看同一请求”双向切入。请求 ID、时间、输出量、速度与阶段共用同一份 canonical 样例生成规则，双向进入只改变场景上下文。原路径和 Esc 逐级返回；时间范围变化保留平台、模型，清空单次请求和目标渠道；未运行继续只展示整体。

平台样例使用显式静态配额独立派生，不从真实日志、常用程度、入口或 Token 规模推断来源。四平台汇总与已知渠道模型样例守恒；未知组合不分配给已知平台，未观测来源仍应保留未区分。当前只是设计演示，生产采集需要可靠的平台标识。项目 / 会话层、实时来源识别与跨渠道比较仍待后续设计。
