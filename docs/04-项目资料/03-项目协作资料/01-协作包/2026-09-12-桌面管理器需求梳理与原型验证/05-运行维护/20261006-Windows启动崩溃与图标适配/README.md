# Windows 启动崩溃与图标适配

- 维护记录：**MNT-OPENCODEX-DESKTOP-20261006-01**。
- 诊断与登记日期：**2026-10-06**，Asia/Shanghai。
- 来源：用户反馈本设备安装 Windows 版 0.1.7 后打不开，快捷方式图标显示不对、偏小；后续明确要求在本协作包的 `05-运行维护` 下新增维护包，**暂定 0.1.8 发版**。
- 对象：安装在 `D:\Software\Develop\OpenCodeX Desktop` 的桌面管理器 **0.1.7 / Windows x64**。
- 源码基线：`v0.1.7@ed99a59af25e49dbed21820d3300ebdf3273e86a`，与安装实例启动日志声明的构建提交一致。
- 状态：**0.1.8 特性分支与首屏续修已推送；9262a5b 的 CI 和 Windows 普通/管理员首屏复验均通过；cffca3af 的 Windows NSIS/MSI 候选包新装、首屏与卸载通过，已可下载；未合并、未正式发布**。macOS 原生首屏、偏好恢复、隔离 .app 副本升级和真实安装往返已通过；最终包的用户设备升级/双权限/DPI、完整生命周期与签名 OTA 门禁仍待执行。0.1.7 原始诊断保持当时口径，补 HOME 对照不作为修复回执。

## 结论

两个直接问题均有本机证据，Windows 的运行适配仍有遗漏：

1. **启动崩溃：** 0.1.7 的启动阶段强制读取 HOME，本机默认环境缺少该变量，setup 返回 `application is not configured yet` 后进程退出。仅向同一 EXE 的诊断进程设置 `HOME=USERPROFILE`，进程即保持运行并创建主窗口。未确认完整界面渲染与业务流程。
2. **图标偏小：** 已安装 EXE 的 ICO 解码像素与源码 ICO 一致。32×32 档实际图形仅 10×10，边长占比 31.25%；256×256 档也只有 68×68。应用 PNG 已是另一套饱满图形，Windows ICO 仍有大面积透明留白。
3. **后续适配风险：** 默认发现仍使用 macOS 的 Node/npm/ocx 路径；托管入口仍生成 `/bin/sh` 脚本，受控 PATH 仍按 Unix 拼接；Windows 本机 IPC 尚未实现。以上由固定版本源码确认，尚未逐项运行验收。
4. **门禁不足：** Windows CI 仅执行 `cargo check`，启动接线测试还限定 Unix，没有检查最终 Windows EXE 在缺少 HOME 时能否启动。
