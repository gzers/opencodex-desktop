## Superba 设置页可以佐证什么

1. 它采用版本化配置目录和通用编辑器，简单字段、简单列表及标量映射可编辑；部分复杂表、联合类型和数组结构只读，目录项数量不能视为独立已实现功能数量。
2. 默认视图按生命周期筛选，开发中、废弃或移除项通常在高级模式中显示；已有配置、待改或推荐项仍可能出现。截图的“已修改”按 managed / pending 筛选，不必然表示偏离默认值。
3. 连接、模型和供应商等字段有保留 owner，普通设置不能覆盖。其写入计划检查版本、类型、取值范围、父子路径重叠及 TOML 形状冲突；未发现针对本专题后台压缩与 token budget 的专门互斥校验。
4. 它可在临时配置目录运行 `codex features list` 获取功能开关状态。这不证明 Desktop 使用同一引擎，也不证明渠道授予或实际执行了该能力，不构成采用运行时自动探索机制的依据。

## 优先评估的配置候选

下表表示先进入字段盘点、只读目录和可行性验证的候选顺序。页面归属是建议，实际支持的全局 / 项目 / 会话作用域需通过公开接口和真实客户端核验，不能从页面划分反推接口存在。

| 方向 | 字段 | 价值和限制 | 建议承接 |
|---|---|---|---|
| 推理摘要 | `model_reasoning_summary` | `auto / concise / detailed / none`；与推理强度分别设置 | 模型配置，共用已有选择器 |
| 输出详细度 | `model_verbosity` | `low / medium / high`；依赖模型能力，不能对所有模型承诺生效 | 模型配置 |
| 审查模型 | `review_model` | `/review` 的模型覆盖；Desktop 对应审查入口是否消费仍需验证 | 模型 / 对话配置评估 |
| 速度档 | `service_tier`、`features.fast_mode`、`features.ultrafast_mode` | 沿用现有 Standard / Fast / Ultrafast 方向，区分选择、发送和实际授予 | 模型配置＋渠道特殊能力，不另建重复总开关 |
| 自动压缩计数 | `model_auto_compact_token_limit`、`model_auto_compact_token_limit_scope` | 阈值及 `total / body_after_prefix` 统计范围；与上下文窗口一起说明 | 模型 / 渠道特殊能力的高级项 |
| 后台预压缩 | `features.async_compaction.enabled`、`features.async_compaction.model_async_compact_threshold_percent` | 表形式阈值 1–100，目录默认 65%；默认值是来源事实，非本项目已选默认 | 渠道特殊能力，受协议与模式前提约束 |
| 轮次结束压缩 | `model_post_turn_compact_threshold_percent` | 0–100，未配置或 0 关闭；最终回复后检查，与后台预压缩分别表达 | 渠道特殊能力的高级项 |
| history/notes | `features.context_management`、`features.token_budget.enabled`、`features.token_budget.use_history_notes_extension` | 沿用本包已有认证、provider、会话归属与 Krill 互斥边界 | 渠道特殊能力 |
| 项目说明 | `project_doc_max_bytes`、`project_doc_fallback_filenames`、`project_root_markers` | 项目说明字节预算、备用文件名、根目录识别；影响指令读取 | 全局 / 项目高级设置 |
| 工具输出预算 | `tool_output_token_limit` | 工具输出存入上下文时的截断预算，不是模型输出总量或请求费用上限 | 全局 / 项目或对话配置评估 |
| 搜索 | `web_search`、`tools.web_search.allowed_domains`、`tools.web_search.context_size`、`tools.web_search.location` | 此目录有 `disabled / cached / indexed / live`；域名、上下文量和大致位置还取决于渠道支持 | 已有 Codex 对话配置包 |
| 子 Agent | `agents.enabled`、`agents.default_subagent_model`、`agents.default_subagent_reasoning_effort`、`agents.max_concurrent_threads_per_session` | 默认模型、推理强度和并发上限；复用模型目录，不另造模型管理 | 已有 Codex 对话配置包 |
| MCP | `mcp_servers.<name>.enabled`、`required`、`startup_timeout_sec`、`tool_timeout_sec`、`mcp_optional_startup_grace_ms` | 启用、必需服务、启动与调用超时、可选服务的共享启动等待；注意版本和旧超时字段 | 多 Agent 平台扩展管理评估，先限定 Codex 适配器 |
| Skills | `skills.bundled.enabled`、`skills.config`、`skills.include_instructions`、`skills.max_context_tokens` | 内置与单项开关、技能清单注入和目录预算；不是技能正文执行时全部上下文的统一上限 | 多 Agent 平台扩展管理评估，保留客户端差异 |

字段来源：[模型](https://github.com/krill-lab/superba/blob/c6bb2faa3e0bf6aac9c68de9400c06f165d62442/catalog/overlay/config-model.toml#L33)、[上下文](https://github.com/krill-lab/superba/blob/c6bb2faa3e0bf6aac9c68de9400c06f165d62442/catalog/overlay/config-context.toml#L287)、[子 Agent](https://github.com/krill-lab/superba/blob/c6bb2faa3e0bf6aac9c68de9400c06f165d62442/catalog/overlay/config-agents.toml#L56)、[Skills 与搜索](https://github.com/krill-lab/superba/blob/c6bb2faa3e0bf6aac9c68de9400c06f165d62442/catalog/overlay/config-tools.toml#L299)、[完整类型目录及 MCP 字段](https://github.com/krill-lab/superba/blob/c6bb2faa3e0bf6aac9c68de9400c06f165d62442/catalog/dist/codex-0.163.0.json)。

## 渠道连接与传输的高级候选

以下字段均位于 Codex 的 `model_providers.<name>` 下，不能直接等同于我们代理内部同名渠道。

| 字段后缀 | 用途 | 后续需要核对 |
|---|---|---|
| `model_catalog_url` | Codex 原生模型目录的完整 URL | 与现有上游模型列表获取和目录投影的关系，避免重复设置 |
| `capabilities.external_web_access` | 实时搜索访问能力声明 | 声明不代表渠道实际支持；影响搜索模式可用性 |
| `capabilities.remote_compaction` | 自定义 provider 的远程压缩协议声明 | 内置 `openai` 路径不能直接套用自定义 provider 表；压缩真实处理路径沿既有验证 |
| `supports_websockets`、`websocket_connect_timeout_ms` | WebSocket 能力和连接超时 | Codex → 代理与代理 → 渠道两段是否均支持 |
| `request_max_retries` | HTTP 失败重试次数 | 与代理已有重试、故障切换的叠加，避免放大请求 |
| `stream_max_retries`、`stream_idle_timeout_ms` | 流断线重连、流空闲超时 | 不等同于代理上游超时或整个任务运行时限 |
| `http_headers`、`env_http_headers` | 固定或从环境取值的请求头 | 凭据字段归属、保留头和传输位置，不能用界面字符串覆盖认证规则 |
| `query_params` | URL 查询参数 | 参数作用于哪一段连接、是否已有公开入口 |

保留原版 OpenCodex 多渠道和公开入口边界。每项先确定由 Codex、原版公开配置还是外部适配层承接，无法映射的保留候选或上游依赖，不以写入一个 Codex 字段代替完整代理适配。来源：[供应商能力](https://github.com/krill-lab/superba/blob/c6bb2faa3e0bf6aac9c68de9400c06f165d62442/catalog/overlay/config-provider.toml#L248)、[目录、传输与重试](https://github.com/krill-lab/superba/blob/c6bb2faa3e0bf6aac9c68de9400c06f165d62442/catalog/overlay/config-provider.toml#L405)。

## 后续或仅高级设置评估

| 方向 | 字段 | 建议与限制 |
|---|---|---|
| 上下文预算细节 | `features.token_budget.reminder_threshold_tokens`、`guidance_message`、`reminder_message_template`、`auto_compact_fallback_prompt`、`auto_compact_fallback_buffer_tokens` | 先跟随 Codex 默认；兜底提示词与缓冲有配套条件，不能只开放一个孤立字段 |
| 长期记忆 | `features.memories`、`memories.generate_memories`、`memories.use_memories`、提取 / 整合模型与保留期限 | 与当前窗口的 history/notes 是不同机制，可能增加模型请求；生成和使用也分别控制 |
| 持久目标 | `features.goals`、`goals.max_goal_token_budget` | 目标和自动继续执行预算，不代表整个账号或全部 API 请求的费用上限 |
| Hooks | `features.hooks`、`hooks.*`、`hooks.state.*.enabled / trusted_hash` | 涉及命令、事件和复杂结构，先由扩展管理方向评估专用编辑方式 |
| 子 Agent 后端 | `features.multi_agent`、`features.multi_agent_v2`、`agents.max_depth`、命名代理配置 | V1 / V2 优先级不同；`max_depth` 在 V2 被忽略，角色 config_file 不能当普通标量功能自动实现 |
| 审批与权限 | `approval_policy`、`approvals_reviewer`、`sandbox_mode`、`sandbox_workspace_write.network_access / writable_roots`、`default_permissions`、`permissions` | 全局 / 项目范围；新权限配置与传统沙箱组合须核验版本；`never` 不等于取消所有安全检查 |
| Shell 环境 | `shell_environment_policy`、`allow_login_shell` | 影响实际进程环境和凭据可见性，不随渠道自动改变；旧 inherit/include/exclude 与 filters 形式需版本适配 |
| 隐私与反馈 | `analytics.enabled`、`feedback.enabled`、`otel.*` | 全局偏好；关闭内置统计不能宣称关闭独立配置的 OTLP 指标导出 |
| 显示与通知 | `hide_agent_reasoning`、`show_raw_agent_reasoning`、`notify` | 不等于推理强度；原始推理内容不保证可得，外部通知命令与管理器自身通知分别归属 |
| 空闲资源 | `thread_unload_delay_secs` | app-server 无订阅和活动时从内存卸载会话，目录默认 1800 秒且要求重启；不是删除会话 |
| 存储路径 | `log_dir`、`sqlite_home`、实验性 thread store 与符号链接主目录 | 影响发现、备份和迁移，先诊断或只读，不优先开放任意路径切换 |
| 压缩提示词 | `compact_prompt`、`experimental_compact_prompt_file` | 参考说明限定客户端本地压缩路径，不能宣传控制远程协议的压缩质量 |
| 内置指令替换 | `model_instructions_file` | 覆盖模型内置指令，不宜包装成普通附加提示词；`developer_instructions` 语义另行区分 |

## 配置管理底座建议与实施顺序

建议共享一份版本化配置目录，让现有模型、渠道、对话和扩展页面按 owner 使用；普通设置页承接其余适用字段。审批、隐私、机器路径等不随渠道切换隐式改变。按会话覆盖只在公开接口和客户端确实支持时开放。

候选目录元数据包括字段类型、来源、适用引擎和客户端、生命周期、默认值、互斥依赖、归属、可编辑性和重启条件。界面分别表达文件当前值、来源、待应用值和可确认的运行值；未知就显示未知，不从保存成功推导实际生效。恢复默认与停止管理该字段的语义也需分别设计。

优先级建议：

1. 先完成配置目录、版本识别和差异预览，并证明隔离、独立恢复和共同文件写入保护。
2. 先评估压缩参数、模型回复表现、搜索参数、子 Agent 并发、项目说明 / 工具输出 / 技能目录预算，以及 Codex 的 MCP 和 Skills 参数。
3. 再评估 Memories、Goals、Hooks、权限和环境配置；防休眠需先解决 Desktop 适用性。存储路径、遥测细节及 TUI 专用项维持高级或只读候选。

具体交付范围后续冻结，不将以上顺序视为全部进入同一版。多 Agent 平台扩展包优先承接 MCP、Skills，并评估 Hooks；子 Agent 行为仍由已有 Codex 对话配置包评估，不能因名称相近就迁移归属。

本次没有安装或运行 Superba、改写原版 OpenCodex 或运行配置，也没有新增渠道请求、故障演练或产品通过项。本文只补齐可追溯的配置候选分析；恢复前提、现有代理限制及同版候选关系继续有效。
