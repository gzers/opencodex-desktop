## 本轮证据

[20261011-方案逻辑与可行性审计](20261011-方案逻辑与可行性审计.md)记录 8 项缺口、8 项实测与源代码定位。

- 原生项目分页、稳定 ID、thread 项目筛选、标题回写已实测可用。
- 同一 app-server 可热更新已加载 thread 的后续轮次模型 / effort；一次性覆盖和撤销继承需要显式处理持久参数。
- 同 CODEX_HOME 的第二实例能读记录，但不能直接控制第一实例已加载的 thread。
- OpenCodex 已有全局搜索 sidecar、辅助调用模型路由及多项子 Agent 配置；局部作用域不能通过切换全局默认值实现。

以上技术结论限定于审计所列版本与路径，不等于本项目已经实现功能。

## 独立存储与订阅建议

用户要求分析独立配置文件，并由方案判断订阅的必要性与易用安排。[详细方案](../02-方案草案/独立配置存储与事件订阅适配方案.md)建议分离用户策略、本机绑定、操作状态和可重建缓存；采用配置及执行事件，定时刷新按实际缺口补充。0.1.10 活动根、写者准入和事件底座可复用；协作备份范围、协作事件、实际实例连接和可能的共享调度扩展仍需实现。

这些属于分析建议，具体文件名、schema、约 60 秒的缓存新鲜度和首批范围尚未冻结。用户授权分析必要性不等于批准全部候选设计，版本与开发时机继续待定。

用户后续明确建议按项目拆分，避免单文件随项目 / 对话数增长，并在项目删除、对话归档时同步清理配置。当前草案已改为全局文件 + 项目目录 + 按需 thread 文件，替代全量作用域单文件建议。原生 ID 稳定不代表配置必须永久保留。具体迁移、取消归档继承和事件缺失处理见详细方案第 7.5 节；自动清理及分层恢复尚未实施或实测。

用户已明确要求 WebDAV 默认不同步本包对话配置，适用于全局、项目和对话三级，替代此前跨设备默认包含新增全局行为的建议。手动导出 / 导入、本机备份独立于 WebDAV 选择；详细入口与载荷仍属方案建议，见 [导出与 WebDAV 默认范围](../02-方案草案/独立配置存储与事件订阅适配方案.md#81-导出与-webdav-默认范围)，尚未实现。

## 导出容量评估

[对话体积与导出空间评估](20261013-对话体积与导出空间评估.md)只读本机文件元数据：192 个原生历史文件约 12.69 GiB，中位数约 1.57 MiB，最大约 10.09 GiB。多数文件小于 10 MiB，少数超大记录主导空间；数量不是独立主对话数。未读取正文，未测压缩率。

联合导出方案已补按用途选主要历史表示、体积预览、流式压缩和 ZIP64，避免默认三份重复历史；原生恢复载荷不通过任意删事件瘦身。上述为容量设计建议，大包性能、实际空间峰值和恢复验收仍待实现验证。

后续用户明确仅用于临时重装，并要求对话像配置一样在同步范围中默认未勾选。另统计未归档 sessions：75 个原生文件约 12.01 GiB，中位数 1.39 MiB，最大两份约 10.09 / 1.28 GiB，其余 73 份约 654.30 MiB。首批内容流程收敛为本地恢复包，不要求周期历史备份或远端交换；详细依据见 [重装用途评估](20261013-对话体积与导出空间评估.md#7-后续澄清未归档容量与临时重装用途)。具体包格式、原生集成、版本及开发时机仍未冻结。
