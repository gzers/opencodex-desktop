# 统一事件注册与多触发源规划（0.1.10 候选）

关联 MNT-OPENCODEX-DESKTOP-20261009-01；2026-10-09。输入为用户本轮五条概览批注、明确要求“事件触发多种，文档规划全部事件”，以及既有通知与反馈体系规划。

范围是桌面管理器当前产品流程中的领域结果、持续状态及公共反馈。下表是完整设计盘点，**不是生产发出点全量接入证明**。维护者为 Ezio 与协作 Agent，保留至维护闭环；实施映射与设备证据继续回写 IMP / RUN，批准的稳定规则再回写产品规格。

## 配置与职责

候选机器配置唯一来源为 [maintenance-events.js](../../../../../../01-项目支撑资料/01-产品原型/原型/maintenance-events.js)。普通 script 与 CommonJS 双入口兼容 file://，不 fetch JSON。原型状态和注册表弹窗直接消费同一配置；下表是可阅读的规划快照，修改注册项时同步本文。配置在 docs/governance-main，生产实施需在代码分支落地受控注册模块并引用本设计。

- triggers：允许的触发源 ID 与含义；来源可以多种，不能用一段说明代替枚举。
- jobs：任务 ID、对象、多个触发源、启动延迟、通道周期、失败退避、启用条件、接入状态；负责何时执行检查。
- events：事件 ID、模块、条件摘要 trigger、允许的 triggers[]、来源、分类、级别、性质、检查周期、提醒周期、去重、冷却、解除事件、投递面、保留与脱敏；负责结果如何反馈。摘要不是调度表达式。
- 发出时携带 objectId / operationId / revision / channel / stage / origin 等白名单上下文。原型只使用固定示例；生产禁止路径、账户显示名、口令、token、原始异常进入通知。错误使用可定位事务的脱敏错误码。

一次任务可由多个来源发起，结果只发出一次。对象保留内部 runtime 键以兼容原型桥接，面向用户统一称“面板”；其更新仍指 OpenCodex 官方包，不创建一套面板独立安装器。

## 触发源与默认调度

| 来源 ID | 意义与门控 |
|---|---|
| user.action | 手动检查 / 明确操作；跳过缓存，受同对象事务互斥保护 |
| app.ready | 当前原型应用就绪后 15 秒；生产目标改为 UI 就绪后 30–60 秒低优先级到期评估，具体值在 P0 冻结；持久缓存未过期时复用，不每次启动重复联网 |
| route.overview.enter | 进入概览显示缓存，只在到期后检查；重复切入不重复请求 |
| route.settings.enter | 对应设置的状态检查；诊断候选来源，更新页与概览共用缓存 |
| schedule.due | 到期触发；管理器 stable 24h / beta 6h，面板官方包 24h |
| window.resume | 挂起恢复时检查到期任务；只补一次，不补跑错过周期 |
| network.online | 网络恢复后执行到期 / 退避到期检查，不绕过失败退避 |
| policy.changed | 管理器通道改变，只使管理器旧查询 / 确认失效后重新检查；面板不由此触发，手动模式不自动执行 |
| retry.due | 失败后 5min → 30min → 2h，最多三次快速重试，之后回到正常周期 |
| state.changed | 代理、面板、账户或拓展受控状态变化；不按轮询帧重复通知 |
| data.changed | 配置 / 对象变更，可使相关检查失效；不直接触发覆盖或修复 |
| operation.result | 异步事务结果，生产继承最初来源与操作 ID |

更新两个对象各有任务锁、缓存和世代号。启动、概览、定时、恢复同时到达时，只创建每个对象一个事务；手动操作也不能叠加正在检查 / 应用的事务。成功按各自周期缓存；失败不刷新成功缓存，用下一次允许时间统一拦截各自动源，防止请求风暴。取消后自动源冷却 5min；手动可重试。切通道只使管理器旧查询 / 确认失效并重置管理器缓存；面板官方来源、候选、缓存、世代号、失败退避、已有确认和在途检查 / 应用均保留。policy.changed 只调度管理器，不以切通道为由重新检查面板。选择当前通道无副作用；管理器写入或待重启阶段阻止切换，面板忙碌不阻止管理器通道调整。

手动模式关闭两个对象所有新的自动检查；已经接受的面板检查 / 应用继续完成。退出手动模式后面板按原 nextDue 与退避恢复，不重置到期时间、不补跑错过的周期；自动源只做只读检查与通知，**不自动下载、安装、重启或恢复**。生产需持久化最后成功检查、下一次允许检查、候选版本与提醒记录；内存原型刷新重置，不覆盖跨启动去重验收。

其他周期任务也显式注册：诊断每 6h 是候选；WebDAV 自动同步每 15min 是候选且默认关闭，必须具备连接、范围和用户授权。两项目前 planned，原型不调度，不从更新周期推导它们。

2026-10-10 性能与持久缓存补充：生产使用一个集中 nextDue 单次定时器，不沿用原型分钟评估 timer 作为生产方案。macOS 更新元数据默认在 ~/Library/Application Support/com.gzers.opencodex.desktop/cache/updates/；Windows 在 <实际安装目录>\data\cache\updates/，已有自定义活动根优先。调度 / 退避 / 去重持久状态归活动根 manager-state，清除可丢弃缓存不重置检查周期。普通权限不可写不静默回退 AppData；旧数据升级不自动搬动。全流程、性能预算、跨启动与真实 24h / 6h 周期验收见 [IMP-20 第 4–5 节](../../../../../../../03-开发实施/IMP-OPENCODEX-DESKTOP-20.md)。持久缓存及集中调度已有源码提交 a8a67377，生产首屏就绪延迟取 45s；设备配对性能与真实周期仍未验收。表内 prototype / planned 表示原型状态，生产接入进度另见执行基线与契约，不在本表冒充稳定核心事实。

## 更新交互

概览保留“检查更新”一个按钮；手动检查完成进入结果步骤。管理器 / 面板状态行分别打开详情与确认，不再并列“查看更新”和“升级前备份”。检查中、未检查、应用中行禁用；已最新 / 完成可查看信息；失败可查看并重试。手动检查期间离开概览或已打开其他弹窗，结果不抢弹窗，仍可回概览点击状态行。

确认步骤说明对象、版本、来源、影响，并提供默认勾选的“更新前备份管理器偏好”。只含偏好、清单和摘要，保存在当前数据根 backups；不承诺完整面板配置 / 会话 / 登录态 / 安装包。可取消勾选；勾选后备份失败阻断更新，停留确认步骤。取消确认不备份 / 更新；过期版本 / 世代号拒绝执行。可选方案仍待生产契约定稿，既有强制保护事务不能依据原型被静默降低门禁。

## 通知规则

性质分一次性、状态变化、周期检查。检查周期与提醒周期分别配置：每天检查但后台“没有更新”只写记录；新候选进中心。手动无更新给 toast；后台失败进中心 / 日志，避免每个自动源各弹一次。新版本不主动弹确认框。

去重按事件 + 对象 + 版本 / 状态修订 + 通道 + 阶段；一次性事务另带 operationId，来源不参与去重。相同候选 24h 冷却内合并计数；不同版本 / 通道不能被吞。检查成功只解除同对象、同通道的 checking 失败；完成更新才解除同对象、同通道、同候选版本的 applying 失败、可用更新与待重启提醒。阶段缺失不作通配符；切换通道不是失败恢复证据。代理崩溃 / 冲突按恢复事件解除。已读、已解决、软删除沿既有语义，不相互替代。

### 2026-10-10 原型审计修正：解除必须有对应成功证据

本轮修正已获用户授权，仅修改共用原型与本协作包。配置新增可选 recoveryMatch（被解除事件 → 必须相等且非空的上下文字段）及 dedupeFields；通知只保存白名单 action / stage / operationId / channel / revision / errorCode 等。解除规则仍先匹配事件与对象，阶段限定必须在失败和成功两端都存在且一致。缺少元数据的右侧通用示例只演示投递，不解除有范围约束的真实原型失败。移除模型中绕过注册规则的宽泛 resolve(id, object) 入口。

| 失败与解除 | 必须对应的范围 | 不构成解除的操作 |
|---|---|---|
| backup.failed → backup.created | 对象 preferences、动作 create、阶段 creating、同一备份创建 / 更新确认事务 operationId | 手动另建备份、另一个对象的更新备份、过期确认、取消勾选、跨事务创建成功 |
| backup.restore.failed → backup.restored | 恢复源备份 ID、动作 restore、阶段 restoring；同源重试经校验并成功恢复 | 创建恢复前保护备份、恢复另一份有效备份、源不存在或仍校验失败、只结束任务 |
| update.failed:checking → update.available / update.latest | 更新对象、通道、checking 阶段；新检查成功可解除同范围旧失败，不要求同一请求 ID | 其他通道成功、仅完成下载、缺少阶段或通道 |
| update.failed:applying / update.available / update.restart.required → update.complete | 更新对象、通道、候选版本；应用失败另限定 applying 阶段 | 仅检查成功、其他版本 / 通道完成、管理器未重启回读 |

恢复源缺失使用 source.missing，校验失败使用 integrity.invalid，创建失败使用 creation.failed，均为固定示例错误码。创建失败去重带失败事务 ID；恢复失败按源 ID、动作、阶段与错误码合并，成功后再次失败产生新记录。已读不随解除改变。更新确认失败后在同一版本 / 世代号内重试才视为同一创建事务；取消勾选只是绕过候选备份选项，不能声称此前备份成功或解除其失败。

这些约束须由后续代码实施映射真实对象、动作、阶段、事务、来源与成功证据；不把原型示例 ID / 错误码当作已定生产契约。尚未接入的其他 planned 事件仍需逐项审核解除语义，不能据此宣称所有生产异常都已覆盖。验证与待验边界见 [原型 QA](../原型/原型QA.md)。事件规则尚未稳定，本轮不提前晋升为核心事实文档。

reminderPeriod 是提醒策略说明，当前不另运行通用提醒定时器：更新在下一次检查仍有同状态时按冷却投递，其余模块需生产接入后验证。中心默认保留 30 天，但未读与 danger 保护沿通知策略，不能到期硬删。task / inline / toast / center / system / log 六种表面分别承载进度、输入错误、操作反馈、需要处理的记录、授权后的系统提醒和审计；不是全部事件都进通知中心。
