# 原型准备度与模型模版边界评估

日期：2026-10-13（Asia/Shanghai）。对象：OpenCodex 桌面管理器，COL-LOCAL-20261011-01。状态：设计启动评估与候选安排；尚未制作本包原型，版本与开发时机未定。

用户要求：“评估一下这个协作包是否可以做原型设计了，担心原型设计会和模型模版（0.2.0）搞混。”本文依据当前协作包、模型配置包和唯一总原型进行有界核对；评估结果不等于用户批准全部交互或指定开发版本。

## 1. 结论

可以开始本包的交互原型：配置入口、对象选择、字段继承、保存反馈、生命周期与导出范围已足以组织可点击流程。第一轮以这些流程及三项功能的基础字段为主，使用 mock 展示执行未接通与不同采用边界。真实执行实例连接、局部搜索上下文及 child 参数验证可以与设计继续并行，不必等全部技术问题解决才画配置页。

目前尚不适合将原型定稿为“全部局部设置均已可执行”，也不据此启动生产实施。新建任意角色 / 权限、搜索统一回退、每轮命名、跨项目总并发与定时切策略继续作为后续讨论；不把它们加入首轮必须完成的字段墙。

本包与模型模版可以共用产品壳、模型目录和控件，但需要独立页面、配置所有权及设计范围标注。模型配置包的 0.2.0 仍是其候选版本，本包继续版本未定。

## 3. 与模型模版的职责边界

| 比较项 | 模型配置管理与同步（0.2.0 候选） | Codex 对话配置管理（版本未定） |
|---|---|---|
| 用户操作的对象 | 渠道、模型、模型模版及固定 revision | Codex 数据源、项目、对话和其子 Agent 策略 |
| 核心问题 | 模型如何连接、暴露哪些能力、采用哪些规则 | 命名、搜索、子 Agent 在这个范围使用什么设置 |
| 模型字段 | 协议、端点、上下文、输入模态、可选档位、默认档、Fast 声明等 | 模型引用及本任务选择的档位；能力与兼容范围由模型 / 执行路径提供 |
| 匹配与继承 | 模型原始 ID、渠道范围、版本 / 后缀匹配及渠道 / 单模型例外 | 原生默认、全局、项目、对话及执行时显式值的作用域继承 |
| Agent 的含义 | 帮用户自动填充和纠偏模型模版的管理器助手 | Codex 执行对话中的子 Agent 及其运行设置 |
| 命名的含义 | 模型别名 / 显示名称是模型身份展示 | 对话标题自动命名；命名提示词不称为模型模版 |
| 保存结果 | 保存模版进入候选；采用后形成渠道草稿，渠道保存另有加载核对 | 保存本作用域策略，再按具体执行边界报告采用 |
| WebDAV | 模型双文件按原包范围安排；本机绑定与助手执行偏好仍排除 | 全局、项目、对话协作策略均默认排除，需显式选择 |

同一个“推理档位”控件可以复用，但语义必须分开。例如某模型在模型模块声明可选 low / medium / high、默认 medium，本项目的子 Agent 选择 high，只形成项目覆盖，不把该模型的通用默认改成 high。项目恢复继承后重新读取模型与上层的当前默认，不复制一个过期的 medium 常量。

普通默认与强制限制也须区分：合并任务选择后，由具体路径检查模型可用性、强制档位、cap 及参数表达。冲突显示实际限制和影响，不能以项目覆盖为理由放宽模型声明或原生权限；能力未知时如实保留未知，不伪造全套档位。

模型模版页的“Agent 自动填充”及 `preferences.modelTemplateAgent` 继续归原包，本包不接管、不将其挂到 Codex 全局子 Agent 默认下。该助手的公开资料检索也不因本包设置 Codex 搜索就自动改变；外部 CLI 制模任务仍使用执行工具自身配置。可复用连接选择和模型解析服务，不共享同一份可写运行偏好。

本包选择的是模型身份，如 nativeModelId 或 channelId + modelId；不直接采用某个模版 revision 作为“对话模版”。查看模型规则时可展示该模型最终规则及来源 revision，修改入口回到模型页，并保留对话页未保存输入。

模型目录变化后刷新候选及继承值；模型被删除 / 停用或路径不兼容时保留原引用并说明原因，不按同名静默替换。模型选择器排序、子 Agent 推荐 roster 和默认对话模型保持各自职责。现有 OpenCodex 全局字段仍经其管理 API 保存，本包不再镜像一份独立可改的相同值。

模型边界依据：[自由模版与匹配规则](../../../2026-10-04-模型配置管理与同步/01-需求分析/02-方案草案/模型模版与匹配规则方案.md)、[模型配置管理方案](../../../2026-10-04-模型配置管理与同步/01-需求分析/02-方案草案/模型配置管理方案.md)、[制模助手执行配置](../../../2026-10-04-模型配置管理与同步/01-需求分析/02-方案草案/Agent制模与版本恢复方案.md)。

## 4. 会造成混淆的具体位置

1. **页面归属**：现有 `#models` 已有“渠道模型 / 模型模版”。2026-10-13 用户确认独立菜单名称为“对话”，页面标题与 tooltip 为“Codex 对话配置”；内部是自动命名、联网搜索、子 Agent，不把本包作为模型模版编辑器的第三个配置分区。功能名称已确认，布局与具体交互继续通过原型讨论。
2. **模版与提示词**：本包字段称“命名提示词”“子 Agent 指令”，不用“新建模型模版”“设主版本”“采用模版”等按钮。已有角色显示为角色设置，不复刻一套模型模版版本库。
3. **助手与子 Agent**：模型页的制模助手留在模型页；对话页以“子 Agent 默认模型”“推荐模型”等具体用途命名，避免共用一个不带对象的“配置 Agent”入口。首轮无需新增用于填写协作表单的聊天助手。
4. **保存与生效**：模型页已有“保存后待 Codex 重启核对”，不能搬成对话页统一反馈。后者按实际接入显示“未接通”“下一轮”“下一次搜索计划”“新创建的子 Agent”或该字段确需的重载；mock 的采用结果只由演示场景驱动。
5. **同步默认**：现有 `sync-config.js` 的 `fresh(mode)` 对文件同步选择 catalog 全部、对 WebDAV 主要排除 endpoints。直接加入新协作分类会自动选中。后续应为新模块配置明确的默认排除规则，覆盖初始化、缺字段升级和预设重置；“全部配置”等通用预设及模型依赖收集不应自动启用协作模块。协作范围只有显式选择后才加入；关闭时远端含此模块也跳过应用 / 删除。
6. **总原型版本标签**：支撑资料的总原型 README 当前写“0.2.0 可交互设计草稿”。加入本包时应改为按模块列设计范围，分别标“模型配置：0.2.0 候选”“Codex 对话配置：版本未定”。同一产品的一套原型可包含不同版本候选，不让统一壳或历史标签替本包承诺 0.2.0。

上述为源码 / 文档核对所得及设计建议。本轮没有改导航、同步默认选择代码或总原型版本标签。

显示名称改为“对话”不要求同步修改候选技术文件名、CollaborationService 或 collaboration 命名空间。它们尚未形成生产契约，实施时再统一确定；本次不迁移真实配置，不改 COL 身份或测试证据引用。

## 5. 第一轮原型建议范围

目标是普通用户能够选对对象、理解继承、保存覆盖并看到真实边界。平台为 Desktop，沿用已有 [UI 规范](../../../../../../02-项目核心/UI规范.md) 的 1180 × 760 和 900 × 600、亮暗主题及公共 Select / 树表。只用 mock 数据，不连接真实 Codex / OpenCodex、WebDAV 或模型。

| 页面 / 流程 | 第一轮应展示的行为与状态 |
|---|---|
| 对话配置主页面 | 数据源单一时无需反复选择；全局 / 项目 / 对话切换；按需分页对象选择。同名项目用来源 / 路径辅助区分，身份细节按需查看 |
| 当前作用域编辑 | 自动命名 / 联网搜索 / 子 Agent 三个分区；逐字段继承或自定义，显示有效值与来源；保存本全局 / 本项目 / 本对话，恢复本层继承 |
| 自动命名 | 默认保持现有原生命名；可选管理器命名的首轮一次、模型与提示词；手工改名后停用、失败保留原标题。原生 helper 可能影响其他辅助调用时，按实际路径说明 |
| 联网搜索 | sidecar 路径的模型与档位；hosted search 或搜索服务路径显示其实际适用字段。模型声明支持工具不等于已接通搜索；局部路径未接通保留配置意图 |
| 子 Agent | 推荐 roster 与默认模型意图分开；已有角色展示和推理选择；V1 / V2 及未接通字段给具体说明。普通操作不必先编辑角色权限 |
| 保存反馈 | 未保存、保存中、已保存但执行未接通、已接收 / 待观察、观察到采用、应用失败；离线仍可编辑已有绑定。常规保存一次提交，不加统一二次审批 |
| 生命周期场景 | 原生归档 / 删除后的关联清理反馈；归档对话只读、取消归档继承；移动项目改继承，归属未知保留待核对。通过 mock 事件驱动，不顺带建设完整项目 / 对话管理器 |
| 导出 / 导入与同步 | 专用导出带入当前作用域、选择携带上层；导入对象与模型待匹配；本机备份独立。共用同步页新增默认未勾选模块，不新建第二个 WebDAV 页面或连接配置 |

切换对象与分区要保留未保存输入，查看模型规则返回后也保留；状态刷新不抢选择和焦点。命名、搜索、子 Agent 是否可执行按字段显示，缺一项能力不禁用整页。

第一轮可点击走查：

1. 项目 A 的子 Agent 模型从全局继承，改为项目覆盖；对话 A1 再覆盖档位，A2 继续继承项目；恢复 A1 继承后来源正确。
2. 在对话页改变档位，返回模型页，模型模版的规则、revision 和制模助手执行偏好均未被修改。
3. 保存配置后区分未接通、执行端接收、实际采用；更新或恢复继承不让 mock 暗中统一跳到成功。
4. 归档 A1 清其专属覆盖，项目设置保留；取消归档继承，历史命名不补跑；项目改名保持匹配。
5. 模型停止可用、数据源断线或列表为空时保留输入，说明受影响字段；不把分页缺项当删除。
6. 导出指定项目配置并演示映射导入；模型双文件导出不带对话配置，WebDAV 初始化 / 预设重置仍不选择协作模块，导出 / 导入不改变同步选择。

上述是后续设计检查建议，尚未执行，不记为原型 QA 通过。

## 8. 同日补充：项目与对话也需导出

用户在评估后提出项目与对话文件也应导出。此前表格中的配置导出只满足设置复用；任务迁移需要加入记录、关联配置与对象映射，详见 [联合导出及恢复方案](../02-方案草案/项目与对话联合导出及恢复方案.md)。这不改变模型模版边界，也不阻止基础配置原型开始，但第一轮导出 / 导入流程需增加仅配置、对话记录和联合包的用途，以及阅读 / 可继续的能力区分。

最短原生往返链路已有同版本隔离证据；跨版本、实际桌面集成、策略绑定和子 Agent 树仍未验。WebDAV 不因新增内容导出自动包含历史，原对象归档也不删除已生成导出文件。本轮只补方案与探针，没有绘制原型。
