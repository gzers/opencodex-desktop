## 路径与边界

| 对象 | 当前规则 |
| --- | --- |
| macOS初始默认根 | ~/Library/Application Support/com.gzers.opencodex.desktop |
| Windows新默认根 | 实际应用安装目录下data，与盘符无关，不从cwd或临时updater位置推导 |
| 已有绑定 | 已登记的合法自定义根优先；旧AppData数据不因升级被静默丢弃，安装位置变化不隐式搬动已绑定根 |
| 不可写根 | Windows提供明确目录选择/初始化与持久启动指针，等待原进程结束再重启；不静默换AppData或要求日常管理员运行 |
| 初始化 | 确实空目录为uninitialized，经显式初始化后建立当前结构；非空缺元数据保持corrupted，空目录不能直接活动引用 |
| 管理器分区 | manager-state、runtime、backups、logs、exports、cache、sync-state由同一活动根解析；托管HOME使用活动根内部位置，已有外置HOME保持原绑定 |
| 例外 | OS凭据/OS及WebView管理文件、外部已有软件、用户明确选择的导出位置不声称由应用控制全部写入 |
| 迁移 | 全写者/运行准入、受保护清单、复制/验证及原子绑定，结果不确定保持冻结；重启在锁内回读，旧根保留，不自动删除 |
| 卸载 | 默认保留用户数据。Windows NSIS明确勾选清理时只作用于核验自有根，持有实例/备份锁、重验绑定，外置HOME保留；MSI没有新增原生清理复选框 |

## 备份目录与每种文件的用途

以下为结构说明，实际UI必须按清单构建树表，不生成虚构文件或把路径模板当作已经存在的文件。

| 层级 / 名称 | 用途与读取规则 | UI操作 |
| --- | --- | --- |
| backups | 当前活动根的备份分区 | 打开目录前警告 |
| 年 / 月 | UTC年月分类 | 默认根/年展开，月份收起；刷新保留展开与焦点 |
| action | upgrade/import/sync-overwrite/data-root-move/extension-write/runtime-uninstall/manual-preferences/restore-protection/preferences-protection | 用途由实际动作确定，不能全显示为偏好备份 |
| bk_UTC14_随机8hex | 一次实际备份记录的目录 | 从真实manifest识别归属、保护与恢复能力 |
| backup-manifest.json | 记录来源、动作、摘要、字节、恢复能力及管理元数据 | 打开文件前警告，后端再次校验路径/权限/存在与链接 |
| preferences.json（偏好备份） | 管理器偏好全文件payload，只恢复当前活动根偏好 | 不包含面板完整配置、会话、登录态或安装包 |
| 其他真实payload | 按该事务实际来源文件名和清单展示 | 不硬编码全部动作都是preferences.json |

v1每条记录为一个payload，摘要在manifest内部，没有独立checksum文件；多个payload/未知结构不得推定可恢复。两个文件均须完整保留，不能只留清单或只留payload。未来新增备份范围同时更新核心登记、manifest版本/消费者、目录用途、恢复/清理和事件规则，不能只加一个UI节点。

## BackupManifest的实际字段

当前schema_version=1，snake_case序列化。旧核心的kind/target/stored_at相对目录描述须在最终回写时更正为下表实际语义，不改历史载荷原文。

| 字段 | 类型 / 实际含义 |
| --- | --- |
| schema_version | u32，当前1，未来版本不自动接受 |
| backup_id | string，稳定备份标识 |
| action | enum，以上九类动作 |
| target_path | string，原被备份目标；恢复仍重新核对活动根及允许范围，不凭字符串任意写回 |
| stored_at / created_at | string，RFC3339 UTC时间；不是相对备份目录字段 |
| sha256 / bytes | payload摘要及字节数 |
| file_count | u64，当前受支持单payload记录为1 |
| restorable | bool，声明能力，恢复前仍重新验结构/摘要/归属 |
| note | string或null，说明文字，不提供事务归属或解除证明 |
| management | 可缺省的结构化管理元数据；旧无此字段不推定事务归属 |

management实际字段：version、kind、pinned、related_backup_id及可缺省transaction_state。v1/v2/v3的可接受组合由当前消费者严格核验，不将未知状态推成已完成；用户固定和临时事务保护独立。PreferencesProtectionRef用精确backup_id与payload sha256关联，不通过路径/note或同版本猜测备份。

## 保留、清理和恢复

- 按用途保留最近N=10份或D=30天内，满足其一保留；固定项不占N。不是最多10份，也不是到第30天全部删除。
- 默认先预览再手动确认；策略保存不立即删除。可选新备份成功后自动轮换，旧备份/关联/未知/损坏或受保护记录保持，清理失败不否定已成功备份。
- 预览有效期900秒，执行前重算并核对；在途关联组不得拆删。成功核验后解除的是对应临时保护，不取消用户固定。
- 恢复前创建当前偏好保护，核对原件大小/摘要/schema/类型与活动根边界，校验失败不覆盖当前偏好；恢复提交后再核对持久结果和关联解除。
- 目录/文件浏览拒绝链接、重解析点、越界及非普通对象，打开前UI警告不替代后端校验。静态组件/叶句柄检查不宣称抵抗任意并发父目录替换攻击。
- 损坏runtime-protection关联当前保留并阻止覆盖，普通本地重试不能重建缺失的精确关联；没有独立的受控修复入口，保留已知限制。

字段来源为modules/data_root、modules/backup/mod.rs/manager.rs/browser.rs、modules/update/schedule.rs、modules/runtime/protection.rs及真实8e原生记录。本提案描述当前实现与明确限制，不提升未验原生、安装、更新或周期门禁。
