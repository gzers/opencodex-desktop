# 0.2.24 发布后修复与官方运行包适配

2026-11-10。用户最新授权“本对话可以按顺序进行，目标模式进行”，当前执行开发/测试/集成及固定候选准备，Windows沿Git独占贡献；正式发布仍需有效授权，不从旧版本发布指令推造本版发布许可。发现版0.2.23与旧截图0.2.22分别保持；验收由本文、顺序由[IMP-34](../../03-开发实施/IMP-OPENCODEX-DESKTOP-34.md)、角色与写集由[TEAM-0.2.24](../../03-开发实施/TEAM-0.2.24.md)维护。

采用范围承接[后继修复边界](../../04-项目资料/01-项目支撑资料/06-问题记录/20261110-后继修复开发前边界确认.md)与其原型链接；不重新引入已取消的导入变化清单/二次确认、渠道协议或旧版兼容/自动迁移。原样官方2.99不制作新维护修订，必要能力由Desktop侧适配。

原型源中尚有并行概览/同步/模型探索未提交变更，开工与验收应固定本版已采用页面/状态的实际源码摘要，不能整树认领并行工作或只引用易漂移URL。布局采用：程序安装/卸载卡第一、端口第二；模型工具栏读取现有渠道→导入配置→新增渠道，文件按钮“选择文件”，导入一层直接备份覆盖；读取结果注册公共Toast及铃铛，保存前只更新草稿。

NAME剩余项未确定实现出口，保持其最终验收，不阻塞无依赖代码开发。此前固定键显示候选被官方覆盖不作为普通英文改名失败依据；真实保存10组证据复用。历史首错缺失不承诺重建原事故或永不报错；已证实链路与准确诊断/恢复有新证据即可分别验收。

## 完成与验证边界

- **AC-P24-01**：Mac标准单.app、用户独立运行程序目录与Windows实际自定义安装根；程序/配置分离，所有供应/安装/更新/回退/卸载同源且失败保全。
- **AC-P24-02**：终端ocx显式启用/禁用，使用与Desktop相同版本及HOME；已有命令不覆盖，只修改可证明归属的用户入口和PATH。
- **AC-P24-03**：保存基线区分有限格式/记账等价与真实外部冲突；草稿、凭据和导入来源保持，明确重核后可保存，最终锁内复验。
- **AC-P24-04**：原生JSON一层选择文件后点导入，自动完整备份再覆盖，保留本机port及模式；其它按源替换，校验/并发/备份失败不覆盖，可整文件回退。
- **AC-P24-05**：内置Node/npm/OpenCodex供应和就绪分别呈现，独立于系统Node；npm/GitHub按生效网络配置分类失败/缓存/重试，不伪装成功。
- **AC-P24-06**：实际磁盘版本、已证明运行版本与管理历史分开；外部更新后重新观测，执行前核对来源，备份与回退匹配。
- **AC-P24-07**：软件与采用原型一致：安装/卸载第一端口第二；读取/导入/新增相邻；单层导入；读取匹配公共通知；无渠道级协议。
- **AC-P24-08**：原样官方2.99的产品侧启停/身份/状态/恢复等价能力完整；30/5/10秒、未知拒绝、真实双SID/桌面与必要安装原生检查保持，限两稳定锁例外。
- **AC-P24-09**：普通英文新增/改名既有能力保持；非直接合法运行键及派生组展示方案经采用后，完整名称/人工显示优先、真实路由/模型/认证/能力、刷新/默认客户端/重启/回退可核验。


Windows仅按本次实际平台变更触发验收；普通共享UI以页面/组件验证。复用r5单用户技术可行性，不把test宿主通过冒充生产接入；最终真实双SID/候选安装/CLI等按固定集成来源验收。测试只用隔离合成配置/凭据，禁止真实业务同步或模型调用、日常重启/配置修改；保留原失败与成功，清理本轮所有权明确的残留。
