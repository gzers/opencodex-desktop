## 约定

1. **不重开协作包**：维护记录以附件形式承接，不改写 `01-需求分析/` 的既有结论，不改变需求与实施对象状态。
2. **按问题拆分**：每条记录一个目录，命名 `YYYYMMDD-问题短名`；日期取问题发现/首次登记日，作为开记录快照，之后持续更新不改目录名。同日多条靠问题短名区分。
3. **每条记录结构**：
   - `README.md`——摘要：来源、分析、结论、后续处理、文件索引、运行边界、外部关联
   - `问题来源记录/`——业务反馈、裁决口径、实施授权的来源引用与摘录（只引路径，不复制全文）
   - `分析/`——按生命周期编号（分析 → 处置/执行 → 决策），文件名不带日期
   - `输出/`——**默认不建**，仅在明确要求生成独立报告时创建
4. **稳定 ID**：每条记录挂 `MNT-<项目>-<日期>-<序号>`；外部文档引用记录时优先用 ID 指向该记录 `README.md`。
5. **运行事实边界**：本目录保存依据、清单与验证证据；实际运行事实以正式运行记录为准，不在此伪造执行结果。
