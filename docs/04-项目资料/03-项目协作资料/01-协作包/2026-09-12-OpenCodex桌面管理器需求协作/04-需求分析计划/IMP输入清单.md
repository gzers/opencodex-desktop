# IMP 输入清单

## 1. 目的

- 回答两个问题：**现在能不能建 IMP**、**IMP 必须冻结什么**。
- 本文件是 Gate E（移交门）的产物；创建 IMP 仍需用户确认。

## 2. Gate A ~ E 现状检查

| 门 | 通过条件 | 现状 | 结论 |
|---|---|---|---|
| A 范围门 | P0/P1/P2 与不包含项无冲突；外部 provider、npm、launchd、`codex-shim`、官方 update 边界明确 | DMD revision 3 已回写；OQ-01 至 OQ-09 全部关闭；扩展管理纳入 P1 | **通过** |
| B 交互门 | P0 原型覆盖主要流程与异常状态；不可逆操作有确认、备份与结果反馈 | 原型覆盖六路由；`state-and-flows.md` 已补状态维度与四类补强流程；动作按状态渲染 | **通过** |
| C 安全门 | P1/P2 敏感数据流、加密边界与恢复路径完成安全评审；无明文凭据进入产物 | 四域材料齐备（`安全评审输入.md` §2 ~ §16）；阻塞项 B-1 ~ B-5 已转为已确认需求并回写 DMD（§16.5） | **通过**（实现细节留 IMP；建议项 S-1 ~ S-7 一并处理） |
| D 验收门 | AC-01 至 AC-11 可映射到场景、输入、动作与可观察结果；验收环境与 mock 数据可重复构造 | `场景与验收矩阵.md` 已含逐 AC 四路径、异常矩阵与 mock 数据方案 | **通过** |
| E 移交门 | 未决事项关闭或明确记为阻塞；稳定需求已回写 DMD；IMP 输入至少包含目录布局、状态协议、进程模型、加密格式、同步规则与验收环境 | 本清单补齐 IMP 输入；Gate C 阻塞项需在 IMP 内关闭 | **条件具备，可创建 IMP** |

**结论**：A、B、C、D 已通过；E 的产物已补齐。**具备创建 IMP 的条件**；IMP 仍需把 B-1 ~ B-5 的**实现细节**（锁的粒度与方式、证书校验错误文案、敏感字段清单等）与 S-1 ~ S-7 一并冻结。

### 3.5 加密格式（配置迁移）

| 契约项 | 要求 | 来源 |
|---|---|---|

### 3.6 扩展管理契约

| 契约项 | 要求 | 来源 |
|---|---|---|
| SSOT 与 per-app 启用矩阵 | 统一扩展配置 + 逐客户端投影 | `安全评审输入.md` §15.6 |
| 逐客户端适配器 | 六客户端各自实现导入 / 全量同步 / 单条同步 / 移除 | `安全评审输入.md` §4.2 / §15.2 |
| 写入事务 | 文件锁 + 摘要比对 + 备份 + 临时文件 + 原子替换 + 权限保留 | `安全评审输入.md` §8、§16.2 B-3 |
| 敏感值处理 | `env`、`args`、`headers` 默认掩码，不进日志与错误信息 | `安全评审输入.md` §7、§16.2 B-2 |

### 3.7 WebDAV 同步契约

| 契约项 | 要求 | 来源 |
|---|---|---|
| manifest 协议 | 格式串、协议版本、兼容版本、快照 ID、逐件哈希 | `安全评审输入.md` §12.2 |
| 传输顺序与校验 | 载荷先、manifest 后；逐件校验后才应用 | 同上 |
| 客户端加密与信任模型 | 上传前加密；**远端不可信**，真实性由 AEAD/签名覆盖 | `安全评审输入.md` §16.2 B-4 |
| 冲突与备份 | 冲突先入待处理；覆盖前备份被覆盖侧 | DMD §5 |
| 并发与上限 | 单端点单次同步；manifest 与单件大小上限；解压条目上限 | `安全评审输入.md` §12.2 |
| TLS 行为 | 证书校验失败默认拒绝，不提供忽略选项 | `安全评审输入.md` §16.2 B-5 |

## 5. 创建 IMP 的前提

```text
1. 用户确认本清单与安全评审结论（Gate C 有条件通过的 5 项阻塞）
2. 用户确认创建 IMP
3. IMP 草案需冻结 §3.1 ~ §3.9 全部契约输入，并把 B-1 ~ B-5 作为首个冻结批次
4. IMP 确认后才拆分 TASK，授权实现
```

> 在 IMP 建立并通过确认前，不创建实施 TASK，也不声称需求已完成。
