# 架构与流程图（drawio）

## 定位

本分区把**已定稿的原型与已建立的项目核心事实**转成可编辑的 drawio 图，用于评审、对齐和实施前的整体理解。

- 本分区是**派生产物**，**不是事实源**。
- 事实来源：`docs/02-项目核心/`（产品定义、能力地图、系统架构、数据与状态、集成与安全边界）与 `01-需求分析/05-原型/文档/state-and-flows.md`。
- 稳定结论回写 DMD 或项目核心；实施契约留 IMP 冻结。本分区不引入新需求。

### 核心流程页

| 页 | 流程 | 覆盖要点 |
|---|---|---|
| 01 | 首次发现与前置门禁 | `node → npm → ocx` 短路检查、缺失态引导、发现结果 |
| 02 | 正常启停 | `stopped → starting → pending → running`；失败、停止、重启分支 |
| 03 | 状态采集数据流 | 官方状态源 → 后端映射 → 三维状态 → 前端渲染；持久化与渲染约束 |
| 04 | 受控写入 | 校验 → 备份 → 原子替换 → 重新校验 → 成功 / 回滚（扩展配置） |
| 05 | 数据目录切换 | 检查 → 引用 / 迁移 → 备份 → 停代理 → 迁移 → 校验 → 恢复；失败与取消分支 |
| 06 | Restore 引导 | 风险查看 → 影响摘要 → 备份 → 确认 → 官方 restore 引导 → 结果 → 刷新 |
| 07 | 导入配置 | 口令 / 完整性 / 版本校验 → 备份 → 确认 → 原子写入 → 回滚（含全部异常分支） |
| 08 | WebDAV 同步 | 连接状态链、客户端加密、清单比对、冲突待处理、覆盖前备份 |
| 09 | 应用自身更新 | 检查 → 下载 → 签名校验 → 安装 → 重启接管 → 成功 / 回滚 |
| 10 | 官方升级引导 | 版本偏差 → 升级前备份 → 确认 → 引导官方 `ocx update` → 结果展示 |

## 口径与约束

- **连线规则（强制）**：每条连线**只用一条直线段**——要么水平、要么竖直，**没有折角、没有斜线**；直线段不得**穿过任何节点**。
  为此，端点节点必须共线（水平：同一中心 y；竖直：同一中心 x）。版面按此设计：主链节点共用中心 x，右侧结果框的垂直中心与其触发节点严格对齐；无法直连时**调整版面或改用注释**，而不是画折线。
  改动后用 `python3 工具/check_orthogonal.py` 复核（检查折角、斜线与穿节点；退出码 0 为通过）。

## 视觉规范（对齐本项目设计 token）

取色来源：`01-需求分析/05-原型/文档/design-tokens.md`（官方 GUI token 的对照值），保持与本项目一致的简约中性风格。

- **不使用纯白 `#ffffff` 与纯黑 `#000000`**：画布 `#FBFBFC`；正文 `#262626`；标题与强调 `#0D0D0D`（官方 accent 近黑）；次要文字 `#6E6E6E`；连线 `#8A8A8E`。
- **低饱和分组色**（浅底 + 同色系描边，不用高饱和实色）：

| 语义 | 浅底 | 描边 |
|---|---|---|
| 前端界面层（blue） | `#EDF1FD` | `#B7C6EE` |
| 管理器后端（green） | `#E8F4EF` | `#ABD7C7` |
| 外部依赖（amber） | `#FBF2E8` | `#E8C89E` |
| 数据 / 状态（neutral slate） | `#F1F3F7` | `#C7CDD9` |
| 失败 / 禁止写入（red） | `#FBECEC` | `#E4B1B0` |
| 注释（neutral，虚线） | `#F6F6F7` | `#D9D9DB` |

- **形状与层次**：流程节点圆角 10、状态节点胶囊 24、起止节点近黑胶囊（`#2E2E2E` 底 + `#F4F4F5` 字）；分组容器圆角 3、浅底细边；**一律不使用阴影**。
- **连线**：1.4px `#8A8A8E`，标签带画布底色，避免文字压线。
- 配色语义与界面一致：green = 可用 / 成功，amber = 需注意，red = 失败 / 禁止，neutral = 结构与信息。
- 图上内容与 `docs/02-项目核心` 及 `state-and-flows.md` 保持一致；如两者冲突，以项目核心与 DMD 为准，并回写本分区。
- 架构图只表达**约束与边界**，不表达尚未冻结的实现细节（如具体命令集、字段命名、写入客户端清单）。
- 不引入新需求、不新增真实副作用；本分区不授权实施。
- 应用界面里不出现阶段编号（P0 / P1 / P2）的口径在图上同样适用。
- 「重试 / 回场」这类需要回环的语义（例如启动失败重试、写入失败回滚后重来、安装后手动重新检查）画回环必然产生折角，因此**一律写进该页注释**，不用折线表达。

## 维护约定

- 默认**直接在 draw.io 中编辑 `.drawio`**；编辑后请重新导出 `导出图片/` 下对应 PNG。
- `工具/build_diagrams.py` 仅用于首次生成或整体重排；用它重生成会覆盖手工编辑，需谨慎并同步说明。
- 在 draw.io 中手工加线时请沿用同一规则：一条连线只用一条直线段，不出现折角、斜线或穿越节点；需要折角才能表达的关系改用注释。
- 改完图后先跑 `python3 工具/check_orthogonal.py` 再提交。
- 导出命令：
  ```text
  draw.io --export --format png --scale 2 --output 导出图片/整体架构.png OpenCodex-Desktop-整体架构.drawio
  draw.io --export --format png --scale 2 --page-index N --output 导出图片/流程-NN.png OpenCodex-Desktop-核心流程.drawio
  ```

## 打开方式

用 [draw.io / diagrams.net 桌面版](https://www.drawio.com/) 直接打开 `.drawio` 文件；多页图在左下角切换页面。
