**供 L0 接入的最小变更请求**

1. 新启动入口：OS Profile/LocalAppData 与 TokenUser SID 一次解析后注入；L0 的 data_root/bootstrap/instance/IPC 消费相同身份；Windows adapter 去掉旧 HKCU 选择/安装旁 data 回退，固定用户准入生命周期与活动 D 数据锁分别保留。
2. IPC：以 SID 取代 USERNAME/unknown-user；只允许本 SID 的业务请求，同 SID 跨会话找到同一管理器；DACL、对端 token 核验与“已运行/无权/无法访问”错误由共享实现接入。
3. 安装：L0 单写 WiX/Tauri/资源供应与 NSIS 默认目录接入；若交给 L4，逐个转移模板文件并提供渲染接口。L4 候选写集仍只含已列出的 Windows adapter/hook/独立测试。
4. 程序维护：固定安装身份、owner/scope、package+Node+entry+manifest/hash，安装根级 busy/unknown 协调；普通用户维护权限按真实 I 校验，不能把 runtime 代码的旧“数据根/系统保护路径”校验整体关闭。
5. 测试交接：明确第二账户执行通道、同 SID 第二会话、私有隔离 ACL、MSVC/SDK 来源与新维护运行包 hash；现有两 SID/Profile/会话/权限观察仍有效，未形成产品并行证明。

**验证矩阵增量**

- 默认安装：NSIS/MSI 分别在无旧登记的一次性环境执行，记录真实安装上下文与最终 I；不传 /D 或 INSTALLDIR。另用仅合成旧登记的独立单元验证其不会把新版默认程序来源引回旧安装；不在当前主机删除旧登记。
- 两类更新：记录 Desktop 与 runtime 各自版本/hash，先独立升级 runtime，再升级 Desktop，验证受管入口/包清单及 runtime 字节保留；同时覆盖重装/失败回退及被另一 SID 使用的 busy/unknown。
- 默认根和显式根：真实 token 解析 OS Profile/LocalAppData；用户 U 与程序 I 分离；同 SID 在同/异会话用不同显式 U 尝试启动仍保持单管理器，两个 SID 指定同一活动 U 明确拒绝。
- 凭据/文件：合成秘密 DPAPI 双向归属，隔离测试目录使用可证明的私有 DACL；现有 liangjh23 Profile 授予15119 FullControl、项目目录 Authenticated Users Modify 的 ACL 不得作为隔离通过证据；不改变这些既有目录。
