## 探针修正与复用

首次真实子 Agent 探针没有载入渠道目录，工具未出现，结果为 inconclusive、真实请求为 0，见[首次记录][child-initial]。补入现有目录中该型号的原样元数据后发现它使用 `code_mode_only` 和 multi-agent v1；按该目录启用对应工具模式，再执行真实父子流程通过。没有修改模型元数据或伪造工具支持。默认／显式选择的优先级由独立隔离探针验证，真实父子测试只证明实际创建、发送和完成。

原始结果各自保留：Ultrafast 的 400 是型号不支持；WS 的 426 是现有入口关闭；缺目录是测试前提遗漏。这三项不能合并为普通网络故障，也没有为通过测试开启日常服务功能。

程序位于实现工作树 `ocx-0110-main` 的 `test/architecture-probes/`，分支 `codex/worktree-probes-20261028`；文档工作树只保存结果和说明。复用 `probe_protocol_schema.py`、`probe_owner_connection.py`、`probe_native_children.py`、`probe_opencodex_service.py`、`probe_real_route.py`；新增 `probe_krill_feature_round.py` 与 `probe_krill_native_child.py`。每份结果记录已运行脚本的 SHA-256；新增脚本本轮未提交。

本轮 12 次真实请求报告的用量合计为 **86,572 输入 token、321 输出 token**；包含缓存输入，不能换算成实际账单金额。每次请求设置 512 或 768 输出上限，推理均为 low。真实调用复用本机代理认证，探针未保存、展示或发送 API Key；没有改写日常配置、重启日常服务或当前 App。OpenCodex 配置、Codex 配置以及用于复验的模型目录摘要前后一致，见[汇总][summary]。
