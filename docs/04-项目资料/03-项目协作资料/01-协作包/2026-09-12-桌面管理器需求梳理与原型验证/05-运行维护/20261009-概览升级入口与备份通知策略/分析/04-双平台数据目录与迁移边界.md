# 双平台数据目录与迁移边界

关联 MNT-OPENCODEX-DESKTOP-20261009-01；2026-10-10。用户确认 Windows 默认数据位置以**实际软件安装目录**派生，不固定盘符；macOS 保持用户 Application Support。纳入 0.1.10；feature/0.1.10-maintenance 已提交启动活动根解析及 Windows 新默认源码，迁移、停写和安装权限方案尚待验收。不在本轮提前提升为核心事实文档。

## 目标位置与自定义规则

“数据根”即管理器组织配置、备份、托管安装和运行记录的顶层目录；产品界面称“数据目录”。以下为目标规则，不是本机已迁移路径。

| 对象 | Windows 默认 | macOS 默认 | 自定义与边界 |
|---|---|---|---|
| 程序 | 实际安装目录（用户安装时选择） | /Applications/OpenCodex Desktop.app 或实际应用位置 | 程序位置与数据位置分别登记 |
| 数据目录 | <实际安装目录>\data | ~/Library/Application Support/com.gzers.opencodex.desktop | 允许自定义；已有选择优先，升级不得重置 |
| 管理器配置与记录 | <数据目录>\manager-state | <数据目录>/manager-state | 偏好、扩展、同步连接配置、运行来源等；不等于全部官方配置 |
| 备份 | <数据目录>\backups | <数据目录>/backups | 默认跟随数据目录；独立备份位置是后续候选，未定稿，不提供已可用承诺 |
| 托管 OpenCodex 包体与面板 | <数据目录>\runtime\opencodex | <数据目录>/runtime/opencodex | 保留已登记的自定义私有前缀；外部安装单独管理 |
| 托管入口 | <数据目录>\runtime\bin\ocx.cmd | <数据目录>/runtime/bin/ocx | 非系统全局命令；变更后核验入口、包名与版本 |
| 官方配置与运行数据 HOME | <数据目录>\opencodex-home | <数据目录>/opencodex-home | 保留外置 OPENCODEX_HOME；不能随默认根变更而隐式重置 |
| 日志、缓存、导出与同步摘要 | <数据目录>\logs、cache、exports、sync-state | <数据目录>/logs、cache、exports、sync-state | 导出格式由导出流程决定；不承诺所有导出均加密 |
| 管理器托管凭据 | Windows 凭据管理器 | macOS 钥匙串 | 不作为普通目录文件迁移或偏好备份；官方配置内的敏感数据另按官方边界处理 |

上述目录不涵盖系统 WebView 缓存、操作系统安装信息以及用户外部安装的全部文件。原生 Codex 的 ~/.codex/config.toml 不属于管理器迁移范围。分区存在不代表本期自动备份全部分区。

备份范围保持独立约束：当前升级备份是 manager-state/preferences.json 的偏好快照，加清单与完整性摘要，不含官方完整配置、账户、会话、登录态、Skills / MCP 内容或运行时包体。现有备份层级为 backups/<YYYY>/<MM>/<action>/<bk_ID>。迁移保护快照的覆盖范围须另列清单，不能直接用偏好备份承担全部目录回滚。

## 当前代码事实与差距

备份内部文件、其他事务范围与后续增补要求见 [备份目录树与范围登记](05-备份目录树与范围登记.md)。数据目录分区表说明文件在哪里，备份树说明一次备份实际保存什么，两者不可互相推定覆盖范围。

以下为历史只读基线 main@de6862d4（0.1.9）的问题来源，不描述当前特性分支现状；源码不复制到文档分支：

- apps/desktop/tauri/src/lib.rs 使用 app.path().app_data_dir()；Windows 当前为 %APPDATA%\com.gzers.opencodex.desktop，macOS 为上述 Application Support。Windows 安装目录内 data 是新目标，尚非现状。
- SharedDataRoot 与运行句柄在启动时按默认数据根初始化；偏好、备份和运行命令仍通过它取路径。因此不能把“目录引用修改成功”等同全部存储已切换。
- modules/data_root/mod.rs::switch_reference 当前拒绝 MigrateData；ReferenceOnly 写活动根引用但没有完成所有存储重绑定，且会将 HOME 重置为根内模式。本期需改造这些差距并验证持久化与重启后的回读。
- modules/runtime/paths.rs::is_system_protected 当前拒绝 Program Files、Program Files (x86)、ProgramData、系统目录与驱动器根等托管安装目标。新的“随实际安装路径”规则遇到受保护位置，与现有校验冲突；实施不能只改一处默认字符串或删除校验。
- commands/upgrade.rs::create_upgrade_backup_with_root 仅覆盖管理器偏好；infrastructure/keychain.rs 使用系统 keyring。扩展与同步连接等文件是否纳入某种备份需按事务核定，不能根据目录表推定已覆盖。

## Windows 权限与旧版本兼容

1. 首次安装从实际安装记录解析安装目录，派生 data；不依赖固定盘符、当前工作目录或临时更新进程的位置。已有活动根、自定义前缀、外置 HOME 优先保留。
2. 对普通用户执行可写、空间、所有权及路径安全检查。Program Files 场景必须明确受支持的方案；不能默认要求日常管理员运行，也不授予整个程序目录宽泛写权限。
3. 无法写入时显示具体失败与可写目录选择，让用户确认；不得静默退回 C 盘 AppData 或声称已采用安装目录。受保护位置的产品处理与安装器权限实现是未关闭门禁。
4. 从 0.1.9 的 AppData 转入新位置须显式选择，仅升级程序不自动迁走旧数据。真实迁移单独确认；普通 / 管理员应看到一致的活动路径与归属，不因权限身份建立第二套数据。

## 修改、迁移、升级与卸载

修改数据目录：选择目标 → 停止相关代理 / 写任务 → 校验目标与冲突 → 明确“仅切换引用”或“迁移数据” → 保护旧数据 → 复制并校验 → 原子切换引用和全部使用方 → 重启核验。任一步失败保留旧数据与可用引用；成功不自动删除旧目录。外置 HOME、自定义托管前缀不能隐式搬走，须单独列明保留或迁移选择。根内 HOME 是正常派生关系；只有外置目标的危险交叉嵌套才需拒绝，不能笼统禁止所有嵌套。

“仅切换引用”不复制旧数据，但必须让所有后端使用方一致绑定目标，说明目标为空或已有数据的后果，不用半切换状态对外宣告成功。打开 / 复制须使用活动根的真实解析路径；保存位置、安装前缀、运行入口、备份、日志及概览读取同一事实源。

更新：保留安装目录内 data、自定义数据目录与备份，不以安装器目录清理覆盖数据；程序改安装位置时，不自动移动已有活动根。Windows 更新重启前后、macOS 应用替换后均核对目录与数据完整性。

卸载：分别列明程序、管理器托管包体、配置 / HOME、备份和托管凭据的处理，默认保留配置与备份；删除数据额外确认并核验归属。保留安装目录下 data 时，不得由卸载器递归删除安装目录将其带走。外置与其他工具的文件不随程序卸载清除。原有面板卸载流程不等于管理器卸载已实现这一规则。

## 原型与验收

共用原型设置的“安装与数据”展示当前目录、分区与修改预览；备份页显示对应 backups 位置。右侧 0.1.10 目录规则入口可切 macOS / Windows、默认 / 已自定义 / 受保护安装目录，盘符只是 fixture。进入 Windows 外观专题同步切目录平台；独立目录测试不替代 Windows 外观验收。原型只变内存，不选真实目录、不检测权限、不迁移、不写盘。

实施门禁：覆盖普通 / 管理员、不同盘符与含空格 / 中文安装目录、受保护目录与可写目录、旧 AppData 保留和显式迁移、已有自定义根 / 前缀 / 外置 HOME、目标冲突 / 空间不足 / 复制失败 / 中断恢复、重启全部路径一致、升级不覆盖 data、卸载保留 / 明确删除。备份完整性、失败回滚、凭据归属和所有存储重绑定需要真实设备证据。目录设计增加到 0.1.10，0.2.0 文件 / WebDAV 同步的实现范围不因此进入本次版本。

### 2026-10-10 未决安装关联与目录互锁

5401dd5c 新增活动根 manager-state/runtime-protection.json，macOS 仍随 Application Support / 自定义活动根，Windows 随实际安装目录 data / 已选活动根。它是精确安装关联状态，不是可清理缓存，也不写进偏好备份 payload。使用版本化严格字段与有界读取，拒绝链接；不重新执行所记录的包。

关联未决（含损坏 / 不确定）时，在共享偏好事务锁内拒绝 reference-only；复制内核在预留目标前拒绝迁移，源与目标不变化。先完成受控核验，再允许改活动根，不能复制绝对安装关联后推定保护已完成。启动、安装 / 卸载前可本地重试；当前没有损坏关联的修复 / 放弃入口，仍是未关闭门禁。定向与全量源码证据见 [验证记录](../验证/20261010-面板保护持久核验/README.md)，不推定双平台原生已验收。
