## 输入与信任边界

I 是当前实际程序根，D 是当前 Desktop 数据根；二者按既有路径策略完全分离。调用方负责应用写入准入、运行操作租约及真实生命周期/配置保护；候选 CurrentSelection 必须来自固定资源或已验证安装器。program_selection::read_image 复用既有版本、包身份、关键文件和入口校验，不执行程序、不扫描其它版本，也不定义新的上游签名或完整依赖树信任政策。

Mutation::acquire(I) 取得 I 下的程序操作锁，普通只读消费者不取得它。首次供应在完整固定资源校验并创建新镜像目录之后提交选择；旧/候选镜像目录均不被激活或恢复过程删除。没有 current 的状态不等于允许接管一个已存在但无身份的稳定入口。

## 事务与 API

| 接口 | 行为 |
| --- | --- |
| activate(D, expected, after, admit) | 供应器内部入口；核对当前版本、候选、当前 D 的来源镜像，再开始事务；明确准入失败时不创建 pending |
| pending_summary(D) | 返回已完整核对的本事务 ID、原/目标版本；不是可接受结果或替代停止证明 |
| recover(D, attempt_id, Complete/Rollback, admit) | 用户明确决定由未来产品命令传入；只操作原事务绑定的元数据，不猜根、不接新来源、不隐式重启服务 |

I/runtime/.selection-pending.json 采用严格 schemaVersion 2，保存校验摘要、随机事务 ID、当前 D、原/目标 CurrentSelection，以及稳定入口、current.json、D/manager-state/runtime.json 的实际原字节和预定后像。所有文件有界读取、拒绝重定向/共享链接。其它格式不被猜测升级。来源记录保留未知字段；回退恢复原字节，不能把重新序列化的默认对象当原件。

步骤为 pending 持久化 → 稳定入口 → current → D 来源记录 → 所有目标及所选程序读回 → 保存终态回执 → 清 pending。中断或未知读回保留 pending，普通 program_selection::read 继续拒绝它，不在启动时自动恢复，也不回退扫描其它版本。

恢复前先核对本事务属于实际 D，随后才在该 D 建立来源锁。每个目标的当前内容必须等于原件或本事务后像，三个目标在首个恢复写入前整体检查，操作中及最终再次复核。外部改动、另一用户 D、错误事务 ID、修改的镜像或异常记录一律保留原件和事务；没有“把未知当原件”的分支。

终态回执位于 D/manager-state/runtime-activations/<attempt>-complete|rollback.json，保存原事务和决定。它是事务证据，不是版本发布证书。回退首次选择时可恢复为无 current/入口/来源记录，仍保留已核验镜像；后续采用保留镜像必须有显式、已准入来源，不让普通启动猜测接管。
