## 3. 待用户裁决（集中提出）

> 以下为实质产品/安全选择，影响 0.1.2 是否包含 U-01～U-04。未决期间先推进 §2。

- **D-1 桌面自更新端点与公钥来源**：
  - A（推荐）：端点指向本仓库 GitHub Releases（`latest.json` / `.sig` 作为 Release 资产）；公钥由维护者用 `tauri signer generate` 生成，私钥进 CI secrets，公钥作为编译期常量写入 `tauri.conf.json`。
  - B：维护者自有更新托管地址与公钥，稍后提供具体值。
  - C：本版不接通真实自更新，只做通道策略收敛与占位替换为可配置结构（范围退化为 §2）。
- **D-2 自更新签名的私钥与发布流程授权**：是否允许在 CI 使用 `TAURI_SIGNING_PRIVATE_KEY` 产出签名制品；公开发布仍另行确认。
- **D-3 官方版本卡片语义**：是否新增只读远端查询（`npm view @bitkyc08/opencodex@latest version` + `dist.integrity`），或仅把按钮文案改为「重新读取本地版本」。
- **D-4 外部安装官方更新**：是否授权桌面管理器复用 `install_runtime` 代跑官方更新（写流程），或仅保留只读查询与引导。

## 4. 验收标准（0.1.2）

1. 前后端门禁全绿：`vue-tsc`、`vitest`、`vite build`、`cargo fmt`、`cargo clippy -D warnings`、`cargo test --workspace --features integration-test`。
2. 配置有效行为：读取即校验；非法/过新/损坏不覆盖原件；当前 schema 启动不重复写盘、mtime 不变、无新备份；legacy v0 迁移保留用户选择。
3. 更新通道：所选通道驱动真实检查与安装；检查/安装/调度共用同一策略；切换通道作废旧候选。
4. 沙箱隔离：开发/测试身份与日常使用身份分离；受控模拟日常根的哨兵文件在全部配置测试后内容与 mtime 不变。
5. 制品与安装：macOS（aarch64）与 Windows 构建通过；隔离 HOME 冒烟启动，`startup version=0.1.2`；本机安装验证日常配置未被测试改写。
6. 文档：根 `README.md` / `README.en.md` 与实际配置行为一致且两分支副本一致；`CHANGELOG.md`（main）有且只有一个 `[0.1.2]` 段落。
7. 结果回写 `docs/03-开发实施/` 的 `IMP-*` / `REL-*` / `RUN-*`；不把规划或构建成功写成运行验收通过。
