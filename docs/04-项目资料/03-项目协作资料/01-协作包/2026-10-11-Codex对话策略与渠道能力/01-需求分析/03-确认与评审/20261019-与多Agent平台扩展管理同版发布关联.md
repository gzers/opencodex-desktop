## 用户输入

用户在配置写入风险记录后补充：

本记录将当前渠道特殊能力及相邻 Codex 配置管理讨论，与[多 Agent 平台扩展管理](../../../2026-10-14-多Agent平台扩展管理/README.md)建立同版候选关联。它不将全部 Superba 配置候选自动转为交付范围，也不并入已有模型配置管理 0.2.0。

## 版本关系与职责

| 协作包 | 继续承接的职责 | 版本关系 |

两个包继续独立维护需求、原型、实现与验收依据，版本规划应联合考虑。共用底座与联合验证不代表将两包合并，也不代表一包完成可以替另一包验收。

## 后续需要一起考虑的事项

| 事项 | 统筹建议 |
|---|---|
| 配置文件与字段归属 | Codex 的 MCP 节点可能与渠道 / 功能设置同处一个配置文件。先列出两包的实际读写落点、字段及权威写入者；扩展操作不得覆盖渠道设置，渠道操作也不得重建或丢弃 MCP 节点 |
| 并发写入与版本基准 | 评估复用同一文件身份、锁与写前摘要校验，避免两个模块各自持有旧快照后覆盖对方；共享协调方案尚未实现或验收 |
| 隔离与独立恢复 | 共同引用[配置写入风险与独立恢复前提](20261019-配置写入风险与独立恢复前提.md)，将独立于 Codex 的恢复和真实隔离纳入共同版本的准备工作。恢复任一模块的变更时，应保留另一模块随后合法保存的内容，明确整批恢复与字段恢复的边界 |
| 凭据与运行边界 | 认证或启动环境的特殊适配由其所属模块处理，不因共享备份底座而让扩展模块接管认证；保持外部管理层和不修改 OpenCodex 的既有边界 |
| 生效与重启 | 区分文件已保存、待重启、待核验和可确认的实际生效；同一次组合应用明确配置批次与状态，不假设所有平台或字段具有相同热更新行为 |
| 导入、同步与恢复 | 按最终确认范围检查格式兼容、未知字段保留及模块归属，组合导入和恢复不得用一包的旧快照抹去另一包的新设置 |
| 联合回归 | 在各包验收之外，补扩展先写 / 渠道后写、反向顺序、并发冲突、部分失败、重启和独立恢复等组合；当前均待执行 |
| 最终发布范围 | 冻结版本时统一核对两包的就绪程度、共同底座与遗留风险；如需调整同版安排，记录最终决定和影响，不静默将候选改写为已定发布承诺 |

共用恢复、写入或同步机制只复用经过确认的职责和接口，具体实现依赖应以实际代码核验为准，本记录不据此新增通用引擎或重复管理入口。
