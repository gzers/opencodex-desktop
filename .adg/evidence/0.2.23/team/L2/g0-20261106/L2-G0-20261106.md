## 2. 建议冻结的协议原则

1. 全部配置同步入口均不以 ETag、mtime、大小、文件名或设备时钟替代内容校验；新格式不读写旧 latest 域，不做旧格式迁移或混合同步。
2. 一个操作持久冻结一个 UUID 和精确字节；载荷和提交均使用独立文件，发布过程中不覆盖单一 latest。发现多个提交头时保留全部文件，显式处理冲突，不按时间或 UUID 排序选赢家。
3. 远端业务视图来自有效提交图。载荷存在但无提交是孤立材料，不是有效版本；提交缺父/缺载荷/摘要不符是未知或损坏，不是空目录。
4. 同一操作只读核对与允许新写入的检查分开。原操作是否存储、本机是否后来改变、当前观察是否存在后继/并发分别记录。
5. 协议保证面向遵守唯一 UUID、冻结字节和不修改已发布文件的新版写者。它不提供服务器原子 CAS、全设备实时一致性或对非遵约外部覆盖者的不可变存储保证。

## 3. 正式文件候选与版本边界

建议在用户指定且已存在的远端集合中使用扁平布局，避免为正常上传引入 MKCOL/DELETE：

| 文件 | 核心字段及用途 |
| --- | --- |
| `config-v2-generation-<G>.json` | `format=OCXD_CONFIG_GENERATION`、`formatVersion=1`、`generationId=G`。初始化唯一生成；不可变。 |
| `config-v2-data-<G>-<O>.ocxdconf` | 本操作冻结后的完整文档字节，可明文或沿现有保护格式加密；摘要针对实际传输字节。 |
| `config-v2-commit-<G>-<O>.json` | `format=OCXD_CONFIG_COMMIT`、`formatVersion=1`、`generationId`、`operationId`、`parents[]`、`payloadDigest`、`payloadBytes`、`payloadSchema`、`intent`。最后写入。 |

G/O 均为独立 UUID。每个父引用包含 `operationId` 与对应提交原始字节的 SHA256；父集合排序去重，仅引用同 G 的有效提交。`intent` 候选为 `update` 或 `resolve`；resolve 额外携带用户选择的头及范围摘要，不携秘密或本机路径。文件相对路径由校验后的 G/O 派生，不接受远端 JSON 提供任意 URL。提交摘要基于第一次冻结且持久保存的精确字节，重试不重新序列化或重新加密。

文件前缀的 v2 与元数据 formatVersion=1 是不同层：前者区隔现行 config-v1 域，后者是新提交协议首版。便携文档/模型载荷版本由 L1/L0 冻结；现行便携外壳 formatVersion=3 不能被默认为已支持新模型 Schema。新增格式不静默丢弃字段、不降级为旧载荷。

远端提交的载荷是按现有选定范围更新后的完整云端文档：保留基线中未选对象，不传播整对象删除；完整文档由现有共享导出/合并服务和 L1 编码器产生。L2 不实现第二个模版匹配器或模型解析器。

## 4. 初始化、代次与明确恢复动作

初始化仅在显式初始化动作中发生。普通预览、连接测试、核对原操作和读取回执均不得创建代次。只有成功完成列举、确认不存在旧域/未知业务文件且不存在有效新代次，才可进入空目录初始化；403/404 根目录不存在、解析失败、列举不完整不能当空。集合自身条目排除后才判断空。

初始化生成新的 G，持久化原初始化 ID/字节，写独立代次文件并直接 GET 核对，再列举。观察到多个代次、代次内容与文件名不符或已知代次消失时，停止普通上传/下载应用，持久保留分支与操作材料。不得删掉另一个代次、以先后时间或名称排序选胜者。

**初始化歧义的首版恢复建议：保留有歧义的原目录，只读列出各代次/提交并允许选择、下载或导出恢复内容；在明确选择的另一个已核实为空的远端目录重新初始化，再按同一预览上传选定恢复内容。** 其它设备在成功读取新目录唯一代次后加入；无自动清空、无自动搬迁。新目录由用户/既有服务准备；若要应用内创建目录，须由 L0 另行冻结 MKCOL 能力及写集，不能由 L2 暗加。

此为具体可恢复的首版候选，需 L0/L3采用相应状态和动作；不是已经确定的产品取舍。若要求原目录内保留全部代次并恢复，需另冻结不可变“初始化决议图”及其并发决议、迟到提案和种子快照规则，不能用一个可覆盖的 active-generation 文件代替。

每份计划绑定规范化端点/目录身份、配置修订、凭据引用身份、G 及代次文件摘要。普通执行每次远端写前、写后及下载应用前重验；观察到代次改变或消失即拒绝旧计划，且旧计划不能自行重建代次。新 G 中的读者从不把旧 G 的迟到文件当成有效提交。

必须写清的限制：没有服务器原子互斥时，两个一致的空列举不证明不存在迟到初始化；先前未见歧义时两个设备可能各自写入 G，之后发现歧义再停止，内容仍保留。清空恰好发生在代次检查与 PUT 之间也无法保证绝对零远端字节写入；协议可保证拒绝已观察到失效的旧计划、旧代迟到内容不进入新代视图。若验收要求任意交错下清空后绝对零写入，必须增加服务器可验证的原子能力；不能用重读次数冒充这一保证。实际清空仍须所有写入设备停写，本回交不执行。

## 5. 提交图、并发与冲突选择

读取全部受限文件名，通过精确 GET 校验提交及父引用；缺父时按引用直接 GET 补齐，不因一次列举漏项当作根提交。拒绝环、重复 ID 不同内容、跨代父和不支持版本。有效头为有效提交中没有被其它有效提交引用为祖先的节点。

- 空代次无有效提交：可首次上传。若只有载荷则显示孤立材料，不宣称它是已同步配置；有损坏提交时阻断，不以“零有效头”当空。
- 唯一有效头：普通上传冻结它为父；真正写前发现父集合变化，保留计划并重新预览，不自动更新父。
- 同父并发 A/B：两者的独立载荷/提交都保留；列举最终能看到两者后头集合为 `{A,B}`。任一操作可以已存储，但当前关系为冲突。
- resolve：显式展示所有已观察冲突头的影响，在确认选择后生成新 O，parents 引用所有已确认冲突头。可采用某头完整快照，或经既有对象级服务形成明确合并；范围外影响必须展示，不静默丢弃另一分支。原头文件保留。
- 决议同时发生：得到两个新的 resolve 头，继续显式冲突；决议期间出现未见 C，则 C 与新决议继续构成多头，不能声称永久解决。

列举两轮相同仅形成“本次观察稳定”的视图摘要。维护当前绑定内的已见引用集合，暂时漏列不使已见提交消失；已知文件 GET404 仍是未知/损坏，不能回退为空。无全局可见性证明时，UI 只能表述本次核对事实。长期不会被列举或引用发现的提交无法由此协议探测；服务器最终完整可列举是必要能力前提。

## 6. 上传、下载和原操作核对

上传先落盘操作日记及冻结载荷，再检查本机已保存来源、范围/MCP来源选择、端点、代次和父集合。首次发送前这些基准改变，拒绝新写入并重新预览。顺序为：载荷 PUT → 精确 GET 校验摘要/长度 → 再验 G → 提交 PUT → 精确 GET 校验提交和载荷 → 重读图得出当前关系。2xx 不直接等于存储确认，未收到响应也不直接等于失败。

每次发送前先持久记录“可能已发送”。载荷/提交曾发送后发生超时、重启或取消，只读核对同 G/O，不生成新 O；重试写入必须走单独动作，在读回原精确字节后判断，且重新满足普通写入准入。同 ID 读到不同内容直接报身份冲突，禁止覆盖。GET404 可能是延迟可见，不能据一次404认定未发送；同 ID 重传只允许持久原字节且符合恢复合同。

首次未发出网络写入前取消可取消计划；已进入可能写入阶段只能停止后续动作并保留待核对事实，不能声称远端已撤回。孤立载荷不自动删除。

下载冻结 G、唯一头/已明确选择的头、提交摘要及载荷字节；校验后重新观察图，再沿当前确认/备份/来源摘要保护写本机。头或本机目标摘要改变时返回基准变化并保留预览，不套用过期计划。未选对象、凭据和未保存编辑的保护继续走现有服务，取消不写业务对象。晚到头可在完成后的下一次观察形成待同步或冲突，不把有限核对说成全局原子下载。

“核对原上传”只验证原端点身份、G/O/冻结摘要和远端原文件，不读取或重建当前来源包、当前范围、当前编辑及当前MCP来源，也不发 PUT。当前连接换到另一个端点时不能拿新端点核对旧 O；只允许用户明确回到原绑定或通过 L0 的受控原连接解析能力读取。凭据失效返回认证错误，不修改绑定。

原提交及载荷吻合：标记 stored，即使当前图已有后继或本机已修改。原载荷吻合但无可确认提交：保持 unknown/orphan；不能标发布完成。当前代次已换时可保留历史已确认的存储事实，但不能据残留旧文件声称当前代仍成功。当前关系比较另外读取已保存来源事实，失败或当前范围不同则关系 unknown/local_changed，不阻断原文件只读核对。

## 7. 持久状态、错误及界面事实

建议用正交字段，避免一个 success 同时代表三个不同结论：

| 字段 | 候选值 / 语义 |
| --- | --- |
| phase | prepared、payload_may_be_written、commit_may_be_written、settled、cancelled_before_write |
| storageStatus | not_attempted、unknown、stored、invalid；stored 只由原提交及载荷直接核验得到 |
| relation | unknown、observed_equal、local_changed、remote_descendant、remote_conflict、generation_changed |
| failure | 稳定 code、step、可选 HTTP 状态、脱敏 cause、可执行 recoveryActions；不只存 message |
| observation | G、已见头引用/摘要、viewDigest、observedAt、范围摘要；时间是核对时刻，不是业务保存时间 |

日记保存原 O、冻结包/提交摘要和位置、父集合、端点绑定、保护方式、重试/备份意图及上次证据；原子写，复用 L0 路径与锁。保护口令/连接密码通过系统凭据引用获取，不进日记或回执；保护格式启用时重试复用已冻结的密文字节。敏感明文冻结材料沿当前受保护本机落盘边界处理，不写聊天、日志或仓库。

状态或原计划读取损坏返回明确错误，不沿用 `read_state(...).ok()` 将错误变成无状态；无需为读回执联网。进程重启恢复到待核对原 O，不能自动重新上传。回执和通知引用同一事实，核对后修正状态时保留首次失败原因；已存储但同步状态落盘失败不回退远端或重传。

稳定错误候选：`sync_generation_ambiguous`、`sync_generation_changed`、`sync_listing_incomplete`、`sync_remote_invalid`、`sync_remote_conflict`、`sync_operation_unknown`、`sync_operation_collision`、`sync_source_changed`、`sync_scope_changed`、`sync_payload_schema_unsupported`、`sync_limit`；认证/网络/容量原因保留独立 cause，不都包成 publication_unconfirmed，更不归因本机目录权限。

同名 MCP 的多客户端不同定义不是提交图冲突：本机 mcpSources 仍须由用户明确选来源，并冻结对应客户端/定义摘要；上传不能随意挑一个定义。传输保全不能宣称这类来源歧义已自动解决。

## 8. 容量、列举与保护合同候选

当前便携文件上限64MiB、解包文档32MiB；底层旧同步有256MiB载荷/16MiB清单上限，不能拿较大值覆盖配置文件格式的较小上限。建议新管道统一沿64MiB文件/32MiB文档；提交/代次元数据各64KiB；每代最多4096提交、64冲突头、单次列举最多10000条且XML最多16MiB，支持按文件摘要缓存、按引用补读和有界遍历。上述新增数字是待总控冻结的预算，非已有通过证据。

超限、507或列举部分失败时明确停止，保留所有现有提交；不截断成唯一头，不自动GC/清空。达到预算后通过显式保护/归档与新目录初始化流程处理，不在本版暗加远端删除器。正常核对不自动下载所有历史大载荷；先验提交图，只对当前选用/原操作载荷直接读回校验，历史损坏一旦被发现需保留诊断。

Depth1解析必须限制href为同源、同配置集合、规范化后的直接子项；拒绝外域、跨目录、编码斜杠/穿越、重复身份及部分失败，忽略集合自身；禁实体/DTD扩展。TLS校验/禁重定向/认证边界沿当前客户端。缓存控制可请求重新验证，不能假称它强制远端无缓存。ETag可作为非权威诊断字段，但无值、弱值、变化均不阻断。
