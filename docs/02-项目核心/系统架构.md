# 系统架构

## 技术栈与平台

| 项 | 取值 |
|---|---|
| 桌面壳 | Tauri v2 |
| 后端 | Rust |
| 前端 | Web 前端（渲染在 Tauri WebView 内） |
| 平台 | 第一阶段以 **macOS** 优先；跨平台能力在实现层预留抽象，不作为首期验收范围 |

## 分层

```text
┌─────────────────────────────────────────────┐
│ 前端界面层                                    │
│ 概览 / 面板 / 拓展 / 日志与诊断 / 设置 / 托盘   │
└──────────────────┬──────────────────────────┘
                   │ 命令调用（Tauri IPC）
┌──────────────────▼──────────────────────────┐
│ 管理器后端（Rust）                             │
│ 发现 · 进程托管 · 状态 · 日志 · 迁移 · 同步     │
│ 扩展管理 · 更新 · 数据根 · CLI/IPC · 通知       │
└──────────────────┬──────────────────────────┘
                   │ 子进程 / 文件 / 网络
┌──────────────────▼──────────────────────────┐
│ 外部依赖                                      │
│ ocx CLI · 官方 Web 面板 · 各客户端配置文件      │
│ WebDAV 远端 · 应用自身更新通道                 │
└─────────────────────────────────────────────┘
```

## 组成部件

| 部件 | 职责 |
|---|---|
| 桌面壳窗口 | 承载界面、标题栏、侧栏与全幅面板视图；约束在 macOS 应用窗口尺寸内 |
| 管理器后端 | 全部业务逻辑与外部交互；前端不直接访问文件系统与网络 |
| 托管子进程 | 由后端启动并持有的官方 `ocx` 进程 |
| 本机 IPC 端点 | 可选 CLI 控制面与运行中实例之间的通道 |
| 数据根 | 管理器自有产物的统一落点（见 `数据与状态.md`） |
| 官方 Web 面板视图 | 以源码级快照承载官方 GUI，不重绘、不注入 |

## 模块划分

模块与能力域一一对应，便于从能力追溯实现：

| 模块 | 对应能力 |
|---|---|
| 发现模块 | 安装发现：路径、版本、可执行校验、前置条件门禁 |
| 进程托管模块 | 启停子进程的调用、超时、退出码与错误摘要 |
| 状态模块 | 官方状态命令的采集、映射与三维状态维护 |
| 日志与诊断模块 | 日志读取、脱敏、日志目录打开、Doctor 只读摘要 |
| 面板模块 | 官方 Web 面板快照的承载与失败回退 |
| 数据根模块 | 数据根的选择、检查、引用或迁移、备份 |
| 迁移模块 | 加密容器的导出、校验、导入与回滚 |
| 同步模块 | WebDAV 的加密、清单、冲突与覆盖前备份 |
| 扩展管理模块 | Skills 与 MCP 的读取、投影与受控写入 |
| 更新模块 | 官方升级引导与应用自更新（两条独立通道） |
| 通知模块 | 通知的产生、存储、聚合与清理 |
| CLI / IPC 模块 | 命令解析、本机 IPC 委托、机读输出与访问控制 |
| 托盘与菜单模块 | 托盘菜单与原生菜单入口 |

## 运行时与进程模型

1. **管理器进程**：即桌面应用本体；持有界面、后端逻辑与托管子进程。
2. **托管子进程**：官方 `ocx start / stop / restart` 由其直接启动与持有；进程标识与退出码进入状态展示。
3. **CLI 客户端**：`ocxd` 不独立执行能力，而是连接运行中实例的**本机 IPC 端点**委托执行；实例未运行时不得绕过实例直接改状态。
4. **重启语义**：应用自更新会重启应用本体，但**不停止**托管中的 OpenCodex 代理；重启后重新接管并恢复状态展示。
5. **离线语义**：代理离线时，依赖实时能力的功能（如实时日志）明确标注不可用，本地历史日志与日志目录仍可用。

## 主要数据流

### 状态采集

```text
托管子进程 / 官方状态命令
→ 后端采集与字段映射
→ 三维状态（运行 / 连接 / 操作）
→ 前端按状态渲染动作与说明
```

### 受控写入

```text
用户动作（扩展管理 / 迁移 / 同步）
→ 前置校验（目标合法性、冲突比对）
→ 备份
→ 临时区写入 + 原子替换
→ 重新校验
→ 成功 / 回滚
```

## 架构级约束

| 约束 | 含义 |
|---|---|
| 单一真相源 + 投影 | 管理器维护统一事实，客户端配置是投影，不是权威 |
| 只改目标节点 | 结构化读改写，保留未知字段与注释；不整文件重建 |
| 原子写 | 同目录临时文件 + 原子替换；替换后保留原文件权限 |
| 备份先行 | 任何可能覆盖数据的写入前必须生成可恢复备份 |
| 跨进程互斥 | 与官方 CLI、编辑器共享同一批配置文件，写入需跨进程文件锁与内容摘要比对 |
| 凭据不出域 | 凭据不进日志、命令行参数、错误信息与未加密文件 |
| 后端独占外部访问 | 前端不直接触碰文件系统与网络 |

## 外部依赖

| 依赖 | 用途 | 关系的权威归属 |
|---|---|---|
| 官方 `ocx` CLI | 启停、状态、诊断、升级 | 官方；本产品只调用与引导 |
| 官方 Web 面板 | 面向用户的官方界面 | 官方；本产品只承载视图 |
| 各客户端配置文件 | MCP 与 Skills 落点 | 共享节点；本产品受控写入扩展配置 |
| WebDAV 远端 | 跨机同步目标 | 用户指定的端点，视为不可信 |
| 应用自身更新通道 | 桌面应用升级 | 本产品自有 |
