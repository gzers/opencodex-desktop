## 1. 推荐的简单操作逻辑

2026-10-04 用户“3. 同意”按前序第三项版本 / 恢复问题记录为局部同意：采用 **模板多版本 + 单份当前渠道策略 + 自动应用快照** 的方向。具体 metadata 和同步交互仍待实施契约冻结；历史保留及下拉规则已于2026-10-14确认，见文末补充。用户平时只面对两个 Tab 和一个草稿工作区，历史在需要比较或恢复时展开；不要求为每个渠道命名、保存和切换一组完整策略版本。沿用已有模板 `id + revision`，不建立第二套模板版本身份。

| 对象 | 日常操作 | 反悔方式 |
|---|---|---|
| 模型模版 | 新建 / 自动生成模版 → 查看候选及对话纠偏 → 保存模版 → 设为主版本或采用到指定渠道 | 候选可删除；旧版可查看、比较、重新采用；依赖中的版本先归档 |
| 渠道模型 | 在一个草稿里勾选白名单、排序、调整上下文 / 模态 / 推理 / Fast、引用确定版本 → 点击保存、确认差异并写入 → 重启核对 | 编辑中撤销 / 重做；未提交可丢弃草稿；已写入通过应用记录转草稿恢复 |
| 导入导出 / WebDAV | 跨机器携带两个配置文件及精确依赖，输入先成为待审候选 | 本机应用记录用于日常恢复，文件导入不承担唯一撤回入口 |

模板候选、主版本指针和版本正文属于 `model-family-templates.json`；当前渠道的精确模板引用、白名单、顺序和覆盖属于 `model-policy.json`。应用快照和操作记录属于本机历史，不增加第三份需要用户维护或同步的策略配置。多版本字段结构与生产主指针存储仍待冻结；历史保留数量及UI已按2026-10-14后续确认调整，现有两个 JSON 仅为最小 payload 示例，尚未演示这些新增元数据。

## 2. 自动生成模版

### 2.1 生成入口与产出

“自动生成模版”属于新建 / 编辑模版内的辅助功能，输入提示词自动建议名称、说明、匹配规则和配置；不作为与新建并列的独立流程。模版即自建模型族，不要求选择固定族。已有版先编辑为新候选，当前一次聚焦一个缓冲，多份新增 / 修改走 §2.3 独立外部入口。完整字段及身份见 [自由模版专项方案](模型模版与匹配规则方案.md)。

生成检查本机执行模型，未配置先设置并返回输入；目标模型不等于执行模型。Agent 应参考官方资料、渠道参数说明、当前 adapter 与已有声明，记录来源 / 时间 / 范围；未知继承、推断和手工声明分开。发现 ID 不是推理 / Fast 能力证据。

| 产出 | 必须表达 |
|---|---|
| 身份与匹配建议 | 自由名称 / 说明；包含、排除、大小写、渠道全部 / 白名单 / 黑名单及列表、优先级；输出协议独立 |
| 配置规则 | 族通用配置及可选的具体型号后缀 / 差异字段；协议、窗口、模态、可选档位与独立默认、Fast 和高级，各项可继承，未知不填 true |
| 来源 / 未确认 | 支持字段、适用型号 / 协议、日期及证据；矛盾和渠道未确认原因，不冒充实测 |
| 变更与生成记录 | 基准、执行模型、锁定字段、本轮差异 / 未接受字段；不含凭据与完整 runtime 配置 |

建议接受只改编辑缓冲，匹配预览 / 比较后保存 immutable 候选；不设主、不采用、不写运行。每轮生成 / 纠偏显示资源使用及执行身份，目标能力探测另需显式动作。A6api 无额度，不发生成或探测。检索工具 / runner 未接入不声称搜索完成；真实 Agent、schema 和 CLI 为 WP-06 候选交付，原型只 mock。

### 2.1.1 内置 Agent 执行配置（新增候选）

执行配置与要生成的模板对象分开：为 Claude 制作模板可以使用另一个渠道的执行模型；目标族不决定执行模型，执行模型也不必加入 Codex 选择器白名单。执行仅从已保存、已绑定且可用的连接中选择；未提交的渠道开关、白名单或推理草稿不作为执行连接事实。

2026-10-13 范围明确：这是本机“模型模版 Agent”的一份共用执行配置。自动填充 / 对话纠偏、当前模版更新、勾选模版更新和全部更新均读取它，不按模版单独保存执行模型。它与 Codex 对话的命名、搜索和子 Agent 配置独立；外部 Agent / CLI 继续使用自身配置。保存不改正在执行任务的冻结参数，只影响下一任务。

2026-10-14 用户同意设置页收敛为“Agent 配置”：设置 Tab、页面标题及配置按钮统一此名称；卡片明确“模型模版助手 · 本机共用”，模型摘要显示实际推理和快速已开启 / 已关闭，未支持或能力未知另说明。设置页只承载助手执行偏好；后续确认进一步取消模型页的“高级模型配置”入口与独立全局 Fast 控件。型号、推理和快速模式统一由公共选择器返回；模型支持能力继续定义在规则中。已有运行策略与目录兼容字段先保留，是否仍需要独立 Fast 项须按真实客户端核实，详见[Fast 入口收简](../06-版本记录/20261014-移除高级模型配置与统一Fast选择.md)。交互 / 实现边界与内部配置文件说明收进原型标签，不常驻产品正文。详见 [本轮调整](../06-版本记录/20261014-Agent配置页收敛与快速状态.md)。

执行模型、推理和快速模式选择采用 [公共渠道模型选择器](../../../../../01-项目支撑资料/01-产品原型/公共渠道模型选择器交互方案.md)的弹窗组件，按已纳入 0.2.0 的 WP-07 接入。共用设置中只提供“执行模型”选择入口及当前组合摘要，替换渠道 / 型号 / 推理三个下拉并移除独立 Fast 开关；左渠道、右模型、表头搜索排序、底部标签及推理 / 快速模式玻璃浮层由公共组件负责。主“确定选择”后返回本次设置缓冲，保存共用设置才更新执行偏好；取消选择返回原缓冲，取消设置保留已保存值。

| 字段 / 状态 | 交互与边界 |
|---|---|
| 执行渠道 | 公共选择弹窗左栏复用现有连接，不重填密钥；停用 / 待绑定 / 明确无额度项不可用，并说明原因 |
| 执行模型 | 公共选择弹窗右侧从已保存的完整发现目录选择，不受 Codex 模型白名单限制；稳定 channelId + modelId 返回；原生目录尚无管理器执行绑定时显示不可用原因 |
| 推理档位 | 公共组件显示已保存策略解析后的实际默认及支持集合；未显式选择不固化显示值，恢复默认清除覆盖，显式 none 单独保留。能力来源是执行模型，不使用待编辑目标模版的草稿 |
| Fast | 在公共模型选择器内选择，与型号 / 推理组合一起返回，不在 Agent 设置重复显示开关。显式 false 保留关闭意图；换型号未返回 fast 时采用该目录默认（目前为 false），不沿用旧型号的开启值。仅明确支持时可开启，保存时复核；执行偏好与渠道策略的全局 Fast 草稿分开 |
| 未配置 / 失效 | 生成和发送纠偏不可用，提供“配置执行模型”；渠道删除、停用、端点改变或模型失效时重新选择，不静默换执行模型 |
| 检索 / runner | 模型选择不等于已获得搜索能力。资料模式另显示“当前规则 / 用户提供资料”或“公开资料检索”；检索未接入就显示待接入，不伪称搜索完成 |
| 保存 | 保存执行偏好后返回原生成或对话输入；不改渠道草稿，不写 Codex 运行配置，不要求重启 |

拟复用现有 `manager-state/preferences.json` 的本机命名空间 `modelTemplateAgent`，候选字段为稳定本机连接引用、模型 ID、推理偏好、Fast 偏好。不要再建需要用户维护的第三份模型规则文件；执行偏好不写模板库或渠道策略。具体命名、schema、迁移与连接解析在 WP-06 冻结；当前只有内存 mock，没有落盘实现。

现有 preferences 已属于同步产物，因此新增这段本机数据必须配套同步 / 导出过滤与导入保留规则，不能据“放在 preferences”声称天然不外传。默认 preferences / WebDAV、普通双文件与全配置导出均排除本机执行引用；从其他机器导入偏好时保留本机段，不复制远端连接引用。本轮尚未实现过滤，须进入后续工作包验收。

一次生成冻结执行身份与参数，结果记录非敏感模型标识和时间；执行过程中改设置只影响下一次。真实接入仍须核对凭据解析、文本 / 工具能力、结构化结果校验、检索工具、资源消耗、停止与晚返回。A6api 因用户说明无额度，不作为执行候选或默认测试渠道；不会发送额度探测。

2026-10-15操作区修订：常用Agent自动填充与统一“外部任务”直接可见，外部任务涵盖创建/提交/回执；复制直接放在操作区，版本比较 / 恢复收进标题的版本与历史。返回有未保存修改时合并差异与保存 / 放弃选择，放弃会失效该对象的晚返回，已保存 revision 保留；后文的前序入口描述以 [本轮分工](../06-版本记录/20261014-模版操作分工与返回处理.md)为当前规则。

### 2.2 编辑缓冲上的连续对话

新建 / 编辑内从左侧导航下第一个“Agent 自动填充”文字按钮打开非模态对话面板，不保留顶部重复条或右下启动器。收起后焦点尝试返回左侧按钮；导航收起保留图标、tooltip 和可读标签。面板顶部为“Agent 助手”、实际执行模型入口与放大 / 还原、收起图标；未配置显示配置入口，失效原因可查，点击模型打开执行设置并返回原输入。中部以按角色区分的对话为主，消息区独立滚动；底部紧凑资料 / 上下文锁 / 导出一行，输入框与统一“发送”相邻，持续纠偏沿用同一入口。结果待比较、接受 / 保留当前和停止仍可达；比较确认接受后才改缓冲。默认悬浮面板无遮罩，浮动模式不锁页面控件或滚动；放大铺满原型应用窗口，可还原到默认悬浮约束。放大 / 还原不重建表单 / 聊天 DOM，保留输入 / caret、聊天与正文位置；收起记住窗口尺寸偏好，再开沿用，刷新重置；收起或连续表单的锚点跳转保留按模版隔离的输入 / 消息，点击导航不重建表单；异步返回保留焦点、光标和可见锚点。每次生成冻结目标及执行身份，切换模版不将用户带回旧对象；公共 Select 高于面板和模态弹窗。生成建议进入相同缓冲，用户可持续说“默认改中档，窗口继承，匹配排除 embedding”或直接修改。每轮携带任务目标、当前缓冲、基准、用户约束及人工锁，长期摘要可查看，不假定完整聊天永远在上下文。

返回按发送时基准、当前缓冲与建议做三方比较：无关改动可合并，期间手改保留，冲突显示差异。锁定字段不能悄悄重置，通用及具体型号的人工上下文锁同时保护，删除锁定型号不能绕过限制；具体型号数组当前按整体三方比较，冲突保留人工数组。协议不可表达的请求说明原因。接受只更新缓冲，保存后的 revision 再纠偏须新候选。失败 / 停止保留输入和旧版本；停止使晚回失效，过期返回供比较，不覆盖。完整会话默认本机，普通双文件只带用户选择的非敏感来源 / 摘要；正式逐字段锁、会话存储与 late-return 服务待实现。

### 2.3 独立外部 Agent 配置、文件与 CLI

2026-10-15用户明确外部任务是一套制模“鞍具”，本节主流程已由[外部制模任务鞍具方案](外部制模任务鞍具方案.md)修订：列表和详情只保留“外部任务”，选范围和预置场景后，一次复制的内容包含最小目标/精确基准/字段契约，外部执行者据此处理，校验并经软件提交服务新增版本，再查询回执。取消“生成外部任务＋导入外部结果”两个并列主入口；兼容回传留在同一任务内。

预置场景指令、契约和目标快照组合为一份完整内容，一次复制给外部Agent，不再默认输出全部渠道/模型/节点或聊天；无资料能力声明保持未知。字段契约、匹配器、人工锁及最终版本/摘要/事务服务与人工和内置生成共用；外部不计算新版本号，不裸写模版库、默认指针、渠道采用、运行配置或凭据。任一坏项/过期基准全批拒绝，同一提交ID同内容重试返回原回执，取消后晚回不保存。

任务资料只读、工作目录输出和服务写库必须由真实权限/能力边界落实；任务ID和上传资料不单独构成授权。真实CLI/MCP/文件入口、schema协商、持久任务、锁和原子落盘仍待WP-01/02/06冻结，通知由WP-08统一注册发布。当前只有内存原型，未调用外部执行者或写真实文件；旧整数版本/FNV摘要仅原型兼容，不代表生产身份与安全协议。

## 3. 模板版本、主版本与渠道引用

每个模板保持稳定 ID，规则版本用 revision 标识。未保存草稿可直接修改；已保存版本的规则内容不可原地改写，编辑生成新的候选 revision。仅修改显示名称不改变规则身份。2026-10-13 用户同意 UI 使用“完整保存时间＋短标识”，例如 2026-10-13 14:32:08 · A7F2；北京时间固定，完整唯一 revisionId 用于底层身份，短标识碰撞时扩展。来源、修改摘要、基于版本与采用 / 确认可用状态同时展示，不再只凭 v1 / v2 序号判断。原型接入及生产差距见 [时间版本与检查更新](../06-版本记录/20261013-模型模版时间版本与检查更新.md)。

2026-10-14 入口修订：两类列表仅通过行内编辑进入，名称 / 空白不导航；模版独立查看页已合并到统一编辑器。清洁表单同时显示编辑状态与保存版本采用状态，浏览不创建新版本；有修改时先保存或通过返回处理，再切版本 / 采用，见 [本轮记录](../06-版本记录/20261014-列表显式编辑入口与统一模版编辑页.md)。

2026-10-14 展示修订：编辑侧栏与保存确认动作统一称“保存”，标题集中显示编辑或已保存版本的状态，并由原型标签说明八种状态。新建未保存 / 未保存修改 / 已采用待确认用橙色，配置待修正用红色，已保存未采用用蓝色，已采用已确认可用用绿色；未修改与曾确认可用用中性。颜色不替代文字或真实采用 / 确认记录；保存仍只生成新版本，不能通过文案缩短把保存候选和渠道采用混为一个动作。具体规则见 [保存与彩色状态](../06-版本记录/20261014-模版保存按钮与彩色状态.md)。

Agent 面板的“更新模型资料”复用现有执行配置，选择当前 / 勾选 / 全部后检查；差异树表逐项选择，人工值默认保留。确认保存只新增独立候选版本，批量保存另登记批次；采用仍通过渠道草稿保存。用户实际试用后可确认当时配置可用并保留恢复点。无变化、检索失败及过期返回不产生新版本。真实检索与生产版本服务尚未实现。

同日入口修订：模型模版列表顶部常驻“检查全部更新”，一次点击检查全部并查看差异；勾选后的“检查所选更新”仅处理勾选范围。两者复用同一 Agent 更新任务；执行设置缺失时先设置，保存后继续，取消不执行。单个模版仍从 Agent 面板检查，不为每一行增加重复入口。

| 显示状态 / 动作 | 语义 |
|---|---|
| 候选版本 | 手动或 Agent 生成，允许预览、比较、另存修改和删除未被依赖的候选；不会自己生效 |
| 主版本 | 每个模板至多一个推荐的默认 revision；初次采用和以后套用时默认选择它，可暂时没有主版本 |
| 历史版本 | 不再作为主版本但保留以供比较、已有渠道引用或恢复；并非失效版本 |
| 设为主版本 | 更新默认选择指针；明确提示“已有渠道继续使用原版本”，不批量升级引用或写运行态 |
| 采用此版本 | 选择明确渠道 / 模型范围 → 查看规则和继承差异 → 形成策略草稿 → 点击保存、确认差异并写入 |
| 删除 / 归档 | 未被策略、主指针或保留恢复记录依赖的候选可删除；存在依赖时先展示引用并允许归档，不留下悬空引用 |

“主版本”是推荐指针，“渠道当前引用版本”是实际策略选择，两者可以不同。版本状态与“被多少渠道引用”分别显示；即使 v2 从未成为主版本，也可以被某个明确选择的渠道使用。不把候选 / 历史状态当作禁止显式采用的隐藏规则。

常用路径收敛为“新建 / 编辑 → 可选自动填充与持续纠偏 → 匹配预览 / 比较 → 保存候选 → 采用此版本 → 保存渠道配置”。采用向导可同时勾选“设为以后默认版本”，并一次选择多个渠道；最后只执行一次渠道“保存”的差异确认并写入，避免要求用户来回切 Tab。这个选项不隐式扩大渠道范围；默认不勾选，也不自动清除已有单模型例外。页上同时显示例如“主版本 v3；此渠道使用 v2”，让用户看到为什么当前行为还没有变化。

规则存档保持 immutable；本机验证状态、显示名称、主指针和归档标记为单独元数据。相同 ID / revision 但规则内容不同仍按冲突处理。删除模板整个条目和导入替换同样检查依赖；归档版本仍可被旧渠道与恢复记录解析，但不默认出现在新套用列表。

版本身份分配须防多机并发。显示 v1 / v2 / v3 仅为浏览序号，不能以“本机最大整数 + 1”假定跨机全局唯一。WP-01 冻结可跨机唯一的 revision 身份和迁移规则；同一 ID / revision 不同内容仍保留冲突副本，用户可将一份规则另存为新唯一 revision 后再显式切引用，不能静默重编号已被引用的版本。规则 digest、可变元数据 digest 和整个产物 digest 区分：改显示名称不改规则身份，改主指针要参与同步冲突和恢复差异。引用的 revision 不能由规则摘要不同的结果替代。

候选 / 主 / 历史用于浏览，引用数量与归档是独立属性。归档主版本前须显式清空或移到另一个主指针，不能让“默认套用”隐含选中已归档版本；已有策略 / 历史仍可解析归档规则。未保存策略草稿和待审输入引用的 revision 也须临时保护，放弃这些候选后可解除保护。整模版删除检查系统基线、手动保留、策略、草稿、待审输入和保留恢复点依赖；自建模版自身的默认指针随无外部依赖的整条删除移除，不永久锁定模版。

## 4. 单份渠道策略与恢复

渠道策略只保留一个当前工作区，不给每个渠道再增加主 / 候选 / 历史版本。编辑与运行态提交分开，但用户只需要一次“保存”主动作：内部完成差异确认、备份和写入，再提示重启。状态明确区分草稿、保存中、已保存待重启、待验证和客户端已生效；只保存模版与渠道保存分开命名。运行应用历史不等于模板 revision。

渠道编辑不再提供撤销 / 重做，详情返回保留工作区。未提交时在列表 Tab 右侧点击“还原修改”，确认全部范围后回到最近成功保存的配置，第一次尚未保存则回初次读取基线；无修改或保存中禁用，确认基准过期拒绝。已保存但待重启的配置同样作为还原基准，客户端是否已加载独立标识。渠道列表不再提供保存与恢复 / 保存记录或更多入口；导入导出继续在同步页。自动保存快照和模版采用恢复保留，不通过还原删除模版版本、助手已保存执行设置或历史数据。

**每次保存写入前保存可恢复的组合基线**：上次成功应用的策略、对应模板精确 revision / digest 和主指针，以及本次写入前实际运行态的受管字段与绑定身份。不能只备份已保存的新草稿，否则无法恢复上一次效果。首次应用先记录从运行态读取的基线；备份保存失败则不开始写入。每次尝试记录结果，写入与运行读回成功才成为新的成功写入基线，客户端生效状态另记；部分失败 / 崩溃不能冒充完整历史状态。

恢复流程为选择记录 → 将该记录中的目标配置放入新草稿 → 重新读取当前运行态与依赖 → 预览差异 / 漂移与激活预算 → 点击“保存”明确写入并读回 → 提示重启并核对。旧模板规则与必要依赖可从快照恢复到库中；不为了恢复一份旧策略删除此后新增且无关的模板候选。选择器顺序、上下文窗口、输入模态、推理和 Fast 都出现在恢复差异中，主指针变化也单列说明。恢复后产生新应用记录，保留当前成功状态以便再向前恢复。

恢复默认只撤回所选记录影响的策略 / 受管字段，完整策略回到某个基线是另一个显式范围选择。主指针恢复是独立的可选库变更，默认保留当前指针；在恢复预览列出差异，不因恢复渠道策略回退整个模板库。当前已有未保存草稿时，先暂存 / 合并 / 丢弃明确范围，再接受历史候选，不能覆盖草稿。成功快照是默认可恢复点；partial / 超时记录只供核对或本次补偿，不当作完整成功版本。

本机操作记录绑定 endpoint / adapter / provider 身份；端点或绑定已变化时先重新核对，不把旧验证结果迁移到新对象。仅恢复受管字段，官方配置中的外部修改继续按漂移冲突处理；不把旧 config.json 整份覆盖回去，也不通过关闭 discovery 复原白名单。自动补偿用于本次部分失败，用户主动恢复成功历史用于撤回先前配置，界面区分两者。

快照和应用记录不默认通过 WebDAV 同步，也不混进普通双文件导出。删除历史前显示受影响恢复点；清理保留规则、容量与是否支持额外导出历史在冻结时确定，不能静默清掉仍被依赖的版本。

## 5. 文件与同步的版本边界

| 版本标识 | 意义 |
|---|---|
| Desktop 0.2.0 | 产品迭代，不决定模板是否主用 |
| 两个文件各自的 schemaVersion | 读取与兼容的结构版本，不是模板内容版本 |
| template ID + revision | 一份模板的规则版本，由策略精确引用 |
| 主版本指针 | 以后默认选择哪个 revision，不替换既有渠道引用 |
| 应用记录 / snapshot ID | 一次本机应用与可恢复基线，不建立第二套渠道配置版本树 |

普通策略导出默认携带其引用的精确模板规则；仅模板导出可以选当前候选、主版本或完整库，明确选择范围与依赖。新多版本元数据的导出字段在 WP-01 冻结；来源采用可移植的非敏感摘要，机器验证、绑定与执行凭据不导出。

导入或下载的主指针先显示为候选变化，不直接替换本机主指针。新增规则可以并入候选库，策略引用变化必须预览；缺精确 revision 阻止应用，不用“最新”替代。同步默认只接收候选，不自动切主版本、升级渠道引用或写运行态；是否允许以后显式授权的无冲突自动应用另行评审，不能从旧同步范围推断新增配置的授权。

### 4.3 0.1.10 → 0.2.0 升级路径

**3阶段迁移流程**：

#### Phase 1: Backup & Detect（备份与检测）

```typescript
// 伪代码，实际实施时需遵循生产规范
async function migrateFrom0110() {
  // 1.1 备份旧DB
  const backupPath = await backupDatabase('0.1.10', timestamp);
  
  // 1.2 检测数据源
  const oldDB = await openDatabase(OLD_DB_PATH);
  const recordCount = await oldDB.query('SELECT COUNT(*) FROM models');
  
  // 1.3 兼容性预检
  const issues = await detectBreakingChanges(oldDB);
  if (issues.blocking.length > 0) {
    throw new MigrationAbortError(issues);
  }
  
  return { backupPath, recordCount, warnings: issues.warnings };
}
```

#### Phase 2: Identity Mapping（身份映射）

```typescript
// 2.1 旧记录提取
const oldRecords = await oldDB.query(`
  SELECT id, name, endpoint, api_key_field, config_json
  FROM models WHERE active = 1
`);

// 2.2 生成新身份
const migrationMap = oldRecords.map(old => ({
  oldId: old.id,
  newTemplateId: uuidv4(),
  revisionId: uuidv4(),
  sourceFingerprint: hash(old.name + old.endpoint)
}));

// 2.3 记录映射表（用于失败恢复）
await writeMigrationLog(migrationMap);
```

#### Phase 3: 3-Stage Import Validation（三级导入校验）

```typescript
// 3.1 Stage 1: Dry-run Transform
const transformed = await transformRecords(oldRecords, migrationMap);
const dryRunErrors = await validateSchema(transformed, STRICT_MODE);
if (dryRunErrors.length > 0) {
  return { status: 'dry-run-failed', errors: dryRunErrors };
}

// 3.2 Stage 2: Isolated Write
await newDB.transaction(async tx => {
  for (const record of transformed) {
    await tx.insert('model_templates', record);
  }
  // 不提交，仅校验约束
  await tx.rollback();
});

// 3.3 Stage 3: Commit with Audit Trail
await newDB.transaction(async tx => {
  await tx.insert('model_templates', transformed);
  await tx.insert('migration_audit', {
    fromVersion: '0.1.10',
    toVersion: '0.2.0',
    recordCount: transformed.length,
    timestamp: Date.now(),
    backupPath
  });
  await tx.commit();
});

return { status: 'success', migrated: transformed.length };
```

### 4.4 失败与恢复链

**5类故障场景**：

| 故障类型 | 检测点 | 恢复策略 | 用户影响 |
|---------|--------|----------|----------|
| **导入中断** | Phase 3.3事务提交前 | 自动rollback，保留0.1.10 DB不变 | 重新尝试迁移 |
| **字段冲突** | Phase 3.1 dry-run校验 | 提示冲突字段列表，提供"跳过/手动映射"选项 | 需用户介入决策 |
| **数据库损坏** | 打开0.1.10 DB失败 | 尝试从最近备份恢复，无备份则降级为"仅新建" | 旧数据丢失风险 |
| **revisionId碰撞** | Phase 2.2 UUID生成 | 重新生成UUID（理论概率<10^-15） | 无，自动重试 |
| **用户回滚** | 迁移完成后用户主动回退 | 恢复§4.4备份文件，清除0.2.0 DB | 丢失迁移后新增数据 |

**恢复链集成**：
- 每次迁移在`migration_audit`表记录`backupPath`
- 恢复工具读取最近一条audit记录
- 调用备份管理器执行restore（见"同步与备份契约"§恢复链）

  - 旧数据库文件完整性校验通过
