# P0 状态与流程说明

## 1. 原型状态机

| 状态 | 说明 | 可用动作 |
|---|---|---|
| `not_found` | 未发现 OpenCodex 安装 | 刷新发现（mock） |
| `loading` | 正在探测本机安装与状态 | 无 |
| `stopped` | 已发现但未运行 | 启动 |
| `starting` | 正在启动 | 取消观察（仅原型示意） |
| `pending` | 代理端口可达但未通过 ready | 刷新状态 |
| `running` | 代理运行且 ready 通过 | 停止、重启、打开面板、查看日志 |
| `starting_failed` | 启动失败 | 查看错误、重试启动 |
| `at_risk` | 官方 status 报告 startup at-risk | 先查看建议；restore 需确认 |
| `external_takeover` | 外部 provider 接管 Codex 配置 | 查看；restore 需确认 |
| `unreachable` | 进程或端口不可达 | 刷新状态、查看日志 |

原型中的启停模型是：桌面壳直接托管 `ocx start` / `ocx stop` / `ocx restart` 子进程。状态源优先使用官方 `ocx status --json`、`health`、`ready`、`doctor`。

## 2. 关键流程

### 2.0 根入口与页面串联

1. `../原型/index.html` 是原型根入口，使用 hash 路由维护当前页面。
2. 可路由页面为：概览、官方面板、安装与数据根、日志和设置。
3. 浏览器中的原型放在模拟 macOS 应用窗口内，默认 1180 × 760，标题栏只作视觉参考，不可交互。官方面板采用方案 B：保留标题栏与 64px 图标栏，官方页面占满剩余内容区。
4. 概览是唯一的进程状态与启停控制入口；官方面板不依赖启动状态，直接展示静态中文快照。
5. 面板不可用时自动回退概览，避免留下空白窗口内容区。
6. 概览提供配置迁移、WebDAV 同步、版本升级的常用动作和安装、日志、设置入口；旧 `#config`、`#webdav`、`#upgrade` 自动回落设置。

### 2.1 首次发现

1. 应用进入 loading。
2. 探测本机安装形态、版本、可执行路径和数据目录。
3. 展示已发现安装；未发现时提供只读说明，不引导 npm 安装。
4. 用户确认统一数据根与 `OPENCODEX_HOME` 策略。

### 2.2 正常启停

1. 用户点击启动。
2. 桌面壳托管官方子进程。
3. 状态从 stopped -> starting -> pending -> running。
4. 启动成功后显示端口、PID、健康结果和日志入口。
5. 停止前需要确认；重启前需要确认。

### 2.3 at-risk 与外部接管

1. 状态面板展示风险摘要，而不是只显示红色状态。
2. 说明外部 provider 接管属于 OpenCodex CLI 边界。
3. 桌面壳不自动修改配置。
4. 用户显式确认后进入官方 restore 引导。
5. restore 过程展示前置备份、执行中和结果状态。

### 2.4 日志与官方面板

1. 日志默认只读。
2. 敏感字段统一脱敏显示。
3. 代理离线时说明官方 observe 能力不可用。
4. 提供打开日志目录。
5. 官方面板是常驻图标栏的独立视图，直接可进入；官方快照为中文版。
6. 该视图保留管理器标题栏与 64px 图标栏，隐藏概览页标题、提示条和流程控件，仅保留最小悬浮操作（返回概览、重载、浏览器打开）。
7. 嵌入区域只承载官方 GUI，不重绘内部、不插入管理器控件。
8. 面板加载失败时在同一全幅区域内展示重试与“在浏览器打开”。
9. 原型可加载官方 GUI 渲染后的源码级快照，仅用于视觉与布局判断；快照保留真实 DOM 与 CSS，但不请求运行态 API，不得视为生产嵌入方案。
10. macOS 原生菜单提供进程、视图、日志入口；应用内侧栏同步提供官方面板入口。
11. 2026-09-12 布局复核：面板模式左栏约 64px，中文官方面板主内容区约 1116px。

### 2.5 设置与快捷动作

概览负责高频动作：

- 配置迁移：导出、导入、打开迁移设置。
- WebDAV 同步：立即同步、测试连接、打开同步设置。
- 版本升级：检查更新、升级前备份、打开升级设置。

设置负责参数与边界，分为五个分区：

| 分区 | 设置范围 |
|---|---|
| 通用 | 面板自动打开、内嵌优先、关闭窗口后保持代理、启停通知、同步冲突提醒 |
| 数据与备份 | 升级 / 导入 / 覆盖前自动备份、保留策略、完整性校验 |
| 配置迁移 | 导出范围、口令保护、导入校验流程、导出目录 |
| WebDAV 同步 | 端点、目录、凭据掩码、客户端加密、冷同步、覆盖备份、冲突策略 |
| 版本升级 | 两块：**OpenCodex 版本**（当前版本、升级前备份、官方 `ocx update` 引导、失败恢复建议）与**桌面管理器版本**（应用自身版本、可用更新、下载并重启、更新通道与频率） |

设置不保存真实偏好、端点或凭据；所有输入均为 mock。

## 2.6 统一数据根

原型展示以下分区，不代表最终目录名：

- manager state：桌面壳设置。
- opencodex home：可选承载 `OPENCODEX_HOME`。
- backups：升级、导入、同步覆盖前备份。
- logs：管理器与运行日志。
- exports：加密导出容器。
- cache：可丢弃缓存。
- sync state：同步与冲突历史摘要。

## 2.7 视觉与颜色规则

1. 颜色体系优先从官方 GUI 构建产物提取 token，再向 OpenCodex 官方面板对齐，避免嵌入面板后割裂。
2. 官方截图仅作为视觉 QA 证据；不通过截图反推样式。
3. light / dark / system 主题由桌面壳与官方 GUI 各自保持一致，桌面壳不重绘官方面板内部。
4. primary 交互色使用官方中性近黑 / 近白；进程启停等风险动作不使用品牌色强调。
5. OpenCodex 品牌色仅用于 Logo、轻量识别元素和局部强调。
6. 状态色使用官方 green / amber / red / blue 语义。
7. AiMaMi 仅作为 macOS 原生窗口气质参考，不作为颜色母版。

## 3. 文案规则

- 按钮使用明确动词：启动、停止、重启、刷新状态、打开面板、查看日志。
- 不使用“修复”“清理”等含糊按钮表达不可逆动作。
- 涉及 restore、停止、重启、切换数据目录时必须解释后果。
- 敏感值永远掩码。
- 不把 npm 管理能力伪装成可用功能。

## 概览控制台（2026-09-12 晚）
概览改为一屏控制台：上方集中运行状态、版本、Runtime、`OPENCODEX_HOME`、统一数据根、日志与备份路径，并保留启动、停止、重启、Doctor、数据根和设置入口；下方仅保留配置迁移、WebDAV 同步和版本升级的高频动作，参数仍在设置页维护。

原型注释、按钮边界说明和状态测试器统一移到模拟 App 窗口右侧；所有路由的说明随路由切换，避免解释性内容进入软件界面。

## 概览定稿（2026-09-13）

概览布局定稿为 **B+ 合并版**，其余方案（baseline / B 三段式 / C 摘要 + 抽屉）已下线；对比过程与实测见 `design-qa.md`。

结构：**运行状态卡**（一行运行摘要 + 按状态渲染的动作）→ **运行详情**（页内折叠，折叠条自带关键事实）→ **快捷动作卡**（版本升级 / 配置迁移 / WebDAV 同步，按钮撑满内容宽度）。

定稿采用的行为：

1. **动作按状态渲染**（不是渲染全部按钮再禁用）：

| 状态 | 出现动作 |
|---|---|
| `loading` | 无（只显示状态说明） |
| `not_found` | 刷新状态 |
| `stopped` | 启动 OpenCodex、刷新状态 |
| `starting` / `pending` | 刷新状态 |
| `running` | **打开面板**、停止、重启、查看日志 |
| `starting_failed` | 重试启动、查看日志 |
| `at_risk` / `external_takeover` | 查看建议、刷新状态 |
| `unreachable` | 刷新状态、查看日志 |

   不再渲染无解释的禁用按钮；`starting_failed` 下启动按钮文案变为「重试启动」。
2. 状态区显示一句状态说明（10 个状态各有文案），替代灰按钮传达原因。
3. 快捷动作卡压缩为状态文本行 + 横排按钮；标签只表达状态（「规划中 / 可用」），不在应用界面里出现阶段编号（P0 / P1 / P2），也不显示实时连接值。

### WebDAV 卡片的状态（按状态渲染，不渲染无解释的禁用态）

| 状态 | 标签 | 连接状态 | 冲突策略 | 动作区 |
|---|---|---|---|---|
| 未配置（默认） | 未配置 | 未配置 | 未设置 | 配置 WebDAV（单颗整行） |
| 未连接 | 未连接 | 未连接 | 每次询问 | 立即同步 / 测试连接 |
| 同步中 | 同步中 | 同步中… | 每次询问 | 取消同步 / 测试连接 |
| 已同步 | 已同步 | 已同步 | 每次询问 | 立即同步 / 测试连接 |
| 连接失败 | 连接失败 | 连接失败 | 每次询问 | 重试连接 / 立即同步 |
| 冲突待处理 | 冲突待处理 | 已同步 | 待处理 | 处理冲突 / 立即同步 |

- 「未配置」不做整卡置灰：主体说明未配置，动作区只留一颗「配置 WebDAV」直达设置，右上角 `⋯` 恒可用。理由见 `design-qa.md` 的「WebDAV 未配置态」条目。

### 两个版本对象（不要混）

| | OpenCodex 本体 | 套壳应用 OpenCodeX-Desktop |
|---|---|---|
| 版本示例 | `v2.50.0`（npm `@bitkyc08/opencodex`） | `v0.1.0`（Tauri 应用） |
| 更新方式 | 官方 `ocx update` | 应用自更新：下载 → 校验签名 → **重启应用** |
| 桌面壳角色 | 不接管；只做升级前备份 + 引导 + 结果展示 | 自己就是更新主体 |
| 界面落点 | 概览「版本升级」卡 + 设置「版本升级」第一块 | 设置「版本升级」第二块；外部**只通过通知中心**提示 |

- 套壳更新会重启应用，因此文案必须写明「不停止 OpenCodex 代理」，且不与 OpenCodex 的升级混用一个按钮。
- 应用更新通道（stable/beta）与 OpenCodex 的 npm 通道彼此独立。

### 通知（通知中心 / 通知历史）

- 通知中心（顶栏铃铛）与「诊断中心 → 通知历史」**共用同一份数据**，任一处改动两处同步。
- **点击任一通知 → 详情弹窗**：标题、完整正文、`时间 · 级别`；有可执行动作时给「前往处理」，否则只有「关闭」；弹窗内可删除。
- **每条通知有单独删除按钮**；批量动作（全部已读 / 清理通知 / 清理已读）保留在通知中心头部与「设置 → 日志与通知」。
4. 版本只在「版本升级」卡出现一次。
5. **Doctor 不再出现在概览动作行**。`ocx doctor` 是官方**只读环境诊断**（paths、WSL `/mnt`、代理环境变量、ChatGPT 可达性、Codex runtime 与 shim、coordinator 状态），属于排障而不是运行控制。它现在落在「诊断中心 - 运行环境诊断」，运行异常时由「查看建议 / 查看日志」进入；原型只展示只读摘要，不提供 `--reclaim-response-temps` / `--recover-zero-byte-coordinator` 这类写入型修复参数。
6. 快捷动作卡的按钮行**撑满内容宽度、与上方状态行左右对齐，按钮之间等间距**；卡片存在当前建议动作时该按钮**高亮为 primary**（当前「版本升级」可升级，故「检查更新」高亮）。
7. 快捷动作卡按内容宽度切换排布：能放下三列时三列并排；放不下时整体改为**单列「条目行」**（标题 + 状态 + 操作同一行），避免「两列 + 第二行空一半」。当前窗口上限 1180px 下实际始终为条目行。
8. 用户可见文案统一用**「数据目录」**（原「统一数据根 / 数据根」），正式文档术语见 QA-16。

运行详情交互：点击折叠条在「展开 / 收起」间切换；收起时折叠条自身显示 `v2.50.0 · Codex runtime … · ~/OpenCodexData`，展开后按 3 列网格列出健康、PID / 进程、Runtime、可执行文件、数据目录与 `OPENCODEX_HOME`，并提供「选择数据目录 / 打开日志目录」入口。窄窗口下网格降为 2 列。

高窗口「最近事件」：运行详情展开时，在其后显示 3 条状态相关摘要，随 normal / risk / error 状态切换；不复制完整日志，只承担高窗口余量感知。用户手动收起详情后同步隐藏；完整日志、Doctor 与通知历史仍集中在「诊断中心」。

### CLI 控制面入口

- 设置新增独立分区，默认关闭；开启前弹出确认，说明本机 IPC、运行中实例委托和仅管理器自有域边界。
- 开启后显示命令入口、实例在线状态、开放能力、明确不开放项与 `--json` 示例；provider / 路由 / 模型映射仍标为官方 CLI。
- 原型不注册 PATH、不复制剪贴板、不建立真实 IPC；具体命令集待 IMP 冻结。
