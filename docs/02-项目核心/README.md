## 阅读顺序

1. `产品定义.md` —— 产品是什么、为谁解决什么问题、明确不做什么。
2. `能力地图.md` —— 能力范围与验收口径。
3. `系统架构.md` —— 由哪些部分组成、怎么跑起来、模块怎么分。
4. `数据与状态.md` —— 数据放在哪、状态如何建模。
5. `领域模型.md` —— 系统里的实体各有哪些字段。
6. `契约字段.md` —— 跨边界传递的数据长什么样。
7. `集成与安全边界.md` —— 与外部系统交互的边界与安全约束。
8. `术语与命名.md` —— 术语与写法约定，写文档和代码时对齐用。

## 冻结状态口径

字段级文档里每条都会标一个状态，含义如下：

| 标记 | 含义 |
|---|---|
| ✅ **已定** | DMD revision 4 与本目录既定事实；实现不得偏离。 |
| `FZ-*` | 已在 `IMP-OPENCODEX-DESKTOP-01` 冻结；字段与参数以 IMP 为准。 |

字段级取值与 IMP 契约冲突时，先修订 IMP；派生文档随后按 IMP 同步。任何核心约束变更仍要先回写 DMD，不能只改本目录。

## 与其他文档的关系

- 本目录只保存**当前事实**：删除需求历史、协作过程与生成物后，仍可据此理解并重建本项目。
- 需求与验收标准的权威在 `01-需求管理`（`DMD-OPENCODEX-DESKTOP-MANAGER`）；本目录**不复述需求变更过程**，只写已成立的事实。
- 实施契约（`IMP-*`）、运行记录（`RUN-*`）与评审讨论不在本目录。
- 每个事实只写一次；本目录已写的内容，其他文档以引用代替重复。
- 需求编号（`REQ-*`）、验收标准（`AC-*`）与风险编号（`R-*` / `T-*`）引用自需求侧与安全评审，本目录**不重新定义**它们。
