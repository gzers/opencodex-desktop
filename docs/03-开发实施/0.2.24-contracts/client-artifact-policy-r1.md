# 0.2.24 客户端目录恢复的共享内容判定

revision: 1；2026-11-11。归IMP-34 P24-04，承接macos-versioned-lifecycle-r1；代码main604f2763e604b70550c1b3519d9d1893dcaaf6a7。当前仅共享内容判定，非实际恢复事务或最终候选，accepted=false。

## 本批输出及明确责任

modules/runtime/client_artifact_policy.rs提供有界、纯内存的catalog/cache/audit四阶段判定。输入是启动前、就绪、停止前、正常停止后的快照，含原字节/缺席/未知、由平台独立核验的文件代次/保护标记，以及启动前独立完整路由声明、原生保留进程PID集合和官方审计投影/时间窗口。没有反序列化所有权凭证，没有文件路径、写入、删除、后台服务或持久保存入口；Assessment只表示内容满足既定恢复范围，不能单独授权写盘。

真正恢复仍须同一生命周期独立提供：当前程序/HOME及受保护配置上下文；启动前原件及缺席留存；原进程代次/保留句柄/受控集合和正常退出；官方claim/N/K协调；原生文件/祖先身份、权限及阻止重定向；受保护持久日志及每个写前CAS/写后读回；原30/5/10预算。不能从匹配hash/审计PID反推写者或从JSON生成所有权证书。此模块未接生产Start/Stop，不改变上轮三个实际恢复失败事实，也没有预建一个默认通过的Host。

## 已实现判定

- 任一阶段/对象未知均整批拒绝；缺席显式区分。每件最多2MiB、4096模型/路由、256个保留PID、审计最多400行且每行2KiB，越限保持不覆盖。边界之外不声称自动支持，真正事务可保留原件并提示需核对，不能以截断输入产生方案。
- 就绪与停止前的原字节、代次、保护必须一致；同内容替换inode或权限变化也拒绝。本批不接活跃配置/模型刷新协调，后继事务必须处理刷新后重新建立自身可证明的状态，不能轮询抢写覆盖。
- 路由来自启动前已完成的独立声明；None表示未知而拒绝，Some(empty)表示完整空集。实际native slug可以含斜杠，不用斜杠启发式分类。原native与声明路由冲突、ready出现未知行或声明行缺失均拒绝。
- 停止后catalog已等于原字节/保护可不写；否则只允许原native行的原对象或本轮ready投影子集、已知顶层值。原native被官方过滤的情形可恢复原件；新用户行/不同字段或未知顶层值拒绝，不能为了目录相等抹掉用户模型。
- cache已等于原件时保留原始不透明字节；否则ready必须是官方固定过期wrapper（fetched_at=2000-01-01T00:00:00Z、client_version=0.0.0，精确三字段），模型与ready catalog相等。停止后只接受同ready原字节或上述已知native子集，真实客户端新缓存/额外字段/未知模型拒绝。JSON递归拒绝重复键/模型重复slug。
- audit只是辅助一致性检查。原前缀保持，新增部分每行完整、字段/写者/target/intent固定，PID/PPID在独立保留集合、HOME投影和时间窗口一致。截断/压缩造成原前缀丢失、遗漏ready后像、新第三方事件或未知字段拒绝；原字节已恢复可不写。用户HOME字符串按官方UTF-16截断单位检查，不能把UTF-8字节数当该上限。没有让诊断日志承担文件归属证明。
- Snapshot的Debug仅输出长度不泄露内容/权限字符串。任一项失败不返回其余两项的部分恢复方案。
