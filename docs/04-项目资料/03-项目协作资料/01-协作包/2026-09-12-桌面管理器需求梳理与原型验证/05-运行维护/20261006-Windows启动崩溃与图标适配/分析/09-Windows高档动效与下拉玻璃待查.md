## 当前源码可确认的策略

以下是固定源码的只读核对，不是用户设备的运行诊断。

- `apps/desktop/ui/src/app/appearance/effects.ts`：默认高档；系统 `prefers-reduced-motion: reduce` 会将高档的有效表现降为中档，保留用户保存值；连续动效还依赖页面可见和原生前台信号。因此设置显示“高”不能单独证明连续动画已获准。
- `apps/desktop/ui/src/features/runtime/motion/states.ts`：待接入应为轻缓漂浮、三球分离和低强度雾蓝光场；运行中才是完整内核持续旋转。待接入并非默认完全静止。
- `apps/desktop/ui/src/features/runtime/components/RuntimeMotionMark.vue`：高档且可见时连续动画；中/低档静态。组件没有按 Windows 平台禁用动画。
- `apps/desktop/tauri/src/infrastructure/app_activity.rs` 与 `lib.rs`：Windows 有初始焦点查询及窗口焦点/尺寸事件发布路径；是否在用户设备上正确反映前台状态尚未验证。
- `apps/desktop/ui/src/app/appearance/glowRender.ts`：WebGL 不可用时应回退 CSS 光场；该回退本身不应关闭形象动画。设置显示 WebGL 不等于运行能力探测通过。
- `apps/desktop/ui/src/styles/materials.css` 与 `effects.css`：菜单与设置行都使用玻璃材质；中档仍保留玻璃，低档才统一实底。截图中的清晰文字穿透不能据此认定为预期玻璃效果。

前台状态未恢复、系统减少动态、动画循环停滞、嵌套玻璃层采样范围或 WebView2 合成差异，均仅是待验证方向，**本轮未确认任何一个为根因**。标题栏原生 Mica 与页面下拉玻璃分别验证，不用云母适配解释菜单穿透。

## Windows 对话接续排查

1. 核对安装身份：EXE 路径、版本、构建提交与 SHA-256；记录 Windows 构建号、WebView2 版本、显示缩放和普通/管理员权限。与[08 候选包交接](08-Windows安装候选包与验收交接.md)的制品身份对照。
2. 保留配置现状：保存的特效档位、实际 `data-effects`、系统动画/减少动态、页面可见性、原生 `app_foreground` 查询和事件。先采集再对照，避免仅通过改设置掩盖问题。
3. 动效：在概览前台采集连续帧或短视频，以及 SVG 变换/帧推进情况；验证切到后台、最小化、托盘隐藏和重新打开后的暂停/恢复。分别确认形象与背景光，不把 rAF 有回调等同于视觉已运动。
4. 菜单：复现截图中的“界面特效”下拉，记录菜单与父层的背景色、`backdrop-filter`、层叠/裁剪状态和渲染截图；对照浅/深主题、高/中/低档及 macOS 同场景。计算样式声明了 blur 仍不足以证明像素实际被模糊。
5. 确认根因后再实施最小修复，回归动效恢复、菜单可读性、选择/关闭行为、键盘操作与缩放边界；补普通/管理员 Windows 原生验收证据。代码提交到实现特性分支，证据和结论提交到文档分支。
