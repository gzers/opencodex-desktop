## 1. 设计目标与判定

渠道负责连接身份及能力依据，对话策略负责选择和使用；实际运行记录负责确认采用结果。认证通过只证明对应认证接口和凭据成立，不是站点品牌认证或所有功能的通行证。单次检测必须限定到连接版本、服务节点、认证方式及适用型号。

用户已明确采用：Sol／Astra的Ultrafast支持可由官方说明、Krill目录及请求接受确认；响应default另列为回显、性能或计费待核实，不否定支持。不为所有特殊能力强加同一套完整付费检测门槛。

将信息分为两个并列维度，避免把能力、网络和运行开关混成一个状态：

| 维度 | 展示值 | 含义 |
|---|---|---|
| 支持情况 | 支持／待核对／明确不支持 | 基于适用版本的来源、目录声明和相应验证，附来源与适用范围 |
| 当前使用条件 | 可使用／待认证／待接通／需复验／当前不可用 | 当前节点、身份、本机引擎与代理链路能否使用；未保存、待重启另外显示 |

网络失败只更新本次检查结果，不能抹掉已有支持依据或永久改成不支持。404保留具体路径和时间，不等同整站或功能永久取消。人工调整模版的能力声明不修改“实际已验证”事实。

## 2. 页面位置与紧凑展示

保持渠道详情四个分区：渠道配置、服务节点、模型默认、模型列表。

| 位置 | 新增或复用 | 规则 |
|---|---|---|
| 渠道配置 | 将接入方式合并为凭据类型，紧邻API Key／PAT输入；下方保留身份结果与实例绑定 | 不再同时配置“认证方式”和“Codex接入方式”，切类型不自动认证 |
| 服务节点 | 站点适配、节点地址、接口路径与最终地址预览；行内测速、特殊能力操作 | 适配提供默认路径，节点可覆盖模型基址、模型清单和原生服务前缀；检测不自动切换当前节点 |
| 模型区域 | 直接展示模型列表及已确认支持的简要标记，不再提供能力结果Tab | 完整结果在对应节点的特殊能力弹窗；型号引用当前渠道唯一清单，不把Sol结论泛化到Terra |
| 渠道列表 | 原连接检测入口与独立特殊能力按钮 | 不再用一个模糊的能力总数代替型号结果，不给每行铺满标签 |
| 对话策略 | 当前接入来源与所选功能的条件 | 复用渠道对象，不另填地址、Key或重复全局开关 |

详情用小型能力表展示“功能｜支持情况｜当前条件”，时间、来源、适用型号、检测路径和错误置于展开区／提示。颜色配合文字和图标，不仅靠圆点判断。延续公共玻璃表面、Select、Modal和现有字号，不用额外仪表盘或整页卡片。

凭据只由现有秘密存储引用管理；原生PAT等高级接入方式仅在相应适配器已实现时提供，不能通过界面选项假造后端支持。站点URL与允许接口来自明确配置／可信适配规则，不按渠道名猜测并向任意地址试送Key。模型请求协议仍由模版和单模型规则解析，不恢复渠道级默认协议。

## 3. 检测流程

使用两个独立居中玻璃弹窗：“检测连接”仅列节点连通、基础鉴权及响应耗时；“特殊能力”固定展示所点节点，集中配置请求地址、独立认证接入身份，并按需选择型号和验证项目。不再使用首轮的两个检测分区Tab。节点配置在先，检测入口归节点列表：各行提供测速及特殊能力，取消节点列表底部重复的连接／能力按钮；完整能力结果统一归节点行的特殊能力入口。

1. 用户明确选择当前节点，进行基础连接检查。分别显示接口可达、认证通过与目录读取；一个公开模型列表200不能代替全部认证流程通过。
2. 按节点路径、站点适配、实际身份和当前草稿的型号清单展示可检查项。支持先建空渠道，再配置节点／路径、检查连接、读取模型；没有型号仍可认证和检查链路，型号项禁用。未知协议不自动猜测，清单获取方式仍只作用于本次读取。
3. 基础检查不自动对全部型号发生成请求。用户在独立特殊能力弹窗选择验证项后，明确型号、合成输入范围和是否产生用量。型号调用、Fast、Ultrafast、原生远程压缩分别保存各型号结果；节点／身份条件独立记录，换型号不伪造一次新认证。
4. 停止检查使本轮迟到结果不能覆盖新一轮或变更后的连接；失败和取消保留原配置与草稿。复用现有检测任务宿主，关闭与停止仍区分，不新建通知／执行状态系统。

| 功能 | 适用验证与显示边界 |
|---|---|
| 普通调用 | 正确型号取得有效响应；认证与目录可达分别记账 |
| Fast／Ultrafast | 有效来源／目录声明与请求接受确认支持；拒绝只作用于所测型号。速度收益和账单不在普通能力检查中推断 |
| WebSocket | 握手和完整响应分别标识；客户端→本地入口、本地→上游分别观察，不能仅写“全链路已启用” |
| 原生远程压缩 | 真实协议、返回状态及续聊分别核对；代理摘要不能标为原生协议通过 |
| 后台压缩 | 检查引擎及协议前提；能读开关不证明后台／前台重叠或真实渠道长上下文通过 |
| 历史／笔记 | thread_hint、历史查询、笔记读写分别记录；本地空提示只证明兼容回复，完整使用仍需真实工具链与会话归属成立 |

笔记实际写入、长上下文或其他高用量验证不是保存配置时的隐式操作；后续专门设计明确的验证范围。mock原型仅演示这些步骤，不执行API、文件或系统命令。

## 4. 依赖功能绑定与生效

对话策略引用**实际执行连接**。模型、原生历史和笔记应保持同一接入身份与会话归属，不能模型走A、笔记因B支持就发给B。原生上下文／传输在当前方案作用于Codex实例；界面显示该实例的接入，不能靠项目／对话下拉假造逐对话PAT热切换。

| 条件 | 页面行为 |
|---|---|
| 未绑定 | 保留功能可发现性，显示选择接入来源 |
| 未认证或失败 | 显示原因和前往渠道配置；不因普通调用成功自动确认原生身份 |
| 支持但本机未接通 | 显示缺项，允许准备草稿；不能显示为已启用 |
| 当前服务不可用 | 保留已有设置和证据，提供复验；阻止新激活，但不静默删除用户意图或把进行中的会话切去别处 |
| 条件满足 | 允许启用，保存后按实际边界显示待重启／待连接／采用待观察；保存不生成实际采用记录 |

普通、可离线编辑的设置不必完成付费检测才能保存；依赖外部认证和服务的功能在实际启用前核对必要条件。执行失败只更新实际观察，不自动覆写用户策略。

## 5. 结果失效、节点切换与迁移

- 检测结果引用配置修订、节点、认证方式及秘密引用修订（不含秘密值）；型号相关项附实际型号和解析协议，应用链路项附引擎／代理身份与版本。字段名仍待正式契约，不在本稿制造生产Schema。
- 更换地址、Key、接入方式后相应结果需复验；只改显示名不失效。相关引擎／代理升级只影响依赖它的结论，不机械清空站点全部能力。尚不设未经讨论的固定有效期。
- 草稿检测绑定草稿快照；保存后只有连接内容一致才归入该保存版本。草稿取消、变更或新一轮检查后，旧请求不能写回当前结论。
- 自动故障切换必须检查目标节点是否满足依赖能力与共享身份／远程状态；原生压缩及笔记状态不能仅凭同站点名就迁移。不能安全延续时明确提示，保留当前会话和恢复信息。
- 同步／导入可带声明和用户设置；源机器的认证通过、已运行及本机链路检测结果不能冒充目标机器事实。具体便携范围沿既有同步owner后续采用，本稿不新增同步实现承诺。

## 2026-11-10：第二轮结构调整（批注后继）

用户指出首轮把凭据、路径、节点和型号能力混在一起，授权按讨论调整一版。本节覆盖首轮“接入与能力整块置于基础配置、两个检测分区共用一个弹窗”的布局，不撤销首轮真实服务验证结论或历史证据。当前仍供评审，未形成生产批准基线。

- 凭据：API Key／原生PAT／无需认证合并到一个凭据类型，与现有输入表单同组，保留掩码、清空、草稿和保存行为。基础配置不再常驻整张能力表。
- 节点与路径：站点适配移至服务节点；编辑／新增节点可展开接口路径，跟随默认或自定义模型请求基址、模型清单、原生服务前缀。输入相对路径，按节点同域生成最终地址，拒绝完整URL、查询参数和相对跳转；取消不写草稿。配置变化使对应旧检测需复验。路径为本轮原型候选，真实适配器注册、协议端点及允许范围仍需生产契约。
- 两个检测：节点区域底部独立“检测连接／特殊能力检测”；前者保留单节点／一键检测，后者只处理接入身份和特殊能力，没有合并弹窗的分区Tab。选择检测对象不会切当前节点，检测不改模型清单或配置。
- 模型与结果：原模型列表包入“模型列表／能力结果”Tab，能力分型号与节点／接入两组。型号来源为同一渠道全部清单（不以启用开关另筛一份），手动添加后立即可选，检测不自动启用型号。型号结果逐型号保留，历史／笔记等接入条件不随型号重复丢失。
