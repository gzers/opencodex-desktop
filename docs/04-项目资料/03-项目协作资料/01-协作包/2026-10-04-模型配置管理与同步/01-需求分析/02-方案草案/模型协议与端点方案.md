# 模型协议与渠道端点方案（0.2.0 候选）

日期：2026-10-04。用户已同意“一个逻辑渠道包含多个协议端点”的方向，并要求模型模版可覆盖模型协议，继续允许单模型自定义。本文承接 [主方案](模型配置管理方案.md)、[统一字段编辑器](模型页交互细化.md#46-渠道模型与模版的统一字段编辑器) 与 [本机源码证据](本地调研依据.md#单模型协议与多端点核对2026-10-04)。具体 schema / 运行适配仍待冻结；当前只有共享内存原型，未写运行配置。

## 1. 渠道、协议与连接的职责

Desktop 列表继续将 NewApi 等显示为一个渠道。该渠道可以包含 Responses、Chat Completions、Anthropic Messages、Google AI Studio、Ollama 等端点；每个端点负责一种协议和自己的本机地址、路径、认证及凭据引用。通用连接选项与本机 registry 对齐为五项；其他注册 adapter 显示专用绑定限制，Vertex、登录、CLI 等不能用同一 API Key 表单伪装已接入。

模型模版定义可复用的输出协议与能力规则，不存渠道地址或 API Key。渠道配置负责可用端点；单模型设置负责最终协议及可选的端点指向。同名模型在不同渠道中保持独立身份，族名不证明上游支持某种协议。

| 配置层 | 编辑内容 | 保存责任 |
|---|---|---|
| 模型模版 | 自由模版身份及版本化匹配范围；输出协议继承 / 自定义；能力、推理、Fast | 模板库 immutable revision；采用才影响渠道草稿 |
| 渠道默认 | 模版未声明时的默认协议与能力 | 单份渠道策略；默认连接单独在本机绑定 |
| 渠道内族覆盖 | 当前渠道对该族的协议及能力例外 | 当前渠道策略，保留其他渠道设置 |
| 单模型例外 | 协议继承 / 自定义，以及端点自动匹配 / 指定 | 精确模型策略；人工值默认不被采用模版清除 |
| 渠道协议端点 | 稳定端点 ID、协议声明及本机连接 | 可移植策略只带 ID / 协议；地址 / 路径 / 认证 / credential ref 留本机 |

## 2. 协议优先级与继承

协议从低到高按 **渠道默认 → 所采用的一份模版通用输出协议 → 命中的具体型号输出协议 → 渠道内族显式覆盖 → 单模型显式覆盖** 解析。每层“继承”跳过本层；“自定义”明确选择协议。不存在模版输出规则时回到渠道默认；模型恢复继承后使用族或模版规则，不必回到渠道默认。具体型号只在选中的 immutable revision 内取最长字面后缀，不能新建端点 / 绑定；未命中沿用通用配置。

能力字段仍沿用原有“官方声明 → 模版通用 → 命中的具体型号 → 渠道默认 → 渠道族 → 单模型”的顺序。协议使用独立优先级，保证采用模版可以实际改变模型协议；不能将渠道默认能力的优先级机械套到协议上。

先读单模型精确引用（人工指定可越过匹配）；否则全局 / 渠道已采用引用按 templateId 合并，同 ID 的渠道 revision 替代全局，再按精确 / 前缀 / 通配、排除、scope 与优先级选择一份。同最高优先级多份命中阻止受影响保存；未采用候选与主版本变化无运行影响。输出协议不是匹配条件，不能因当前渠道 Responses 拒绝 Anthropic 模版，也不按改变后的协议循环重选。厂商 / 用途标签仅供浏览，完整匹配见 [自由模版方案](模型模版与匹配规则方案.md)。

例如：NewApi 默认 Responses；采用 Claude 模版声明 Anthropic 后，该族模型最终走 Anthropic。某个模型手动设为 Chat，则该模型保持 Chat。把该模型协议改成继承，再回到上层 Anthropic。

采用新 revision 默认保留族覆盖、单模型字段、精确模版引用及指定端点，并在差异中列出哪些对象被例外挡住。明确“清除目标单模型例外”时才移除人工字段和指定端点；精确模版引用属于独立引用设置，不随清除字段例外删除。全局采用只影响没有更具体引用的对象，不能把引用改变误报成所有渠道已换协议。目标生产流程须显示清除的完整范围；原型精确模型采用选择器仍有缺口。

## 3. 最终协议与端点匹配

协议字段与指定端点是独立设置。端点选择不会暗改协议；指定端点必须与最终协议一致。

| 情况 | 保存行为 |
|---|---|
| 一项兼容端点且本机绑定完整 | 自动匹配，显示端点 ID 和协议来源 |
| 没有该协议端点 | 阻止受影响的保存计划；提供“配置协议端点”，保留草稿 |
| 同协议有多个端点 | 要求指定端点，不根据名称、顺序或密钥状态猜测 |
| 指定端点不存在或与最终协议冲突 | 显示模型级错误，要求改端点或恢复自动匹配，不回退其他协议 |
| 缺地址 / 认证 / 凭据或版本不支持 | 待绑定 / 不支持，不标成功，不自动创建无凭据渠道 |
| 停用或未发布模型 | 可保留草稿规则与错误标记；启用 / 发布前按实际计划检查 |

删除端点前列出受影响模型，确认只改草稿，保留引用用于解释错误；可撤销 / 重做。删除后已选模型仍指向该端点时保存被阻止，不把它们切到默认端点。编辑默认连接不重置附加端点。端点 ID 在创建后保持稳定；迁入已有渠道时记录原身份，不按列表位置命名。

发现清单只证明 ID 被公布，不能证明所有端点都能调用它。目标发现服务支持按端点获取清单，合并时保存来源端点及精确 ID；同逻辑渠道相同 ID 去重并保留多个来源，默认只维护一个主动协议 / 路由。若未来允许同 ID 多个可选变体，须另冻结变体身份与目录预算，当前不能直接复制条目。新发现项默认不选；discovery 保留；每个实际 provider 使用非空 selectedModels 或明确的隐藏策略。

当前 mock 获取列表仍使用默认连接的静态 fixture，附加端点没有真实 discovery；不能把端点表或生成的计划当作协议已通过测试。A6api 维持无额度（手工）提示，不发能力探测。

## 4. 编译到 OpenCodex 的路径

本机已安装 OpenCodex 2.69.0 有 per-model modelAdapters，其允许值为 openai-chat 与 openai-responses；请求路径确实读取逐模型解析结果。它并非完全没有逐模型协议能力。Anthropic / Google 是真实 adapter，但不属于该覆盖白名单，不能写进 modelAdapters 冒充支持。详见本机证据，版本能力须在实施时重检。

编译器先检查 hard pin、模型 ID、共享连接 / 路径与认证契约，再决定是否复用一个实际 provider。同连接下合法的 Chat / Responses 切换可用 modelAdapters；已有原生 Anthropic 或 Google provider 在认证与地址兼容、无硬约束冲突时，也可能承载合法的 OpenAI 单模型覆盖，不能一概要求拆分。

无法由一个 provider 合法表达的混合协议、独立地址 / 路径或不同认证凭据，展开为多个 Desktop 受管 provider。分组依据是 **协议可表达性 + 规范化地址 / 路径 + 认证方式 + 凭据身份**，不能只按协议或“已配置密钥”布尔值合并。模型 ID 使用上游精确原值；provider adapter 选择、modelAdapters 和逐模型能力写入保持同一计划。

| 逻辑模型示例 | Desktop 最终规则 | 候选运行表达 |
|---|---|---|
| GPT A / GPT B，共享连接 | Responses / Chat | 一个合法 provider，加 GPT B 的 modelAdapters 覆盖 |
| Claude + GPT，共享且认证兼容 | Anthropic / Responses | 允许时原生 provider 加合法 OpenAI 覆盖；否则分别受管 |
| Claude + Gemini + GPT | Anthropic / Google / Responses | 按真实适配能力及连接分组，必要时多个实际 provider |
| 同协议但不同凭据 / 地址 | 相同协议、指定不同端点 | 分开绑定和编译，避免共用错误认证 |

物理 provider 是本机实现映射，UI 的渠道、白名单、内部模型顺序不因分组变化拆散。最终选择器仍按逻辑渠道顺序逐组展开内部模型，Fast 独立行紧跟父项；全局排序将每项映射到实际 catalog ID。不能按物理组先后排列导致一个渠道内的交错顺序丢失。

bindings 须持久化逻辑 channelId、endpointId、实际 providerId、adapter、受管模型和字段及已发布 catalog 身份。实际 provider ID 和基础 adapter 不随勾选集合变化而重新派生；复用 / 拆分 / 合并需显式迁移差异。mock 的分组名称仅演示计划，不是生产稳定 ID 算法。

迁入时读取现有 modelAdapters 和原生 adapter，不用族名重写协议。旧 provider 和外部未受管字段保留；迁移不能短暂全选。已有会话可能保存旧路由 ID，必须验证稳定别名 / 路由兼容契约；若版本不支持，无损连续性不能宣称通过，提供明确迁移范围、旧会话影响与恢复方案。未完成身份和会话门时，不静默替换运行绑定。

## 5. 保存、能力校验与草稿预览

字段编辑“确定”、端点“加入草稿”、模版“采用到草稿”都只更新工作区。查看草稿列出默认协议、模版输出、族 / 模型例外、指定端点、端点增删和最终协议 / 来源。保存确认另列逻辑渠道到实际 provider 的写入计划，内部排序与真实目录预算一并检查。

切换协议会使旧推理和 Fast 能力证据失效。生产编译器须按最终协议验证档位列表 / 默认、标签映射、pin、authoritative、noReasoning、fastWire / service-tier，显示保留、删除或不兼容项的差异；没有合法映射时阻止受影响写入，不能静默丢参数或沿用另一协议的“已验证”。模板继承未知能力，禁止因族名推断支持。

保存计划冻结协议、端点绑定和凭据身份及相关基线；端点 / 模版 / 发现或运行态变化使旧确认失效。注册 / 更新受管 providers、白名单、字段和排序属于同一可观察计划，继承 G-09 的安全写入 / 超时核对 / 补偿要求。只有真实配置、请求路由及完整 catalog 读回一致才晋升成功策略，仍提示 Codex 重启与客户端核对。未修改的独立离线对象沿用主方案的保存范围，不任意扩大发布。

当前 mock 演示缺端点 / 歧义 / 冲突阻止保存、协议分组计划与草稿差异；推理 / Fast 的完整协议合法性、稳定身份和实际请求未验证。

## 6. 双文件、同步与外部 Agent

仍保留两份可移植配置：model-family-templates.json 的版本正文带协议规则，model-policy.json 带默认协议、端点 ID / 协议声明、引用及模型协议 / 指定端点覆盖。完整地址、路径、认证和凭据引用、实际 provider 注册、验证状态留本机 model-policy-bindings.json / 安全凭据服务，不增加第三份可同步策略事实源。

导入 / WebDAV 只接收候选并保留本机连接；新 endpointId 显示待绑定，不能以相同显示名自动匹配。绑定后重新校验最终协议、推理 / Fast、目录计数与排序，再走保存。恢复旧策略保留所依赖协议规则及端点身份；本机凭据缺失时先补绑定，历史策略不提供不存在的密钥恢复保证。

外部任务包含目标模版 / revision 与编辑缓冲、版本化匹配规则 / 多目标基准、期望输出协议、协议优先级、可用端点 ID / 协议与绑定是否完整、模型人工例外、字段限制、基准 digest 和来源摘要。包不含具体 URL、认证秘密或 Desktop 执行偏好；外部工具无需读取会话历史。候选协议需在允许集合中，证据与未知能力明确；未知协议拒绝导入或标不支持，候选不能自动创建端点 / 修改主指针 / 写运行配置。真实 CLI / 检索仍待 WP-06。

两个 JSON 示例为待冻结形状，使用 canonical adapter 名表示协议；共享 mock 使用 Responses / Chat / Anthropic / Google 显示值，两者不被宣称为同一个生产 schema。

## 7. 原型入口与交付条件

入口：渠道列表“管理” → 连续“协议端点”分区，左侧锚点定位；新增 / 编辑端点打开紧凑 D-13。模型列表“展开编辑”或“编辑明细” → 协议继承 / 自定义与指定端点；批量编辑按字段保留 / 继承 / 自定义协议；模型模版“编辑候选” → 同一协议规则。渠道详情左侧底部“查看草稿”及保存确认展示协议写入计划。渠道连接表单直接展示，未确认连接和行编辑需先确认或还原；缺对应端点可保留草稿，正式保存前阻止继续并提示补齐。对应 D-13 / W-13，布局更新见[渠道分区记录](../06-版本记录/20261005-列表操作与渠道详情分区.md)。

新增 AC-M75～M80、技术门 G-10，承接 WP-01～06。完整条件见 [验收矩阵](../../03-测试验收/README.md) 与 [逻辑审计](../03-确认与评审/协作包逻辑审计.md)。本轮源码状态检查不替代真实 adapter 路由、凭据分组、稳定绑定 / 旧会话、推理 / Fast、目录读回、跨机绑定或视觉 / 焦点验证。

## 8. 原始 ID 与命名策略

协议编译、后缀匹配、发现、选择及顺序均以渠道内上游原始 modelId 为身份，不按别名 / 显示名称判断能力。单模型 `naming` 为候选便携字段；编译后按实际 provider 写 raw ID → `modelAliases` / `modelDisplayNames`，本机 2.69.0 的合法字符、保留前缀和冲突限制见 [命名依据](本地调研依据.md#模型别名与显示名称核对2026-10-04)。别名用于路由短名，显示名称用于目录提示；别名请求在路由前还原 raw ID，不修改上游请求模型名或协议。

共享原型已加入列表别名编辑、明细显示名称和批量别名，校验非法字符、保留前缀、大小写重复与原始 ID 冲突；草稿差异、导入导出保留 naming。生产仍须验证真实目录条目数、Fast 派生、稳定身份与旧会话，不假定别名天然不占预算或修复迁移。AC-M94 仍归 G-10；未写运行配置或测试真实客户端别名。
