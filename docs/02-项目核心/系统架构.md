## 2. 分层

```text
┌─────────────────────────────────────────────┐
│ 前端界面层                                    │
│ 概览 / 面板 / 拓展 / 日志与诊断 / 设置 / 托盘   │
└──────────────────┬──────────────────────────┘
                   │ 命令调用（Tauri IPC）
┌──────────────────▼──────────────────────────┐
│ 管理器后端（Rust）                             │
│ 发现 · 进程托管 · 状态 · 日志 · 迁移 · 同步     │
│ 扩展管理 · 更新 · 数据根 · CLI/IPC · 通知       │
└──────────────────┬──────────────────────────┘
                   │ 子进程 / 文件 / 网络
┌──────────────────▼──────────────────────────┐
│ 外部依赖                                      │
│ ocx CLI · 官方 Web 面板 · 各客户端配置文件      │
│ WebDAV 远端 · 应用自身更新通道                 │
└─────────────────────────────────────────────┘
```

**后端独占外部访问**：前端不直接触碰文件系统与网络，所有外部访问经后端模块。这是一条硬边界，不是风格偏好。

## 3. 组成部件

| 部件 | 职责 |
|---|---|
| 桌面壳窗口 | 承载界面、标题栏、侧栏与全幅面板视图；约束在 macOS 应用窗口尺寸内 |
| 管理器后端 | 全部业务逻辑与外部交互；前端不直接访问文件系统与网络 |
| 托管子进程 | 由后端启动并持有的官方 `ocx` 进程 |
| 本机 IPC 端点 | 可选 CLI 控制面与运行中实例之间的通道 |
| 数据根 | 管理器自有产物的统一落点（见 `数据与状态.md`） |
| 官方 Web 面板视图 | 承载官方 GUI，不重绘、不注入；**原型**以源码级快照承载，快照不随仓库分发也不进发布包，**生产承载方式待冻结**（`R-17`） |

## 4. 模块划分

模块与能力域一一对应，便于从能力追溯实现。模块编号稳定，不随排序变化。

| 模块 | 名称 | 能力域 | 职责 | 主要输入 | 主要输出 |
|---|---|---|---|---|---|
| `MOD-01` | 发现模块 | `DOM-01` | 前置条件门禁、安装发现与可执行校验 | 本机命令存在性、安装路径 | `Installation`、`EnvironmentGate` |
| `MOD-02` | 进程托管模块 | `DOM-03` | 启停子进程的调用、超时、退出码与错误摘要 | 用户动作、确认结果 | `AgentProcess` |
| `MOD-03` | 状态模块 | `DOM-03` `DOM-05` | 官方状态命令的采集、字段映射与三维状态维护 | 官方状态输出 | 运行状态取值、风险摘要 |
| `MOD-04` | 日志与诊断模块 | `DOM-04` | 日志读取、脱敏、日志目录打开、Doctor 只读摘要 | 本地日志文件、官方 doctor 输出 | 脱敏日志视图、诊断摘要 |
| `MOD-05` | 面板模块 | `DOM-04` | 官方 Web 面板视图的承载与失败回退 | 原型阶段为官方页面快照；生产承载方式见 §1 | 面板视图 |
| `MOD-06` | 数据根模块 | `DOM-02` | 数据根的选择、检查、引用或迁移、备份 | 目标路径、检查结果 | `DataRoot`、`BackupRecord` |
| `MOD-07` | 迁移模块 | `DOM-06` | 加密容器的导出、校验、导入与回滚 | 全量配置、口令、容器文件 | `ExportContainer`（契约对象）、`BackupRecord` |
| `MOD-08` | 同步模块 | `DOM-07` | WebDAV 的加密、清单、冲突与覆盖前备份 | 端点与凭据、本地载荷 | `SyncManifest`（契约对象）、`SyncRun`、`Conflict` |
| `MOD-09` | 扩展管理模块 | `DOM-11` | Skills 与 MCP 的读取、投影与受控写入 | 统一扩展配置、启用矩阵 | `Skill`、`McpServer`、`McpServerProjection`、`ClientTarget`、`WriteTransaction` |
| `MOD-10` | 更新模块 | `DOM-08` `DOM-09` | 官方升级引导与应用自更新（两条独立通道） | 版本偏差、更新包 | `UpdateTarget`、备份与回滚结果 |
| `MOD-11` | 通知模块 | `DOM-04` | 通知的产生、存储、聚合与清理 | 各模块事件 | `Notification` |
| `MOD-12` | CLI / IPC 模块 | `DOM-10` | 命令解析、本机 IPC 委托、机读输出与访问控制 | `ocxd` 命令 | IPC 响应、`--json` 输出 |
| `MOD-13` | 托盘与菜单模块 | `DOM-12` | 托盘菜单与原生菜单入口 | 运行状态 | 菜单项与状态图标 |

> **契约对象 vs 领域实体**：`ExportContainer` 与 `SyncManifest` 是**跨边界契约对象**，字段定义在 `契约字段.md`，不在 `领域模型.md`；它们不参与内存态流转，只以「写入磁盘 / 发往远端」的格式存在。其余输出均为领域实体，定义见 `领域模型.md`。
>
> `MOD-11` 通知模块不单独占能力域：`DOM-04` 的 `CAP-4.4` 由它实现。`DOM-13` 关于与归属为界面内容，无独立模块。

## 5. 运行时与进程模型

| # | 对象 | 说明 |
|---|---|---|
| 1 | 管理器进程 | 即桌面应用本体；持有界面、后端逻辑与托管子进程 |
| 2 | 托管子进程 | 官方 `ocx start / stop / restart` 由其直接启动与持有；进程标识与退出码进入状态展示 |
| 3 | CLI 客户端 | `ocxd` 不独立执行能力，而是连接运行中实例的**本机 IPC 端点**委托执行；实例未运行时不得绕过实例直接改状态 |
| 4 | 重启语义 | 应用自更新会重启应用本体，但**不停止**托管中的 OpenCodex 代理；重启后重新接管并恢复状态展示 |
| 5 | 离线语义 | 代理离线时，依赖实时能力的功能（如实时日志）明确标注不可用，本地历史日志与日志目录仍可用 |
| 6 | 超时与取消 | 启动 20 秒、停止 10 秒；`pending` 为端口可达但就绪检查失败；取消等待系统调用结束，不强制杀进程（`FZ-10`） |
| 7 | 并发锁归属 | 扩展写入先取 `<数据根>/manager-state/app.lock`，再按目标文件取 `<target>.lock`；`flock` 超时 3 秒（`FZ-26` / `FZ-39`） |

进程数量约束：**同一时刻只允许一个管理器实例持有托管子进程与 IPC 端点**，避免出现第二写入者。

## 6. 主要数据流

### 6.1 状态采集

```text
托管子进程 / 官方状态命令
→ MOD-03 采集与字段映射
→ 三维状态（运行 / 连接 / 操作）
→ 前端按状态渲染动作与说明
```

字段映射规则（官方输出 → UI 枚举）留 IMP 冻结；状态枚举本身见 `数据与状态.md`。

### 6.2 受控写入（扩展管理 / 迁移 / 同步共用）

```text
用户动作
→ 前置校验（目标合法性、路径边界、冲突比对）
→ 备份（失败即阻断）
→ 临时区写入 + 原子替换
→ 重新校验
→ 成功 / 回滚
```

规则字段见 `集成与安全边界.md` 的写入事务；事务实体字段见 `领域模型.md` 的 `WriteTransaction`。

### 6.3 CLI 委托

```text
ocxd 命令 → 本机 IPC 端点 → 调用方校验 → 实例在线检查
→ 执行管理器自有域操作 → 文本 / --json 输出（敏感值掩码）
```

## 7. 架构级约束

| ID | 约束 | 含义 |
|---|---|---|
| `ARC-01` | 单一真相源 + 投影 | 管理器维护统一事实，客户端配置是投影，不是权威 |
| `ARC-02` | 只改目标节点 | 结构化读改写，保留未知字段与注释；不整文件重建 |
| `ARC-03` | 原子写 | 同目录临时文件 + 原子替换；替换后保留原文件权限 |
| `ARC-04` | 备份先行 | 任何可能覆盖数据的写入前必须生成可恢复备份 |
| `ARC-05` | 跨进程互斥 | 与官方 CLI、编辑器共享同一批配置文件，写入需跨进程文件锁与内容摘要比对 |
| `ARC-06` | 凭据不出域 | 凭据不进日志、命令行参数、错误信息与未加密文件 |
| `ARC-07` | 后端独占外部访问 | 前端不直接触碰文件系统与网络 |
| `ARC-08` | 动作按状态渲染 | 界面按三维状态渲染动作，不渲染无解释的禁用按钮 |
| `ARC-09` | 未安装不落盘 | 目标客户端未安装时跳过写入与删除，不创建任何文件或目录 |
| `ARC-10` | 不制造第二写入者 | **官方拥有写入权的核心运行配置一律不写**；**MCP 扩展节点允许受控共享写入**——靠跨进程文件锁 + 摘要比对 + 备份 + 原子替换 + 冲突待处理，**不靠独占**。六个客户端的 MCP 节点都有官方写入者，这一点不可回避 |

## 8. 外部依赖

| 依赖 | 用途 | 关系的权威归属 | 失败时的行为 |
|---|---|---|---|
| 官方 `ocx` CLI | 启停、状态、诊断、升级 | 官方；本产品只调用与引导 | 明确报错与原因，不伪造成功 |
| 官方 Web 面板 | 面向用户的官方界面 | 官方；本产品只承载视图 | 区域内给重试与「在浏览器打开」 |
| 各客户端配置文件 | MCP 与 Skills 落点 | 共享节点；本产品受控写入扩展配置 | 冲突进入待处理，不静默覆盖 |
| WebDAV 远端 | 跨机同步目标 | 用户指定的端点，视为**不可信** | 进入 `failed`，本地不变 |
| 应用自身更新通道 | 桌面应用升级 | 本产品自有 | 保留可回滚的上一版本 |
