## 1. 产品目标与现状

日志由用户按来源选择，不再根据运行风险自动切换文件。以低常驻内存、按需读取、来源明确为原则。

2026-09-23 已实施：日志页在「日志历史」内新增「应用日志 / 调用日志」分类并附「面板请求日志」入口；选择分类即按该分类读取，不再由运行状态决定文件。
日志与 doctor 输出改为**纯文本渲染**（原 `v-html` 已移除），不再有 HTML 注入面。
仍未做：读取器的总读取字节硬上限（当前仍只有行数上限）。
此前“读取开销为零”的说法不准确：文件缓冲、JSON 解析和界面显示均占用内存。

## 2. 首期分类与来源

| 分类 | 来源 | 展示内容 | 可用边界 |
|---|---|---|---|
| 应用日志 | 管理器数据根 `logs/app.log` | 最近的管理器操作、启停结果；保留原始文本与换行 | 文件存在即可，代理停止不影响查看 |
| 调用日志 | 与审计写入器一致的活跃数据根 `audit.log` | 时间、命令、调用来源、执行结果；未知字段以“—”显示 | 只代表已接入 IPC 审计的调用，不宣称覆盖所有界面操作 |

代理请求、模型调用、耗时、用量与请求错误由官方面板负责；管理器不重复实现列表、筛选与详情，不调用 `ocx logs`、不直接读取 `usage.jsonl`、不新增请求日志缓存。

首期不新增同步日志、代理标准输出采集、全文搜索、实时追踪和历史分页。
`agent.log` / `sync.log` 无独立写入方时不提供误导性的空分类。

### 已核实事实与限制

- 本机官方包版本 2.50.0：`src/cli/observe.ts` 支持 `--limit`（默认 200）与 `--json`，不带 follow 时查询一次后返回；经 runtime API 请求 `/api/logs`。
- 官方 `src/usage/log.ts` 存在 `usage.jsonl` 追加写入；`src/server/request-log.ts` 可用持久化记录恢复请求日志。因此不能宣称官方完全不落盘日志。
- 上述官方日志能力仅用于确认职责归属，不作为管理器首期读取接口。官方面板能否稳定直达“日志与调试”尚待核实；未核实前只导航到面板，不承诺精准跳转。
- 审计写入器：`apps/desktop/tauri/src/modules/ipc/audit.rs`；其调用方 `modules/ipc/service.rs` 传入 active_data_root。当前日志读取器统一拼接管理器数据根 `/logs/`，不能直接用于审计分类。
- 应用读取：`apps/desktop/tauri/src/commands/logs.rs`；读取算法：`modules/logs/mod.rs`；页面：`apps/desktop/ui/src/routes/LogsRoute.vue`。

## 3. 界面与交互

### 诊断中心的第一层 Tab（2026-09-24 修订）

**环境诊断｜日志历史｜通知历史**——三个 Tab 共处一张内容卡，`环境诊断` 是**第一个** Tab（四个字）。

- 用户要求（2026-09-24）：「运行环境诊断」原本是日志页下方的一张独立卡片，改为诊断中心的第一个 Tab；托盘 / 概览 / 设置的「运行 Doctor」入口一律切到该 Tab 再运行，否则用户看不到结果。
- **环境诊断**：调用官方 `ocx doctor` 的只读摘要（默认只读，不修改配置、不设置代理、不改网络）；写入型修复参数不在应用内提供。内容 = 卡片标题 + 只读说明 + 「环境诊断」按钮 + 摘要输出 + 写入型修复提示 + 「界面异常自检」。
- **默认落地页是「环境诊断」（第一个 Tab）**（2026-09-28 用户要求，取代 2026-09-24 的「日志历史」口径）：进入诊断中心先看到只读的环境诊断；`#logs?tab=logs` 可直达日志历史。
- **界面异常自检**（2026-09-28）：环境诊断面板内提供「界面诊断」按钮，主动触发一次受控界面异常，走真实错误边界（Vue `errorHandler` → `reportUiFault`）置位顶部兜底条（`.ui-fault`），用于验证「关闭提示 / 重新加载界面」恢复动作；只在本次会话生效，不写配置、不改数据，可重复执行。
- 非法 / 缺失的 tab 取值一律回落**环境诊断**。
- **命名**：左侧导航短名 = `诊断`（2 字）；页面标题与入口动作用全名 `诊断中心` / `打开诊断中心`。不再用「日志」指代本路由（见 `UI规范.md` §11.2、`术语与命名.md`）。

在日志历史内增加：

**应用日志｜调用日志**

分类区右侧提供轻量入口“在官方面板查看请求日志”，不是第三个分类：

- 代理运行时进入应用内既有官方面板；未验证直达能力前提示“请在面板中选择『日志与调试』”。
- 代理未运行时点击给出说明“代理未运行，请先启动后查看”，不自动启动、不切走当前日志分类。
- 面板加载失败时沿用既有失败与重试反馈，不伪装成请求日志为空；两类本地日志仍可查看。
- 本入口不新建窗口、不新增 WebView、不后台预加载官方面板。

- 首次进入默认应用日志；当前页面内保留用户选择，运行状态变化不得替用户换分类。
- 进入或切换分类时读一次，提供“刷新”，显示来源、条数、最近读取时间和截断提示。
- 只保留当前分类的结果；切换时取消旧请求或忽略迟到结果，避免串类。
- 同时最多一个有效读取任务，连续刷新不叠加；离开页面停止读取并释放页面数据。
- 无后台轮询、无 `--follow`、无常驻 tail、无跨分类预加载和缓存。
- 应用日志以纯文本显示；调用日志使用紧凑表格，**执行结果只显示状态标识**（不加虚线、不加提示文字等冗余修饰），完整详情在**鼠标悬停（或键盘聚焦）时以浮层显示**——不就地展开、不改变行高；浮层只用当前已取得的数据，不额外加载完整日志。
- 来源说明用可读名称及脱敏路径；界面不暴露凭据，不把技术参数作为普通用户操作项。
- 取消跨分类自动回退。不可用时可提供“查看应用日志”，由用户主动切换并更新选中项。
- 保留通知历史和 Doctor 的既有职责，不将通知、诊断结果混入两类本地日志。
- 不恢复原型已移除的“打开日志目录”按钮；目录入口保留在设置中的既有位置。
- 不给两类本地日志共用“清理全部”动作。现有清理日志入口只在应用日志下保留，并如实说明现有本地日志分区清理范围；不得扩展到官方请求数据或活跃数据根审计文件。

### 状态文案

> 命名口径：界面上的**分类显示名**是「调用日志」；它与契约里的机制名（`FZ-40` 调用审计）、文件名（`audit.log`）**不是同一个东西**，改名不涉及文件与契约。

| 状态 | 示例与动作 |
|---|---|
| 首次读取 | 正在读取应用日志…；刷新中不得重复发起任务 |
| 成功 | 最近 200 条 · 更新于 14:30:00；显示真实来源 |
| 空内容 | 暂无应用日志记录 / 暂无调用日志记录 |
| 文件缺失 | 尚未生成应用日志文件 / 尚未生成调用日志文件 |
| 面板入口：代理停止 | 代理未运行，请先启动后查看；不自动启动，当前本地日志不受影响 |
| 面板入口：可用 | 进入应用内官方面板；未验证直达能力前提示选择“日志与调试” |
| 读取失败或超时 | 本次读取失败，请重试；说明当前显示的旧内容是否已过期，不跨类替换 |
| 截断 | 内容超过本次显示上限，已截断；不声称展示完整历史 |

## 4. 低内存约束（设计值，待实测）

- 最多 200 条；单次文件读取最多 1 MiB；单条展示最多 8 KiB。
- 字节限制须在读取流中执行，不能先读完整文件再截断。
- 本地读取设置有界超时（首期建议 5 秒）；超限、超时或取消后停止继续读取并释放资源，不影响官方 daemon。
- 管理器不查询或保存代理请求/响应正文；本地日志仅显示必要记录，显示前脱敏。文本使用转义渲染，不执行日志内 HTML。
- 不新增写入器、索引数据库和常驻日志组件；不改变现有轮转策略。
- 上述大小不等于进程 RSS 上限。本地读取与渲染峰值、打开官方面板的额外开销须分别测量，不能宣称“零内存”或“最省内存已验证”。

## 5. 原型范围与验收

原型使用明确标记的虚构数据，不读取用户文件、不启动代理、不调用真实清理。
演示状态选择器放在独立演示工具区，不进入正式产品导航；时间、路径、记录均为示例。

原型须覆盖两类切换、刷新、调用日志详情悬停浮层、长行、截断、加载、空记录、缺文件、失败与超时；另覆盖面板入口可用、代理未运行和面板加载失败。
删除管理器侧代理请求标签、表格、演示记录及命令不支持等查询专属状态；官方面板原有请求日志功能保持不变。旧三分类截图与验证记录保留为历史，不作为新方案验收证据。
保持现有亮暗主题、圆角内容页、侧栏和缩放机制；以 1180×760 及现有最小窗口检查布局。

后续真实验收：

1. 两类各读真实来源，特别检查审计活跃根与管理器根不同的情况。
2. 面板入口复用既有面板路由；代理停止不启动服务，风险状态不阻断应用/审计读取、不改变所选分类。
3. 快速切换、连续刷新、离开页面均不串数据、不遗留读取任务。
4. 大文件、超长单行与超大审计 JSON 行按字节限制停止；截断不破坏界面。
5. 日志中的 HTML 以文字显示，凭据及 URL query 被脱敏。
6. 测量进入前、读取峰值、切换后、离开后的内存和读取任务状态。
7. 原型演示、单测通过与真实功能验收分别记录；未真实验证不得标记完成。
