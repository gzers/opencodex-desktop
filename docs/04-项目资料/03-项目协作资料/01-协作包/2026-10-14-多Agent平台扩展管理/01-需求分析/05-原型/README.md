## 2026-11-01 扩展页去掉外层滚动条

用户指出扩展业务页的主区 main.main 出现外层滚动条，而左右两个列表已经各有滚动条，要求外层不再滚动。改动只在唯一总原型的 [extension-manager.css](../../../../../01-项目支撑资料/01-产品原型/原型/extension-manager.css) 末尾追加一段样式，以及 index.html 中该文件的缓存版本（v=20261101-noscroll）。公共组件 interactive-collection.css / .js、extension-manager.js、生产代码、契约和本机配置都没改，没有新建原型目录。

原因在公共样式 [interactive-collection.css](../../../../../01-项目支撑资料/01-产品原型/原型/interactive-collection.css) 第 25 和 27 行混入的两条扩展页规则：列表区高度写成 clamp(360px, 100vh − 350px, 560px)，整页限高写成 100vh − 170px 并自带滚动。原型的软件窗口是固定尺寸的模拟窗口（默认 1180 × 760），这两条规则却按浏览器视口高度计算，视口和窗口不一致时就会算错：视口偏高时内容超出主区，出现外层滚动条；视口和窗口接近时，页脚下方又留出空白。

新规则在扩展页可见时把主区改为纵向 flex 并关闭外层滚动。顶栏、模式条、提示和页脚按内容取高，中间两栏占满剩余高度，滚动只发生在两个列表内部。选择器用 html[data-route="extensions"] 加 :has(#extensionManagerContent:not([hidden])) 限定，其他页面的主区仍是原来的 block 加 auto 滚动；写法与同步页 sync-config.css 第 3 至 4 行一致。

改前和改后实测如下，取按扩展 · Skills 视图。“外层多出”是主区 scrollHeight 减 clientHeight，大于 0 就有外层滚动条；列表高为列表可视高度，单位 px。

|---|---|---|---|---|---|
| 窗口 1180 × 760（默认） | 0 | 77 | 284 | 0 | 360 |
| 窗口 900 × 600 | 224 | — | 424 | 0 | 200 |
| 视口 1898 × 1128（批注时的尺寸） | 74 | — | 434 | 0 | 360 |
| 窗口 1600 × 900 | 0 | 67 | 434 | 0 | 500 |

改后各尺寸的页脚都贴住主区底边，1 px 差值来自边框。读取失败场景多一行提示，列表高度在 1180 × 760 和 1898 × 1128 下为 332，900 × 600 下为 172，1600 × 900 下为 472。

实屏检查在目标模式下用 Playwright 无头 Chromium 实际操作，覆盖 1180 × 760 浅色与暗色、900 × 600 窗口、1898 × 1128 视口和 1600 × 900 窗口五组。每组检查四个视图（按扩展 / 按平台 × Skills / MCP）、读取失败 / 空结果 / 恢复正常、平台数量 6 与 50、三个详情弹窗、切到概览 / 模型 / 设置再切回，并用真实滚轮确认滚动的是列表、主区不动。合计 505 项全部通过，控制台 error 为空。第一次运行有 15 项滚轮检查失败，原因在检查脚本：视口宽 1180 或 1440 时原型外壳把工具板排到软件窗口下方，浏览器页面本身可以整页滚动，第一次滚轮把整页滚走，后面的滚轮落点就偏离了列表；用改前样式复测也是这样。脚本改为每次滚轮前先把页面滚回顶部，之后全部通过，样式没有因此改动。上一轮右表批量按钮的 304 项检查用新样式重跑，全部通过。Node 回归 34 项通过，比上一轮多出的 3 项来自这次一并运行的 tree-table.test.cjs，其余 31 项与上一轮相同。证据见[浏览器检查](../../../../../../../.adg/evidence/COL-LOCAL-20261014-01/main-no-outer-scroll-20261101/browser-checks.json)、[改前改后实测](../../../../../../../.adg/evidence/COL-LOCAL-20261014-01/main-no-outer-scroll-20261101/before-after-metrics.json)、[批量按钮回归](../../../../../../../.adg/evidence/COL-LOCAL-20261014-01/main-no-outer-scroll-20261101/regression-bulk/browser-checks.json)、[Node 回归](../../../../../../../.adg/evidence/COL-LOCAL-20261014-01/main-no-outer-scroll-20261101/node-tests.txt)和[截图目录](../../../../../../../.adg/evidence/COL-LOCAL-20261014-01/main-no-outer-scroll-20261101/screenshots/)。

限制有三点。interactive-collection.css 里的两条扩展页规则这次只是被覆盖，仍留在公共文件中，以后整理时建议移到 extension-manager.css。900 × 600 最小窗口下列表可视高度只有 200 px，读取失败时为 172 px，这是窗口本身的空间。浏览器视口比原型工具板窄时，原型外壳会把工具板排到软件窗口下方，整个浏览器页面可以滚动，这是外壳本身的布局，和软件窗口里的主区无关，本次未改。仍为内存 mock，版本与开发时机未定。

## 2026-11-01 列表最小高度与外层滚动兜底

用户看过上一节的改动后要求给列表规定最小尺寸，并说明空间不够时出现外层滚动条无法避免，可以接受。用户原话是“需要规定最小版本”，这里按“最小尺寸”理解。规则因此变为：正常情况下仍只有两个列表各自滚动；列表会被压到最小高度以下时，列表停在下限，改由主区出现纵向滚动条。

## 2026-11-04 Agent 平台默认选中并决定拓展同步范围

用户补充：默认选中 Agent 平台；没有选中平台就不应同步 Skills / MCP。本节取代前文“平台默认不选”和“可不选择平台而独立同步拓展内容”的规则，保留平台只读路径 / 映射结果、只列已发现平台及未映射不阻止同步的规则。采用入口仍为[同步](../../../../../01-项目支撑资料/01-产品原型/原型/index.html#sync?tab=webdav)与[拓展](../../../../../01-项目支撑资料/01-产品原型/原型/index.html#extensions)的唯一总原型。

- Agent 平台分组放在 Skills / MCP 之前，首次对本机已发现平台默认全选；原型当前为 24 项。后续沿用文件 / WebDAV 各自的选择，刷新页面内存复位。不因刷新范围、检测或手动加入重新覆盖用户取消的选择，新发现项不额外自动扩大已记忆范围；未发现仍不显示。
- 两层含义：Agent 平台选择本次涉及哪些平台，Skills / MCP 选择传输哪些内容。取消全部平台时内容对象不进入有效范围、预览、导出载荷和凭据清单，内容复选框与分组选择禁用，明确提示“未选择 Agent 平台，本次不同步 Skills / MCP；其他配置可继续同步”。不删除用户已有资源或配置。
- 内容和凭据勾选保留为本机偏好；重选任一平台恢复之前的内容选择。取消单个平台仅缩小平台范围，不自动取消其他内容。隐藏搜索选择沿既有规则保留；父组全选 / 取消仍仅影响当前显示结果。页面顶层清空可清除全部范围。
- 同步不要求先映射。已发现但未映射的平台默认可选，内容保存仍能完成；使用该平台 Skills 前需检查并映射目录，不通过同步创建链接。安装和映射事实、绝对路径不进入载荷。
- MCP 定义仅带所选平台的启用关系。导出与上传过滤未选平台关系，下载 / 导入只合并所选平台关系，目标设备中未选平台启用位保持；共享 MCP 定义内容仍是同一对象。同步预览冻结平台列表，后续改选择需要重新预览；执行中改勾选只影响下一次，失败重试沿原冻结范围。
- Skills 使用单一共享源，按 Skill 对象只保存一次，不重复打包映射目录。所选 Skill 的内容 / 全局启用变化会影响本机所有已映射平台，不能把未选平台误说成有独立的 Skill 副本；预览明确说明这一点。Agent 平台勾选主要限定关联范围和是否参与本次拓展同步，不改写共享源结构。
