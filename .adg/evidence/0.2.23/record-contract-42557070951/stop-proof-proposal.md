# 本HOME停止证明方案草案（未采用）

来源：local-active-sessions-20261109/status-table.md、c0196df01的runtime_recovery_v2_owner.rs。仅记录边界与待验证设计，不声称已实现，不授权替换names.2维护包。

## 为什么不能直接跳过

当前有本H记录时，先验证运行PID、SID、创建时间、映像、argv与OPENCODEX_HOME。官方停止成功后，原PID、socket与运行记录消失，再扫描全机runtime形态进程以排除本H仍存活的实例。未知身份对象不可读时，无法由名称或会话判定它是无关对象，直接跳过会弱化现行证明。仅凭原PID已退出、监听暂时缺席或tasklist成功也不足够。

## 拟验证的完整替代证明

1. 新版运行包在任何支持的本H服务启动路径进入之前，获取本H受保护的排他运行租约，并让它绑定实例随机代次、真实SID及实际进程生命期。不能只写一个可遗留的JSON文件当锁；需明确Windows内核句柄、共享模式、原子获取和崩溃释放机制。
2. 管理器保留已认证原服务代次的实际进程句柄；PID/FILETIME/SID/映像/argv/H前后核对，不把重新打开的同PID当原实例。CLI或代理派生的必要进程要有不可逃逸的受控集合证明，不能仅用parentPID追溯。若确需Job Object，必须验证实际Bun/Node分离和后继进程均纳入，不能启用kill-on-close来假停或中断客户端还原。
3. 普通Stop仍发同连接认证的官方POST，并只接受客户端还原performed或有真实所有者证明的not-owned；不使用deferred代替还原。还原结果未知不清理记录、不标成功。
4. 官方响应完成后，在原10秒总门内证明保留原句柄已退出、受控集合已空、原port无监听、本H运行记录/PID无新代次、排他租约可在原子观察中证明无活跃持有者，并确认官方服务命名空间不能respawn本H。任何一个证据未知继续失败。
5. 租约与记录的观察应防止“退出后立刻另一个本H服务启动”的竞态。获得租约用于观察的过程不得阻断正在还原的原服务、删除状态或趁间隙误认停止；须明确租约接管点和新代次比较。
6. 只对采用该完整新协议、且身份与固定运行包契约均验证的启动方式使用该证明；缺租约、未知旧进程或非受控启动继续未知。本版不扫描旧路径或自动迁移，不把协议缺席当无服务。

## 必须先补的反例

- 同PID替换、映像/FILETIME变化、另一SID、另一H共享安装前缀，均拒绝授予停止权。
- 本H租约仍持有但record缺失、父CLI退出而服务存活、子进程脱离Job、租约传递失败、进程不可读，均不能Stopped。
- 官方还原失败/超时/仅deferred、端口被另一对象占用、record在观察中换代、停止后马上重启本H，均保持失败或未知。
- 外SID不可读对象只有在本H完整租约/原句柄/受控集合证明闭合后，才不属于该范围；禁止按会话或名字预先跳过。
- 一方Stop成功时另一SID的PID代次、端口、HMAC健康和真实配置保持。真实控制台提升与非提升RDP分别验证；管理员组未提升不等于标准账户覆盖。

## 当前决定

暂不实现替代证明，不改停止断言。先用提升记录隔离诊断确认另一缺口，并核实原版运行包是否已有可复用的生命周期租约/受控进程机制。若现有协议无法满足，形成具体维护包修订补丁与验证清单，再按目标边界说明采用；不能以探索草案代替用户知悉或验收。
