## 现象与范围

0.1.2 只完成了更新通道与配置分层的 A/B 最小闭环。以下四项仍为占位或未实现（详见 MNT-02 的 [分析/01](../20261004-更新通道与配置分层/分析/01-更新通道现状与证据.md) 与 [分析/03](../20261004-更新通道与配置分层/分析/03-0.1.2-候选范围与待决策.md)）：

1. **U-01/U-02 桌面管理器自身自更新**：`tauri.conf.json` 的 `endpoints` 与 `pubkey` 仍为占位，无签名制品管线，应用未接通真实自更新。
2. **U-03 官方版本卡片只读远端查询**：设置页卡片只执行本地 `ocx --version`，从不比较远端版本。
3. **U-04 代跑官方更新**：官方本体更新仍需用户去终端执行；官方面板内置更新器对托管 / 自定义前缀不安全。
4. **C 阶段存储迁移**：磁盘嵌套化、容器 / 同步 schema 迁移未执行。

## 已确认的用户裁决（2026-10-04）

| 编号 | 裁决 | 含义 |
|---|---|---|
| D-1 | **同意方案 A** | 自更新端点指向本仓库 GitHub Releases（`latest.json` / `.sig` 作为 Release 资产）；公钥用 `tauri signer generate` 生成，私钥进 CI secrets，公钥作为编译期常量 |
| D-2 | **同意** | 授权在 CI 使用 `TAURI_SIGNING_PRIVATE_KEY` 产出签名制品 |
| D-3 | **同意方案 B** | 官方版本卡片新增只读远端查询（`npm view @bitkyc08/opencodex@latest version` + `dist.integrity`），显示「有可用更新」 |
| D-4 | **代跑官方更新** | 桌面管理器复用已有受控 `install_runtime` 代跑官方面板更新，**不**代理官方更新器去改托管 / 自定义前缀 |

## 冻结范围（0.1.3，2026-10-04 用户确认）

| 编号 | 候选事项 | 类别 |
|---|---|---|
| U-01 | 桌面自更新使用真实端点（本仓库 Releases），端点有版本默认且可受控覆盖 | 更新通道 |
| U-02 | 生成 minisign 公私钥；公钥编译期固定；CI 产出并发布签名 `latest.json` / `.sig`（`createUpdaterArtifacts` + `TAURI_SIGNING_PRIVATE_KEY`） | 更新通道 / CI |
| U-03 | 官方版本卡片新增只读远端查询（`npm view`），与本地/运行版本比较出「有可用更新」；查询与安装分离 | 产品语义 |
| U-04 | 外部安装官方更新：复用 `install_runtime`（`source=registry, version=<tag>, prefix=当前登记前缀`），沿用离线包 / 代理 / `.runtime-manifest.json` / 重启提示等既有安全路径 | 更新通道 |
| U-04b | 官方更新候选绑定所检查的版本与来源；查询与安装共用同一来源策略，不浮动 `latest` | 更新通道 |
| C | 配置存储 schema 迁移（磁盘嵌套 + 容器 / 同步兼容投影） | 配置 / 兼容 |
| U-05 | 网络代理配置（通用 → 网络卡片，参考 JetBrains；无代理/自动(系统)/手动 HTTP|SOCKS5 + 例外列表，无鉴权）+ 版本升级 tab 快捷跳转 | 网络 / UI |
| U-05b | 独立网络行为配置文件 `config/network.defaults.json`（开发规定，暂不开放） | 配置 / 网络 |

## 冻结说明（2026-10-04）

用户确认 **U-01～U-04 + U-05/U-05b + C 阶段全部纳入 0.1.3**；网络代理**不使用系统钥匙串**，本版不做代理身份验证；「自动检测」= 读系统代理设置。以上为 0.1.3 冻结范围，实施计划另建 IMP。

### 需要单独确认的发布安全操作

- 生成签名私钥、把私钥写入 GitHub secrets（`TAURI_SIGNING_PRIVATE_KEY`）属发布安全操作；实施到 U-02 时需再次单独确认。
- 发布 `0.1.3`（打包 / 公开发布）沿用既有单独确认流程。

## 验收标准（0.1.3 草案）

1. 前后端门禁全绿；C 阶段若纳入，须通过配置兼容与故障恢复测试。
2. 自更新：真实端点可解析 `latest.json`；签名校验通过后才安装；失败保留可回滚的上一版本；stable/beta 通道生效。
3. 官方版本卡片：远端查询带超时与失败不改写本地状态；查询与安装对象一致。
4. 代跑官方更新：走受控 `install_runtime`，落在当前登记前缀，写 `.runtime-manifest.json`，不写全局 npm 前缀；完成提示与托管代理重启符合现状。
5. 真实安装实例核验；结果回写 `REL-*` / `RUN-*`。
