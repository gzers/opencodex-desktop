# C：口令简化与兼容

入口：[实施计划](../IMP-OPENCODEX-DESKTOP-02.md)。本阶段调整的是额外内容加密口令，不取消 WebDAV 服务端认证。

## 目标行为

- 新导出：选择目标并导出，无额外口令。
- 新导入：选择文件、验证格式、展示影响并确认应用，无额外口令。
- WebDAV：保留服务器、路径、账号和应用密码；新同步流程无额外加密口令。
- 新配置内容不再依赖用户口令加密；产品说明直接写明文件或远端保存未加密配置，不暗示仍有端到端加密。
- 真实凭据留在本机凭据存储；其他设备缺少凭据时提示重新认证。

## 实施前形成兼容决策

有界检索原 IMP 与项目核心中涉及容器、加密、同步、凭据和 CLI 的段落。以本轮用户意见为变更依据，记录旧条款、新行为及受影响文件，在交付前同步有效规范，保留历史来源。

| 对象 | 必须确定的策略 |
|---|---|
| 新导出格式 | 格式标识、版本、字段白名单、大小限制、校验、文件权限 |
| 旧加密导出文件 | 自动识别；仅旧格式请求原口令；错误口令不改变现有配置 |
| 新同步格式 | 清单与载荷版本、完整性校验、并发控制和快照提交顺序 |
| 旧加密远端 | 可读取或明确隔离迁移；转换前保留原快照，验证后才切换 |
| 混合版本客户端 | 不支持新版本时明确拒绝；不能误读或静默覆盖 |
| 旧本机口令 | 兼容读仍可能使用；不提前删除导致历史内容不可恢复 |
| CLI | 新格式不强制 `--password-stdin`；明确旧格式的兼容参数和错误行为 |

普通摘要校验用于检测损坏，不是防恶意篡改的身份认证。不要在删除加密后保留不再成立的安全承诺。HTTPS 与服务端认证继续保留。

## 代码改动范围

按调用链核查 `SettingsRoute.vue`、store、前端 migration/sync commands、Rust DTO 与 commands、migration/container/sync/preferences 模块、keychain、IPC service、`ocxd`、帮助文案和测试。

核实所有实际导出／同步载荷，尤其是扩展配置中可能包含的 token、环境变量值和认证字段。明确白名单和排除规则；不得简单序列化完整运行配置。凭据引用不能被当作可跨设备使用的秘密本身。

保留现有备份、格式校验、路径约束与失败回滚。多文件应用应先全量验证，再执行受控提交；中途失败必须避免混合新旧状态。不要通过忽略校验来实现免口令。

## 验收矩阵

- A 隔离环境导出，B 隔离环境导入，逐项比较声明支持的字段；排除字段明确说明。
- 新格式全流程不索要额外口令；取消文件选择不产生写入。
- 旧格式正确口令可读；错误／缺失口令、损坏／未知版本均不修改原配置。
- 本机和异机凭据缺失的反馈正确；新导出文件及远端没有意外秘密。
- 两个隔离客户端完成上传、下载、重复同步和冲突处理。
- 旧远端转换失败保留旧快照；新旧客户端不会互相破坏数据。
- GUI、CLI、存储模式和帮助文案保持一致。

实际用户存量迁移与真实全局同步须单独确认。先用固定样本和测试远端完成实现、兼容验证及迁移预览，不能因未获生产操作授权而停止这些独立工作。

## 本轮兼容决策（实施前，2026-09-20）

依据：用户要求「新导入导出不要求额外口令；WebDAV 保留服务端认证凭据，取消新流程的额外内容加密口令；旧加密内容必须有经过验证的读取或迁移路径」。以下为基于当前代码（`modules/container`、`modules/migration`、`modules/sync`、`bin/ocxd`、`modules/ipc/service`、`types/preferences`）形成的决策，**尚未实现**。真实用户存量迁移与真实全局同步仍须单独确认。

| 对象 | 决策 | 受影响落点 |
|---|---|---|
| 新导出格式 | 明文容器 v2：`container_magic` 仍 `OCXDCONF`，`container_format_version: 2`，载荷直接内联 `ContainerDocument`（`container` / `extension_config` / `sync_endpoints` / `preferences`），不改字段白名单；新增顶层 `integrity { algorithm: "sha-256", digest }`，覆盖载荷规范化字节，仅用于检测损坏（不是防篡改身份认证）；沿用既有 `PLAINTEXT_MAX_BYTES` 等上限；原子写 + `0600` | `modules/container`、`modules/migration` |
| 导出载荷白名单 | 仍只序列化 `ContainerDocument`；**排除** Keychain 密文、WebDAV 口令、加密口令、MCP 环境变量值本体；`SecretReference`/`CredentialRef` 只保留引用，异机缺失时提示重新认证 | `modules/migration`、`types/migration` |
| 旧加密导出文件 | 按 `container_format_version` 自动识别；`== 1` 走旧 Argon2id+AES-256-GCM 路径且**仅此时**索要口令；口令错误/缺失、损坏、未知版本一律不写盘、不改现有配置 | `modules/migration::import_with_container_file` |
| 新同步格式 | 清单 v2：明文 manifest + `format/version/compat_version/device_name/schema_kind` + `sha256` 完整性；载荷沿用 `artifact_sha256` 做完整性与回放检测；远端继续视为不可信，但**不再声称端到端加密**；覆盖前备份、冲突登记、事务提交顺序保持不变 | `modules/sync/engine`、`modules/sync`（`SyncManifest`） |
| 旧加密远端 | `manifest_format_version == 1` 仍走旧 AEAD 路径且需要口令；转换为 v2 前先保留远端原快照，验证通过后才切换；失败保留旧快照 | `modules/sync/engine` |
| 混合版本客户端 | v2 声明 `compat_version`；不认识 v2 的客户端必须显式拒绝，不得误读或静默覆盖 v1 数据 | `modules/sync/engine`、`commands/sync` |
| 旧本机口令 | Keychain 中既有加密口令引用**保留不删**，兼容读继续可用；新流程不再写入加密口令 | `infrastructure/keychain`、`modules/sync/config` |
| CLI | `export` / `import` 的 `--password-stdin` 变为**可选**：仅当目标/来源为 v1 时需要；v2 不要求；必需而缺失时报明确错误而非静默失败 | `bin/ocxd`、`modules/ipc/service` |
| 偏好与 UI | 移除 `clientEncryption: 'forced'` 的强制语义与各处「额外口令」输入框/文案；产品说明直接写明文件/远端为未加密配置 | `types/preferences`、`SettingsRoute.vue`、`stores/app`、`commands/migration`、`commands/sync` |
| 权威规范回写 | `DMD` 的 `AC-06`、`AC-07` 需按新行为改写（保留 HTTPS 与服务端认证、把「客户端加密」改为「完整性校验 + 明确非端到端加密」）；同步 `数据与状态.md`、`能力地图.md`、`集成与安全边界.md`、`领域模型.md`、`系统架构.md`、`契约字段.md`；保留历史来源 | `docs/01-需求管理/**`、`docs/02-项目核心/**` |

实施顺序（建议）：

1. 先做 `container`/`migration` 的 v2 明文格式 + v1 兼容读，配套隔离数据根 A→B 往返验证。
2. 再做 `sync` 清单/载荷 v2 + v1 兼容读，配套测试远端双端同步与冲突验证。
3. 最后统一 UI/CLI/文案与规范回写，做交叉影响检查（D 阶段）。

验收矩阵（对应本文件「验收矩阵」一节）在本轮实现后按隔离数据根与测试远端逐项执行；真实存量迁移与真实全局同步不在自动授权范围内。

## 本轮实现与验证（2026-09-20，C 阶段回写）

已实现（对应上表决策）：

- **配置容器 v2**：`OCXDCONF` + `container_format_version: 2`，载荷内联 `ContainerDocument`，附 `integrity{sha-256}`；限流沿用既有上限；原子写 + `0600`。旧版 v1（Argon2id + AES-256-GCM）按版本号识别后仅走兼容读取。
- **迁移 API 去口令**：`export_with_paths` / `export_with_container_file` 不再接收口令；`import_*` 的口令改为可选。旧容器缺口令返回**独立错误码 13**，前端据此弹出「输入原口令」对话框，其余导入不再索要口令。
- **导出范围跟随开关**：`export_include_skills` / `export_include_mcp` 真正生效（此前被忽略），并补齐 WebDAV 端点的地址、远端路径、认证账号、TLS 与冲突策略；口令仍只以 `keychain://<ref_id>` 引用出现。
- **导入按区段受控提交**：先全量校验，再逐文件备份，随后提交偏好 → WebDAV 端点 → 扩展统一配置（走既有校验/备份/原子写路径）；任一写入失败回滚本批已写文件。异机端点换用本机新凭据引用，需要重新输入应用密码。
- **同步传输 v2**：`OCXDSYNCPKG` manifest 包与 `OCXDPAYLOAD` 载荷包改为明文 + SHA-256；`manifest_format_version` / `payload version` 为 2，旧版 1 走兼容读且仍需原口令。远端不再声称端到端加密。
- **同步配置**：`SyncEndpointInput` 去 `encryption_password`；旧配置里的 `encryption=forced` 作为历史字段读取后忽略、不再写出；新建端点只写 WebDAV 服务端口令。
- **偏好与 UI**：删除 `clientEncryption` 强制项与设置页「客户端加密」行，改为「载荷保护方式：完整性校验」；导出/导入页去掉两个口令输入框，改为展示导出区段、未应用区段与排除项；CLI 文案与 `--password-stdin` 语义同步更新。
- **规范回写**：`DMD` 的 `AC-06` / `AC-07` 及 §4 / §5 / §10 已按新行为改写（Revision 5），并同步 `数据与状态.md`、`契约字段.md`、`领域模型.md`、`系统架构.md`、`能力地图.md`、`集成与安全边界.md`。

验证证据：

- 后端：`cargo test --offline --workspace` 348 通过（含 `modules::migration` 明文/旧容器用例、`commands::migration` A→B 往返、`tests/sync_plaintext.rs` 双端链路）。
- 前端：`vue-tsc`、`vitest`（34 文件 146 例）、`vite build` 通过；`migration.test.ts` 覆盖免口令导出/导入、仅旧容器带口令、错误码 13 分支。
- 隔离数据根往返：源根导出 → 目标根导入，偏好/扩展开关/端点配置逐项比对；异机导入端点换本机凭据引用（单测覆盖）。
- 旧格式：v1 容器缺口令/错误口令均不改动现有配置；正确口令可读并应用。同步 v1 包同样需要原口令。
