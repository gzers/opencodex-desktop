| 场景 | 需要验证的行为 |
|---|---|
| 开发入口与隔离边界 | 核对被测 Desktop 的实际配置、认证、状态和进程来源；缺失隔离配置时不得回落到日常目录，验证失败与恢复不影响当前开发入口 |

| 跨文件与并发恢复 | 覆盖 config、必要认证和启动设置的部分提交、跨启动事务及后来编辑；恢复前比对摘要，冲突不盲目覆盖，恢复后核验文件、权限和必要请求 |
| 渠道固定策略 | 按明确的渠道和模式执行请求规则；不基于文本猜测意图或自动尝试其他机制；静态校验可解释 |
| 保存与重启应用 | 保存后显示待重启及当前旧策略；重启后核对有效配置；同一实例多渠道兼容范围与策略来源清楚 |
| 出口覆盖与回程透传 | 核对目标请求是否到达出口、协议是否保留、原版能否继续处理返回结果；外层不改响应内容，并正确传递流、错误与取消 |
| 原版完整与公开边界 | 不修改 OpenCodex 源码、安装包及内部认证 / 归属逻辑；所有集成入口为已确认公开接口 |
| 升级与停用外层 | 原版升级不需重打补丁；若采用独立组件，验证版本兼容、独立停用及恢复普通路径 |
| 数据面与观测归属 | 明确哪些会话经过 OpenCodex；外层直接转发的会话不虚报为已计入其日志、统计或故障切换 |
| 实际版本与配置 | 区分全局 CLI、桌面附带引擎、托管包和运行进程；确认后台开关与档位被实际读取 |
| 上下文模式与互斥 | 分别检查后台压缩、新版 history/notes 和常规模式的有效配置；覆盖布尔 / 表写法、profile 覆盖和冲突导入；混合开启的优先级仅在隔离环境验证 |
| 配置作用域与重启 | 说明模式应用范围，验证完全重启前后、新旧会话和多客户端配置来源；不把共享设置显示为对话内即时切换 |
| history/notes 全链路 | 通过本地代理完成历史查询和笔记读写，保持协议头及正确会话归属；确认真实 Krill 目的地和认证，写入不盲目重试 |
| 上下文服务身份 | 正文与 history/notes 使用兼容服务身份；跨渠道、跨账号或归属不明确时明确处理，不随机选择另一上游 |
| Krill 压缩路径 | 识别原生请求与代理摘要，确认经过本地代理、到达预期上游；原生结果符合客户端协议 |
| 后台并发与取消 | 正文与后台请求正确并行；取消、超时、重试和晚到结果不破坏会话上下文 |
| 压缩后续聊 | 多次续聊、工具调用与结果回传正常，原生状态或摘要按其契约保留 |
| Ultrafast 全链路 | 目录显示、客户端选择、代理策略与出站档位一致；上游反馈能区分已确认和未知 |
| 两种策略与 Ultrafast 组合 | 分别验证后台压缩 + Ultrafast、history/notes + Ultrafast；不能以一个组合成功替代另一个 |
| Fast 策略交互 | 强制 Fast、强制默认与继承设置按最终确认的规则处理 Ultrafast，不静默误标 |
| 多渠道与故障重试 | 其他渠道继续工作，候选路由满足压缩状态及档位兼容要求；降档行为可解释 |
| 桌面配置生效 | 检查配置和必要环境的实际进程可见性，以及重启前后的提示和错误 |
| 非秘密观测 | 能关联请求种类、渠道、模型、档位和失败原因，不泄露凭据、压缩内容或对话明文 |
