# 官网与源码核对补验

2026-11-09。用户明确“Sol／Astra接受请求就是支持”，要求其余疑点结合官网、GitHub继续验证。本轮修正支持判定、核对来源并增加针对性补验；没有将最新源码视为已安装版本，没有改日常配置或生产功能。

## 当前结论

| 能力 | 判定 | 仍需核实的部分 |
|---|---|---|
| Sol／Astra Ultrafast | **支持已确认**：官方文档、Krill目录及实际请求接受相互印证；可和WS组合使用 | default回显如何对应内部调度、性能收益和计费；不影响支持状态 |
| Terra Ultrafast | 所测型号明确拒绝；Fast可用 | 不扩大为Sol／Astra限制 |
| WebSocket | Krill新域名的原生／兼容WSS已完成真实响应 | 本软件入口开关、OpenCodex第三方出口策略及完整接入 |
| 历史与远程笔记 | 客户端机制存在；当前Krill新域名已测原生流程不可用 | 新服务协议或恢复时间需要渠道有效说明；不开猜测路径、不等旧域名恢复 |
| 自定义搜索模型 | Krill型号可以执行搜索；OpenCodex sidecar候选范围有限 | 自有搜索执行器、用途／项目／对话路由；不把sidecar限制当成所有搜索均不能自定义 |
| 命名专用模型 | **独立调用＋原生标题写回可行，补验通过** | 接入管理器自动触发、正文选择、并发／取消和手动改名冲突；未承诺接管App内部所有自动标题调用 |
| 已加载父会话的子Agent默认值热更新 | 现有resume路径不应用新默认，限制保留 | 显式spawn模型／effort已通过，可作为受控执行器的另一条接入方式；任意外部App接管仍未接通 |
| 推荐模型清单 | 上游源码提供候选／排序和可见目录管理 | 不等于强制默认或保证模型总会选该候选；完整采用需单独运行证据 |
