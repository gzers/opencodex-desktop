# 备份目录树与范围登记

关联 MNT-OPENCODEX-DESKTOP-20261009-01；2026-10-10。用户要求以目录树介绍备份文件及作用，后续新增备份范围同步补充。本文属于 0.1.10 协作包设计与源码核对，不提前提升为核心事实文档，不宣告生产备份、恢复或目录迁移已完成。

## 管理器偏好备份：目录和文件作用

备份目录默认是活动数据目录下的 backups；Windows 目标为 <实际安装目录>\data\backups，macOS 目标为 ~/Library/Application Support/com.gzers.opencodex.desktop/backups，已有自定义目录优先。默认位置与当前代码差距见 [双平台目录规则](04-双平台数据目录与迁移边界.md)。

以下是当前升级前偏好备份的真实布局格式；年月与编号是占位符，不是本机生成证据。两平台相对层级一致，路径分隔符按平台显示。

~~~text
<活动数据目录>/
├── manager-state/
│   └── preferences.json           当前偏好原文件（不是备份副本）
└── backups/
    └── <YYYY>/                    UTC 年份
        └── <MM>/                  UTC 月份
            └── upgrade/           动作分组，不能单凭组名判断覆盖范围
                └── <bk_ID>/       一次备份的独立目录
                    ├── preferences.json
                    └── backup-manifest.json
~~~

| 文件 / 层级 | 内容与作用 | 恢复和管理边界 |
|---|---|---|
| manager-state/preferences.json | 管理器的当前偏好，涉及界面、启动、面板行为、更新通道、备份保留、通知等设置 | 是被备份的来源，不是官方配置 / 账户 / 会话的容器 |
| backups/<YYYY>/<MM>/<action>/<bk_ID> | 按 UTC 年月、动作、备份编号组织；编号格式 bk_<utc14>_<8位随机hex> | UI 时间可本地化，磁盘层级仍按 UTC；一个编号目录整组保留或清理 |
| 备份内 preferences.json | 原文件字节快照；保留原文件 basename，备份内没有额外 manager-state 子目录 | 恢复管理器偏好；当前复制全文件，不是按白名单重新生成一部分字段 |
| backup-manifest.json | schema_version、backup_id、action、target_path、stored_at、created_at、sha256、bytes、file_count、restorable、note | 登记来源、时间、格式和校验信息；SHA-256 与字节数在清单内，没有独立 checksum 文件；清单不能代替快照 |

当前 schema v1 为单 payload 文件，每个记录 file_count=1；恢复前应重新计算摘要和字节数，不能只看 restorable 标记。清单的原路径不是任意写入授权，恢复仍须校验当前归属、目标安全与用户确认。偏好可能含路径、代理与运行选项；不要展示原始内容到通知或日志，也不要将字节复制称为加密备份。校验只证明文件一致，不证明全配置覆盖。

本期“生成备份”、升级前选项和恢复前保护原型均说明**管理器偏好**这一覆盖范围。手动与恢复前的动作分类、保护记录关联及固定语义须在实施契约中确定；上树展示 upgrade 现有格式，feature/0.1.10-maintenance@5bea1d34 已实现手动与恢复前保护，真实清单与隔离测试有证据；原生恢复门禁仍待验。

不包含 OpenCodex 完整配置、模型 / 账户 / 会话、登录态、Skills / MCP 内容、托管包体、日志 / 缓存或系统凭据。preferences.json 中存在 include_skills / include_mcp 等偏好字段，不代表对应文件已备份。迁移保护快照也不能由这份偏好备份替代。

## 设置页使用树表与打开确认

用户于 2026-10-10 补充：产品界面不使用纯文本树，改为**名称 / 用途 / 操作**三列树表，支持打开文件、打开目录，并在打开前给出警告。本文中的文本目录仅用于说明磁盘布局；原型展示使用可操作表格。

- 名称列显示文件 / 目录图标与缩进，目录逐级展开或折叠；用途列解释范围、文件内容和作用；操作列按类型显示“打开目录”或“打开文件”。初始仅显示到月份层：根目录与年份展开，月份及以下目录默认收起；点击后逐级查看动作、编号与文件，后续刷新保留用户节点状态。依据后续评审，整体区域始终显示，标题不提供收起 / 展开，只有树表内部目录节点可折叠。
- 表格使用现有主题、字号与组件，长列表内部滚动，窄窗横向滚动，不压缩操作按钮；键盘可访问展开、打开及滚动区域。刷新策略、记录或平台路径时保留树的展开状态，并恢复对应按钮焦点；浏览器焦点表现仍需实屏检查。
- “打开”先弹确认，列明当前绝对路径，目录说明将调用系统文件管理器，文件说明将调用默认关联应用。统一提示不要直接修改、移动或删除，以免校验失败或无法恢复；清理和恢复使用管理器对应操作。“取消”无操作，“继续打开”仅打开目标，不隐含编辑、恢复、清理或写入授权。
- 删除树表上方独立的备份内容、保存位置、保留与轮换三块重复说明。范围与保存路径仅在树表区域展示，打开目录使用树表根节点入口；保留规则仅在下方策略区说明，数量 / 时间满足其一、固定项额外保护的语义不变。确认前路径如发生变化，要求重新选取，不能沿用旧目录打开。
- 原型树表是现有偏好备份格式的独立 fixture，不对应下方内存备份记录的编号、数量或状态。右侧原型工具注明示例边界；确认仅产生演示反馈，不检查真实文件是否存在，不调用系统文件管理器 / 默认应用，不访问本机文件。年月 / 编号示例不得记为生成证据。

后续开发必须从活动数据目录与实际备份清单生成目录及文件明细，而非沿用固定示例。默认应用打开不等于文件只读，确认警告需保留；打开前由原生端校验目标归属、当前目录、文件是否存在和访问权限，拒绝任意路径、越界相对路径或链接逃逸。缺失、权限不足、未关联默认应用及系统打开失败均需可读反馈，不把点击成功当作打开成功。警告不能替代路径校验，也不授予修改备份或读取内容到日志的权限。

本期树表先解释管理器偏好备份；其他事务应从各自 manifest 与注册规则生成相应用途，不把每份记录固定为这两个文件。后续新增范围必须同步树表解释、打开边界与下述登记规则。

## 其他事务备份必须按实际清单解释

当前通用备份器复用如下格式，payload 名称由来源 basename 决定，不能把所有记录都标成 preferences.json：

~~~text
backups/<YYYY>/<MM>/<action>/<bk_ID>/
├── <来源文件 basename>            该事务的实际 payload
└── backup-manifest.json            该 payload 的来源与校验
~~~

以下是 main@de6862d4 的有界调用点核对，不是“全部事件 / 全部备份已验收”清单，也不扩大 0.1.10 为 0.2.0 同步实现：

| 动作 | 已核对的调用点与覆盖 | 展示与验收要求 |
|---|---|---|
| upgrade | commands/upgrade.rs 备份 preferences.json；modules/migration/mod.rs::write_export 覆盖既有导出目标前也使用 Upgrade，note=pre-export | action 不唯一对应业务范围，须结合 manifest 和事务类型显示 |
| import | modules/migration/mod.rs 对将覆盖的偏好及可选同步配置逐个备份，仅既有文件产生记录 | 文件名从 changed_paths 与 manifest 读取；不泛称导入了全部官方配置 |
| sync-overwrite | modules/sync/engine.rs 对 artifacts 中既有目标逐个备份 | 一批事务可能有多个单文件记录；必须登记关联与恢复边界 |
| extension-write | modules/write/mod.rs 与 modules/extensions/projection.rs 对实际写目标备份；投影还包括 MCP 配置及 Skill 目录打包 payload | 某目录 payload 是归档内容，不能按扩展名或目录 basename 推定可直接还原；按内容格式与对应恢复器解释 |
| runtime-uninstall | modules/runtime/uninstall.rs 收集存在的来源记录、包清单 / 锁文件 / 安装清单等逐个备份，以主编号关联附加记录 | 不含全部包体，不承诺一键恢复面板安装；现有 ACTIONS 遍历未含此项，列表 / 轮换覆盖必须核对 |
| data-root-move | BackupAction 有定义；本轮未获得完整迁移备份调用与恢复证据 | 作为待核对类型，不列为已具备全目录迁移保护 |

## 后续新增范围的同步维护规则

新增或调整备份文件、对象类型、触发流程时，在同一变更中完成：

1. **范围登记**：对象 ID、用途、所属模块、现有 / 候选状态，来源路径或解析规则，包含与排除文件，敏感性、格式 / 加密方式。目录树及文件作用表同步更新；动态文件从实际 manifest 生成，文档写解析规则，不罗列虚构固定文件名。
2. **存储与清单**：保存位置、basename 冲突、动作 / 事务关联、格式版本、逐文件校验与大小。v1 一个记录一个 payload；多文件可以显式关联多个 v1 记录，或引入版本化多文件清单与迁移，不能直接向 v1 目录塞入额外文件。
3. **触发与事件**：自动 / 手动 / 写前 / 恢复前条件、失败是否阻断原操作，登记统一事件配置的对象 / 动作 / 阶段 / operationId，以及成功解除规则。创建另一种范围的备份不能解除原范围失败。
4. **恢复与保护**：允许还原的目标、旧数据保护、版本兼容、权限 / 路径检查、部分失败回滚；明确归档解包与单文件复制的区别。不支持恢复的记录如实标明。
5. **保留与清理**：数量 / 时间 / 固定 / 关联事务保留规则，空间不足、删除失败、卸载留存。新增 action 同步覆盖注册、发现、列表、轮换与恢复入口，不能只加枚举。
6. **交互与证据**：设置目录树、单份备份明细、确认与恢复说明同步实际范围；检查生成内容、摘要不符、旧格式、缺失文件、取消、回滚、轮换不破坏保护备份及两平台路径。只在适用检查通过后记录实现状态。

范围登记、配置注册和运行清单各司其职：文档解释产品范围；代码集中注册支持的对象与规则；manifest 记录某一份备份实际含有什么。三者必须一致，不能靠长期手写目录树掩盖实现漂移。稳定后再按用户后续确认回写核心事实文档；本轮仅协作包与原型增补。
