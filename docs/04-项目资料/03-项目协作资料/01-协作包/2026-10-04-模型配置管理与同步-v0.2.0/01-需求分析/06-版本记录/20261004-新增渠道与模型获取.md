## 最新输入与范围修订

用户原话：

> 还有个问题，你这里没有新增渠道配置呢？还有新增渠道怎么拉取模型？

前一轮把地址 / 密钥与渠道创建留在官方面板，模型页只有已有渠道的清单与策略，导致新增入口缺失。本轮将“新增渠道、编辑本机连接、保存前获取清单”纳入当前候选范围。此前 Agent / 布局记录保留当时边界；当前以本记录、主方案 §2.5 和审计 §6 为准。整体冻结前须回写产品定义 / DMD 的渠道职责边界，不能仅凭原型把候选记成已实现功能。

## 可审阅的原型流程

[共享主原型](../../../../03-共享原型/原型/index.html) → 模型 → 渠道模型 → **新增渠道**，分为“连接配置 / 选择模型”两步：

1. 填写渠道名称、独立稳定标识、协议、Base URL、认证方式与演示 API Key。协议候选为 Responses / Chat / Anthropic / Google AI Studio；认证为 API Key / 无认证。原生来源只读，不提供虚构连接表单。已有自定义渠道可在详情打开“连接设置”，稳定标识不可直接改名。
2. 点击“获取模型”，显示精确上游 ID、来源和未知能力；演示清单 8 项默认全不勾选。搜索、仅已选、选择 / 取消搜索结果和手动精确 ID 可用。清单没有截断为 100 项；全渠道激活预算另计。
3. 至少选择 1 个模型后“加入草稿”，新增渠道追加至顺序末尾，并使用显式白名单；仍保持 discovery。此时未保存、未生效，可撤销 / 重做 / 丢弃。已有全选渠道进入连接向导时先按有效选择初始化，避免误收窄。
4. 页级“保存”继续共用差异确认、预算校验、保存进度和待重启状态。保存后提示重启 Codex；重启后的客户端可达性核对仍是单独步骤。新增渠道、白名单及 Fast 独立条目共同计入全部渠道 xx/100。

同一连接重复获取保留已选与顺序，新发现模型不自动激活；空清单、网络 / 认证错误和无清单接口保留已有结果，可重试或手动添加。返回上一步不改连接时保留选择；协议 / 地址 / 认证 / Key 变化使旧预览失效。取消、关闭、切换场景以及迟到回复不会提前创建渠道或覆盖新目标。新建提交后的恢复先生成删除该新增渠道的草稿，不改其他渠道；移除后页面和批量范围会重新对齐。

新字段共用已统一的 Select 组件。未对原型做真实浏览器 / CSS / 焦点验证；当前窗口适配仍在 QA 待验清单。

## 正式接入的事实与缺口

本机 OpenCodex **2.69.0** 安装源码只读核对见 [本地依据](../02-方案草案/本地调研依据.md#新增渠道与模型获取核对2026-10-04)：

- 当前 `POST /api/providers/test?name=…` 要求渠道已注册，其 `models` 返回数量，并非完整模型 ID。当前 `POST /api/providers` 会立即注册 / 更新运行配置，不能把“先创建、获取后删除”当作安全预览。
- 正式实现需未保存连接的本地清单预览服务，复用协议认证、headers、URL 和发现解析，返回精确 ID，不注册或持久化渠道。此接口尚未实现，原型未虚构可用生产 endpoint。
- NewApi 的 OpenAI 兼容示例：Base URL `https://newapi.example.com/v1` 生成 `https://newapi.example.com/v1/models`。当前通用 helper 追加 `/models`，不会替任意根地址补 `/v1`。Anthropic / Google 有各自请求路径和认证，不能统一硬编码 OpenAI 路径；特殊适配器另核对。
- 正式页级保存须将注册、白名单 / 显隐、顺序、字段和本机绑定纳入同一受管计划，处理失败 / 残留 / 恢复，不能让新渠道短暂按默认全选发布。官方缺失或空 `selectedModels` 表示全部，不能把零选择保存成空数组来表示全部隐藏。
- API Key 经正式本机凭据机制处理，不进两个可移植模型文件、WebDAV、导出、外部制模任务包或普通模型策略快照。原型仅存虚构连接摘要与“已配置”布尔值；原始输入 Key 不进状态 / 回调 / 导出，并在步骤切换和关闭时清空。此内存摘要不是生产 schema，也不证明凭据撤销 / 恢复机制已实现。

清单获取成功只证明发现接口可读，不证明推理、Fast 或请求协议兼容；新模型能力仍未知。A6api 无额度，本轮未发请求。

## 渠道列表工具栏间距修正（同日补充）

用户在渠道模型页选中“新增渠道 / 全部渠道 / 预览选择器”工具栏，反馈“三个按钮间距太大，布局不合理”。原布局将搜索框和每个按钮分别作为 flex 子项，以 space-between 分散剩余宽度，导致按钮间距随窗口扩大。

本轮将全部操作按钮（含选中渠道后出现的“清除选择”）收进同一操作组：搜索在左、操作组靠右，组内采用 space-2（8px）固定间距，按钮保持内容宽度；搜索与操作组使用 space-3（12px）最小间距。空间不足时允许右对齐换行，模版列表沿用同一工具栏规则。按钮顺序和操作逻辑保持原有契约。

重新运行既有列表 / Agent 源码检查 **12 PASS**、新增渠道源码状态检查 **20 PASS**，脚本语法与 git diff --check 通过。这些结果只核对源码状态和格式；受既有浏览器访问限制影响，本次实际间距、窄窗口换行和 CSS 视觉验收仍未执行。

## 列表启用开关与状态定义（同日补充）

用户在“已启用”标签处反馈：

> 这个状态怎么做的我没有看到设置。我建议在列表直接加启用禁用。另外这个状态有哪些要确定好。

原标签只读配置值、没有可操作入口，且同一列混入 A6api 无额度和原生只读。本轮“状态”列改“启用”：自定义渠道复用公共 Toggle + 启用 / 停用文字，与保存值不同附未保存；原生显示官方管理。可用性和发现提示移至渠道名称下，不因提示异常自动停用，亦不以开关开启证明请求可用。状态维度和候选枚举统一写入 [交互细化](../02-方案草案/模型页交互细化.md#启用开关与状态分层)，线框与 [DESIGN](../05-原型/DESIGN.md) 同步。

开关只改草稿并支持撤销 / 重做 / 丢弃；保存中锁定，页级保存差异明确启停，成功写入仍提示待重启。修正选择计数与发布投影混用：停用保留模式、白名单及其数量 / 勾选、顺序、引用、推理 / Fast 和连接，仍可编辑，但基础与独立 Fast 项不贡献激活数。再次启用完整恢复最新草稿，none 不变成全选，超过 100 只阻止保存，不截断清单或关闭 discovery。

A6api 的无额度是手工 fixture，保持独立提示，未发任何请求。可用性摘要不进便携策略 / 模拟 baseline；真实检查来源 / 时间、绑定解析和运行接口仍未实现。Agent 保留执行偏好，以最近保存启用状态判定依赖：保存停用后提示并禁用生成，草稿恢复不能提前放行，也不自动换渠道。该依赖判定仍仅为内存 mock。
