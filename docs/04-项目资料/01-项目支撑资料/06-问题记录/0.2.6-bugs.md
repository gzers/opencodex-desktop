### 结论

1. **结构没落地**：实现把卡片压成“标题 + 说明 + 一颗全宽按钮 + 一行小字”，原型的“标题行（标题＋摘要＋按钮）→ 四项事实 → 适用范围 → 运行配置边界”整块缺失；WP-35 补的原型完整态没有进入代码。
2. **空态缺解释**：未配置时既无摘要位也无空态说明，用户看不到“为什么必须先配置执行模型”。
3. **文案口径不一致**：摘要用 `providerId` 与英文枚举，原型用渠道名 + 中文档位 + 能力状态；`默认快速模式` 不是原型词汇，且没有“（模型默认）”标记。
4. **按钮层级反了**：原型未配置时是主色按钮（引导配置），已配置时降级为「更换执行模型」；实现恒为同一颗普通按钮、同一文案，两种状态在视觉上无差别。
5. **页面层级缺失**：原型卡片上方有 `h2`「Agent 配置」面板标题，实现只有页签，卡片里又用 `h2` 顶替，标题级别与视觉重心都不对。

### 拟定改法（完全照原型，不扩散）

**组件形态**

- `AgentExecutionField.vue` 增加页面态与紧凑态两种呈现（现有 `compact` 保留给 `AgentPanel`、`BatchAgentDialog`、`ModelsRoute` 的页签行）。

- 四项事实固定为 执行渠道 / 型号 / 推理档位 / 快速模式，顺序与原型一致。

**样式**

**测试**

## WP-37：同步总是要输入密码（钥匙串授权 / 端点保存 / 同步口令三件事混在一起）

**优先级**：P1
**位置**：同步 → WebDAV 同步（连接设置、同步配置、下载比较）
**用户原话**：“为什么同步总是要我输入密码？不应该的，目前参考的项目都没有这个要求。” / “能不能不用证书、不要密钥、不走mac密码就可以做到？” / “这样做的话windows也可以支持吗？” / “可以写进去。”
**状态**：仅登记，未实施

### 判定：不是一个问题，是三条互不相干的路径

| 编号 | 什么时候出现 | 要的是什么 | 性质 |
| --- | --- | --- | --- |
| A | 打开 WebDAV 页、每次同步、每次测试连接 | macOS 系统钥匙串授权（弹窗输登录密码） | 发布形态问题 |
| B | 连接设置点「保存端点」 | 应用内「应用密码」表单 | 代码缺陷 |
| C | 从 WebDAV 下载快照 | 「配置同步保护口令」 | 设计缺口（传下去就丢） |

### A：ad-hoc 签名导致钥匙串每次重新授权

**实测证据（本机 0.2.5）**

```
codesign -dv '/Applications/OpenCodeX Desktop.app'
  flags=0x20002(adhoc,linker-signed)   Signature=adhoc   TeamIdentifier=not set
codesign -d -r- ... → designated => cdhash H"29a095918155edeb356210c7b15a43ac65a25ca7"
```

- `.github/workflows/release.yml` 全程没有 Apple 证书 / notarize 步骤，产物是 ad-hoc 签名。
- 钥匙串条目的 ACL 绑定创建它的二进制 CDHash；ad-hoc 每次构建 CDHash 都变，旧条目认不出新版本 → 弹窗。本机 2026-10-22 一天内装过 0.2.2 / 0.2.3 / 0.2.4 / 0.2.5 四版，正好对上“总是”。
- ad-hoc 下即使点「始终允许」也常常存不住，所以不是“每次发版一次”，而是“每次读都来”。

**每次都真读钥匙串的调用点**

| 位置 | 时机 |
| --- | --- |
| `commands/sync.rs:239-240` `webdav_config()` → `load_webdav_password` | 每次同步、每次测试连接、每次列举导入连接 |
| `commands/sync.rs:281` `list_imported_sync_connections()` | 对每个导入候选逐个读 |
| `features/sync/ImportedConnections.vue`（`onMounted` 即 `load()`） | 一打开 WebDAV 页就读一次 |
| `modules/sync/runner.rs:155` `webdav_config()` | 同步线程里再读一次 |

进程内没有任何缓存，所以一次打开页面 + 一次同步就可能触发多次授权。

**旁证：钥匙串已被历史残留污染**

`security dump-keychain` 里有 4 条 `ocx.dav.*`，但 `manager-state/sync-endpoints.json` 只指向 `cred_b740cd36…`（2026-10-03 创建）。另外 3 条是删端点未清理的遗留，没有任何代码再引用。

### B：改个远端目录也要重输密码

- `features/sync/WebDavConnection.vue:27`：表单初始 `password: ''`，后端从不回传口令，所以每次打开连接设置密码框都是空的。
- `modules/sync/config.rs:305-315` `validate_input`：硬性要求 `password` 非空。
- `modules/sync/config.rs:194` `credentials.store(&ref_id, &input.password)`：每次保存都用表单值覆盖写。

结果：**只要点「保存端点」就必须重打一遍密码**，哪怕只改远端目录；密码框空着点保存则静默失败（`store.saveEndpoint` 返回 false，只有一句 toast）。

### C：同步保护口令传下去就丢

- 上传：`features/sync/ModelTransfer.vue:129` `passphrase: exportPassword.value || undefined` → 封包后立刻 `exportPassword.value=''`，没有任何持久化。
- 下载：`:159` 捕获 `passphrase_required` → 弹「读取受保护同步快照」→ 每次都要重填。
- 槽位其实早就留好了：`infrastructure/keychain.rs:77` `store_encryption_password()` 写 `ocx.sync.<ref_id>`；`modules/sync/runner.rs:324-330` 读它——但只在 **v1 旧格式**兼容路径上读。
- 全仓核查：`store_encryption_password` **只有 `keychain.rs:212` 的测试在调用**，生产代码一次都没写过。所以受保护快照永远缺口令。

### 决策（2026-10-22，用户确认）

不引入证书、不使用系统钥匙串、不弹 macOS 密码；两端都要支持。

### 目标方案：凭据落到本机数据目录

把 `infrastructure/keychain.rs` 换成 `infrastructure/credentials.rs`，统一接口 `store / load / load_optional / remove`，按平台分支实现：

| | 路径 | 保护 | 证书 | 系统弹窗 |
| --- | --- | --- | --- | --- |
| macOS | `<数据根>/manager-state/credentials/<ref_id>.json` | 文件 0600、目录 0700（`platform.rs` 的 `set_mode` + `atomic_write`） | 不需要 | 不弹 |
| Windows | `%APPDATA%\com.gzers.opencodex.desktop\manager-state\credentials\<ref_id>.json` | **DPAPI**（`CryptProtectData` / `CryptUnprotectData`，当前用户作用域）密文落盘 | 不需要 | 不弹 |

已核对的落地条件：

- 数据根：`lib.rs:102` 用 `app.path().app_data_dir()`，两端自动给对路径。
- 原子写：`infrastructure/atomic_write.rs` 已跨平台，并含 Windows 共享冲突重试。
- 权限位：`platform.rs:161` `set_mode` 在 Windows 是 no-op —— Windows 不靠权限位，靠 DPAPI 密文。
- DPAPI 依赖：`windows-sys 0.61` 已是现有依赖（`Cargo.toml:67`），只需补 `Win32_Security_Cryptography` feature，不引新 crate。
- 上层调用点（`webdav_config()`、`save_endpoint()`、同步封包、列举导入连接）签名不变，只换实现。

### 三件事的修法

**A**

1. 读写不再经过系统钥匙串 → 无授权弹窗，与签名、版本、重装无关。
2. 进程内加缓存：启动后首次读入内存（`Zeroizing` 持有），同步 / 测试 / 列举都用缓存；端点变更或删除时失效。
3. 已有条目的迁移：启动时尝试从旧钥匙串读一次并写入新存储（这一次可能仍弹一次窗）；读取失败则不阻断启动，按“未配置口令”处理，由用户在连接设置重填一次。
4. 清理 3 条无引用的 `ocx.dav.*` 残留（只删不被 `sync-endpoints.json` 引用、且不在候选清单里的）。

**B**

- 已存在端点且表单 `password` 为空时，沿用已存口令，不覆盖写入。
- `validate_input` 改为：仅当“既没有表单口令、也没有已存口令”时才拒绝。
- 保存失败的原因要显示出来，不再只弹一句通用 toast。

**C**

- 上传时填了口令 → 写入 `ocx.sync.<ref_id>` 对应存储；下载先读存储，读不到才弹窗。
- 用户主动清空并选择“不加密”时，同步删除已存口令，避免下次误用旧口令。

### 范围边界（不在本轮）

钥匙串上还有四类用途，本轮**不动**，各自是否需要迁移另行决策：

| 用途 | 位置 |
| --- | --- |
| 渠道 API Key（`model_channel:<ref>`） | `modules/model_config/discovery.rs` |
| 扩展密钥（`extension_secret:<ref>`） | `modules/sync/portable_assets.rs` |
| 渠道授权保护（`model-provider-protection:<id>`） | `modules/model_config/provider_auth.rs` |
| 官方 Key 引用（`opencodex.provider-api-key.v1`） | `provider_auth.rs:450`、`:1453`，属官方目录，管理器只读 |

这些同样会在 ad-hoc 包上触发授权，但改它们会牵动渠道保存与官方兼容，不与本轮同步凭据混做。

### 代价（写清，不隐瞒）

1. macOS 侧口令在磁盘上是明文（0600 + FileVault 兜底）。这是“不要证书、不弹密码”的必然交换：macOS 没有 DPAPI 这类“无提示 + 加密”的等价物。
2. Windows 侧 DPAPI 绑定当前用户，换账号或换机器解不开，需重填一次；与系统凭据管理器同性质，不算退步。
3. 若日后要加强 macOS，可在同一目录加**应用自持随机密钥**（AES-GCM）——防“单独拷走 credentials 目录”，防不了“有本机读权限的人”。纯增量，接口不变。

### 测试要求

- 存储层：两端写入 / 读取 / 读不到 / 删除后的幂等；损坏文件不静默当成“无口令”；`ref_id` 形状校验沿用现有 `account_key` 规则。
- 迁移：旧钥匙串条目存在 → 读出并落盘；读失败 → 不阻断启动、不覆盖已有文件。
- B：已有端点 + 空 password → 保存成功且原口令未变；无已存口令 + 空 password → 明确拒绝并给出可见原因。
- C：上传带口令 → 下次下载不再弹窗；清空并选不加密 → 旧口令被删除。
- 现有 `modules/sync/config.rs` 与 `keychain.rs` 单测需按新后端改写（含 `save_endpoint_stores_only_the_webdav_secret` 的断言）。

### 未验

未改代码，未在 Windows 原生环境验证 DPAPI 行为，未实测迁移路径下的授权弹窗次数。以上路径与行号取自 0.2.5 的 `fe0b53f2`。

## WP-38：模型选择器加载态与选中反馈未形成公共动画（含“目录未就绪即报模型缺失”）

**优先级**：P2
**位置**：公共模型选择器（ModelPicker）与所有调用方；重点 设置 → Agent 配置 → 选择执行模型
**用户原话**：“怎么做加载动画，还有选中去不报错的动画怎么做，原型体现。这个是公共组件，可以在组件样式专题先做好，我看同意了再到原型软件全改完。” / “始终来说 agent 配置的模型渠道获取有延迟不能秒开，所以能否合理做还在动画提高体验性，并且因为模型没获取到前，会报没有当前模型的错误，所以需要合理动画加载避免错误提示。我们先记录，然后原型上体现。”
**状态**：原型侧已实施（组件样式专题，三项参数已确认），实现侧待跟进

### 现象

1. **慢**：Agent 配置点开选择器要等一次目录往返（modelApi.executionDirectory()），期间没有任何进度感。
2. **误报**：目录还没回来时，已保存的执行模型在目录里找不到，界面按“型号已缺失”处理，于是先报一个“没有当前模型 / 执行型号已缺失”的错误，等目录回来又自己消失。
3. **选中无反馈**：点选一行只是行背景变色，没有“已接收”的即时反馈；推理 / Fast 浮层改完也无过渡。
4. **公共层空缺**：原型 model-picker.js 只有一句纯文本「正在读取模型目录…」（第 158 行），没有骨架、没有进度条；model-picker.css 里没有任何 loading / skeleton 动画。

### 实现侧现状（0.2.5）

| 位置 | 现状 |
| --- | --- |
| features/models/ModelPicker.vue:92 | loading 只渲染一句「正在读取模型目录…」 |
| ModelPicker.vue:29 available() | 把 props.loading 直接并进可用性判定，加载中所有行变不可用 → 视觉上像“全都坏了” |

## WP-39：页面主 Tab 到顶仍是全透明，玻璃背景不出现（原型与软件同病）

**优先级**：P1
**位置**：所有带主 Tab 的页面（模型 / 拓展 / 同步 / 诊断 / 设置 / 对话），原型与桌面软件同源
**用户原话**：“这个tab（所有页面）都是到顶也是全透明，应该到顶有玻璃背景，不然太透明导致tab看不清。而且是淡淡变化进来。” / “包括软件也是这样，所以也算0.2.6内容”
**状态**：已修复（原型 + 实现，2026-10-22）

### 现象

- Tab 条滚到顶部后仍然完全透明，下面的内容从 Tab 背后穿过，文字互相叠压、难以辨认。
- 淡入过渡在 CSS 里其实早就写了（`transition: background-color .18s`），但从来没有被触发过。

### 根因：吸顶判定永远不成立

两边都是同一个错误：把“负的 sticky top”又加了一次。

- Tab 条为了吃掉主容器的内距，`top` 被设成负值（实测 `-20px`），浏览器会把它**夹在滚动口边缘**；Tab 贴住的位置就是容器上边框内侧。
- 但判定写的是 `吸附线 = 容器顶边 + clientTop + offset`，等于把吸附线推到容器上方 20px。Tab 永远够不到这条线，`data-stuck` 永远是 `false`，于是玻璃材质与过渡都不生效。
- 实测证据（原型 models 页）：`scrollTop=100` 时 Tab 已经贴住（`barTop=30`），判定仍返回 false；把 `data-stuck` 强制为 true 后玻璃立即出现。

实现侧还多一层原因：`StickyTabs.vue` 早先用 `offsetTop` 链累加求自然偏移，而 `.main` 是 `position: static`，不是 `offsetParent`，链在中途就跳出容器，累加值不等于相对滚动位置的偏移（实测同一页面两次测得 129 与 429）。这个判定比“加两次负偏移”更不可靠。

### 修法

**原型**（`sticky-tabs.js`）

- 吸附线改为 `滚动容器可视顶边 + clientTop`，与浏览器夹住负偏移的位置一致；半个像素容差只吸收亚像素舍入。
- 同步更新 `sticky-tabs.test.cjs`：原用例把 `top=80` 当作吸附线（正是“加两次”的产物），改为按 `main.top + clientTop` 计算，并显式断言“距吸附线 1px 仍透明、到线才吸顶、越过保持、回滚取消”。

**实现**（`components/layout/StickyTabs.vue`）

- 判定优先用视口坐标：`bar.getBoundingClientRect().top <= main.getBoundingClientRect().top + clientTop + 0.5`。
- jsdom 不做布局、矩形恒为 0，此时退回原 `offsetTop` 链比较，保持既有单测语义不变。这一分支只服务测试环境，真实运行一定走矩形比较。

### 验证

- 原型：`sticky-tabs.test.cjs` 4 项通过；原型全量 31 文件 257 项通过。
- 实现：前端 152 文件 737 项通过 / 11 项跳过；`vue-tsc` 通过。
- 浏览器实测（本地 8931 静态服务）：修复前 `scrollTop=600` 仍 `stuck=false`、`background: rgba(0,0,0,0)`；修复后按矩形判定在 Tab 贴住那一刻切换。
