## 4. 扩展管理安全条款（已生效）

（2026-09-14 OQ-01 决定纳入后生效，已随 AC-11 回写 DMD §10）

- Skills / MCP 属于**扩展配置域**（管理），不属于 OpenCodex 核心运行配置（不管理）。
- 允许修改外部客户端配置；具体允许的客户端清单留 IMP 冻结。
- 写入前**强制备份**，采用临时区 + **原子替换**，失败回滚。
- 删除类操作**必须可恢复**，恢复窗口留 IMP 冻结。
- 环境变量**默认掩码**。
- MCP `command / args / env` **不得静默执行任意本地程序**，必须展示执行边界并经用户显式确认。
- 多客户端配置不一致时**检测冲突并提示**，不静默覆盖。
- 外部应用改写配置后同样**检测冲突并提示**。

## 7. 建议结论（分析级草案，2026-09-14）

> 以下为分析得出的**结论**，用于把契约类开放问题从「未决」推进到「已确认」。
> **OQ-02 ~ OQ-09 已于 2026-09-14 经用户确认采纳**；**OQ-01 同日由用户决定正式纳入需求**。
> 全部结论已随 DMD revision 3 回写（AC-11、§8、§9、§10）。

| ID | 建议结论 | 影响落点 |
|---|---|---|
| OQ-02 | 采用**引用优先、迁移可选**：默认把数据目录「引用」为已有 `OPENCODEX_HOME` 所在位置，不搬动已有数据；仅在用户显式选择「迁移」时执行移动。迁移前强制备份；不可写、空间不足、已有数据结构异常在**检查阶段**即阻断；迁移中断或校验失败**自动回滚**并保留原数据目录；备份不可定位时不得开始迁移。 | `state-and-flows.md §4.1`、AC-02 |
| OQ-03 | restore 结果链固定为：查看风险 → 影响摘要 → 生成备份 → 用户确认 → 官方 restore 引导 → 执行中 → 成功 / 失败 / 取消 → 刷新状态。备份失败即阻断；失败**不自动重试**，只给建议；取消不留副作用；执行结果不改变「restore 属官方路径」的定性。 | `state-and-flows.md §4.2`、AC-05 |
| OQ-04 | 冲突判定以**远端索引摘要 vs 本地内容摘要**比对为准，粒度按文件；同一端点同一时刻**只允许一次同步**（实例持有并发锁）；覆盖前对被覆盖侧生成可恢复备份；检测到冲突先进入 `conflict` 待处理，不静默覆盖；备份保留策略（份数 / 天数）留 IMP 冻结。 | AC-07 |
| OQ-05 | 采用审计给出的完整状态链：检查中 → 有更新 → 下载中 → 校验中 →（校验失败）→ 安装中 → 等待重启 → 重启接管中 → 成功 / 回滚。签名校验失败即终止并保留上一版本；重启**不停止** OpenCodex 代理；`stable` 为默认通道，`beta` 需显式开启；检查结果只走通知中心，非阻塞。 | `state-and-flows.md §4.4`、AC-09 |
| OQ-06 | 导入异常 8 分支（口令错误 / 容器损坏 / 版本不兼容 / 备份失败 / 写入失败 / 自动回滚 / 回滚失败 / 用户取消）全部显式化；容器做**格式、版本、完整性**三重校验；写入走临时区 + 原子替换；备份失败阻断写入；回滚失败进入人工恢复指引并保留备份路径；容器参数采用 DMD 建议的 AES-256-GCM + Argon2id，具体参数留 IMP。 | `state-and-flows.md §4.3`、AC-06 |
