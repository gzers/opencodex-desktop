# 场景与验收矩阵

## 1. 定位与验收口径

- 每条 AC 至少配套：一个正常路径、一个失败或不可达路径、一个取消或用户拒绝路径、一个恢复或回滚路径。
- 验收不得只验证“按钮是否可点击”，必须验证**状态、数据落点、备份可恢复性和敏感信息不泄露**。
- 本阶段不连接真实 CLI、文件系统、WebDAV 或凭据；所有验证使用 mock 数据。
- 未冻结项（状态 `open`）对应的 AC 仍可写验收场景，但在对应 OQ 关闭前**不得判定为通过**。

## 2. 场景清单

| 场景 | 角色 | 前置条件 | 用户动作 | 系统响应 | 可见状态 | 失败处理 | 可恢复性 |
|---|---|---|---|---|---|---|---|
| S-01 首次启动发现 | 首次使用者 | 无管理器数据目录 | 打开应用 | 依次检查 `node` → `npm` → `ocx`，短路失败即停 | `checking` / `missing_*` / 发现结果 | 缺失项展示当前状态与最短可复制命令 | 用户安装后手动重新检查 |
| S-02 正常运行 | 日常使用者 | 已发现安装 | 启动 / 停止 / 重启 | 托管官方子进程 | `stopped → starting → pending → running` | 启动失败进入 `starting_failed` 并提供重试 | 重试启动、查看日志 |
| S-03 异常运行 | 日常使用者 | 已安装 | 刷新状态 | 读取官方状态命令 | `at_risk` / `external_takeover` / `unreachable` | 展示风险摘要与建议动作，不自动改配置 | 用户确认后走官方 restore |
| S-04 日常观测 | 排障使用者 | 已安装 | 查看日志 / 打开面板 / 运行 Doctor | 只读读取 | 日志页、面板页、诊断中心 | 代理离线时说明实时日志不可用 | 本地历史日志与日志目录仍可用 |
| S-05 数据目录切换 | 进阶使用者 | 已有数据目录 | 选择新数据目录 | 检查目录 → 检测已有数据 → 选择引用或迁移 | 操作状态 `validating → backing_up → applying → succeeded/failed` | 迁移失败回滚并保留原数据目录 | 见 AC-02 恢复路径 |
| S-06 配置迁移 | 进阶使用者 | 有可导出配置 | 导出 / 导入 | 加密导出；导入按校验→备份→确认→写入 | 操作状态链 + 掩码摘要 | 校验失败中断，不部分写入 | 导入前备份可恢复 |
| S-07 WebDAV 同步 | 进阶使用者 | 已配置端点 | 立即同步 / 处理冲突 | 客户端加密 → 上传 → 冲突判定 | 连接状态 `connecting → syncing → synced/conflict/failed` | 冲突或网络中断不静默丢失历史 | 覆盖前备份可恢复 |
| S-08 双版本升级 | 日常使用者 | 已安装 | 检查更新 / 升级前备份 | 区分 OpenCodex 与套壳两条通道 | 各自独立状态链 | 失败展示原因与恢复建议 | 保留可回滚上一版本 |
| S-09 通知处理 | 日常使用者 | 有通知 | 打开通知详情 / 删除 | 通知中心与诊断中心共用数据源 | 两处同步 | 操作可撤销语义明确 | 通知数据可重新拉取 |
| S-10 CLI 控制面 | 高级 / AI 使用者 | 已在设置中启用 | 执行 `ocxd` 命令 | 经本机 IPC 委托运行中实例 | 命令输出 / `--json` | 实例未运行时只读降级、变更类报错 | 破坏性操作需确认标志 |

## 3. AC 验收矩阵

### AC-01 安装发现与卸载（Revision 11，2026-09-28）

| 路径 | 输入 / 动作 | 预期可观察结果 |
|---|---|---|
| 正常 | 应用启动，系统存在 npm 安装形态 | 展示路径、版本、运行状态；不触发安装类 npm 操作 |
| 正常 · 卸载（托管） | 来源 = 托管安装 → `卸载`（完整 / 仅包体与入口） | 应用直接移除私有前缀与入口；完整卸载再由应用执行官方 `ocx uninstall` 清理 service / shim / config |
| 正常 · 卸载（外部） | 来源 = 自动发现 / 用户指定 → `卸载` | 应用代执行官方卸包命令移除包体与入口（如 `npm uninstall -g @bitkyc08/opencodex`）；不改写全局前缀中的其它内容 |
| 正常 · 数据清理 | 勾选「清空 `OPENCODEX_HOME` 的非官方自有残留」 | 官方自有清单与 `integrations/`、`lab/` 等残留一并清掉；未勾选则保留并列入残留 |
| 失败 | 未安装 / PATH 不可见 | 展示未发现说明与「安装 OpenCodex / 指定路径」出口，不引导 npm 安装 |
| 失败 · 备份缺失 | 未检测到可恢复备份 | **只提醒、不阻断**；可勾选「卸载前自动生成备份」 |
| 取消 | 用户不处理前置缺失 / 取消卸载 | 门禁保持阻塞／弹窗关闭，无副作用 |
| 恢复 | 卸载后重新发现 | 只读残留核验逐项给结论；运行来源回落或变为 `未解析` |

### AC-02 数据目录

| 路径 | 输入 / 动作 | 预期可观察结果 |
|---|---|---|
| 正常 | 选择或切换 `OPENCODEX_HOME` | 数据根就位，产物按分区落位 |
| 失败 | 目标路径不可写 / 空间不足 | 明确失败原因，不产生半成品目录 |
| 取消 | 迁移确认时取消 | 保持原数据目录，不写入任何变更 |
| 恢复 | 迁移中断 / 失败 | 回滚到原数据目录，备份可定位可恢复 |

> 2026-09-14 已确认（OQ-02）：引用优先、迁移可选；迁移前强制备份；检查阶段阻断不可写/空间不足；失败自动回滚并保留原数据目录。

| 恢复 | 失败后重试启动 | 重新进入 `starting`，成功后回到 `running` |

### AC-05 外部接管

| 路径 | 输入 / 动作 | 预期可观察结果 |
|---|---|---|
| 正常 | 状态为 `at_risk` / `external_takeover` | 展示风险摘要，说明属 OpenCodex CLI 边界 |
| 失败 | restore 执行失败 | 展示失败原因，不重复自动尝试 |
| 取消 | 用户拒绝 restore | 保持现状，仅保留说明 |
| 恢复 | 用户确认后走官方 restore | 展示前置备份、执行中、结果，随后刷新状态 |

> 2026-09-14 已确认（OQ-03）：结果链固定为「查看风险 → 影响摘要 → 生成备份 → 确认 → 官方引导 → 执行中 → 成功/失败/取消 → 刷新状态」；失败不自动重试。

### AC-06 配置迁移

| 路径 | 输入 / 动作 | 预期可观察结果 |
|---|---|---|
| 正常 | 导出 → 导入 | 加密容器生成；导入前校验、备份、确认后写入 |
| 失败 | 口令错误 / 容器损坏 / 版本不兼容 / 写入失败 | 明确失败原因并中断，不部分写入 |
| 取消 | 确认阶段取消 | 不写入，保留原配置 |
| 恢复 | 导入失败自动回滚；回滚失败可见 | 备份可定位、可校验、可恢复 |

### AC-07 WebDAV

| 路径 | 输入 / 动作 | 预期可观察结果 |
|---|---|---|
| 正常 | 立即同步 | 客户端加密后上传；`connecting → syncing → synced` |
| 失败 | 认证失败 / 网络中断 / 远端不可达 | 进入 `failed`，不静默丢失历史 |
| 取消 | 同步中取消 | 停止本次同步，已上传部分有记录 |
| 恢复 | 冲突处理后重试 | 覆盖前生成备份，冲突侧可恢复 |

> 2026-09-14 已确认（OQ-04）：按文件比对远端索引与本地摘要；单端点单次同步；冲突先入 `conflict`，覆盖前备份。

### AC-08 升级

| 路径 | 输入 / 动作 | 预期可观察结果 |
|---|---|---|
| 正常 | 检查更新 → 升级前备份 → 官方更新引导 | 备份成功后才引导 `ocx update` |
| 边界 | 涉及 npm 前缀 | **不安装**、不解析依赖、不改写全局前缀中的其它内容；仅在显式确认的卸载流程中移除官方包自身 |
| 失败 | 备份失败 | 阻断升级引导并说明原因 |
| 取消 | 用户暂不升级 | 保持当前版本，无副作用 |
| 恢复 | 官方更新失败 | 展示备份位置与恢复建议 |

### AC-09 应用自身更新

| 路径 | 输入 / 动作 | 预期可观察结果 |
|---|---|---|
| 正常 | 检查更新 → 下载 → 校验 → 安装 → 重启 | 重启后重新接管代理并恢复状态展示 |
| 失败 | 签名校验失败 / 安装失败 | 保留可回滚上一版本，展示原因与建议 |
| 取消 | 用户暂不重启 | 保留已下载版本，不改变当前运行 |
| 恢复 | 回滚到上一版本 | 应用与代理状态均可正常恢复 |

> 2026-09-14 已确认（OQ-05）：采用完整状态链；签名校验失败即终止并保留上一版本；重启不停止 OpenCodex 代理。

### AC-15 主线、支线与统一反馈

> 详细验收输入见状态专题 §6；本轮文档与原型层已收敛并验证（IMP-04 §19.31），生产实现待实施。

| 路径 | 输入 / 动作 | 预期可观察结果 |
|---|---|---|
| 正常（主线） | 新安装后未启动 / 主动停止 / 主动卸载 | 主线显示「待接入 / 未运行 / 运行中」与下一步；不由单一 at-risk 或未安装枚举制造故障通知 |
| 正常（简略＋详情） | 打开概览 | 环境就绪时默认无框运行状态区；环境／路径／保护进运行详情弹窗。前置缺失时切换准备卡，具体布局见 AC-16 |
| 操作支线 | 启动 / 停止 / 重启 / 同步 / 安装 / 卸载 | 支线「待确认 → 执行 → 核验 → 结果」；结果从执行与核验事实派生，不靠固定延迟伪造成功 |
| 持续问题 | 运行中出现/解除保护或所有权问题 | 即使主线不变也更新问题槽与待处理摘要；解除当前待处理项并保留历史 |
| 失败 | 命令返回成功但核验未通过 / 超时后迟到成功 | 「结果待确认」并按核验收口，不伪造步骤、不假称成功 |
| 部分完成 | 卸载/迁移/同步存在未生效步骤 | 列出已完成/未完成项、实际影响与处理入口，不压成通用成功或失败 |
| 取消 | 取消安装 / 取消操作 | 显示「已取消」而非失败；不写故障告警 |
| 待重启 | 数据根切换等需重启生效 | 保留为明确后续条件，不直接说「已切换」 |
| 冲突不误报 | WebDAV 冲突、测试连接成功 | 测试成功不叫已同步；存在未处理冲突不叫全部完成 |
| 反馈收口 | 同一失败从页面→通知→诊断 | 同一结果/原因、一个主承载入口，无多重弹出，技术信息脱敏 |
| 宽/窄窗口 | 默认与最小窗口、键盘 | 默认摘要紧凑、详情可达、无横向溢出、无遮挡或无解释禁用 |

### AC-16 双形态概览与紧凑运行详情

> 已确认目标，生产待实施。细节引用 UI 规范 §25；测试与证据要求见 IMP-05。

| 路径 | 输入／动作 | 预期结果 |
| --- | --- | --- |
| 就绪 | ready / ready_via_source，代理未启动／已运行 | 无框 Logo 与同源运行操作；三卡和事件摘要可见，无常驻环境行 |

## 4. 异常场景矩阵

| 异常 | 触发 | 期望行为 | 关联需求 |
|---|---|---|---|

| 代理不可达 | 进程或端口不可达 | `unreachable`，可刷新、可看本地日志 | REQ-06/REQ-07 |
| 外部接管 | 外部路由器改写 Codex 配置 | 检测并解释影响，不自动覆盖 | REQ-09 |
| 口令错误 | 导入时口令不匹配 | 中断且不写入 | REQ-14 |
| 容器损坏 | 导出文件被截断 | 完整性校验失败，中断 | REQ-14 |
| 版本不兼容 | 容器版本高于当前支持 | 明确拒绝并说明支持范围 | REQ-14 |
| 备份失败 | 备份目录不可写 | 阻断后续破坏性动作 | REQ-14/REQ-15/REQ-16 |
| 网络中断 | WebDAV 上传中掉线 | 进入 `failed`，保留本地与远端索引摘要 | REQ-15 |
| 远端被篡改 | 远端内容非预期变化 | 标记冲突，覆盖前备份 | REQ-15 |
| 并发动作 | 同一资源上多个动作 | 串行化或拒绝，避免状态互相覆盖 | REQ-25 |
| 扩展写入失败 | 目标客户端不可写、原子替换失败 | 回滚到写入前备份，明确失败原因 | REQ-27 |
| 扩展配置冲突 | 外部应用改写、或多客户端之间不一致 | 标记冲突并提示，不静默覆盖 | REQ-27 |
| MCP 参数越界 | `command` / `args` 指向非预期本地程序 | 展示执行边界，需用户显式确认后才可执行 | REQ-27 |
| 敏感泄漏 | 日志/导出/UI 出现明文凭据 | 视为验收失败 | §安全边界 |

## 7. 反馈与通知验收（2026-09-19 补充）

本节把《通知与反馈体系规划》与原型节点的六类反馈渠道补入验收口径。**关联既有 AC，不新建需求级 AC**：短操作与长任务反馈关联 AC-03（启停状态与错误摘要），通知/日志关联 AC-04（只读脱敏与离线说明），自更新通知关联 AC-09，托盘与原生菜单关联 AC-12。稳定需求仍以 DMD 为唯一权威。

### 7.1 六类渠道场景

| 场景 | 渠道 | 前置 | 用户动作 | 预期可观察结果 | 失败处理 | 取消 / 过期 / 清理 |
|---|---|---|---|---|---|---|
| S-11 短操作反馈 | 操作反馈 Toast | 可发起短操作 | 保存偏好 / 复制命令 / 清理 | 只反馈一次；成功约 3–4 秒、失败约 6 秒自动关闭；不进未读 | 失败 Toast 可带一个轻量动作 | 允许手动关闭；不产生持久通知 |
| S-12 操作任务 | 操作任务卡 | 长任务开始 | 启动 / 停止 / 重启 / 同步 | 立即显示进度；成功后收口转一次 Toast；失败保留错误摘要 | 失败保留摘要，视情况生成通知中心记录 | 「收起 / 后台运行」只隐藏，不取消任务；等待超时收口为「仍在后台观察」，不写成失败 |
| S-13 操作性通知 | 通知中心 + 历史 | 有需处理事件 | 打开详情 / 标记已解决 / 删除 | 通知中心与历史共用同一实体；已读 ≠ 已解决；未读计数只统计存活未读未解决 | 未处理前不自动删除 | 过期与清理资格不等于删除；未解决风险不得静默清除 |
| S-14 日志型记录 | 诊断中心 → 日志历史 | 有技术事实 | 查看日志 | 不弹 Toast、不进未读；可按 `operation_id` 与通知互跳；「查看日志」进入正确 Tab | 读取失败给可读说明 | 仅按日志轮转与保留策略清理 |
| S-15 阻断式确认 | Modal | 高风险动作 | 删除 / 清理 / 导入 / 覆盖 / restore / 数据根切换 | 有明确确认与取消；Escape 可取消；遮罩不确认；焦点移入并归还 | 保持并提示原因，不自动关闭 | 取消关闭；确认后转操作任务或反馈 |
| S-16 页面内状态 | 组件内 | 条件持续存在 | 重试 / 打开日志 | 与条件绑定；恢复后自动消失 | 局部失败不重复弹多个全局提示 | 通过重试或离开页面结束 |

### 7.2 组合与边界场景

| 场景 | 操作 | 预期 |
|---|---|---|
| 组合层级 | 通知中心展开 + Toast + 任务卡 + Modal 同时存在 | 顺次避让、不互相压盖、不越窗、无点击穿透；窄窗口可容纳 / 滚动 |
| 去重与重复轮询 | 相同 `dedupe_key` 事件重复到达 | 存活期内只保留一条；同一操作终态只触达一次 |
| 旧操作晚到终态 | 事件到达时操作已被新操作取代 | 旧操作事件不得完成新操作；不得伪造成功 |
| 重启恢复 | 重启应用 | 通知按 `read`/`resolved`/`deleted` 原样恢复；进行中的观察重新接管 |
| 减少动态 | `prefers-reduced-motion` 开启 | 收起与浮层直接生效，不播放动画 |
| 键盘可访问 | 键盘操作 | 可完成查看、处理、收起与取消；关闭后焦点恢复；不能只靠颜色表达状态 |
