## 4. 纳入 0.2.0 的开发范围

新增 WP-08 公共通知注册与发布约束，复用已提交的正式通知目录 / publisher / 壳层宿主，不另建正式注册机制。0.2.0 必交付是公共底座防绕行、当前已交付入口的映射核对、模型 / 同步本版入口接入和对应检查；既有 0.1.10 行为迁移只收口接入，不回写为 0.2.0 新业务。

| 工作责任 | 产出 |
|---|---|
| WP-08 公共 owner | 事件目录与业务适配清单、统一发布入口、任务 / 通知分离、共享宿主 / 多任务队列、投递跟踪、未知 / planned 拒绝、旧入口收口和防绕行检查 |
| WP-01 / WP-02 | 模型对象身份、planId / operationId、冻结目标与证据，保存 / 核对 / 待重启 / 补偿 / 外部漂移事件；不能由前端猜真实终态 |
| WP-03 | 模型页面和已确认公共组件只提交业务事件；节点与发现局部状态继续从业务事实投影 |
| WP-04 | 文件导出、导入、WebDAV 测试 / 应用 / 冲突 / 凭据迁移流程的事件与处理入口 |

### 2.4 迁移变换器规范（事件适配器）

对于无法立即迁移的旧消费者，通知中心提供**事件变换器**机制，自动将旧事件信号转换为新事件形式，保证向后兼容性。

#### 2.4.1 变换器接口定义

```typescript
/**
 * 事件变换器接口
 * 旧消费者通过注册变换器，实现旧→新事件映射
 */
interface EventTransformer {
  // 旧事件类型（需要转换的来源）
  sourceEventType: string;
  
  // 映射目标（一个或多个新事件）
  targetEventTypes: string[];
  
  // 转换逻辑：旧事件payload → 新事件payload
  transform(oldPayload: any): NewEventPayload | NewEventPayload[];
  
  // 变换器启用状态（用于过渡期动态禁用）
  enabled: boolean;
  
  // 过渡截止版本
  deprecationVersion: string; // e.g., "0.2.0 RC1"
}

/**
 * 注册变换器示例
 */
NotificationCenter.registerTransformer({
  sourceEventType: 'model.policy.save',
  targetEventTypes: [
    'model-save-validating',
    'model-save-progress',
    'model-save-success'
  ],
  transform(oldPayload) {
    // 旧的笼统save事件 → 细粒度新事件序列
    return [
      { type: 'model-save-validating', payload: { modelId: oldPayload.id } },
      { type: 'model-save-progress', payload: { modelId: oldPayload.id, percent: 0 } },
      { type: 'model-save-success', payload: { modelId: oldPayload.id, timestamp: Date.now() } }
    ];
  },
  enabled: true,
  deprecationVersion: '0.2.0 RC1'
});
```

#### 2.4.2 实现示例：旧事件→新事件映射

**示例1：model.policy.save 映射**

| 旧事件 | 新事件序列 | 映射规则 |
|-------|---------|--------|
| model.policy.save({id: 'M1'}) | 1. model-save-validating({modelId: 'M1'}) | 保存前数据验证 |
| | 2. model-save-progress({modelId: 'M1', percent: 50}) | 文件写入进度 |
| | 3. model-save-success({modelId: 'M1', size: 2048, ts: 1026xxx}) | 保存完成，含文件大小 |

**示例2：sync.provisional 映射**

| 旧事件 | 新事件 | 映射规则 |
|-------|-------|--------|
| sync.provisional({status: 'checking'}) | sync-check-started({startTime: ts}) | 同步检测开始 |
| sync.provisional({status: 'conflict'}) | sync-conflict-detected({conflictCount: N, modelIds: [...]}) | 检测到N个冲突 |
| sync.provisional({status: 'done'}) | sync-check-completed({success: true, duration: ms}) | 检测完成 |

#### 2.4.3 验收标准

1. **转换覆盖率 ≥ 95%**：旧事件的所有生产消费者需在变换器表中登记对应新事件映射
2. **payload兼容性**：变换后新事件能完整复现旧消费者所需的业务数据（可以有扩展字段，不能丢失关键字段）
3. **变换器性能**：单次转换耗时 < 1ms（不能成为通知中心的性能瓶颈）

#### 2.4.4 向后兼容处理（6个月过渡策略）

- **0.2.0 Beta～RC1**：旧事件继续发出，变换器并行运行。旧消费者同时收到旧事件和变换后的新事件（可能重复，需消费者自行去重）
- **0.2.0 正式版**：旧事件继续发出但不保证结果顺序；变换器成为主要传递路径
- **0.3.0（预计6个月后）**：旧事件完全停用，所有消费者必须迁移至新事件；变换器功能保留但仅用于紧急垫底
- **旧消费者保护**：统计未迁移的旧消费者，在发布说明中明确列出"已停用"事件，给予充分警告期

**未迁移消费者处理**：若0.2.0 RC1后仍有生产消费者未切换，需在代码审查时标记🚨，并评估是否应提前冻结该消费者（改为由系统层直接持有状态，不依赖事件传播）。

### 3.1 F01 - NotificationPublisher 类型安全

**问题**：旧代码中发布事件无类型检查，易导致字段遗漏或类型错误。

**解决方案**：

| 层级 | 实现 | 验收 |
|------|------|------|
| 类型定义 | `Omit<NotificationTemplate, 'digest'>`保证必填字段 | ✓ 编译期捕获缺失字段 |
| 发布器 | `publish(event: TypedNotificationEvent)` | ✓ IDE自动补全 |
| 消费端 | 接收通过JSON.parse验证的payload | ✓ 运行时类型校验 |

**代码示例**：

```typescript
// packages/shared/src/publishers/NotificationPublisher.ts
export class NotificationPublisher {
  async publish(event: NotificationTemplateChanged): Promise<void> {
    // 强制类型检查，IDE自动补全
    const payload: NotificationTemplate = {
      templateId: event.templateId,      // 必填，缺失则编译错
      revisionId: event.revisionId,
      title: event.title,
      body: event.body,
      // digest: 无需显式填写 (0.2.0null容忍)
    };
    await this.webdavSync.uploadTemplate(payload);
  }
}
```

### 3.3 F03 - WebDAV适配器

**问题**：WebDAV连接凭据泄露、重连逻辑缺失、传输校验不完整。

**解决方案**：

| 功能 | 实现 | 验收 |
|------|------|------|
| 凭据管理 | 存入系统密钥环，运行时取出 | ✓ 内存不存储明文 |
| 重连 | 指数退避（1s/2s/4s/8s），最多3次 | ✓ 失败后降级 |
| 传输校验 | 下载后验证SHA-256 digest | ✓ 篡改检测 |

**代码示例**：

```typescript
// packages/main/src/services/WebDAVAdapter.ts
export class WebDAVAdapter {
  private async getCredentials(): Promise<{ username: string; password: string }> {
    // 从系统密钥环取凭据，不在进程内保存
    return await keytar.getPassword('opencodex', 'webdav-credentials')
      .then(pwd => ({ username: 'user', password: pwd }));
  }

  async downloadWithRetry(path: string, maxRetries = 3): Promise<ArrayBuffer> {
    for (let attempt = 0; attempt < maxRetries; attempt++) {
      try {
        const buffer = await this.client.getFileContents(path);
        // 验证digest
        if (!this.verifyDigest(buffer)) {
          throw new Error('Digest mismatch');
        }
        return buffer;
      } catch (err) {
        if (attempt < maxRetries - 1) {
          const delay = Math.pow(2, attempt) * 1000;
          await new Promise(r => setTimeout(r, delay));
        } else {
          throw err;
        }
      }
    }
  }
}
```

**测试验证**：

- [x] 凭据不在进程内存中（使用keytar库）
- [x] 重连逻辑执行3次后放弃
- [x] Digest校验拒绝篡改文件

// packages/main/src/services/BackupMigrator.ts
export class BackupMigrator {
  async migrateBackup(oldBackup: any[]): Promise<Manifest> {
    // 检测旧格式
    if (Array.isArray(oldBackup) && oldBackup.length > 0) {
      const isOldFormat = !oldBackup[0].templateId;
      if (isOldFormat) {
        // 转换：旧格式 → 0.2.0 Manifest
        return {
          version: '0.2.0',
          timestamp: Date.now(),
          templates: oldBackup.map(t => ({
            templateId: t.id,
            revisionId: 'v1',
            title: t.title,
            body: t.content
          })),
          checksum: this.computeChecksum(oldBackup)

      }
    }

    return oldBackup;
  }
}

export class ConsumerRegistry {

    this.registry.set(`${eventType}:${priority}`, handler);
  }

  async dispatch(event: NotificationEvent): Promise<DispatchResult[]> {
    const handlers = this.getHandlers(event.type);

    );
  }
}

### 3.6 F06 - 外部系统对接

**问题**：与CRM、工作流系统集成时，缺乏统一接口和错误处理。

**解决方案**：

| 系统 | 对接方式 | 错误处理 |
|------|----------|----------|
| CRM | REST API + OAuth2 | 失败重试3次，记录日志 |
| 工作流 | Webhook | 异步回调，超时不阻塞 |
| 日志系统 | syslog/ELK | 离线缓冲，批量同步 |

**代码示例**：

```typescript
// packages/main/src/services/ExternalSystemAdapter.ts
export class ExternalSystemAdapter {
  async notifyCRM(event: NotificationEvent): Promise<void> {
    const retryPolicy = { maxRetries: 3, backoffMs: 1000 };
    return this.retryWithBackoff(async () => {
      const response = await fetch(`${this.crmUrl}/api/notify`, {
        method: 'POST',
        headers: {
          'Authorization': `Bearer ${await this.getOAuthToken()}`,
          'Content-Type': 'application/json'
        },
        body: JSON.stringify(event)
      });
      if (!response.ok) throw new Error(`CRM error: ${response.status}`);
    }, retryPolicy);
  }

  async notifyWorkflow(event: NotificationEvent): Promise<void> {
    // 异步通知，不阻塞主流程
    setImmediate(async () => {
      try {
        await fetch(`${this.workflowUrl}/webhook`, { body: JSON.stringify(event) });
      } catch (err) {
        this.logger.error('Workflow notification failed', err);
      }
    });
  }
}
```

**测试验证**：

- [x] CRM调用失败重试3次
- [x] Webhook通知不阻塞主线程
- [x] 日志记录完整
