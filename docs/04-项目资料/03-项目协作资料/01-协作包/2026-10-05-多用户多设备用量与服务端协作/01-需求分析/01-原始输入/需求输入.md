# 需求输入

来源：2026-10-05 当前会话，用户直接输入。以下为原文。

> 关于opencodex本身有一个用量的功能，但是它是仅限于本设备内，我想做一个支持多用户的统计（数据隔离和全站统计），单个用户的多设备整合用量整合功能，这个是否涉及到服务端。你可以查看opencodex的用量统计有什么内容，可以做一个独立的协作包了，设计一下方案。另外既然涉及到服务端，软件就可以配置服务端，和自己的登录账户，自定义设备标识（也可以默认取系统设备名）。服务端还可以涉及什么功能方便用户使用的分析一下。

同日用户补充原文：

> 那么还得加入团队的概念。

该补充把团队纳入本轮方案核心，下面的具体角色与历史策略仍为设计建议。

## 用户明确的目标

| 编号 | 目标 |
|---|---|
| R-01 | 查看现有 OpenCodex 用量统计的内容与能力边界 |
| R-02 | 支持多个用户，各自数据隔离，并具备全站统计 |
| R-03 | 汇总单个用户多个设备的用量 |
| R-04 | 分析服务端是否必要，设计 Desktop 配置服务地址与自己的登录账户 |
| R-05 | 可自定义设备标识，默认可取系统设备名 |
| R-06 | 建立独立协作包，分析其他值得引入的服务端功能 |
| R-07 | 加入团队概念，形成个人、团队与全站之间清晰的数据和权限关系 |

## 分析派生的设计问题

- “全站统计”由谁可见、是否允许管理员钻取个人明细，需要明确权限；推荐站点管理员看全站聚合，团队管理者看本团队及成员聚合，普通用户看本人有权限的记录。
- 团队是独立归属空间，用户可加入多个团队；事件明确归个人或某个团队，不能把成员的全部个人历史自动共享给团队。
- 用户可改的是设备显示名称；用于关联历史的稳定设备 ID 另行生成，避免改名导致新设备或合并错人。
- 服务账户、OpenCodex 接入密钥、供应商账户、设备和账本来源是不同身份，不能互相代替。
- 默认只同步开启后的记录；历史导入、共享本地代理的归属、Hub 重复观察、费用口径和断网补传需要专门契约。
- 候选目标为“可选服务”：未登录仍能使用本地 OpenCodex；是否集中代理是另一个产品选择。

以上为方案推导，尚未成为用户确认的详细决定。用户关于“仅限本设备”的观察需结合调研修正：所查 2.77.0 已有 Hub 的按密钥远端统计，但并未自动解决完整站点账户和跨独立本地实例的需求。

只读核对现有实现，产出独立文档方案和后续开发 / 验收条件。未要求生产编码、搭建服务器、注册账户、购买资源、迁移历史用量或公开发布；本轮也不把候选方案写成当前产品事实。
