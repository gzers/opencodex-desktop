# 能力地图

> 字段级配套：能力项涉及的状态取值见 `数据与状态.md`，实体字段见 `领域模型.md`，写入边界见 `集成与安全边界.md`。

## 1. 范围原则

- **原型中出现的全部功能都在实现范围内**，不做功能取舍。
- `P0` / `P1` / `P2` 与「可选」只表示**实现与交付顺序及前置依赖**，不表示"可以不做"。
- 顺序依据：**P0** 运行管理主线 → **P1** 需要安全评审的能力（配置迁移、扩展管理、CLI 控制面、**托管安装与卸载**）→ **P2** WebDAV 同步。安全评审未完成不阻塞立项，但阻塞对应能力的实现。**五个域的安全评审材料均已齐备**（`安全评审输入.md` §12 / §16，托管安装域 2026-09-25 补写），阻塞项均已转为已确认需求。

- **横向收敛要求（2026-09-28，REQ-31 / AC-15）**：覆盖全部现有能力域，以主线与节点支线统一状态、结果和报错。既有能力编号与功能范围不减少；新要求待实施验收，不因下表旧能力已标定而视为完成。语义见 `数据与状态.md` §2.7、§5.8，呈现见 `UI规范.md` §19。
- **原型还原与组件要求（2026-10-01，REQ-32 / AC-16 / AC-17）**：用户确认当前软件原型；双形态概览、紧凑详情及三档材质组件体系为新的验收目标。原型确认不表示生产已对齐；所有原能力保留，实施与视觉／流程／性能证据按 IMP-05 收口，规则见 `UI规范.md` §25／§26。

### `DOM-01` 安装发现 · `MOD-01`

| 能力项 | 名称 | 输入 | 可观察输出 | 状态 | 冻结 |
|---|---|---|---|---|---|
| `CAP-1.1` | 环境前置门禁 | 本机 `node` / `npm` / `ocx` 存在性 | 当前缺失项、当前状态、最短可复制命令 | `checking` `missing_node` `missing_npm` `missing_ocx` | ✅ |
| `CAP-1.2` | 安装发现与校验 | 已通过前置门禁 | 安装路径、版本、可执行校验结果 | `not_found` `stopped` | ✅ |
| `CAP-1.3` | 重新检查 | 用户手动触发 | 重新执行门禁与发现 | 同 `CAP-1.1` / `CAP-1.2` | ✅ |
| `CAP-1.4` | 托管安装 | 用户显式确认 + **安装位置（默认数据根内 `runtime/opencodex`，可改）** + 版本（默认最新）或离线 `file.tgz`；联网可选 **HTTP / SOCKS5 临时代理** | 官方包装进数据根 `runtime/opencodex/`，运行来源切到该安装；**就地展示进度**（进度条 + 联网命令行明细 / 离线分包进度） | `installing` `succeeded` `failed` `rolled_back` | ✅ |
| `CAP-1.5` | 卸载（任意已解析来源） | 用户显式确认（+ 二次确认） | 范围两级：① 移除包体与入口（托管由应用直接删；外部由应用**代执行**官方卸包命令）；② 完整卸载再由应用调用官方 `ocx uninstall` 清理 service / shim / config 并恢复原生 Codex；`OPENCODEX_HOME` 纳入清理范围；卸载后**只读残留核验** | `uninstalling` `succeeded` `failed` | ✅ |
| `CAP-1.6` | 更新与回滚 | 引导官方 `ocx update`；回滚用记录版本重装 | 升级前备份、结果展示、可按记录重装同版本 | `backing_up` `updating` `succeeded` `failed` | ✅ |
| `CAP-1.7` | 运行来源解析 | 用户显式路径 / 托管安装 / 自动发现候选 | 生效的运行来源（类型 + 路径 + 版本） | `resolved` `missing` | ✅ |

- 检查顺序**固定短路**：`node` → `npm` → `ocx`；前一项未通过即停止后续检查。`ocx` 缺失**不再是死路**：此时提供**托管安装**（`CAP-1.4`）与离线导入入口。
- **运行来源解析**（`CAP-1.7`）优先于路径探测：用户显式指定 > 数据根内托管安装（`runtime/bin/ocx`）> 自动发现候选（npm 前缀推导 / `~/.local/bin` / Homebrew）；**不读取 PATH**。发现、状态采集、启停与版本检查必须共用同一份解析结果。
- **托管安装**（`CAP-1.4`）写的是**私有前缀**（等价于一个私有 npm 项目：`package.json` + `package-lock.json` + `node_modules`），默认位置 `runtime/opencodex/` 且入口 `runtime/bin/ocx` 稳定；**安装位置可由用户显式修改**（系统目录选择器或编辑路径），但**系统保护目录一律拒绝**，**不安装**到全局 npm 前缀、不改写其中其它内容或任何 OpenCodex 核心运行配置（卸载时按 `CAP-1.5` 移除官方包自身）。安装/卸载前必须显式确认；备份（动作 `runtime-uninstall`）**只提醒、不阻断**；**包体本身不备份**（可按记录重装同版本），备份对象是运行来源记录、锁文件与被改动的配置。
- **安装必须可见**（2026-09-25）：安装不是黑盒——确认后在同一个弹窗内切进度视图（进度条 + 状态行 + 百分比），**联网**给命令行明细、**离线**给包体分包进度且不出现命令行；失败不改动现有运行来源。
- **代理是临时参数**（2026-09-25）：联网安装可填 `HTTP` / `SOCKS5` 代理，只作为本次安装的 `--proxy`（SOCKS5 用 `socks5h://`）传给 npm，**不写系统代理、不改全局 npm 配置、不持久化凭据**。
- **安全评审已确认（2026-09-25，`安全评审输入.md` §12.4 / §16.6）**：只允许官方包 `@bitkyc08/opencodex`（包名硬编码，装后回读 `package.json` 校验 `name` / `version`）；安装脚本**默认 `--ignore-scripts`**，缺 bin 只在用户显式开启并二次确认后才带脚本重跑；离线包**只接受 `.tgz` / `.tar.gz`**，逐条规范化条目路径、拒绝符号链接 / 硬链接、设条目数与解压总大小上限、先解到临时目录再原子就位；目标前缀拒绝符号链接 / 非目录 / 系统保护目录；一级卸载只删安装记录登记的托管前缀，二级卸载本产品不删文件；代理凭据与安装明细一律掩码后进界面与日志。**残余风险**：npm registry 不强制发布者签名，只能校验包名 / 版本 / 内容摘要与来源 URL，以「只允许官方包 + 展示摘要供人工核对」缓解。
- **禁止**：向**全局** npm 前缀**安装**、依赖解析代理、写系统目录；代装 `brew` / `node`；自动监听系统变化。托管安装只写**私有前缀**（`CAP-1.4`），应用只做检测与引导，用户自行安装的环境由本人手动触发重新检查。
- 缺 Node.js 时按是否检测到 Homebrew 分支提示：有 Homebrew 展示 `brew install node`，无则展示 Node.js LTS 官方安装渠道。
