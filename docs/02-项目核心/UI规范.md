### 1.1 覆盖式滚动条

- 不常驻：轨道恒透明，拇指默认透明；指针悬停时 `--text 16%`，滚动中（`.is-scrolling`）`--text 26%`。
- `.is-scrolling` 由脚本在**捕获阶段**监听 `scroll` 统一打点（`scroll` 不冒泡），滚动停止 `0.9s` 后撤掉并淡出。
- 适用容器：`.main`、`.notification-panel`、`.select-menu`、`.modal`、`html`。

### 1.2 界面缩放

界面缩放是**唯一**的一个比例（偏好 `interfaceScale`，50%–200%，默认 100%），同一因子同时作用于管理器外壳与内嵌官方面板。

| 项 | 规则 | 落点 |
|---|---|---|
| 外壳 | 根元素上的 `--ui-zoom`（= 比例/100）；主壳 `.app-window` 以 CSS `zoom` 消费，文字/控件/侧栏/设置/弹窗/通知同源缩放 | `src/scale.ts` `applyInterfaceScale` → `styles/tokens.css` + `styles/base.css` |
| 内嵌面板 | 官方子 WebView 的原生页面缩放 `set_zoom(比例/100)`；面板保持在缩放后的外壳留白内，不叠加第二次缩放 | `commands/panel.rs` `sync_embedded_panel` |
| 应用时机 | 偏好加载、保存、还原默认后立即应用；启动即生效，不依赖打开设置页；重启按持久化值恢复 | `stores/app.ts` |
| 视口单位 | `zoom` 不折算视口单位：`.app-window` 的 `100vh` 与最小尺寸显式除以 `--ui-zoom`；`.notif-layer`、`.modal`、`.select-menu` 的 `vw/vh` 同样折算 | `styles/base.css` |
| 原生装饰 | 原生窗口按钮不随网页内容缩放：标题栏保持物理高度（`calc(28px / var(--ui-zoom))`） | `styles/base.css` |
| 入参归一 | clamp 50–200、四舍五入、空值/不可解析回退 100；读数、刻度、面板浮层读数共用同一归一化 | `src/scale.ts` `clampScale` |
| 保存语义 | 拖动即时预览、去抖落盘、以最后一次选择为准；保存失败回退到持久化值，显示值＝实际比例＝持久化值 | `routes/SettingsRoute.vue` |
| 媒体查询 | 缩放不改变视口宽度，`@media` 不反映实际可用宽度；自适应改用 `@container` 与 `auto-fit`/`flex-wrap` | `styles/base.css` |

### 1.3 首次落地页与外壳生命周期（2026-09-24 修订）

**首次落地页**（用户定义，2026-09-24 澄清）：没有显式入口时（hash 为空），按**面板当前是否已启动**决定——
**面板已启动（OpenCodex 运行中且端口可用、health 非 `unhealthy`）→ 面板；未启动 → 概览**；
有显式入口时一律不覆盖：深链 hash、托盘菜单动作（打开主界面 / 打开扩展面板 / 打开诊断中心 / 快速设置）各自决定去哪。

- 「已启动」的判定与面板内嵌判定**同一口径**（`loadPanelUrl`：`runtime === running`、`port` 非空、`health !== unhealthy`），避免「落地到面板却嵌不进来」。
- 落地页不再由偏好驱动：「启动后自动打开面板」（`auto_panel`）已失效；**2026-09-27 用户批注后，设置页不再为它单独占一行**（落地页由面板状态决定算是实现细节，不需要在界面上陈述）；
  字段仍保留在 `preferences.json` 契约中（不改冻结字段），但不再有任何消费方决定路由。
- 判定必须发生在**应用挂载之前**：状态快照是异步的，若等它返回再跳页，首屏会先渲染概览、再跳面板（可见闪烁）。
  实现上由启动入口先取偏好、再等第一份「运行时已定档」的快照（`loading` / `starting` / `stopping` 视为未定档），
  写好落地 hash 再挂载；等待有上限（1500 ms），取不到就按概览落地，不无限阻塞启动。
- 判定输入是状态快照，不是开关；`get_status_snapshot` 每次调用都会先做一次真实采集（去抖期内读上一次结果），因此「读到 `not_found`」表示确实没发现面板。
- 落地页只有一处实现（启动入口），路由组件与控制器不再各自决定，避免两处规则漂移。
- **恢复的会话 hash 视为显式入口**（2026-09-24 用户决定保持）：macOS 的 WebView 会恢复上次会话的 URL（含 hash），
  应用本身没有「启动时带 hash」的任何入口，因此回到机器上时首屏通常是**上次停留的页面**，而不是按面板状态重判。
  这是有意的取舍——不牺牲「恢复上次停留页」，规则只在真正没有入口（全新会话）时决定首屏；托盘动作仍是挂载后自行导航。

**外壳生命周期**（macOS）：

| 动作 | 结果 |
|---|---|
| 关闭主窗口（`keep_proxy_on_close` 开启） | 只隐藏窗口：**Dock 图标与菜单栏随之消失**（激活策略切到 `Accessory`），**托盘图标保留**，托管代理不受影响 |
| 关闭主窗口（该偏好关闭） | 允许关闭，桌面壳与托盘一起退出 |
| 从托盘打开窗口（打开主界面 / 面板 / 日志 / 设置 / 数据目录 / Doctor） | 窗口显示，**Dock 图标与菜单栏恢复**（切回 `Regular`） |
| 启动时未显示主窗口（`launch_main` 关闭） | 与「隐藏」同态：只有托盘，不占 Dock 图标 |
| 应用退出（托盘退出） | 托盘与菜单项一并清理，不残留 |

- 规则由「窗口是否可见」单向派生，不额外维护状态位；非 macOS 平台不改变激活策略。

### 1.4 窗口拖拽区（2026-09-24）

macOS 用 `titleBarStyle: "Overlay"`（原生红黄绿压在网页内容上，没有原生标题栏可拖），窗口移动由 `App.vue` 的
`.titlebar` 条带承担。**三件套缺一不可**——用户报告「窗口不能拖拽」就是三条全缺：

| 件 | 落点 | 说明 |
|---|---|---|
| DOM 属性 | `App.vue` 的 `<header class="titlebar" data-tauri-drag-region>` | Tauri 注入脚本只在 mousedown 命中带该属性的元素时才处理拖拽（`getAttribute` 判定，必须命中元素本身） |
| 可命中 | `.titlebar { pointer-events: auto }`（**不能** `none`） | 不可命中的元素不会成为 `composedPath[0]`，属性形同虚设 |
| 能力授权 | `apps/desktop/tauri/capabilities/default.json` 的 **`core:window:allow-start-dragging`** | Tauri v2 的 `core:window:default` 只含只读 getter 与 `allow-internal-toggle-maximize`，**不含拖拽**；缺这条时 `invoke('plugin:window\|start_dragging')` 被 ACL 静默拒绝，表现就是「明明点住了却不动」 |

- 条带高度 `--window-controls-height` 只在 `.app-window.is-macos` 下取 `28px`（并按 `--ui-zoom` 折算），
  Windows / Linux 为 `0px`，拖拽仍由原生标题栏承担。
- 条带**横向铺满窗宽**（`grid-column: 1 / -1`）：内容页从第二行开始、通知层 `z-index` 更高，
  所以顶栏右侧也应该是拖拽区，不能只留图标列那 244px。
- 双击条带 = 缩放 / 复原（Tauri 的 `internal_toggle_maximize`，已在 `core:window:default` 授权内）。
- 回归见 `apps/desktop/ui/tests/window-drag.test.ts`（属性、可命中、授权、高度口径四条断言）。

## 3. 基础控件

每类控件给出变体、尺寸与各状态；状态以明确 class/属性驱动，不用广域后代选择器（如 `.panel button`）批量覆盖。

| 控件 | 变体 | 尺寸 | 状态 |
|---|---|---|---|
| Button | 主（`.primary`） / 次 / 危险（`.danger`） / 幽灵（`.ghost`） | 主控制 `--control-md:34`；通知内 `--notif-ctl-h:24` | 默认 / 悬停 / 按下 / `:focus-visible` / 禁用（`opacity:.42`） / 加载（`--btn-spinner`） |
| IconButton | 图标键 / 危险图标键 | `32×32`；通知内 `24×24` | 同上；图标 `stroke-width:1.8`、圆角端点 |
| Tab | 页面内 tab、通知分类 tab **同款** | 自然宽度、`--text-control`、高 36 | 选中：`background:transparent`、底部 `2px --accent` 指示条 |
| Select / Input | — | 主控制档 | 默认 / 悬停 / 聚焦环 / 禁用 / 校验失败 |
| Switch | 开关 | `38×22`，圆点 `16` | on / off / 禁用 |
| Badge / Tag | 通知状态标签 `.n-tag`、计数徽标 `.n-count`；页面状态标签 `.tag` | 行内标签 `10px`；计数高 `16`；`.tag` `min-height:22px`、`padding:2px 8px` | 中性半透明；`.tag` 是胶囊（`1px --border` + `--panel` 底 + `--radius-pill`）；颜色只用于携带语义的未读标记 |
| Card | 页面卡 `.card`、条目卡 `.notification-item`、任务卡 | `--radius` / `10px` | 默认 / 悬停（描边加深） / 收起 |

约定：

- **通知内的按钮统一「半透明 + 小一档」**：共用 `--notif-btn-*`（半透明底 + 描边 + 轻模糊 6px），条目主体不参与；取消类走 `--notif-cancel-*`（半透明红）。
- 图标型按钮（收起键、删除键）**排除**文字内距规则，保持 `width/height + padding:0 + place-items:center`。
- 状态标签必须是 `inline-block` 行内小标签，**不能被正文 `span` 规则拉满**（`.notification-item span` 会命中 `.n-tag`，需用更高优先级的 `.notification-item strong .n-tag` 扳回）。
- **页面级状态标签 `.tag` 与通知内 `.n-tag` 是两个变体，都要有基础规则**：`.tag` 用于设置/关于/概览等页面上的结果标签（结构有效、已检查、有更新、成功/失败等），基础规则必须存在，否则 `.tag.danger`、`.skill-title .tag` 这类局部覆盖会失去依托而退化成纯文本；`.n-tag` 只用于通知条目与历史。

### 4.3 Toast

- 位置：软件窗口内，避开原生控制区、标题栏与通知面板；面板展开时顺次落到面板下方。
- 尺寸：`320–380px`，最多 3 行；通知宿主内宽 `min(392px, calc(100vw - 32px))`。
- 成功 / 信息自动关闭约 3–4 秒；失败约 6 秒；`danger` 不自动消失。
- 失败可带一个轻量动作按钮（半透明小尺寸）。

### 4.4 任务卡

- 位置：窗口内任务区，与 Toast 同列，位于 Toast 下方；不越出窗口底边（越界回退原位置）。
- 尺寸：宽 `360–420px`，单任务高度建议不超过 `240px`。
- 展示 spinner、当前阶段、当前状态和可用动作；动作按行为绑定，未实现时不展示为可点击按钮。
- 「收起 / 后台运行」只隐藏卡片，不取消后台任务。

### 4.5 收起（收起到铃铛）

- 通知中心面板、Toast 卡片、任务卡右上角各有一个「收起到铃铛」按钮；收起时向铃铛收拢并触发铃铛脉冲。
- 收起**不改动** `read` / `resolved` / `deleted`，也不取消后台任务；未读角标保留。
- `prefers-reduced-motion` 下直接收起，不播放动画。

### 4.6 堆叠与避让

- 通知中心展开 + Toast + 任务 + Modal 同时存在时顺次避让，不互相压盖、不越窗、无点击穿透。
- 通知层的三个表面（通知中心 / Toast / 任务卡）收在同一列 `.notif-layer`（列向 flex），避让由正常文档流保证，不依赖 JS 位移或 `z-index` 竞争。
- 原生子 WebView 与 DOM 不是同一合成层，**不得假定提高 `z-index` 就能盖住官方面板**。官方面板浮层采用**原生承载**（随面板子 WebView 注入，见 §9）；通知层不注入面板页，而采用**协调显示**（见 §4.7）。

### 4.7 面板路由的通知层（协调显示）

- 面板路由下官方面板是原生子 WebView，通知层位于窗口级壳层 DOM；两者不是同一合成层。
- 采用 `FZ-43.4` 允许的**「协调显示」**：通知中心 / Toast / 任务进度 / 确认 Modal **任一可见**时，**临时让出（隐藏）面板子视图**；表面全部消失后立即恢复。恢复沿用同一 `sync_embedded_panel`，面板此前已加载完成，不重新计时、不触发二次「加载超时」。
- 通知表面始终是窗口级 DOM（`pointer-events:none` 的宿主 + 子元素 `auto`），**不重排为透明点击层、不复制面板页标记**。
- 进入面板路由时若已有表面可见，保持该表面可见、面板在其后暂不显示，直到表面消失才显示面板。

## 6. 键盘与可访问性

- 通知条目与动作使用**真实按钮语义**（`<button>` 或等价），有可读名称；不嵌套按钮。
- `Modal`：`Escape` = 取消；点击遮罩只允许取消，不得确认；打开时焦点移入，关闭后归还来源焦点。
- Tab 焦点约束在弹层内循环；关闭后焦点恢复。
- live-region 适度播报（`role="status"` / `aria-live="polite"`），不重复播报。
- `prefers-reduced-motion`：关闭入场 / 收起动画。
- 状态不能只靠颜色表达：未读 / 已读同时用形状（圆点）+ 标签文字。

### 18.4 卸载（任意允许来源，2026-09-28 修订）

- **入口常显**：运行来源卡片动作行末位出现 `卸载`，只要运行来源已解析（托管安装 / 用户指定 / 自动发现候选）；`未解析` 时不出现。
- **范围两级**（按**当前运行来源**计算方案，先给事实再给清单）：
  - **完整卸载（推荐）**：移除包体与入口，并由应用调用官方 `ocx uninstall` 移除 service（macOS `~/Library/LaunchAgents/com.opencodex.proxy.plist`，label `com.opencodex.proxy`）/ codex autostart shim / 客户端 `config` 与 shell hook、恢复原生 Codex；之后可选清空 `OPENCODEX_HOME` 残留。
  - **仅移除包体与入口**：只删包体与 `ocx` 入口；**不碰** service / shim / `config.toml` / `OPENCODEX_HOME`。
- **包体与入口由应用代执行**：托管包体由应用直接删除；用户指定与自动发现的安装，由应用在显式确认后执行官方卸包命令（如 `npm uninstall -g @bitkyc08/opencodex`），**不再要求用户去终端**。
- **将移除的对象分层可见**：包体 / 入口 / 运行态（完整卸载时）；`OPENCODEX_HOME` 的官方自有清单（`.opencodex-uninstall.json`，含 `config.json`、`auth.json`、`catalog-backup.json` 等）收进折叠区，非官方自有残留（`integrations/`、`lab/`、`routing-history.sqlite` 等）单独一项、可选一并清空。
- **备份只提醒、不阻断**：未检测到可恢复备份时给出琥珀提醒并默认勾选「卸载前自动备份」；检测到备份则提示可复用。**主行动的可用性只由确认项决定**，与备份状态无关。

## 20. 短文本不断行、长值行内截断（全局，2026-09-25）

**问题**：概览状态卡的事实行里，真实数据根路径很长，把同行的「数据目录」label 挤成「数据目」/「录」两行。
这不是表格问题（§16 只管表格），而是**任何一行「短 label + 长值」的构图都有的通病**：label 不能被长值挤断行。

**规则**（软件与原型同一套口径）：

1. **一行一事实**：label 与它的值属于同一个原子单元（`.ovc-fact`），单元内部 `white-space: nowrap`——
   label 永远不会被拆成两行。空间不够时整个单元换到下一行，而不是把 label 拆开。
2. **长值行内截断**：承载长路径 / 长字符串的值元素 `min-width: 0` + `overflow: hidden` + `text-overflow: ellipsis`，
   在**自己那一行里**截断（`.ovc-fact.mono` / `.ovc-fact.mono b`），不抢同行其他 label 的宽度。
3. **完整值有出口**：截断的值必须带 `title`（或等价的可查看完整值入口），悬停可看全文——
   截断只是省地方，不是丢信息。
4. **合理宽度**：短 label 列（`label` / `.metric label` / `.ovc-fact` / `.setting-title` / `th` / 卡片标题 / 导航按钮）
   给足宽度不换行；长文本列负责压缩。短控件（`.btn` / `.tag` / `.state-pill` / `.icon-btn` / `.runtime-pill`）沿用 §16 的
   `nowrap` 底线。
5. **探针**：`05-原型/原型/qa/nowrap.browser.mjs`（无头 Chromium）遍历全部路由 × 默认 1180 / 最小 900 两种窗口，

   软件侧 `apps/desktop/ui/tests/no-wrap-labels.test.ts` 断言 CSS 口径、`overview-status-announce.test.ts` 断言数据目录带 `title`。

## 21. 内容页表面材质：半透明磨砂（2026-09-27）

**口径**（概览页批注「这里的页面能否做成半透明或者全透明背景？包括其他页面」的结论）：

- **软件底层不透明**：窗口底面（`.app-window`）、菜单（`.side`）、标题栏（`.titlebar`）保持现状，一行不改。
- **透明的是「内容页」这一层**（`.main`）。页面自己的颜色盖在「窗口底面 + 环境光」上，**alpha 就是「盖住多少」**：
  alpha 越低，透上来的软件自己的底越多。
- 参照物**在软件内部**，**与桌面、壁纸无关**：不开系统级窗口透明，不引入 `transparent` / `macOSPrivateApi`，
  也不存在「把桌面垫在窗口后面」这种前提。原型里曾有一个「垫壁纸」开关，那是**错误道具**，不作为生产契约。
- 原型打样过四档（实底 / 半透明磨砂 / 中透 / 更透），**用户选「中透」**。

**令牌**（`apps/desktop/ui/src/styles/tokens.css`）：

| 令牌 | 亮色 | 暗色 | 说明 |
|---|---|---|---|
| `--page-fill` | `rgba(255,255,255,.40)` | `rgba(38,38,38,.40)` | 内容页填充；「中透」= alpha `.40` |

**规则**：

1. 只作用于 `.main`：`background: var(--page-fill)`，**且不加 `backdrop-filter`**。
2. 外壳不带 `backdrop-filter`，也不改底色——整窗仍然只有底面那一层玻璃。
3. 子层（卡片 / 按钮 / 表格 / 弹窗）按 §26 的表面分类取材质：高／中档使用已确认的通知玻璃，低档退实底。
   文字始终实色，不在组件内重复堆叠相同模糊。此条替代旧“所有子层保持实底”的口径。
4. **页面不得使用 `backdrop-filter`（2026-09-27 真机实测）**：WKWebView 里 `.main` 上的 `backdrop-filter`
   会去采样**窗口背后的桌面**——实测把窗口移到不同桌面区域，页面颜色跟着变，而外壳不变。
   那就不是「软件自己的底」了，违反本节口径；同时也带来整页滚动时的合成开销。
   页面透出的「柔和感」由 `.app-window::before` 那层已经 `filter: blur()` 过的环境光提供，不需要再叠模糊。
5. 内容页默认高／中档为「中透」，不暴露独立透明度打样开关；特效低档由 §26 统一退实底。实底打样和低档策略不是两套用户偏好。
6. 观感边界：透上来的是**软件自己的底 + 环境光**，表现为页面从「纯白纸」变成带环境光色偏的玻璃面
   （左上偏冷、右下偏暖），**不是**透出图案。要更强的通透感只能调强窗口底面的环境光，属于另一刀。

**探针与验收**：

- 软件侧 `apps/desktop/ui/tests/page-surface-material.test.ts` 断言令牌取值与 `.main` 规则。
- 真机：概览 / 设置 / 诊断三路由截图，内容页留白处取色，与实底版本对照；并确认外壳未变。

**背景**：设置 → 通用 → 「官方共享配置」原本在原型里是开关，生产一度收敛为只读结论「官方共享域」。

### 22.1 写入失败必须给真实原因（2026-09-27 真机补记）

用户报「开关点不动」后定位到两个真机缺陷，均已修：

1. **子进程 `PATH` 里没有 `codex`**：官方 `ocx codex-shim` 只在 `PATH` 上找 `codex`，找不到时它
   打印警告却**退出 0**（等于什么都没做）。管理器给子进程的 `PATH` 只有 node 所在目录，
   因此「codex 由 `ChatGPT.app` 内置」这类 macOS 常见安装永远装不上。
   现按**固定候选**（`<HOME>/.local/bin`、`/Applications/ChatGPT.app/Contents/Resources`、
   `/opt/homebrew/bin`、`/usr/local/bin`）补齐，且**只接确实存在 `codex` 的目录**（不读 `PATH`）。
2. **不能把「退出 0 但没生效」当成功**：写入后按**目标状态**复读校验，不一致即失败。
3. **写入失败必须说清原因**：写入路径采集官方 stderr 并逐行脱敏截断；界面把已知形态映射成中文可执行说明：
   - 找不到 codex → 「官方 shim 未生效：未找到 codex 可执行文件；请先确认 codex 已安装并可从终端运行。」
   - `EPERM`（macOS 拒绝本应用改动别的应用包）→ 「官方 shim 未生效：macOS 拒绝本应用改动 Codex 所在的应用包；
     请在系统设置里给「OpenCodeX Desktop」开启「App 管理」权限，或改用终端执行 `ocx codex-shim install`。」
   - 其余 → 通用中文提示（不展示官方英文原文）。

**规则**：只读查询失败仍按只读事实收敛；**写入失败一律不得静默**，也不得只给「写入失败」这类没有信息量的句子。

### 22.2 进行态与行内说明（2026-09-27 修订）

真机实测：官方 shim 安装会先做一次探针，**成功路径要 ~20 秒**；失败路径虽然快，但原因（例如 `EPERM`）
只写在官方 stderr 里。原来只有「禁用 + 1.9 秒 toast」，用户看到的等价于「点了没反应」。
因此这一行补齐两件事：

1. **进行态**（**2026-09-27 起由 §22.3 行内面板取代**）：写入期间给出进行态而不是只把开关置灰。
   **任何超过 1 秒的开关动作都要有进行态**，不得让用户对着禁用控件猜。
2. **行内说明**：失败原因与「未就绪」原因写成该行的持久说明（`.setting-note`，`data-testid="codex-shim-notice"`），
   **不依赖 toast**。toast 只留一句「原因见该行说明」做提示——「去开哪个权限」这种内容 1.9 秒读不完。
   未就绪原因按稳定原因码映射中文：`unresolved`（未解析到 ocx）/ `timeout`（读取超时）/ `locked`（状态被占用）/ 其他（读取异常）。

**例外口径**：说明写进行内时，**先回读真实状态、再落本次失败说明**，避免被回读的 `codexShimError = ''` 覆盖。

**顺带记录一条真机事实**（影响用户排查，不是本应用能消除的）：被测制品是 **ad-hoc 签名**（`Signature=adhoc`、无 `TeamIdentifier`），
macOS 的「App 管理」授权是按 cdhash 记账的，**每次 `tauri build` 重新链接都会换 cdhash，之前的授权随即失效** ——
真机复现：授权后安装成功；重新构建后同一操作又回到 `EPERM`。所以「授权后仍无效」要先确认没有换过构建产物。

### 22.3 写入进行态改为行内面板（2026-09-27 修订，用户批准）

用户看原型后三轮纠偏后的定稿：**进行态不再是控件位的一行文字，也不挂在行内文字列里**，
而是在该行**内部底部独占一行**的小框（`.shim-panel{grid-column:1/-1}`）。
默认那行（标题 + 说明 + 开关）**保持同一行不变**，只在写入时于其下方展开。

**时序与形态**：

| 阶段 | 开启（install） | 关闭（uninstall） |
|---|---|---|
| 进行态 | 小框：转圈 + 「正在安装官方 shim」+ **不确定进度条** + 真实「已用 Ns」 | 小框：转圈 + 「正在关闭官方 shim」+ **不给进度条** |
| 提示 | 「官方会先做一次探针校验，通常 10–30 秒；期间请勿退出应用。」 | 「关闭只把 Codex 启动器还原成原始可执行文件；通常几秒内完成，比开启快得多。」 |
| 完成 | 结果说明（停留 ~1.4s） | 结果说明（停留 ~2s） |

**规则**：

1. **不编百分比**：官方 install 先做探针且**不提供分步进度**，所以只给不确定进度条 + 真实耗时，
   **不得**写 `aria-valuenow` 或任何百分比。
2. **开启/关闭不同形**：关闭是短、单一动作，**不复用**开启那根长耗时进度条（`.shim-panel.is-close` 隐藏进度条）。
3. **完成要说「指令做了什么」**：结果说明用一条绿底行写清真实效果——
   安装＝把 Codex 启动器替换为官方 wrapper、原可执行文件备份为 `codex.opencodex-real`、之后启动 Codex 自动运行 `ocx ensure`；
   关闭＝移除 wrapper、把 Codex 启动器还原成原始可执行文件、清理备份、不再自动运行 `ocx ensure`。
   失败时同一位置给红底说明（内容同 `.setting-note`），**不得只留 1.9 秒 toast**。
4. **可查具体指令**：框内「查看执行的具体指令」可展开真实 CLI 清单（安装 `ocx codex-shim status → install → status`；

## 25. 概览定稿：运行／环境准备双形态（2026-10-01 确认）

### 25.1 两种呈现与首屏

- **环境就绪**（`ready / ready_via_source`）：无框居中状态区；Logo → 主线状态 → 必要说明 → 当前操作。不常驻环境摘要行。环境明细并入运行详情；下方按版本升级／配置迁移／WebDAV 同步排列三卡，最后为最近事件摘要。
- **环境准备**（检查中或真实 Node.js/npm/OpenCodex 缺失）：三卡和最近事件退出概览布局，顶部缩短；下方一张通知玻璃卡按内容定高，左侧纵向三项检查，右侧当前指引、最相关命令和处理动作。完整命令和设置保留出口，不再仅给“处理”按钮把原因藏起来。
- “未运行”不代表环境缺失；运行主线、前置检查仍是两组同源事实。托管或指定运行来源已解析时，不因自动发现候选为空误报 OpenCodex 缺失（§18.5）。失败采集不应清空仍有效的运行事实或伪造缺失。
- 环境准备是概览的信息层级，不是把管理器自有迁移／同步能力判为全局不可用；其它页面的能力门禁由现有契约决定。
- 三卡保留两行事实、设置出口及沉底等宽动作，尺寸和内距按当前原型对齐。最近事件正常显示最近两条，紧凑显示最近一条，完整历史保留在诊断；生产必须使用真实事件，不能复制原型固定样例。

| 应用逻辑窗口（100%） | 正常状态舞台 | 环境准备舞台 | Logo 展示参考 |
| --- | --- | --- | --- |
| 1180×760 | 300px，168／66／66 三段 | 174px，114／60 两段 | 正常 140px，准备 90px |
| 900×600 | 222px，128／50／44 三段 | 142px，88／54 两段 | 正常 100px，准备 74px |

### 25.2 状态形象（Logo 三结构动画 + 多光源背景）

- 形象本体是**现有品牌 Logo**（云形轮廓 + 内部聚合镂空），用**内部聚合结构**表达状态：**A 完整内核 / B 分离三球 / C 柔性连接**；云形外轮廓保持原始比例，不做压扁/破损。
- **结构幅度固定为已确认的最大值 `1.25`**，不随窗口或状态变化。
- **悬浮幅度按肉眼可辨标定（2026-09-29）**：整体上下悬浮峰峰值约 `10–13px`（`running` 约 `11.7px`），此前约 `3.7px` 过小、不仔细观察看不出在动；改的是**整体位移**，结构幅度仍固定 `1.25`。
- 关键映射（形象语义，主线/支线/问题/新鲜度仍以 §2.7 为准）：待接入＝B 离散漂浮；未运行＝B 低位待命；正在启动＝B→C 轻跃聚合；运行中＝A 稳定悬浮；正在停止＝A→C→B 下沉；启动失败＝C→B 一次回落；运行中待处理＝C 柔性牵动；正在确认＝B 悬浮探寻；事实过期＝保留上一结构、去饱和漂移。
- **任意切态平滑过渡**：形状、浮动位移、三色渐变、饱和度、透明度、光团与光束均从**当前值与当前速度**做阻尼追踪，切态只改目标，不归零、不排队；周期动作使用连续相位，切态不重置角度。
- **多光源背景**：三束低强度能量光 + 三个柔光团（左青扩散 / 右蓝纵深 / 上紫薄光）+ 近地投影；光效层总透明度浅色 `0.74`、深色 `0.48`——**低于状态形象**，边缘渐隐，不形成可见矩形。
- **光场几何与容器（2026-10-02 修订）**：光场容器＝**正文列整宽**（`top:-75px`、**高 `660px`**，准备 `520`／紧凑就绪 `640`／紧凑准备 `480`）；三个柔光团横向尺寸按**容器百分比**表达（`min(92%,820px)`、`min(86%,760px)`、`min(88%,780px)`），纵向沿用原型像素值（540／660／480，`top` 30／100／-20）；能量束 `min(150%,1280px)` × 840、`top:-40px`；近地光 `380×12`、`top:250px`。能量束必须带径向遮罩 `radial-gradient(ellipse, transparent 24%, #000 45%, transparent 72%)`——没有它，放大后是硬边圆环。**实现里不要用视口单位（`vw`）表达这套横向尺寸，也不要给光场容器加宽度上限**：原型那份光场跑在「与正文列等宽的 iframe」里，`vw` 就等于容器宽；实现若换回 `vw` 并给容器加 `max-width`，光场会比原型小一圈，还可能被裁出硬边。
- **光场要盖到下方卡片后面（2026-10-02 修订）**：光场纵向**必须越过状态区底部、一直铺到下方卡片（三卡与最近事件）之后**——下方卡片是玻璃面（`--glass-fill` + `backdrop-filter`），光在其后才会「透光」；若容器只盖到状态区（旧值 400／260／330／224），事件卡整块落在容器之外，会被 `overflow:hidden` 直接裁掉，一点光都收不到。纵向渐隐用一段长渐变（`transparent 0% → #000 6% → #000 55% → transparent 100%`），上端留住 Logo 附近的光，往下缓慢衰减到卡片之后。
- **光场不做逐层模糊（2026-10-02 修订，性能约束）**：光场**不要用 `filter: blur()` 柔化**——四个光层各做一次模糊（约 2.4M 像素）会把高档帧间隔 p95 顶到约 51ms；收成容器一层也只到约 31ms，仍贴着 §7 的 `2B(33.4ms)`；完全不模糊则约 26ms，而与「容器一层 20px 模糊」的成像差 ≤0.5/255（肉眼不可辨），光场带内相邻像素跳变仍是 1~2（无硬边、无波纹）。这几个光团本就是低频径向／锥形渐变，柔化本来就不需要。**能量束的径向遮罩才是防硬边的那一层，不能省。**
- 形象是**纯装饰层**（`aria-hidden`，无交互焦点），主线文字在父页；进入其它路由或页面隐藏时暂停；系统或页面「减少动态」直接呈现静态目标；不写真、不推定操作成功（动画节奏不代表业务进度）。

| 基础／语义 Token | 主题颜色、字号、间距、边框、焦点、层级，一份值源 |
| 表面配方 | `shell / page / panel / control / emphasis / overlay`；分别规定填充、描边、投影和模糊 |
| 档位覆盖 | 只改变有效 Token 与运动策略，不复制高／中／低三套页面 |
| 基础组件 | Button、Card、Dialog、Menu、Tabs、Badge、Input 等统一变体、忙碌／禁用／焦点规则 |
| 通用布局／组合 | 分栏、间距、键值、路径、设置行、步骤进度；独立于业务状态 |
| 业务组件 | 环境准备、运行舞台、运行详情、同步等组合，消费既有状态和能力 |

组件可按职责使用 `variant / tone / size / density / surface`，不是一个万能组件或多个相互覆盖的档位布尔值；组件内部样式随组件，公共策略集中维护。详见 IMP-05 §3。基础组件不读业务 store，不调用 IPC；每页不再各自写一份玻璃配方、减少动态逻辑或定时器。
