Risks

15 条风险

「阻塞」指的是：这些条目必须在对应能力开工前处理完，不能带着走进实现。

编号风险阻塞现状
R-01原型已承诺扩展管理，但正式需求未授权，实施人员可能把原型当范围否已关闭：正式纳入需求并回写
R-02设计 QA 文档累积多轮历史方案，容易被误读成当前仍有多个选项否已加「以最后定稿章节为准」声明
R-03候选原型可能被误认为正式入口否已在原型 README 说明
R-04界面已隐藏阶段编号，但文档仍在用 P0/P1/P2 描述原型边界否口径已分开：阶段信息只留文档
R-05扩展管理涉及真实系统高风险写入：多客户端配置、删除 MCP、卸载 Skills、改命令参数是已补安全条款，实现前仍需闭环
R-06MCP 的 command / args / env 能执行任意本地程序，不能当普通表单字段是已定确认与展示策略
R-07需求声明不写 OpenCodex 配置，但 MCP 路径含 config.toml，可能制造第二个写入者是已拆分允许管理 / 禁止管理边界
R-08多客户端配置不一致、外部应用改动后缺冲突检测是已核实六家客户端都有官方写入者，按共享写入处理
R-09删除类操作（卸载 Skills、删除 MCP）不可恢复是已定可恢复性与确认模型
R-10原型状态数量超过文档，且混成单一状态机否已拆成运行 / 连接 / 操作三维
R-11多个高风险操作缺失败、取消、回滚与并发状态表达部分依赖 OQ-02 ~ 06 的结论
R-12通知中心与诊断中心共用数据源，两处各自维护会导致不同步否已声明共用，实现需单一数据源
R-13需求追踪、场景矩阵、验收矩阵缺失，无法判定闭环否已补齐三份产物
R-14未决项若被实现工作绕过，会产生越权实现是未关闭的 OQ 一律作为 Gate 阻塞项
R-15官方项目自己也在做扩展编辑能力，本产品的扩展管理落在官方也会做的区间内否差异点定为「运行管理 + 配置管理一体」
6 条阻塞项集中在两处：扩展管理的真实写入面（R-05 ~ R-09），以及未决项不能被绕过（R-14）。这两处在「07 开工清单」里对应工作包 WP-20。
