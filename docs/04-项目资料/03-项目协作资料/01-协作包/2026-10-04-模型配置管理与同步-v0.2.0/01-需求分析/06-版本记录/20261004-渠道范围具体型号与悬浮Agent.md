## 本轮交互与规则

渠道范围提供全部、白名单、黑名单。全部包括以后新增渠道；空白名单不匹配任何渠道，空黑名单允许全部。切模式保留勾选，旧数据缺模式时按非空白名单 / 空全部迁入。此范围只控制模版自动匹配，与 selectedModels 的发布白名单独立，discovery 保持开启。

族通用配置下可自由添加具体型号，按完整原始模型 ID 的字面后缀识别，沿用版本大小写策略；同时命中仅取最长后缀，不叠加多个型号。无子项仅用通用配置，子项未自定义字段继承通用层；重复 ID / 等价后缀和无效合成配置阻止保存。自动匹配先通过顶层范围和包含 / 排除；显式单模型引用保留可见的人工指定例外。

协议优先级为渠道默认 → 模版通用 → 具体型号 → 渠道族覆盖 → 单模型覆盖。能力优先级为官方声明 → 模版通用 → 具体型号 → 渠道默认 → 渠道族覆盖 → 单模型覆盖。模版版本、复制、比较、导入导出和外部任务保留渠道模式及可选 variants；人工上下文锁覆盖通用层和每个子项，删除锁定子项也受保护。导入旧形状未带 variants 时保留当前编辑子项，显式空数组视为清除请求，仍经锁及冲突检查。生产 schema 尚未冻结，不能把 mock 扁平字段与结构化示例直接等同。

编辑器内部导航可展开 / 收起，依次为基本信息、匹配范围、族通用配置、具体型号、来源与版本；一次展示一个分区，切换保留缓冲。表单前提供自动填充入口，并复用既有 Logo 动效候选作为窗口内悬浮按钮。展开非模态对话面板，无遮罩，页面与面板分别滚动；公共模态在面板之上，Select 继续最顶层。最终与设置版本更新组件共用的实现仍待核对，当前不是生产组件验收。

对话输入 / 消息按模版隔离，生成冻结目标、基准、执行身份；晚回不会把用户从当前模版切走，停止使晚回失效。异步重绘保留输入焦点、光标和滚动。接受建议只改编辑缓冲；variants 整数组冲突保留人工数组并提示。当前 mock 仅有一个全局待比较建议并记录目标，正式并发多建议、逐子项合并、持久对话、检索和 runner 仍由 WP-06 承接。

## 模型别名调研与候选设计

只读核对本机 OpenCodex 2.69.0：provider.modelAliases 支持原始 ID → 路由别名，modelDisplayNames 提供显示名称；请求前仍解析回原 ID。合法示例为 Vendor-GPT_5.4-Custom → gpt54；gpt- 等保留前缀、大小写重复与原生 / 组合身份冲突须拒绝。原始 modelId 继续用于发现、选择、排序、后缀匹配与请求。

Desktop 候选把 naming.alias / displayName 置于单模型渠道策略，再编译为运行 provider 映射；本轮只补示例与方案，没有绘制别名表单或实现编译器。具体本机源码和约束见[调研依据](../02-方案草案/本地调研依据.md#模型别名与显示名称核对2026-10-04)及[规则方案](../02-方案草案/模型模版与匹配规则方案.md#7-模型原始-id别名与显示名称)。此结论不外推为官方 Codex config.toml 的任意映射能力，Fast、目录预算、分组与旧会话兼容由 G-10 / AC-M94 待验。
