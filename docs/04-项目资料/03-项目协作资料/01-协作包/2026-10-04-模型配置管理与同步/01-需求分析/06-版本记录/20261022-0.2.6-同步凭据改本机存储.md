# 0.2.6：同步凭据改本机存储（不依赖证书与系统钥匙串）

2026-10-22，0.2.5 装机后用户反馈“同步总是要我输入密码”，并连续确认三条约束：“能不能不用证书、不要密钥、不走 mac 密码就可以做到？”“这样做的话 windows 也可以支持吗？”“可以写进去。”本文登记判定、目标方案与实施边界。仅记录，未实施。

## 判定

“总是要输密码”是三条互不相干的路径叠在一起，必须分开修：

| 编号 | 触发时机 | 要的东西 | 性质 |
| --- | --- | --- | --- |
| A | 打开 WebDAV 页、每次同步、每次测试连接 | macOS 钥匙串授权 | 发布形态 |
| B | 连接设置点「保存端点」 | 应用内「应用密码」 | 代码缺陷 |
| C | 从 WebDAV 下载快照 | 「配置同步保护口令」 | 设计缺口 |

A 的根因已用本机实测确认：产物是 ad-hoc 签名（`flags=0x20002(adhoc,linker-signed)`、`TeamIdentifier=not set`），钥匙串 ACL 绑定的 CDHash 每次构建都变，旧条目认不出新版本，于是每次都弹；且代码里每处 `load_webdav_password()` 都真读钥匙串，进程内无缓存。

## 决策

不引入证书、不使用系统钥匙串、不弹 macOS 密码；macOS 与 Windows 同时支持。凭据改存本机数据目录。

## 目标方案

`infrastructure/keychain.rs` → `infrastructure/credentials.rs`，同一套接口 `store / load / load_optional / remove`，按平台分支：

| | 路径 | 保护 | 证书 | 系统弹窗 |
| --- | --- | --- | --- | --- |
| macOS | `<数据根>/manager-state/credentials/<ref_id>.json` | 0600 文件 / 0700 目录 | 不需要 | 不弹 |
| Windows | `%APPDATA%\com.gzers.opencodex.desktop\manager-state\credentials\<ref_id>.json` | DPAPI 当前用户作用域密文 | 不需要 | 不弹 |

落地条件已核对：数据根用 `app.path().app_data_dir()`（两端自动正确）；`atomic_write.rs` 已跨平台并含 Windows 共享冲突重试；`platform.rs` 的 `set_mode` 在 Windows 是 no-op，因此 Windows 靠 DPAPI 而不靠权限位；`windows-sys 0.61` 已是现有依赖，补 `Win32_Security_Cryptography` feature 即可，不引新 crate。

## A / B / C 的修法

- **A**：读写脱离系统钥匙串；进程内启动时读一次并以 `Zeroizing` 缓存，端点变更或删除时失效；启动时尝试把旧钥匙串条目迁移一次（可能仍弹一次），失败不阻断启动；清理 3 条无引用的 `ocx.dav.*` 残留。
- **B**：已存在端点且表单口令为空时沿用已存口令；`validate_input` 改为“表单与已存都为空”才拒绝；保存失败原因要可见，不再只有通用 toast。
- **C**：上传时填了口令即持久化；下载先读存储、读不到才弹窗；用户主动选“不加密”时删除已存口令。

## 范围边界

钥匙串上另有四类用途本轮不动：渠道 API Key、扩展密钥、渠道授权保护、官方 Key 引用。它们同样会在 ad-hoc 包上触发授权，但改动会牵动渠道保存与官方兼容，不与同步凭据混做。

## 代价

1. macOS 口令落盘为明文（0600 + FileVault）。这是“不要证书、不弹密码”的必然交换：macOS 没有 DPAPI 那种「无提示 + 加密」等价物。
2. Windows DPAPI 绑定当前用户，换账号或换机需重填一次；与系统凭据管理器同性质。
3. 日后若要加强 macOS，可在同目录放应用自持随机密钥做 AES-GCM；防“拷走目录”，防不了“本机读权限”。纯增量，接口不变。

## 未决

1. 旧钥匙串条目迁移时机的选择：启动时静默尝试（可能弹一次）还是首次同步前惰性迁移？
2. 缓存失效粒度：仅端点变更/删除，还是也包含应用偏好变化？
3. `CredentialRef.backend` 字段现为固定字面量 `keychain`，新后端下是否改名（涉及 `sync-endpoints.json` schema 与配置校验），还是保留字段仅为历史兼容？
