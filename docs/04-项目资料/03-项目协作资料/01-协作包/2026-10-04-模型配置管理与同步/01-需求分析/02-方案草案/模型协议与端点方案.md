# 模型协议与服务节点方案（0.2.0 候选）

更新：2026-10-14。用户澄清并确认：一个渠道服务有多个访问节点，节点仅 URL 不同，认证与 Key 共用；第一版手动切换当前节点；本轮追加列表独立服务节点列，以及集成选择 / 单节点检测 / 一键检测的下拉组件。此前“一个渠道维护多个独立协议 / 凭据端点”的设计被本轮替代，历史记录保留当时范围。本文承接[主方案](模型配置管理方案.md)、[交互细化](模型页交互细化.md)与[本机调研](本地调研依据.md#单模型协议与多端点核对2026-10-04)，仍是候选设计与内存 mock，不代表生产路由已实现。

## 1. 渠道、协议与节点的职责

| 层级 | 配置与作用 |
|---|---|
| 渠道 | 稳定渠道 ID、名称、一份认证 / Key、模型清单与选择、排序及规则 |
| 服务节点 | 稳定节点 ID、名称、Base URL；同渠道共用认证，无独立协议 / Key / 模型清单 |
| 当前节点 | 渠道级 activeNodeId，所有模型共用；手动切换加入草稿，明确保存后生效 |
| 模型模版与模型 | 协议、能力、上下文、推理及 Fast 等规则；不保存节点 URL 或凭据，不单独指定节点 |

新增渠道时填写的 Base URL 自动成为 primary 默认节点；后续 URL 只在“服务节点”维护，不在渠道配置保存第二份地址。渠道配置保留默认接口协议与认证。节点名称不是协议名，URL 也不能证明上游支持某协议。节点的初始约定是同一服务的等价访问入口；同一组模型可否调用仍须上游及真实适配校验。

若不同入口需要独立 Key、账户或模型目录，不能作为本方案的同渠道节点静默合并，应作为独立渠道或另行评审连接类型。

## 2. 协议优先级与继承

协议从低到高保持：**渠道默认 → 所采用的一份模版通用输出协议 → 命中的具体型号输出协议 → 渠道内族覆盖 → 单模型覆盖**。继承跳过本层，未采用候选不影响运行。协议不反向参与模版匹配；匹配仍先选择精确引用或最高优先级的一份已采用版本，冲突阻止相关保存。

能力字段继续按“官方声明 → 模版通用 → 具体型号 → 渠道默认 → 渠道族 → 单模型”解析。采用新 revision 默认保留人工规则和精确引用；明确清除单模型例外时只清字段覆盖，不涉及服务节点。具体匹配见[模版规则方案](模型模版与匹配规则方案.md)。

协议决定请求格式 / 路径，当前节点提供 Base URL，渠道提供认证。Responses、Chat、Anthropic 等协议可以有不同请求路径，但不因此要求用户新建一条含协议和 Key 的节点。

## 3. 最终协议与节点选择

渠道服务节点唯一保存 URL，连接由当前节点 URL 与渠道认证组合。节点切换不改变模型协议、白名单、模型顺序、模版引用或 Key，也不增加模型目录项或目录预算。

| 情况 | 行为 |
|---|---|
| 有有效当前节点与完整渠道认证 | 所有模型使用该节点，协议分别按既有规则解析 |
| 新增节点 | 只添加名称 / URL，保留当前节点；首次建立渠道自动选默认节点 |
| 手动设为当前 | 加入草稿，保存差异显示旧 / 新节点及 URL；保存前已提交配置与 Agent 使用原节点 |
| 编辑节点 | 保持稳定 ID；修改当前 URL 使连接验证状态过期，不清模型清单或规则 |
| 多节点 | 不按协议分配；按需单节点 / 一键测速，不轮询、定时测速或自动故障切换 |
| 测速 | 只产生会话级观察，显示接口响应耗时 ms / 失败 / 超时，不表示模型生成速度、可用模型能力或额度，不自动切节点 |
| 删除当前节点或最后一条 | 阻止；先切换到其他节点，至少保留一条 |
| 当前节点缺失 / 地址或认证未配置 | 保留草稿并阻止受影响保存；不静默选另一节点 |
| URL / 名称重复或 URL 含认证信息、查询参数、生成接口路径 | 要求修正，不创建重复节点 |

节点编辑 / 删除确认绑定渠道及编辑基准；过期确认不能覆盖新修改。尚未确认的渠道认证编辑先处理再管理节点；保存期间节点操作锁定。切换当前节点或修改当前 URL 取消旧清单获取结果的晚回，原模型清单和选择保留，可主动刷新重新核验。

节点切换后不沿用旧节点的连接检查结果。保存成功、连接检查通过、客户端加载和用户确认分开记录；原型不发网络请求，不测试真实 Key。

## 4. 编译到 OpenCodex 的路径

本机已核对的 2.69.0 有受限 per-model modelAdapters（openai-chat / openai-responses），Anthropic / Google 等原生 adapter 的合法组合仍需按实际版本、路径及认证契约校验。参照[本机证据](本地调研依据.md#单模型协议与多端点核对2026-10-04)，本轮未重新验证运行产品。

编译器读取一个渠道当前节点的 URL 和一份渠道 credential ref，再解析各模型最终协议。能合法用单 provider 与 modelAdapters 表达时复用；需要协议分组时，所有分组仍共用当前节点和渠道认证。协议分组是运行适配职责，不重新引入用户可配置的独立 Key 端点。受管 provider / catalog 身份不能因切节点或白名单变化而随意重派生，旧会话兼容须实施核验。

当前 mock 只演示协议分组、当前节点引用和写入计划，不能据此承诺上游支持全部协议或官方客户端原生支持多 URL。真实手动切换可以是管理器更新已选运行连接再提示重启；生产接口、配置写入、读回与旧会话依赖仍待 WP-01 / WP-02 完成。

第一版提供用户主动触发的单节点 / 当前渠道全部节点测速，最多两个任务并行，支持停止。运行实现应采用适配器支持的轻量、只读接口探测，不用模型生成测速，具体接口和超时策略待 WP-01 核验；当前原型只有确定性 mock。结果绑定节点 URL、渠道协议与认证版本，配置改变后失效；结果不自动切节点、不写入模型策略或同步包。仍不引入定时探测、自动重试、轮询、熔断或请求级故障转移，未来扩展另行确认运行支持和请求重发语义。

## 5. 保存、恢复与边界

节点和模型更改都进入同一全渠道草稿。保存先展示逐项节点增删 / URL / 当前节点、认证状态与模型规则差异，再校验预算、协议和本机绑定，冻结基准，确认后按备份 / 写入 / 读回流程处理。超时或部分失败先核对，不标成功。成功提示待重启。

返回详情不写配置，工作区草稿保留；列表更多的全部草稿丢弃先列范围并拦截过期确认。保存记录恢复先生成草稿，保留后续冲突修改，再明确保存。旧节点 URL 及当前节点属于本机恢复范围，Key 实值不由原型保存或恢复。

## 6. 导入、同步与外部 Agent

便携模型策略示例携带节点 ID / 名称及当前节点引用，URL 和渠道凭据引用仍依本机绑定规则保存；完整配置同步是否携带节点地址，沿配置同步包的用户范围与凭据选择规则，不能因本次 UI 收简更改既有加密 / 身份确认边界。

原型旧便携候选合并同身份节点时保留本机 URL；新节点缺 URL 显示待配置，当前节点未绑定阻止保存。同渠道合法切换 URL 不应被误判为新服务身份，外来同名不同服务仍需身份确认。生产导入 schema、节点稳定身份与本机绑定迁入待冻结。旧多协议端点若含不同凭据或服务，不能直接批量转成共用 Key 节点，须显式评审迁移；本轮没有运行数据迁移。

外部 Agent 任务只带节点稳定 ID、名称、当前标记和地址 / 认证是否配置，不带真实 URL / Key，不允许结果改节点或认证。模版候选仍只保存规则，不自动切默认版本或渠道引用。

示例见[model-policy.example.json](model-policy.example.json)，仅说明结构与关系，不代表生产 schema 定稿。

## 7. 原型入口与状态

唯一[产品主原型](../../../../../01-项目支撑资料/01-产品原型/原型/index.html#models)：渠道模型行内“编辑” → 渠道配置 → 服务节点 → 模型默认 → 模型列表。渠道列表独立设置服务节点列，单行触发器显示当前节点与响应耗时（名称超长省略，窄窗水平滚动）。下拉浮层每行包含节点名称 / 当前选中标记、检测结果和单独检测按钮，顶部集成一键检测 / 停止及进度；点击节点名称才切换草稿，检测动作不选择节点。外部点击、焦点离开和 Esc 收起，Esc / 选择后焦点回到触发器；滚动 / 切页 / 重绘清理悬空浮层，收起不取消在途检测；异步结果只更新原单元和按钮，不重建选择器。详情节点列表展示名称、URL、当前标记、响应耗时及测速 / 设为当前 / 编辑 / 删除，标题旁提供一键测速。等待 / 测试中 / 成功 / 失败 / 超时 / 停止分开显示，完成进度不把已取消项算作已完成，部分已完成结果停止后保留。异步更新不重建编辑表单或抢弹窗。新增 / 编辑只填名称和 URL。模型展开编辑和明细只保留协议 / 能力规则，移除单模型地址选择。

标题、保存按钮、差异确认、恢复与 Agent 仍沿现有全渠道保存边界。原型仍是内存 mock，真实布局、网络适配、加载与生产验收分别需要证据。本轮变更与检查记录见[服务节点改造](../06-版本记录/20261014-共用认证的服务节点与手动切换.md)。


## 2026-10-20实际2.84.0请求边界补充

本方案“按实际适配器支持校验”在生产保存门落实：Responses/Anthropic虽能保存noReasoningModels，但回环实际请求仍携推理参数，不作为显式“不传”支持。当前noReasoning=true、pin、非空标签映射和请求权威true只准入最终OpenAI Chat目标；其他协议规则可存候选，运行保存前须恢复继承或选用已支持协议，不能报伪成功。原上游兼容字段在无关编辑中保持。节点/Key共用与协议组身份规则不变；Fast service-tier/anthropic-speed的正向wire证据单列，不与推理门捆绑。本条是对既定“不支持则阻止应用”的实际适配校正，不新增端点/认证概念或付费探测范围。
