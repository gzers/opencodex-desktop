# 验证设计与交接

## 1. 目标

先设计“如何证明正确”，再授权写测试。所有验证分为：隔离功能、隔离系统集成、目标环境验收、发布验证四层。

## 3. 场景路径模板

每个 AC 场景至少登记四类路径：

| 路径 | 必须证明 |
|---|---|
| 正常 | 输入、动作、状态变化、可观察输出 |
| 失败 | 触发点、错误摘要、资源不变 |
| 取消 | 取消点、无副作用或明确清理 |
| 恢复 | 备份、回滚、人工路径或重试结果 |

## 5. 证据格式

每个 TASK 回执至少记录：

```text
evidence_id
task_id
commit_or_artifact
check_name
result: passed | failed
command_or_method
environment: isolation | target-environment | release
fixture_ids
expected
actual
logs_or_screenshot_ref
checked_at
```

失败回执必须保留完整失败原因和清理结果；不允许只写“重试后通过”。

## 6. Mock 与目标环境边界

| 层次 | 可以证明 | 不可以证明 |
|---|---|---|
| 隔离功能 | 状态映射、路径规则、加密、白名单、枚举 | 真实权限、系统行为 |
| 隔离系统集成 | 并发锁、临时目录、fake runner、局部 mock 网络 | 真实 Keychain、真实远端、真实 GUI |
| 目标环境验收 | macOS arm64 的真实 CLI、Keychain、窗口、权限、受控 WebDAV | 未授权平台的行为 |
| 发布验证 | 签名、公证、安装升级回退、更新通道 | 未完成安全确认的发布决策 |

`R-17` 生产面板不进入发布验证前置；发布前单独确认。
