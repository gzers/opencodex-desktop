## 四、如何继续

```sh
# 一次跑完全部可自动化验证（18 项）
cd apps/desktop/ui
OCX_OFFICIAL_ENTRY=<官方 ocx.mjs> OCX_OFFICIAL_NODE=<node> npm run gate:release

cd apps/desktop/tauri && cargo fmt --all -- --check && cargo clippy --locked --workspace --all-targets -- -D warnings
```

补齐五项后按发布交付页的「0.2.7 发布程序」执行：合并 main → 打 `v0.2.7` → 验签与版本回读 → `publish/v0.2.7` → 可选 `promote-stable/v0.2.7`。

## 五、不要重复的事

- 不要重新核对规格条文与原型一致性：五套并排对照已覆盖六个主要界面。
- 不要重新跑合并演练：已确认无冲突且合并后测试通过。
- 不要试图在隔离 HOME 里让官方 CLI 写盘：归属证明是官方安全设计，无测试豁免。
- 不要为「看起来更完整」而新增界面微调：已超出原型范围，只会引入回归。
- **不要把 WebKit 自动化通过当成原生窗口通过**——这正是本轮拖拽缺陷漏过去的同一类误判。
- 不要用 `cargo test --lib` + `--tests` 替代 CI 命令：带 `--features integration-test` 时是 39 个测试二进制，不是 38。
