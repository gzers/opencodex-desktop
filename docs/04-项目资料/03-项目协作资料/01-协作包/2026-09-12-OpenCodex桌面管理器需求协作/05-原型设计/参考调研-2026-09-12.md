## 关键发现

### 1. 窗口基准：同类产品都在 1000×650 ~ 1280×800

从三个 Tauri 桌面应用的 `tauri.conf.json` 直接读到：

| 项目 | 默认窗口 | 最小窗口 | 其它 |
|---|---|---|---|
| CC Switch | **1000 × 650** | 900 × 600 | `titleBarStyle: "Overlay"`、`title: ""` |
| SkillDock | **1280 × 800** | 1024 × 700 | `titleBarStyle: "Overlay"`、`hiddenTitle: true` |
| Agent Manager | **1200 × 800** | 900 × 600 | 常规标题栏 |

对照我们的实测：概览要「单屏」需要窗口高 **约 1030–1040px**，比同类默认窗口高 **300–390px**。这说明不是我们要求苛刻，而是当前布局确实超出了一个桌面管理器该有的窗口尺度。

顺带确认：CC Switch 与 SkillDock 都用 `titleBarStyle: "Overlay"` + 空标题，和我们原型里自绘标题栏的思路一致，这条不用改。

### 2. 进程控制不该放在卡片里，应该在常驻状态条

**Rancher Desktop** 的布局文件 `pkg/rancher-desktop/layouts/default.vue` 只有三段：

```
nav（左侧导航） → body（页面内容） → <status-bar>（常驻）
```

相关组件：

- `components/StatusBar.vue` + `StatusBarItem.vue`：常驻状态项（如 Kubernetes 版本）
- `components/BackendProgress.vue`：常驻左下角，显示后端启动 / 切换的进度条
- `components/AsyncButton.vue`：异步操作中的按钮态（进行中 / 成功 / 失败）

**借鉴点**：启停这类「作用于整个应用、任何页面都可能用」的控制，放在常驻状态条里，而不是塞进某一页的某张卡。这样它天然不和导航类按钮混排，也不会随页面滚动被推走。

→ 直接解掉审计 A1（主操作不在主位）与 A3（一行 6 个按钮混 4 类语义）。

### 3. 按钮应该随状态出现，而不是禁用

**Podman Desktop** 把「一个 provider 卡」拆成一组状态组件（`packages/renderer/src/lib/dashboard/`）：

```
ProviderNotInstalled      ProviderDetectionChecksButton   ProviderInstallationButton
ProviderInstalled         ProviderConfiguring             ProviderConfigured
ProviderStarting          ProviderStopped                 ProviderReady
ProviderUpdateButton      ProviderWarnings                PreflightChecks
```

每种状态只渲染该状态合法的操作，而不是渲染全部按钮再逐个 `disabled`。

**借鉴点**：为 `loading / not_found / stopped / starting / pending / running / starting_failed / at_risk / external_takeover / unreachable` 分别定义「这一态下出现哪些按钮、显示什么文案」，取代当前「固定 6 个按钮 + 灰掉一部分」的做法。

→ 直接解掉审计 A4（探测中三个灰按钮且无解释）。

### 4. 卡片要有密度分级，而不是靠拉高窗口

同一目录下，Podman Desktop 给 provider 卡做了**三档密度**：

```
SystemOverviewProviderCardBase / ...Compact / ...Detailed
```

外加 `SystemOverviewContent`、`SystemOverviewResourceUsage`、`SystemOverviewProviderSetup`。

**借鉴点**：概览定义 `compact / detailed` 两档——窄窗口用 compact（只留状态 + 主操作），宽窗口用 detailed（补端口 / PID / 路径）。用**信息密度降级**换取「小窗口不挤」，而不是要求用户把窗口拉到 1040px 高。

→ 直接解掉审计 C（窗口变小内容就挤开）。

### 5. 路径与日志属于「故障排查」，不属于概览

**Rancher Desktop** 的一级导航是：

```
General / Containers / Port Forwarding / Images / Volumes / Kubernetes
/ Troubleshooting / Diagnostics / Snapshots / Extensions
```

关键点：**General（主页面）不放路径细节，Troubleshooting 和 Diagnostics 各是一级页面。**

而 `components/TroubleshootingLineItem.vue` 的结构是「卡内一行 = 标题 + 说明 + options 插槽 + actions 插槽」，也就是**一行一项、右侧直接挂操作按钮**。

**借鉴点**：完整路径、打开目录、重置这类内容，按「一行一项 + 右侧操作」放进诊断 / 故障排查区；概览只保留「统一数据根 + 是否默认位置」这一条结论式信息。

→ 直接解掉审计 B（4 条完整路径占 20% 页面且可推导）。

### 6. 同域产品的一级信息架构（供侧栏对照）

| 产品 | 一级导航 / 模块 |
|---|---|
| Rancher Desktop | General、Containers、Port Forwarding、Images、Volumes、Kubernetes、**Troubleshooting**、**Diagnostics**、Snapshots、Extensions（设置另开一层 Preferences，内含 General/Behavior/Environment/Network/Integrations/Proxy/Hardware…） |
| Podman Desktop | dashboard、**engine**、containers、images、pods、volumes、**onboarding**、**task-manager**、**statusbar**、**troubleshooting**、**welcome**、preferences、learning-center、feedback |
| CC Switch | AppSwitcher（顶层工具切换）、providers、proxy、mcp、prompts、skills、sessions、agents、usage、workspace、settings |

共同规律：

1. **功能/资源 = 一级导航；设置另开一层。**
2. **故障排查 / 诊断是一级页面**，不是主页面里的一个区块。
3. **首次运行单独做 onboarding / welcome**，不塞进主页面。
4. **长任务有独立的 task-manager / 进度条**，不挤在按钮边上。

对照本原型：`概览 / 面板 / 日志 / 设置` 四条偏少——缺「首次运行」「长任务进度」的承载位，而这两件事现在都被压进了概览和按钮行里。

### 7. 更新与备份：收成徽标 + 一步动作

- **CC Switch**：`components/UpdateBadge.tsx`、`DatabaseUpgrade.tsx`、`FirstRunNoticeDialog.tsx`；README 明确「自动更新、原子写入、自动备份」，云同步支持 WebDAV / 坚果云 / NAS / Dropbox / iCloud / OneDrive。
- **Rancher Desktop**：`components/UpdateStatus.vue`、`AutoUpdateCheckbox.vue`。
- **Latest**：整个产品只做一件事——把「你用的应用有新版本」讲清楚并给出升级入口。

**借鉴点**：概览上的「检查更新 / 升级前备份 / 升级设置」三个并列按钮，可以收成一个带状态徽标的更新条目（有更新时才展开动作），把三个按钮压成一个。

### 8. 迁移与首次运行走独立向导

CC Switch 用 `DatabaseUpgrade.tsx`（数据库结构升级）和 `FirstRunNoticeDialog.tsx`（首启告知）承载「会改数据」的动作，而不是放进主界面。

**借鉴点**：数据根切换、配置导入、restore 这些会影响数据的流程，用独立向导 / 弹层承载，主界面只给入口和当前状态。

## 审计问题 → 借鉴方案对照

| 审计问题 | 借鉴项目 | 借鉴做法 |
|---|---|---|
| A1 主操作不在主位；A3 一行 6 按钮混 4 类语义 | Rancher Desktop | 进程启停移入常驻状态条，与页面内导航按钮物理分离 |
| A4 禁用按钮无解释 | Podman Desktop | 按状态渲染按钮，而非固定按钮 + disabled |
| A5 版本信息重复 | CC Switch / Rancher | 更新状态徽标统一承载版本与更新信息，其它位置不再复述 |
| B 环境路径过细 | Rancher Desktop | 路径细节移入诊断 / 故障排查，按「一行一项 + 右侧操作」呈现 |
| C 窗口变小就挤 | Podman Desktop / 同类窗口配置 | 卡片做 compact / detailed 密度分级；窗口基准对齐同类 1000×650 ~ 1280×800 |
| 侧栏信息架构偏薄 | Rancher / Podman / CC Switch | 增设「首次运行 / 故障排查」承载位，长任务给独立进度槽 |
| P1/P2 快捷卡被读成已实现 | CC Switch（未实现能力明确分区） | 未实现能力用规划态占位，不与真实状态混排 |

## 建议的落点（若采纳）

1. **窗口基准定 `1180 × 760`（默认）/ `900 × 640`（最小）**，与同类区间对齐；「单屏」降级为目标不是硬约束。
2. **概览重构为三段：常驻状态条（状态 + 启停）+ 状态详情（可折叠）+ 快捷动作。**
3. **按钮改为状态驱动**：每个状态定义自己的按钮集合，不再出现无解释的灰按钮。
4. **路径收敛为一行**，完整路径与打开目录进诊断区。
5. **未实现能力（P1/P2）统一规划态**，不与真实运行状态同框显示。
