## 目标清单

| 分类 → 对象 | 携带内容 | 文件导入 / 导出 | WebDAV | 凭据处理 |
|---|---|---|---|---|
| 模型模版 → 一份模版 | 已保存版本、匹配范围、协议 / 能力、版本或后缀、来源、精确引用 | 可选模版与版本 | 可选；主版本变化先待审 | 不保存 Key |
| 渠道与模型 → 一个逻辑渠道 | 端点、协议、显式模型、启停、顺序、别名、覆盖、模版引用 | 可选渠道；明细可限定模型 | 可选，上传已提交配置 | API Key 与认证字段单独选 |
| OpenCodex 原有渠道 / 模型 | 包含非 Desktop 创建的实际配置 | 纳入同一渠道清单 | 纳入同一清单 | 同上 |
| 账户 → 一个账户 | 提供方、稳定身份、显示信息、授权上下文 | 可选账户 | 可选账户 | 勾选账户默认包含可迁移的登录态 / 刷新材料；详情可选仅账户信息 |
| Skills → 一个扩展 | 实际 SKILL.md 和所需资源、启用与分发信息 | 可选 | 可选 | 可识别秘密排除；未知自定义内容待检查 |
| MCP → 一个定义 | 传输、命令 / 参数 / 地址、启用与目标配置 | 可选 | 可选 | 环境变量、授权头等另选受保护部分 |
| 桌面偏好 → 可移植偏好 | 主题、语言等字段白名单 | 可选 | 可选 | 排除机器路径和执行绑定 |
| WebDAV 配置 | 地址、目录、用户名与连接密码 | 默认勾选；导入为未启用连接 | 不参与自覆盖 | 密码默认随配置携带，可选仅配置；分享预设排除密码 |

模型范围仅 OpenCodex；不扩展为直接同步独立 Codex 客户端自身的 provider / model 设置。账户范围是 OpenCodex 管理和使用的登录账户，恢复真实登录态的可行性逐类核验，不泛化为同步任意客户端的全部浏览器 Cookie 或系统登录状态。

普通默认选择全部可移植配置，其中已选账户包含可迁移的登录状态；文件同步默认勾选 WebDAV 配置并携带连接密码，对象详情可选“仅同步配置，不含密码”。渠道 Key 与扩展凭据仍需另选。“分享配置 · 不含凭据”预设关闭全部受保护部分，保留 WebDAV 普通配置。WebDAV 配置不参与 WebDAV 自同步；设备路径、日志、缓存、进程状态、发现缓存、失败 journal、未提交草稿、Agent 完整对话和执行身份绑定不属于默认同步内容。

## 统一对象与应用计划

Desktop 的 model-policy.json 与 OpenCodex 运行字段可能描述同一渠道。以稳定渠道 ID、提供方 / 认证身份、端点映射建立统一对象；展示两个来源，不制造两份可独立覆盖的渠道。不能只按显示名称去重。

导入先比较目标运行配置与已知提交基准；外部修改构成漂移，不能凭 Desktop 快照强行覆盖。将模版、策略、原有渠道、账户和扩展转换为一个范围明确的应用计划，由各域适配器执行；不同域可能非原子，结果逐域报告。

本地发现结果、生成的运行字段与持久配置要标明来源。只将用户明确配置且可重建的内容当作可移植事实。字段明细按需显示来源文件、身份、依赖和包含项，主界面不要求用户理解目录结构。
