# 状态形象动画 · 方案分析（候选）

> 2026-09-28 · 用户批注：不满意概览用「颜色显示块」表达状态、占用空间大；希望改成 **SVG 形象动画** 表达不同状态，并能 **实时响应** 状态变化。
> 本文只做分析与候选验证，**不改现行原型、不改生产代码、不冻结视觉**。候选演示：`./index.html`。

## 1. 目标与边界

- **目标**：用一个形象化的 SVG 图形承载「运行主线 / 当前支线 / 持续问题 / 操作结果」，替代或压缩状态色块，做到占用小、一眼可读、随状态实时变化。
- **边界**：形象是**状态的另一种投影**，不是新的状态机、不是新的真源。语义仍以 `docs/02-项目核心/数据与状态.md` §2.7、§5.8 为唯一来源；形象只消费与摘要卡、托盘一致的投影。
- **不改变**：状态枚举、CLI、动作能力与安全边界；不把「过期事实」画成「实时」。

## 2. 它放在哪、承担什么

| 位置 | 承担 | 说明 |
|---|---|---|
| 概览摘要卡（首选） | 主线 + 支线/结果 + 问题 | 取代现在的「状态点（色块）+ 文本」，形象与文本同源并排 |
| 概览空态 / 首次引导 | 待接入、正在确认 | 用形象缓和「未安装」的观感，仍给出真实下一步 |
| 托盘图标（可选复用） | 仅进程事实 | 同一图形降级为单色 16px 模板图标；结论不进托盘（§15） |
| 诊断/详情 | 与主线一致的小图形 | 保持同源，不新增第二套状态 |

**信息层级不变**：形象只替「状态点 + 标签」这一小块；环境、路径、检查明细仍在详情里。

## 3. 状态 → 动画映射（建议）

| 状态（§2.7） | 形象表现 | 动效 | 颜色 |
|---|---|---|---|
| 正在确认 | 环扫描 + 眼睛左右探看 | 扫掠 1.3s 循环、天线脉冲 | 蓝 |
| 待接入 | 灰、虚线环、身体偏暗、眼睛一条线 | 静态（或极慢） | 中性 |
| 未运行 | 灰环、呼吸、眼睛半睁 | 呼吸 3.4s | 中性 |
| 运行中 | 绿环、轻微浮动、偶发眨眼 | 浮动 2.6s、眨眼 4.4s | 绿 |
| 支线进行中 | 环旋转 + 工作抖动 | 扫掠 0.9s、天线脉冲 | 蓝 |
| 操作成功 | 绿环 + ✓ 弹出 | 一次性 pop | 绿 |
| 部分完成 | 琥珀 + ½ | 静态 | 琥珀 |
| 失败 | 红环 + ! ，**一次抖动后稳定** | 抖动 0.5s（不循环） | 红 |
| 已取消 | 灰 + ✕，身体偏暗 | 静态 | 中性 |
| 结果待确认 | 蓝 + ? 轻微浮动 | 1.8s 循环 | 蓝 |
| 待重启生效 | 绿环旋转 + ↻ | 扫掠 1.6s | 绿 |
| 持续问题 | 琥珀环慢脉冲 + 担忧眼神 + ! | 2.4s 循环 | 琥珀 |

原则：
- **失败不做常驻警示**：一次抖动后回到「未运行 + 结果」，避免把一次性结果做成持续告警。
- **进行中才循环**：稳定态用极轻的呼吸/眨眼或静态，避免「一直在动」分散注意、增加耗电。
- **颜色不作唯一手段**：形状/符号/文本同时表达（可访问性）。

## 4. 技术选型

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| **内联 SVG + CSS 动画**（推荐） | 零依赖、可主题化（CSS 变量）、GPU 合成友好、易于 `prefers-reduced-motion`、Vue 里就是一个组件 | 复杂形变/骨骼动画能力有限 | ✅ 首选 |
| SVG SMIL | 可做路径形变、无 JS | 控制弱、工具链差 | 仅在需要路径形变时局部用 |
| Lottie / dotlottie | 设计稿直出、动画丰富 | 引入运行时 + JSON 体积；不易跟随主题色；状态机需自己粘 | 备选（若形象很复杂） |
| Rive | 交互状态机强 | 引入运行时 + `.riv` + 编辑器；对「小状态图标」过重 | 不推荐 |
| Canvas / WebGL | 极强 | 过重、可访问性与主题化差 | 不推荐 |

**推荐落地形态**：一个 Vue 组件 `<StateMascot :state :stale>`，内部是内联 SVG（分组：环 / 天线 / 头 / 眼 / 徽标），状态由根元素 `data-state` 单一属性驱动，CSS 关键帧负责动画，JS 只做属性切换与去抖。

## 5. 实时绑定与去抖

- **单一数据源**：复用现有状态投影（运行事实 / 支线 / 问题）。组件只订阅投影，不自行采集（§6.1 刷新协调器）。
- **只在变化时动**：`data-state` 变化触发 CSS 过渡 / 一次性关键帧；同值重推不重放动画。
- **去抖**：`starting → pending → running` 这类快速连跳可合并为「进行中」，避免形象抖动（例如 300–600ms 内多次变化只保留最终态 + 一次进行态）。
- **新鲜度**：事实过期 / 采集失败时（§2.7 的「上次观测」）形象切到 **stale**：降饱和 + 虚线环 + 时间提示，**绝不显示「实时运行中」**。
- **一次性结果**：成功/失败/取消等结果动画只播一次，随后回到所属主线态，不循环。

## 6. 性能

- 只用 `transform` / `opacity` 做动画（走合成层），不触发重排；`will-change` 仅加在少数元素上。
- 页面不可见（`visibilitychange`）与 `prefers-reduced-motion` 时**暂停**动画。
- 图形保持轻量（< ~30 个节点）；不引入位图/视频。
- 托盘图标为静态帧 + 极简（系统菜单栏不适合动画）。

## 7. 可访问性

- `role="img"` + `aria-label`（如「运行中」「启动失败，端口被占用」），状态变化时按需 `aria-live="polite"` 播报（可配置）。
- `prefers-reduced-motion: reduce` → 静态帧，仍保留状态与颜色/符号。
- 不依赖颜色：配合符号（✓ / ½ / ! / ✕ / ? / ↻）与文本。

## 8. 与现有规范的衔接

- 不新增状态：形象 = `数据与状态` §2.7 的投影；放在 `UI规范` §19 的摘要块内。
- 「简略＋详情」不变：形象替代色块，检查明细仍进详情。
- 托盘复用同一图形的单色版；结论仍不进托盘（`UI规范` §15）。
- 生产实现须与 §19.31.3 交接清单的字段/刷新改造一起做，不能只加动画。

## 9. 落地顺序（建议）

1. **视觉定稿**：本候选确认形象风格与状态映射（当前待用户确认）。
2. 缩到摘要卡尺寸（28–40px）验证可读性与窄窗口。
3. 用真实状态投影替换 mock 驱动；补 stale / reduced-motion / 暂停。
4. 托盘单色版打样（可选）。
5. 回写 `UI规范` §19 / `数据与状态` §2.7 引用，进 IMP 契约（字段无变化，仅展示层）。

## 10. 风险与待决点

- **风格风险**：形象「AI 味」/ 幼稚化；需克制、专业（建议机械/几何风而非卡通）。
- **干扰风险**：过度动画；坚持「只有进行中才循环」。
- **性能风险**：低端机；限动画范围 + 可见性暂停。
- **一致性风险**：形象与文本不同源会漂移；强制同源消费。
- **待决**：① 风格方向（机械/圆润/极小几何）？② 是否用于托盘？③ 是否保留一行文字标签，还是仅形象 + 悬浮说明？④ 配额（连续动画的可接受数量）。
