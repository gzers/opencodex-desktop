# 团队配置发布订阅需求输入

日期：2026-10-05（Asia/Shanghai）。来源：本轮用户会话。

## 用户原话

> docs/04-项目资料/03-项目协作资料/01-协作包/2026-10-04-模型配置管理与同步-v0.2.0
> 这里再思考下，虽然之前有webdav同步配置、导出配置，但是都是针对个人。对于团队，大家共用一套模型配置体系，所以想做一个渠道模型模版整套体系的发布分享和接收订阅的体系和skill、mcp的发布订阅的体系，我觉得可能依赖于服务端docs/04-项目资料/03-项目协作资料/01-协作包/2026-10-05-多用户多设备用量与服务端协作，但是我觉得是下一个版本了，做一个独立协作包思考。客户端可以选择发布订阅的范围内容，然后服务端管理订阅，其他用户或者团队选择订阅，然后订阅像clash支持不同渠道模型模版整套体系、skill、mcp等（类似版本、各自模块可以分别改选取的订阅）、保留本地的配置可选。

## 已明确的方向

| 编号 | 用户目标 | 本包落点 |
|---|---|---|
| R-01 | 从个人配置同步转为团队共享一套模型配置体系 | 总体方案中的发布者 / 接收者与整套模型体系 |
| R-02 | 渠道、模型、模版整套发布分享与接收订阅 | 发布清单、模型依赖集合、整套采用 |
| R-03 | Skills、MCP 也能发布与订阅 | 同一订阅框架，分别使用内容和应用适配器 |
| R-04 | 客户端可以选择发布与订阅的内容范围 | 双侧选择范围、依赖预览与新增内容策略 |
| R-05 | 服务端管理订阅，个人或团队可以订阅 | 个人 / 团队主体、访问授权与设备应用状态 |
| R-06 | 类似 Clash，多源选择、版本化，各模块分别换订阅 | 模块选择表、固定 / 跟随版本、组合方案 |
| R-07 | 可选择保留本地配置 | 本地条目、本地覆盖分开控制；退出订阅可保留 |
| R-08 | 下一版本独立思考，可能依赖服务端包 | 独立 COL；不扩大 v0.2.0，不指定正式版本号 |

## 派生建议，尚非用户决定

- 首期采用一个已登录服务实例下的多个发布源；团队目录和访问控制优先，跨站聚合 / 公共市场后置。
- 一份发布可以只含某模块，也可以含三个模块；整套方案提供默认组合，用户仍可改某个模块。
- 模型体系默认选择一个策略主源，并附带精确模版依赖；额外模版源先进入候选库。任意多份完整模型策略自动融合不作为首期承诺。
- 版本不可变，订阅可固定版本或跟随稳定 / 测试轨道；自动下载只更新候选，默认手动应用。
- 默认保留本地条目与显式覆盖；同名、同字段冲突均可解释，不按下载先后覆盖。
- 内容分发只携带可分享内容和绑定要求；密钥、登录会话、本机路径及运行验证记录不进入发布包。
- 订阅服务复用账户与团队底座，但不以开启用量上传为前提；团队成员模型沿用服务端包的补充设计，本包增加内容发布、读取和订阅权限。

待评审项见 [评审入口](../03-确认与评审/README.md)。用户没有指定工期、版本号、服务域名、实际发布内容或自动执行权限，这些不妨碍形成当前协作包。
