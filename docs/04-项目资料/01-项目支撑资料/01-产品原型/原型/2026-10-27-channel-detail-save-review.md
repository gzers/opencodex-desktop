## 本次两处调整

| 位置 / 状态 | 试用行为 |
| --- | --- |
| 模型 → 渠道详情 → 渠道配置（mpChannelSection-connection） | 名称、协议、认证和 Key 直接进入内存编辑；删除连接区“还原配置／加入草稿”两个局部按钮，也不沿用软件的“确认连接与模型”命名。只读 ID、Key 掩码/眼睛与明确清空保留。 |
| 模型列表 / 服务节点 | 获取模型列表留在模型列表；检测/切换服务节点留在节点区，使用当前内存连接。请求和测速仍为 mock，不要求先完成连接确认。 |
| 渠道详情侧栏保存（mpPolicySave） | 只模拟保存当前渠道，不打开完整保存预览；保存进行中留在详情，成功后回到渠道列表。失败、取消或实际提交超限时留在详情并保留输入。 |
| 详情标题（mpChannelHeadingStatus） | 保存状态只反映当前渠道；其它渠道未保存修改不使本渠道显示未保存。沿用原有徽标，无新增状态行。 |
| 渠道列表保存（mpPolicySave） | 继续打开已有完整“保存预览”，确认才提交全部剩余编辑；取消不撤销已完成的单渠道保存。 |

详情保存以 mock saved 为底，只替换当前渠道；不顺带提交其他渠道、全局渠道顺序或全局采用关系。新增渠道只插入当前渠道，保留已有渠道的保存顺序；渠道内型号顺序按当前编辑保存。其它渠道的名称、节点、Key 意图、待确认型号规则和模版编辑缓冲保持。历史记录记载该次实际 before / after；不将局部写入冒记为整套历史恢复完成。

型号行“加入草稿”仍属于独立的行编辑确认，只限制所属渠道；不改成再次保存文件。详情保存预算按实际将提交的合并快照计算，不借用其它尚未保存的停用，也不因其它尚未提交的超限草稿拒绝有效的本渠道保存。

## 建议模拟顺序

1. 在 NewApi 详情修改名称或模型，点返回，不保存。
2. 进入 Aimami，修改后点左侧保存。应直接返回列表，重开 Aimami 显示未修改；NewApi 仍保留未保存内容。
3. 在列表点保存，应仍看到完整保存预览，只提交剩余修改；也可取消，检查已保存的 Aimami 不被撤销。
4. 用右侧原型工具板的“备份失败／写入失败／写入超时”演示，检查详情保存失败后仍留在编辑页。
